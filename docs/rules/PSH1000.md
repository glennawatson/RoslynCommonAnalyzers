# PSH1000 — Anonymous functions without captures should be static

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Allocations |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A lambda or anonymous method uses no local variables, parameters, or instance
members from outside itself, but is not marked `static`. Using its own parameters
is allowed. The rule applies to C# 9 and later.

Adding `static` stops later edits from capturing outside values. Capturing a local
can create an extra object to hold it, called a closure. A function that captures
nothing can already have its delegate reused by the compiler.

Functions that capture outside values are not reported. Neither are lambdas
assigned to `Expression<TDelegate>`, which cannot be `static`.

## Example

Before:

```csharp
public class Calculator
{
    public System.Func<int, int> GetDouble() => x => x * 2;
}
```

After:

```csharp
public class Calculator
{
    public System.Func<int, int> GetDouble() => static x => x * 2;
}
```

## Code fix

The fix inserts `static` before the lambda or `delegate` keyword. For an `async`
function, it inserts `static` before `async`. It keeps leading comments and spacing.
Fix All applies the change to every reported function in the selected scope.

## Configuration

The default severity is `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1000.severity = warning
```

Use `error`, `suggestion`, or `silent` to change the severity, or `none` to disable
the rule.

## When to suppress

Suppress when the same source must also compile in a project using C# 8 or earlier.
Otherwise, adding `static` records a useful restriction without changing the body.
