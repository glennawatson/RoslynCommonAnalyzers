# PSH1001 — Avoid allocating zero-length arrays

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Allocations |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

Code creates an empty array with `new T[0]`, `new T[] { }`, or `new T[0] { }`.
Each evaluation creates an array that can never hold an element. `Array.Empty<T>()`
returns a shared empty array. In C# 12 and later, `[]` can do the same for an array.

The rule accepts a literal `0` size, not a variable or named constant. It reports
jagged arrays such as `new int[0][]`, but skips multidimensional arrays such as
`new int[0, 0]`, attribute arguments, and element types that cannot be generic type
arguments, such as pointers. It reports nothing when the framework lacks
`System.Array.Empty<T>()`.

## Example

Before:

```csharp
public class Results
{
    public int[] GetEmpty() => new int[0];
}
```

After, with C# 12 or later and the default option:

```csharp
public class Results
{
    public int[] GetEmpty() => [];
}
```

For older language versions, return `System.Array.Empty<int>()` instead.

## Code fix

The fix replaces the array creation with `[]` when the option is enabled, the
language version is C# 12 or later, and the surrounding code specifies the same
array type. This includes explicitly typed local, field, and property initializers,
method and property returns, and simple assignments. For declarations and returns,
the array type must also be written the same way as in the creation.

Other cases become `System.Array.Empty<T>()`. These include `var` declarations,
method arguments, and targets with a different element type, such as
`object[] values = new string[0]`. This keeps the original array type and avoids
changing which method overload is called.

Fix All is supported. Comments before and after the creation are kept; comments
inside the replaced creation can be lost.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.PSH1001.severity = warning
performancesharp.prefer_collection_expressions = true
```

The default severity is `warning`; use `error`, `suggestion`, `silent`, or `none`
to change it. The collection-expression option defaults to `true`. Set it to
`false` to always get `Array.Empty<T>()`; `0` and `no` also disable it. Before
C# 12, the fix uses `Array.Empty<T>()` regardless of this option.

## When to suppress

Suppress when each call must return a distinct array object, for example when
code deliberately checks array identity with `ReferenceEquals`.
