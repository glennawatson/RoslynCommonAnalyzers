# PSH1002 — Empty finalizers should be removed

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Allocations |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A class declares a finalizer, written as `~ClassName()`, whose block contains no
statements. A body containing only comments is also reported. A finalizer with
statements or an expression body is not reported.

An empty finalizer does no cleanup, but still makes the garbage collector track
the object for finalization. This adds work and can delay reclaiming its memory.

## Example

Before:

```csharp
public class Connection
{
    ~Connection()
    {
    }
}
```

After:

```csharp
public class Connection
{
}
```

## Code fix

The fix deletes the whole finalizer declaration. Comments inside it and comments
attached to the declaration are removed too. Move any comment you need to keep
before applying the fix. Fix All removes all reported finalizers in the selected
scope.

## Configuration

The default severity is `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1002.severity = warning
```

Use `error`, `suggestion`, or `silent` to change the severity, or `none` to disable
the rule.

## When to suppress

Suppress in a test or benchmark that deliberately needs an object with a finalizer
to study its lifetime or cost. An empty finalizer in ordinary application code
should be removed.
