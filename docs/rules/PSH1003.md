# PSH1003 — 'in' parameters should use readonly structs

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Allocations |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A parameter uses `in`, or C# 12's `ref readonly`, with a struct that is not declared
`readonly`. Primitive types, enums, generic type parameters, and reference types
are not reported.

These parameter modifiers pass a reference that the method cannot write through.
Calling a non-readonly member of a mutable struct can force the compiler to copy
the struct first, so the member cannot change the caller's value. Repeated copies
can cost more than passing the value once.

The rule checks the struct declaration, even when the method only reads fields or
calls members marked `readonly` and makes no such copies.

## Example

Before:

```csharp
public struct Point
{
    public readonly int X;
}

public static class Geometry
{
    public static int Measure(in Point point) => point.X;
}
```

After:

```csharp
public readonly struct Point
{
    public readonly int X;
}

public static class Geometry
{
    public static int Measure(in Point point) => point.X;
}
```

## How to fix violations

There is no code fix.

Declare the whole struct `readonly` if its instance data does not need to change.
Its fields must also be readonly, and its automatic properties cannot have ordinary
setters. Otherwise, remove `in` or `ref readonly` and pass the value normally. Remove
explicit `in` or `ref` argument modifiers at callers too. Changing a public
parameter's passing mode requires rebuilding its callers.

Marking individual members `readonly` can prevent copies, but does not clear this
diagnostic.

## Configuration

The default severity is `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1003.severity = warning
```

Use `error`, `suggestion`, or `silent` to change the severity, or `none` to disable
the rule.

## When to suppress

Suppress when the parameter only reads fields or calls readonly members, and
keeping the reference avoids a measured copying cost. Also suppress when an
interface or external API fixes the signature and you cannot change the struct.
