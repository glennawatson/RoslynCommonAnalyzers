# PSH1004 — Hoist constant array arguments

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Allocations |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A method or constructor call creates an array directly in its argument list, and
every element is a constant. This allocates the same contents each time the call
runs. Storing the array in a shared field avoids repeated allocations.

The rule checks `new T[] { ... }` and `new[] { ... }` with nonempty initializers.
It recognizes literals, named constants, enum members, and literals with a leading
operator, such as `-1`. It skips calculations such as `1 + 2`, collection expressions
such as `[1, 2]`, and attribute arguments. Empty arrays are covered by
[PSH1001](PSH1001.md).

## Example

Before:

```csharp
public class Example
{
    public int Run() => Count(new[] { 1, 2, 3 });

    private static int Count(int[] values) => values.Length;
}
```

After:

```csharp
public class Example
{
    private static readonly int[] Values = { 1, 2, 3 };

    public int Run() => Count(Values);

    private static int Count(int[] values) => values.Length;
}
```

## How to fix violations

There is no code fix.

Move the array to a `static readonly` field and pass the field to the call. Do this
only when every user of the array treats its contents as read-only. The `readonly`
modifier prevents replacing the field; it does not prevent changing array elements.

## Configuration

The default severity is `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1004.severity = warning
```

Use `error`, `suggestion`, or `silent` to change the severity, or `none` to disable
the rule.

## When to suppress

Suppress when the receiving code changes the array or requires its own instance.
Keeping an allocation can also be reasonable for a call that runs once, where a
shared field would keep the array alive for longer.
