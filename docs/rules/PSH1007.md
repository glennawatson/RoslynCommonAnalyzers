# PSH1007 — Pass large readonly structs by in reference

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Allocations |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A method, constructor, or local function takes a `readonly struct` by value whose
estimated size is at least 32 bytes by default. Passing it with `in` can avoid
copying the whole value on each call. The method receives a reference it cannot
write through.

By default, members visible outside the assembly are skipped. The rule also skips
parameters with modifiers such as `in`, `ref`, `out`, `this`, or `params`, and
structs whose size cannot be estimated.

## Example

Before:

```csharp
public readonly struct Snapshot
{
    public readonly long A, B, C, D, E;
}

internal static class Scoring
{
    internal static long Score(Snapshot snapshot) => snapshot.A;
}
```

After:

```csharp
public readonly struct Snapshot
{
    public readonly long A, B, C, D, E;
}

internal static class Scoring
{
    internal static long Score(in Snapshot snapshot) => snapshot.A;
}
```

## What is not reported

- Mutable structs and `ref struct` types. Adding `in` to a mutable struct can
  cause extra copies; see [PSH1003](PSH1003.md).
- `Span<T>`, `ReadOnlySpan<T>`, `Memory<T>`, `ReadOnlyMemory<T>`, `CancellationToken`,
  `ValueTask` and `ValueTask<T>`, and `ImmutableArray<T>`.
- Framework vector and matrix types: `Vector<T>`, `Vector2`, `Vector3`, `Vector4`,
  `Quaternion`, `Plane`, `Matrix3x2`, `Matrix4x4`, and `Vector64<T>` through
  `Vector512<T>`.
- Async methods, iterator methods that use `yield`, and parameters used inside a
  nested lambda, local function, or query. These uses cannot accept an `in`
  parameter in the same way.
- Parameters assigned to or passed as `ref` or `out` within the body.
- Interface members and implementations, overrides, virtual, abstract, partial,
  and extern members, members of attribute classes, and methods marked
  `[UnmanagedCallersOnly]`.
- Operators, delegate declarations, lambdas, primary constructors, and methods
  converted to delegates in the same project.

## Code fix

The fix adds `in` before the parameter type and keeps its comments and indentation.
Fix All is supported. Ordinary callers can keep passing the argument without
writing `in`.

The modifier requires C# 7.2 or later. Adding it changes the compiled signature:
already compiled callers must be rebuilt. Check delegate uses in other projects
and calls with `dynamic` arguments before changing a public member.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.PSH1007.severity = warning
performancesharp.in_parameter_minimum_size = 32
performancesharp.in_parameter_include_public_api = false
```

| Key | Values | Default |
| --- | --- | --- |
| `performancesharp.in_parameter_minimum_size` | Positive integer in estimated bytes. Values from 1 to 16 become 17; invalid values use 32. | `32` |
| `performancesharp.in_parameter_excluded_types` | Comma-separated type names, such as `My.Lib.Handle, OtherStruct`. Names are case-sensitive, bare or namespace-qualified, without generic type arguments. | No extra exclusions |
| `performancesharp.in_parameter_include_public_api` | `true` or `false`. Set `true` to include members visible outside the assembly. | `false` |

Extra type exclusions are added to the built-in list above. A size is an estimate,
not a guarantee of the struct's runtime size.

Each option also has a rule-specific form, which takes precedence when set:

```ini
performancesharp.PSH1007.in_parameter_minimum_size = 32
performancesharp.PSH1007.in_parameter_excluded_types = My.Lib.Handle, OtherStruct
performancesharp.PSH1007.in_parameter_include_public_api = false
```

For the boolean option, an invalid rule-specific value falls back to the general
value. The default severity is `warning`; use `error`, `suggestion`, `silent`, or
`none` to change it. See the [configuration reference](../CONFIGURATION.md).

## When to suppress

Suppress when measurements show no benefit, or when callers require the by-value
signature. Passing a property or calculated value can still require a temporary
copy with `in`. Keep the existing signature when a delegate in another project or
a call with `dynamic` arguments depends on it.
