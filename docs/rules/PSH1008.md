# PSH1008 — Remove SuppressFinalize calls for finalizer-free types

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Allocations |
| Severity | Warning |
| Code fix | Yes, for calls used as statements |
| Default | Enabled |

## Cause

Code calls `GC.SuppressFinalize(this)` in a struct, or in a sealed class with no
finalizer in the class or its base classes. There is no finalizer to suppress, so
the call adds work without doing cleanup.

Unsealed classes are not reported because a derived class can add a finalizer.
Calls on another object are not reported. The rule recognizes `GC.SuppressFinalize`
and its qualified forms, such as `System.GC.SuppressFinalize`.

## Example

Before:

```csharp
using System;

public sealed class Connection : IDisposable
{
    public void Dispose()
    {
        GC.SuppressFinalize(this);
    }
}
```

After:

```csharp
using System;

public sealed class Connection : IDisposable
{
    public void Dispose()
    {
    }
}
```

## Code fix

The fix removes the statement containing the call and supports Fix All. Comments
attached to that statement are removed too; move any you need to keep first.
Other cleanup statements remain in place.

The fix is offered only for a call used as a statement. An expression-bodied
method such as `void Dispose() => GC.SuppressFinalize(this);` must be edited by
hand, for example by replacing its body with an empty block.

## Configuration

The default severity is `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1008.severity = warning
```

Use `error`, `suggestion`, or `silent` to change the severity, or `none` to disable
the rule.

## When to suppress

Suppress when shared source includes a finalizer in another build configuration
and keeping a common disposal method is useful. For a type that never has a
finalizer, remove the call.
