# PSH1011 — Pass state to callbacks through the state-taking overload

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Allocations |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A lambda or anonymous method passed directly to a method captures a local,
parameter, or `this`, and another overload accepts an extra state argument.
Capturing locals can allocate a closure, an object that holds the captured values,
as well as a delegate. Capturing only `this` can still create a new delegate.
Passing state separately lets a callback without captures be reused.

For example, `Task.ContinueWith` and `CancellationToken.Register` offer overloads
that pass your state to the callback. The rule looks for an overload on the same
type with one extra parameter, taking state by value as `object` or a generic
method type parameter, and a matching callback parameter list.

## Example

Before:

```csharp
using System;
using System.Threading;

public class Cleanup
{
    public CancellationTokenRegistration Register(
        CancellationToken token, IDisposable resource)
        => token.Register(() => resource.Dispose());
}
```

After, using C# 9 or later:

```csharp
using System;
using System.Threading;

public class Cleanup
{
    public CancellationTokenRegistration Register(
        CancellationToken token, IDisposable resource)
        => token.Register(static state => ((IDisposable)state!).Dispose(), resource);
}
```

## What is not reported

Callbacks that capture nothing, named callback arguments, and calls with no
matching state overload are not reported. An unrelated object parameter does not
count as added state. For example, the lock argument to
`LazyInitializer.EnsureInitialized` is passed by reference, and the key supplied
to a keyed service registration is already present in the original overload.
Neither supplies an extra place for captured data.

## How to fix violations

There is no code fix.

Choose the overload with a state argument. Pass the required data there and read
it from the callback's parameter. Add `static` in C# 9 or later to prevent captures.
Check the overload's other options so scheduling and cancellation keep the behavior
you need.

State passes the value at the time of the call. A captured variable can observe
later assignments, so preserve that behavior if the callback needs it. When state
is a struct, prefer a generic state overload where available: an `object` state
parameter boxes it, creating an object to hold the value.

## Configuration

The default severity is `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1011.severity = warning
```

Use `error`, `suggestion`, or `silent` to change the severity, or `none` to disable
the rule.

## When to suppress

Suppress when the callback must share a changing variable with its caller, or when
packing several values into state adds complexity without a measured benefit.
Also suppress if the suggested overload cannot preserve the callback behavior.
