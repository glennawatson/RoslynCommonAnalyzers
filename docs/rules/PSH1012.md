# PSH1012 — Compare type parameter values with EqualityComparer<T>.Default

**Category:** Allocations
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

Two values of the same generic type parameter are compared with `current.Equals(next)`
or `object.Equals(current, next)`. The type parameter can be a value type, and the call
uses the `object` or `ValueType` equality method.

These calls can cause boxing: wrapping a value type in a heap object.
`EqualityComparer<T>.Default` uses the equality support available for `T` without
requiring the caller to pass the values as `object`.

Reference-type constraints such as `where T : class` are not reported. An instance
call that uses `IEquatable<T>.Equals` is also not reported. A static `object.Equals`
call can still be reported when `T` implements `IEquatable<T>`.

## Example

Before:

```csharp
public class Comparisons
{
    public bool Same<T>(T current, T next) => current.Equals(next);
}
```

After:

```csharp
using System.Collections.Generic;

public class Comparisons
{
    public bool Same<T>(T current, T next) =>
        EqualityComparer<T>.Default.Equals(current, next);
}
```

## Code fix

The fix replaces either call with `EqualityComparer<T>.Default.Equals(current, next)`.
It uses the full type name if `System.Collections.Generic` is not imported.
Comments around the removed call name or arguments can be lost.

The comparer handles null values and can use `IEquatable<T>.Equals`. Check the change
if your code relies on a null receiver throwing or on a different `Equals(object)` result.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1012.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when the original null or equality behavior is required. For a custom struct,
implement `IEquatable<T>` if the default comparer still needs to box its values.
