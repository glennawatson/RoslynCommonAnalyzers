# PSH1014 — Declare immutable structs as readonly

**Category:** Allocations
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A struct can be declared `readonly` but is missing the modifier. Its instance
fields are already readonly, and its auto-properties have only `get` or `init`
accessors. Static members do not prevent the report.

Without `readonly`, calling a struct member through an `in` parameter, a
`ref readonly` local, or a readonly field can make the compiler copy the struct
to protect the original value. Declaring the struct `readonly` avoids those copies.

Partial structs, fixed buffers, instance events declared without accessors, and
record structs with a primary constructor are not reported. Members that assign
to `this` or pass it as a `ref` or `out` argument also prevent the report.
The rule applies from C# 7.2.

## Example

Before:

```csharp
public struct Size
{
    public Size(int width) => Width = width;

    public int Width { get; }
}
```

After:

```csharp
public readonly struct Size
{
    public Size(int width) => Width = width;

    public int Width { get; }
}
```

## Code fix

The fix adds `readonly` after access modifiers and before `ref` or `unsafe`.
It keeps the members, attributes, and comments.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1014.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when an external tool or an API contract requires the struct declaration
to remain unchanged. Mutable structs are already excluded.
