# PSH1015 — Avoid casting value types through object

**Category:** Allocations
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A value is cast to `object` and immediately cast to a value type, such as
`(int)(object)day`. Casting to `object` can cause boxing: wrapping the value in a
heap object. A direct cast avoids that intermediate object.

Both types must be concrete value types with a built-in conversion between them.
Generic type parameters, reference types, and user-defined conversions are not reported.

## Example

Before:

```csharp
using System;

public class Dates
{
    public int Number(DayOfWeek day) => (int)(object)day;
}
```

After:

```csharp
using System;

public class Dates
{
    public int Number(DayOfWeek day) => (int)day;
}
```

## Code fix

The fix removes the intermediate `object` cast and keeps the outer cast, even
when the source and destination types are the same. Comments attached to the
removed cast or surrounding parentheses can be lost.

A direct numeric cast can change behavior: `(long)(object)1` throws because the
boxed value is an `int`, while `(long)1` succeeds. The rule reports the cast
through `object` when a built-in conversion exists; it does not require the
original cast to succeed.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1015.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when a test deliberately checks boxing or the exception from casting a
boxed value to a different type.
