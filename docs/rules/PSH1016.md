# PSH1016 — Test enum flags with bitwise operators

**Category:** Allocations
**Severity:** Warning
**Code fix:** Yes, for supported flag expressions (supports Fix All)

## Cause

A value of a concrete enum type calls `Enum.HasFlag`. The rule does not require
the enum to have a `[Flags]` attribute. Calls on a variable typed as `System.Enum`
and unrelated methods named `HasFlag` are not reported.

On .NET Framework, `HasFlag` can box the value and flag: wrap each in a heap
object. The bitwise test avoids that cost. Modern .NET can optimize `HasFlag`,
so measure the benefit on your target runtime.

## Example

Before:

```csharp
using System;

[Flags]
public enum Options { None = 0, Cache = 1, Log = 2 }

public class Settings
{
    public bool UsesCache(Options options) => options.HasFlag(Options.Cache);
}
```

After:

```csharp
using System;

[Flags]
public enum Options { None = 0, Cache = 1, Log = 2 }

public class Settings
{
    public bool UsesCache(Options options) =>
        (options & Options.Cache) == Options.Cache;
}
```

## Code fix

The fix writes `(value & flag) == flag`. For a directly negated call, it uses
`!=` instead. It puts combined flags such as `Options.Cache | Options.Log` in
parentheses and formats the comparison on one line.

The flag appears twice. The fix accepts names, member accesses, literals, and
`|` combinations of them, including parenthesized forms. It does not offer a fix
for a method call argument. Store a changing flag value in a local first;
property getters in the replacement run twice. Comments around removed parts
of the call can be lost.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1016.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when measurements show no benefit on your runtime and `HasFlag` makes
the intent clearer. Keep it when a test needs its argument validation behavior.
