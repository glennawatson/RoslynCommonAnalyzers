# PSH1017 — Properties should not copy a collection on every read

**Category:** Allocations
**Severity:** Warning
**Code fix:** None

## Cause

A collection property returns a fresh collection from its getter. Reading the
property repeatedly can allocate and copy all the items each time, including
when the property appears in a loop condition.

Reported returns include:

- `ToArray()`, `ToList()`, `ToHashSet()`, or `ToDictionary(...)` calls that return a collection.
- `Clone()` calls on a collection, including array clones cast back to an array.
- Collection constructors in `System.Collections.Generic` or
  `System.Collections.Concurrent` whose first parameter takes a source collection.
- Array creations with an initializer, such as `new[] { first, second }`.

The property must return an array or a type that implements `IEnumerable`.
Strings and `ref struct` types are excluded. The return can be an expression
body or a `return` statement inside a getter, including a branch.

## What is not reported

Auto-properties, cached fields, and cached copies such as `_cache ??= _items.ToArray()`
are not reported. Neither are read-only wrappers, capacity-only constructors,
indexers, setters, or returns inside a getter's lambda or local function.

## Example

Before:

```csharp
using System.Collections.Generic;

public class Catalog
{
    private readonly List<int> _items = new();

    public int[] Items => _items.ToArray();
}
```

After, when callers need a fresh copy:

```csharp
using System.Collections.Generic;

public class Catalog
{
    private readonly List<int> _items = new();

    public int[] GetItems() => _items.ToArray();
}
```

## How to fix violations

There is no automatic code fix. Use a method to make the copying cost clear,
or return a cached copy or a read-only view. A view reflects later changes to
the source collection; a snapshot does not. Choose the behavior callers need.

## Configuration

Enabled by default as a warning.

| Key | Default | Values |
| --- | --- | --- |
| `dotnet_diagnostic.PSH1017.severity` | `warning` | `none`, `silent`, `suggestion`, `warning`, `error` |
| `performancesharp.PSH1017.excluded_properties` | Empty | Comma-separated property names to exclude |
| `performancesharp.excluded_properties` | Empty | Fallback list when the rule-specific key is absent |

Names are case-sensitive. Spaces around names and empty entries are ignored.
The rule-specific list replaces the fallback list, even when it is empty.

```ini
[*.cs]
dotnet_diagnostic.PSH1017.severity = warning
performancesharp.PSH1017.excluded_properties = Defaults, Corners
```

See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Exclude a property when its contract requires a fresh copy and changing it to a
method would break callers. A small, fixed collection read rarely can also be
worth keeping as a property when the measured cost is negligible.
