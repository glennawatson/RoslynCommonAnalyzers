# PSH1022 — Use EventArgs.Empty instead of allocating a new EventArgs

**Category:** Allocations
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

Code creates a parameterless `System.EventArgs` with no object initializer.
This includes `new EventArgs()`, qualified type names, and target-typed `new()`
when the name `EventArgs` is available at that location.

The base `EventArgs` type carries no event data. Reusing `EventArgs.Empty`
avoids allocating a new object each time the event is raised.
Derived event-argument types and constructions with an initializer, even `{ }`,
are not reported. A construction written through a differently named type alias
is also not reported.

## Example

Before:

```csharp
using System;

public class Publisher
{
    public event EventHandler Changed;

    public void Raise() => Changed?.Invoke(this, new EventArgs());
}
```

After:

```csharp
using System;

public class Publisher
{
    public event EventHandler Changed;

    public void Raise() => Changed?.Invoke(this, EventArgs.Empty);
}
```

## How to fix violations

The code fix replaces the construction with `EventArgs.Empty`. It keeps a
written type qualification, so `new System.EventArgs()` becomes
`System.EventArgs.Empty`. Target-typed `new()` becomes `EventArgs.Empty`.
Comments before and after the construction are kept; comments inside it can be lost.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1022.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when a caller deliberately needs a distinct object, such as a test that
compares event arguments with `ReferenceEquals`. `EventArgs.Empty` returns the
same shared instance each time.
