# PSH1023 — Use a tuple instead of an anonymous type for a local value

**Category:** Allocations
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A local variable declared inside a block is initialized with an anonymous type
containing at least two named members. Each use of the local is a member access,
such as `pair.Left`. Names can be written explicitly or taken from an expression
such as `source.Width`.

An anonymous type is a class, so creating it allocates an object. A named tuple
is a value type that can carry the same data without a separate object allocation
when kept as a value.

Returning, passing, assigning, or otherwise using the whole local prevents the
report. A single-member anonymous type is not reported. The rule applies from C# 7;
older target frameworks may need the `System.ValueTuple` package to use the fix.

## Example

Before:

```csharp
public class Calculator
{
    public int Sum()
    {
        var pair = new { Left = 1, Right = 2 };
        return pair.Left + pair.Right;
    }
}
```

After:

```csharp
public class Calculator
{
    public int Sum()
    {
        var pair = (Left: 1, Right: 2);
        return pair.Left + pair.Right;
    }
}
```

## How to fix violations

The code fix replaces `new { ... }` with a tuple and writes an explicit name
for every element. For example, `new { source.Width, source.Height }` becomes
`(Width: source.Width, Height: source.Height)`. Member reads stay unchanged.
Comments around removed braces, member names, or separators can be lost.

Review calls such as `pair.ToString()` or `pair.GetType()`: they also count as
member accesses, but a tuple gives different results. Member reads inside a
lambda do not prevent the report. Some names, such as `Rest`, are not valid
tuple element names; rename those members manually before applying the change.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1023.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when code depends on the anonymous type's method results or member names,
or when the target framework cannot support value tuples. Keep the anonymous type
when measurements show that copying a large tuple costs more than the saved allocation.
