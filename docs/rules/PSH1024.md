# PSH1024 — Build a BitArray from a span instead of a temporary array

| Item | Value |
| --- | --- |
| Category | Allocations |
| Severity | Warning |
| Code fix | No |
| Applies to | Frameworks offering a `BitArray` span constructor |

## Cause

A `BitArray` is constructed from an array created at the call site.

```csharp
var flags = new BitArray(new[] { true, false, true });
```

## Rule description

The array is copied into the `BitArray` and then dropped, so it is pure garbage: it exists for the
duration of one call and never escapes. The span constructors read the same values without the
intermediate collection, and the source can be a `stackalloc` or a collection expression targeting the
span, which keeps the values off the heap entirely.

```csharp
// 👍
ReadOnlySpan<bool> values = [true, false, true];
var flags = new BitArray(values);
```

## What is not reported

- An array the caller already holds. It is not a temporary, and passing it allocates nothing extra:

  ```csharp
  public BitArray Wrap(bool[] flags) => new BitArray(flags);   // not reported
  ```

- Constructors that take no array at all, such as `new BitArray(8)` or `new BitArray(8, true)`.
- Anything at all when the referenced framework has no span constructor. The rule resolves one in the
  analyzed compilation and stays silent when it is absent, so the suggestion always has somewhere to
  go.

## How to fix violations

Pass a span instead of allocating an array. For a small, fixed set of values, `stackalloc` or a
collection expression targeting `ReadOnlySpan<T>` avoids the heap altogether; for values already in a
buffer, slice that buffer rather than copying it into a new array.
