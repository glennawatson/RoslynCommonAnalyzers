# PSH1024 — Build a BitArray from a span instead of a temporary array

| Item | Value |
| --- | --- |
| Category | Allocations |
| Severity | Warning |
| Code fix | No |
| Applies to | Frameworks offering a `BitArray` span constructor |

## Cause

A `BitArray` constructor receives an array created inside the call, such as
`new[] { true, false }` or `new byte[] { 1, 2, 3 }`. The constructor copies the
values, leaving the temporary array for the garbage collector to reclaim.

An existing array variable is not reported. Neither are the constructors that
take a length. The rule reports nothing when the project targets a framework
without a `BitArray` constructor that accepts `ReadOnlySpan<T>`.

## Example

Reported:

```csharp
using System.Collections;

var flags = new BitArray(new[] { true, false });
```

Use a span with the same element type:

```csharp
using System;
using System.Collections;

ReadOnlySpan<bool> values = stackalloc bool[] { true, false };
var flags = new BitArray(values);
```

The small `stackalloc` buffer avoids a separate array allocation. The `BitArray`
still allocates its own storage. For data in an existing buffer, pass a span over
that buffer instead of copying it into a new array.

There is no automated code fix.

## Configuration

Enabled by default at `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1024.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when this construction is infrequent and the temporary array has no
meaningful cost. Keep the array if avoiding it would require a large or unbounded
stack allocation; `stackalloc` is suitable only for small, bounded buffers.
