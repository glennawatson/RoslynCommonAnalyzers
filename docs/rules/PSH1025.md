# PSH1025 — Avoid a value-typed union case

**Category:** Allocations
**Severity:** Warning
**Code fix:** No
**Applies to:** C# 15 or later, on a compiler that carries the union syntax model

A union is itself a value type, but it stores whichever case it currently holds in a single
object-typed payload field. A case declared as a value type therefore **boxes every time a value of
that case is created**.

```csharp
// 👎 every Reading boxes, whichever case it holds
public union Reading(int, double);

// 👍 no boxing: both cases are already references
public union Payload(string, byte[]);
```

That turns a type which reads as allocation-free into one that allocates per instance — the opposite
of what the shape suggests, and most expensive in exactly the per-item and per-notification types
unions get reached for. A union produced once per delivered item allocates once per delivered item.

## What is reported

Each case in the union's case list whose type binds to a value type: the built-in numeric and `bool`
types, an `enum`, a `struct`, a tuple, or a nullable value type. A mixed union is reported only on the
cases that box, so the reference-typed cases stay quiet.

```csharp
public union Payload(string, int); // reported on 'int' only
```

## How to fix violations

1. **Use reference-typed cases.** Where each case already has a natural type, prefer the reference
   form — a small sealed record per case makes the allocation explicit and lets the case carry a name.
2. **Wrap and share.** Where the value set is small and fixed, a cached instance per value removes the
   per-construction allocation entirely.
3. **Keep the hand-rolled tagged type.** A struct with a discriminator and the payload fields inline
   does not box at all. [SST2338](SST2338.md) will not push such a type toward a union when any of its
   payloads is a value type, for this reason.

## Related rules

- [SST2338](SST2338.md) — suggests a union for a hand-rolled discriminated type, and deliberately
  stays silent when the payloads are value types so the two rules cannot pull in opposite directions.
