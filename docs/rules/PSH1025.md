# PSH1025 — Avoid a value-typed union case

| Item | Value |
| --- | --- |
| Category | Allocations |
| Severity | Warning |
| Code fix | No |
| Applies to | Compilers and target frameworks that support C# union declarations |

## Cause

A union declares a case whose type is a value type, such as `int`, an enum, a
struct, a tuple, or a nullable value type. Each value of that case stored in the
union is boxed: it is wrapped in a new object so the union can hold it as an
`object`. This adds an allocation even though the union itself is a value type.

Each value-type case is reported separately. Reference-type cases, such as
`string`, arrays, and classes, are not reported.

## Example

The `int` case is reported:

```csharp
public union Payload(string, int);
```

If the value can be represented by a shared reference object, use that object as
the case:

```csharp
public sealed record Number(int Value);
public union Payload(string, Number);
```

Creating a new `Number` for every value still allocates. Reuse an existing instance
when that suits the data. For numeric values that change often, a struct with a
field identifying the case and fields holding the values can avoid both boxing
and wrapper objects.

The examples require union language support and the matching runtime support.
There is no automated code fix; changing the cases changes how callers use the type.

## Configuration

Enabled by default at `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1025.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the union is created rarely, measurements show the allocation is
acceptable, or changing a public union would break its callers. A wrapper created
for every value is not a reason to expect a memory saving.
