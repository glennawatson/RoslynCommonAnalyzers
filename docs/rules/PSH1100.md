# PSH1100 - Avoid LINQ calls on hot paths

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Collections |
| Severity | Warning |
| Code fix | No |
| Default | Disabled (opt-in) |

## Cause

A call uses one of the supported `System.Linq.Enumerable` methods in a file where
the rule is enabled. LINQ can create objects to track iteration and call a function
for each element. In code that runs often, these costs can matter.

The rule covers these methods, including extension calls and direct static calls:

- `Aggregate`, `All`, `Any`, `Contains`, `Count`, `Max`, `Min`, `Sum`.
- `DefaultIfEmpty`, `ElementAt`, `First`, `FirstOrDefault`, `Last`, `LastOrDefault`, `Single`, `SingleOrDefault`.
- `Cast`, `OfType`, `Select`, `SelectMany`, `Where`.
- `OrderBy`, `OrderByDescending`, `Reverse`, `ThenBy`, `ThenByDescending`.
- `Skip`, `SkipWhile`, `Take`, `TakeWhile`.
- `Append`, `Concat`, `Distinct`, `Except`, `Intersect`, `Prepend`, `Union`, `Zip`.
- `GroupBy`, `ToArray`, `ToDictionary`, `ToHashSet`, `ToList`, `ToLookup`.

It does not report `Queryable` calls or unrelated methods such as
`string.Contains`. It checks every matching call in the enabled files; it does
not measure how often that code runs. A call covered by [moving a filter into the
final call](PSH1101.md) or [type filtering](PSH1102.md) receives that diagnostic
instead, though other calls in the same chain can still be reported here.

## Example

Reported when enabled:

```csharp
using System;
using System.Linq;

int[] values = { 1, 2, 3 };
foreach (var value in values.Select(value => value + 1))
{
    Console.WriteLine(value);
}
```

Move the work into the loop:

```csharp
using System;

int[] values = { 1, 2, 3 };
foreach (var value in values)
{
    Console.WriteLine(value + 1);
}
```

There is no automated code fix. When rewriting a query, preserve when it runs,
the order of its results, and when it stops reading the source.

## Configuration

Both settings are required to enable the rule:

```ini
[*.cs]
dotnet_diagnostic.PSH1100.severity = warning
performancesharp.avoid_linq_on_hot_path = true
```

The rule is disabled by default and the option defaults to `false`. The option
accepts `true` or `false`; `yes` and `1` also enable it, ignoring letter case.
Other values leave it off. Severity values are `error`, `warning`, `suggestion`,
`silent`, and `none`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled in code where LINQ makes the intent clearer and its cost
does not matter. Suppress a reported call when measurements show it is acceptable,
or scope the settings to the folders that contain frequent, expensive work.
