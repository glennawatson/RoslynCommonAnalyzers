# PSH1101 - Carry LINQ predicates at the terminal call

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Collections |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `Where` call is followed directly by `Any()`, `Count()`, `First()`,
`FirstOrDefault()`, `Last()`, `LastOrDefault()`, `Single()`, or `SingleOrDefault()`.
The final call has no arguments. Both calls must be `System.Linq.Enumerable`
methods; `Queryable` calls are not reported.

The final method can apply the filter itself, removing the separate `Where` call.

## Example

Reported:

```csharp
using System.Linq;

int[] values = { -1, 0, 1 };
bool hasPositive = values.Where(value => value > 0).Any();
```

Use:

```csharp
using System.Linq;

int[] values = { -1, 0, 1 };
bool hasPositive = values.Any(value => value > 0);
```

## Code fix

The fix removes `Where` and moves its argument into the final call. It keeps the
filter expression. Comments and line breaks attached to the removed call are not
all preserved.

A `Where` filter that takes both a value and an index is also reported. The final
methods have no matching two-parameter filter overload, so accepting the fix in
that case produces code that does not compile. Keep the indexed filter or rewrite
the operation by hand.

## Configuration

Enabled by default at `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1101.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the filter needs the element index, or when keeping the filtering
step separate makes the code easier to maintain and its cost is acceptable.
