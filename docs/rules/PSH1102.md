# PSH1102 - Filter LINQ values by type once

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Collections |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `Where` filter whose body is an `is` type test is followed directly by
`Cast<T>()`, with the same type written in both places. Both calls must be
`System.Linq.Enumerable` methods. A different cast type, a filter with a block
body, or a `Queryable` chain is not reported.

For a filter that only checks each element's type, `OfType<T>()` does both jobs:
it keeps matching, non-null elements and returns them as `T`.

## Example

Reported:

```csharp
using System.Linq;

object[] values = { "one", 2, "three" };
var strings = values.Where(value => value is string).Cast<string>();
```

Use:

```csharp
using System.Linq;

object[] values = { "one", 2, "three" };
var strings = values.OfType<string>();
```

## Code fix

The fix replaces `Where(...).Cast<T>()` with `OfType<T>()`. It removes the whole
filter, including comments inside it; comments between the removed calls can also
be lost.

Check that the filter tests only the element's type. A typed property pattern
such as `value is string { Length: > 0 }` is also reported, but the fix drops its
length check. A type test on an expression other than the element also needs a
manual edit to preserve what it checks.

## Configuration

Enabled by default at `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1102.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the filter does more than check the element's type and replacing it
with `OfType<T>()` would change which values are returned. Keep a separate filter
if it communicates a useful step and its cost is acceptable.
