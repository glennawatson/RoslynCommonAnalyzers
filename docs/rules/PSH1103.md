# PSH1103 — Prefer the collection's own count over enumerating

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Collections |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A parameterless LINQ `Count()` or `Any()` call uses a collection whose declared
type exposes a public instance `int` property named `Count` or `Length`. Arrays
and strings use `Length`. Collection interfaces such as `ICollection<T>` and
`IReadOnlyCollection<T>`, including generic constraints that expose their count,
are also supported.

Read the collection's size directly to avoid the extra LINQ call. LINQ already
uses a count property for some collections; it does not always walk the elements.

The rule does not report calls with a filter argument, direct static calls such as
`Enumerable.Count(list)`, or a variable declared as plain `IEnumerable<T>`.
A count available only through an explicit interface implementation on a concrete
type is not reported.

## Example

Reported:

```csharp
using System.Collections.Generic;
using System.Linq;

var list = new List<int> { 1, 2, 3 };
int total = list.Count();
bool hasItems = list.Any();
bool isEmpty = !list.Any();
```

Use:

```csharp
using System.Collections.Generic;

var list = new List<int> { 1, 2, 3 };
int total = list.Count;
bool hasItems = list.Count > 0;
bool isEmpty = list.Count == 0;
```

## Code fix

The fix changes `Count()` to the property, `Any()` to a comparison with zero, and
`!Any()` to an equality check against zero. It uses `Length` where appropriate and
adds parentheses around comparisons inside larger expressions. Comments inside
the removed call parentheses are lost.

## Configuration

Enabled by default at `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1103.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress for a custom collection whose `Count` or `Length` is expensive or means
something other than the number of elements. Keep the LINQ call if its exception
on a null source is part of a contract you must preserve; a property read throws a
different exception.
