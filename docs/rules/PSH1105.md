# PSH1105 — Avoid double lookups on dictionaries and sets

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Collections |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An `if` checks membership before a single `Add` or `Remove` call that can do the
lookup itself. The `if` has no `else`, and its body contains only that call, with
or without braces.

| Condition | Body | Replacement |
| --- | --- | --- |
| `map.ContainsKey(key)` | `map.Remove(key);` | `map.Remove(key);` |
| `!map.ContainsKey(key)` | `map.Add(key, value);` | `map.TryAdd(key, value);` |
| `!set.Contains(item)` | `set.Add(item);` | `set.Add(item);` |
| `set.Contains(item)` | `set.Remove(item);` | `set.Remove(item);` |

The dictionary or set and its key must match in both calls. They must be variables
or simple member accesses; a key can also be a literal. Arguments must be unnamed.
`Remove` and the set's `Add` must return `bool`. The dictionary insertion form
requires an accessible instance `TryAdd` method that returns `bool`.

A guard around `List<T>.Add` is not reported: that method returns `void`, and
dropping the guard would allow duplicates.

## Example

Reported:

```csharp
using System.Collections.Generic;

var items = new HashSet<string> { "one" };
string item = "one";
if (items.Contains(item))
{
    items.Remove(item);
}
```

Use:

```csharp
using System.Collections.Generic;

var items = new HashSet<string> { "one" };
string item = "one";
items.Remove(item);
```

## Code fix

The fix replaces the whole `if`, including its braces, with the body call. For a
guarded dictionary insertion, it also changes `Add` to `TryAdd`. Comments before
the `if` are kept; comments on the removed condition or braces, and comments
before the body call inside the block, can be lost.

The replacement evaluates the dictionary value argument even when the key is
present. For example, `map.TryAdd(key, CreateValue())` always calls `CreateValue`.
Keep the guard when that work must happen only for a missing key.

## Configuration

Enabled by default at `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1105.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when constructing the value is expensive or has effects that must remain
conditional. Also suppress for custom collection methods or property getters
whose behavior depends on keeping the membership check.
