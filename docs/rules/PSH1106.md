# PSH1106 — Index collections directly instead of using LINQ element access

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Collections |
| Severity | Warning |
| Code fix | Yes, with limits |
| Default | Enabled |

## Cause

A LINQ `First()`, `Last()`, or `ElementAt(index)` call uses a one-dimensional
array, string, or a type that is or implements `IList<T>` or `IReadOnlyList<T>`.
`Last()` also requires a `Count` or `Length` property on the declared type.

An indexer reads the element directly and avoids the LINQ call. LINQ already uses
an indexer for some collection types; it does not always walk the elements.

Calls with a filter argument, `FirstOrDefault`, `LastOrDefault`, direct static calls
such as `Enumerable.First(list)`, and plain `IEnumerable<T>` variables are not reported.

## Example

Reported:

```csharp
using System.Collections.Generic;
using System.Linq;

var list = new List<int> { 1, 2, 3 };
int first = list.First();
int last = list.Last();
int third = list.ElementAt(2);
```

Use:

```csharp
using System.Collections.Generic;

var list = new List<int> { 1, 2, 3 };
int first = list[0];
int last = list[list.Count - 1];
int third = list[2];
```

## Code fix

The fix changes `First()` to `[0]`, `ElementAt(index)` to `[index]`, and `Last()`
to `[Count - 1]`, using the same collection's count. Arrays and strings use
`Length`. Comments attached to the removed method call can be lost.

For `Last()`, the fix writes the collection expression twice. It is offered only
for a variable, `this`, or a simple member-access chain. A method call such as
`Create().Last()` is reported without a fix. Store its result in a local first.
Use a local for a property getter too if evaluating it twice would change behavior.

## Configuration

Enabled by default at `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1106.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when callers depend on the exception thrown for an empty collection,
invalid index, or null source: direct indexing can throw a different exception.
For a custom list, keep the LINQ call if indexing has a different order, cost, or
behavior. An explicitly implemented indexer may require accessing the list through
its interface before the replacement will compile.
