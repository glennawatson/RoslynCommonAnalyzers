# PSH1107 - Filter sequences before sorting them

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Collections |
| Severity | Warning |
| Code fix | Yes, with limits |
| Default | Enabled |

## Cause

A `Where` call follows `OrderBy`, `OrderByDescending`, `ThenBy`, or
`ThenByDescending` directly. Both calls must be `System.Linq.Enumerable` methods
and each must take one lambda with one parameter. Calls with a comparer, named
filter functions, index-taking filters, and `Queryable` chains are not reported.

Filtering first avoids sorting values that the filter will discard.

## Example

Reported:

```csharp
using System.Linq;

int[] values = { 3, -1, 2 };
var positives = values.OrderBy(value => value).Where(value => value > 0);
```

Use:

```csharp
using System.Linq;

int[] values = { 3, -1, 2 };
var positives = values.Where(value => value > 0).OrderBy(value => value);
```

## Code fix

The fix moves `Where` before a single `OrderBy` or `OrderByDescending`, keeping
the filter and sort expressions. Comments and line breaks between the calls can
be lost or moved.

There is no automated fix after `ThenBy` or `ThenByDescending`, or when the sort
itself immediately follows another sort. Move the filter before the whole sort
chain by hand.

## Configuration

Enabled by default at `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1107.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the filter must see elements in sorted order, or when the filter or
sort function changes state, logs, or throws in a way that depends on execution
order. Moving the filter also stops the sort function from running on discarded
elements. Keep the order when those effects are required.
