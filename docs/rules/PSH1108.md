# PSH1108 - Chain secondary sorts with ThenBy

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Collections |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

`OrderBy` or `OrderByDescending` follows another `OrderBy`, `OrderByDescending`,
`ThenBy`, or `ThenByDescending` call directly. Both calls must be
`System.Linq.Enumerable` methods, each with one lambda argument taking one
parameter. Comparer overloads, named key functions, and `Queryable` chains are
not reported.

A second `OrderBy` makes its key the primary sort key. The earlier ordering only
breaks ties. Use `ThenBy` when the earlier key should stay primary; this also
avoids creating a separate primary sort.

## Example

Reported:

```csharp
using System.Linq;

int[] values = { 3, 2, 1, 4 };
var ordered = values.OrderBy(value => value % 2).OrderBy(value => value);
```

To put even numbers first, then sort the numbers within each group:

```csharp
using System.Linq;

int[] values = { 3, 2, 1, 4 };
var ordered = values.OrderBy(value => value % 2).ThenBy(value => value);
```

## Code fix

The fix changes only the second method name: `OrderBy` becomes `ThenBy`, and
`OrderByDescending` becomes `ThenByDescending`. It keeps the key expression and
sort direction. This changes key priority and can change the result order; accept
it only when the first sort key should take priority.

## Configuration

Enabled by default at `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1108.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the second sort is deliberately the primary sort and the existing
order must be preserved. A separate sort can also be intentional when composing
independent query steps and its cost is acceptable.
