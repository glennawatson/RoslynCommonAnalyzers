# PSH1109 - Merge consecutive Where calls

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Collections |
| Severity | Warning |
| Code fix | Yes, with limits |
| Default | Enabled |

## Cause

Two `System.Linq.Enumerable.Where` calls appear directly next to each other.
Both filters are lambdas with one parameter and an expression body. Filters with
a block body, index-taking filters, named filter functions, and `Queryable` chains
are not reported.

One `Where` with `&&` expresses both conditions. The second condition runs only
when the first is true. LINQ can already combine consecutive filters internally,
so the runtime and source collection affect the performance saving.

## Example

Reported:

```csharp
using System.Linq;

int[] values = { -1, 5, 12 };
var matches = values.Where(value => value > 0).Where(value => value < 10);
```

Use:

```csharp
using System.Linq;

int[] values = { -1, 5, 12 };
var matches = values.Where(value => (value > 0) && (value < 10));
```

## Code fix

The fix removes the second `Where`, joins the filter bodies with `&&`, and adds
parentheses where needed. It keeps the first parameter name and changes references
to the second parameter to match it. Comments around the filter bodies or the
removed call can be lost.

When the parameter names differ and the first name also occurs in the second
body, the diagnostic has no fix. Rename the parameters to an unused name or merge
the filters by hand. If the first lambda is `static` but the second reads an outer
local variable, merge by hand and remove `static` so the combined lambda can read it.

## Configuration

Enabled by default at `warning`. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1109.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when separate filters make distinct conditions easier to understand or
maintain and measurements show their cost is acceptable.
