# PSH1111 — Use Contains for membership tests

**Category:** Collections
**Severity:** Warning, enabled by default
**Code fix:** Yes

## Cause

A LINQ `Any` call tests only `x == value` or `value == x`, and the collection
type provides a `Contains` method for its elements. `Contains` avoids calling
the lambda for each element. A hash set can also use its lookup table instead
of checking elements one at a time.

The lambda must return the equality expression directly. The compared value
must not refer to the lambda parameter. Lists, sets, and collections declared
as `ICollection<T>` qualify; a plain `IEnumerable<T>` does not. A block lambda
such as `x => { return x == value; }` is not reported here.

## Example

```csharp
using System.Collections.Generic;
using System.Linq;

public class Example
{
    // Before
    public bool Before(HashSet<int> values, int target)
        => values.Any(x => x == target);

    // After
    public bool After(HashSet<int> values, int target)
        => values.Contains(target);
}
```

## How to fix violations

The code fix replaces `Any` with `Contains`, removes the lambda, and passes the
compared value as the argument. Comments inside the removed lambda are lost
unless they are inside the retained value expression.

The compared value is evaluated once, even for an empty collection. `Contains`
uses the collection's equality rules, which can differ from `==`. For example,
a string set with `StringComparer.OrdinalIgnoreCase` ignores letter case in
`Contains`, while the string `==` operator does not.

## Configuration

The rule is enabled at `warning` by default. In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PSH1111.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none`.
There are no rule-specific options.

## When to suppress

Suppress when `==` must keep different equality rules from `Contains`, or when
evaluating the compared expression once would change required behavior.
