# PSH1112 — Seed the collection through its constructor

**Category:** Collections
**Severity:** Warning, enabled by default
**Code fix:** Yes, including Fix All

## Cause

A local declaration creates an empty `List<T>` or `HashSet<T>`, and the very
next statement calls `AddRange(source)` or `UnionWith(source)` on it. Passing
the source during creation lets the collection use the source's count when
it is available and avoids a separate population statement.

The declaration must be inside a block and declare one variable. The creation
must have no constructor arguments or collection initializer. The source must
not refer to the new collection. A capacity, comparer, existing source, or
intervening statement prevents the report.

## Example

```csharp
using System.Collections.Generic;

public class Example
{
    // Before
    public List<int> Before(int[] source)
    {
        var list = new List<int>();
        list.AddRange(source);
        return list;
    }

    // After
    public List<int> After(int[] source)
    {
        var list = new List<int>(source);
        return list;
    }
}
```

## Code fix

The fix moves the source into the initializer and deletes the `AddRange` or
`UnionWith` statement. Comments attached to the deleted statement are lost;
move comments you need before accepting the fix.

With C# 12 or later, an explicitly typed declaration, and the default preference,
the fix uses a collection expression, such as `List<int> list = [.. source];`.
A `var` declaration, an older language version, or a preference of `false`
uses the constructor, as in the example.

## Configuration

The rule is enabled at `warning` by default. In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PSH1112.severity = warning
performancesharp.prefer_collection_expressions = true
```

The preference accepts `true` (default) or `false`. Set it to `false` to use
seeded constructors in the fix. Severity accepts `error`, `warning`,
`suggestion`, `silent`, or `none`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when measurement for your source shows that the two-step form is
preferable. If only the collection-expression style is unwanted, set the
preference to `false` instead.
