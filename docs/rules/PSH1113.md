# PSH1113 — Sort naturally instead of ordering by the element itself

**Category:** Collections
**Severity:** Warning, enabled by default
**Code fix:** Yes, including Fix All

## Cause

A LINQ `OrderBy(x => x)` or `OrderByDescending(x => x)` call returns each element
unchanged as its sort key. `Order()` and `OrderDescending()` compare the elements
directly and remove the unnecessary key-selection function.

The rule requires `Enumerable.Order`, available in .NET 7 and later. It does not
report a lambda that selects a member, a block lambda, or a `Queryable` call
used by a query provider such as a database library.

## Example

```csharp
using System.Collections.Generic;
using System.Linq;

public class Example
{
    // Before
    public IEnumerable<int> Before(int[] values) => values.OrderBy(x => x);

    // After
    public IEnumerable<int> After(int[] values) => values.Order();
}
```

## Code fix

The fix changes `OrderBy` to `Order`, or `OrderByDescending` to `OrderDescending`,
and removes the lambda. It keeps a comparer argument: `OrderBy(x => x, comparer)`
becomes `Order(comparer)`. Comments inside the removed lambda or around the
comparer argument are lost.

## Configuration

The rule is enabled at `warning` by default. In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PSH1113.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none`.
There are no rule-specific options.

## When to suppress

Suppress when this source file must also compile for a target without `Order`
or `OrderDescending`. Otherwise the shorter call expresses the same sort.
