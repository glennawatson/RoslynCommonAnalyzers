# PSH1114 — Freeze static lookup collections that are never mutated

**Category:** Collections
**Severity:** Warning when enabled; disabled by default
**Code fix:** Available for some initializers, including Fix All

## Cause

A private `static readonly` field holds a `Dictionary<TKey, TValue>` or
`HashSet<T>`, has an initializer in its declaration, and is only used for
supported reads. A `FrozenDictionary` or `FrozenSet` spends more work during
creation to make repeated lookups faster. Frozen collections require .NET 8
or another reference that supplies `System.Collections.Frozen`.

Supported reads are `ContainsKey`, `TryGetValue`, `Contains`, `Count`, indexer
reads, `GetEnumerator`, and `foreach`. Other uses, including passing or returning
the collection, accessing `Keys` or `Values`, or calling mutation methods,
prevent the report. Fields in partial types, fields with wider visibility,
and declarations containing multiple fields are not reported.

## Why it is opt-in

Freezing costs time and memory during startup. Enable this rule only for a
collection built once and read often enough to repay that cost. Benchmark
construction and lookups together before changing a table.

## Example

Before:

```csharp
using System.Collections.Frozen;
using System.Collections.Generic;

public class Example
{
    private static readonly Dictionary<string, int> Lookup = new Dictionary<string, int>
    {
        ["one"] = 1,
    };

    public int Read(string key) => Lookup.TryGetValue(key, out var value) ? value : 0;
}
```

After:

```csharp
using System.Collections.Frozen;
using System.Collections.Generic;

public class Example
{
    private static readonly FrozenDictionary<string, int> Lookup = new Dictionary<string, int>
    {
        ["one"] = 1,
    }.ToFrozenDictionary();

    public int Read(string key) => Lookup.TryGetValue(key, out var value) ? value : 0;
}
```

## Code fix

The fix changes the field type and wraps its initializer with `ToFrozenDictionary`
or `ToFrozenSet`. It keeps the original construction and copies an explicit
comparer argument into the freezing call. A `new(...)` initializer becomes
`new Dictionary<...>(...)` or `new HashSet<...>(...)` to retain its original type.
Comments immediately before or after the initializer can be lost.

The fix requires a field type written as `Dictionary<...>` or `HashSet<...>` and
an initializer written with `new`. A fully qualified field type or a factory
call can be reported without a fix. If the file has no top-level
`using System.Collections.Frozen;`, the fix uses fully qualified names instead
of adding an import.

If the comparer argument calls a method, the fix repeats that call. Ensure both
calls return the intended comparer. When copying from another dictionary without
an explicit comparer, check the frozen result's comparer before accepting the fix.

## Configuration

The rule is disabled by default. Enable it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PSH1114.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none`.
Use `none` to disable it. There are no rule-specific options.

## When to suppress

Leave the rule disabled or suppress a field when lookups are infrequent,
startup cost matters more, or a benchmark shows no overall gain. Keep the
original collection when callers depend on its enumeration order or comparer
behavior and the frozen collection would change that behavior.
