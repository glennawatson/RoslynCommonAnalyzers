# PSH1115 — Insert-if-absent should probe the dictionary once

**Category:** Collections
**Severity:** Warning, enabled by default
**Code fix:** Available for the `ContainsKey` form, including Fix All

## Cause

An `if (!map.ContainsKey(key))` statement contains only `map[key] = value`,
with no `else`, and the dictionary type provides `TryAdd`. Testing and then
writing the same key performs two lookups; `TryAdd` combines them.

The rule also reports `if (!map.TryGetValue(key, out ...))` on `Dictionary<TKey,
TValue>` when its body ends by assigning `map[key]` or calling `map.Add(key, value)`.
This form suggests `CollectionsMarshal.GetValueRefOrAddDefault`, available in
.NET 6 and later. It requires a manual rewrite. Neither form is reported with
an `else` or a final write to a different dictionary or key.

## Example

```csharp
using System.Collections.Generic;

public class Example
{
    // Before
    public void Before(Dictionary<string, int> map, string key, int value)
    {
        if (!map.ContainsKey(key))
        {
            map[key] = value;
        }
    }

    // After
    public void After(Dictionary<string, int> map, string key, int value)
    {
        map.TryAdd(key, value);
    }
}
```

## Code fix

For the `ContainsKey` form, the fix replaces the entire `if` statement with
`map.TryAdd(key, value);`. It removes the condition and braces. Comments inside
the removed statement are not all preserved.

`TryAdd` evaluates `value` even if the key exists. If `value` is an expensive
calculation or changes other state, accepting the fix changes when that work
happens. Expressions used for the dictionary and key are evaluated once by
the replacement, rather than again for the write.

There is no code fix for the `TryGetValue` form. `GetValueRefOrAddDefault` returns
a reference to the stored value and inserts a default value when the key is
missing. A manual rewrite must fill that value and must not add or remove
dictionary entries while the reference is in use. If value creation throws,
the inserted default entry needs handling too.

## Configuration

The rule is enabled at `warning` by default. In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PSH1115.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none`.
There are no rule-specific options.

## When to suppress

Suppress when the value must be computed only for a missing key, when the
replacement would change required evaluation behavior, or when managing a
reference to the dictionary's value adds complexity without a measured gain.
