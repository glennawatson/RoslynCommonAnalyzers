# PSH1117 — Ask the collection whether it is empty

**Category:** Collections
**Severity:** Warning, enabled by default
**Code fix:** Yes, including Fix All

## Cause

A comparison uses `Count` or `Length` to test whether a collection is empty,
and the collection type has a Boolean `IsEmpty` property. `IsEmpty` states the
question directly. On concurrent collections, it also avoids the work needed
to obtain a count across the collection.

The rule covers both operand orders and the comparisons in the table below.
It does not report thresholds such as `Count > 1`, or types such as `List<T>`
and `string` that have no `IsEmpty` property.

## Example

```csharp
using System.Collections.Concurrent;

public class Example
{
    // Before
    public bool Before(ConcurrentQueue<int> queue) => queue.Count == 0;

    // After
    public bool After(ConcurrentQueue<int> queue) => queue.IsEmpty;
}
```

## Code fix

The fix replaces the whole comparison, preserving whether it asks for an empty
or nonempty collection. The same replacements apply to `Length`.

| Comparison | Replacement |
| --- | --- |
| `Count == 0`, `Count <= 0`, `Count < 1` | `IsEmpty` |
| `Count != 0`, `Count > 0`, `Count >= 1` | `!IsEmpty` |

Comments within the removed comparison are lost; comments around the whole
expression are kept.

## Configuration

The rule is enabled at `warning` by default. In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PSH1117.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none`.
There are no rule-specific options.

## When to suppress

Suppress for a custom type whose `IsEmpty` property has a different meaning or
cost from testing its count. For a concurrent collection, neither a count
comparison nor `IsEmpty` guarantees that the next read will succeed; use an
operation such as `TryDequeue` when you need to take an item.
