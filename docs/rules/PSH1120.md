# PSH1120 — Do not materialize a sequence just to enumerate it

**Category:** Collections
**Severity:** Warning, enabled by default
**Code fix:** Yes, including Fix All

## Cause

A `foreach` reads directly from a LINQ `ToList()` or `ToArray()` call. These
calls copy the entire sequence into a new collection before the loop starts.
Iterating the source directly avoids that temporary copy.

The rule does not report a copy stored in a local variable, a custom method
or overload with arguments, or `await foreach`. It also skips a loop whose
body mentions the source name, even for a read such as `items.Count`. This
includes sources written with parentheses, member access, or a LINQ chain.

## Example

```csharp
using System.Collections.Generic;
using System.Linq;

public class Example
{
    // Before
    public int Before(IEnumerable<int> items)
    {
        var total = 0;
        foreach (var item in items.Where(i => i > 0).ToList())
        {
            total += item;
        }

        return total;
    }

    // After
    public int After(IEnumerable<int> items)
    {
        var total = 0;
        foreach (var item in items.Where(i => i > 0))
        {
            total += item;
        }

        return total;
    }
}
```

## Code fix

The fix removes the final `ToList()` or `ToArray()` call and formats the remaining
expression. The loop body stays the same. Comments inside the removed call are
lost.

The source is read as the loop runs, instead of being fully read before the
first iteration. A `break` can therefore stop reading the source early.

## Configuration

The rule is enabled at `warning` by default. In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PSH1120.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none`.
There are no rule-specific options.

## When to suppress

Suppress when the copy is an intentional snapshot, when called code or another
reference changes the source during the loop, or when the source must finish
running before the loop body starts. The rule's source-name check does not
detect every indirect modification.
