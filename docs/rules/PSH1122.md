# PSH1122 — Use a sorted set's Min and Max properties

**Category:** Collections
**Severity:** Warning, enabled by default
**Code fix:** Yes, including Fix All

## Cause

A LINQ `Min()` or `Max()` call has no arguments, and its collection is declared
as `SortedSet<T>` or `ImmutableSortedSet<T>`. The set already keeps its elements
in order. Its `Min` and `Max` properties use that order to find an end without
comparing every element again.

Calls with a selector or comparer are not reported. Neither are collections
declared as `ISet<T>` or `IEnumerable<T>`, other collection types, or `Queryable`
calls.

## Example

```csharp
using System.Collections.Generic;
using System.Linq;

public class Example
{
    // Before
    public int Before(SortedSet<int> values) => values.Min();

    // After
    public int After(SortedSet<int> values) => values.Min;
}
```

## Code fix

The fix removes the call parentheses, changing `set.Min()` to `set.Min`, or
`set.Max()` to `set.Max`, and formats the replacement. Comments inside the
removed parentheses are lost.

The property uses the set's comparer. The parameterless LINQ call uses the
element type's default ordering. On an empty set, the property returns
`default(T)`; LINQ throws for non-nullable value types such as `int`.

## Configuration

The rule is enabled at `warning` by default. In `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PSH1122.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none`.
There are no rule-specific options.

## When to suppress

Suppress when you need LINQ's default ordering instead of the set's custom
ordering, or when callers depend on an exception for an empty set. Null elements
also need care: the `Min` property can return null from the start of the set,
while LINQ `Min()` skips nulls when a non-null element exists.
