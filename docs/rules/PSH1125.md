# PSH1125 — Do not enumerate the same sequence twice

**Category:** Collections  
**Default severity:** Warning  
**Code fix:** None

## Cause

You read an `IEnumerable<T>` or `IEnumerable` parameter or explicitly typed local
more than once in the same body. A lazy sequence produces items as you read it.
Reading it twice can repeat a query, file read, or calculation, or give different
results.

The rule counts `foreach` and LINQ calls that consume items, such as `Any`, `Count`,
`First`, `Sum`, and `ToList`. A chain such as `source.Where(...).Count()` also
counts. Passing the sequence to an unrelated method does not count.

## Example

Before:

```csharp
using System.Collections.Generic;
using System.Linq;

public class Reader
{
    public int FirstOrZero(IEnumerable<int> source)
        => source.Any() ? source.First() : 0;
}
```

After, read only once:

```csharp
using System.Collections.Generic;
using System.Linq;

public class Reader
{
    public int FirstOrZero(IEnumerable<int> source) => source.FirstOrDefault();
}
```

## What is not reported

- Arrays and collection types such as `List<T>` and `IReadOnlyCollection<T>`.
- Locals declared with `var`, and indexer parameters.
- Locals initialized with `new`, an array, a collection expression, or a call such
  as `ToList()` or `ToArray()`.
- Variables reassigned or passed by `ref` or `out` anywhere in the body.
- Reads in opposite `if`/`else` or conditional branches, different switch branches,
  or a `try` body and its `catch`.

## How to fix violations

Combine the reads into one pass where possible. If you need several passes, save
the items once with `ToList()` or `ToArray()`, then use that collection. This stores
all items in memory, so use it only for finite sequences that fit. If callers must
provide a collection, use a collection type in the parameter instead.

There is no automatic code fix; the right choice depends on how the method uses
the items.

## Configuration

The rule is enabled by default with warning severity. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1125.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.
Use `none` to disable the rule; `default` restores its warning severity.
See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when the sequence is known to be cheap and safe to read again, or when
each read must deliberately obtain fresh results. Keep that reason near the code.
