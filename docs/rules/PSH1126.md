# PSH1126 — Ask whether an async sequence has elements without counting them

**Category:** Collections  
**Default severity:** Warning  
**Code fix:** Yes, including Fix All

## Cause

You compare an awaited `CountAsync()` result with `0` or `1` only to ask whether
any items exist. Counting can process every match. `AnyAsync()` lets the query
provider stop when it finds a match.

The count must return `Task<int>` or `ValueTask<int>`. The provider must offer an
`AnyAsync` extension in the same class, accepting the same sequence and argument
types and returning `Task<bool>` or `ValueTask<bool>`.

## Example

These examples use Entity Framework Core and require its package reference.

Before:

```csharp
using System.Linq;
using System.Threading.Tasks;
using Microsoft.EntityFrameworkCore;

public class Reader
{
    public async Task<bool> HasItems(IQueryable<int> query)
        => await query.CountAsync() > 0;
}
```

After:

```csharp
using System.Linq;
using System.Threading.Tasks;
using Microsoft.EntityFrameworkCore;

public class Reader
{
    public async Task<bool> HasItems(IQueryable<int> query)
        => await query.AnyAsync();
}
```

## Code fix

The fix replaces the whole comparison and keeps the query, predicate, and
cancellation-token arguments. It is offered only when the replacement call is
valid at that location.

| Count comparison | Replacement |
| --- | --- |
| `await q.CountAsync() > 0` | `await q.AnyAsync()` |
| `await q.CountAsync() >= 1` | `await q.AnyAsync()` |
| `await q.CountAsync() != 0` | `await q.AnyAsync()` |
| `await q.CountAsync() == 0` | `!await q.AnyAsync()` |
| `await q.CountAsync() < 1` | `!await q.AnyAsync()` |
| `await q.CountAsync() <= 0` | `!await q.AnyAsync()` |

Reversed comparisons, such as `0 < await q.CountAsync()`, are also reported.
Comments attached to the removed comparison operator or number are not kept.

Counts stored in a variable, comparisons needing an exact count, and calls without
a matching `AnyAsync` are not reported. A call wrapped in `ConfigureAwait(...)`
is not reported either.

## Configuration

The rule is enabled by default with warning severity. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1126.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.
Use `none` to disable the rule; `default` restores its warning severity.
See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when a custom provider's `AnyAsync` does not preserve the required result
or effects, or measurements show that its count query is preferable.
