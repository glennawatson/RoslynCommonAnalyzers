# PSH1127 — Clear an array instead of filling it with its default

**Category:** Collections  
**Default severity:** Warning  
**Code fix:** Yes, including Fix All

## Cause

You call `Array.Fill` with `default`, `default(T)`, `null`, `false`, or the literal
`0`. `Array.Clear` asks the runtime to reset the array's elements directly.

For `null`, the element type must be a reference type or nullable value type. For
`0` and `false`, it must be a non-nullable value type. Filling an `object[]` with
`0` is not reported: that stores zero values, while clearing it stores nulls.
Other fill values are not reported.

## Example

Before:

```csharp
using System;

int[] buffer = { 1, 2, 3 };
Array.Fill(buffer, 0);
```

After, on .NET 6 or later:

```csharp
using System;

int[] buffer = { 1, 2, 3 };
Array.Clear(buffer);
```

## Code fix

The fix replaces `Array.Fill(array, value)` with `Array.Clear(array)`. A ranged
call, `Array.Fill(array, value, start, count)`, becomes
`Array.Clear(array, start, count)`. It removes the fill value and reformats the
call. Comments on the removed value and between arguments can be lost.

Where `Array.Clear(array)` is unavailable, the whole-array fix uses
`Array.Clear(array, 0, array.Length)`. This fallback is limited to names and member
accesses, such as `buffer` or `this.Buffer`; it is not offered for `GetBuffer()`.
It reads the array expression twice, so store a property result in a local first
if reading the property does work or can return a different array.

The rule reports nothing when the target framework lacks `Array.Fill` or
`Array.Clear`. A fix is offered only when its replacement call is valid.

## Configuration

The rule is enabled by default with warning severity. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1127.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.
Use `none` to disable the rule; `default` restores its warning severity.
See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when the older-framework fallback would repeat a property read that must
happen once and you cannot introduce a local, or measurements favor `Fill` for
your target runtime.
