# PSH1202 — Append characters as char, not single-character strings

**Category:** Strings  
**Default severity:** Warning  
**Code fix:** Yes, including Fix All

## Cause

You pass a one-character string literal to `StringBuilder.Append(string)` or
`StringBuilder.Insert(int, string)`. The character overload writes the character
directly instead of handling it as a string.

Only ordinary string literals qualify, including escaped characters. Variables,
longer strings, verbatim strings, raw strings, and interpolated strings are not
reported. `AppendLine` and `Insert` overloads with extra arguments are also left
alone. The matching character overload must exist on the target framework.

## Example

Before:

```csharp
using System.Text;

var builder = new StringBuilder();
builder.Append("x");
builder.Insert(0, ",");
```

After:

```csharp
using System.Text;

var builder = new StringBuilder();
builder.Append('x');
builder.Insert(0, ',');
```

## Code fix

The fix changes only the string literal to a character literal. It escapes quotes,
backslashes, and control characters as needed, and keeps surrounding comments.
Fix All handles multiple calls, including chained appends.

## Configuration

The rule is enabled by default with warning severity. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1202.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.
Use `none` to disable the rule; `default` restores its warning severity.
See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when retaining a string literal is needed to keep a shared code template
consistent. Otherwise the character overload produces the same text.
