# PSH1203 — Let StringBuilder do the formatting work

**Category:** Strings  
**Default severity:** Warning  
**Code fix:** Yes, including Fix All

## Cause

You pass a `string.Format`, parameterless `ToString`, or `Substring` result to
`StringBuilder.Append(string)`. The builder can accept the original values or
string slice, avoiding a temporary string.

`ToString()` is reported for strings, booleans, characters, and numeric types with
a matching `Append` overload. Calls with format or culture arguments and calls on
other types are not reported. `Substring` is reported only on a name or member
access, such as `text` or `this.Text`. `AppendLine` is not reported. The required
builder overload must exist on the target framework.

## Example

Before:

```csharp
using System.Text;

var builder = new StringBuilder();
int value = 42;
string text = "abcdef";
builder.Append(string.Format("{0:N2}", value));
builder.Append(value.ToString());
builder.Append(text.Substring(2, 3));
```

After:

```csharp
using System.Text;

var builder = new StringBuilder();
int value = 42;
string text = "abcdef";
builder.AppendFormat("{0:N2}", value);
builder.Append(value);
builder.Append(text, 2, 3);
```

## Code fix

The fix moves `string.Format` arguments, including a format provider, into
`AppendFormat`. For `ToString()`, it passes the value directly. For
`text.Substring(start, count)`, it writes `Append(text, start, count)`.

The one-argument substring form becomes `Append(text, start, text.Length - start)`.
This reads both `text` and `start` twice. Store property results, method results,
or increments in locals first if repeating them could change the result. The
substring rewrite rebuilds the argument list; comments between its arguments can
be lost. Comments attached to removed calls can also be lost.

Removing `ToString()` on a null string changes an exception into an append that
adds nothing. `AppendFormat` can also leave partial text in the builder if
formatting throws, whereas `string.Format` finishes before `Append` starts.

## Configuration

The rule is enabled by default with warning severity. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1203.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.
Use `none` to disable the rule; `default` restores its warning severity.
See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when the original exception behavior or the builder's state after an
exception is required. For a substring expression with effects, prefer introducing
locals and making the change manually.
