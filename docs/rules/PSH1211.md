# PSH1211 — Pass values directly instead of ToString results

**Category:** Strings
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A parameterless `ToString()` call creates text for an operation that can use
the value directly. Removing it lets that operation handle the formatting
and can avoid a temporary string.

The rule reports two cases:

- A method argument where another overload accepts the value directly and
  the other parameter types match. An overload taking only `object` does not
  qualify. Named arguments and calls to extension methods are skipped.
- A value inside an interpolated string that produces a plain `string` and
  contains more than one part, such as `$"{count.ToString()} items"`.

Calls with a format or culture argument are not reported. Neither are
`FormattableString` values or interpolated strings passed to custom formatting
handlers. Values declared as `ref struct`, including spans, need framework
support to be formatted directly inside interpolation. They are reported
there only when `DefaultInterpolatedStringHandler` is available.

## Example

Bad:

```csharp
using System;

public class Output
{
    public void Write(int value) => Console.Write(value.ToString());

    public string Label(int count) => $"{count.ToString()} items";
}
```

Corrected:

```csharp
using System;

public class Output
{
    public void Write(int value) => Console.Write(value);

    public string Label(int count) => $"{count} items";
}
```

## Code fix

The fix removes `.ToString()` and leaves the value in its place. A method call
then uses a value-taking overload; interpolation formats the value itself.
Comments attached to the removed method call can be lost.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.
Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PSH1211.severity = warning
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when a custom type's `ToString()` must run, or when the value-taking
overload formats or handles the value differently. Check null handling too:
calling `ToString()` on a null reference throws, while passing null directly
may be accepted.
