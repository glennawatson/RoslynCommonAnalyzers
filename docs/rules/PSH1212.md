# PSH1212 — Slice with AsSpan when the call accepts a span

**Category:** Strings
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A `Substring(start)` or `Substring(start, length)` result is passed directly
to a method that also accepts `ReadOnlySpan<char>` in that position. A span
is a view of the original characters, so `AsSpan` avoids creating a string
for the slice.

The other parameter types must match. The framework must provide `AsSpan`,
and `System.MemoryExtensions` must be in scope, usually through `using System;`.
The rule skips named arguments to the receiving method, extension-method
consumers, and substrings stored or returned on their own.

## Example

Bad:

```csharp
using System;

public class Reader
{
    public void Read(string value) => Use(value.Substring(1));

    private static void Use(string text) { }

    private static void Use(ReadOnlySpan<char> text) { }
}
```

Corrected:

```csharp
using System;

public class Reader
{
    public void Read(string value) => Use(value.AsSpan(1));

    private static void Use(string text) { }

    private static void Use(ReadOnlySpan<char> text) { }
}
```

## Code fix

The fix changes only `Substring` to `AsSpan`. It keeps the start and length
arguments, comments, and spacing. If the slice uses the named argument
`startIndex:`, change that name to `start:` manually to match `AsSpan`.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.
Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PSH1212.severity = warning
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when the string and span overloads do different work, or when the
call is part of a query that cannot use spans. If you depend on an exception
for null input, check that contract: `AsSpan(0)` accepts a null string as an
empty span, while `Substring(0)` throws.
