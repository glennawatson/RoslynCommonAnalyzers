# PSH1215 — Concatenate when there is no separator

**Category:** Strings
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

`string.Join` or `String.Join` is called with `""` or `string.Empty` as its
first argument. There is no separator to insert. `string.Concat` expresses
that intent directly and avoids work for separators.

The rule covers arrays, enumerable sequences, and separate value arguments.
It also covers span overloads when the framework provides a matching
`Concat` overload. Calls with a start and count, a named separator argument,
or a separator held in a variable are not reported. Neither are character
separators or nonempty strings.

## Example

Bad:

```csharp
public class TextJoiner
{
    public string Combine(string[] parts) => string.Join("", parts);
}
```

Corrected:

```csharp
public class TextJoiner
{
    public string Combine(string[] parts) => string.Concat(parts);
}
```

## Code fix

The fix renames `Join` to `Concat` and removes the separator argument.
It keeps the values in order, including separate arguments in calls such
as `string.Join("", a, b, c)`. Explicit generic type arguments are kept.
It reformats the call; comments attached to the removed separator can be lost.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.
Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.PSH1215.severity = warning
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when keeping the same `Join` form alongside related calls makes
rarely run code easier to maintain.
