# PSH1220 — Do not pass a length that reaches the end

**Category:** Strings
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A slice call passes a length of `text.Length - start`, where `text` and `start`
match the string and start argument. A start of `0` with `text.Length` is also
reported. The shorter call already means "take everything from here to the end."

This applies to `string.Substring`, `AsSpan`, `AsMemory`, and `Slice` on spans and
memory. It requires a matching overload without the length argument. The string
form works on .NET Framework and .NET Standard 2.0 too.

## Example

Before:

```csharp
public class TextSlice
{
    public string From(string text, int start) => text.Substring(start, text.Length - start);
}
```

After:

```csharp
public class TextSlice
{
    public string From(string text, int start) => text.Substring(start);
}
```

## What is not reported

- A separate length variable, or different arithmetic such as `text.Length - start - 1`.
- A method call or calculation used as the string or start argument.
- Named arguments or a custom type's `Slice` method.
- Code stored in an `Expression<...>` for a query provider.

## Code fix

The fix removes the length argument. It keeps the start argument, including `0`.
Comments on the removed argument or around the start argument can be lost.

## Configuration

Enabled by default at `warning` severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1220.severity = warning
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`.
See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when an explicit length makes a group of related slice operations easier
to maintain. Also keep the original call if reading a property fewer times would
change its behavior.
