# PSH1221 — Ask whether a string starts with a value, not where the value is

**Category:** Strings
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A string's `IndexOf` result is compared with `0` using `==` or `!=`. The zero can
be on either side. `IndexOf` can search the whole string, but this check only needs
to know whether the value is at the start.

The rule covers `IndexOf(char)`, `IndexOf(string)`, and
`IndexOf(string, StringComparison)` when the matching `StartsWith` overload exists.
The character form is not reported on .NET Framework or .NET Standard 2.0, which
lack `StartsWith(char)`.

## Example

Before:

```csharp
public class PrefixCheck
{
    public bool HasSlash(string text) => text.IndexOf('/') == 0;
}
```

After:

```csharp
public class PrefixCheck
{
    public bool HasSlash(string text) => text.StartsWith('/');
}
```

## Code fix

The fix replaces `IndexOf(...) == 0` with `StartsWith(...)`. For `!= 0`, it uses
`!StartsWith(...)`. It keeps the arguments and their comparison settings:

| Search | Prefix check |
| --- | --- |
| `IndexOf(char)` | `StartsWith(char)`, an exact character comparison |
| `IndexOf(string)` | `StartsWith(string)`, using the current culture |
| `IndexOf(string, StringComparison)` | `StartsWith(string, StringComparison)`, keeping that argument |

Comments attached to the removed comparison or zero can be lost.

## What is not reported

- Searches with a start index, or `IndexOf(char, StringComparison)`.
- Other comparisons, such as `>= 0` or `== 1`.
- Code stored in an `Expression<...>` for a query provider.

## Configuration

Enabled by default at `warning` severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1221.severity = warning
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`.
See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when shared code needs a consistent `IndexOf` pattern and the extra search
cost is acceptable.

## Related rules

[PSH1207](PSH1207.md) asks for an explicit `StringComparison` on string searches.
This fix keeps the comparison you wrote; it does not add one.
