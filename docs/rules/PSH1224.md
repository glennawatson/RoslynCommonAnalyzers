# PSH1224 — Convert bytes to hex in one call

**Category:** Strings
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

`BitConverter.ToString(bytes).Replace("-", "")` builds a string with hyphens and
then another string without them. `Convert.ToHexString` produces the hex text in
one call. Both use uppercase letters.

The rule also accepts `string.Empty` as the replacement and the
`BitConverter.ToString(bytes, start, length)` overload. It requires a matching
`Convert.ToHexString` overload, available in .NET 5 and later.

## Example

Before:

```csharp
using System;

public class HexFormatter
{
    public string Format(byte[] hash) => BitConverter.ToString(hash).Replace("-", "");
}
```

After:

```csharp
using System;

public class HexFormatter
{
    public string Format(byte[] hash) => Convert.ToHexString(hash);
}
```

## Code fix

The fix replaces the `ToString(...).Replace(...)` chain with
`Convert.ToHexString(...)`, keeping the byte array, offset, and count arguments.
A trailing call such as `ToLowerInvariant()` stays in place.

It uses `global::System.Convert` when `Convert` is not available by its short name.
Comments attached to the removed calls or `Replace` arguments can be lost.

## What is not reported

- `BitConverter.ToString` with its hyphens kept.
- Replacing hyphens with another separator, such as `":"`.
- A `ToString` call on a different type.
- Code stored in an `Expression<...>` for a query provider.

## Configuration

Enabled by default at `warning` severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1224.severity = warning
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`.
See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when the same source must also compile for an older target that lacks
`Convert.ToHexString`. The rule is silent when analyzing that older target alone.
