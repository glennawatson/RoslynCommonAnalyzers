# PSH1225 — Decode bytes to a string in one call

**Category:** Strings
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

`new string(encoding.GetChars(bytes))` creates a temporary character array and then
copies it into a string. Use `encoding.GetString(bytes)` to get the string directly.

The rule applies to `System.Text.Encoding` and derived types when `GetChars`
returns a character array and a matching `GetString` accepts the same arguments.
The byte-array overloads work on .NET Framework and .NET Standard 2.0 too.

## Example

Before:

```csharp
using System.Text;

public class TextDecoder
{
    public string Decode(byte[] bytes) => new string(Encoding.UTF8.GetChars(bytes));
}
```

After:

```csharp
using System.Text;

public class TextDecoder
{
    public string Decode(byte[] bytes) => Encoding.UTF8.GetString(bytes);
}
```

## Code fix

The fix removes `new string(...)` and changes `GetChars` to `GetString`. It keeps
the same encoding and arguments, including any byte index and count. Comments
inside the removed constructor or on the replaced method name can be lost.

## What is not reported

- A character array that is kept or used before creating a string.
- `new string(chars)` without a direct `GetChars` call.
- `GetChars` on a type unrelated to `Encoding`, or without a matching `GetString`.
- Code stored in an `Expression<...>` for a query provider.

## Configuration

Enabled by default at `warning` severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1225.severity = warning
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`.
See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress if a custom encoding gives `GetChars` and `GetString` different behavior.
The rule checks that the methods accept the same arguments, not that custom methods
produce the same text.
