# PSH1300 — Use System.Threading.Lock for a dedicated lock object

**Category:** Concurrency
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A `private readonly object` field is used only in `lock` statements. Using
`System.Threading.Lock` gives the compiler a dedicated locking API instead of the
general object-locking API.

The field must be initialized at its declaration with `new()` or `new object()`,
be the only variable in that declaration, and have at least one `lock` use.
Static fields are also eligible.

This rule requires C# 13 or later and a reference to `System.Threading.Lock`,
included in .NET 9 and later. It reports nothing when either requirement is missing.

## Example

Before:

```csharp
public class Counter
{
    private readonly object _gate = new();
    private int _count;

    public void Add()
    {
        lock (_gate)
        {
            _count++;
        }
    }
}
```

After:

```csharp
public class Counter
{
    private readonly System.Threading.Lock _gate = new();
    private int _count;

    public void Add()
    {
        lock (_gate)
        {
            _count++;
        }
    }
}
```

## How to fix violations

The code fix changes the field type to `System.Threading.Lock` and writes the
initializer as `new()`. It keeps the field name, modifiers, and `lock` statements.
Comments inside the replaced type or initializer can be lost.

## What is not reported

- A field that is also read, passed as an argument, or used with `Monitor` directly.
- Fields in partial types.
- Fields without explicit `private readonly` modifiers or without an initializer
  at the declaration.

## Configuration

Enabled by default at `warning` severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1300.severity = warning
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`.
See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when the same source must compile with an older language version or target
that lacks `System.Threading.Lock`.
