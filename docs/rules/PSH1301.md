# PSH1301 — Use a single task directly

**Category:** Concurrency
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

`Task.WhenAll` or `Task.WaitAll` receives one argument whose type is `Task` or
`Task<T>`. Combining a single task adds an array and coordination work without
having multiple operations to wait for.

For `Task<T>`, `WhenAll` is reported only in a direct statement such as
`await Task.WhenAll(operation);`, where the result is unused. Other forms are
excluded because `WhenAll` returns an array of results, while the original task
returns one value.

## Example

Before:

```csharp
using System.Threading.Tasks;

public class TaskRunner
{
    public async Task RunAsync(Task operation)
    {
        await Task.WhenAll(operation);
    }
}
```

After:

```csharp
using System.Threading.Tasks;

public class TaskRunner
{
    public async Task RunAsync(Task operation)
    {
        await operation;
    }
}
```

## Code fix

The fix replaces `Task.WhenAll(operation)` with `operation` and
`Task.WaitAll(operation)` with `operation.Wait()`. It adds parentheses around a
complex task expression when needed. Comments around the task argument or on the
removed call can be lost.

The `WaitAll` fix still blocks the thread. Use `await operation` when the enclosing
method can wait asynchronously.

## What is not reported

- Arrays or collections of tasks, even `new[] { operation }`.
- Zero or multiple task arguments, `WhenAny`, or `WaitAny`.
- Calls without a type name, such as `WhenAll(operation)` after a static import.
- Custom task subclasses or type parameters constrained to `Task`.
- `WhenAll` on `Task<T>` when the call is returned, stored, assigned to a discard,
  wrapped in parentheses, or followed by `ConfigureAwait`.

## Configuration

Enabled by default at `warning` severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1301.severity = warning
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`.
See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when shared code intentionally keeps the multi-task form and accepts the
extra work. Also keep the wrapper when callers rely on its separate task object
or its handling of cancellation and exceptions.
