# PSH1302 — TaskCompletionSource should run continuations asynchronously

**Category:** Concurrency
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A `TaskCompletionSource` or `TaskCompletionSource<T>` is created without
`TaskCreationOptions.RunContinuationsAsynchronously`. The rule reports constructors
with no options argument, or with constant options that omit this flag.
Creation written as `new()` is covered too.

Without the flag, completing the task can run continuations — the code waiting
for that task — on the thread that completes it. This can delay that thread or
deadlock if the waiting code needs a lock held by the completing thread. The flag
schedules that work asynchronously.

## Example

Before:

```csharp
using System.Threading.Tasks;

var source = new TaskCompletionSource<int>();
```

After:

```csharp
using System.Threading.Tasks;

var source = new TaskCompletionSource<int>(TaskCreationOptions.RunContinuationsAsynchronously);
```

## Code fix

The fix adds the flag as an options argument. It replaces `TaskCreationOptions.None`
with the flag, or combines other constant options with it using `|`. Any state
argument is kept. It uses the fully qualified enum name when needed.

## What is not reported

Options that already include the flag are not reported. A non-constant options
argument is also left alone, because its value is only known at runtime.

## Configuration

Enabled by default at `warning` severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1302.severity = warning
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`.
See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress only when running waiting code on the completing thread is intentional,
its work is controlled, and the risk of blocking or deadlock has been assessed.
