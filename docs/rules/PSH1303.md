# PSH1303 — Do not block an async method with Thread.Sleep

**Category:** Concurrency
**Severity:** Warning
**Code fix:** Yes, for supported contexts (supports Fix All)

## Cause

`Thread.Sleep` is called inside an `async` method, local function, or lambda.
It blocks the current thread for the whole delay. `await Task.Delay(...)` lets the
thread do other work while the method waits.

The nearest enclosing function decides whether the rule applies. A synchronous
local function or lambda inside an async method is not reported. A method returning
`Task` without the `async` keyword is also excluded.

## Example

Before:

```csharp
using System.Threading;
using System.Threading.Tasks;

public class Pause
{
    public async Task RunAsync()
    {
        Thread.Sleep(100);
        await Task.Yield();
    }
}
```

After:

```csharp
using System.Threading;
using System.Threading.Tasks;

public class Pause
{
    public async Task RunAsync()
    {
        await Task.Delay(100);
        await Task.Yield();
    }
}
```

## Code fix

The fix replaces a `Thread.Sleep(...)` statement with `await Task.Delay(...)`.
It keeps the duration argument, whether it is milliseconds or a `TimeSpan`, and
uses the fully qualified `Task` name when needed. Comments on the removed
`Thread.Sleep` name can be lost.

The fix also handles a sleep used directly as a lambda body. Expression-bodied
methods and local functions need a manual edit. A sleep inside a `lock` needs a
manual redesign because `await` is not allowed there.

If the duration uses a named argument, rename it for `Task.Delay`: change
`millisecondsTimeout` to `millisecondsDelay`, or `timeout` to `delay`. The fix
keeps argument names as written.

## Configuration

Enabled by default at `warning` severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1303.severity = warning
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`.
See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when deliberately testing blocking behavior. Also keep `Thread.Sleep(0)`
when its purpose is to yield the current thread: `Task.Delay(0)` completes
immediately and does not yield.
