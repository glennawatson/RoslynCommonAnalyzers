# PSH1304 — Use PeriodicTimer for periodic asynchronous work

**Category:** Concurrency
**Severity:** Warning
**Code fix:** None

## Cause

A `while` or `do` loop contains a standalone `await Task.Delay(...)` directly in
its body. A delay on each pass creates timer and task work, and adds the time
spent doing the work to the interval. `PeriodicTimer` reuses one timer and keeps
a regular schedule.

The rule requires `System.Threading.PeriodicTimer`, available in .NET 6 and later.
It does not report `for` or `foreach` loops, delays inside an `if`, or loops whose
condition contains `<`, `<=`, `>` or `>=`. It also skips loops that change a
variable used in the delay arguments, such as retry backoff.

## Example

Before:

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

class Worker
{
    public async Task RunAsync(CancellationToken token)
    {
        while (!token.IsCancellationRequested)
        {
            Console.WriteLine("Working");
            await Task.Delay(1000, token);
        }
    }
}
```

After:

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;

class Worker
{
    public async Task RunAsync(CancellationToken token)
    {
        using var timer = new PeriodicTimer(TimeSpan.FromSeconds(1));
        while (await timer.WaitForNextTickAsync(token))
        {
            Console.WriteLine("Working");
        }
    }
}
```

The corrected loop waits before its first run. If work must start immediately,
run it once before waiting. Keep any other stop condition your loop needs.
Cancellation of `WaitForNextTickAsync` throws `OperationCanceledException`;
disposing the timer ends the wait with `false`. Missed ticks are combined, so
slow work does not create a queue of pending runs.

There is no code fix. Restructure the loop to preserve its start and stop behavior.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1304.severity = warning
```

Enabled as a warning by default. There are
no rule-specific options. Severity values are `none`, `silent`, `suggestion`,
`warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the full delay must start after each piece of work finishes, or
when the interval intentionally changes in a way the rule does not recognize.
A regular timer would change that timing contract.
