# PSH1306 — Guard one-time execution with an interlocked latch

**Category:** Concurrency
**Severity:** Warning (disabled by default)
**Code fix:** None

## Cause

Code checks a `bool` field, returns when it is `true`, and later assigns `true`
to the same field. Both operations are outside a `lock`. Two threads can pass
the check before either sets the flag, so both run code intended to run once.

The check can use the field name alone or `this.field`. Local flags and checks
without a later assignment of `true` are not reported.

## Example

Before:

```csharp
using System;

class Resource : IDisposable
{
    private bool _disposed;

    public void Dispose()
    {
        if (_disposed)
        {
            return;
        }

        _disposed = true;
        Console.WriteLine("Cleaning up");
    }
}
```

After:

```csharp
using System;
using System.Threading;

class Resource : IDisposable
{
    private int _disposed;

    public void Dispose()
    {
        if (Interlocked.Exchange(ref _disposed, 1) != 0)
        {
            return;
        }

        Console.WriteLine("Cleaning up");
    }
}
```

`Interlocked.Exchange` sets the flag and returns its old value as one operation.
Only the caller that receives zero enters the cleanup. Other callers return
without waiting for that cleanup to finish. Use a lock if they must wait for it.

There is no code fix. Changing the field from `bool` to `int` requires checking
every use of it.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1306.severity = warning
```

Disabled by default. The setting above enables the rule as a warning. There are
no rule-specific options. Severity values are `none`, `silent`, `suggestion`,
`warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled, or suppress a specific guard, when the type is used by
one thread or an existing lock protects the whole operation. A check and write
inside a `lock` are already excluded.
