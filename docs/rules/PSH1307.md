# PSH1307 — Access interlocked fields with Volatile

**Category:** Concurrency
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

Code reads or writes a field directly while the same type declaration also
passes that field to `Interlocked`. Plain accesses do not provide the ordering
needed to share updates between threads. Use `Volatile.Read` and `Volatile.Write`
for those accesses.

The rule checks unqualified field names and `this.field` accesses. It skips
fields declared `volatile`, constructor and field-initializer accesses, accesses
inside `lock`, `ref`/`out` arguments, and `nameof`. It also skips instance-field
accesses through a readonly struct member or a `readonly struct`, where taking
the writable reference needed by `Volatile` is not allowed.

## Example

Before:

```csharp
using System.Threading;

class Counter
{
    private int _count;

    public void Add() => Interlocked.Increment(ref _count);
    public int Count => _count;
}
```

After:

```csharp
using System.Threading;

class Counter
{
    private int _count;

    public void Add() => Interlocked.Increment(ref _count);
    public int Count => Volatile.Read(ref _count);
}
```

## Code fix

The fix replaces a read with `Volatile.Read(ref field)` and a simple assignment
with `Volatile.Write(ref field, value)`. It uses the full
`global::System.Threading.Volatile` name when needed. Comments within the
replaced assignment can be lost; check the preview.

Compound assignments such as `+=`, and `++` or `--`, are reported without a fix.
Use an appropriate `Interlocked` operation, such as `Add` or `Increment`, so
another thread cannot change the value between the read and the write.
`Volatile.Write` returns no value; manually rewrite an assignment whose result
is used by another expression.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1307.severity = warning
```

Enabled as a warning by default. There are
no rule-specific options. Severity values are `none`, `silent`, `suggestion`,
`warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress a specific access only when a separate synchronization mechanism
guarantees that it cannot race with an update. State which mechanism protects
the access. Do not suppress merely because the field is an `int`.
