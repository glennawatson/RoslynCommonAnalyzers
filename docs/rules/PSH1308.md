# PSH1308 — Return the completed task instead of Task.FromResult

**Category:** Concurrency
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A `Task.FromResult(...)` call is used where the type is plain `Task`, such as a
return value or variable. The result value is hidden by that type.
`Task.CompletedTask` expresses completion without a result and can avoid a task
allocation. Some `Task.FromResult` values are cached by the runtime already.

Calls used as `Task<T>` or awaited directly are not reported. The rule requires
`Task.CompletedTask` to be available in the project.

## Example

Before:

```csharp
using System.Threading.Tasks;

class Writer
{
    public Task FlushAsync() => Task.FromResult(0);
}
```

After:

```csharp
using System.Threading.Tasks;

class Writer
{
    public Task FlushAsync() => Task.CompletedTask;
}
```

## Code fix

The fix replaces the whole call with `Task.CompletedTask`, keeping any namespace
qualification on `Task`. It deletes the argument expression and comments inside
the call. If that expression calls a method, changes state, or can throw, keep
that work as a separate statement before returning the completed task.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1308.severity = warning
```

Enabled as a warning by default. There are
no rule-specific options. Severity values are `none`, `silent`, `suggestion`,
`warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an existing API contract requires the returned object to remain a
`Task<T>`, even though the declared type is `Task`. Otherwise prefer a completed
task and preserve any necessary argument evaluation explicitly.
