# PSH1311 — Remove a pass-through async state machine

**Category:** Concurrency
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

An `async` method or local function only awaits and forwards another task.
The compiler creates bookkeeping to pause and resume an async method, called a
state machine. Returning the inner task directly avoids that extra work.

The whole body must be `=> await task`, a single `return await task;`, or a
single `await task;` in a method returning `Task`. The inner task must have
exactly the declared `Task` or `Task<T>` type. Lambdas, `async void`, `ValueTask`,
and bodies with other statements or a surrounding `using` or `try` are excluded.

## Example

Before:

```csharp
using System.Threading.Tasks;

class Counter
{
    public async Task<int> CountAsync() => await ReadCountAsync();

    private Task<int> ReadCountAsync() => Task.FromResult(0);
}
```

After:

```csharp
using System.Threading.Tasks;

class Counter
{
    public Task<int> CountAsync() => ReadCountAsync();

    private Task<int> ReadCountAsync() => Task.FromResult(0);
}
```

## Code fix

The fix removes `async` and `await`. A lone `await task;` becomes
`return task;`. It also removes a trailing `ConfigureAwait(true)` or
`ConfigureAwait(false)` and formats the method. Other `ConfigureAwait` arguments
are not covered. Comments attached to removed keywords or the removed
`ConfigureAwait` call can be lost; check the preview.

Without `async`, an exception thrown while obtaining the task reaches the caller
immediately, instead of being stored in the returned task. The forwarding
method also loses its separate entry in async stack traces.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1311.severity = warning
```

Enabled as a warning by default. There are
no rule-specific options. Severity values are `none`, `silent`, `suggestion`,
`warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when callers depend on all failures being stored in the returned task,
or when the method's entry in async stack traces is useful enough to keep the
extra work. Keep `await` where cleanup must wait for the task to finish.
