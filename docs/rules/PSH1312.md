# PSH1312 — Return a completed task, never null

**Category:** Concurrency
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A non-async method, local function, property getter, or indexer getter returns
`null`, `default`, or a typed default such as `default(Task<int>)` where its
declared type is `Task` or `Task<T>`. Awaiting a null task throws
`NullReferenceException`. Return an actual
completed task when there is no work to do.

An async method returning a null result is excluded: it still returns a task.
Lambdas are excluded too. A default `ValueTask` already represents successful
completion and is not reported. The rule requires `Task.CompletedTask` in the
project.

## Example

Before:

```csharp
using System.Threading.Tasks;

class Writer
{
    public Task FlushAsync() => null;
}
```

After:

```csharp
using System.Threading.Tasks;

class Writer
{
    public Task FlushAsync() => Task.CompletedTask;
}
```

## Code fix

For `Task`, the fix replaces the returned expression with `Task.CompletedTask`.
For `Task<T>`, it uses `Task.FromResult<T>(default)`. Before C# 7.1 it writes
`default(T)` instead. It keeps surrounding comments and formats the replacement.

Check that the default result is valid for your API. For a non-nullable reference
type, supply a real value or change the result type to allow null. If null meant
failure or cancellation, return a faulted or canceled task instead of accepting
a fix that reports success.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1312.severity = warning
```

Enabled as a warning by default. There are
no rule-specific options. Severity values are `none`, `silent`, `suggestion`,
`warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress only for an existing contract in which a null task has a documented
meaning and every caller handles it without awaiting it. For ordinary async
APIs, fix the return value.
