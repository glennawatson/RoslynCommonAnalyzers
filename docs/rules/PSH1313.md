# PSH1313 — Call the async overload from an async method

**Category:** Concurrency
**Severity:** Warning
**Code fix:** Yes, for supported calls (supports Fix All)

## Cause

An `async` method, local function, or lambda calls a synchronous method with a
matching `Async` method. A synchronous I/O call can hold a thread while it waits.
Awaiting its async counterpart releases the thread during the wait.

Both methods must be non-generic and declared on the same type. The async
method must be public, agree on whether it is static, and return `Task`,
`Task<T>`, `ValueTask`, or `ValueTask<T>` with the same result as the synchronous
call. Its starting parameters must match; any extra parameters must be optional.

Synchronous functions nested inside an async method are excluded. Calls that
already return tasks, methods whose names end in `Async`, and `Dispose` are
excluded too.

## Example

Before:

```csharp
using System.IO;
using System.Threading.Tasks;

class Reader
{
    public async Task<string> LoadAsync(string path)
    {
        return File.ReadAllText(path);
    }
}
```

After:

```csharp
using System.IO;
using System.Threading.Tasks;

class Reader
{
    public async Task<string> LoadAsync(string path)
    {
        return await File.ReadAllTextAsync(path);
    }
}
```

## Code fix

The fix changes the method name and inserts `await`, keeping the arguments. It
adds parentheses where needed, such as `(await File.ReadAllTextAsync(path)).Length`,
and formats the expression. It does not add a cancellation token or
`ConfigureAwait`.

There is no fix for calls reached through `?.`, or when the async call cannot
accept the arguments as written. Those cases need a manual rewrite that keeps
the null check and passes the correct arguments.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1313.severity = warning
```

Enabled as a warning by default. There are
no rule-specific options. Severity values are `none`, `silent`, `suggestion`,
`warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the synchronous method performs no blocking work and the async
version adds unnecessary cost, or when the two methods have different behavior
that matters to the caller. Matching names and parameter types do not guarantee
matching behavior.
