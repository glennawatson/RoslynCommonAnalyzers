# PSH1314 — Read and write streams through the memory-based overloads

**Category:** Concurrency
**Severity:** Warning
**Code fix:** Yes, when the replacement call is available (supports Fix All)

## Cause

Code directly awaits `Stream.ReadAsync` or `Stream.WriteAsync` with a byte array,
offset, and count, with or without a cancellation token. The memory overloads
describe the same part of the array in one value and return `ValueTask` or
`ValueTask<int>`. These can avoid allocating a task when the operation finishes
immediately.

Calls awaited through `ConfigureAwait` are included. Calls whose task is stored,
returned, or passed elsewhere are excluded because the return type would change.
The rule requires the memory types and stream overloads available in .NET Core
2.1 and later, including a matching overload on the stream's type or a base type.

## Example

Before:

```csharp
using System;
using System.IO;
using System.Threading;
using System.Threading.Tasks;

class Reader
{
    public async Task<int> ReadAsync(
        Stream stream, byte[] buffer, CancellationToken token)
        => await stream.ReadAsync(buffer, 0, buffer.Length, token);
}
```

After:

```csharp
using System;
using System.IO;
using System.Threading;
using System.Threading.Tasks;

class Reader
{
    public async Task<int> ReadAsync(
        Stream stream, byte[] buffer, CancellationToken token)
        => await stream.ReadAsync(buffer.AsMemory(0, buffer.Length), token);
}
```

## Code fix

The fix replaces the array, offset, and count arguments with
`buffer.AsMemory(offset, count)`. It keeps the cancellation token and any outer
`ConfigureAwait` call. It formats the call, but comments around the replaced
arguments can be lost; check the preview.

The fix requires `AsMemory` to be in scope and the new call to match a memory
overload. Add `using System;` if needed. Named or reordered arguments can require
a manual rewrite. `AsMemory` creates a view of the array; it does not copy the
bytes.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1314.severity = warning
```

Enabled as a warning by default. There are
no rule-specific options. Severity values are `none`, `silent`, `suggestion`,
`warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a custom stream gives the array overload different behavior that
your code needs, or measurements show that its memory overload adds cost. Keep
the rule enabled for streams where the memory overload is a suitable replacement.
