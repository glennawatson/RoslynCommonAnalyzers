# PSH1315 — Do not block on a task that may not be complete

**Category:** Concurrency
**Severity:** Warning
**Code fix:** Yes, where awaiting is supported (supports Fix All)

## Cause

Code waits synchronously for a task without a recognized completion check.
Blocking holds the calling thread. In a UI app, this can deadlock if the task
needs that thread to finish. In a server, enough blocked calls can exhaust the
available worker threads. `await` releases the thread while the task is pending.

The rule covers `Task`, `Task<T>`, `ValueTask`, and `ValueTask<T>`, in both
synchronous and asynchronous code.

## What is reported

| Blocking expression | Code fix in an async function |
| --- | --- |
| `task.Result` | `await task` |
| `task.Wait()` | `await task` |
| `task.GetAwaiter().GetResult()` | `await task` |
| `task.ConfigureAwait(false).GetAwaiter().GetResult()` | `await task.ConfigureAwait(false)` |
| `Task.WaitAll(a, b)` | `await Task.WhenAll(a, b)` |
| `Task.WaitAny(a, b)` with its result discarded | `await Task.WhenAny(a, b)` |
| Waits with a timeout or cancellation token | No fix |
| `Task.WaitAny(...)` with its returned index used | No fix |
| `task.RunSynchronously()` | No fix |

`GetResult()` on a framework task awaiter is also reported when the awaiter is
stored in a local, field, property, or parameter. An awaiter is the object
returned by `GetAwaiter()`. Custom awaiter types are not reported by this check.

## Example

Before:

```csharp
using System.Threading.Tasks;

class Reader
{
    public async Task<int> ReadAsync(Task<int> pending)
    {
        return pending.Result;
    }
}
```

After:

```csharp
using System.Threading.Tasks;

class Reader
{
    public async Task<int> ReadAsync(Task<int> pending)
    {
        return await pending;
    }
}
```

## Code fix

The fix uses the replacements in the table, preserves an existing
`ConfigureAwait`, and adds parentheses where needed, such as
`(await task).Length`. It formats the expression. Comments inside the removed
blocking call can be lost; check the preview.

The enclosing function must already be `async`. No fix is offered inside a
`lock`, `unsafe` block, `fixed` statement, exception filter, or query expression.
For a synchronous method, change its return type and callers to support `await`
where practical.

A local initialized with `task.GetAwaiter()` can be rewritten to await that
task expression. The fix leaves the local declaration in place. If its
initializer calls a method or reads a property, review the edit so it does not
start or fetch the operation twice. Awaiters held in fields, properties, or
parameters have no automatic fix.

A plain await does not preserve a wait's timeout or cancellation behavior, so
those calls need a manual rewrite. `WaitAny` returns an index; `WhenAny` returns
the finished task. `RunSynchronously` starts and runs a task, so replacing it
with `await` alone could wait forever for a task that was never started.
Also check exception handling: `Wait`, `Result`, and `WaitAll` wrap task failures
in `AggregateException`, while `await` throws a task's exception directly.

## What is not reported

A wait is excluded when a recognized `IsCompleted` or
`IsCompletedSuccessfully` check proves that the same task has finished. Supported
forms include a positive `if` body, a conditional expression, a suitable `&&`
or `||` condition, and an earlier guard that returns, throws, breaks, or continues
when the task is incomplete. A prior await of that task also counts.

For `WaitAll(a, b)`, both tasks must be known to have finished. For `WaitAny(a, b)`,
one finished task is enough. A check on one task does not cover a different task.
Checks must be in the same function as the wait. Checks saved in a boolean local,
written as `is true`, or based on `Task.Status` are not recognized. Repeated
method calls are not treated as the same task.

The rule also excludes synchronous overrides and interface implementations,
including `IDisposable.Dispose`; the program's synchronous entry point and
top-level statements; and blocking inside a custom awaiter's own `GetResult`
implementation. These exclusions do not mean that blocking is safe in every
such implementation. Generated code is excluded.

## When to suppress

Suppress a specific wait when every caller guarantees that its task has already
finished, but the completion check is outside the helper containing the wait.
Document that guarantee and check every caller. The helper must not replace the
task before reading its result.

A required synchronous boundary can also justify a local suppression after
checking that the operation can finish without the blocked thread and that the
thread cost is acceptable. An absence of deadlocks in a few test runs is not a
completion guarantee.
