# PSH1316 - Consume a ValueTask exactly once

| Item | Value |
| --- | --- |
| Category | Concurrency |
| Severity | Warning |
| Code fix | Some loop cases |
| Default | Enabled |

## Cause

A `ValueTask` or `ValueTask<T>` local is declared outside a loop and used inside it,
or copied into another local and both copies are used. Uses include `await`,
`.Result`, `.GetAwaiter()`, `.AsTask()`, and `.ConfigureAwait()`.

A `ValueTask` can refer to an operation whose storage is reused after completion.
Awaiting it again can fail or return the wrong result. Copying the value does not
start another operation.

The rule skips a local declared or assigned inside the loop. It also skips a
local on which `Preserve()` is called. A single use is not reported.

## Example

Bad:

```csharp
using System;
using System.Threading.Tasks;

public class Reader
{
    public async Task ReadManyAsync(Func<ValueTask> readAsync)
    {
        ValueTask pending = readAsync();
        for (int i = 0; i < 3; i++)
        {
            await pending;
        }
    }
}
```

Corrected:

```csharp
using System;
using System.Threading.Tasks;

public class Reader
{
    public async Task ReadManyAsync(Func<ValueTask> readAsync)
    {
        for (int i = 0; i < 3; i++)
        {
            ValueTask pending = readAsync();
            await pending;
        }
    }
}
```

## How to fix violations

Create a fresh operation for each iteration. The code fix moves the whole local
declaration to the start of the loop body. This runs its initializer on each
iteration, and does not run it if the loop is skipped. Check that this matches
the intended work.

The fix requires a loop with braces, one initialized variable in the declaration,
and no use of that variable outside the loop body. It does not move a `using`
declaration or cross a preprocessor directive. It uses the first loop statement's
indentation and can drop comments above the original declaration. Review those
comments before accepting the edit. There is no fix for the copy case.

If several callers need the same result, call `Preserve()` once and keep its
return value, for example `pending = pending.Preserve()`. Await that saved value.
Calling `Preserve()` and discarding its return value does not make reuse safe.

## Configuration

The default and recommended severity is `warning`. There are no rule-specific
options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1316.severity = warning
```

Other severity values are `none`, `silent`, `suggestion`, and `error`. Use `none`
to disable the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress a specific use only when the operation's documented contract allows
repeated consumption, or the reported loop can run at most once. Prefer saving
the result of `Preserve()` when repeated awaits are intentional.
