# PSH1317 - Pass the cancellation token to the call that accepts one

| Item | Value |
| --- | --- |
| Category | Concurrency |
| Severity | Warning |
| Code fix | Yes, except conditional access |
| Default | Enabled |

## Cause

A function has a `CancellationToken` parameter, but a call omits an optional token
or uses a method with a compatible token-taking overload. Passing the token lets
that work respond when the caller cancels it.

The overload must be accessible, declared on the same type, return the same type,
and accept the existing parameters plus one token. Any further parameters must
be optional. A static method must stay static; an instance method must stay an
instance method.

The token comes from the nearest function with a parameter explicitly typed as
`CancellationToken`. This includes methods, local functions, and lambdas. A static
lambda or local function can supply its own token but cannot use an outer one.
Tokens held only in fields or locals, implicit lambda parameters, and `ref`, `in`,
or `out` parameters are not used.

Calls that already pass a token, including `CancellationToken.None` or `default`,
are not reported. Constructors are excluded. Separate overloads of generic
methods and extension methods called as `target.Method()` are excluded too;
an optional token on the called method itself is still checked.

## Example

Bad:

```csharp
using System.Threading;
using System.Threading.Tasks;

public class Worker
{
    public async Task PauseAsync(CancellationToken cancellationToken)
    {
        await Task.Delay(100);
    }
}
```

Corrected:

```csharp
using System.Threading;
using System.Threading.Tasks;

public class Worker
{
    public async Task PauseAsync(CancellationToken cancellationToken)
    {
        await Task.Delay(100, cancellationToken);
    }
}
```

## How to fix violations

The code fix inserts the token at its parameter position. It uses a named argument
when other arguments are named or optional parameters were skipped. It keeps the
existing arguments and their comments. Fix All applies the same edit to eligible
calls.

The fix is offered only when the edited call selects the intended overload.
Calls through `?.`, such as `target?.Send(1)`, can be reported but need a manual
edit.

## Configuration

The default and recommended severity is `warning`. There are no rule-specific
options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1317.severity = warning
```

Other severity values are `none`, `silent`, `suggestion`, and `error`. Use `none`
to disable the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

If an operation must finish even after its caller cancels, pass
`CancellationToken.None` explicitly. This records the decision and avoids the
diagnostic without a suppression.
