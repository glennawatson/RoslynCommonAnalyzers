# PSH1318 - Validate options asynchronously instead of blocking

| Item | Value |
| --- | --- |
| Category | Concurrency |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A method named `Validate` blocks on a task in a type that implements
`Microsoft.Extensions.Options.IValidateOptions<T>` and does not implement
`IAsyncValidateOptions<T>`. The rule reports nothing unless the project references
both interfaces.

Blocking includes reading `.Result`, calling `.Wait()` or
`.GetAwaiter().GetResult()`, and using `Task.WaitAll`, `Task.WaitAny`, or
`RunSynchronously`. The diagnostic appears on the method name. The rule can report
a result read even when the task is already complete.

Waiting for a database or remote service this way holds a thread until the work
finishes. Asynchronous validation lets that thread do other work while it waits.
Validation that only checks values in the options object can stay synchronous.

## Example

These examples require an options package that provides `IAsyncValidateOptions<T>`.
The delay represents asynchronous work inside validation.

Bad:

```csharp
using Microsoft.Extensions.Options;
using System.Threading.Tasks;

public sealed class AppOptions { }

public sealed class AppValidator : IValidateOptions<AppOptions>
{
    public ValidateOptionsResult Validate(string? name, AppOptions options)
    {
        Task.Delay(1).Wait();
        return ValidateOptionsResult.Success;
    }
}
```

Corrected:

```csharp
using Microsoft.Extensions.Options;
using System.Threading;
using System.Threading.Tasks;

public sealed class AppOptions { }

public sealed class AppValidator : IAsyncValidateOptions<AppOptions>
{
    public async Task<ValidateOptionsResult> ValidateAsync(
        string? name, AppOptions options, CancellationToken cancellationToken)
    {
        await Task.Delay(1, cancellationToken);
        return ValidateOptionsResult.Success;
    }
}
```

## How to fix violations

There is no code fix.

Implement `IAsyncValidateOptions<T>` and move the body into `ValidateAsync`, awaiting the work instead
of blocking on it. Register the validator the same way; the options infrastructure resolves the
asynchronous interface when it is present.

## Configuration

The default and recommended severity is `warning`. There are no rule-specific
options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1318.severity = warning
```

Other severity values are `none`, `silent`, `suggestion`, and `error`. Use `none`
to disable the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress a specific method when its caller requires synchronous validation and
cannot use the asynchronous interface, or when every reported task is guaranteed
to be complete before its result is read. A type that already implements the
asynchronous interface is excluded without a suppression.
