# PSH1400 - Use the static HashData method for one-shot hashing

| Item | Value |
| --- | --- |
| Category | ApiSelection |
| Severity | Warning |
| Code fix | Chained calls only |
| Default | Enabled |

## Cause

Code calls `Create().ComputeHash(data)` on a built-in hash algorithm, or creates
an algorithm in a `using` declaration or statement and uses it only for
`ComputeHash(byte[])` calls. One or several such calls qualify.

The static `HashData` method avoids creating and disposing an algorithm object
for this work. The chained form also leaves its object undisposed.

The rule covers `MD5`, `SHA1`, `SHA256`, `SHA384`, `SHA512`, `SHA3_256`, `SHA3_384`,
and `SHA3_512`, only when the target framework provides that algorithm's
`HashData(byte[])` method. The original algorithms provide it from .NET 5; SHA-3
requires .NET 8. Custom factories, stream overloads, and calls with an offset and
count are excluded. A saved algorithm used for anything else is also excluded.

## Example

Bad:

```csharp
using System.Security.Cryptography;

public class Hasher
{
    public byte[] Hash(byte[] data) => SHA256.Create().ComputeHash(data);
}
```

Corrected:

```csharp
using System.Security.Cryptography;

public class Hasher
{
    public byte[] Hash(byte[] data) => SHA256.HashData(data);
}
```

## How to fix violations

The code fix replaces a chained `Create().ComputeHash(...)` call with
`HashData(...)`. It keeps the algorithm type name as written and the existing
arguments. Comments inside the removed `Create()` and `ComputeHash` chain can be
lost. If the argument is named, check that its name matches the `HashData`
parameter.

There is no automatic fix for a saved algorithm in a `using`. Replace each
`sha.ComputeHash(data)` with the matching static call, then remove the unused
`using` declaration or statement.

## Configuration

The default and recommended severity is `warning`. There are no rule-specific
options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1400.severity = warning
```

Other severity values are `none`, `silent`, `suggestion`, and `error`. Use `none`
to disable the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress a specific use when measurements show that retaining one algorithm for
several buffers is useful. An instance needed for other operations is already
excluded.
