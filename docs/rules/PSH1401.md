# PSH1401 - Attribute types should be sealed

| Item | Value |
| --- | --- |
| Category | ApiSelection |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A class inherits directly or indirectly from `System.Attribute` and is neither
`abstract` nor `sealed`. Sealing an attribute tells runtime attribute lookups
that they do not need to look for derived attribute types.

## Example

Bad:

```csharp
public class MyAttribute : System.Attribute
{
}
```

Corrected:

```csharp
public sealed class MyAttribute : System.Attribute
{
}
```

## How to fix violations

The code fix adds `sealed` after the accessibility modifiers and before
`partial`, if present. It keeps the class body, indentation, and documentation
comments. Fix All seals all reported attribute classes in the selected scope.

Check for derived classes before accepting the fix. The rule reports an attribute
even when another class inherits from it. Sealing it makes those derived classes
invalid, including classes in other projects that use your library.

## Configuration

The default and recommended severity is `warning`. There are no rule-specific
options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1401.severity = warning
```

Other severity values are `none`, `silent`, `suggestion`, and `error`. Use `none`
to disable the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress the rule on an attribute intended to be inherited. If the base attribute
should never be created directly, make it `abstract` instead. Abstract attribute
classes are not reported.
