# PSH1402 - Use const for compile-time constants

| Item | Value |
| --- | --- |
| Category | ApiSelection |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `static readonly` field or an unchanged local has a value known when the code
is compiled. Declaring it `const` lets the compiler put that value directly into
code that uses it.

The rule covers `bool`, `char`, built-in numeric types other than `nint` and
`nuint`, `string`, and enums. Literals, constant arithmetic, `nameof`, and other
constants qualify. A field with `public` or `protected` access is excluded.

A local is excluded if it is assigned again, incremented, decremented, passed
with `ref`, `out`, or `in`, or used through a reference or pointer. Changes inside
lambdas and local functions also count. `using` declarations, `ref` locals,
variables declared by `for` or `foreach`, and declarations with several variables
are excluded.

## Example

Bad:

```csharp
public class Settings
{
    private static readonly int MaxRetries = 3;

    public string Prefix()
    {
        var prefix = "app";
        return prefix;
    }
}
```

Corrected:

```csharp
public class Settings
{
    private const int MaxRetries = 3;

    public string Prefix()
    {
        const string prefix = "app";
        return prefix;
    }
}
```

## How to fix violations

The code fix replaces a field's `static readonly` modifiers with `const`, keeping
other modifiers such as `new`. Comments attached to the removed second modifier
can be lost. For a local, it adds `const` and replaces `var` with the actual type.
Fix All applies the same changes to eligible declarations.

Constants are copied into compiled callers. This is why public and protected
fields are excluded: changing a library's constant does not update an existing
caller until that caller is rebuilt.

## Configuration

The default and recommended severity is `warning`. There are no rule-specific
options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1402.severity = warning
```

Other severity values are `none`, `silent`, `suggestion`, and `error`. Use `none`
to disable the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Keep `static readonly` when the field is assigned in a static constructor or its
value must be read at runtime. Also consider this for internal fields shared with
another assembly through `InternalsVisibleTo`: callers can otherwise keep an old
constant value until rebuilt. Suppress a local when keeping related declarations
in the same form makes the code easier to maintain.
