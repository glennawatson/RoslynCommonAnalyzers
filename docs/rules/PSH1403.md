# PSH1403 - Do not initialize fields to their default value

| Item | Value |
| --- | --- |
| Category | ApiSelection |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A field in a class has an initializer that repeats its default value. Fields
already start with that value, so the assignment is unnecessary.

The rule reports `default`, `default(T)` for the field's type, and constant
defaults: numeric zero, `false`, `'\0'`, a zero-valued enum member, or `null` for
reference and nullable types. It checks static and instance fields, and each
variable in a declaration separately.

It excludes `const` fields, fields in structs and record structs, negative
floating-point zero, and initializers such as `null!`. Removing `null!` could
reintroduce a nullable warning.

## Example

Bad:

```csharp
public class State
{
    private int _count = 0;
    private bool _ready = false;
    private string? _name = null;
}
```

Corrected:

```csharp
public class State
{
    private int _count;
    private bool _ready;
    private string? _name;
}
```

## How to fix violations

The code fix removes the reported `= value` and the space before it. Other
variables in the declaration stay unchanged. Fix All removes all reported
initializers in the selected scope.

Comments inside the removed initializer can be lost. Comments after its value
are kept. Move any explanation you need to keep above the field before accepting
the fix.

## Configuration

The default and recommended severity is `warning`. There are no rule-specific
options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1403.severity = warning
```

Other severity values are `none`, `silent`, `suggestion`, and `error`. Use `none`
to disable the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress a field when an explicit default helps explain a group of related
initial values. Also check unusual initialization code where another initializer
can change the field before this assignment resets it; removing that reset would
change the result.
