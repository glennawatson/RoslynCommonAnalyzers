# PSH1404 - Get the assembly from a type

| Item | Value |
| --- | --- |
| Category | ApiSelection |
| Severity | Warning |
| Code fix | Inside a type declaration |
| Default | Enabled |

## Cause

Code calls `System.Reflection.Assembly.GetExecutingAssembly()`. This includes
calls through an alias or `using static`, and calls in top-level statements.

`typeof(T).Assembly` names an assembly through a known type. Using a type declared
in the same assembly avoids asking the runtime to identify the executing assembly.
Calls to `GetCallingAssembly()` or `GetEntryAssembly()` are not reported; they ask
for a different assembly.

## Example

Bad:

```csharp
using System.Reflection;

public class ResourceLoader
{
    public Assembly GetAssembly() => Assembly.GetExecutingAssembly();
}
```

Corrected:

```csharp
using System.Reflection;

public class ResourceLoader
{
    public Assembly GetAssembly() => typeof(ResourceLoader).Assembly;
}
```

## How to fix violations

The code fix replaces the call with `typeof(CurrentType).Assembly`, using the
nearest enclosing type and including its type parameters, such as
`typeof(Cache<T>).Assembly`. It keeps comments before and after the call, but
comments inside the replaced call can be lost. Fix All uses each call's enclosing
type.

Top-level calls are reported without a code fix. Replace them manually using a
type declared in the same project, such as `Program` for top-level code.

## Configuration

The default and recommended severity is `warning`. There are no rule-specific
options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1404.severity = warning
```

Other severity values are `none`, `silent`, `suggestion`, and `error`. Use `none`
to disable the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress a specific call when a shared source file must work in several projects
and naming a type would tie it to one project's structure. In ordinary code,
using the enclosing type gives the same assembly.
