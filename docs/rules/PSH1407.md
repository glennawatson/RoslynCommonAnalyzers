# PSH1407 - Query dictionaries directly

| Item | Value |
| --- | --- |
| Category | ApiSelection |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

Code calls `map.Keys.Contains(key)` with one argument, and `map` exposes a public
instance method named `ContainsKey` that takes one parameter and returns `bool`.
The rule covers standard dictionaries, dictionary interfaces, and custom types
with these members.

`ContainsKey` asks the dictionary directly. It avoids obtaining a key collection
and any extra work needed to search that collection.

Calls with an explicit comparer, calls on a saved key collection, and calls written
as `Enumerable.Contains(map.Keys, key)` are not reported. A `ContainsKey` method
available only through an explicit interface implementation is not suggested on
the concrete class.

## Example

Bad:

```csharp
using System.Collections.Generic;
using System.Linq;

public class Lookup
{
    public bool HasKey(IDictionary<string, int> map, string key)
        => map.Keys.Contains(key);
}
```

Corrected:

```csharp
using System.Collections.Generic;

public class Lookup
{
    public bool HasKey(IDictionary<string, int> map, string key)
        => map.ContainsKey(key);
}
```

## How to fix violations

There is no code fix. Replace `map.Keys.Contains(key)` with
`map.ContainsKey(key)`.

For custom types, check that `ContainsKey` accepts the key and means the same
thing. The rule can report an incompatible parameter type, a `ref` parameter, or
a generic method that needs a type argument. Also check how keys are compared:
`ContainsKey` uses the dictionary's comparison rules, which can differ from a
separate search through its keys.

## Configuration

The default and recommended severity is `warning`. There are no rule-specific
options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1407.severity = warning
```

Other severity values are `none`, `silent`, `suggestion`, and `error`. Use `none`
to disable the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress a specific call when the suggested method cannot accept the key or when
the key collection intentionally uses different comparison rules. Do not change
the answer of the lookup to satisfy the rule.
