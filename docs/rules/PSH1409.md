# PSH1409 — Use the built-in throw helpers for argument guards

**Category:** ApiSelection
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

An `if` statement only throws an exception, and a throw helper is available for
the check. Throw helpers keep exception construction out of the calling method,
which can help the runtime optimize that method.

The rule covers null checks on a named reference value, `IsNullOrEmpty` and
`IsNullOrWhiteSpace` checks, disposal checks, and numeric comparisons. A null or
range guard must name the checked value in the exception, using `nameof` or a
string literal. An `else` branch or extra statements inside the guard exclude it.
Null checks on `System.Threading.Lock` are also excluded.

## Example

Before:

```csharp
using System;

public class Greeting
{
    public void Write(string name)
    {
        if (name is null)
        {
            throw new ArgumentNullException(nameof(name));
        }
    }
}
```

After:

```csharp
using System;

public class Greeting
{
    public void Write(string name)
    {
        ArgumentNullException.ThrowIfNull(name);
    }
}
```

## Code fix

The fix replaces the entire `if` statement with a helper call. It uses
`ThrowIfNull`, `ThrowIfNullOrEmpty`, `ThrowIfNullOrWhiteSpace`, or a numeric helper
such as `ThrowIfNegative` or `ThrowIfGreaterThan`. A disposal guard becomes
`ObjectDisposedException.ThrowIf(condition, this)`; in a static member it passes
`typeof(ContainingType)` instead.

The helper supplies its standard exception message. A string guard that throws
`ArgumentNullException` can become an `ArgumentException` helper call, so review
code that depends on the exception type. Comments before and after the guard
are kept, but comments inside the removed guard can be lost.

Each suggestion requires the corresponding helper in the target framework or
an available replacement helper. Projects using aliases named
`ArgumentExceptionHelper`, `ArgumentNullExceptionHelper`,
`ArgumentOutOfRangeExceptionHelper`, or `ObjectDisposedExceptionHelper` get a
call through the matching alias when it provides the helper. Otherwise, the fix
uses the framework exception type.

## Configuration

The rule is enabled at `warning` by default. It has no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1409.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when callers depend on the custom message, exception type, or disposal
object name. Also suppress in shared source that must compile for a target
without the helper and has no suitable replacement helper.
