# PSH1410 — Mark trivial forwarders for aggressive inlining

**Category:** ApiSelection
**Severity:** Warning (disabled by default — opt-in)
**Code fix:** Adds `[MethodImpl(MethodImplOptions.AggressiveInlining)]` (supports Fix All)

An expression-bodied method that only forwards to another member — a
delegation, member read, or constant — can still be skipped by the JIT's
IL-size inlining heuristics, leaving a call frame around a one-line body.
`MethodImplOptions.AggressiveInlining` makes the intent explicit.

Virtual, abstract, override, async, extern, partial, and interface members
are skipped, as is anything already carrying a `MethodImpl` attribute
(including `NoInlining`, which is an explicit decision the rule respects).
Blanket inlining attributes are an opinionated convention, so the rule is
opt-in:

```editorconfig
dotnet_diagnostic.PSH1410.severity = warning
```

## Example

```csharp
public int GetValue() => _value;   // PSH1410

[MethodImpl(MethodImplOptions.AggressiveInlining)]
public int GetValue() => _value;   // fixed
```

The attribute goes above any the member already carries, and the member's doc comment
and surrounding directives **move** to sit above it rather than being copied. It is always
written fully qualified:

```csharp
/// <summary>Reads the value.</summary>
[global::System.Runtime.CompilerServices.MethodImpl(global::System.Runtime.CompilerServices.MethodImplOptions.AggressiveInlining)]
[SuppressMessage("Design", "CA1000", Justification = "…")]
public int GetValue() => _value;
```

The spelling is unconditional on purpose. A multi-targeted project compiles one linked file
once per framework, and Roslyn reconciles those results into a single document — where they
differ, it writes conflict markers into the source instead. Anything that decides the spelling
per compilation diverges: the semantic model, because what binds depends on the framework, and
the `using` directives, because a `using` inside an `#if` is a syntax node in one compilation
and inactive text in another. The qualified form needs no import, so it is correct everywhere
and identical everywhere.
