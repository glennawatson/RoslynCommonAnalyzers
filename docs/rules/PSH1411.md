# PSH1411 — Seal types that nothing derives from

**Category:** ApiSelection
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A class has no derived class in the project and can be marked `sealed`.
Sealing prevents inheritance and can help the runtime call its members directly.

By default, the rule reports classes that cannot be reached outside the assembly:
private nested classes, file-local classes, and internal classes. A public class
inside an internal class also counts as internal. If `[InternalsVisibleTo]`
grants another assembly access, internal classes are excluded because that
assembly may derive from them. Private and file-local classes remain eligible.

## Example

Before:

```csharp
internal class Widget
{
}
```

After:

```csharp
internal sealed class Widget
{
}
```

## What is not reported

- Classes that are already `sealed`, `static`, or `abstract`, and records.
- Classes with a derived class in the project, including generated subclasses.
- Classes used in generic constraints such as `where T : Widget`, including
  constraints on local functions.
- Classes declaring new virtual or protected members. Overrides do not exclude
  a class.
- Externally visible classes, unless `include_public` is enabled.

## Code fix

The fix inserts `sealed` after the access modifier and before `partial`, if
present. It keeps the class body and comments. For a partial class, it adds the
modifier to the reported declaration; that seals the whole class.

## Configuration

The rule is enabled at `warning` by default.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1411.severity = warning
performancesharp.PSH1411.include_public = false
```

| Key | Values | Default | Effect |
| --- | --- | --- | --- |
| `performancesharp.PSH1411.include_public` | `true`, `false` | `false` | Also report externally visible classes. |
| `performancesharp.include_public` | `true`, `false` | `false` | Fallback when the rule-specific value is absent or invalid. |

The valid rule-specific value takes priority. Enabling it does not override the
`InternalsVisibleTo` exclusion for internal classes. Use it in an application
only when outside code does not need to derive from its public classes.

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.
See the [configuration reference](../CONFIGURATION.md).

## When to suppress

Suppress for classes that a mocking library, object mapper, or interceptor
derives from at runtime. If public classes are included, suppress where an
external consumer needs inheritance: sealing such a class breaks that consumer.
