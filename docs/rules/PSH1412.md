# PSH1412 — Use Random.Shared instead of allocating a Random

**Category:** ApiSelection
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

Code creates a `System.Random` with no constructor arguments or object
initializer. This includes cached fields and `Random random = new()` when
`Random.Shared` can be written at that location.

`Random.Shared` provides a shared instance that is safe to call from multiple
threads. It avoids creating a separate generator for each use. The rule applies
only when the target framework provides it, such as .NET 6 or later.

## Example

Before:

```csharp
using System;

public class Dice
{
    public int Roll() => new Random().Next(1, 7);
}
```

After:

```csharp
using System;

public class Dice
{
    public int Roll() => Random.Shared.Next(1, 7);
}
```

## What is not reported

A seeded generator such as `new Random(42)` is excluded, as is construction of
a subclass of `Random`. The rule reports nothing when `Random.Shared` is absent
from the target framework.

## Code fix

The fix replaces construction with `Random.Shared`. It preserves a written
qualification: `new System.Random()` becomes `System.Random.Shared`. A reported
`new()` becomes `Random.Shared`. Cached fields remain in place, and a local can
still be reassigned later. Comments inside the removed constructor call can be
lost; comments surrounding it are kept.

## Configuration

The rule is enabled at `warning` by default. It has no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1412.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when the code needs a separate generator instance with its own state,
or shared source must also compile on a framework without `Random.Shared`. If
you need repeatable results, pass an explicit seed; that form is already excluded.
