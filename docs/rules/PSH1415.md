# PSH1415 — Hold the concrete type when the concrete type is what you have

**Category:** ApiSelection
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

## Cause

A local variable or private field is declared as an interface but initialized
with an explicitly named class or struct, such as `IList<int> items = new
List<int>()`. Code accesses a member or indexer on the variable, or uses it as
the collection in a `foreach`. Declaring the implementation type can help the
runtime call its members directly.

The declaration must contain one variable. Every reassignment the rule checks
must create the same type with `new Type(...)`. A private field's containing
type must have a single declaration.

## Example

Before:

```csharp
using System.Collections.Generic;

public class Counter
{
    public int Count()
    {
        IList<int> items = new List<int>();
        items.Add(1);
        return items.Count;
    }
}
```

After:

```csharp
using System.Collections.Generic;

public class Counter
{
    public int Count()
    {
        List<int> items = new List<int>();
        items.Add(1);
        return items.Count;
    }
}
```

## What is not reported

- Parameters, return types, non-private fields, `var` declarations, and
  declarations using a base class rather than an interface.
- Variables reassigned from a factory or to a different implementation.
- Variables passed with `ref`, `out`, or an explicit `in` keyword.
- Member calls or property reads that need an explicit interface implementation:
  a member available only through the interface. For example,
  `IList<int>.IsReadOnly` cannot be read directly from `List<int>`.
- Variables only passed, returned, assigned, or compared, with no member access,
  indexer access, or `foreach` use.

## Code fix

The fix replaces only the declared interface type with the implementation type.
It leaves construction and uses in place, keeps surrounding comments, and lets
the editor simplify and format the type name. Comments inside the replaced type
name can be lost. No fix is offered if the replacement type name cannot be used
at that location.

## Configuration

The rule is enabled at `warning` by default. It has no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1415.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when keeping the interface is a deliberate design choice and measurements
show no useful gain. Also suppress when changing the declared type would select
a different overload or change behavior that depends on using the interface.
