# PSH1416 — Cache the serializer options instead of building them per call

**Category:** ApiSelection
**Severity:** Warning
**Code fix:** None.

## Cause

Code constructs `System.Text.Json.JsonSerializerOptions` inside a method,
property getter or setter, local function, or lambda. Both `new
JsonSerializerOptions(...)` and target-typed `new(...)` are covered. An
expression-bodied property that creates options is reported on each construction
site because it creates a fresh instance on every read.

Reusing options lets the serializer reuse the information it caches about your
types, instead of repeating that setup for fresh options.

## Example

Before:

```csharp
using System.Text.Json;

public class Writer
{
    public string Write(object value)
    {
        var options = new JsonSerializerOptions { WriteIndented = true };
        return JsonSerializer.Serialize(value, options);
    }
}
```

After:

```csharp
using System.Text.Json;

public class Writer
{
    private static readonly JsonSerializerOptions Options =
        new() { WriteIndented = true };

    public string Write(object value) => JsonSerializer.Serialize(value, Options);
}
```

## What is not reported

Direct construction in a field initializer, property initializer, or constructor
is excluded. A lambda or local function declared there can still be reported,
because its body runs when called.

Construction that reads a local variable, parameter, instance field, instance
property, `this`, or `base` is excluded. For example, options initialized with
a caller-supplied `TypeInfoResolver` are left alone. The rule reports nothing
when the project does not reference `System.Text.Json.JsonSerializerOptions`.

## How to fix violations

Move reusable options into a `static readonly` field. Finish configuring them
before the first serialization or deserialization. A `readonly` field prevents
replacing the object; it does not make the object's settings immutable.
`JsonSerializerOptions` rejects changes after it has been used by the serializer.

There is no automatic code fix. Choose the shared field's location and check
that its settings and converters are suitable for every caller.

## Configuration

The rule is enabled at `warning` by default. It has no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1416.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress for a factory that must return separately configurable options, or when
settings and converters need different state for each operation. The rule does
not check changes made to the options after construction, so review those before
sharing an instance.
