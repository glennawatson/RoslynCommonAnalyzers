# PSH1419 — Use the built-in cross-platform time-zone API

**Category:** ApiSelection
**Severity:** Warning
**Code fix:** One-argument `GetTimeZoneInfo` calls only (supports Fix All)

## Cause

Code calls one of these static methods on `TimeZoneConverter.TZConvert` while
the corresponding framework API is available:

| Package method | Framework replacement |
| --- | --- |
| `GetTimeZoneInfo` | `TimeZoneInfo.FindSystemTimeZoneById` |
| `IanaToWindows` | `TimeZoneInfo.TryConvertIanaIdToWindowsId` |
| `WindowsToIana` | `TimeZoneInfo.TryConvertWindowsIdToIanaId` |

Using the framework API can remove the need for the package. Methods on your
own types are not reported.

## Example

Before, in a project referencing TimeZoneConverter:

```csharp
public class Zones
{
    public System.TimeZoneInfo Find(string id) =>
        TimeZoneConverter.TZConvert.GetTimeZoneInfo(id);
}
```

After:

```csharp
public class Zones
{
    public System.TimeZoneInfo Find(string id) =>
        System.TimeZoneInfo.FindSystemTimeZoneById(id);
}
```

## Code fix

For a `GetTimeZoneInfo` call with one argument, the fix replaces the method name
and its qualifier with `System.TimeZoneInfo.FindSystemTimeZoneById`. It retains
the argument list. It does not remove imports or the package reference. Comments
inside the replaced method name or between it and the opening parenthesis can
be lost.

The two ID conversion methods have no automatic fix. Their framework
replacements return a success flag and put the converted ID in an `out`
parameter. Check that flag before using the result. For example, on .NET 6 or later:

```csharp
using System;

public class Zones
{
    public string ToWindows(string id)
    {
        if (TimeZoneInfo.TryConvertIanaIdToWindowsId(id, out var windowsId))
        {
            return windowsId;
        }

        throw new ArgumentException("Unknown time-zone ID.", nameof(id));
    }
}
```

## Rule description

Cross-platform ID support requires .NET 6 or later and suitable time-zone data
and runtime settings. Verify that the framework accepts your application's IDs
on each deployed platform before removing the package.

The lookup suggestion can appear on older frameworks because
`FindSystemTimeZoneById` exists there even when it only accepts that platform's
ID style. The two conversion suggestions appear only when their respective
`TryConvert` methods exist. The rule reports nothing without the package type
or `FindSystemTimeZoneById`.

## Configuration

The rule is enabled at `warning` by default. It has no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1419.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when an older target framework still needs the package to accept IDs
from another platform. Also suppress when the package's mappings or fallback
behavior are part of your application's contract, or the deployed runtime
cannot supply the required ID conversion.
