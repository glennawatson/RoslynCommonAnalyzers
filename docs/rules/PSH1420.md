# PSH1420 — Do not hold a per-invocation client in a function class field

**Category:** ApiSelection
**Severity:** Warning
**Code fix:** None.

## Cause

An Azure Functions isolated-worker class or record class declares an instance
field or auto-property with a supported client type. The same declaration must
contain a method with `Microsoft.Azure.Functions.Worker.FunctionAttribute`.

The worker normally creates the function class for each invocation. Creating a
client with that object can repeat connection and cache setup on every request.
A shared client can reuse that work across invocations.

## What is reported

| Client | Namespace |
| --- | --- |
| `HttpClient` | `System.Net.Http` |
| `BlobServiceClient` | `Azure.Storage.Blobs` |
| `QueueServiceClient` | `Azure.Storage.Queues` |
| `ShareServiceClient` | `Azure.Storage.Files.Shares` |
| `DataLakeServiceClient` | `Azure.Storage.Files.DataLake` |
| `TableServiceClient` | `Azure.Data.Tables` |
| `ServiceBusClient` | `Azure.Messaging.ServiceBus` |
| `EventHubProducerClient` | `Azure.Messaging.EventHubs.Producer` |
| `EventGridPublisherClient` | `Azure.Messaging.EventGrid` |
| `CosmosClient` | `Microsoft.Azure.Cosmos` |
| `SecretClient` | `Azure.Security.KeyVault.Secrets` |
| `KeyClient` | `Azure.Security.KeyVault.Keys` |
| `CertificateClient` | `Azure.Security.KeyVault.Certificates` |

The report is on the field or property, whether its value comes from an
initializer, constructor, or dependency injection. **An injected singleton is
still reported.** The rule does not check how the dependency was registered;
holding a reference in a function class does not make a shared client short-lived.

Static members, computed properties, and types without a function method in the
same declaration are excluded. The rule reports nothing unless the project
references both the worker function attribute and `HttpClient`.

## Example

Before, in an isolated-worker project:

```csharp
using System.Net.Http;
using System.Threading.Tasks;
using Microsoft.Azure.Functions.Worker;

public class ImageFunctions
{
    private readonly HttpClient _client = new HttpClient();

    [Function("Run")]
    public Task<string> Run(string url) => _client.GetStringAsync(url);
}
```

After:

```csharp
using System.Net.Http;
using System.Threading.Tasks;
using Microsoft.Azure.Functions.Worker;

public class ImageFunctions
{
    private static readonly HttpClient Client = new HttpClient();

    [Function("Run")]
    public Task<string> Run(string url) => Client.GetStringAsync(url);
}
```

## How to fix violations

Use a shared static client, or register a singleton client and inject it. For an
injected singleton, suppress this report after checking its registration. Do
not dispose a shared client at the end of an invocation.

For `HttpClient`, another option is to inject `IHttpClientFactory` and obtain
clients from it. The factory manages the underlying connections. If you keep
a static `HttpClient`, set `SocketsHttpHandler.PooledConnectionLifetime` when
connections need to refresh after DNS changes.

There is no automatic code fix.

## Configuration

The rule is enabled at `warning` by default. It has no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.PSH1420.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when the field holds a verified singleton or a factory-managed client
whose connections are reused. Suppress for a custom function lifetime that
already shares the client, or a test deliberately exercising client creation.

## Related rules

[PSH1418](PSH1418.md) reports client construction in `using` statements or
declarations and immediate member access on a new client. It leaves direct
field and property initialization alone.
