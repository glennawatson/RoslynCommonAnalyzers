# PSH1421 — Hoist a Regex out of the loop that calls it

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | ApiSelection |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A static `Regex` method is called from inside a loop body.

```csharp
// 👎 reported
foreach (var value in values)
{
    if (Regex.IsMatch(value, "[a-z]+"))
    {
        Handle(value);
    }
}
```

## Rule description

The static `Regex` methods look up the pattern in a process-wide cache on every call: they hash the pattern
string to do it, and take a lock on the cache while they do. That is per-call overhead a loop pays once per
iteration.

Worse, the cache is bounded — `Regex.CacheSize` defaults to fifteen entries — so a program using more
patterns than that evicts and fully re-parses the pattern each time round, turning a lookup into a compile.

A single instance resolves the pattern once:

```csharp
// 👍 — one instance, resolved once
private static readonly Regex Word = new("[a-z]+");

foreach (var value in values)
{
    if (Word.IsMatch(value))
    {
        Handle(value);
    }
}
```

On a hot loop the instance can also carry `RegexOptions.Compiled`, which the static overloads cannot be given
per call without adding another cache key. On .NET 7 and later, a source-generated partial property is better
still: the matcher is emitted at build time, so there is no pattern parsing at run time at all.

### What is reported

- A static `Regex` call written inside a `for`, `foreach`, `while`, or `do` body.

### What is not reported

- An instance call, which already holds its pattern.
- A call outside any loop, where the cache lookup happens once.
- A call inside a lambda or local function declared in the loop, which runs when the delegate does rather
  than once per iteration.

## How to fix violations

Hold the pattern in a `static readonly Regex` field, or — on a framework that has it — a `[GeneratedRegex]`
partial member, and call that from the loop. There is no code fix: naming the field and choosing between the
cached instance and the source generator are decisions about the surrounding code.

## Performance

The rule resolves `Regex` once per compilation and registers nothing when the type is absent, so a project
that never references the regular-expression assembly pays only that one lookup. For a call that does reach
the rule, the loop test is an ancestor walk bounded by the enclosing member.
