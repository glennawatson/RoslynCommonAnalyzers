# PSH1500 — Prefer TypedResults over Results in a minimal API handler

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | AspNetCore |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A call uses `Microsoft.AspNetCore.Http.Results`, such as `Results.Ok()`, and `TypedResults` has a static method with the same name. The call can be anywhere; it does not have to be inside a route handler.

`Results` returns `IResult`, which hides the specific response type. `TypedResults` returns a type such as `Ok<string>`, so the endpoint can describe its status code and response body to API documentation tools.

The rule reports nothing when the project does not reference `TypedResults`, which is available in ASP.NET Core 7 and later. It also skips methods with no matching name on `TypedResults` and unrelated classes named `Results`.

## Example

This handler returns the general `IResult` type:

```csharp
using Microsoft.AspNetCore.Http;

public static class Handlers
{
    public static IResult Get() => Results.Ok("ready");
}
```

Return the specific result type:

```csharp
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Http.HttpResults;

public static class Handlers
{
    public static Ok<string> Get() => TypedResults.Ok("ready");
}
```

## How to fix violations

Change the factory to `TypedResults` and check the method's arguments and return type. A matching method name does not guarantee that every overload accepts the same arguments.

If a handler returns different results, declare the allowed types with `Results<T1, T2>`:

```csharp
using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Http.HttpResults;

public static class Handlers
{
    public static Results<Ok<string>, NotFound> Get(bool found)
        => found ? TypedResults.Ok("ready") : TypedResults.NotFound();
}
```

There is no automatic code fix.

## Configuration

The default severity is `warning`, also used by the recommended preset. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1500.severity = warning
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule for matching files. See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Suppress when a shared API must keep returning `IResult` and adopting typed results would add return-type changes without helping its callers or endpoint documentation.
