# PSH1501 — Use the two-parameter middleware delegate

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | AspNetCore |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An ASP.NET Core `Use` call receives a one-parameter lambda that returns another lambda or anonymous method. This includes a delegate returned directly or by a `return` statement in the outer lambda's block.

The inner delegate keeps access to `next` through captured state, called a closure. The two-parameter overload passes `context` and `next` directly to the handler. The outer lambda runs when the pipeline is built, so this shape alone does not mean a new closure is created for every request.

## Example

This registration nests two lambdas:

```csharp
using Microsoft.AspNetCore.Builder;

public static class MiddlewareSetup
{
    public static void Configure(IApplicationBuilder app)
    {
        app.Use(next => async context =>
        {
            await next(context);
        });
    }
}
```

Put both parameters on one lambda:

```csharp
using Microsoft.AspNetCore.Builder;

public static class MiddlewareSetup
{
    public static void Configure(IApplicationBuilder app)
    {
        app.Use(async (context, next) =>
        {
            await next(context);
        });
    }
}
```

## What is not reported

The rule skips two-parameter middleware, `next => next`, and lambdas that return an existing delegate or call a helper to create one. It also skips unrelated `Use` methods and projects without the ASP.NET Core middleware types.

## How to fix violations

Move `context` beside `next` and remove the inner lambda. Keep `next(context)` so the call selects the overload that accepts a `RequestDelegate`. Keep any work that must run once at startup outside the request handler.

There is no automatic code fix.

## Configuration

The default severity is `warning`, also used by the recommended preset. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1501.severity = warning
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule for matching files. See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Suppress when the outer lambda deliberately creates state once for the pipeline and the returned handler needs that state. Moving that setup into the two-parameter handler would run it on every request.
