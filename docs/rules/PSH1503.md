# PSH1503 — Prefer output caching over response caching

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | AspNetCore |
| Severity | Suggestion |
| Code fix | No |
| Default | Enabled |

## Cause

A call registers ASP.NET Core response caching with `AddResponseCaching` or `UseResponseCaching`, and output caching is available in the project. Output caching is available in ASP.NET Core 7 and later. Unrelated methods with these names are excluded.

Response caching follows HTTP cache headers, so a client's request headers can prevent a cache hit. Output caching lets the server set caching policies, group entries by tag, and remove cached entries when data changes.

## Example

These registrations use response caching:

```csharp
using Microsoft.AspNetCore.Builder;
using Microsoft.Extensions.DependencyInjection;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddResponseCaching();
var app = builder.Build();
app.UseResponseCaching();
app.MapGet("/message", () => "hello");
app.Run();
```

Register output caching and enable it for the endpoint:

```csharp
using Microsoft.AspNetCore.Builder;
using Microsoft.Extensions.DependencyInjection;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddOutputCache();
var app = builder.Build();
app.UseOutputCache();
app.MapGet("/message", () => "hello").CacheOutput();
app.Run();
```

## How to fix violations

Replace both registrations, then enable caching with `CacheOutput()`, an `[OutputCache]` attribute, or a base policy in `AddOutputCache`. Changing the registrations alone does not enable caching for every endpoint.

If routing or CORS middleware is registered explicitly, place `UseOutputCache` after `UseRouting` and `UseCors`. Review expiration and cache-key settings as part of the change. The default output-cache policy excludes authenticated requests and responses that set cookies.

There is no automatic code fix.

## Configuration

The default severity is `suggestion`, also used by the recommended preset. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1503.severity = suggestion
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule for matching files. See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Suppress when response caching is deliberate because the application needs its cache to follow HTTP request and response headers. Output caching does not replace the headers used by browsers and proxies.
