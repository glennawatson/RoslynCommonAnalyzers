# PSH1505 — Handle exceptions in an IExceptionHandler, not an MVC exception filter

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | AspNetCore |
| Severity | Suggestion |
| Code fix | No |
| Default | Enabled |

## Cause

A class directly lists ASP.NET Core's `IExceptionFilter` or `IAsyncExceptionFilter` as an implemented interface, and `IExceptionHandler` is available in the project. `IExceptionHandler` is available in ASP.NET Core 8 and later.

Use a shared exception handler for error responses that apply across the application. An MVC exception filter covers part of MVC request handling. An exception handler can also handle errors from middleware placed after `UseExceptionHandler`.

The rule skips classes that inherit the filter interface through a base class or another interface. It also skips unrelated interfaces with the same names and projects without `IExceptionHandler`.

## Example

This filter handles an application-wide error response inside MVC:

```csharp
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.Mvc.Filters;

public sealed class GlobalExceptionFilter : IExceptionFilter
{
    public void OnException(ExceptionContext context)
    {
        context.Result = new StatusCodeResult(500);
        context.ExceptionHandled = true;
    }
}
```

Move that response into a shared handler:

```csharp
using System;
using System.Threading;
using System.Threading.Tasks;
using Microsoft.AspNetCore.Diagnostics;
using Microsoft.AspNetCore.Http;

public sealed class GlobalExceptionHandler : IExceptionHandler
{
    public ValueTask<bool> TryHandleAsync(
        HttpContext context, Exception exception, CancellationToken cancellationToken)
    {
        context.Response.StatusCode = StatusCodes.Status500InternalServerError;
        return ValueTask.FromResult(true);
    }
}
```

## How to fix violations

Register the handler with `builder.Services.AddExceptionHandler<GlobalExceptionHandler>()` and add `builder.Services.AddProblemDetails()` for fallback error responses. Call `app.UseExceptionHandler()` before the middleware and endpoints whose exceptions it should handle. These registration methods need `Microsoft.Extensions.DependencyInjection` and `Microsoft.AspNetCore.Builder` imports.

Remove the replaced filter registration. Return `true` from `TryHandleAsync` only after handling the error; return `false` to let another handler try. Handlers are singletons, so do not store request-specific state in their fields.

There is no automatic code fix.

## Configuration

The default severity is `suggestion`, also used by the recommended preset. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1505.severity = suggestion
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule for matching files. See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Suppress when the filter needs the selected MVC action's context or must apply only to particular actions or controllers. Keep that scope when moving other error handling into middleware.
