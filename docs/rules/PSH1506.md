# PSH1506 — Synchronous read or write of the HTTP request or response body

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | AspNetCore |
| Severity | Warning |
| Code fix | Yes, in supported async calls |
| Default | Enabled |

## Cause

Code reads or writes `HttpRequest.Body` or `HttpResponse.Body` synchronously. The rule also checks a local initialized from a body property, and a `StreamReader` or `StreamWriter` constructed directly over a body property, either inline or in a local initializer.

The reported method names are `Read`, `ReadByte`, `Write`, `WriteByte`, `Flush`, `CopyTo`, `ReadToEnd`, `ReadLine`, and `ReadBlock`. A report requires an async method with the corresponding name to exist, but its arguments need not match the synchronous call.

Network I/O can hold a request thread while it waits for data. Awaiting an async call releases the thread during that wait. ASP.NET Core servers disable synchronous body I/O by default, so these calls can also throw.

## Example

This method writes the response synchronously:

```csharp
using Microsoft.AspNetCore.Http;

public static class ResponseWriter
{
    public static void Write(HttpContext context, byte[] payload)
    {
        context.Response.Body.Write(payload, 0, payload.Length);
    }
}
```

Use the async call and have the caller await the returned task:

```csharp
using System.Threading.Tasks;
using Microsoft.AspNetCore.Http;

public static class ResponseWriter
{
    public static async Task WriteAsync(HttpContext context, byte[] payload)
    {
        await context.Response.Body.WriteAsync(payload, 0, payload.Length);
    }
}
```

## Code fix

**Await the async overload** changes the method name, keeps the existing arguments, and inserts `await`. It is offered only inside an already-`async` method, local function, or lambda, when an async overload accepts those arguments and produces the same result after awaiting.

The fix formats the edited expression and adds parentheses when needed, such as `(await reader.ReadToEndAsync()).Length`. Comments attached to the replaced method name can be lost.

The fix does not change the containing method's signature or its callers, so the full example above needs a manual edit. It also skips calls reached through `?.` and calls such as `ReadByte` or `WriteByte` that need different arguments for async I/O.

## What is not reported

Async calls and calls on unrelated streams, such as a separate `MemoryStream` or file stream, are excluded. The rule does not follow fields, helper methods, or chains of local aliases back to a body stream. It reports nothing without ASP.NET Core's `HttpRequest` type.

## Configuration

The default severity is `warning`, also used by the recommended preset. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1506.severity = warning
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule for matching files. See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Suppress only when you know the body is backed entirely by memory and the operation cannot wait on network I/O. A synchronous method signature alone is not a reason to suppress.
