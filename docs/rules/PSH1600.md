# PSH1600 — Delegate captures the loop variable inside a component render loop

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Blazor |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A lambda or anonymous method inside a `for` or `foreach` render loop reads the loop variable or a local declared in that loop. The rule checks `BuildRenderTree` methods with one `RenderTreeBuilder` parameter, including render code produced from `.razor` files.

The callback keeps access to a local variable after the loop moves on. This is called a closure. Creating callbacks this way during rendering creates delegates and captured state repeatedly, adding memory that must be collected.

## Example

This component creates a callback for each item on every render:

```csharp
using Microsoft.AspNetCore.Components;
using Microsoft.AspNetCore.Components.Rendering;

public sealed class Rows : ComponentBase
{
    private readonly int[] _items = { 1, 2 };
    private int _selected;

    protected override void BuildRenderTree(RenderTreeBuilder builder)
    {
        foreach (var item in _items)
        {
            builder.OpenElement(0, "button");
            builder.AddAttribute(1, "onclick",
                EventCallback.Factory.Create(this, () => _selected = item));
            builder.AddContent(2, item);
            builder.CloseElement();
        }
    }
}
```

Create each item's callback once and reuse it across renders:

```csharp
using Microsoft.AspNetCore.Components;
using Microsoft.AspNetCore.Components.Rendering;

public sealed class Rows : ComponentBase
{
    private readonly int[] _items = { 1, 2 };
    private EventCallback[] _handlers = System.Array.Empty<EventCallback>();
    private int _selected;

    protected override void OnInitialized()
    {
        _handlers = new EventCallback[_items.Length];
        for (var i = 0; i < _items.Length; i++)
        {
            var item = _items[i];
            _handlers[i] = EventCallback.Factory.Create(this, () => _selected = item);
        }
    }

    protected override void BuildRenderTree(RenderTreeBuilder builder)
    {
        for (var i = 0; i < _items.Length; i++)
        {
            builder.OpenElement(0, "button");
            builder.AddAttribute(1, "onclick", _handlers[i]);
            builder.AddContent(2, _items[i]);
            builder.CloseElement();
        }
    }
}
```

## How to fix violations

Cache each item's callback when the item is created or loaded. Refresh those callbacks when the items change. If all rows perform the same action without using an item value, use one cached handler or a method name.

For a `for` loop, copy the counter into a local before capturing it. This keeps callbacks from all reading the final counter value; it does not remove the allocation warning inside a render loop.

There is no automatic code fix.

## What is not reported

The rule skips method names used as handlers, reused delegate values, and lambdas that read only fields or variables declared outside the loop. It also skips callbacks outside the render method and callbacks inside a local function declared in the loop. A lambda nested directly inside another lambda is not reported separately.

These exclusions do not guarantee that the code allocates nothing. The rule reports nothing without Blazor's `RenderTreeBuilder` type.

## Configuration

The default severity is `warning`, also used by the recommended preset. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1600.severity = warning
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule for matching files. See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Suppress for a small list that renders rarely when measurements show no useful saving from managing cached callbacks. Keep callbacks correct when items change.
