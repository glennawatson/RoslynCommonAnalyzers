# PSH1601 — JavaScript-interop call issued once per loop iteration

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Blazor |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An `InvokeAsync` or `InvokeVoidAsync` call on `IJSRuntime`, `IJSObjectReference`, or a type implementing either appears inside a `for` or `foreach` loop. The rule applies in any method, not only component render methods, and does not depend on the hosting mode.

JavaScript interop lets C# call JavaScript functions. On Interactive Server, each call travels between the server and browser. Awaiting one call per item pays that network delay repeatedly. WebAssembly has no server round trip for the call, but crossing between C# and JavaScript still has a cost.

## Example

This method makes one call for each item:

```csharp
using System.Threading.Tasks;
using Microsoft.JSInterop;

public static class Highlighter
{
    public static async Task ApplyAsync(IJSRuntime js, int[] ids)
    {
        foreach (var id in ids)
        {
            await js.InvokeVoidAsync("app.highlight", id);
        }
    }
}
```

Pass the items in one call:

```csharp
using System.Threading.Tasks;
using Microsoft.JSInterop;

public static class Highlighter
{
    public static async Task ApplyAsync(IJSRuntime js, int[] ids)
    {
        await js.InvokeVoidAsync("app.highlightAll", ids);
    }
}
```

## How to fix violations

Provide a JavaScript function such as `app.highlightAll` that accepts the array and performs the per-item work in the browser. Build the payload before making the call. For large collections, use bounded batches so a single message does not become too large.

There is no automatic code fix.

## What is not reported

The rule skips calls outside `for` and `foreach` loops, unrelated receiver types, and calls inside a lambda or local function declared in the loop. It does not report a standalone `while` or `do` loop. It reports nothing without `Microsoft.JSInterop.IJSRuntime`.

## Configuration

The default severity is `warning`, also used by the recommended preset. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1601.severity = warning
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule for matching files. See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Suppress when each call must wait for the previous result before deciding what to do next and that logic cannot move into JavaScript. A small loop used rarely can also be acceptable after measuring its cost.
