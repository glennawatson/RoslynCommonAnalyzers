# PSH1602 — StateHasChanged is called unconditionally in a render callback

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Blazor |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A component calls `StateHasChanged()` or `this.StateHasChanged()` directly in `OnAfterRender` or `OnAfterRenderAsync`, outside a conditional statement. Expression-bodied callbacks are included.

These callbacks run after a render. Calling `StateHasChanged` each time requests another render, which can keep the component rendering continuously and waste CPU time and network traffic.

## Example

This callback requests another render every time:

```csharp
using Microsoft.AspNetCore.Components;

public sealed class Counter : ComponentBase
{
    protected override void OnAfterRender(bool firstRender)
    {
        StateHasChanged();
    }
}
```

If an extra render is needed only after the first render, guard it:

```csharp
using Microsoft.AspNetCore.Components;

public sealed class Counter : ComponentBase
{
    protected override void OnAfterRender(bool firstRender)
    {
        if (firstRender)
        {
            StateHasChanged();
        }
    }
}
```

## How to fix violations

Remove the call when there is no state change to display. Otherwise, place it inside `if (firstRender)` for one-time work or behind a state flag. Update the flag before requesting the next render so it does not keep requesting more renders.

There is no automatic code fix.

## What is not reported

The rule skips calls inside an `if` or another control statement, calls inside lambdas or local functions, and calls in other methods. It reports nothing without Blazor's `ComponentBase` type.

A call after an early `return` guard is still reported: the rule does not use that guard to decide whether rendering stops. Put the call inside the condition if practical. An unreported condition such as `if (true)` does not make a render loop safe.

## Configuration

The default severity is `warning`, also used by the recommended preset. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1602.severity = warning
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule for matching files. See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Suppress only when you can show that another condition limits the extra renders, such as a correct early-return guard that the rule does not recognize. Do not suppress an unrestricted render loop.
