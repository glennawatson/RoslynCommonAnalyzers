# PSH1603 — Allocation used as a component parameter inside a render loop

| Item | Value |
| --- | --- |
| Package | PerformanceSharp.Analyzers |
| Category | Blazor |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `RenderTreeBuilder.AddComponentParameter` call receives a newly created value inside a `for` or `foreach` loop in `BuildRenderTree`. This includes render code produced from `.razor` files when it uses that call.

The rule reports `new` objects other than delegates, explicit or inferred array creation with `new`, and LINQ calls to `ToList`, `ToArray`, `ToHashSet`, `ToDictionary`, or `ToLookup`. The new value must be passed directly as the parameter value.

Creating a collection for every row on every render produces repeated allocations. Reusing the data removes those allocations. It does not guarantee that a child component will skip rendering; mutable collection parameters can still cause a render even when the reference is unchanged.

## Example

This component builds the same list repeatedly:

```csharp
using System.Collections.Generic;
using Microsoft.AspNetCore.Components;
using Microsoft.AspNetCore.Components.Rendering;

public sealed class Rows : ComponentBase
{
    protected override void BuildRenderTree(RenderTreeBuilder builder)
    {
        for (var i = 0; i < 2; i++)
        {
            builder.OpenComponent<RowView>(0);
            builder.AddComponentParameter(1, "Data", new List<int> { 1, 2 });
            builder.CloseComponent();
        }
    }
}

public sealed class RowView : ComponentBase
{
    [Parameter]
    public IReadOnlyList<int> Data { get; set; } = System.Array.Empty<int>();
}
```

Cache the data and pass it to each child:

```csharp
using System.Collections.Generic;
using Microsoft.AspNetCore.Components;
using Microsoft.AspNetCore.Components.Rendering;

public sealed class Rows : ComponentBase
{
    private readonly IReadOnlyList<int> _data = new List<int> { 1, 2 };

    protected override void BuildRenderTree(RenderTreeBuilder builder)
    {
        for (var i = 0; i < 2; i++)
        {
            builder.OpenComponent<RowView>(0);
            builder.AddComponentParameter(1, "Data", _data);
            builder.CloseComponent();
        }
    }
}

public sealed class RowView : ComponentBase
{
    [Parameter]
    public IReadOnlyList<int> Data { get; set; } = System.Array.Empty<int>();
}
```

## How to fix violations

Create shared values outside the render method. For values that differ by row, store each value with its item and rebuild it when that item's data changes. Share mutable data only when the child components are not meant to own separate copies.

There is no automatic code fix.

## What is not reported

The rule skips existing values, fields, delegate creation, and calls other than the listed LINQ methods. It also skips collection expressions written as `[item]`, values passed through `AddAttribute`, and allocations outside the checked render loops. Those exclusions do not mean the code allocates nothing.

It reports nothing without Blazor's `RenderTreeBuilder` type. [PSH1600](PSH1600.md) covers lambdas that capture loop variables.

## Configuration

The default severity is `warning`, also used by the recommended preset. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.PSH1603.severity = warning
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule for matching files. See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Suppress when each child needs a fresh, independent value on every render and caching would change that behavior. A small list that renders rarely can also be left as written when measurements show that caching is not worthwhile.
