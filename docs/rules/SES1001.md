# SES1001 — AEAD encryption must not use a constant or reused nonce

| Item | Value |
| --- | --- |
| Package | SecuritySharp.Analyzers |
| Category | Cryptography |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An `Encrypt` call on `AesGcm`, `AesCcm`, or `ChaCha20Poly1305` receives a fixed nonce. These ciphers provide authenticated encryption: they hide the message and detect changes to it. A nonce is a value that must be unique for every message encrypted with the same key.

Reusing a nonce with the same key can expose message contents and let an attacker forge messages. A nonce does not need to be secret, but it must not repeat for that key.

The rule reports these nonce arguments, including ones named `nonce:`:

- An inline `new byte[N]` with no initializer, which contains only zeroes.
- An inline `new byte[] { ... }` or `new byte[N] { ... }` whose elements are all constants.
- A `static readonly` field, regardless of how it was initialized.

## Example

This method uses the same all-zero nonce for every message:

```csharp
using System.Security.Cryptography;

public static class MessageEncryption
{
    public static void Encrypt(
        byte[] key, byte[] plaintext, byte[] ciphertext, byte[] tag)
    {
        using var aes = new AesGcm(key, 16);
        aes.Encrypt(new byte[12], plaintext, ciphertext, tag);
    }
}
```

Generate a new nonce for each message and return it for storage with the encrypted data:

```csharp
using System.Security.Cryptography;

public static class MessageEncryption
{
    public static byte[] Encrypt(
        byte[] key, byte[] plaintext, byte[] ciphertext, byte[] tag)
    {
        using var aes = new AesGcm(key, 16);
        byte[] nonce = RandomNumberGenerator.GetBytes(12);
        aes.Encrypt(nonce, plaintext, ciphertext, tag);
        return nonce;
    }
}
```

The caller supplies a ciphertext buffer the same length as the plaintext and a 16-byte tag buffer. The example uses the .NET 8 or later `AesGcm` constructor that specifies the tag size.

## How to fix violations

Use a cryptographic random source for each message's nonce, and store or transmit the nonce alongside the ciphertext and tag. Decryption must receive the same nonce. Use the length required by the chosen cipher.

Random nonces can collide at high message volumes. Follow the cipher's per-key usage limits and rotate keys, or use a counter scheme that guarantees uniqueness across restarts and all senders sharing the key.

## Why there is no code fix

There is no automatic code fix. Generating a nonce also requires deciding where to store it and updating decryption to read it from that location.

## What is not reported

The rule does not track nonce reuse through locals, parameters, instance fields, or mutable static fields. It also skips inferred arrays written with `new[]`, collection expressions, and array initializers with nonconstant elements. Silence does not prove that a nonce is unique.

Only the referenced framework's `AesGcm`, `AesCcm`, and `ChaCha20Poly1305` types are checked. If none is available, nothing is reported.

## Configuration

The default severity is `warning`, also used by the recommended preset. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1001.severity = warning
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule for matching files. See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Suppress for fixed cryptographic test vectors that never encrypt production data. Another valid case requires proof that the nonce cannot repeat with the same key; document that guarantee at the use. Do not suppress to keep a constant nonce with a reused key.
