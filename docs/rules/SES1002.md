# SES1002 — Password-based key derivation must not use a constant or predictable salt

**Category:** Cryptography  
**Severity:** Warning  
**Code fix:** None.

## Cause

A `Rfc2898DeriveBytes` constructor or `Rfc2898DeriveBytes.Pbkdf2` call receives a
fixed salt. A salt is extra data used with a password to derive a key. Each stored
password needs its own random salt so that equal passwords produce different keys.

The rule reports these salt arguments:

- An inline `new byte[N]`, which contains only zeroes.
- An inline `new byte[] { ... }` whose elements are all constants.
- A `static readonly` field, even if it was filled with random bytes once.
- An `Encoding.GetBytes` call with a constant string.

It does not report salts passed through local variables, instance fields, or helper
methods. That does not prove those salts are safe. Constructor overloads that take
a `saltSize` generate their own salt and are not reported.

## How to fix violations

Bad:

```csharp
using System.Security.Cryptography;

public static class PasswordKeys
{
    public static byte[] Derive(string password) =>
        Rfc2898DeriveBytes.Pbkdf2(
            password, new byte[16], 100_000, HashAlgorithmName.SHA256, 32);
}
```

Generate a fresh salt when storing a password, and keep it with the derived key:

```csharp
using System.Security.Cryptography;

public static class PasswordKeys
{
    public static (byte[] Salt, byte[] Key) Derive(string password)
    {
        byte[] salt = RandomNumberGenerator.GetBytes(16);
        byte[] key = Rfc2898DeriveBytes.Pbkdf2(
            password, salt, 100_000, HashAlgorithmName.SHA256, 32);
        return (salt, key);
    }
}
```

Use the stored salt again when checking the password. Generating a new salt during
verification produces a different key. There is no automatic code fix because the
change must include salt storage and retrieval.

## Configuration

The rule is enabled at `warning` by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1002.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress for a fixed test vector that must reproduce a published result. Keep the
rule enabled for real password storage. Reusing a stored per-password salt during
verification is expected; sharing one salt across all passwords is not.
