# SES1003 — Password-based key derivation must use a sufficient iteration count

**Category:** Cryptography  
**Severity:** Warning  
**Code fix:** None.

## Cause

A static `Rfc2898DeriveBytes.Pbkdf2` call uses a constant `iterations` value below
the configured minimum. The default minimum is `100000`. More iterations make each
password guess cost more work if an attacker steals the stored keys and salts.

The rule checks literal numbers and `const` values, including named `iterations`
arguments. It does not check constructors, the `IterationCount` property, or counts
read from fields, parameters, or configuration. Validate those counts yourself.

## How to fix violations

Bad:

```csharp
using System.Security.Cryptography;

public static class PasswordKeys
{
    public static byte[] Derive(byte[] password, byte[] salt) =>
        Rfc2898DeriveBytes.Pbkdf2(
            password, salt, 1000, HashAlgorithmName.SHA256, 32);
}
```

Choose a count that meets your security policy and gives acceptable sign-in times
on your hardware. This example exceeds the default minimum:

```csharp
using System.Security.Cryptography;

public static class PasswordKeys
{
    public static byte[] Derive(byte[] password, byte[] salt) =>
        Rfc2898DeriveBytes.Pbkdf2(
            password, salt, 600_000, HashAlgorithmName.SHA256, 32);
}
```

Store the count with each derived key. Existing keys must be checked with the count
used to create them. There is no automatic code fix because the right count depends
on your application and hardware.

## Configuration

The rule is enabled at `warning` by default.

```ini
[*.cs]
dotnet_diagnostic.SES1003.severity = warning
securitysharp.SES1003.iterations = 100000
```

| Key | Values | Default |
| --- | --- | --- |
| `securitysharp.SES1003.iterations` | Integer from `1` to `2147483647` | `100000` if neither key is valid |
| `securitysharp.iterations` | Integer from `1` to `2147483647` | Fallback when the rule-specific key is absent or invalid |

A valid rule-specific value wins. If it is missing or invalid, the rule tries the
project-wide key. If neither is valid, it uses `100000`. A count equal to the
minimum is accepted. Severity values are `error`, `warning`, `suggestion`, `silent`,
and `none`.

## When to suppress

Suppress for published test vectors or a compatibility path that verifies existing
password records with their original count. Use a suitable count for new records
and upgrade old records after a successful sign-in.
