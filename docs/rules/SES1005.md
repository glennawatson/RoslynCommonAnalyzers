# SES1005 — Compare secret values in constant time

**Category:** Cryptography  
**Severity:** Warning  
**Code fix:** Byte-array and byte-span `SequenceEqual` calls without a comparer.

## Cause

Two strings or byte buffers are compared with `==`, `!=`, `Equals`, or
`SequenceEqual`, and at least one value is named like a secret. Ordinary content
comparisons can take different amounts of time depending on where values differ.
Repeated timing measurements can reveal information about a secret.

Both values must be `string`, `byte[]`, `Span<byte>`, or `ReadOnlySpan<byte>`. The
rule recognizes names containing `hmac`, `signature`, `sig`, `mac`, `tag`, `token`,
`hash`, `digest`, or `secret`, ignoring case. It also checks a called method's name,
such as `ComputeHmac(key)`. Names containing `expected` or `actual` count only
inside a method or local function whose name contains `verify`, `validate`, `check`,
`compare`, `authenticate`, or `match`.

Comparisons with a constant, including `null` or `""`, are not reported. Static
comparison calls with named arguments for either of the first two values are not
reported. The rule reports nothing when `CryptographicOperations` is unavailable.

## How to fix violations

Bad:

```csharp
using System.Linq;
using System.Security.Cryptography;

public static class Signatures
{
    public static bool Verify(byte[] mac, byte[] expectedMac) =>
        mac.SequenceEqual(expectedMac);
}
```

Compare the bytes with `FixedTimeEquals`. For equal-length inputs, its running time
does not depend on their contents:

```csharp
using System.Linq;
using System.Security.Cryptography;

public static class Signatures
{
    public static bool Verify(byte[] mac, byte[] expectedMac) =>
        CryptographicOperations.FixedTimeEquals(mac, expectedMac);
}
```

For strings, choose a consistent encoding or decode their stored format before
comparing the bytes. For byte arrays, `==`, `!=`, and `Equals` compare whether the
arrays are the same object. Decide whether your code needs that check or a content
comparison before changing it.

## Code fix

The fix replaces `left.SequenceEqual(right)` or `Enumerable.SequenceEqual(left,
right)` with `CryptographicOperations.FixedTimeEquals(left, right)`. It handles
byte arrays and byte spans, including span extension calls, when `FixedTimeEquals`
is available. It does not fix strings, equality operators, `Equals`, or calls with
an extra comparer argument.

The fix uses the short type name when the file has a regular
`using System.Security.Cryptography;` directive at the top. Otherwise it writes
`global::System.Security.Cryptography.CryptographicOperations`. It leaves existing
`using` directives in place, including a LINQ import that becomes unused.

The replacement uses a space after the comma. Comments and whitespace around the
whole call are preserved, but comments attached to the old method name, argument
separators, or the edges of either value can be lost. Review comments inside the
call before accepting the fix.

## Configuration

The rule is enabled at `warning` by default. Its name lists cannot be configured.

```ini
[*.cs]
dotnet_diagnostic.SES1005.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when the values are public data, such as file hashes, or when an array
reference check is intentional. A matching name alone does not make a value secret.
Keep the rule enabled for checks that authorize access or authenticate a message.
