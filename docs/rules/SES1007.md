# SES1007 — Do not hand-implement a cryptographic primitive

**Category:** Cryptography  
**Severity:** Warning  
**Code fix:** None.

## Cause

A class derives from `HashAlgorithm`, `KeyedHashAlgorithm`, `HMAC`,
`SymmetricAlgorithm`, `AsymmetricAlgorithm`, or `DeriveBytes` in
`System.Security.Cryptography`. These base classes let you supply a hashing,
encryption, or key-derivation algorithm. Mistakes in such algorithms can expose
secrets even when the code produces the expected output in tests.

Abstract classes and classes that inherit through another class in your source
are also reported. The rule does not inspect method bodies, so a wrapper that
delegates every operation to a trusted implementation can still be reported.

Classes that inherit through a different base class from a referenced assembly,
such as `HMACSHA256` or `Aes`, are not reported. That exclusion does not prove a
custom implementation is secure.

## How to fix violations

Bad: this class starts a custom keyed-hash implementation.

```csharp
using System.Security.Cryptography;

public class MyMac : HMAC
{
}
```

Use a platform algorithm at the call site instead:

```csharp
using System.Security.Cryptography;

public static class MessageTags
{
    public static byte[] Compute(byte[] key, byte[] message)
    {
        using var mac = new HMACSHA256(key);
        return mac.ComputeHash(message);
    }
}
```

Choose the replacement for the task: for example, `SHA256` for hashing,
`HMACSHA256` for authenticating a message, or `Rfc2898DeriveBytes.Pbkdf2` for
deriving a key from a password. Use a reviewed library if the platform lacks the
algorithm you need.

There is no automatic code fix because replacing an algorithm can also require
changes to callers and stored data formats.

## Configuration

The rule is enabled at `warning` by default. Its list of base classes cannot be
configured.

```ini
[*.cs]
dotnet_diagnostic.SES1007.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress for a wrapper that only delegates to a trusted implementation, a test
double, or an algorithm implementation that is the purpose of a specialist
cryptography library and has had appropriate security review. Passing functional
tests alone is not enough reason to suppress a custom algorithm.
