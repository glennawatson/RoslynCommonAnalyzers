# SES1008 — Verify an XML signature against a known key

**Category:** Cryptography  
**Severity:** Warning  
**Code fix:** None.

## Cause

`SignedXml.CheckSignature()` is called without a trusted key or certificate. The
rule also reports a `CheckSignature` overload taking only a `bool`, where one is
available. Calls that pass an `AsymmetricAlgorithm` key or an `X509Certificate2`
certificate are not reported.

A key embedded in the XML document proves only that its owner signed that
document. An attacker can change the document, sign it with their own key, and
include that key. A successful check alone does not identify a trusted sender.

The rule applies to `System.Security.Cryptography.Xml.SignedXml`. It reports
nothing when that type is unavailable. On modern .NET, it is supplied by the
`System.Security.Cryptography.Xml` package.

## How to fix violations

Bad:

```csharp
using System.Security.Cryptography.Xml;

public static class DocumentSignatures
{
    public static bool Verify(SignedXml signedXml) => signedXml.CheckSignature();
}
```

Pass the expected signer's public key, obtained from a source you trust:

```csharp
using System.Security.Cryptography;
using System.Security.Cryptography.Xml;

public static class DocumentSignatures
{
    public static bool Verify(SignedXml signedXml, AsymmetricAlgorithm trustedKey) =>
        signedXml.CheckSignature(trustedKey);
}
```

You can also pass a trusted certificate to `CheckSignature(certificate,
verifySignatureOnly: false)`. Choose which signers your application accepts;
accepting any certificate issued by a trusted authority may be too broad.

If you use `CheckSignatureReturningKey`, validate the returned key against your
trusted signers before accepting the document. There is no automatic code fix
because the rule cannot choose your source of trust.

## Configuration

The rule is enabled at `warning` by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1008.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress for tests that check signature mechanics, or when a separate verified
check establishes that the exact key used belongs to an accepted signer. Do not
suppress merely because the document contains a certificate.
