# SES1009 — Passwords must use a slow, salted key-derivation function

**Category:** Cryptography  
**Severity:** Warning  
**Code fix:** None.

## Cause

A value named like a password is passed to `HashData` or `ComputeHash` on `MD5`,
`SHA1`, `SHA256`, `SHA384`, or `SHA512`. These hashes are fast. If stored password
hashes leak, an attacker can test password guesses quickly. Adding a salt alone
does not slow each guess.

The first input's variable, member, or called method name must contain `password`,
`passwd`, `pwd`, `passphrase`, or `credential`, ignoring case. For a nested
`GetBytes(...)` call, the rule checks that call's first argument, as in
`Encoding.UTF8.GetBytes(password)`.

For `ComputeHash`, the variable's type must be one of the five listed hash types.
Calls through `HashAlgorithm`, keyed hashes such as `HMACSHA256`, and inputs whose
names do not match are not reported. This does not establish that they are suitable
for storing passwords.

## How to fix violations

Bad:

```csharp
using System.Security.Cryptography;
using System.Text;

public static class PasswordKeys
{
    public static byte[] Derive(string password) =>
        SHA256.HashData(Encoding.UTF8.GetBytes(password));
}
```

Use a password hashing or key-derivation function such as PBKDF2, Argon2, scrypt,
or bcrypt. This PBKDF2 example creates a salt for each password and returns the
values needed for verification:

```csharp
using System.Security.Cryptography;

public static class PasswordKeys
{
    public static (byte[] Salt, int Iterations, byte[] Key) Derive(string password)
    {
        byte[] salt = RandomNumberGenerator.GetBytes(16);
        const int iterations = 600_000;
        byte[] key = Rfc2898DeriveBytes.Pbkdf2(
            password, salt, iterations, HashAlgorithmName.SHA256, 32);
        return (salt, iterations, key);
    }
}
```

Store the algorithm, salt, iteration count, and derived key so you can repeat the
same calculation when checking a password. Plan how existing records will be
verified and upgraded. There is no automatic code fix because the change affects
password storage and verification.

## Configuration

The rule is enabled at `warning` by default. The recognized password names and hash
types cannot be configured.

```ini
[*.cs]
dotnet_diagnostic.SES1009.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when a matching name refers to non-password data, or in a limited
compatibility path that verifies old records before upgrading them. Do not use
that exception to create new password records with a fast hash.
