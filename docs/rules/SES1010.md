# SES1010 — Do not implement AES key wrapping by hand

| Item | Value |
| --- | --- |
| Category | Cryptography |
| Severity | Warning |
| Code fix | No |
| Applies to | Frameworks offering `Aes.EncryptKeyWrap` |

## Cause

The AES key-wrap integrity check value appears in source, either as a single 64-bit constant or as the
eight bytes it is made of.

```csharp
private const ulong InitialValue = 0xA6A6A6A6A6A6A6A6;

private static readonly byte[] Iv = { 0xA6, 0xA6, 0xA6, 0xA6, 0xA6, 0xA6, 0xA6, 0xA6 };
```

## Rule description

That constant has one purpose: it is the default initial value AES key wrapping prepends to the key
before wrapping, and compares against after unwrapping to decide whether the result is genuine. Code
holding it is implementing key wrap itself.

A hand-written implementation is exactly where this goes wrong. The unwrap check has to be
constant-time and has to fail closed; the block loop has to run the full six passes in the right
order. Getting any of it subtly wrong yields a routine that still round-trips its own output while
accepting forged or truncated wrapped keys — so it passes every functional test and protects nothing.

The platform ships a vetted implementation that handles the integrity value, the padding, and the
comparison:

```csharp
// 👍
byte[] wrapped = aes.EncryptKeyWrap(keyToProtect);
byte[] unwrapped = aes.DecryptKeyWrap(wrapped);
```

`Aes.TryDecryptKeyWrap` reports failure without throwing, and `Aes.GetKeyWrapLength` sizes the
destination buffer.

## What is not reported

- A shorter run of the same byte, or any other constant. The check value is exactly eight bytes, and
  matching only that keeps the rule precise.
- Anything at all when the referenced framework does not offer `Aes.EncryptKeyWrap`. The rule resolves
  the API in the analyzed compilation and stays silent when it is absent, so a project that cannot
  call it is not told to.

Deriving a cryptographic primitive from an abstract base is a different shape, covered by **SES1007**.

## How to fix violations

Replace the hand-written wrap and unwrap routines with `Aes.EncryptKeyWrap` and `Aes.DecryptKeyWrap`
on an `Aes` instance holding the key-encryption key, and delete the integrity constant. Where the
existing code stores wrapped keys, the platform's output is the standard RFC 3394 format, so already
wrapped material unwraps unchanged.
