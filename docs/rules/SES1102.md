# SES1102 — Do not accept any server certificate

**Category:** Transport  
**Severity:** Warning  
**Code fix:** None.

## Cause

Code reads `HttpClientHandler.DangerousAcceptAnyServerCertificateValidator`. When
used as a certificate validation callback, it accepts every server certificate,
including certificates for the wrong host or from an untrusted issuer. An attacker
can then impersonate the server and read or change traffic.

The rule reports the reference even if you only store the callback in a variable.
It also covers fully qualified references. A member with the same name on an
unrelated type is not reported. The rule reports nothing when your framework does
not provide this member.

## How to fix violations

Bad:

```csharp
using System.Net.Http;

public static class Clients
{
    public static HttpClient Create()
    {
        var handler = new HttpClientHandler
        {
            ServerCertificateCustomValidationCallback =
                HttpClientHandler.DangerousAcceptAnyServerCertificateValidator
        };
        return new HttpClient(handler);
    }
}
```

Remove the callback and use normal certificate validation:

```csharp
using System.Net.Http;

public static class Clients
{
    public static HttpClient Create() => new HttpClient(new HttpClientHandler());
}
```

If a private service uses its own certificate authority, configure the client to
trust that authority. If you need a custom callback, make it enforce your specific
trust policy. Returning `true` for all certificates does not do that.

There is no automatic code fix because the rule cannot choose the required trust
policy or determine whether the callback can be removed safely.

## Configuration

The rule is enabled at `warning` by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1102.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Test
files are checked too; scope an exception to those files if needed.

## When to suppress

Suppress for an isolated test that deliberately exercises invalid certificates or
connects to a controlled local test server. Keep the exception out of production
clients and clients that send real credentials.
