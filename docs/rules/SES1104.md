# SES1104 — Certificate-chain validation must not be deliberately weakened

**Category:** Transport  
**Severity:** Warning  
**Code fix:** None.

## Cause

An assignment to `X509ChainPolicy` disables a certificate trust check:

- `RevocationMode = X509RevocationMode.NoCheck` skips checks for certificates
  withdrawn by their issuer, for example after a private key is stolen.
- `VerificationFlags` includes `AllowUnknownCertificateAuthority` or `AllFlags`,
  allowing certificates that do not lead to a trusted issuer. `AllFlags` also
  ignores other validation errors.

The rule covers direct assignments and object initializers. It recognizes the
named flags on their own or joined with `|`. It does not follow values through
local variables or helper methods.

`Online`, `Offline`, and `NoFlag` are not reported. Other individual verification
flags are also outside this rule; choose them only when your trust policy allows
the specific check they disable.

## How to fix violations

Bad:

```csharp
using System.Security.Cryptography.X509Certificates;

public static class CertificatePolicy
{
    public static void Configure(X509ChainPolicy policy)
    {
        policy.RevocationMode = X509RevocationMode.NoCheck;
        policy.VerificationFlags = X509VerificationFlags.AllFlags;
    }
}
```

Keep revocation and trust checks enabled:

```csharp
using System.Security.Cryptography.X509Certificates;

public static class CertificatePolicy
{
    public static void Configure(X509ChainPolicy policy)
    {
        policy.RevocationMode = X509RevocationMode.Online;
        policy.VerificationFlags = X509VerificationFlags.NoFlag;
    }
}
```

Use `Offline` when your deployment must rely on cached revocation information.
For a private certificate authority, configure trust in that authority instead of
ignoring every unknown issuer. There is no automatic code fix because revocation
access and trust requirements differ between deployments.

## Configuration

The rule is enabled at `warning` by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1104.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress for tests that deliberately construct invalid chains, or for a custom
validation path that performs the skipped checks separately and rejects failures.
Document which check replaces the disabled one. A certificate error alone is not
a reason to turn validation off.
