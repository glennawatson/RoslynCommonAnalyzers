# SES1105 — Bearer and OpenID Connect metadata must not be retrieved over plain HTTP outside development

**Category:** Transport  
**Severity:** Warning  
**Code fix:** None.

## Cause

`JwtBearerOptions.RequireHttpsMetadata` or
`OpenIdConnectOptions.RequireHttpsMetadata` is assigned the literal `false`
without an enclosing development guard. Direct assignments and object initializers
are checked. Assignments of `true` or a value computed elsewhere are not reported.

These handlers download information about an identity provider, including its
signing keys. Allowing plain HTTP lets an attacker on the network replace that
information and supply keys for forged tokens. The option defaults to `true`.
Setting it to `false` permits HTTP; it does not change an HTTPS address into HTTP.

## How to fix violations

Bad:

```csharp
using Microsoft.AspNetCore.Authentication.JwtBearer;

public static class AuthenticationOptions
{
    public static void Configure(JwtBearerOptions options)
    {
        options.RequireHttpsMetadata = false;
    }
}
```

Keep the default, or set it explicitly, and serve metadata over HTTPS:

```csharp
using Microsoft.AspNetCore.Authentication.JwtBearer;

public static class AuthenticationOptions
{
    public static void Configure(JwtBearerOptions options)
    {
        options.RequireHttpsMetadata = true;
    }
}
```

If a local development server requires HTTP, keep the exception inside an explicit
development check:

```csharp
using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.Extensions.Hosting;

public static class AuthenticationOptions
{
    public static void Configure(JwtBearerOptions options, IHostEnvironment env)
    {
        options.RequireHttpsMetadata = true;
        if (env.IsDevelopment())
        {
            options.RequireHttpsMetadata = false;
        }
    }
}
```

There is no automatic code fix because the change must suit your environment and
identity provider.

## What is not reported

An enclosing `if` or `?:` condition containing a call named `IsDevelopment` stops
the report. The rule does not check which branch runs or whether the condition is
negated. Put the exception in the branch that actually runs only during
development. A flag stored in a local variable or a differently named helper does
not count as this guard.

The rule reports nothing when neither authentication options type is referenced.

## Configuration

The rule is enabled at `warning` by default. Guard names cannot be configured.

```ini
[*.cs]
dotnet_diagnostic.SES1105.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when equivalent checks elsewhere restrict the assignment to a controlled
local development environment and cannot be expressed at the call site. Keep HTTPS
required when the application trusts a real identity provider.
