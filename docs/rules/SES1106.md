# SES1106 — Do not send HttpClient requests to a cleartext http URL

**Category:** Transport  
**Severity:** Warning  
**Default:** Enabled

## Cause

An `HttpClient` request uses an `http://` URL written directly in the call. HTTP
does not encrypt the request or response, so someone on the network can read or
change them.

The rule checks URL strings passed to `GetAsync`, `GetStringAsync`,
`GetByteArrayAsync`, `GetStreamAsync`, `PostAsync`, `PutAsync`, `PatchAsync`, and
`DeleteAsync`. It also checks strings inside `new Uri(...)` passed to these methods
or assigned to `HttpClient.BaseAddress`. The scheme is case-insensitive.

## Example

Bad:

```csharp
using System.Net.Http;
using System.Threading.Tasks;

public class ApiClient
{
    public Task<HttpResponseMessage> GetAsync(HttpClient client) =>
        client.GetAsync("http://example.com/api");
}
```

Corrected, after confirming the endpoint supports HTTPS on that host and port:

```csharp
using System.Net.Http;
using System.Threading.Tasks;

public class ApiClient
{
    public Task<HttpResponseMessage> GetAsync(HttpClient client) =>
        client.GetAsync("https://example.com/api");
}
```

No code fix is available; changing the scheme can break an endpoint that does not support HTTPS.

## What is not reported

- HTTPS URLs and loopback hosts: `localhost`, `*.localhost`, `127.0.0.1`, and `[::1]`.
- URLs supplied through variables, constants, interpolation, concatenation, or configuration.
- URLs inside an `HttpRequestMessage` passed to `SendAsync`.

An unreported URL can still use insecure HTTP. Check URLs read from configuration too.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1106.severity = warning
```

The default is `warning`. Allowed severities are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress a specific request when it must test HTTP behavior or contact a legacy
endpoint without HTTPS, and the accepted exposure is documented. Prefer HTTPS for
production traffic. Loopback requests do not need suppression.
