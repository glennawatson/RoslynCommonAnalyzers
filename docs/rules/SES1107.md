# SES1107 — Do not weaken SQL connection transport security

**Category:** Transport  
**Severity:** Warning  
**Default:** Enabled

## Cause

A SQL connection disables required encryption or accepts a server certificate
without checking it. This can expose database traffic to reading or tampering.
The rule applies to `Microsoft.Data.SqlClient` and `System.Data.SqlClient`.

It reports these settings in a string literal passed to a `SqlConnection` or
`SqlConnectionStringBuilder` constructor, or assigned to their `ConnectionString` property:

- `TrustServerCertificate=true` or `yes`.
- `Encrypt=false`, `no`, or `optional`.

Keys and values are case-insensitive, and surrounding whitespace is ignored.
It also reports builder property assignments and object initializers that set
`TrustServerCertificate` to constant `true`, `Encrypt` to constant `false`, or
`Encrypt` to `SqlConnectionEncryptOption.Optional` where that option exists.

## Example

Bad:

```csharp
using Microsoft.Data.SqlClient;

using var connection = new SqlConnection(
    "Server=db;Encrypt=false;TrustServerCertificate=true");
```

Corrected:

```csharp
using Microsoft.Data.SqlClient;

using var connection = new SqlConnection(
    "Server=db;Encrypt=true;TrustServerCertificate=false");
```

Configure the server to support encryption and present a certificate the client
trusts before changing the connection. `Mandatory` and `Strict` encryption options
are also accepted where supported by the client.

No code fix is available; the server must be ready for an encrypted, validated connection.

## What is not reported

Connection strings supplied through variables, constants, interpolation, or
configuration are not checked. Builder property values chosen at runtime are also
not reported. These exclusions do not establish that a connection is secure.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1107.severity = warning
```

The default is `warning`. Allowed severities are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress a specific setting in an isolated test that needs an invalid certificate
or unencrypted connection. For a legacy production server, document the accepted
exposure and the plan to enable encryption and certificate validation.
