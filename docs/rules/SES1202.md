# SES1202 — Do not hard-code a credential value

**Category:** Secrets  
**Severity:** Warning  
**Default:** Enabled

## Cause

A non-empty string literal is passed directly to a method or constructor parameter
whose name indicates a credential. The value does not need to match a known key
format. A hard-coded credential is exposed in source and the built application.

Parameter names are matched case-insensitively, for both positional and named arguments:

- `apiKey`, `api_key`, `password`, `passwd`, `pwd`.
- `secret`, `clientSecret`, `client_secret`.
- `token`, `accessToken`, `access_token`, `sasToken`, `sas_token`.
- `connectionString`, `connection_string`.
- `accessKey`, `access_key`, `accountKey`, `account_key`, `privateKey`, `private_key`.

A parameter named `key` is also checked on `System.Net.NetworkCredential`,
`Azure.AzureKeyCredential`, `Azure.Core.AzureKeyCredential`,
`Azure.Identity.ClientSecretCredential`, and `System.ClientModel.ApiKeyCredential`.
An ordinary `key` parameter on another type is not checked.

## Example

Bad:

```csharp
using System.Net;

public class Credentials
{
    public NetworkCredential Create() =>
        new NetworkCredential("svc-account", "literal-password-value");
}
```

Corrected:

```csharp
using System;
using System.Net;

public class Credentials
{
    public NetworkCredential Create() =>
        new NetworkCredential("svc-account",
            Environment.GetEnvironmentVariable("SERVICE_PASSWORD")
            ?? throw new InvalidOperationException("Service password is not configured."));
}
```

Read real credentials from configuration outside version control, environment
variables, or a secret store. Replace any real credential that has been exposed.

No code fix is available; choose the source of the credential.

## What is not reported

- Variables, `const` references, and other expressions instead of a direct string literal.
- Empty strings, values made of one repeated character, values starting with `<`
  or `your`, and placeholders such as `changeme`, `placeholder`, `example`, or `test`.

Moving a literal into a variable or constant does not protect the secret.
[SES1201](SES1201.md) can report its content wherever the literal is declared.
Conversely, this rule can report a literal passed to `connectionString` even when
it contains no password; the parameter name is enough.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1202.severity = warning
```

The default is `warning`. Allowed severities are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options or example allow-lists.

## When to suppress

Suppress a specific argument that is verified test data or is not a credential,
such as a password-free connection string or a non-secret value passed to a
parameter named `token`. Document why that value can be public.
