# SES1203 — Do not use an empty or missing database connection-string password

**Category:** Secrets  
**Severity:** Warning  
**Default:** Enabled

## Cause

A string literal contains a database connection string with a user key but no
non-empty password. If the server accepts that account without another form of
authentication, anyone who can reach it may be able to sign in.

The literal must contain both:

- `Server`, `Data Source`, `Host`, `Initial Catalog`, or `Database`.
- `User ID` or `Uid`.

It is reported if `Password` or `Pwd` is missing, empty, or only whitespace. Keys
are case-insensitive and surrounding whitespace is ignored. The presence of a user
key counts even when its value is empty.

## Example

Bad:

```csharp
public class DatabaseSettings
{
    public string GetConnectionString() =>
        "Server=db;Database=app;User Id=sa;Password=;";
}
```

Corrected, when the database supports integrated authentication:

```csharp
public class DatabaseSettings
{
    public string GetConnectionString() =>
        "Server=db;Database=app;Integrated Security=true;";
}
```

Otherwise, supply a strong password from a secret store or configuration outside
version control. Reading a connection string from configuration is only a fix if
that configuration supplies suitable authentication.

No code fix is available; choose the authentication method and supply any required secret.

## What is not reported

- `Integrated Security=true` or `SSPI`, or `Trusted_Connection=true` or `yes`.
- Connection strings without a recognized user key or data-source key.
- Literals with any non-empty `Password` or `Pwd` value. A hard-coded password can
  still be reported by [SES1201](SES1201.md).
- Connection strings assembled through variables, expressions, or builder properties.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1203.severity = warning
```

The default is `warning`. Allowed severities are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress a literal in a test of missing-password behavior, or a connection where
authentication is supplied separately, such as an access token. Confirm how the
server authenticates that connection before suppressing it.
