# SES1301 — Do not build a process command line from non-constant string parts

**Category:** Injection  
**Severity:** Warning  
**Default:** Enabled

## Cause

A string built with interpolation or `+` is assigned to
`ProcessStartInfo.Arguments`, including in an object initializer, or passed to the
`arguments` string parameter of `Process.Start`. At least one part is not a
compile-time constant: its value is chosen while the program runs.

Spaces and quotes in that value can change where arguments start and end. An
attacker may be able to add options or, when a command interpreter is involved,
commands. Use `ArgumentList` to pass each argument as a separate value.

## Example

Bad:

```csharp
using System.Diagnostics;

public class Commands
{
    public ProcessStartInfo Clone(string repository)
    {
        var start = new ProcessStartInfo("git");
        start.Arguments = $"clone {repository}";
        return start;
    }
}
```

Corrected:

```csharp
using System.Diagnostics;

public class Commands
{
    public ProcessStartInfo Clone(string repository)
    {
        var start = new ProcessStartInfo("git") { UseShellExecute = false };
        start.ArgumentList.Add("clone");
        start.ArgumentList.Add("--");
        start.ArgumentList.Add(repository);
        return start;
    }
}
```

`ArgumentList` handles quoting. In this example, Git's `--` also prevents the
repository value from being read as an option. Validate values according to the
program being launched; quoting does not make arbitrary commands or options safe.

No code fix is available; you must decide where one intended argument ends and the next begins.

## What is not reported

Constant strings, including concatenations or interpolations made entirely from
constants, are not reported. A bare variable or method call is also not reported,
even if it returns an unsafe command line. `ArgumentList` and the collection
overload of `Process.Start` are outside this rule.

The rule reports nothing when `ProcessStartInfo.ArgumentList` is unavailable,
including .NET Framework and .NET Standard 2.0 targets. `ArgumentList` is available
on .NET Core 2.1 and later and .NET Standard 2.1.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1301.severity = warning
```

The default is `warning`. Allowed severities are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress a specific command line when the launched program requires a custom
argument format and you have verified its escaping for every variable part.
Prefer separate arguments whenever the program accepts them.
