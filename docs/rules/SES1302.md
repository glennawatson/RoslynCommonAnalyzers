# SES1302 — A shell-executed process must not use a non-constant FileName

**Category:** Injection  
**Severity:** Warning  
**Default:** Enabled

## Cause

A `new ProcessStartInfo(...)` object initializer sets `UseShellExecute = true`
while its `FileName` is not a compile-time constant. The filename comes from the
initializer when present, otherwise from the constructor's `fileName` argument.

Shell execution asks the operating system to open the named program, document, or
URL. A filename controlled by outside data can launch an unintended program or handler.

## Example

Bad:

```csharp
using System.Diagnostics;

public class Commands
{
    public ProcessStartInfo Create(string fileName) => new ProcessStartInfo(fileName)
    {
        UseShellExecute = true
    };
}
```

Corrected, when the intended operation is to launch Git on this deployment:

```csharp
using System.Diagnostics;

public class Commands
{
    public ProcessStartInfo Create() => new ProcessStartInfo("/usr/bin/git")
    {
        UseShellExecute = false
    };
}
```

Choose a fixed executable path appropriate to the deployment. Pass user data as
arguments through `ArgumentList` where available. Turning shell execution off
does not make an attacker-chosen executable safe. If opening a document or URL
requires shell execution, restrict the allowed destinations before launching it.

No code fix is available; changing shell execution can break document or URL opening.

## What is not reported

- A constant filename, including one that overrides a variable constructor argument.
- An initializer without the literal `UseShellExecute = true`; a Boolean variable
  or `const` reference in that assignment is not checked.
- A creation with no filename, separate property assignments, or target-typed `new(...)`.

A variable filename inside the checked initializer or constructor is reported
even when its value was assigned earlier. These exclusions are limits of the rule,
not proof that a launch is safe.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1302.severity = warning
```

The default is `warning`. Allowed severities are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress a launch that intentionally opens a user-selected document or URL after
checking it against your application's allowed paths, schemes, and destinations.
Also consider suppression for a trusted executable path read from deployment
configuration that users cannot change.
