# SES1303 — Regular-expression pattern must not be built from non-constant data

**Category:** Injection  
**Severity:** Warning  
**Default:** Enabled

## Cause

A regular-expression pattern is chosen or built while the program runs. Someone
who controls the pattern can change what matches, add capture groups, or supply a
pattern that takes too long to evaluate.

The rule checks the `pattern` argument of `new Regex(...)` and the static
`Regex.IsMatch`, `Match`, `Matches`, `Replace`, and `Split` methods. Named
`pattern:` arguments are checked too. Variables, fields, method results, and
expressions with non-constant parts are reported, regardless of whether their
source is trusted.

## Example

Bad, when the application should enforce a fixed validation rule:

```csharp
using System.Text.RegularExpressions;

public class Validator
{
    public bool IsValid(string input, string userPattern) =>
        Regex.IsMatch(input, userPattern);
}
```

Corrected: define the allowed format in source and pass user text as the input.

```csharp
using System.Text.RegularExpressions;

public class Validator
{
    public bool IsValid(string input) => Regex.IsMatch(input, "^[a-z]+$");
}
```

For literal text comparisons, use string operations such as `string.Equals` with
an explicit `StringComparison`. If a pattern must contain runtime text, use
`Regex.Escape` on each part that should match literally. The resulting pattern is
still non-constant and is still reported; review it before suppressing the diagnostic.

No code fix is available; escaping a value changes its meaning when it was intended as a pattern.

## What is not reported

String literals, `const` references, and expressions made entirely from constants
are accepted. Variable input with a constant pattern is accepted. Instance calls
such as `regex.IsMatch(input)` do not supply a pattern and are not checked here.

A constant pattern can still take too long on some input. Set an appropriate
matching timeout when input is untrusted.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1303.severity = warning
```

The default is `warning`. Allowed severities are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options or escape-method exceptions.

## When to suppress

Suppress a reviewed pattern built from fixed syntax and correctly escaped literal
text, or a pattern selected from trusted configuration. If accepting full patterns
is a required feature, constrain their source and execution time before suppressing.
