# SES1304 — Do not build a write path from an archive entry name without a containment check

**Category:** Injection  
**Severity:** Warning  
**Default:** Enabled

## Cause

An archive entry name is joined into a path and passed directly to a file write in
the same expression. An entry such as `../outside.txt` or an absolute path can
write outside the intended directory. This is path traversal.

The entry name must be a direct argument of `Path.Combine` or a direct operand of
the final string `+` operation. The combined path must then be passed directly as
the destination to one of these calls:

| Entry name | Calls checked |
| --- | --- |
| `ZipArchiveEntry.FullName` | `File.Create`, `File.WriteAllBytes`, `File.WriteAllText` |
| `TarEntry.Name` | The same calls, plus `TarEntry.ExtractToFile`, `File.OpenWrite`, and `new FileStream` |

## Example

Bad:

```csharp
using System.IO;
using System.IO.Compression;

public class ArchiveWriter
{
    public void Write(ZipArchiveEntry entry, string destination, byte[] bytes)
    {
        File.WriteAllBytes(Path.Combine(destination, entry.FullName), bytes);
    }
}
```

Corrected: resolve the full path and reject entries outside the destination.

```csharp
using System;
using System.IO;
using System.IO.Compression;

public class ArchiveWriter
{
    public void Write(ZipArchiveEntry entry, string destination, byte[] bytes)
    {
        string root = Path.GetFullPath(destination);
        string prefix = root.EndsWith(Path.DirectorySeparatorChar)
            ? root
            : root + Path.DirectorySeparatorChar;
        string target = Path.GetFullPath(Path.Combine(root, entry.FullName));

        if (!target.StartsWith(prefix, StringComparison.Ordinal))
        {
            throw new IOException("Archive entry is outside the destination.");
        }

        File.WriteAllBytes(target, bytes);
    }
}
```

The trailing separator prevents a sibling such as `data-other` from matching a
root named `data`. Use a destination that untrusted users cannot modify; this
string check does not prevent symbolic links from pointing outside it.

No code fix is available; choose the destination root and how to reject an unsafe entry.

## What is not reported

Names or paths stored in variables, or entry names passed through helper methods,
are not checked. Zip entry paths passed to `ExtractToFile`, `File.OpenWrite`, or
`new FileStream` are also outside this rule. They still need containment checks.

The Tar cases require `System.Formats.Tar`, available on .NET 7 and later.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1304.severity = warning
```

The default is `warning`. Allowed severities are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress a write only when the exact entry name and destination have already been
validated, or a test deliberately exercises unsafe archive names. Document the
check that guarantees the write stays inside the intended directory.
