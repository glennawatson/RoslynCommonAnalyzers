# SES1305 — Do not build a storage path from an uploaded file name

**Category:** Injection  
**Severity:** Warning  
**Default:** Enabled

## Cause

`Microsoft.AspNetCore.Http.IFormFile.FileName` is used directly to build or access
a file path. The uploading client chooses this name and can include `..` or an
absolute path, allowing access outside the intended upload directory.

The rule reports the `FileName` access when it is:

- An argument to `Path.Combine`, `File.Create`, `File.OpenWrite`,
  `File.WriteAllBytes`, `File.Copy`, or `new FileStream`. Either source or
  destination arguments of `File.Copy` are checked.
- Part of a string `+` chain that contains a string literal with `/` or `\`.
  This can also report URL-building code.

## Example

Bad:

```csharp
using System.IO;
using Microsoft.AspNetCore.Http;

public class UploadPaths
{
    public string GetStoragePath(IFormFile file, string root) =>
        Path.Combine(root, file.FileName);
}
```

Corrected: generate the stored name on the server.

```csharp
using System;
using System.IO;

public class UploadPaths
{
    public string GetStoragePath(string root) =>
        Path.Combine(root, Guid.NewGuid().ToString("N"));
}
```

Use a server-controlled upload directory outside the web root. Keep the original
name as metadata if needed. If you must retain that name on disk,
`Path.GetFileName(file.FileName)` removes directory parts recognized by the host
platform and is not reported. Still reject empty names, `.` and `..`, validate
allowed names, and prevent overwriting existing files.

No code fix is available; choose whether to preserve the client name or generate a stored name.

## What is not reported

Names copied into variables or passed through helper calls are not checked.
Concatenations without a path-separator literal and calls such as `File.ReadAllText`
are not reported. A lack of a diagnostic does not make those uses safe.

The rule applies to the `FileName` property declared by `IFormFile`; it does not
report an unrelated property with the same name. It reports nothing when the
project does not reference `IFormFile`.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1305.severity = warning
```

The default is `warning`. Allowed severities are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress a specific use when the name has already passed strict validation, or
when a reported concatenation is display text and never addresses a file or
resource. Document that constraint. Do not trust a name because the client
supplied it through a file picker.
