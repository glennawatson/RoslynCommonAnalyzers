# SES1307 — Do not create predictable temporary files with Path.GetTempFileName

| Item | Value |
| --- | --- |
| Package | SecuritySharp.Analyzers |
| Category | Injection |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

The code calls `System.IO.Path.GetTempFileName()`. This includes fully qualified
calls and calls made through `using static System.IO.Path`.

The method creates a file in the temporary directory and closes it. Your code must
open it again to use it. Check who can access that directory and file: another user
with enough access could read the data or replace the file before you open it.

`Path.GetRandomFileName()` and `Path.GetTempPath()` are not reported. Neither are
methods named `GetTempFileName` on other types.

## Example

Reported:

```csharp
using System.IO;

public static class TemporaryFiles
{
    public static string Create() => Path.GetTempFileName();
}
```

Use a random name and open the file with `FileMode.CreateNew`, which fails if the
name already exists:

```csharp
using System.IO;

public static class TemporaryFiles
{
    public static FileStream Create(string privateDirectory)
    {
        string path = Path.Combine(privateDirectory, Path.GetRandomFileName());
        return new FileStream(path, FileMode.CreateNew, FileAccess.ReadWrite,
            FileShare.None, 4096, FileOptions.DeleteOnClose);
    }
}
```

## How to fix violations

There is no automatic code fix.

Use a directory whose permissions restrict access to the intended user. Keep using
the open stream, and dispose it when finished; the example deletes the file on close.
`Path.GetRandomFileName()` supplies only a name, so it does not replace the file
creation step by itself.

On .NET 7 and later, `Directory.CreateTempSubdirectory()` is another option for an
isolated temporary directory. Delete the directory when finished. The diagnostic
suggests this API only when it is available to your project.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1307.severity = warning
```

The rule is enabled by default as a warning. There are no
rule-specific options. Severity values are `none`, `silent`, `suggestion`, `warning`,
and `error`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the temporary directory is controlled, other users cannot read or
replace the file, and the existing create-then-open behaviour is required.
