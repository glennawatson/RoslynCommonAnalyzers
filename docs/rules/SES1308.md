# SES1308 — Do not create a group- or world-writable file or directory

| Item | Value |
| --- | --- |
| Package | SecuritySharp.Analyzers |
| Category | Injection |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A constant `UnixFileMode` grants `GroupWrite` or `OtherWrite` through one of these APIs:

- `File.SetUnixFileMode` or the mode overload of `Directory.CreateDirectory`.
- `FileInfo.UnixFileMode` or `DirectoryInfo.UnixFileMode`.
- `FileStreamOptions.UnixCreateMode`.

These permissions let other accounts change the file, or change entries in the
directory. The rule reports single flags, combinations joined with `|`, and values
held in `const` fields or locals.

## Example

Reported:

```csharp
using System.IO;

public static class Permissions
{
    public static void Set(string path) => File.SetUnixFileMode(path,
        UnixFileMode.UserRead | UnixFileMode.UserWrite | UnixFileMode.GroupWrite);
}
```

Grant write access only to the owner:

```csharp
using System.IO;

public static class Permissions
{
    public static void Set(string path) => File.SetUnixFileMode(path,
        UnixFileMode.UserRead | UnixFileMode.UserWrite);
}
```

## How to fix violations

There is no automatic code fix.

Remove `GroupWrite` and `OtherWrite` unless sharing requires them. Keep any read or
execute permissions that the file or directory needs.

## What is not reported

Owner-only writes and read/execute access for other users are not reported. Values
read from non-constant variables, parameters, or method calls are not checked;
validate those permissions yourself. Unrelated APIs with the same names are ignored.

The rule requires `System.IO.UnixFileMode`, available in .NET 7 and later. It reports
nothing when that type is unavailable.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1308.severity = warning
```

The rule is enabled by default as a warning. There are no
rule-specific options. Severity values are `none`, `silent`, `suggestion`, `warning`,
and `error`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress a specific assignment when a trusted group must write to a shared file or
directory and group membership is controlled. Allowing every local user to write
needs a separate, deliberate access policy.
