# SES1310 — Do not bind to a directory without authenticating

| Item | Value |
| --- | --- |
| Package | SecuritySharp.Analyzers |
| Category | Injection |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

The code creates a `System.DirectoryServices.DirectoryEntry` with either:

- `AuthenticationTypes.Anonymous` as a constructor argument or as the
  `AuthenticationType` value in an object initializer.
- A literal path starting with `LDAP:` and both username and password written as
  `""` or `null`. The path check ignores letter case.

Both `new DirectoryEntry(...)` and `DirectoryEntry entry = new(...)` are covered.
An anonymous directory bind supplies no user identity. Use an authenticated account
when directory data must be restricted to known callers.

## Example

Reported:

```csharp
using System.DirectoryServices;

public static class DirectoryConnection
{
    public static DirectoryEntry Connect(string userName, string password) =>
        new DirectoryEntry("LDAP://ad.example.com", userName, password,
            AuthenticationTypes.Anonymous);
}
```

Use an authenticated account:

```csharp
using System.DirectoryServices;

public static class DirectoryConnection
{
    public static DirectoryEntry Connect(string userName, string password) =>
        new DirectoryEntry("LDAP://ad.example.com", userName, password,
            AuthenticationTypes.Secure);
}
```

## How to fix violations

There is no automatic code fix.

Supply valid credentials and choose an authentication type supported by your
directory. Read credentials from a secret store or hosting environment. Dispose the
returned `DirectoryEntry` after use, and configure transport protection for the
deployment.

## What is not reported

The empty-credential check ignores paths or credentials supplied through variables,
paths for other providers such as `WinNT:`, and calls that omit credentials.
Supplying only one empty credential does not trigger that check. Choosing
`AuthenticationTypes.Anonymous` still triggers the rule when credentials are supplied.

The rule checks construction, not later assignments to `AuthenticationType`. It
reports nothing when `System.DirectoryServices` is not referenced.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1310.severity = warning
```

The rule is enabled by default as a warning. There are no
rule-specific options. Severity values are `none`, `silent`, `suggestion`, `warning`,
and `error`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress explicit anonymous access only for directory data intended to be public.
For a null-credential case that deliberately uses the current Windows identity,
verify that the deployed bind authenticates with that identity before suppressing.
