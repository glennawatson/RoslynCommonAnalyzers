# SES1401 — A type resolved from non-constant data must not be instantiated or used as a deserialization target

| Item | Value |
| --- | --- |
| Package | SecuritySharp.Analyzers |
| Category | Serialization |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An inline `Type.GetType(name)` call uses a non-constant name and is passed directly
to a `System.Type` parameter of `Activator.CreateInstance` or a method named
`Deserialize`.

If an attacker controls the name, they can choose the type your application creates.
Its constructor or deserialization code can run before your application checks the
result.

## Example

Reported:

```csharp
using System;

public static class Factory
{
    public static object Create(string typeName) =>
        Activator.CreateInstance(Type.GetType(typeName));
}
```

Choose a known type:

```csharp
using System;
using System.Text;

public static class Factory
{
    public static object Create() => Activator.CreateInstance(typeof(StringBuilder));
}
```

## How to fix violations

There is no automatic code fix.

Use `typeof(...)` or the generic creation/deserialization API for the expected type.
If several types are allowed, map input values to a fixed set of types and reject
everything else before creating an object.

## What is not reported

Constant names, `typeof(...)`, generic `Activator.CreateInstance<T>()`, and
`assembly.GetType(name)` are not reported. A type stored in a variable before the
creation or deserialization call is also not reported. These exclusions do not
validate the source of the type name.

The `Deserialize` check applies to any method with that name and a `System.Type`
parameter, including methods in your own code. The creation check applies only to
`System.Activator`.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1401.severity = warning
```

The rule is enabled by default as a warning. There are no
rule-specific options. Severity values are `none`, `silent`, `suggestion`, `warning`,
and `error`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the type name comes from a trusted source or an enforced list of
allowed types, and the application requires dynamic type selection. Keep that check
close to the creation or deserialization call.
