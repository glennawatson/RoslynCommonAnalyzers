# SES1402 — Do not load an assembly from raw bytes or a non-constant location

| Item | Value |
| --- | --- |
| Package | SecuritySharp.Analyzers |
| Category | Serialization |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

The code loads an assembly through one of these APIs:

- `Assembly.Load` with a `byte[]` as its first parameter.
- `AssemblyLoadContext.LoadFromStream`.
- `Assembly.LoadFrom`, `Assembly.LoadFile`, or `Assembly.UnsafeLoadFrom` with a
  non-constant path.

An assembly contains executable code. Loading code from an untrusted source gives
it access to the permissions of your application.

## Example

Reported:

```csharp
using System.Reflection;

public static class Plugins
{
    public static Assembly Load(string path) => Assembly.LoadFrom(path);
}
```

Use a fixed path to an assembly you ship:

```csharp
using System.Reflection;

public static class Plugins
{
    public static Assembly Load() => Assembly.LoadFrom("plugins/known.dll");
}
```

## How to fix violations

There is no automatic code fix.

Prefer a normal project or package reference. If loading is required, restrict it to
assemblies from trusted sources and protect their files from replacement. A constant
path alone does not make a file trustworthy.

For downloaded plugins, verify their contents against a trusted signature or hash
before loading. A collectible `AssemblyLoadContext` supports unloading; it does not
prevent loaded code from accessing your process or its data. Use a separate process
with restricted permissions when untrusted code must run.

## What is not reported

`Assembly.Load(string)` and `Assembly.Load(AssemblyName)` are outside this rule, as
are literal or `const` paths passed to the path-based APIs.

An in-memory load is also ignored when its source argument is a direct call named
`GetManifestResourceStream`, such as
`context.LoadFromStream(host.GetManifestResourceStream("Embedded.Plugin.dll"))`.
The rule checks the method name for this exception; it does not verify that the
resource is trustworthy. Passing the stream through a variable or helper does not
receive this exception.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1402.severity = warning
```

The rule is enabled by default as a warning. There are no
rule-specific options. Severity values are `none`, `silent`, `suggestion`, `warning`,
and `error`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress a load when it is required by a plugin system and the bytes or path have
been checked against a trusted source before loading. Document how the application
prevents untrusted replacement of that input.
