# SES1403 — JSON deserialization depth limit must stay within a safe ceiling

| Item | Value |
| --- | --- |
| Package | SecuritySharp.Analyzers |
| Category | Serialization |
| Severity | Info (suggestion) |
| Code fix | No |
| Default | Enabled |

## Cause

A constant `MaxDepth` value exceeds the configured ceiling, which defaults to `64`.
The rule checks object initializers and assignments on `JsonSerializerOptions`,
`JsonReaderOptions`, and `JsonDocumentOptions` from `System.Text.Json`.

The depth limit bounds how deeply objects and arrays can nest. A large limit lets
untrusted input consume more resources in JSON processing and in code that walks
the resulting data.

## Example

Reported with the default ceiling:

```csharp
using System.Text.Json;

public static class JsonSettings
{
    public static JsonSerializerOptions Create() =>
        new JsonSerializerOptions { MaxDepth = 5000 };
}
```

Keep the depth within the ceiling:

```csharp
using System.Text.Json;

public static class JsonSettings
{
    public static JsonSerializerOptions Create() =>
        new JsonSerializerOptions { MaxDepth = 64 };
}
```

## How to fix violations

There is no automatic code fix.

Leave the framework default or choose the smallest depth your inputs need. For
unusually deep documents, consider changing their structure before raising the limit.

## What is not reported

Values at or below the configured ceiling are not reported. `0` selects the
framework default of `64` and is not reported, even when your configured ceiling is
lower than `64`.

Non-constant values, including values read from configuration, are not checked.
Validate them at runtime; moving a large value into a variable does not make it safe.
Unrelated `MaxDepth` properties are ignored. The rule reports nothing when none of
the supported `System.Text.Json` option types is available.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1403.severity = suggestion
securitysharp.SES1403.maxdepth = 64
```

| Key | Values | Default |
| --- | --- | --- |
| `securitysharp.SES1403.maxdepth` | Integer from `1` to `2147483647` | `64` when neither key is valid |
| `securitysharp.maxdepth` | Integer from `1` to `2147483647` | `64` when neither key is valid |

A valid rule-specific value wins. If it is missing or invalid, the rule uses a valid
project-wide value; if neither is valid, it uses `64`. The ceiling changes which
assignments are reported; it does not set your application's `MaxDepth`.

The default severity is `suggestion`. Severity values are `none`, `silent`,
`suggestion`, `warning`, and `error`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress a specific setting when trusted input requires deeper nesting and resource
use has been checked. If the same requirement applies across the project, set a
reviewed ceiling in `.editorconfig`.
