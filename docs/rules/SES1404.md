# SES1404 — A type must not be instantiated by name from non-constant data

| Item | Value |
| --- | --- |
| Package | SecuritySharp.Analyzers |
| Category | Serialization |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

The `typeName` argument of `Activator.CreateInstance(assemblyName, typeName, ...)`
or `Activator.CreateInstanceFrom(assemblyFile, typeName, ...)` is not a compile-time
constant.

This includes parameters, non-constant locals and fields, method results, and names
built from those values. Named and reordered arguments are covered. An attacker
who controls the name can choose a type whose constructor runs unwanted code.

## Example

Reported:

```csharp
using System;

public static class Factory
{
    public static void Create(string typeName) =>
        Activator.CreateInstance("MyAssembly", typeName);
}
```

Choose the expected type directly:

```csharp
using System;

public sealed class KnownHandler
{
}

public static class Factory
{
    public static KnownHandler Create() => Activator.CreateInstance<KnownHandler>();
}
```

## How to fix violations

There is no automatic code fix.

Use a known type or a constant type name. If input selects among several types, map
it to a fixed set of allowed types and reject unknown values before creating an
object. A non-constant name is still reported after validation, so that case can
require a local suppression.

## What is not reported

Literal and `const` type names are not reported. The generic and `System.Type`
overloads are outside this rule, as are same-named methods on other types. This
rule does not check whether the assembly name or file is trusted.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1404.severity = warning
```

The rule is enabled by default as a warning. There are no
rule-specific options. Severity values are `none`, `silent`, `suggestion`, `warning`,
and `error`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when dynamic type selection is required and the name is checked against
an enforced list of allowed types, or comes from configuration that untrusted users
cannot change. Verify the assembly source as well as the type name.
