# SES1406 — Reflection must not reach non-public members to bypass their declared accessibility

| Item | Value |
| --- | --- |
| Package | SecuritySharp.Analyzers |
| Category | Serialization |
| Severity | Warning |
| Code fix | No |
| Default | Disabled (opt-in) |

## Cause

A reflection lookup on `System.Type` receives constant `BindingFlags` containing
`NonPublic`. Reflection lets code find and use members by name at runtime; this
flag includes members that the type's public API does not expose.

The rule covers `GetMethod`, `GetField`, `GetProperty`, `GetMember`,
`GetConstructor`, `GetEvent`, their plural forms, and `InvokeMember`. Calls to
these inherited methods through `TypeInfo` are covered too.

Accessing private or internal members couples your code to details their author can
change. Such code can break at runtime after a library update.

## Example

Reported when the rule is enabled:

```csharp
using System;
using System.Reflection;

public static class Inspection
{
    public static MethodInfo Find(Type type) =>
        type.GetMethod("Hidden", BindingFlags.NonPublic | BindingFlags.Instance);
}
```

Use a public member that the type supports:

```csharp
using System;
using System.Reflection;

public static class Inspection
{
    public static MethodInfo Find(Type type) =>
        type.GetMethod("Visible", BindingFlags.Public | BindingFlags.Instance);
}
```

## How to fix violations

There is no automatic code fix.

Use a public API or interface. When reflection is necessary, look up supported
public members. Removing `NonPublic` alone does not make a hidden member public;
the lookup can return `null` or fail to invoke the member.

## What is not reported

Calls without a `BindingFlags` argument, flags without `NonPublic`, and calls on
unrelated types are not reported. Non-constant flags, including `static readonly`
fields, are not checked. A `const` field or local containing `NonPublic` is checked.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1406.severity = warning
```

The rule is disabled by default; this setting enables it as a warning. There are no
rule-specific options. Severity values are `none`, `silent`, `suggestion`, `warning`,
and `error`. See [configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled, or suppress a specific lookup, when a test, serializer,
or framework must access non-public members and there is no suitable public API.
Keep that reflection in one place and test it against supported library versions.
