# SES1502 — A CORS origin predicate must not unconditionally allow every origin

| Item | Value |
| --- | --- |
| Package | SecuritySharp.Analyzers |
| Category | WebHardening |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

`CorsPolicyBuilder.SetIsOriginAllowed` receives a callback that returns the literal
`true` for every return it contains. This allows every origin. An origin is the
scheme, host, and port of a site making a browser request.

With `AllowCredentials()`, accepting every origin can let an attacker-controlled
site read responses made with a user's credentials. Check the requested origin
against the sites your application trusts.

## Example

Reported:

```csharp
using Microsoft.AspNetCore.Cors.Infrastructure;

public static class CorsConfiguration
{
    public static void Configure(CorsPolicyBuilder builder) =>
        builder.SetIsOriginAllowed(origin => true);
}
```

Allow only a trusted origin:

```csharp
using Microsoft.AspNetCore.Cors.Infrastructure;

public static class CorsConfiguration
{
    public static void Configure(CorsPolicyBuilder builder) =>
        builder.SetIsOriginAllowed(origin => origin == "https://app.example.com");
}
```

## How to fix violations

There is no automatic code fix.

Compare the whole origin against an explicit list, or replace the callback with
`WithOrigins(...)`. A prefix check can also accept an attacker's domain whose name
starts with the trusted text.

## What is reported

The rule covers expression callbacks such as `origin => true`, blocks and
anonymous methods with at least one return and all returns equal to literal `true`,
and methods or local functions passed by name with those bodies.

Statements before a return, including logging or checks that throw, do not prevent
a report. Returns inside a nested callback or local function are ignored when
checking the outer callback.

## What is not reported

A callback that returns `false` on a path, returns a comparison, or returns a
computed value is not reported. Callbacks stored in variables and methods whose
source is unavailable are not checked. The absence of a report does not prove that
an origin check is secure.

The rule reports nothing when ASP.NET Core's `CorsPolicyBuilder` is unavailable.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1502.severity = warning
```

The rule is enabled by default as a warning. There are no
rule-specific options. Severity values are `none`, `silent`, `suggestion`, `warning`,
and `error`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress only for a deliberately public API that returns no sensitive data and does
not allow credentials, or when a check in the callback rejects unwanted origins by
throwing before it can return. Prefer returning `false` for rejected origins.
