# SES1503 — JWT signature verification must not be disabled on TokenValidationParameters

**Category:** WebHardening
**Severity:** Warning
**Code fix:** No code fix is available.

## Cause

The rule reports an assignment of the literal `false` to `RequireSignedTokens`
or `ValidateIssuerSigningKey` on
`Microsoft.IdentityModel.Tokens.TokenValidationParameters`. Direct assignments
and object initializers are checked.

`RequireSignedTokens` rejects unsigned JSON Web Tokens (JWTs).
`ValidateIssuerSigningKey` enables validation of the token's signing key.
Set both to `true` and configure the signing keys your application trusts.

Assignments to `ValidateIssuer`, `ValidateAudience`, and `ValidateLifetime`
are outside this rule. Values held in variables and properties on unrelated
types are not reported.

## Example

Bad:

```csharp
using Microsoft.IdentityModel.Tokens;

public static class TokenSetup
{
    public static void Configure(TokenValidationParameters parameters)
    {
        parameters.RequireSignedTokens = false;
        parameters.ValidateIssuerSigningKey = false;
    }
}
```

Corrected:

```csharp
using Microsoft.IdentityModel.Tokens;

public static class TokenSetup
{
    public static void Configure(TokenValidationParameters parameters)
    {
        parameters.RequireSignedTokens = true;
        parameters.ValidateIssuerSigningKey = true;
    }
}
```

These flags are part of token validation. Also configure trusted signing keys
and the required issuer, audience, and lifetime checks for your application.

## Configuration

Enabled by default. The package default and recommended profile use `warning`.
There are no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.SES1503.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress in an isolated test that deliberately accepts unsigned tokens or
exercises disabled key validation. For production code, suppress only when a
reviewed validation step provides the same protection before the token is trusted.
