# SES1504 — A cookie with SameSite=None must be marked Secure

**Category:** WebHardening
**Severity:** Warning
**Code fix:** No code fix is available.

## Cause

A `CookieOptions` or `CookieBuilder` object initializer sets
`SameSite = SameSiteMode.None` without a secure setting in that same initializer.
`SameSite=None` allows the browser to send the cookie with requests from other
sites. Browsers require the `Secure` attribute, which limits the cookie to HTTPS.

The rule reports these ASP.NET Core types:

- `CookieOptions`: `Secure` is missing or is a constant `false`.
- `CookieBuilder`: `SecurePolicy` is missing or is `CookieSecurePolicy.None`.

Setting `Secure` on a later statement does not prevent the report. Put it next
to `SameSite` in the initializer.

## Example

Bad:

```csharp
using Microsoft.AspNetCore.Http;

var options = new CookieOptions { SameSite = SameSiteMode.None };
var builder = new CookieBuilder { SameSite = SameSiteMode.None };
```

Corrected:

```csharp
using Microsoft.AspNetCore.Http;

var options = new CookieOptions
{
    SameSite = SameSiteMode.None,
    Secure = true
};
var builder = new CookieBuilder
{
    SameSite = SameSiteMode.None,
    SecurePolicy = CookieSecurePolicy.Always
};
```

Use `SameSiteMode.Lax` or `Strict` if the cookie does not need to accompany
cross-site requests.

## What is not reported

The rule accepts a runtime value for `Secure` and a `SecurePolicy` value other
than `None`. This includes `SameAsRequest`, which sets `Secure` only for an
HTTPS request. Use `Always` when the cookie must always carry `Secure`.
Other cookie types and `SameSite` values are not checked.

## Configuration

Enabled by default. The package default and recommended profile use `warning`.
There are no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.SES1504.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when another configuration step always sets the secure attribute before
the cookie is sent and moving that setting into the initializer is impractical.
Do not suppress to make an insecure cross-site cookie work over HTTP; browsers
can reject that cookie.
