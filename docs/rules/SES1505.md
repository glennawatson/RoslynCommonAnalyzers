# SES1505 — The request body size limit must not be removed

**Category:** WebHardening
**Severity:** Warning
**Code fix:** No code fix is available.

## Cause

The rule reports `[DisableRequestSizeLimit]` on a controller or action. It also
reports assigning the literal `null` to `MaxRequestBodySize` on
`KestrelServerLimits` or `IHttpMaxRequestBodySizeFeature`, including in an
object initializer.

Removing the size limit allows very large requests to consume server memory
or disk space. Keep a finite limit sized for the uploads your application accepts.

## Example

Bad:

```csharp
using Microsoft.AspNetCore.Server.Kestrel.Core;

var limits = new KestrelServerLimits { MaxRequestBodySize = null };
```

Corrected:

```csharp
using Microsoft.AspNetCore.Server.Kestrel.Core;

var limits = new KestrelServerLimits { MaxRequestBodySize = 10_485_760 };
```

The example allows 10 MiB. Choose a limit that fits your application. For an
action marked `[DisableRequestSizeLimit]`, remove the attribute to use the
configured limit, or replace it with `[RequestSizeLimit(10_485_760)]` using
an appropriate byte count.

Finite limits and same-named members on unrelated types are not reported.

## Configuration

Enabled by default. The package default and recommended profile use `warning`.
There are no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.SES1505.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when a trusted gateway enforces a finite body limit and clients cannot
bypass it, or when a streaming endpoint enforces an equivalent byte limit itself.
Document where that limit is enforced. Large uploads alone are a reason to raise
the limit, not remove it.
