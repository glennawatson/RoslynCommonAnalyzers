# SES1506 — The developer exception page must be guarded by a development-environment check

**Category:** WebHardening
**Severity:** Info (suggestion)
**Code fix:** No code fix is available.

## Cause

An ASP.NET Core `UseDeveloperExceptionPage` call has no surrounding `if` or `?:`
whose condition calls `IsDevelopment`. The rule covers both extension and static
calls, including the overload that takes `DeveloperExceptionPageOptions`.

The developer exception page sends exception messages, stack traces, and request
details to the client. Those details can expose secrets and application internals.
Enable it only in development.

## Example

Bad:

```csharp
using Microsoft.AspNetCore.Builder;

public static class ErrorSetup
{
    public static void Configure(IApplicationBuilder app)
    {
        app.UseDeveloperExceptionPage();
    }
}
```

Corrected:

```csharp
using Microsoft.AspNetCore.Builder;
using Microsoft.Extensions.Hosting;

public static class ErrorSetup
{
    public static void Configure(IApplicationBuilder app, IHostEnvironment env)
    {
        if (env.IsDevelopment())
        {
            app.UseDeveloperExceptionPage();
        }
    }
}
```

Configure a production error handler that returns a generic response without
exception details.

## What is not reported

An enclosing `if` or `?:` condition containing a call named `IsDevelopment`
prevents the report. The rule does not check which branch runs in development,
so keep the developer page in the development branch.

A check stored in a variable or performed in a separate helper is not recognized.
Methods named `UseDeveloperExceptionPage` on unrelated types are not reported.

## Configuration

Enabled by default. The package default and recommended profile use `suggestion`.
There are no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.SES1506.severity = suggestion
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress for a development-only host or a helper whose callers enforce the
environment check. Confirm that production requests cannot reach the developer
page. A guard directly around the call is easier to maintain.
