# SES1507 — AllowAnonymous and Authorize on the same declaration conflict

**Category:** WebHardening
**Severity:** Warning
**Code fix:** No code fix is available.

## Cause

The same method or type declaration has both ASP.NET Core `[AllowAnonymous]`
and `[Authorize]` attributes. Anonymous access takes precedence, so the
authorization attribute does not protect the endpoint. The rule highlights
`[Authorize]`, including an attribute derived from `AuthorizeAttribute`.

The attributes can be in one list or separate lists, and can use their full
names. Both must appear on the same declaration.

## Example

Bad:

```csharp
using Microsoft.AspNetCore.Authorization;

[Authorize]
[AllowAnonymous]
public class ReportsController
{
}
```

Corrected for an endpoint that requires authorization:

```csharp
using Microsoft.AspNetCore.Authorization;

[Authorize]
public class ReportsController
{
}
```

If anonymous access is intended, remove `[Authorize]` instead.

## What is not reported

An `[Authorize]` controller with an `[AllowAnonymous]` action is not reported.
That pattern exposes one public action on a protected controller. The rule does
not combine attributes from base types or separate partial declarations, or
check policies configured elsewhere.

## Configuration

Enabled by default. The package default and recommended profile use `warning`.
There are no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.SES1507.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when testing this conflict deliberately, or when custom framework code
needs both attributes and you have verified the resulting access policy.
Ordinary ASP.NET Core endpoints should keep only the attribute that matches
their intended access.
