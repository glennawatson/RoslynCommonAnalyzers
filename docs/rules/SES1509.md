# SES1509 — Backtracking-prone regular expression has no match timeout

**Category:** WebHardening
**Severity:** Warning
**Code fix:** No code fix is available.

## Cause

A constant regular expression repeats a group without an upper limit, and the
group contains another unlimited repetition or alternatives separated by `|`.
Examples include `(a+)+`, `(.*)*`, and `(a|aa)+`.

The regex engine can try many ways to match the same input. This is called
backtracking. Some patterns take so long on crafted input that they can make a
server unresponsive.

The rule reports the pattern in `new Regex(...)`, static `Regex.IsMatch`,
`Match`, `Matches`, `Replace`, `Split`, and `Count` calls, and
`[GeneratedRegex(...)]`. It reports only when no timeout is supplied and the
options are absent or constant without `RegexOptions.NonBacktracking`.

## Example

Bad:

```csharp
using System.Text.RegularExpressions;

var expression = new Regex("(a+)+");
```

Corrected:

```csharp
using System;
using System.Text.RegularExpressions;

var expression = new Regex(
    "(a+)+", RegexOptions.None, TimeSpan.FromSeconds(1));
```

Choose a finite timeout that fits the operation. A match that exceeds it throws
`RegexMatchTimeoutException`; handle that as a failed or interrupted operation.
For `[GeneratedRegex]`, supply `matchTimeoutMilliseconds`, for example `1000`.
The rule checks for a timeout argument, not whether its value is finite.

You can also simplify the pattern, such as replacing `(a+)+` with `a+`, or use
`RegexOptions.NonBacktracking` on .NET 7 or later. That option does not support
some features, including backreferences and lookaround, so check the pattern
before switching engines.

## What is not reported

Nonconstant patterns or options are not checked. Bounded repetitions such as
`(a+){2,3}`, and repeated groups without inner unlimited repetition or
alternatives, such as `(abc)+` and `(\d{4})+`, are not reported. The rule
recognizes risky pattern shapes; it does not prove how long a match takes.

## Configuration

Enabled by default. The package default and recommended profile use `warning`.
There are no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.SES1509.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when a finite application-wide regex timeout is enforced, or when
enforced input limits and measurements establish an acceptable worst-case cost.
A fixed pattern alone is not sufficient: the input can still trigger slow matching.
