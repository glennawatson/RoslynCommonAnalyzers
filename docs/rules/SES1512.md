# SES1512 — Sensitive framework diagnostics must not be enabled outside development

**Category:** WebHardening
**Severity:** Warning
**Code fix:** No code fix is available.

## Cause

Sensitive logging is enabled without an enclosing `if` or `?:` condition that
calls `IsDevelopment`. The rule checks:

- `DbContextOptionsBuilder.EnableSensitiveDataLogging()` and the generic
  `DbContextOptionsBuilder<TContext>` version, called without an argument or
  with a constant `true`. These can include data values in Entity Framework
  Core logs and errors.
- Assigning the literal `true` to `IdentityModelEventSource.ShowPII` or
  `IdentityModelEventSource.LogCompleteSecurityArtifact`. These enable logging
  of personal information or complete security tokens.

Keep these switches off in production, where logs can expose user data or tokens
to anyone with log access.

## Example

Bad:

```csharp
using Microsoft.EntityFrameworkCore;
using Microsoft.IdentityModel.Logging;

public static class LoggingSetup
{
    public static void Configure(DbContextOptionsBuilder options)
    {
        options.EnableSensitiveDataLogging();
        IdentityModelEventSource.ShowPII = true;
    }
}
```

Corrected:

```csharp
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Hosting;
using Microsoft.IdentityModel.Logging;

public static class LoggingSetup
{
    public static void Configure(DbContextOptionsBuilder options, IHostEnvironment env)
    {
        if (env.IsDevelopment())
        {
            options.EnableSensitiveDataLogging();
            IdentityModelEventSource.ShowPII = true;
        }
    }
}
```

## What is not reported

`EnableSensitiveDataLogging(false)` and runtime arguments such as
`EnableSensitiveDataLogging(env.IsDevelopment())` are not reported. Identity
assignments with a value other than the literal `true` are not checked.

An enclosing condition containing a call named `IsDevelopment` prevents a
report. The rule does not check which branch runs in development. Keep the
enabling code in that branch. An environment check stored in a variable or
performed by a separate helper is not recognized.

## Configuration

Enabled by default. The package default and recommended profile use `warning`.
There are no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.SES1512.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when the code runs only in an isolated development or test host, or
when a caller enforces a development check that the rule cannot see. Ensure
sensitive diagnostics cannot be enabled on production data through that path.
