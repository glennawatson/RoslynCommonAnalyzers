# SES1513 — An authorization result must be checked, not discarded

**Category:** WebHardening
**Severity:** Warning
**Code fix:** No code fix is available.

## Cause

An `IAuthorizationService.AuthorizeAsync` call discards its result. A denied
authorization check returns an `AuthorizationResult` with `Succeeded = false`;
it does not throw because access was denied. Ignoring that result lets execution
continue without enforcing the decision.

The rule reports a call used as a standalone statement or assigned to a discard
(`_ = ...`), with or without `await` or `.ConfigureAwait(...)`. It covers the
interface methods and extension methods whose first parameter is
`IAuthorizationService`.

## Example

Bad:

```csharp
using System.Security.Claims;
using System.Threading.Tasks;
using Microsoft.AspNetCore.Authorization;

public static class AccessCheck
{
    public static async Task EnsureCanDeleteAsync(
        IAuthorizationService service, ClaimsPrincipal user, object resource)
    {
        await service.AuthorizeAsync(user, resource, "CanDelete");
    }
}
```

Corrected:

```csharp
using System;
using System.Security.Claims;
using System.Threading.Tasks;
using Microsoft.AspNetCore.Authorization;

public static class AccessCheck
{
    public static async Task EnsureCanDeleteAsync(
        IAuthorizationService service, ClaimsPrincipal user, object resource)
    {
        var result = await service.AuthorizeAsync(user, resource, "CanDelete");
        if (!result.Succeeded)
        {
            throw new UnauthorizedAccessException();
        }
    }
}
```

Run the protected operation only after this check completes successfully.
In a controller, return `Forbid()` for an authenticated user without permission,
or `Challenge()` when authentication is required.

## What is not reported

A result stored in a variable, returned, passed to another method, or read
through `Succeeded` is not reported. A declared variable named `_` counts as
storage, not a discard. The rule does not check whether a stored result is
used later, so storing it alone does not enforce authorization.

## Configuration

Enabled by default. The package default and recommended profile use `warning`.
There are no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.SES1513.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress for a deliberate test or an informational authorization probe that does
not control access. Verify that the protected operation has a separate enforced
authorization check. Never suppress because awaiting the call appears sufficient.
