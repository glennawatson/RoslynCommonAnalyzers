# SES1514 — OpenID Connect PKCE, state, and nonce protections must not be disabled

**Category:** WebHardening
**Severity:** Warning
**Code fix:** No code fix is available.

## Cause

The rule reports an assignment of the literal `false` to any of these properties,
directly or in an object initializer:

- `UsePkce` on `Microsoft.AspNetCore.Authentication.OpenIdConnect.OpenIdConnectOptions`.
  PKCE ties an authorization code to the client that started the sign-in.
- `RequireState` or `RequireStateValidation` on
  `Microsoft.IdentityModel.Protocols.OpenIdConnect.OpenIdConnectProtocolValidator`.
  State connects the sign-in response to the request that started it.
- `RequireNonce` on the same validator. A nonce is a value unique to a sign-in;
  checking it helps reject a token replayed from another sign-in.

Turning off these checks can weaken the sign-in process. Restore the required
protections and check that your identity provider supports the configuration.

## Example

Bad:

```csharp
using Microsoft.AspNetCore.Authentication.OpenIdConnect;

public static class SignInSetup
{
    public static void Configure(OpenIdConnectOptions options)
    {
        options.UsePkce = false;
        options.ProtocolValidator.RequireNonce = false;
    }
}
```

Corrected:

```csharp
using Microsoft.AspNetCore.Authentication.OpenIdConnect;

public static class SignInSetup
{
    public static void Configure(OpenIdConnectOptions options)
    {
        options.UsePkce = true;
        options.ProtocolValidator.RequireNonce = true;
    }
}
```

## What is not reported

Values held in variables, same-named properties on unrelated types, and token
validation settings such as issuer, audience, lifetime, and signature checks
are outside this rule.

The project must reference `OpenIdConnectOptions` for the rule to apply, even
for assignments made directly to `OpenIdConnectProtocolValidator`.

## Configuration

Enabled by default. The package default and recommended profile use `warning`.
There are no rule-specific options.

```editorconfig
[*.cs]
dotnet_diagnostic.SES1514.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress for an isolated protocol test, or a reviewed integration that enforces
the same protection elsewhere. A provider compatibility problem alone is not
enough: document how the sign-in remains protected from forged or replayed responses.
