# SES1515 — A Content-Security-Policy value disables its own protection

## Cause

A string literal contains `'unsafe-inline'`, `'unsafe-eval'`, or a standalone `*`
alongside one of these policy directives: `default-src`, `script-src`, `style-src`,
`object-src`, or `base-uri`.

The rule reports the literal if it starts with one of those directives, wherever
it appears. It also reports a literal used as the value in a two-argument call
such as `headers.Add("Content-Security-Policy", value)`, or assigned through
`headers["Content-Security-Policy"]`. The header name ignores letter case.

These sources weaken the browser's restrictions: they allow inline code, code
evaluation from strings, or resources from any host.

## How to fix violations

Remove the unsafe sources and list the origins the page needs.

```csharp
using System.Collections.Generic;

public static class ResponsePolicy
{
    // Before: permits inline scripts.
    public static void Before(IDictionary<string, string> headers) =>
        headers["Content-Security-Policy"] = "script-src 'self' 'unsafe-inline'";

    // After: permits scripts from this origin.
    public static void After(IDictionary<string, string> headers) =>
        headers["Content-Security-Policy"] = "script-src 'self'";
}
```

If the page needs inline scripts, allow each one with a content hash or a nonce,
an unpredictable value generated for each response. Update both the policy and
the script tags that use the nonce.

There is no automatic code fix.

## What is not reported

Host patterns such as `*.example.com` and `https://*` are not standalone `*`
sources. A string that only mentions a directive in the middle of ordinary text
is not reported unless it sets the header. A literal starting with a listed
directive is still checked in a report-only header or a test fixture.

The rule checks individual string literals. It does not evaluate a complete
interpolated or concatenated policy, though a literal within a concatenation can
itself trigger the rule.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1515.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.

## When to suppress

Suppress a specific literal used to test or document an unsafe policy. For a
deployed policy, suppress only after reviewing why the permissive source is
required and which browser restrictions remain effective.
