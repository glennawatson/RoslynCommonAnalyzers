# SES1601 — System prompts must use constant, trusted text

## Cause

A system message receives text whose value is not known at compile time. The
rule checks these string-content calls:

- `Microsoft.Extensions.AI.ChatMessage` constructed with `ChatRole.System`.
- Semantic Kernel's `ChatHistory.AddSystemMessage` and
  `ChatHistory.AddMessage(AuthorRole.System, ...)`.
- Semantic Kernel's `ChatMessageContent` constructed with `AuthorRole.System`.

Parameters, properties, non-constant fields and local variables are reported,
even when a local was assigned a string literal. Runtime string interpolation
is also reported. String literals, `const` values, and other expressions the
compiler can evaluate as constants are accepted.

System messages carry the application's instructions. Mixing user input into
them lets that input alter the instructions. Keeping the channels separate
reduces this risk; it does not guarantee that hostile input will be ignored.

## How to fix violations

Keep the system message fixed and put changing input in a user message.

```csharp
using Microsoft.SemanticKernel.ChatCompletion;

public static class Conversation
{
    // Before: user input becomes system instructions.
    public static void Before(ChatHistory history, string input) =>
        history.AddSystemMessage(input);

    // After: instructions and input have separate roles.
    public static void After(ChatHistory history, string input)
    {
        history.AddSystemMessage("Summarize the supplied text.");
        history.AddMessage(AuthorRole.User, input);
    }
}
```

If a fixed template is stored in a field or local, declare it `const`.

There is no automatic code fix.

## What is not reported

Other message roles and non-string content overloads are outside the rule.
For calls with a role argument, the role must be written as the library's
`System` property; a role passed through a variable is not checked. Methods on
unrelated types are ignored. Projects without either supported library receive
no diagnostic.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1601.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.

## When to suppress

Suppress a specific call when its template must be loaded at runtime from a
source controlled by the application owner. Confirm that requests, user-edited
records, documents, and tool results cannot change that template.
