# SES1602 — Keep generated response text out of commands and file paths

## Cause

The `Text` property of `Microsoft.Extensions.AI.ChatResponse` or `ChatMessage`
is passed directly to an operation that runs a command or selects a file. The
rule also checks a local initialized from that property in the statement
immediately before the operation, in the same block.

It reports these uses:

- The `fileName` or `arguments` argument of `Process.Start`.
- Assignments to `ProcessStartInfo.FileName` or `Arguments`, including object initializers.
- The first path argument of `System.IO.File` read, write, append, open, create,
  delete, copy, move, and replace methods, including their async versions where available.
- The `sql` argument of Entity Framework Core's `FromSqlRaw`, `ExecuteSqlRaw`,
  or `ExecuteSqlRawAsync`.

Generated responses can contain instructions or paths chosen through hostile
input. Using that text as a command can run unwanted programs, access unintended
files, or change database queries.

## How to fix violations

Let the application choose the operation and destination. Treat the response as
data. This example stores the response in a fixed file:

```csharp
using System.IO;
using Microsoft.Extensions.AI;

public static class ResponseStorage
{
    // Before: the response chooses which file to overwrite.
    public static void Before(ChatResponse response) =>
        File.WriteAllText(response.Text, "Result");

    // After: the application chooses the file; the response is its content.
    public static void After(ChatResponse response) =>
        File.WriteAllText("result.txt", response.Text);
}
```

For processes, select a fixed executable and validate each permitted argument.
Use `ProcessStartInfo.ArgumentList` to pass arguments separately; it does not
make an unsafe argument safe. For SQL, use a fixed query with parameters for
response values.

There is no automatic code fix.

## What is not reported

Logging, displaying, returning, or writing the text as file content does not
trigger this rule. Other `Text` properties and operations on unrelated types
are ignored. The rule does not follow text through helper methods, multiple
locals, or intervening statements. Those limits do not make a command safe.

## Configuration

Enabled by default as a warning. There are no validator lists or other
rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1602.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.

## When to suppress

Suppress only when validation outside the recognized pattern restricts the
value to a reviewed set of commands, arguments, or paths. Document that check
at the call. A request for safe output in the prompt is not validation.
