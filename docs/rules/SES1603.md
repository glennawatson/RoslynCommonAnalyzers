# SES1603 — A tool declared read-only must not change state

## Cause

A method marked with `ModelContextProtocol.Server.McpServerToolAttribute`
explicitly sets `ReadOnly = true` or `Destructive = false`, but contains a call
that can change state. Attributes derived from `McpServerToolAttribute` also
count. Either safety claim is enough to trigger the rule.

The checked calls are `File.Delete`, `File.WriteAllText`, `Directory.Delete`,
`Process.Start`, `DbCommand.ExecuteNonQuery`, `DbContext.SaveChanges`, and Entity
Framework Core's `ExecuteSqlRaw`, `ExecuteSqlInterpolated`, `ExecuteDelete`, and
`ExecuteUpdate`. Their async versions are checked where available.

A host can use these hints to decide whether to run a tool without confirmation.
Incorrect hints can therefore allow an unexpected write or deletion.

## How to fix violations

If the operation is meant to change state, describe it accurately:

```csharp
using System.IO;
using ModelContextProtocol.Server;

public class FileTools
{
    // Before: claims to only read, but deletes a file.
    [McpServerTool(ReadOnly = true)]
    public void Before(string path) => File.Delete(path);

    // After: declares the intended effect.
    [McpServerTool(ReadOnly = false, Destructive = true)]
    public void After(string path) => File.Delete(path);
}
```

If the tool must only read, remove the changing operation or replace it with a
read operation. Moving a write into a helper does not make the tool read-only.
Correct hints inform the host; the host's own policy determines whether it asks
for confirmation.

There is no automatic code fix.

## What is not reported

Tools with neither safety claim are ignored, as are ordinary methods and
methods marked only with Semantic Kernel's `KernelFunction`. The rule checks
calls written inside the tool method; it does not inspect called helpers.
It reports the first matching call in each method, so review the entire body.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1603.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.

## When to suppress

Suppress a specific call only when you have verified that it cannot change the
state the tool promises to leave untouched. For example, a fixed program launched
by the tool might only read data. Document why the safety claim remains true.
