# SES1604 — Prompt-template input encoding must not be disabled

## Cause

`AllowDangerouslySetContent` is assigned the literal `true` on one of these
Semantic Kernel types:

- `Microsoft.SemanticKernel.PromptTemplateConfig`.
- `Microsoft.SemanticKernel.InputVariable`.
- `Microsoft.SemanticKernel.KernelPromptTemplateFactory`.
- `Microsoft.SemanticKernel.PromptTemplates.Handlebars.HandlebarsPromptTemplateFactory`.

Direct assignments and object initializers are checked. Disabling encoding lets
substituted text change surrounding message markup, such as closing a
`<message>` tag and adding a system message.

## How to fix violations

Keep the property at its default, `false`, so substituted content stays encoded.

```csharp
using Microsoft.SemanticKernel;

public static class TemplateSettings
{
    // Before: inserts substituted content without encoding.
    public static void Before(PromptTemplateConfig config) =>
        config.AllowDangerouslySetContent = true;

    // After: keeps substituted content encoded.
    public static void After(PromptTemplateConfig config) =>
        config.AllowDangerouslySetContent = false;
}
```

There is no automatic code fix.

## What is not reported

The rule checks only the literal `true`. It does not report a constant name,
property, or runtime expression assigned to the flag. Such values can still
disable encoding. A property with the same name on an unrelated type is ignored.
The rule requires Semantic Kernel's `PromptTemplateConfig` to be available in
the project.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1604.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.

## When to suppress

Suppress only for content that must contain message markup and is fully
controlled by the application owner. Prefer trusting a single `InputVariable`
over disabling encoding for a whole template or factory. That narrower opt-out
still triggers the rule and needs the same review.

For guidance on trusted template content, see
[Protecting against prompt injection attacks in chat prompts](https://learn.microsoft.com/semantic-kernel/concepts/prompts/prompt-injection-attacks).
