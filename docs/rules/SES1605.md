# SES1605 — Keep sensitive content out of telemetry

## Cause

`EnableSensitiveData` is assigned a compile-time value of `true` on a supported
`Microsoft.Extensions.AI` OpenTelemetry type. The types are
`OpenTelemetryChatClient`, `OpenTelemetryEmbeddingGenerator<TInput, TEmbedding>`,
`OpenTelemetryRealtimeClient`, `OpenTelemetrySpeechToTextClient`,
`OpenTelemetryTextToSpeechClient`, `OpenTelemetryImageGenerator`, and
`OpenTelemetryHostedFileClient`.

The rule checks direct assignments, object initializers, and configuration
callbacks. A `const bool` set to `true` also triggers it.

This switch allows raw inputs and outputs in telemetry. Prompts, responses, and
tool arguments can contain passwords, tokens, or personal data. Exporting them
copies that content into another store with its own access and retention rules.

## How to fix violations

Leave sensitive-data capture at its default, `false`, or turn it off explicitly.

```csharp
using Microsoft.Extensions.AI;

public static class TelemetrySettings
{
    // Before: allows raw content in telemetry.
    public static void Before(OpenTelemetryChatClient client) =>
        client.EnableSensitiveData = true;

    // After: keeps raw content out of this instrumentation.
    public static void After(OpenTelemetryChatClient client) =>
        client.EnableSensitiveData = false;
}
```

There is no automatic code fix.

## What is not reported

Assignments of `false` and values computed at runtime are ignored, as are
properties on unrelated types. A runtime configuration flag can still enable
sensitive capture in production; absence of a diagnostic does not check the
deployed value.

## Configuration

Enabled by default at Info severity, written as `suggestion` in `.editorconfig`.
There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1605.severity = suggestion
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.

## When to suppress

Suppress for an isolated debugging session using synthetic or reviewed data,
with controlled access to the telemetry. Keep that setting out of production
and remove captured content when the investigation ends.
