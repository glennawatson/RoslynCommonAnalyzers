# SES1704 — HttpContext accessed from an interactive component is stale

## Cause

A Blazor component declares a render-mode attribute and captures request state
through either of these patterns:

- An `[Inject]` property or field, or an ordinary constructor parameter, typed
  `IHttpContextAccessor`.
- A `[CascadingParameter]` property or field typed `HttpContext`.

During interactive rendering, `HttpContext` can be absent or refer to an earlier
request. Its user, cookies, and headers are not a reliable source of current
authorization state.

## How to fix violations

Use `AuthenticationStateProvider` for the authenticated user. Pass other needed
request values explicitly instead of retaining the entire `HttpContext`.
This C# example uses a custom attribute to select interactive server rendering:

```csharp
using Microsoft.AspNetCore.Components;
using Microsoft.AspNetCore.Components.Authorization;
using Microsoft.AspNetCore.Components.Web;
using Microsoft.AspNetCore.Http;

// Before: retains access to HTTP request state.
[ServerMode]
public class BeforeDashboard : ComponentBase
{
    [Inject]
    public IHttpContextAccessor Accessor { get; set; } = default!;
}

// After: gets authentication state through the Blazor service.
[ServerMode]
public class Dashboard : ComponentBase
{
    [Inject]
    public AuthenticationStateProvider AuthState { get; set; } = default!;
}

public sealed class ServerModeAttribute : RenderModeAttribute
{
    public override IComponentRenderMode Mode => new InteractiveServerRenderMode();
}
```

Obtain the user from `GetAuthenticationStateAsync()` and respond to
authentication-state changes when the component depends on them.

There is no automatic code fix.

## What is not reported

The render-mode attribute and the capturing member must appear on the same
class declaration. A mode applied only where the component is used, or inherited
from a parent, is not checked. Primary-constructor parameters are also outside
this check. A component with no diagnostic can still render interactively.

Other dependency types and classes not derived from `ComponentBase` are ignored.
This rule requires the Blazor render-mode APIs available in .NET 8 and later.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SES1704.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.

## When to suppress

Suppress only when the captured context is used exclusively during a live
request, such as a guarded prerendering path. Verify that interactive rendering
cannot read it, especially for permission checks.
