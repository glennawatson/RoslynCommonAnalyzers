# SES1705 — Navigate only to a verified destination

## Cause

`NavigationManager.NavigateTo` receives a destination that is neither a constant
relative URL nor the direct result of a configured validator. The rule applies
inside any class, including classes that are not components.

It reports runtime values, constant URLs with a scheme such as `https:`, and
values starting with two slashes or backslashes in any combination. A relative
constant such as `/home`, `counter`, or `#section` is accepted. Even an
interpolated local path is reported when its value is not constant.

An unchecked return URL can send a user to another website. This is an open
redirect: a link through your application leads to a destination an attacker
controls.

## How to fix violations

Use a fixed relative destination where possible. If the destination must vary,
validate it and pass the validator call directly to `NavigateTo`. The corrected
call below uses the configuration shown later and limits navigation to fixed
local paths:

```csharp
using Microsoft.AspNetCore.Components;

public static class ReturnNavigation
{
    // Before: accepts any destination.
    public static void Before(NavigationManager navigation, string returnUrl) =>
        navigation.NavigateTo(returnUrl);

    // After: selects a permitted local destination.
    public static void After(NavigationManager navigation, string returnUrl) =>
        navigation.NavigateTo(EnsureLocal(returnUrl));

    private static string EnsureLocal(string url) => url switch
    {
        "/home" => "/home",
        "/account" => "/account",
        _ => "/"
    };
}
```

A validator result stored in a local and passed later is still reported. So is
a value checked by an earlier `if`. The rule recognizes the direct validator
call, not separate validation steps.

There is no automatic code fix.

## Configuration

Enabled by default as a warning.

```ini
[*.cs]
dotnet_diagnostic.SES1705.severity = warning
securitysharp.SES1705.validators = EnsureLocal
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`.

`securitysharp.SES1705.validators` accepts comma-separated method names and
defaults to an empty list. If it is absent, `securitysharp.validators` supplies
the project-wide list, also empty by default. A rule-specific list, including
an empty one, overrides the project-wide list.

Names are case-sensitive and match only the method name. Both `EnsureLocal(url)`
and `helper.EnsureLocal(url)` match. The rule trusts the listed name without
checking the method's body; list only validators that reject unwanted destinations.

## When to suppress

Suppress a specific call when an external destination is intentional and
restricted to reviewed sites, or when validation elsewhere establishes that
the destination is safe. Document that restriction. A validator can also allow
selected external destinations if the application requires them.
