# SES1706 — A Blazor uploaded-file read must have a bounded, server-chosen size limit

| Item | Value |
| --- | --- |
| Package | SecuritySharp.Analyzers |
| Category | Blazor |
| Default severity | Warning, enabled |
| Code fix | No |

## Cause

A call to `IBrowserFile.OpenReadStream` passes one of these values for `maxAllowedSize`:

- `long.MaxValue`.
- The browser's reported file size, `IBrowserFile.Size`.
- An `int` or `long` constant greater than the configured ceiling, which defaults to `10485760` bytes (10 MiB).

This also applies to classes that implement `IBrowserFile`. The browser supplies the file size, so it cannot be trusted to set the server's limit. An oversized upload can fill the server's memory or disk.

## How to fix violations

Choose a limit that covers the largest upload your application accepts. Stream large files to storage instead of holding the whole file in memory.

Bad:

```csharp
using System.IO;
using Microsoft.AspNetCore.Components.Forms;

public class Upload
{
    public Stream Open(IBrowserFile file) => file.OpenReadStream(file.Size);
}
```

Corrected:

```csharp
using System.IO;
using Microsoft.AspNetCore.Components.Forms;

public class Upload
{
    public Stream Open(IBrowserFile file) => file.OpenReadStream(10 * 1024 * 1024);
}
```

There is no code fix; you must choose the upload limit.

## What is not reported

- Omitting `maxAllowedSize`, including when only `cancellationToken:` is supplied, keeps the framework's `512000`-byte default.
- A constant at or below the ceiling is not reported.
- Other values calculated at runtime are not reported. You must still check that they impose a safe limit.
- A `Size` property on an unrelated type is not reported.

The rule reports nothing when the project does not reference Blazor's `IBrowserFile` type.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1706.severity = warning
securitysharp.SES1706.max_bytes = 10485760
```

`securitysharp.SES1706.max_bytes` accepts whole numbers from `1` through `9223372036854775807`. If it is absent or invalid, the rule tries `securitysharp.max_bytes`, which accepts the same values. If neither is valid, the ceiling is `10485760` bytes. A constant equal to the ceiling is allowed. `long.MaxValue` and `IBrowserFile.Size` are reported regardless of the ceiling.

Severity accepts `default`, `none`, `silent`, `suggestion`, `warning`, or `error`. The default is `warning`.

## When to suppress

Raise the ceiling for a reviewed upload limit that exceeds 10 MiB. Suppress an individual read only when another enforced limit protects memory and storage. The browser's reported size alone is not such a limit.
