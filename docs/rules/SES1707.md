# SES1707 — Do not hard-code secrets in code that runs in the browser as WebAssembly

**Category:** Blazor  
**Default severity:** Warning, enabled  
**Code fix:** None

## Cause

A string literal looks like a credential and appears in code the rule identifies as running in the browser. Browser code can be downloaded and read, including its private fields and constants.

The rule checks all types in a project that references `WebAssemblyHostBuilder`. In other projects with WebAssembly support, it checks types with a render-mode attribute defined in source that selects Interactive WebAssembly or Interactive Auto. A server render mode or an unmarked type is not reported in those other projects.

Recognized values include `sk-` API keys, AWS access key IDs, GitHub and Slack tokens, Google API keys, private-key blocks, Azure keys in connection strings, and connection-string passwords. Ordinary strings and placeholders such as `<your-key>` are not reported. An unreported value can still be a secret.

## How to fix violations

Keep credentials on the server. Let the browser call an authenticated server endpoint that performs the operation without returning the credential. Revoke or rotate a real credential that has been shipped to a browser.

Bad, in a Blazor WebAssembly client project (the value is synthetic):

```csharp
public class ReportClient
{
    public string GetApiKey() => "AKIA2E4RJKL7MNPQ6XYZ";
}
```

Corrected, with the credential held by the server behind `api/report`:

```csharp
using System.Net.Http;
using System.Threading.Tasks;

public class ReportClient
{
    public Task<string> GetReportAsync(HttpClient http) =>
        http.GetStringAsync("api/report");
}
```

There is no code fix; moving the operation to the server requires application changes.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1707.severity = warning
securitysharp.allow_documentation_examples = false
securitysharp.allowed_example_secrets =
```

The two secret-scanning settings are shared with [the general hard-coded-secret rule](SES1201.md):

| Key | Values and default |
| --- | --- |
| `securitysharp.allow_documentation_examples` | `true` or `false`; default `false`. `true` skips literals containing `EXAMPLE`, ignoring letter case. |
| `securitysharp.allowed_example_secrets` | Comma-separated literal values; empty by default. Matches are exact and case-sensitive. Spaces around entries and empty entries are ignored. |

The corresponding `securitysharp.SES1201.allow_documentation_examples` and `securitysharp.SES1201.allowed_example_secrets` keys take precedence when present, even for this rule. An invalid boolean value means `false`. There are no equivalents under the WebAssembly rule's ID.

Severity accepts `default`, `none`, `silent`, `suggestion`, `warning`, or `error`. The default is `warning`.

## When to suppress

Suppress a verified dummy credential or a public value that happens to match a credential format. For test data, prefer an exact entry in `allowed_example_secrets` over allowing every value containing `EXAMPLE`. Do not suppress a real credential because the field is private or the code is hard to read after publishing.
