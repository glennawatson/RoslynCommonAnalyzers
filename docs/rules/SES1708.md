# SES1708 — Circuit detailed errors must not be enabled outside development

**Category:** Blazor  
**Default severity:** Warning, enabled  
**Code fix:** None

## Cause

`Microsoft.AspNetCore.Components.Server.CircuitOptions.DetailedErrors` is assigned the literal `true`, either directly or in an object initializer. Detailed errors send exception messages and stack traces to the browser. These can contain file paths, connection strings, or other private information.

The rule does not report `false`, a variable, a named constant, or an expression such as `environment.IsDevelopment()`. It also ignores same-named properties on other types. An assignment of `true` inside an environment check is still reported.

## How to fix violations

Leave detailed errors disabled, or assign the result of a development-environment check.

Bad:

```csharp
using Microsoft.AspNetCore.Components.Server;

public class CircuitSetup
{
    public void Configure(CircuitOptions options)
    {
        options.DetailedErrors = true;
    }
}
```

Corrected:

```csharp
using Microsoft.AspNetCore.Components.Server;

public class CircuitSetup
{
    public void Configure(CircuitOptions options)
    {
        options.DetailedErrors = false;
    }
}
```

There is no code fix; choose whether to disable the option or tie it to your environment.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1708.severity = warning
```

There are no rule-specific options. Severity accepts `default`, `none`, `silent`, `suggestion`, `warning`, or `error`. The default is `warning`, with the rule enabled.

## When to suppress

Suppress only for code restricted to local development, or for an assignment already guarded by a development-environment check. Keep detailed errors disabled in deployed production code.
