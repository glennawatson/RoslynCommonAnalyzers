# SES1709 — Do not serialize every claim into the client-readable authentication state

**Category:** Blazor  
**Default severity:** Warning, enabled  
**Code fix:** None

## Cause

`Microsoft.AspNetCore.Components.WebAssembly.Server.AuthenticationStateSerializationOptions.SerializeAllClaims` is assigned the literal `true`, either directly or in an object initializer.

A claim is a piece of information about the signed-in user. This option copies every claim into authentication state that the browser can read. Claims can include private identifiers, tokens, and personal data. The default sends only name and role claims.

The rule does not report `false`, a variable, a named constant, or another expression. It ignores same-named properties on other types. A value that avoids the diagnostic can still expose claims if it evaluates to `true`.

## How to fix violations

Leave `SerializeAllClaims` at its default of `false`. If the browser needs more claims, choose the individual claims to include through the serialization callback.

Bad:

```csharp
using Microsoft.AspNetCore.Components.WebAssembly.Server;

public class AuthenticationSetup
{
    public void Configure(AuthenticationStateSerializationOptions options)
    {
        options.SerializeAllClaims = true;
    }
}
```

Corrected:

```csharp
using Microsoft.AspNetCore.Components.WebAssembly.Server;

public class AuthenticationSetup
{
    public void Configure(AuthenticationStateSerializationOptions options)
    {
        options.SerializeAllClaims = false;
    }
}
```

There is no code fix; changing this option can remove claims the client depends on.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1709.severity = warning
```

There are no rule-specific options. Severity accepts `default`, `none`, `silent`, `suggestion`, `warning`, or `error`. The default is `warning`, with the rule enabled.

## When to suppress

Suppress only when every claim is intended to be readable by the browser and the application controls which claims can be added. Review that decision whenever the authentication provider or claim set changes. Sending a selected set of claims is easier to keep safe.
