# SES1710 — Do not disable antiforgery validation on a form

**Category:** Blazor  
**Default severity:** Warning, enabled  
**Code fix:** None

## Cause

`Microsoft.AspNetCore.Antiforgery.RequireAntiforgeryTokenAttribute` is applied to a class or method with a `required` argument that is the constant `false`. Both `required: false` and positional `false` are reported.

Antiforgery validation checks a form's token to help stop another website from submitting a request as the signed-in user. Disabling the check removes that protection.

The attribute with no argument, or with `true`, is not reported. A same-named attribute from another namespace is ignored.

## How to fix violations

Remove the argument or pass `true` so the token is required.

Bad:

```csharp
using Microsoft.AspNetCore.Antiforgery;
using Microsoft.AspNetCore.Components;

[RequireAntiforgeryToken(required: false)]
public class UploadForm : ComponentBase
{
}
```

Corrected:

```csharp
using Microsoft.AspNetCore.Antiforgery;
using Microsoft.AspNetCore.Components;

[RequireAntiforgeryToken]
public class UploadForm : ComponentBase
{
}
```

There is no code fix; check that callers supply antiforgery tokens before enabling validation.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SES1710.severity = warning
```

There are no rule-specific options. Severity accepts `default`, `none`, `silent`, `suggestion`, `warning`, or `error`. The default is `warning`, with the rule enabled.

## When to suppress

Suppress only after checking that forged cross-site requests cannot act on a user's behalf. An endpoint that changes no state and uses no user session can be an exception. Keep validation for forms that change data using the user's cookies or session.
