# SST1162 — Struct primary constructor parameters should be on unique lines

| | |
| --- | --- |
| **Category** | Readability |
| **Default severity** | Warning (enabled) |
| **Code fix** | Yes |

## Cause

A struct primary constructor has two or more parameters and mixes line breaks with parameters that share a line with `(` or another parameter.

Keep `(` and the start of every parameter on one line, or start each parameter on a separate line after `(`. Lists with zero or one parameter are ignored. The position of `)` does not affect this rule.

Struct primary constructors require C# 12 or later. This rule checks the parameters after the struct name; record structs use the record parameter rule.

## How to fix violations

Move each parameter onto its own line after `(`, or put the whole list on one line.

Before:

```csharp
public struct Foo(
    int a, int b)
{
    public int Sum => a + b;
}
```

After:

```csharp
public struct Foo(
    int a,
    int b)
{
    public int Sum => a + b;
}
```

## Code fix

The fix adds a line break after `(` and puts each parameter on a separate indented line. It keeps the parameters in order and matches the file's line endings. Fix All applies the same edit to other reported lists.

The fix can remove comments before parameters, around commas, or beside the parentheses. Check the preview and move any comments you need to keep before accepting it.

## Configuration

The rule is enabled as a warning by default. It has no options beyond severity.

```ini
[*.cs]
dotnet_diagnostic.SST1162.severity = warning
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [configuration](../CONFIGURATION.md) for file and directory settings.

## When to suppress

Suppress when a required struct declaration layout groups related parameters on shared lines. Generated code is ignored. Set the severity to `none` for the files that need the exception.
