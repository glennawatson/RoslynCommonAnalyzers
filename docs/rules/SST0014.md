# SST1163 — Target-typed new arguments should be on unique lines

| | |
| --- | --- |
| **Category** | Readability |
| **Default severity** | Warning (enabled) |
| **Code fix** | Yes |

## Cause

A `new(...)` expression with no type name has two or more arguments and mixes line breaks with arguments that share a line with `(` or another argument.

Keep `(` and the start of every argument on one line, or start each argument on a separate line after `(`. Lists with zero or one argument are ignored. The position of `)` does not affect this rule.

This form of `new` requires C# 9 or later. It also applies when the expression is an argument to another constructor or method.

## How to fix violations

Move each argument onto its own line after `(`, or put the whole list on one line.

Before:

```csharp
public class Foo
{
    public Foo(int a, int b) { }

    public static Foo Create() => new(
        1, 2);
}
```

After:

```csharp
public class Foo
{
    public Foo(int a, int b) { }

    public static Foo Create() => new(
        1,
        2);
}
```

## Code fix

The fix adds a line break after `(` and puts each argument on a separate indented line. It keeps the arguments in order and matches the file's line endings. Fix All applies the same edit to other reported lists.

The fix can remove comments before arguments, around commas, or beside the parentheses. Check the preview and move any comments you need to keep before accepting it.

## Configuration

The rule is enabled as a warning by default. It has no options beyond severity.

```ini
[*.cs]
dotnet_diagnostic.SST1163.severity = warning
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [configuration](../CONFIGURATION.md) for file and directory settings.

## When to suppress

Suppress when a required layout groups related constructor arguments on shared lines. Generated code is ignored. Set the severity to `none` for the files that need the exception.
