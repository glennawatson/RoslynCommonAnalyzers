# SST1168 — Conversion operator parameters should be on unique lines

| | |
| --- | --- |
| **Category** | Readability |
| **Default severity** | Warning (enabled) |
| **Code fix** | Not offered for valid conversion operators |

## Cause

This rule reports a conversion operator with multiple parameters that mixes shared lines and line breaks. Valid C# conversion operators have exactly one parameter, so they cannot trigger it. A declaration with extra parameters is a compiler error.

## Example

There is no valid C# violation example. Both of these layouts are accepted:

```csharp
public class Foo
{
    public static implicit operator int(Foo value) => 0;
}
```

```csharp
public class Foo
{
    public static implicit operator int(
        Foo value) => 0;
}
```

## Code fix

No code fix is offered for valid conversion operators because they produce no diagnostic. For an invalid declaration with extra parameters, the fix puts each parameter on a separate indented line after `(`. It can remove comments around parameters, commas, and parentheses. It does not correct the parameter count; fix the declaration so it has exactly one parameter.

## Configuration

The rule is enabled as a warning by default. It has no options beyond severity.

```ini
[*.cs]
dotnet_diagnostic.SST1168.severity = warning
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [configuration](../CONFIGURATION.md) for file and directory settings.

## When to suppress

Valid conversion operators need no suppression. If an invalid declaration triggers the rule, fix its compiler error first. Set severity to `none` if you do not want an extra formatting diagnostic while editing incomplete declarations. Generated code is ignored.
