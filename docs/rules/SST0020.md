# SST0020 — Type parameter lists should be on unique lines

| Item | Value |
| --- | --- |
| Reported diagnostic | [SST1169](SST1169.md) |
| Category | Readability |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

A type parameter list with two or more entries is partly on one line and partly wrapped.
Either start all parameters on the same line as `<`, or start each parameter on a separate
line after `<`. A list with only one parameter is not reported.

## Example

Bad:

```csharp
public class Foo<
    T1, T2>
{
}
```

Corrected:

```csharp
public class Foo<
    T1,
    T2>
{
}
```

## How to fix violations

The code fix puts a line break after `<` and each comma. It indents each parameter four
spaces beyond the line containing `<` and keeps the file's line endings. It can remove
comments after `<`, around commas, or before parameters. Review the preview if the list
contains comments.

You can also put the whole list on one line, such as `Foo<T1, T2>`.

## Configuration

Configure the reported diagnostic with this key:

```ini
[*.cs]
dotnet_diagnostic.SST1169.severity = warning
```

The default is `warning`. The other values are `error`, `suggestion`, `silent`, and `none`.
There are no layout options. See [configuration](../CONFIGURATION.md) for file-specific settings.

## When to suppress

Use `none` for files whose required layout groups related type parameters on the same line.
Code recognized as generated is already excluded.
