# SST0021 — Type argument lists should be on unique lines

| Item | Value |
| --- | --- |
| Reported diagnostic | [SST1170](SST1170.md) |
| Category | Readability |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

A generic type argument list with two or more entries is partly on one line and partly
wrapped. Either start all type arguments on the same line as `<`, or start each on a
separate line after `<`. A list with only one type argument is not reported.

## Example

Bad:

```csharp
public class Foo
{
    private readonly System.Collections.Generic.Dictionary<
        int, string> _map = new();
}
```

Corrected:

```csharp
public class Foo
{
    private readonly System.Collections.Generic.Dictionary<
        int,
        string> _map = new();
}
```

## How to fix violations

The code fix puts a line break after `<` and each comma. It indents each type argument four
spaces beyond the line containing `<` and keeps the file's line endings. It can remove
comments after `<`, around commas, or before type arguments. Review the preview if the list
contains comments.

You can also put the whole list on one line, such as `Dictionary<int, string>`.

## Configuration

Configure the reported diagnostic with this key:

```ini
[*.cs]
dotnet_diagnostic.SST1170.severity = warning
```

The default is `warning`. The other values are `error`, `suggestion`, `silent`, and `none`.
There are no layout options. See [configuration](../CONFIGURATION.md) for file-specific settings.

## When to suppress

Use `none` for files whose required layout groups related type arguments on the same line.
Code recognized as generated is already excluded.
