# SST0022 — Function pointer parameter lists should be on unique lines

| Item | Value |
| --- | --- |
| Reported diagnostic | [SST1171](SST1171.md) |
| Category | Readability |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

A function pointer list with two or more entries is partly on one line and partly wrapped.
Either start all entries on the same line as `<`, or start each on a separate line after
`<`. The return type is the last entry and follows the same layout. A list containing only
a return type is not reported.

Function pointers require C# 9 or later, an `unsafe` context, and unsafe compilation enabled.

## Example

Bad:

```csharp
unsafe class C
{
    delegate*<
        int, string, void> f;
}
```

Corrected:

```csharp
unsafe class C
{
    delegate*<
        int,
        string,
        void> f;
}
```

## How to fix violations

The code fix puts a line break after `<` and each comma. It indents each entry four spaces
beyond the line containing `<` and keeps the file's line endings. It can remove comments
after `<`, around commas, or before entries. Review the preview if the list contains comments.

You can also put the whole list on one line, such as `delegate*<int, string, void>`.

## Configuration

Configure the reported diagnostic with this key:

```ini
[*.cs]
dotnet_diagnostic.SST1171.severity = warning
```

The default is `warning`. The other values are `error`, `suggestion`, `silent`, and `none`.
There are no layout options. See [configuration](../CONFIGURATION.md) for file-specific settings.

## When to suppress

Use `none` when a function pointer declaration must keep the layout of an external API.
Code recognized as generated is already excluded.
