# SST1001 — Commas should be spaced correctly

| Item | Value |
| --- | --- |
| Category | Spacing |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

A list comma has whitespace or a comment before it on the same line, or touches the next
item without a separating space. Line breaks are accepted. A comma before `)`, `]`, or `}`
does not need a following space.

There are two exceptions:

- A comma used in place of omitted generic types, as in `typeof(Dictionary<,>)`, needs no
  following space. A space after this comma is reported and removed.
- A comma before a string alignment width, as in `$"{value,8}"`, does not need a following space.

## Example

Bad:

```csharp
class C
{
    void M(int a, int b) => Combine(a ,b);
    void Combine(int x, int y) { }
}
```

Corrected:

```csharp
class C
{
    void M(int a, int b) => Combine(a, b);
    void Combine(int x, int y) { }
}
```

## How to fix violations

The **Fix spacing** code fix removes spaces and tabs before the comma, or inserts a missing
space after it. For omitted generic types, it removes spaces and tabs after the comma.
Use Fix All to correct both sides when needed. The fix keeps line breaks and comments.
If a comment immediately before the comma still triggers the rule, move the comment
elsewhere by hand.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST1001.severity = warning
```

The default is `warning`. The other values are `error`, `suggestion`, `silent`, and `none`.
There are no spacing options. See [configuration](../CONFIGURATION.md) for file-specific settings.

## When to suppress

Use `none` for files that must preserve a different comma layout, such as hand-aligned tables.
