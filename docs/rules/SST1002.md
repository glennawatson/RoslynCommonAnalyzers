# SST1002 — Semicolons should be spaced correctly

| Item | Value |
| --- | --- |
| Category | Spacing |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

A semicolon has whitespace or a comment before it on the same line, or touches the code
that follows it.
Line breaks are accepted. No following space is required before another semicolon or a
closing `)`, `]`, or `}`. This allows the empty clauses in `for (;;)`.

## Example

Bad:

```csharp
class C
{
    void M()
    {
        System.Console.WriteLine() ;
    }
}
```

Corrected:

```csharp
class C
{
    void M()
    {
        System.Console.WriteLine();
    }
}
```

## How to fix violations

The **Fix spacing** code fix removes spaces and tabs before the semicolon, or inserts a
missing space after it. Use Fix All to correct both sides when needed. The fix keeps
line breaks and comments. If a comment immediately before the semicolon still triggers
the rule, move the comment elsewhere by hand.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST1002.severity = warning
```

The default is `warning`. The other values are `error`, `suggestion`, `silent`, and `none`.
There are no spacing options. See [configuration](../CONFIGURATION.md) for file-specific settings.

## When to suppress

Use `none` for files that must preserve a different semicolon layout, such as aligned declarations.
