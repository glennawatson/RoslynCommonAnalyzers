# SST1011 — Closing square brackets should be spaced correctly

| Item | Value |
| --- | --- |
| Category | Spacing |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A space or tab appears before `]` in an array type or an access such as `items[0]`.
For collection expressions (`[1, 2]`) and list patterns (`items is [1, 2]`), spacing
before `]` must match the configured style. A line break before `]` is allowed.
Attribute brackets are handled by [SST1017](SST1017.md).

## Example

Reported:

```csharp
int[] items = { 1, 2 };
int first = items[0 ];
```

Corrected:

```csharp
int[] items = { 1, 2 };
int first = items[0];
```

## How to fix violations

Choose **Fix spacing** to remove spaces and tabs before `]` or insert a space,
as the configured style requires. The fix preserves comments and line breaks.
A comment before `]` can keep a warning active when spaces are forbidden; move
that comment if needed.

## Configuration

The default severity is `warning`. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1011.severity = error
stylesharp.collection_expression_spacing = none
```

Severity can be `error`, `warning`, `suggestion`, `silent`, or `none`.

[`stylesharp.collection_expression_spacing`](../CONFIGURATION.md#collection-expression-spacing)
controls collection expressions and list patterns:

| Value | Spacing inside non-empty brackets |
| --- | --- |
| `none` (default) | No padding: `[1, 2]` |
| `space` | Padding required: `[ 1, 2 ]` |

With `none`, `[ ]` becomes `[]`. With `space`, both empty forms are accepted.
Array, element-access, and indexed-initializer brackets always use no inner padding.
Enable [SST1010](SST1010.md) to enforce the same style at the opening bracket.

## When to suppress

Disable the rule if your team's format requires spaces inside array or
element-access brackets. For padded collections, choose `space` instead. Suppress
an individual warning if a comment before `]` must stay in place.
