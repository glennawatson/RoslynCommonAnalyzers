# SST1013 — Closing braces should be spaced correctly

| Item | Value |
| --- | --- |
| Category | Spacing |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A closing `}` touches the code before it. Add a space or put `}` on the next line.
This applies to blocks, initializer lists, and property accessors, even when the
opening brace is on another line. Empty `{}` and the braces around expressions
inside interpolated strings, such as `$"{value}"`, are exempt.

## Example

Reported:

```csharp
int[] values = new[] { 1, 2};
```

Corrected:

```csharp
int[] values = new[] { 1, 2 };
```

## How to fix violations

Choose **Fix spacing** to insert one space immediately before `}`. The fix keeps
the code on the same line and preserves comments.

## Configuration

The default severity is `warning`. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1013.severity = error
```

Severity can be `error`, `warning`, `suggestion`, `silent`, or `none`. There are
no rule-specific options.

## When to suppress

Disable the rule if your team's format deliberately omits spaces inside braces.
Empty braces and interpolated-string expressions do not need suppression.
