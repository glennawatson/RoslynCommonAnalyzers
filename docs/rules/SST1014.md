# SST1014 — Opening generic brackets should be spaced correctly

| Item | Value |
| --- | --- |
| Category | Spacing |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A space or tab appears before or after the `<` in generic code, such as `List<int>`
or a declaration of `Container<T>`. Line breaks are allowed. A less-than comparison
such as `count < limit` is not reported by this rule.

## Example

Reported:

```csharp
var values = new System.Collections.Generic.List < int>();
```

Corrected:

```csharp
var values = new System.Collections.Generic.List<int>();
```

## How to fix violations

Choose **Fix spacing** to remove spaces and tabs on the reported side of `<`.
If both sides have spaces, fix both warnings. The fix preserves comments and line
breaks. A comment beside `<` can also trigger the rule; move it if the warning remains.

## Configuration

The default severity is `warning`. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1014.severity = error
```

Severity can be `error`, `warning`, `suggestion`, `silent`, or `none`. There are
no rule-specific options.

## When to suppress

Disable the rule if your team's format requires spaces around generic brackets.
Suppress an individual warning if a comment beside `<` must stay in place.
