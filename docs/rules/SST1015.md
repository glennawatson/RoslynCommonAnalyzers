# SST1015 — Closing generic brackets should be spaced correctly

| Item | Value |
| --- | --- |
| Category | Spacing |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A space or tab appears before the `>` in generic code, such as `List<int>` or a
declaration of `Container<T>`. A line break before `>` is allowed. Greater-than
comparisons and spaces after `>` are not reported by this rule.

## Example

Reported:

```csharp
var values = new System.Collections.Generic.List<int >();
```

Corrected:

```csharp
var values = new System.Collections.Generic.List<int>();
```

## How to fix violations

Choose **Fix spacing** to remove spaces and tabs immediately before `>`.
The fix preserves comments and line breaks. A comment before `>` can also
trigger the rule; move it if the warning remains.

## Configuration

The default severity is `warning`. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1015.severity = error
```

Severity can be `error`, `warning`, `suggestion`, `silent`, or `none`. There are
no rule-specific options.

## When to suppress

Disable the rule if your team's format requires spaces inside generic brackets.
Suppress an individual warning if a comment before `>` must stay in place.
