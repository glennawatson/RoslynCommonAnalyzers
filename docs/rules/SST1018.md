# SST1018 — Nullable type symbols should not be preceded by a space

| Item | Value |
| --- | --- |
| Category | Spacing |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A space or tab separates a type from its nullable `?` on the same line, as in
`int ?`. This applies to both value types and nullable reference types.
The `?` in a conditional expression or `?.` access is not reported by this rule.

## Example

Reported:

```csharp
class Example
{
    public int ? Read() => null;
}
```

Corrected:

```csharp
class Example
{
    public int? Read() => null;
}
```

## How to fix violations

Choose **Fix spacing** to remove spaces and tabs immediately before `?`.
The fix preserves comments and line breaks. A comment between the type and `?`
can also trigger the rule; move it if the warning remains.

## Configuration

The default severity is `warning`. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1018.severity = error
```

Severity can be `error`, `warning`, `suggestion`, `silent`, or `none`. There are
no rule-specific options.

## When to suppress

Disable the rule if your team's format requires a space before a nullable `?`.
Suppress an individual warning if a comment between the type and `?` must stay in place.
