# SST1019 — Member access symbols should be spaced correctly

| Item | Value |
| --- | --- |
| Category | Spacing |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A space or tab appears beside `.` on the same line in a member access or a
qualified name, such as `System.Console`. The dot in `value?.Name` is also checked.
Line breaks are allowed, including a dot at the start of the next line in a chain
of calls. Keep the member name next to that dot.

## Example

Reported:

```csharp
string text = "hello";
string copy = text .ToString();
```

Corrected:

```csharp
string text = "hello";
string copy = text.ToString();
```

## How to fix violations

Choose **Fix spacing** to remove spaces and tabs on the reported side of `.`.
If both sides have spaces, fix both warnings. The fix preserves comments and line
breaks. A comment beside `.` can also trigger the rule; move it if the warning remains.

## Configuration

The default severity is `warning`. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1019.severity = error
```

Severity can be `error`, `warning`, `suggestion`, `silent`, or `none`. There are
no rule-specific options.

## When to suppress

Disable the rule if your team's format deliberately puts spaces around dots.
Suppress an individual warning if a comment beside `.` must stay in place.
