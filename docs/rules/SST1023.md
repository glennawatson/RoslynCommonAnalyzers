# SST1023 — Dereference and address-of symbols should be spaced correctly

| Item | Value |
| --- | --- |
| Category | Spacing |
| Default severity | Warning when enabled |
| Enabled by default | No |
| Code fix | Yes |

## Cause

A pointer operator is separated from the value it applies to on the same line.
The `*` operator reads the value at an address. The `&` operator gets a value's
address. Write them as `*ptr` and `&value`.

The rule applies to `unsafe` pointer code. It does not report multiplication,
bitwise AND, or pointer declarations such as `int* ptr`. Spacing around binary
operators is covered by [SST1003](SST1003.md). A line break after a pointer
operator is allowed.

## Example

These examples require unsafe code to be enabled in the project.

Before:

```csharp
unsafe class C
{
    int Copy(int value)
    {
        int* ptr = & value;
        return * ptr;
    }
}
```

After:

```csharp
unsafe class C
{
    int Copy(int value)
    {
        int* ptr = &value;
        return *ptr;
    }
}
```

## How to fix violations

The code fix removes spaces and tabs immediately after `*` or `&`. It keeps
comments and line breaks. Move an intervening comment by hand if it prevents the
symbol from touching its value.

## Configuration

The rule is disabled by default. There are no rule-specific options. Enable it
as a warning:

```ini
[*.cs]
dotnet_diagnostic.SST1023.severity = warning
```

Other severity values are `error`, `suggestion`, `silent`, and `none`.

## When to suppress

Leave the rule disabled, or set its severity to `none`, if your team uses spaces
after pointer operators. It has no effect on code that does not use pointers.
