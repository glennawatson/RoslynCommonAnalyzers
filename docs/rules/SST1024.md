# SST1024 — Colons should be spaced correctly

| Item | Value |
| --- | --- |
| Category | Spacing |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A colon has a missing or unwanted space for the way it is used.

## Rule description

On the same line, use these spacing rules:

- A space on each side for inheritance (`class C : B`), constructor calls
  (`C() : base()`), conditional expressions (`test ? a : b`), and generic
  constraints (`where T : class`).
- No space before and a space after for labels (`case 1:`, `default:`, `label:`),
  named arguments (`name: value`), tuple element names (`name: value`), property
  patterns (`{ Name: value }`), and attribute targets (`[return: ...]`).

Line breaks next to a colon are allowed. Format colons inside interpolated
strings, such as `$"{value:F2}"`, are not reported.

## Example

Before:

```csharp
class B { }
class C: B { }
```

After:

```csharp
class B { }
class C : B { }
```

## How to fix violations

The code fix inserts a missing space or removes spaces and tabs before a colon
where they are not allowed. It edits the reported side of the colon; both sides
can need separate fixes. It keeps comments and line breaks. Extra spaces where
one space is required are covered by [SST1025](SST1025.md).

## Configuration

The default severity is `warning`. There are no options to change the spacing
conventions. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1024.severity = error
```

Other severity values are `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Disable the rule with `none` if your team uses different colon spacing. Suppress
it locally when intentional alignment is more useful than the standard spacing.
