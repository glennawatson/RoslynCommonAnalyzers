# SST1100 — Do not prefix calls with base unless a local override exists

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |

## Cause

A `base.` prefix accesses a member that the current type neither overrides nor
hides with a member of the same name.

## Rule description

Use `base.` when you need the inherited implementation instead of your own
override or hiding member. For example, a property declared with `new` can use
`base.Value` to reach the inherited property. Those uses are not reported.

The rule checks member access, including method calls and properties. It does
not report constructor calls such as `: base(value)`.

## Example

Before:

```csharp
class Base
{
    public void Help() { }
}

class Derived : Base
{
    void Call() => base.Help();
}
```

After:

```csharp
class Base
{
    public void Help() { }
}

class Derived : Base
{
    void Call() => Help();
}
```

## How to fix violations

Remove the redundant `base.` prefix. Use `this.` instead if a local variable or
parameter has the same name as the inherited member.

There is no code fix.

## Configuration

The default severity is `warning`. There are no rule-specific options. To report
violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1100.severity = error
```

Other severity values are `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress the rule if keeping `base.` makes the intended inherited member clearer,
or if removing it would change which member is used. Overrides and hiding
members are already allowed and do not normally need suppression.
