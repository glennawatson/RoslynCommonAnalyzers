# SST1102 — Query clause should follow the previous clause

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |

## Cause

A part of a LINQ query, such as `where` or `select`, starts more than one line
after the preceding part ends. Blank lines and lines containing only comments
both count as gaps.

## Rule description

Keep consecutive query clauses together. A clause can follow on the same line
or the next line. Other query layout rules can still require a new line.
Clauses after an `into` continuation are not checked by this rule.

## Example

Before:

```csharp
using System.Collections.Generic;
using System.Linq;

class C
{
    IEnumerable<int> Filter(int[] source) =>
        from x in source

        where x > 0
        select x;
}
```

After:

```csharp
using System.Collections.Generic;
using System.Linq;

class C
{
    IEnumerable<int> Filter(int[] source) =>
        from x in source
        where x > 0
        select x;
}
```

## How to fix violations

Remove blank lines between clauses. Move an intervening comment above the query
or to the end of the preceding clause's line.

There is no code fix.

## Configuration

The default severity is `warning`. There is no option to allow a number of blank
lines. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1102.severity = error
```

Other severity values are `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress the rule when a blank line or separate comment makes a long query
easier to follow. Set the severity to `none` if your team uses that layout
throughout the project.
