# SST1103 — Query clauses should be on the same line or each on its own line

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |

## Cause

Two consecutive LINQ query clauses share a line, each fits on that line, and
the query as a whole spans several lines.

## Rule description

Put the whole query on one line, or start each clause on its own line. A clause
is a part of the query, such as `from`, `where`, or `select`.

If one of the two clauses itself spans several lines, [SST1104](SST1104.md) or
[SST1105](SST1105.md) reports the layout instead. Clauses after an `into`
continuation are not checked by this rule.

## Example

Before:

```csharp
using System.Collections.Generic;
using System.Linq;

class C
{
    IEnumerable<int> Filter(int[] source) =>
        from x in source
        where x > 0 select x;
}
```

After:

```csharp
using System.Collections.Generic;
using System.Linq;

class C
{
    IEnumerable<int> Filter(int[] source) =>
        from x in source
        where x > 0
        select x;
}
```

## How to fix violations

Put every clause on its own line, or put the whole query on one line if it is
short enough to read comfortably.

There is no code fix.

## Configuration

The default severity is `warning`. There are no options to allow mixed layouts
or set a line-length limit. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1103.severity = error
```

Other severity values are `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress the rule when keeping short, related clauses together makes a query
easier to read. Set the severity to `none` if your team prefers mixed layouts.
