# SST1104 — Query clause should begin on a new line after a multi-line clause

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |

## Cause

A LINQ query clause begins on the last line of a preceding clause that spans
multiple lines. A clause is a part of the query, such as `where` or `select`.

## Rule description

Start the following clause on a new line so the two parts are easy to tell
apart. Clauses after an `into` continuation are not checked by this rule.

## Example

Before:

```csharp
using System.Collections.Generic;
using System.Linq;

class C
{
    IEnumerable<int> Filter(int[] source) =>
        from x in source
        where x > 0 &&
            x < 10 select x;
}
```

After:

```csharp
using System.Collections.Generic;
using System.Linq;

class C
{
    IEnumerable<int> Filter(int[] source) =>
        from x in source
        where x > 0 &&
            x < 10
        select x;
}
```

## How to fix violations

Move the following clause onto its own line. Keep it directly after the
preceding clause; inserting a blank line can trigger [SST1102](SST1102.md).

There is no code fix.

## Configuration

The default severity is `warning`. There are no rule-specific options. To report
violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1104.severity = error
```

Other severity values are `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress the rule only when sharing the final line makes the query easier to
read under your team's layout convention. Otherwise, move the clause.
