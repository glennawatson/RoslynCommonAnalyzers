# SST1105 — Query clauses spanning multiple lines should begin on their own line

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |

## Cause

A query clause spans several lines but starts on the same line as the preceding single-line
clause. Start the clause on its own line so readers can see where it begins.

A query written entirely on one line is allowed. Clauses after a query continuation (`into`)
are not checked. If the preceding clause also spans several lines, [SST1104](SST1104.md)
reports the shared line instead.

## Example

Bad:

```csharp
using System.Collections.Generic;
using System.Linq;

class Filter
{
    public IEnumerable<int> Apply(int[] source) =>
        from x in source where x > 0 &&
            x < 10
        select x;
}
```

Corrected:

```csharp
using System.Collections.Generic;
using System.Linq;

class Filter
{
    public IEnumerable<int> Apply(int[] source) =>
        from x in source
        where x > 0 &&
            x < 10
        select x;
}
```

## How to fix violations

Move the start of the multi-line clause onto its own line. There is no code fix.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1105.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).

## When to suppress

Suppress when you must preserve the layout of a query copied from an external example.
For ordinary queries, moving the clause is clearer.
