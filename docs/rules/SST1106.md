# SST1106 — Code should not contain empty statements

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes (supports Fix All) |

## Cause

A semicolon forms a statement by itself. This can be a typing mistake, such as a doubled
semicolon, or an empty loop or `if` body. An accidental semicolon after a loop or `if`
condition can leave the following code outside that body.

A labeled empty statement, such as `done: ;`, is not reported.

## Example

Bad:

```csharp
class Example
{
    public void Run()
    {
        var x = 1;
        ;
    }
}
```

Corrected:

```csharp
class Example
{
    public void Run()
    {
        var x = 1;
    }
}
```

## How to fix violations

The code fix removes the empty statement from a block, a `switch` section, or top-level code.
It also removes whitespace and comments attached to that statement. Move any comment you need
before accepting the fix. Fix All removes all eligible empty statements.

There is no fix for a semicolon used as a loop or `if` body. Review the intended control flow
and write the body yourself. Use an empty block with a comment if the body is deliberately empty.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1106.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).

## When to suppress

Suppress for a deliberate empty loop body when the semicolon is part of an established style.
Add a comment explaining why the loop needs no body.
