# SST1107 — Code should not contain multiple statements on one line

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |

## Cause

A statement starts on the same line where the previous statement ends within a block or
`switch` section. Put each statement on its own line so readers can follow the steps in order.

Top-level statements are not checked. An empty statement is reported by [SST1106](SST1106.md)
instead, though a non-empty statement after it can still be reported here.

## Example

Bad:

```csharp
class Example
{
    public void Run()
    {
        System.Console.WriteLine(1); System.Console.WriteLine(2);
    }
}
```

Corrected:

```csharp
class Example
{
    public void Run()
    {
        System.Console.WriteLine(1);
        System.Console.WriteLine(2);
    }
}
```

## How to fix violations

Move each statement onto its own line. There is no code fix.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1107.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).

## When to suppress

Suppress for compact test cases where keeping related statements together helps compare cases.
Use separate lines when the order of operations needs explanation.
