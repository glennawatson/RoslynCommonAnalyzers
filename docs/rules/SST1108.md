# SST1108 — Remove files that contain only commented-out code

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | None |
| Default | Disabled (opt-in) |

## Cause

The file contains only commented-out C# code. This can be a namespace, a type,
or a delegate. The code has no effect on the program. Keeping an unused copy
makes the project harder to read.

The rule checks both `//` comments and `/* ... */` blocks. The comments must
contain a complete C# declaration. A copyright or license header may come first.

Empty files, plain text, and files with live code are not reported. Files with
directives such as `#if` or `#nullable` are also excluded.

## Example

Bad, when the rule is enabled:

```csharp
// namespace Example
// {
//     public class Processor
//     {
//         public void Run() { }
//     }
// }
```

## How to fix violations

There is no automatic code fix. Delete the file if the code is not needed.
Version control keeps a copy if you need it later. Keep useful comments near
the live code they explain.

## Configuration

The rule is disabled by default and has no rule-specific options. Enable it
with:

```ini
[*.cs]
dotnet_diagnostic.SST1108.severity = warning
```

Set the severity to `none` to disable it. See [configuration](../CONFIGURATION.md)
for severity and file-specific settings.

## When to suppress

Suppress the rule when the file serves a clear purpose. For example, a tool may
read it as input, or your team may need it as a reference during an upgrade.
