# SST1110 — Opening parenthesis or bracket should be on the declaration line

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes (supports Fix All) |

## Cause

The opening `(` or `[` of a parameter or argument list starts on a different line from the
code before it. This applies to declarations, calls, indexers, array access, and attribute
arguments. Keep the opening character beside the name it belongs to.

Lambda parameter lists and dictionary initializer entries such as `["key"] = value` are exempt.

## Example

Bad:

```csharp
class Example
{
    public void Set
        (int x) => _ = x;
}
```

Corrected:

```csharp
class Example
{
    public void Set(int x) => _ = x;
}
```

## Code fix

The fix deletes the whitespace and line breaks before the opening parenthesis or bracket,
joining it directly to the preceding code. Text after that character moves with it; the fix
does not put the first parameter on a separate line. Fix All applies the same edit to each occurrence.

If a comment or directive lies in the gap, accepting the fix leaves the code unchanged.
Move that content yourself before joining the lines.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1110.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).

## When to suppress

Suppress when a required declaration or call layout puts the opening parenthesis on its own line.
Disable the rule for files that consistently use that layout.
