# SST1111 — Closing parenthesis or bracket should be on the line of the last parameter

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |

## Cause

The closing `)` or `]` of a non-empty parameter or argument list is on a different line from
the end of its last item. This applies to declarations, calls, indexers, array access, and
attribute arguments.

The final item can span several lines; the closing character belongs on the line where that
item ends. Empty lists are covered by [SST1112](SST1112.md).

## Example

Bad:

```csharp
class Example
{
    public void Set(
        int x
    ) => _ = x;
}
```

Corrected:

```csharp
class Example
{
    public void Set(
        int x) => _ = x;
}
```

## How to fix violations

Move the closing parenthesis or bracket onto the last item's ending line. If that line ends
with a `//` comment, place the closing character before the comment. There is no code fix.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1111.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).

## When to suppress

Suppress or disable this rule when your layout puts closing parentheses or brackets on separate
lines to align them with the start of a declaration or call.
