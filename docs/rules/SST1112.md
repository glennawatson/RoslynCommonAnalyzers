# SST1112 — Closing parenthesis should be on the line of the opening parenthesis when the list is empty

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |

## Cause

An empty parameter or argument list has its closing parenthesis on a different line from its
opening parenthesis. This includes empty declarations, calls, and attribute argument lists.
Keep `()` together because there are no items to separate.

## Example

Bad:

```csharp
class Example
{
    public void Run(
    )
    {
    }
}
```

Corrected:

```csharp
class Example
{
    public void Run()
    {
    }
}
```

## How to fix violations

Place the closing parenthesis on the opening parenthesis's line. Move any comment between them
above the declaration or call. There is no code fix.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1112.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).

## When to suppress

Suppress when an empty list must match a shared layout that places every closing parenthesis
on its own line. Otherwise, keep the parentheses together.
