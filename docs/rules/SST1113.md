# SST1113 — Comma should be on the same line as the previous parameter

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |

## Cause

A comma between parameters or arguments is on a different line from the end of the preceding
item. This applies to declarations, calls, indexers, array access, and attribute arguments.
Place the comma after the item it separates from the next one.

## Example

Bad:

```csharp
class Example
{
    public int Add(int x
        , int y) => x + y;
}
```

Corrected:

```csharp
class Example
{
    public int Add(int x,
        int y) => x + y;
}
```

## How to fix violations

Move the comma onto the preceding item's ending line. Place it before any `//` comment on that
line. There is no code fix.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1113.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).

## When to suppress

Disable the rule when your team uses a leading-comma layout. Suppress an individual occurrence
when it must match surrounding code in that style.
