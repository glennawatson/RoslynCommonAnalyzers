# SST1115 — A parameter should follow the comma without a blank line

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |

## Cause

A parameter or argument starts more than one line after the comma before it. This applies to
declarations, calls, indexers, array access, and attribute arguments.

The next item must start on the comma's line or the next line. Intervening comment lines also
count as a gap. Spacing before the first item is covered by [SST1114](SST1114.md).

## Example

Bad:

```csharp
class Example
{
    public int Add(int x,

        int y) => x + y;
}
```

Corrected:

```csharp
class Example
{
    public int Add(int x,
        int y) => x + y;
}
```

## How to fix violations

Remove blank lines after the comma. Move any intervening comment onto the item's line or above
the declaration or call. There is no code fix.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1115.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).

## When to suppress

Suppress when a gap separates meaningful groups of arguments or holds a comment that needs to
stay beside an item. Keep ordinary parameter lists compact.
