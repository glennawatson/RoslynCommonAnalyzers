# SST1116 — Prefer the shortest symbol-equivalent name

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes (supports Fix All) |

## Cause

A type or namespace name includes a prefix that can be removed without changing what the name
refers to. For example, `System.Text.StringBuilder` can become `StringBuilder` when
`using System.Text;` is already present. Generic type names are also checked.

Names in `using` directives and namespace declarations are excluded. A prefix is kept if removing
it would make the name ambiguous or refer to a different type or namespace.

## Example

Bad:

```csharp
using System.Text;

public sealed class Example
{
    public int Count(System.Text.StringBuilder builder) => builder.Length;
}
```

Corrected:

```csharp
using System.Text;

public sealed class Example
{
    public int Count(StringBuilder builder) => builder.Length;
}
```

## Code fix

The fix replaces the reported name with its final part, keeping any generic type arguments.
It can also remove an unnecessary `global::` prefix. It does not add `using` directives.
Qualified parameter types inside XML documentation references can be shortened too.
Fix All applies the same replacement to each reported name.

Comments before or after the full name are kept. A comment inside the removed prefix can be
lost, so move it outside the name before accepting the fix.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1116.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).

## When to suppress

Suppress when the namespace helps readers distinguish similar APIs, even though the shorter name
compiles. No suppression is needed when the shorter name would be ambiguous.
