# SST1117 — Use configured instance-member qualification

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes (supports Fix All) |

## Cause

Access to a field, property, method, or event on the current object does not match
`stylesharp.instance_member_qualification`.

The default, `omit_this`, reports unnecessary `this.` prefixes. It keeps `this.` when a local
variable, parameter, or local function with the same name could change what the access means.
Extension methods and extension-block members that need `this.` keep it too.

With `require_this`, the rule reports unqualified instance-member names. Static members, local
variables, named argument labels, names inside `nameof(...)`, already-qualified member names,
and member names being assigned in object initializers are excluded. Calls with explicit generic
type arguments, such as `Read<int>()`, are not reported in this mode.

## Example

Bad with the default `omit_this` setting:

```csharp
public sealed class Counter
{
    private readonly int _value = 1;

    public int Value => this._value;
}
```

Corrected:

```csharp
public sealed class Counter
{
    private readonly int _value = 1;

    public int Value => _value;
}
```

With `require_this`, the second example is reported and the first is the correction.

## Code fix

The fix removes `this.` in `omit_this` mode and adds `this.` in `require_this` mode.
Fix All applies the configured style to every reported access.

Comments before and after the access are kept. Removing `this.` can lose a comment between
`this` and the member name; move that comment before accepting the fix.

## Configuration

The rule is enabled as a warning by default.

```ini
[*.cs]
dotnet_diagnostic.SST1117.severity = warning
stylesharp.instance_member_qualification = omit_this
```

| Option value | Effect |
| --- | --- |
| `omit_this` (default), or `omit` | Remove unnecessary `this.` prefixes. |
| `require_this`, or `this` | Add `this.` to reported instance-member accesses. |

Values ignore letter case and surrounding whitespace. Missing or unknown values use `omit_this`.
Severity values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).

## When to suppress

Choose the option that matches your team's style before suppressing the rule. Suppress an
individual access when showing or omitting `this.` makes an example clearer, or disable the
rule if your codebase deliberately mixes both styles.
