# SST1118 — A parameter should not span multiple lines

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity when enabled | Warning |
| Enabled by default | No |
| Code fix | Yes (supports Fix All) |

## Cause

An argument expression spans several lines. The rule checks arguments in calls, indexers,
array access, and attributes. Despite the title, it does not report parameters in declarations.

Arguments written directly as lambdas, anonymous methods, object or array creations,
initializers, switch expressions, query expressions, or interpolated strings are exempt.
Wrapping one of these expressions in parentheses can make the outer argument reportable.

## Example

Bad when the rule is enabled:

```csharp
public sealed class Example
{
    public int Calculate() => Add(1 +
        2);

    private static int Add(int value) => value;
}
```

Corrected:

```csharp
public sealed class Example
{
    public int Calculate() => Add(1 + 2);

    private static int Add(int value) => value;
}
```

## How to fix violations

The code fix joins the wrapped parts of the argument onto one line. It replaces line breaks
and indentation between parts with a space, or no space beside parentheses, brackets, and commas.

No fix is offered if a gap being joined contains a comment or directive, or if the resulting
line exceeds the configured line limit. Comments in gaps that stay on one line are preserved.
For an ordinary call, consider extracting a long expression into a local variable yourself.
Attribute arguments must remain valid attribute values, so a local variable is not a replacement there.

Fix All is supported, but it uses the default 120-character limit even when a different limit
is configured. Apply individual fixes when you need them to use your configured limit.

## Configuration

The rule is disabled by default. Enable it when your team wants short arguments on one line:

```ini
[*.cs]
dotnet_diagnostic.SST1118.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).

The individual code fix uses the line-length options shared with [SST1521](SST1521.md):

| Key | Values and default |
| --- | --- |
| `stylesharp.max_line_length` | Positive integer; default `120` characters. |
| `stylesharp.SST1521.max_line_length` | Positive integer; overrides the general key when valid. |

An invalid override falls back to the general key. A missing or invalid general value falls back
to `120`. The limit controls whether a fix is offered; it does not change which arguments are reported.

## When to suppress

Leave the rule disabled, or suppress an occurrence, when wrapping an argument improves readability
or keeps a useful comment beside part of an expression. Do not force a long argument onto one line
to satisfy this layout preference.
