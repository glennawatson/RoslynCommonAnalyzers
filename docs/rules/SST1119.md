# SST1119 — Digit separators should group digits regularly

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A numeric literal contains `_` separators, but its digit groups after the first have different widths or use an unsupported width. Decimal groups must have three digits. Hexadecimal and binary groups must all have two digits or all have four digits. The first group's width is not checked.

Literals without separators, or with a decimal point or exponent, are not reported. An `f`, `d`, or `m` suffix alone does not exclude a literal.

```csharp
public class Population
{
    public int Count => 1_000_00_000;
}
```

## How to fix violations

Group the digits so the number is easier to read:

```csharp
public class Population
{
    public int Count => 100_000_000;
}
```

The code fix groups from the right, using three digits for decimal and four for hexadecimal or binary. It keeps the digits, base prefix, and integer suffix. A short number loses its separators: `0xFF_F` becomes `0xFFF`. Valid groups of two, such as `0x_FF_FF`, are already accepted and need no fix.

For a reported decimal literal ending in `f`, `d`, or `m`, regroup the digits manually. The automatic fix counts that suffix as part of the group and can leave the literal reported.

## Configuration

Enabled by default as a warning. There is no option to change the group widths. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1119.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` (disable), and `default` (restore the default).

## When to suppress

Suppress when the groups match a documented data format, bit-field layout, or regional numbering convention that would be harder to read with these widths.
