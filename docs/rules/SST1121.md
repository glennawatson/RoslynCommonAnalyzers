# SST1121 — Use built-in type alias

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled |

## Cause

A framework type name such as `Int32` or `System.String` is used where its C# keyword, `int` or `string`, can be used.

The supported keywords are `bool`, `byte`, `sbyte`, `char`, `decimal`, `double`, `float`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`, `object`, and `string`. `IntPtr` and `UIntPtr` are excluded. A user-defined type with the same name is not reported.

Names used directly in `nameof`, such as `nameof(System.Int32)`, are left alone.

```csharp
class Counter
{
    public System.Int32 Value;
}
```

## How to fix violations

Use the C# keyword for the same type:

```csharp
class Counter
{
    public int Value;
}
```

The code fix replaces the reported type name, including its namespace prefix, with the keyword. Comments before or after the type stay in place. Comments inside a qualified name, such as between `System.` and `Int32`, are dropped; move those comments outside the type name before applying the fix.

## Configuration

Disabled by default, with warning severity when enabled. There are no rule-specific options. To enable it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST1121.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` (disable), and `default` (restore the disabled default).

## When to suppress

Leave the rule disabled if your team prefers framework type names or already enforces this spelling through another style setting. Suppress individual cases that must match a shared example written for several .NET languages.
