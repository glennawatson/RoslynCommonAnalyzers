# SST1122 — Use string.Empty for empty strings

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An empty string literal, `""` or `@""`, is used outside a position that requires a constant. `string.Empty` makes the empty value explicit. Raw and interpolated strings are not checked.

```csharp
class Message
{
    public string GetText() => "";
}
```

`string.Empty` is a field, so it cannot replace a constant. The rule skips `const` fields and locals, attribute arguments, default parameter values, switch case labels, and constant patterns such as `value is ""`.

## How to fix violations

Use `string.Empty`:

```csharp
class Message
{
    public string GetText() => string.Empty;
}
```

The code fix replaces the reported literal with `string.Empty` and preserves surrounding comments and whitespace.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1122.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` (disable), and `default` (restore the default).

## When to suppress

Disable the rule if your team prefers `""`. Suppress an individual case when matching nearby string literals makes a table of values easier to read. Constant-only positions need no suppression.
