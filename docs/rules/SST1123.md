# SST1123 — Do not place regions within elements

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `#region` starts inside a code block, such as a method, constructor, accessor, or nested block. A region around class members is outside this rule's scope.

```csharp
class Worker
{
    public void Run()
    {
        #region Work
        System.Console.WriteLine("Working");
        #endregion
    }
}
```

## How to fix violations

Remove the matching `#region` and `#endregion` lines:

```csharp
class Worker
{
    public void Run()
    {
        System.Console.WriteLine("Working");
    }
}
```

If the hidden code needs a name, extract it into a method. There is no code fix.

[SST1124](SST1124.md) reports regions at any level, including these. To allow regions around members while forbidding them inside methods, disable that rule and keep this one enabled.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1123.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` (disable), and `default` (restore the default).

## When to suppress

Suppress when a tool requires a region inside a block, or when a long routine must stay together and named regions help your team navigate it.
