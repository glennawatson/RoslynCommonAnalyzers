# SST1125 — Use shorthand for nullable types

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A nullable value type is written as `Nullable<T>` or `System.Nullable<T>` instead of `T?`. Both spellings let a value type, such as `int`, hold `null`. A user-defined type named `Nullable` is not reported.

```csharp
class Counter
{
    public System.Nullable<int> Value;
}
```

## How to fix violations

Write the value type followed by `?`:

```csharp
class Counter
{
    public int? Value;
}
```

The code fix replaces the full nullable type with `T?`, keeping the type argument. It preserves comments outside the full type, but can drop comments around the type argument or the removed `Nullable<...>` text. Move those comments outside the type before applying the fix.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1125.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` (disable), and `default` (restore the default).

## When to suppress

Suppress when the long form is needed to match a shared example or teach how `Nullable<T>` works. Disable the rule if your team consistently prefers the long form.
