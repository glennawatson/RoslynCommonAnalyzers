# SST1127 — Generic type constraints should be on their own line

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `where` clause starts on the same line as the end of a declaration or the previous constraint clause. Each clause should start on its own line so the limits on each type parameter are easy to find.

```csharp
class Worker
{
    public void Run<T, U>() where T : class where U : struct
    {
    }
}
```

## How to fix violations

Start each `where` clause on a new line. Constraints for the same type parameter can stay together, as in `where T : class, new()`.

```csharp
class Worker
{
    public void Run<T, U>()
        where T : class
        where U : struct
    {
    }
}
```

## Code fix

The fix replaces the whitespace before the reported `where` with a line break and the declaration's indentation plus four spaces. It uses the file's line ending. Fix All moves all reported clauses. A fix is not offered if a comment or other non-whitespace text sits immediately between the previous code and `where`; move the clause manually in that case.

## Configuration

Enabled by default as a warning. There are no rule-specific options; the fix's four added spaces are not configurable. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1127.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` (disable), and `default` (restore the default).

## When to suppress

Suppress for a compact declaration whose short constraints are easier to read together. Disable the rule if that layout is your team's standard.
