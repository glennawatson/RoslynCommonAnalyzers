# SST1128 — Constructor initializers should be on their own line

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

The `:` before a constructor's `base(...)` or `this(...)` call shares a line with the closing `)` of the constructor's parameter list. This also applies when the parameter list spans several lines.

```csharp
class Base
{
    protected Base(int value) { }
}

class Derived : Base
{
    public Derived() : base(1)
    {
    }
}
```

## How to fix violations

Move the colon and constructor call to the next line:

```csharp
class Base
{
    protected Base(int value) { }
}

class Derived : Base
{
    public Derived()
        : base(1)
    {
    }
}
```

There is no code fix.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1128.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` (disable), and `default` (restore the default).

## When to suppress

Suppress when a short constructor and its call read better on one line. Disable the rule if your team's formatting standard keeps constructor initializers beside the parameter list.
