# SST1129 — Do not use default value type constructor

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A value type is created with `new T()` with no arguments or object initializer, using its implicit parameterless constructor. `default(T)` expresses the same default value more directly.

Calls with arguments, reference types, object initializers, and calls written as `new()` are not reported. A struct's explicitly declared parameterless constructor is also excluded because it can run code that `default(T)` would skip.

```csharp
class Schedule
{
    public System.DateTime Start() => new System.DateTime();
}
```

## How to fix violations

Use `default` with the type in parentheses:

```csharp
class Schedule
{
    public System.DateTime Start() => default(System.DateTime);
}
```

The code fix replaces the whole constructor call with `default(T)`, using the type name as written. It keeps surrounding comments but drops comments between `new` and the type or inside the empty argument list. Move those comments outside the expression before applying the fix.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1129.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` (disable), and `default` (restore the default).

## When to suppress

Suppress when keeping `new T()` beside other constructor calls makes initialization code easier to read. No suppression is needed for a struct's explicitly declared parameterless constructor.
