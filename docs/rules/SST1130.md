# SST1130 — Use lambda syntax

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An inline callback uses `delegate` syntax. Every anonymous method is reported, including one that omits its parameter list. Delegate type declarations are not reported.

```csharp
class Callbacks
{
    public System.Action<int> Create() => delegate (int value) { _ = value; };
}
```

## How to fix violations

Replace `delegate (parameters)` with `(parameters) =>`. You can omit a single parameter's parentheses and type when C# can work out its type:

```csharp
class Callbacks
{
    public System.Action<int> Create() => value => { _ = value; };
}
```

If the original `delegate` omitted its parameter list, add lambda parameters to match the callback's signature, even if they are unused. There is no code fix.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1130.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` (disable), and `default` (restore the default).

## When to suppress

Suppress when omitting an unused parameter list with `delegate { ... }` makes the callback clearer than a lambda with several unused parameters. Also suppress in code that must compile with a C# version before lambdas were introduced in C# 3.
