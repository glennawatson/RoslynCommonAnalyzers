# SST1131 — Use readable conditions

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A comparison puts a literal value on the left and a non-literal expression on the right. The operators checked are `==`, `!=`, `<`, `<=`, `>`, and `>=`. Literals include `null`, strings, numbers, and numbers prefixed with `+` or `-`.

Two literal operands, such as `1 == 2`, are left alone. A named `const` value or a parenthesized literal on the left is not reported.

```csharp
class Counter
{
    public bool IsPositive(int count) => 0 < count;
}
```

## How to fix violations

Put the changing value first:

```csharp
class Counter
{
    public bool IsPositive(int count) => count > 0;
}
```

The code fix swaps the operands. It reverses `<` and `>` or `<=` and `>=`, and leaves `==` and `!=` unchanged. Spacing and comments around the operands stay in their original positions; check comments that refer to a particular value.

The fix does not check custom comparison operators. For a type that defines its own operators, check that the reversed comparison compiles and has the same meaning before accepting it.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1131.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` (disable), and `default` (restore the default).

## When to suppress

Suppress when the comparison is clearer as part of a range, such as `0 < count && count < limit`, or when reversing a custom comparison operator would change behavior.
