# SST1132 — Do not combine declarations

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A field or local declaration declares more than one variable. Each variable after the first is reported.
Separate declarations make each variable easier to read and edit.

Declarations inside `for (...)`, `using (...)`, and `fixed (...)` are not reported.
A `using` declaration without parentheses is a local declaration and is checked.

## Example

Bad:

```csharp
public class Counters
{
    public int First, Second;
}
```

Corrected:

```csharp
public class Counters
{
    public int First;
    public int Second;
}
```

## How to fix violations

Give each variable its own declaration. Keep its modifiers, type, and initial value, and preserve
the order of initializers. The same change applies to locals such as `int a = 0, b = 1;`.

There is no code fix.

## Configuration

There are no rule-specific options. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1132.severity = error
```

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when a short group of related variables is clearer together and your project's style allows it.
