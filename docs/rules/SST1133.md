# SST1133 — Do not combine attributes

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

Two or more attributes share one pair of brackets. Each attribute after the first is reported,
including attributes on parameters and assembly attributes.

## Example

Bad:

```csharp
using System;

[Serializable, Obsolete]
public class Record
{
}
```

Corrected:

```csharp
using System;

[Serializable]
[Obsolete]
public class Record
{
}
```

## How to fix violations

Give each attribute its own brackets. If the list has a target such as `assembly:` or `return:`,
repeat that target in each new bracket pair. [SST1134](SST1134.md) also requires attributes on
types and members to occupy separate lines.

There is no code fix.

## Configuration

There are no rule-specific options. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1133.severity = error
```

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when keeping a short attribute group together follows your project's style, especially for inline parameter attributes.
