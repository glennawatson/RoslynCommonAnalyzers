# SST1134 — Attributes should not share a line

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An attribute on a type or member ends on the same line as the next attribute list or the declaration
it describes. Putting each on its own line makes the declaration easier to scan.

Attributes on parameters and accessors are not reported. A comma-separated list inside one pair of
brackets is covered by [SST1133](SST1133.md).

## Example

Bad:

```csharp
using System;

[Serializable] public class Record
{
}
```

Corrected:

```csharp
using System;

[Serializable]
public class Record
{
}
```

## How to fix violations

Put a line break after each attribute list, before the next list or the declaration.

There is no code fix.

## Configuration

There are no rule-specific options. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1134.severity = error
```

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when inline attributes are an established style for short declarations in your project.
