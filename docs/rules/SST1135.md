# SST1135 — Using directives should be qualified

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `using` directive relies on its enclosing namespace to complete a namespace or type name.
Write the full name so readers can tell what it imports without checking the surrounding namespace.

Ordinary and `using static` directives are checked. Alias directives such as `using Tasks = ...;`
are not reported. A full name with or without `global::` is accepted. Unresolved names are not reported.

## Example

Bad:

```csharp
namespace System.Threading
{
    using Tasks;
}
```

Corrected:

```csharp
namespace System.Threading
{
    using System.Threading.Tasks;
}
```

## How to fix violations

The code fix replaces the imported name with its full name, without adding `global::`.
It keeps surrounding whitespace and comments, but comments between parts of the replaced name
are lost. Move those comments outside the name before applying the fix.

## Configuration

There are no rule-specific options. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1135.severity = error
```

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when the import is deliberately relative to its enclosing namespace and should follow that namespace when the code moves.
