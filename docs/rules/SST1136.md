# SST1136 — Enum values should be on separate lines

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An enum member starts on the same line where the previous member ends. One member per line makes
the values easier to scan and edit. An enum with zero or one member is not reported.

## Example

Bad:

```csharp
public enum Color
{
    Red, Green, Blue
}
```

Corrected:

```csharp
public enum Color
{
    Red,
    Green,
    Blue
}
```

## How to fix violations

Put each member on a separate line. Keep its attributes, assigned value, and comments with it.

There is no code fix.

## Configuration

There are no rule-specific options. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1136.severity = error
```

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress for a short enum that your project's style deliberately keeps on one line.
