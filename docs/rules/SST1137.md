# SST1137 — Elements should have the same indentation

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes, except for multiline string content |
| Default | Enabled |

## Cause

A statement or member starts at a different indentation from the first element on its own line
in the same container. This applies to statement blocks, classes, structs, records, interfaces,
enums, and namespaces with braces.

Elements with other code or a comment before them on the same line are skipped. File-level members
and members directly under a file-scoped namespace are not compared. Continuation lines within
an expression are not checked by this rule.

## Example

Bad:

```csharp
public class Values
{
    public int First => 1;
        public int Second => 2;
}
```

Corrected:

```csharp
public class Values
{
    public int First => 1;
    public int Second => 2;
}
```

## Code fix

The code fix shifts the reported element's lines to match the first element's indentation.
It adds spaces when moving right and removes leading whitespace when moving left, keeping nested
code's relative indentation where enough whitespace is available. Blank lines are left alone.

No fix is offered if the element contains string text with line breaks, including multiline raw,
verbatim, or interpolated strings. Adjust that code by hand without changing the string's value.

## Configuration

There are no rule-specific options. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1137.severity = error
```

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

The first element supplies the expected indentation; `indent_size` and `tab_width` do not set it.
Each tab counts as one character, so visually aligned tabs and spaces can still be reported.

See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress for intentional visual grouping, or when alignment depends on tabs displaying at a different width from spaces.
