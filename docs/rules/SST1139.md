# SST1139 — Use literal suffix notation instead of casting

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A numeric literal without a suffix is cast using `long`, `ulong`, `uint`, `float`, `double`, or
`decimal`. A suffix is a letter after the number that gives it a type, such as `1L` for a `long`.

The rule checks a literal directly inside the cast or inside one extra pair of parentheses.
It skips literals ending in a letter, including existing suffixes and some hexadecimal numbers.
Casts of variables, calculations, or signed expressions such as `(long)-1` are not reported.
Literals with a decimal point or exponent are not reported for integer casts.

## Example

Bad:

```csharp
public class Values
{
    public long One() => (long)1;
}
```

Corrected:

```csharp
public class Values
{
    public long One() => 1L;
}
```

## How to fix violations

The code fix removes the cast and any parentheses around the literal, then adds the suffix below.
It keeps comments outside the cast, but drops comments inside it. Move those comments before
applying the fix.

| Cast type | Suffix |
| --- | --- |
| `long` | `L` |
| `ulong` | `UL` |
| `uint` | `U` |
| `float` | `F` |
| `double` | `D` |
| `decimal` | `M` |

## Configuration

There are no rule-specific options. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1139.severity = error
```

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Keep the cast when its conversion or rounding is intentional. In particular, converting a
floating-point value to `decimal` can differ from writing a decimal literal directly. Also keep
casts from hexadecimal or binary literals to `float`, `double`, or `decimal`: appending those
suffixes can change the value or produce invalid code.
