# SST1140 — Start conditional operators on indented continuation lines

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes, when operator gaps contain only whitespace |
| Default | Enabled |

## Cause

A conditional expression has a line break next to `?` or `:`, but one or both operators lack the
required line break and indentation before them. Both operators must start continuation lines
four characters deeper than the indentation of the line where the condition begins.

A conditional expression on one line is not reported. Branch expressions can span further lines.

## Example

Bad:

```csharp
public class Choice
{
    public int Pick(bool condition) => condition ?
        1 :
        2;
}
```

Corrected:

```csharp
public class Choice
{
    public int Pick(bool condition) => condition
        ? 1
        : 2;
}
```

## How to fix violations

The code fix moves both operators onto new lines, adds four spaces to the condition line's
indentation, and puts one space between each operator and its branch expression. It keeps the
expressions and the file's line endings.

No fix is offered when comments or directives appear in the gaps around either operator.
Adjust those line breaks by hand while keeping the comments and directives.

## Configuration

There are no rule-specific options. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1140.severity = error
```

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

The four-character indent step is fixed. `indent_size` and `tab_width` do not change it;
each tab counts as one character.

[SST1145](SST1145.md) has separate placement settings:
`stylesharp.conditional_operator_placement` and
`stylesharp.SST1145.conditional_operator_placement`. They accept `leading` (default) or `trailing`,
with the rule-specific setting taking priority. These settings do not change this rule's requirement.

See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Disable this rule if your project uses trailing conditional operators or a continuation indent other than four characters.
