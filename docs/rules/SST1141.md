# SST1141 — Use tuple syntax

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `System.ValueTuple` type with two through seven type arguments is written as `ValueTuple<...>`
instead of `(T1, T2, ...)`. Tuple syntax expresses the same group of values with less text.

The rule requires C# 7 or later. It does not report `ValueTuple<T>`, the eight-argument form,
or unrelated types named `ValueTuple`. Tuples with more than seven elements can use tuple syntax,
but the rule does not report their outer eight-argument `ValueTuple` type.

## Example

Bad:

```csharp
using System;

public class Values
{
    public ValueTuple<int, string> Get() => (1, "one");
}
```

Corrected:

```csharp
using System;

public class Values
{
    public (int, string) Get() => (1, "one");
}
```

## How to fix violations

The code fix replaces the type with tuple syntax, removes any `System.` qualification on that type,
and also converts nested value-tuple type arguments. It keeps the element order and does not add
element names or remove `using System;`.

The replacement uses comma-space separators. Comments around type arguments or between them can
be lost, so move those comments outside the type before applying the fix.

## Configuration

There are no rule-specific options. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1141.severity = error
```

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when you need to keep the explicit framework type spelling, such as source shared with a project using C# 6. Projects set to C# 6 are already excluded.
