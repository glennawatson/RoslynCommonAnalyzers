# SST1142 — Refer to tuple elements by name

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

Code uses `Item1`, `Item2`, or another positional field to access a tuple element that has a name.
The name makes the value's purpose clearer.

The rule requires C# 7 or later. It leaves unnamed elements and ordinary objects with `ItemN`
members alone. It checks direct access such as `data.Item1`, not access through `?.`.

## Example

Bad:

```csharp
public class Values
{
    public int Count()
    {
        (int Count, int Total) data = (1, 2);
        return data.Item1;
    }
}
```

Corrected:

```csharp
public class Values
{
    public int Count()
    {
        (int Count, int Total) data = (1, 2);
        return data.Count;
    }
}
```

## How to fix violations

The code fix replaces only the positional member name with the available element name.
It keeps surrounding comments and whitespace, and leaves the tuple declaration unchanged.

Review uses inside `nameof`: changing `nameof(data.Item1)` to `nameof(data.Count)` changes
the resulting string from `"Item1"` to `"Count"`.

## Configuration

There are no rule-specific options. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1142.severity = error
```

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when positional access is intentional, such as code illustrating tuple positions or a `nameof` expression that must keep returning the positional name.
