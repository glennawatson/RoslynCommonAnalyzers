# SST1143 — Do not compare to a boolean literal

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A boolean expression is compared with `==` or `!=` to `true` or `false`.
For a plain `bool`, use the expression itself or negate it with `!`.
The literal can appear on either side of the comparison.

Comparisons between two literals or two non-literal values are not reported. Direct comparisons
of nullable variables, such as `bool? value` followed by `value == true`, are also left alone:
that comparison defines what happens when the value is `null`.

## Example

Bad:

```csharp
public class Checks
{
    public bool IsEnabled(bool enabled) => enabled == true;
    public bool IsNotReady(bool ready) => ready == false;
}
```

Corrected:

```csharp
public class Checks
{
    public bool IsEnabled(bool enabled) => enabled;
    public bool IsNotReady(bool ready) => !ready;
}
```

## How to fix violations

The code fix removes the comparison. It keeps the other expression for `== true` and `!= false`,
and adds `!` for `== false` and `!= true`. It adds parentheses when needed for negation;
`(a && b) == false` becomes `!(a && b)`.

Comments attached to the removed operator or literal can be lost. Move them outside the comparison
before applying the fix.

## Configuration

There are no rule-specific options. To treat violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1143.severity = error
```

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when explicit comparisons make a group of conditions easier to read. Also keep a
comparison when removing it changes how a nullable result or a custom operator behaves.
