# SST1144 — Combine case labels with an or-pattern

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled (opt-in) |

## Cause

Two or more `case` labels share the same switch body and can be joined with `or`.
This rule requires C# 9 or later. It skips a group that includes `default` or a
`when` condition.

The rule also skips a group if the combined label would exceed the line length
allowed by [SST1521](SST1521.md). Disabling that rule removes this length limit.

## Example

Bad, when the rule is enabled:

```csharp
public class Example
{
    public int Choose(int value)
    {
        switch (value)
        {
            case 1:
            case 2:
                return 0;
            default:
                return 1;
        }
    }
}
```

Good:

```csharp
public class Example
{
    public int Choose(int value)
    {
        switch (value)
        {
            case 1 or 2:
                return 0;
            default:
                return 1;
        }
    }
}
```

## Code fix

The fix joins the labels into one `case A or B:` label and keeps the shared body.
It can drop comments between labels or next to their patterns. Move those comments
above the first label before accepting the fix.

## Configuration

The rule is disabled by default. Enable it with:

```ini
[*.cs]
dotnet_diagnostic.SST1144.severity = warning
```

The line limit uses `stylesharp.SST1521.max_line_length`, then
`stylesharp.max_line_length`. Both accept positive integers; the first valid value
wins, with a default of 120 characters including indentation.

Set the severity to `none` to disable the rule. See [configuration](../CONFIGURATION.md)
for severity and file-specific settings.

## When to suppress

Leave the rule disabled if your team prefers stacked labels. Suppress an occurrence
when separate labels make comments about individual cases easier to read.
