# SST1145 — Place conditional operators consistently

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled; leading placement |

## Cause

A wrapped `condition ? whenTrue : whenFalse` expression puts `?` or `:` on the
wrong end of a line for the configured style. `leading` puts the operator before
its branch on the next line. `trailing` puts it at the end of the preceding line.
Single-line expressions are not reported.

[SST1140](SST1140.md) requires leading operators indented by four spaces. When it
reports an operator, this rule does not report that operator again. To use trailing
placement, disable that related rule as shown below.

## Example

Bad with `trailing` configured:

```csharp
public class Example
{
    public int Choose(bool condition) => condition
        ? 1
        : 2;
}
```

Good with `trailing` configured and the related indentation rule disabled:

```csharp
public class Example
{
    public int Choose(bool condition) => condition ?
        1 :
        2;
}
```

## How to fix violations

Move each operator to the configured end of its line, or keep a short expression
on one line. No automatic code fix is available for this rule.

## Configuration

The rule is enabled at warning severity. These are its default settings:

```ini
[*.cs]
dotnet_diagnostic.SST1145.severity = warning
stylesharp.conditional_operator_placement = leading
```

`stylesharp.SST1145.conditional_operator_placement` overrides the general key when
it is not empty. Both keys accept `leading` or `trailing`, ignoring letter case.
An unrecognized value uses `leading`.

To choose trailing placement:

```ini
[*.cs]
stylesharp.SST1145.conditional_operator_placement = trailing
dotnet_diagnostic.SST1140.severity = none
```

Set `dotnet_diagnostic.SST1145.severity = none` to disable this rule. See
[configuration](../CONFIGURATION.md) for severity and file-specific settings.

## When to suppress

Suppress this rule for a deliberately aligned expression whose layout is clearer
than either style. For a team-wide preference, configure the placement instead.
