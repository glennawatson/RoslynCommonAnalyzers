# SST1147 — Do not nest conditional operators

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | No |
| Default | Disabled (opt-in) |

## Cause

A `?:` expression appears directly inside the condition or either branch of
another `?:` expression. Adding parentheses around the inner expression does not
avoid the diagnostic. Separate conditional expressions and conditionals in switch
arms are not reported.

## Example

Bad, when the rule is enabled:

```csharp
public class Example
{
    public string Describe(int value) =>
        value == 0 ? "zero" : value > 0 ? "positive" : "negative";
}
```

Good:

```csharp
public class Example
{
    public string Describe(int value)
    {
        if (value == 0)
        {
            return "zero";
        }

        return value > 0 ? "positive" : "negative";
    }
}
```

## How to fix violations

Use an `if` statement to separate the decisions, as above. A switch expression
can also help when several branches test the same value. Keep each expression
evaluated only in the branch that needs it.

No automatic code fix is available.

## Configuration

The rule is disabled by default and has no rule-specific options. Enable it with:

```ini
[*.cs]
dotnet_diagnostic.SST1147.severity = warning
```

Set the severity to `none` to disable it. See [configuration](../CONFIGURATION.md)
for severity and file-specific settings.

## When to suppress

Leave the rule disabled if your team accepts short conditional chains. Suppress a
particular chain when splitting it would make a small decision harder to read.
