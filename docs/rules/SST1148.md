# SST1148 — Commented-out code should be removed

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled (opt-in) |

## Cause

A `//` comment looks like a C# statement. The text after `//`, excluding spaces
at its ends, must have at least four characters and either:

- End with `;`, `{`, or `}`.
- Start with `return `, `throw `, `var `, `if (`, `for (`, or `while (`.

The rule skips comments before the file's first code, `///` documentation, and
`/* ... */` comments. It also skips content starting with `TODO`, `HACK`, `http`,
`-`, `=`, or `*`. These prefixes are case-sensitive.

## Example

Bad, when the rule is enabled:

```csharp
public class Example
{
    public void Run()
    {
        // return;
        System.Console.WriteLine("a");
    }
}
```

Good:

```csharp
public class Example
{
    public void Run()
    {
        System.Console.WriteLine("a");
    }
}
```

## Code fix

The fix deletes the reported comment. If the comment is alone on its line, it
deletes the whole line, including the newline. If it follows code, it deletes the
comment and the spaces before it, keeping the code.

The fix does not distinguish prose from code. Check the comment before accepting
it; keep useful explanations and code examples.

## Configuration

The rule is disabled by default and has no rule-specific options. Enable it with:

```ini
[*.cs]
dotnet_diagnostic.SST1148.severity = warning
```

Set the severity to `none` to disable it. See [configuration](../CONFIGURATION.md)
for severity and file-specific settings.

## When to suppress

Suppress a useful code example or a prose comment that matches these shapes. For
example, an English sentence ending in a semicolon is reported. Reword the line
if that keeps its meaning clear; otherwise keep the comment and suppress the
occurrence. Remove abandoned code and use source control to recover it if needed.
