# SST1149 — Prefer the `is null` pattern for null checks

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A comparison uses `==` or `!=` with the literal `null` on exactly one side.
`null == value` is included. The rule reports `==` checks in C# 7 or later and
`!=` checks in C# 9 or later, when the suggested patterns are available.

Checks inside lambdas assigned to `Expression<TDelegate>` are excluded. Those
lambdas store code for another API to inspect, and they cannot contain these
patterns.

## Example

Bad:

```csharp
public class Example
{
    public bool IsMissing(object value) => value == null;

    public bool HasValue(object value) => value != null;
}
```

Good, in C# 9 or later:

```csharp
public class Example
{
    public bool IsMissing(object value) => value is null;

    public bool HasValue(object value) => value is not null;
}
```

## Code fix

The fix replaces `== null` with `is null` and `!= null` with `is not null`. It puts
the value first when `null` was on the left, and adds parentheses around complex
values when needed. Comments beside the old operator or `null` can be lost; move
them outside the comparison before accepting the fix.

The pattern checks for null without calling a custom `==` or `!=` operator.
The rule also reports types with those operators, so applying the fix can change
their behavior.

## Configuration

The rule is enabled at warning severity and has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1149.severity = warning
```

Set the severity to `none` to disable it. See [configuration](../CONFIGURATION.md)
for severity and file-specific settings.

## When to suppress

Suppress a comparison that must call a type's custom equality operator. Keep the
comparison if that operator treats a value as null in a way the pattern does not.
