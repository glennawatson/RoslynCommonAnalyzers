# SST1153 — Indexer declaration parameters should be on unique lines

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An indexer declaration with at least two parameters mixes shared and separate
lines. Keep all parameters on the opening `[` line, or start every parameter on
its own line after `[`. A wrapped list is reported even when only the first
parameter shares the opening line.

Indexers with one parameter are not reported. The rule checks where each parameter
starts; it does not require a long parameter to fit on one line.

## Example

Bad:

```csharp
public class Example
{
    public int this[
        int row, int column] => default;
}
```

Good:

```csharp
public class Example
{
    public int this[
        int row,
        int column] => default;
}
```

## Code fix

The fix starts every parameter on a separate line after `[`, indents the list
by four spaces, and puts `]` after the last parameter. It follows the file's
newline style. It can discard comments before parameters, around commas, or beside
the opening and closing brackets. Move those comments before accepting the fix,
or adjust the line breaks by hand. Keeping a short list on the opening line also
satisfies the rule.

## Configuration

The rule is enabled at warning severity and has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1153.severity = warning
```

Set the severity to `none` to disable it. See [configuration](../CONFIGURATION.md)
for severity and file-specific settings.

## When to suppress

Suppress this rule when keeping coordinate pairs together on a line makes an
indexer easier to understand.
Use a file-specific severity setting when the whole file follows that layout.
