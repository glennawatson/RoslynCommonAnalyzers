# SST1160 - Record primary-constructor parameters should be on unique lines

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

The parameters declared after a record's name mix shared lines with separate lines. This applies to both record classes and record structs.

For two or more parameters, start them all on the line with `(`, or
start each on a separate line below it. A mix of these layouts is reported.
The rule checks where each parameter starts, not where it ends or where
the closing `)` appears. Lists with zero or one parameter and generated
code are ignored.

Record classes require C# 9 or later; record structs require C# 10 or later. Records without a parameter list are ignored.

## Example

Before:

```csharp
public record Point(
    int X, int Y);
```

After:

```csharp
public record Point(
    int X,
    int Y);
```

## How to fix violations

Put each parameter on a separate line after `(`, as shown above.
You can also keep all parameters on the line with `(` if the list is short.

## Code fix

The code fix adds a line break after `(` and puts each parameter on its
own line. It indents the entries four spaces beyond the line where the
record declaration starts and keeps the file's line endings. Fix All is supported.

Comments after `(` or commas, before parameters, or beside `)` can be
removed by the fix. Check the preview when the list contains comments, or
change the line breaks by hand to keep them.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default;
this repository sets its severity to `error`. To use the default severity:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1160.severity = warning
```

Supported severities are `none`, `silent`, `suggestion`, `warning`, and `error`;
`default` restores the warning default. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress for files whose layout is controlled by an external formatter, or when
grouping related parameters on one line is clearer. Set the severity to `none`
in a file-specific `.editorconfig` section to limit the exception.
