# SST1164 - Constructor initializer arguments should be on unique lines

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A constructor's `this(...)` or `base(...)` call mixes arguments on shared lines with arguments on separate lines.

For two or more arguments, start them all on the line with `(`, or
start each on a separate line below it. A mix of these layouts is reported.
The rule checks where each argument starts, not where it ends or where
the closing `)` appears. Lists with zero or one argument and generated
code are ignored.

## Example

Before:

```csharp
public class Base
{
    public Base(int a, int b) { }
}

public class Item : Base
{
    public Item()
        : base(
            1, 2)
    {
    }
}
```

After:

```csharp
public class Base
{
    public Base(int a, int b) { }
}

public class Item : Base
{
    public Item()
        : base(
            1,
            2)
    {
    }
}
```

## How to fix violations

Put each argument on a separate line after `(`, as shown above.
You can also keep all arguments on the line with `(` if the list is short.

## Code fix

The code fix adds a line break after `(` and puts each argument on its
own line. It indents the entries four spaces beyond the line where the
constructor's `this` or `base` call starts and keeps the file's line endings. Fix All is supported.

Comments after `(` or commas, before arguments, or beside `)` can be
removed by the fix. Check the preview when the list contains comments, or
change the line breaks by hand to keep them.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default;
this repository sets its severity to `error`. To use the default severity:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1164.severity = warning
```

Supported severities are `none`, `silent`, `suggestion`, `warning`, and `error`;
`default` restores the warning default. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress for files whose layout is controlled by an external formatter, or when
grouping related constructor arguments on one line is clearer. Set the severity to `none`
in a file-specific `.editorconfig` section to limit the exception.
