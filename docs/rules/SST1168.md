# SST1168 - Conversion operator parameters should be on unique lines

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Not offered for valid conversion operators |
| Default | Enabled |

## Cause

This rule reports nothing in valid C#. A conversion operator must have exactly one
parameter, and lists with one parameter are not checked.

## Example

There is no valid C# example that triggers the diagnostic. Both layouts below are
accepted; neither needs a correction.

```csharp
public class Source
{
    public static implicit operator int(Source value) => 0;

    public static explicit operator long(
        Source value) => 0;
}
```

## Code fix

A code fix exists to split multiple parameters onto separate lines, but it is not
offered for valid conversion operators. It leaves a single parameter unchanged.

## Configuration

The rule is enabled by default with warning severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1168.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` and
`default`. Use `none` to disable the rule or `default` to use its declared
default. See [Configuration](../CONFIGURATION.md) for settings that apply to specific files.

## When to suppress

No suppression is needed for valid conversion operators, regardless of their line breaks.
