# SST1169 - Type parameters should be on unique lines

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A generic declaration mixes shared lines and line breaks between `<` and the
start of each type parameter. This applies to generic types, methods and delegates.

Keep `<` and all type parameters on one line, or start every type parameter on a
separate line after `<`. A list with one type parameter is not reported. Moving
only the closing `>` to another line does not trigger the rule.

## Example

Reported:

```csharp
public class Pair<
    TKey, TValue>
{
}
```

Corrected:

```csharp
public class Pair<
    TKey,
    TValue>
{
}
```

## Code fix

The fix puts a line break after `<` and each comma, then indents each type parameter
four spaces beyond the line containing `<`. It preserves line breaks before `>`.
Comments after `<`, around commas, or immediately before a type parameter can be
lost. Move those comments before accepting the fix.

## Configuration

The rule is enabled by default with warning severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1169.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` and
`default`. Use `none` to disable the rule or `default` to use its declared
default. See [Configuration](../CONFIGURATION.md) for settings that apply to specific files.

## When to suppress

Disable the rule for files that must follow an external formatting convention or when your team prefers mixed wrapping.
