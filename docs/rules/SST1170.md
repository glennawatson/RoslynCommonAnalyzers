# SST1170 - Type arguments should be on unique lines

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A generic type or method use mixes shared lines and line breaks between `<` and
the start of each type argument.

Keep `<` and all type arguments on one line, or start every type argument on a
separate line after `<`. A list with one type argument is not reported. Moving
only the closing `>` to another line does not trigger the rule.

## Example

Reported:

```csharp
using System.Collections.Generic;

public class Lookup
{
    public readonly Dictionary<
        int, string> Values = new();
}
```

Corrected:

```csharp
using System.Collections.Generic;

public class Lookup
{
    public readonly Dictionary<
        int,
        string> Values = new();
}
```

## Code fix

The fix puts a line break after `<` and each comma, then indents each type argument
four spaces beyond the line containing `<`. It preserves line breaks before `>`.
Comments after `<`, around commas, or immediately before a type argument can be
lost. Move those comments before accepting the fix.

## Configuration

The rule is enabled by default with warning severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1170.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` and
`default`. Use `none` to disable the rule or `default` to use its declared
default. See [Configuration](../CONFIGURATION.md) for settings that apply to specific files.

## When to suppress

Disable the rule for files that must follow an external formatting convention or when your team prefers mixed wrapping.
