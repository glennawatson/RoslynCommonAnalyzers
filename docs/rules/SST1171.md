# SST1171 - Function pointer parameters should be on unique lines

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A function pointer declaration mixes shared lines and line breaks between `<` and
the start of each entry. The last entry is the return type and is checked too.

Keep `<` and all entries on one line, or start every entry on a separate line after
`<`. A pointer with only a return type, such as `delegate*<void>`, is not reported.
Moving only the closing `>` to another line does not trigger the rule.

Function pointers require C# 9 or later and unsafe code enabled in the project.

## Example

Reported:

```csharp
public unsafe class Callbacks
{
    public delegate*<
        int, string, void> Callback;
}
```

Corrected:

```csharp
public unsafe class Callbacks
{
    public delegate*<
        int,
        string,
        void> Callback;
}
```

## Code fix

The fix puts a line break after `<` and each comma, then indents every entry,
including the return type, four spaces beyond the line containing `<`. It preserves
line breaks before `>`. Comments after `<`, around commas, or immediately
before an entry can be lost. Move those comments before accepting the fix.

## Configuration

The rule is enabled by default with warning severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1171.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` and
`default`. Use `none` to disable the rule or `default` to use its declared
default. See [Configuration](../CONFIGURATION.md) for settings that apply to specific files.

## When to suppress

Disable the rule for interop declarations that must follow an external formatting convention or when your team prefers mixed wrapping.
