# SST1172 - Negated comparisons should use the opposite operator

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A comparison using `==`, `!=`, `<`, `<=`, `>` or `>=` is wrapped in `!`.
Writing the opposite operator removes the extra negation.

Negated `==` and `!=` comparisons are reported regardless of the types compared. For `<`,
`<=`, `>` and `>=`, the rule skips nullable values, `float`, `double`, `Half`,
`NFloat` and expressions using `?.`. For these comparisons, `null` or `NaN`
(not a number) can make the two forms give different results.

Plain negation, such as `!ready`, and negated logical expressions, such as
`!(ready && enabled)`, are not reported.

## Example

Reported:

```csharp
public class Checks
{
    public bool Different(int a, int b) => !(a == b);

    public bool AtLeast(int count, int limit) => !(count < limit);
}
```

Corrected:

```csharp
public class Checks
{
    public bool Different(int a, int b) => a != b;

    public bool AtLeast(int count, int limit) => count >= limit;
}
```

## How to fix violations

The code fix removes `!` and the parentheses around the comparison. It swaps `==`
with `!=`, `<` with `>=`, and `<=` with `>`, in either direction, and adds spaces
around the operator. Comments inside the removed parentheses or beside the
operator can be lost; move them before accepting the fix.

## Configuration

The rule is enabled by default with warning severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1172.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` and
`default`. Use `none` to disable the rule or `default` to use its declared
default. See [Configuration](../CONFIGURATION.md) for settings that apply to specific files.

## When to suppress

Suppress when the negated form matches a formula your readers need to compare with the code. Also suppress when a type defines comparison operators whose results are not opposites; the rule does not exclude custom operators.
