# SST1173 - Redundant anonymous-type member names should be omitted

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An anonymous object repeats a name C# can infer from the value, such as
`new { count = count }` or `new { X = point.X }`. The explicit and inferred names
must match exactly, including case.

A different name, such as `new { Renamed = point.X }`, is not reported. Neither is
a named calculation, such as `new { Sum = a + b }`, which needs an explicit name.

## Example

Reported:

```csharp
public class Results
{
    public object Create(int count) => new { count = count };
}
```

Corrected:

```csharp
public class Results
{
    public object Create(int count) => new { count };
}
```

## How to fix violations

The code fix removes the `Name =` prefix. The member keeps the same name, type and
value. Comments within the removed prefix or between `=` and the value can be
lost; move them before accepting the fix.

## Configuration

The rule is enabled by default with warning severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1173.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` and
`default`. Use `none` to disable the rule or `default` to use its declared
default. See [Configuration](../CONFIGURATION.md) for settings that apply to specific files.

## When to suppress

Suppress when keeping every member name explicit makes a large anonymous object easier to compare with an external data format.
