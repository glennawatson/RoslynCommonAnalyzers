# SST1175 - Unnecessary casts should be removed

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A cast or `as` expression names the type the value already has. The rule also
reports `System.Linq.Enumerable.Cast<T>()` when the source already contains
elements of type `T`, and `OfType<T>()` when those elements have the same type and
cannot be null.

Casts to a different type are not reported. Casts that change whether a value or
generic type argument permits null are left alone, as are casts of `default` and
`default(T)`. `OfType<T>()` on reference types or nullable value types is left
alone because it can remove null elements.

## Example

Reported:

```csharp
using System.Collections.Generic;
using System.Linq;

public class Values
{
    public int Copy(int value) => (int)value;

    public string Text(string value) => value as string;

    public IEnumerable<int> Numbers(IEnumerable<int> values) => values.Cast<int>();

    public IEnumerable<int> Filter(IEnumerable<int> values) => values.OfType<int>();
}
```

Corrected:

```csharp
using System.Collections.Generic;

public class Values
{
    public int Copy(int value) => value;

    public string Text(string value) => value;

    public IEnumerable<int> Numbers(IEnumerable<int> values) => values;

    public IEnumerable<int> Filter(IEnumerable<int> values) => values;
}
```

## How to fix violations

The code fix replaces a cast or `as` expression with its value. For extension
calls such as `values.Cast<int>()`, it replaces the call with `values`. It leaves
using directives in place. Comments within the removed conversion can be lost.

For a static call such as `Enumerable.Cast<int>(values)`, replace the whole call
with `values` manually. The offered code fix keeps `Enumerable` instead, which
does not compile as a value.

Removing a sequence call can also change the type inferred by `var`. For example,
an array followed by `Cast<int>()` becomes an array directly, rather than an
`IEnumerable<int>`. Write the intended variable type explicitly if later code
depends on it.

## Configuration

The rule is enabled by default with warning severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1175.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` and
`default`. Use `none` to disable the rule or `default` to use its declared
default. See [Configuration](../CONFIGURATION.md) for settings that apply to specific files.

## When to suppress

Suppress when an explicit cast documents a type that is otherwise hard to see. Keep a sequence call if it must throw an exception when the source is null; replacing the call with the source removes that check.
