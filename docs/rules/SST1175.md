# SST1175 — Unnecessary casts should be removed

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |
| Analyzer | `ExpressionSimplificationAnalyzer` |

## Cause

A cast targets the type the operand already has, so the cast does nothing.

```csharp
// 👎 reported
int a = (int)anInt;
object o = (object)alreadyObject;

// 👍
int a = anInt;
object o = alreadyObject;
```

## Rule description

When the cast's target type matches the operand's own type, the conversion is an identity
cast that only adds noise. Because the types are equal (not merely related), removing the
cast cannot change overload resolution or binding.

The operand's type is the one it already has, so a cast is reported wherever that type is
written again — including where the type arrives through generic substitution, which is
the shape that hides best:

```csharp
// 👎 reported — ReplaceNodes<TRoot> already returns the receiver's type
var rewritten = (CompilationUnitSyntax)unit.ReplaceNodes(nodes, rewrite);
```

A cast that narrows the null-state is kept, because asserting the value is not null is the
reason to write it. Only the annotated form is redundant:

```csharp
string s = (string)maybeNull;    // 👍 kept — asserts not-null
string? t = (string?)maybeNull;  // 👎 reported — the operand is already 'string?'
```

`default` and `default(T)` operands are never reported, having no independent type. The
semantic model is consulted only after the cheap syntactic match on a `CastExpression`.

The `as` and `Cast<T>()`/`OfType<T>()` variants are out of scope for this implementation.

## How to fix violations

Delete the cast, keeping the operand. The provided code fix does this automatically.
