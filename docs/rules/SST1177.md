# SST1177 - Redundant base types should be removed

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A class or record class explicitly derives from `object`, or an enum explicitly
uses `int` as its underlying type. These are the defaults when the type is omitted.
The rule also recognizes `System.Object`, `System.Int32` and aliases for them.

Other base classes and enum underlying types are not reported. Redundant interface
entries are covered by [SST1490](SST1490.md).

## Example

Reported:

```csharp
public class Item : object
{
}

public enum State : int
{
    Ready
}
```

Corrected:

```csharp
public class Item
{
}

public enum State
{
    Ready
}
```

## How to fix violations

The code fix removes the redundant type. It keeps any listed interfaces. If the
removed type was the only entry, it removes the colon too. Comments within the
removed entry can be lost; move them before accepting the fix.

## Configuration

The rule is enabled by default with warning severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1177.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` and
`default`. Use `none` to disable the rule or `default` to use its declared
default. See [Configuration](../CONFIGURATION.md) for settings that apply to specific files.

## When to suppress

Suppress when an explicit enum underlying type documents a storage or interop contract. Removing `: int` does not change that type or its size.
