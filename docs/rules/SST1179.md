# SST1179 - Redundant default switch sections should be removed

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `switch` has a section with only the `default:` label and one statement,
`break;`. Without that section, unmatched values still continue after the switch.

A section that contains other statements or shares `default:` with a `case`
label is not reported. Switches over enums are also left alone: their `default:`
can document deliberately unhandled values and prevent a diagnostic about missing
enum cases from [SST2242](SST2242.md).

## Example

Reported:

```csharp
public class Handler
{
    public void Handle(int value)
    {
        switch (value)
        {
            case 1:
                return;
            default:
                break;
        }
    }
}
```

Corrected:

```csharp
public class Handler
{
    public void Handle(int value)
    {
        switch (value)
        {
            case 1:
                return;
        }
    }
}
```

## How to fix violations

The code fix deletes the whole `default:` section. Comments in or directly above
that section can be lost. Directives needed to match a `#region` or `#if` outside
the section are kept, so an empty region can remain. Move useful comments before
accepting the fix.

## Configuration

The rule is enabled by default with warning severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1179.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none` and
`default`. Use `none` to disable the rule or `default` to use its declared
default. See [Configuration](../CONFIGURATION.md) for settings that apply to specific files.

## When to suppress

Suppress when an explicit `default: break;` documents that all other values are intentionally ignored, or when your coding convention requires a default section.
