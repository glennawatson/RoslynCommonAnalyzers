# SST1181 — Redundant overriding members should be removed

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An override only calls the base method of the same name, passing every parameter unchanged and in order. Any `ref`, `out`, or `in` keyword must also match. A property is reported when each getter, setter, or `init` accessor only forwards to the same base property. Both block bodies and `=>` bodies are covered.

Members with attributes on the declaration, `sealed override` members, and generic methods are not reported. Overrides that add work or change the arguments are not reported.

## Example

Bad:

```csharp
public class Calculator
{
    public virtual int Add(int x, int y) => x + y;
}

public class DerivedCalculator : Calculator
{
    public override int Add(int x, int y) => base.Add(x, y);
}
```

Good:

```csharp
public class Calculator
{
    public virtual int Add(int x, int y) => x + y;
}

public class DerivedCalculator : Calculator
{
}
```

## Code fix

The fix deletes the entire overriding method or property. Calls then use the inherited member. Comments and XML documentation attached to the deleted member are removed too.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1181.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when callers need the override's parameter names or default argument values, or when a framework requires the member to be declared on the derived class. Also keep an override with a required attribute on an accessor: only attributes on the member declaration exclude it from this rule.
