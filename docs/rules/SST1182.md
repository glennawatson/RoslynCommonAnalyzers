# SST1182 — Conditional expressions should not return only boolean literals

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A conditional expression returns `true` and `false`, in either order. For a `bool` condition, `condition ? true : false` repeats the condition, and `condition ? false : true` reverses it. Branches with the same value, such as `condition ? true : true`, are not reported. Neither are branches that return variables or method calls.

## Example

Bad:

```csharp
public class Example
{
    public bool IsPositive(int value) => value > 0 ? true : false;

    public bool IsNotReady(bool ready) => ready ? false : true;
}
```

Good:

```csharp
public class Example
{
    public bool IsPositive(int value) => value > 0;

    public bool IsNotReady(bool ready) => !ready;
}
```

## Code fix

The fix replaces the conditional expression with its condition. For `? false : true`, it adds `!` and parentheses where needed, or removes an existing leading `!`. Comments on the removed branches are lost.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1182.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the condition uses a custom type whose operators make the conditional expression necessary to produce a `bool`. For an ordinary `bool` condition, use the shorter expression.
