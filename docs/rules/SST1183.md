# SST1183 — Interpolated strings without interpolations should be plain strings

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A string with a `$` prefix has no `{expression}` that inserts a value. This includes empty strings and text with escaped braces (`{{` and `}}`). Strings that insert at least one value are not reported.

## Example

Bad:

```csharp
public class Example
{
    public string Greeting() => $"hello";
}
```

Good:

```csharp
public class Example
{
    public string Greeting() => "hello";
}
```

## Code fix

The fix replaces the whole expression with a regular quoted string. Verbatim and raw interpolated strings also become regular strings, with characters such as backslashes and line breaks escaped.

Escaped braces need a manual correction: the fix turns `$"{{value}}"` into `"{{value}}"`, which changes the text. Use `"{value}"` to keep the original value.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1183.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an API needs the interpolated form, such as a parameter of type `FormattableString` or a custom interpolated string handler. A plain string can select a different method overload or fail to compile in those cases.
