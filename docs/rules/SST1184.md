# SST1184 — Verbatim string literals without escapes should be regular strings

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A verbatim string (`@"..."`) contains no backslash, quote, newline, or carriage return. The `@` prefix is unnecessary for that text.

Strings such as `@"C:\temp"` keep their verbatim form. Regular strings, raw strings, and UTF-8 string literals are not reported.

## Example

Bad:

```csharp
public class Example
{
    public string Greeting() => @"hello";
}
```

Good:

```csharp
public class Example
{
    public string Greeting() => "hello";
}
```

## Code fix

The fix replaces the verbatim string with a regular quoted string holding the same text. It preserves surrounding comments and spacing. A literal tab is written as `\t`.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1184.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when keeping the same quoting style across a set of paths or regular expressions makes that set easier to maintain.
