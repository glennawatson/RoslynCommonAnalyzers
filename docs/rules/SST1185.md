# SST1185 — Use a compound assignment operator

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An assignment repeats its target as the left operand of an operation, such as `count = count + 1`. Use the combined operator, such as `+=`, to avoid repeating the target.

The supported operators are `+`, `-`, `*`, `/`, `%`, `&`, `|`, `^`, `<<`, and `>>`. The target and repeated operand must be written the same way. Targets can be names or member accesses such as `this.Count` or `item.Count`.

Targets containing method calls or indexers are not reported. Assignments in object or `with` initializers are also excluded: a compound assignment is not allowed there.

## Example

Bad:

```csharp
public class Example
{
    public void Update(int count)
    {
        count = count + 1;
    }
}
```

Good:

```csharp
public class Example
{
    public void Update(int count)
    {
        count += 1;
    }
}
```

## Code fix

The fix changes `count = count + 1` to `count += 1`, using the corresponding combined operator for each supported operation. It keeps the spacing around `=`. Comments on the removed operand or operator, and comments immediately before the remaining right operand, are lost.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1185.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the expanded expression needs to match a documented formula. Also suppress if evaluating a property in the target twice is intentional: the combined assignment evaluates its target once, and the rule does not check what property getters do.
