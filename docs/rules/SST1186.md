# SST1186 — A literal should be on the right side of a comparison

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `==` or `!=` comparison has a literal, such as `0` or `"ready"`, on the left and an expression on the right. Put the value being checked first.

The rule does not report `<`, `<=`, `>`, or `>=` comparisons. It also skips a left-hand `null`, two non-null literals, and comparisons between two variables. For null checks, see [SST1149](SST1149.md).

## Example

Bad:

```csharp
public class Example
{
    public bool IsEmpty(int count) => 0 == count;
}
```

Good:

```csharp
public class Example
{
    public bool IsEmpty(int count) => count == 0;
}
```

## Code fix

The fix swaps the operands and keeps `==` or `!=` unchanged. Spacing and comments around the operands stay in their original positions, so check any comment that refers to one operand.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1186.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a custom type defines comparison operators whose meaning depends on operand order. Swapping the operands must keep the same result and still compile.
