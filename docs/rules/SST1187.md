# SST1187 — Assignments should not be chained

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A simple `=` assignment directly uses another simple assignment as its value, as in `a = b = c`. This hides a write inside another write. Parenthesized inner assignments and compound assignments such as `+=` are not reported by this rule.

## Example

Bad:

```csharp
public class Example
{
    public void Update(int a, int b, int c)
    {
        a = b = c;
    }
}
```

Good:

```csharp
public class Example
{
    public void Update(int a, int b, int c)
    {
        b = c;
        a = b;
    }
}
```

## How to fix violations

Write separate assignments. For local variables, assign the rightmost value first, as shown above. If a target is a property or indexer, preserve the order of calls and the assigned value; reading the target back can run extra code. Use a temporary variable where needed.

There is no automatic code fix.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1187.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress for a short, deliberate reset of several local variables when the shared value is clearer as a chain and the assignments have no other effects.
