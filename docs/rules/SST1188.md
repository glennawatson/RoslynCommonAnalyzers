# SST1188 — Use the 'default' literal instead of 'default(T)'

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `default(T)` expression repeats a type that the surrounding code already supplies. The rule covers return values, `=>` bodies, assignment values, and initializers with an explicit type. It reports only when that type matches `T`, including whether the type allows null.

`var x = default(int)` is not reported because `var` needs the explicit type. Neither is `object x = default(int)`: replacing it with `default` would change zero to null. Method arguments and member access such as `default(int).ToString()` are not reported.

This rule applies only in C# 7.1 or later, where the `default` literal is available.

## Example

Bad:

```csharp
public class Example
{
    public int Count() => default(int);
}
```

Good:

```csharp
public class Example
{
    public int Count() => default;
}
```

## Code fix

The fix replaces the whole `default(T)` expression with `default`. Surrounding comments remain, but comments inside the removed parentheses are lost.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1188.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the source is also compiled by a project using C# 7.0 or earlier, or when showing the type at that location is important for understanding the code.
