# SST1189 — Variables should not be self-assigned

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Standalone statements only |
| Default | Enabled |

## Cause

An assignment copies a variable or member onto itself. This often means the wrong source or target was typed. The rule covers matching names and member accesses, including `this._value = _value` when both sides are the field. It does not report that spelling when `_value` on the right is a parameter.

Tuple assignments are checked one element at a time: in `(x, y) = (x, z)`, only `x` is reported. Targets involving a method call or indexer are excluded. Assignments in object and `with` initializers are also excluded because matching names can refer to different objects.

## Example

Bad:

```csharp
public class Example
{
    private int _value;

    public void Reset()
    {
        _value = 5;
        _value = _value;
    }
}
```

Good:

```csharp
public class Example
{
    private int _value;

    public void Reset()
    {
        _value = 5;
    }
}
```

## Code fix

The fix deletes a self-assignment that forms a whole statement, including comments attached to that statement. It does not fix tuple elements, `=>` bodies, or assignments used inside larger expressions.

If the assignment should copy a different value, correct the source or target by hand instead of deleting it.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1189.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when assigning a property to itself intentionally runs its setter, such as to raise a change notification. The rule also reports properties and does not check what their getters or setters do.
