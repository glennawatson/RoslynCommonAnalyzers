# SST1190 — Doubled negation operators should be removed

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

The same `!` or `~` operator is applied at least twice in a row. For a `bool`, `!` reverses true and false, so `!!flag` returns `flag`. For a built-in integer type, `~` flips each bit and applying it twice restores the value.

The rule also covers longer runs and operators separated by parentheses. A single operator or a pair of different operators is not reported.

## Example

Bad:

```csharp
public class Example
{
    public bool IsReady(bool flag) => !!flag;

    public bool IsNotReady(bool flag) => !!!flag;
}
```

Good:

```csharp
public class Example
{
    public bool IsReady(bool flag) => flag;

    public bool IsNotReady(bool flag) => !flag;
}
```

## Code fix

The fix removes pairs of matching operators. An even count leaves the operand; an odd count leaves one operator. It also removes parentheses around that operand and comments attached to the removed parts. Check the result when the operand is a larger expression, since those parentheses can affect the order of operations.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1190.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a custom type defines `!` or `~` so that applying it twice has a required effect. Also keep an expression when the integer conversion caused by `~` is needed: for example, `~~value` produces an `int` when `value` is a `byte`.
