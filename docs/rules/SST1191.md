# SST1191 — Long numeric literals should use digit separators

| Item | Value |
| --- | --- |
| Category | Readability |
| Default severity | Warning |
| Code fix | No |
| Default | Disabled (opt-in) |

## Cause

When enabled, the rule reports a base-10 integer literal with at least five digits and no `_` separators. Integer suffixes such as `L`, `U`, or `UL` are allowed and do not count as digits.

Literals starting with `0`, hexadecimal and binary literals, floating-point literals, and numbers that already contain `_` are not reported. The five-digit threshold is fixed.

## Example

Bad when the rule is enabled:

```csharp
public class Limits
{
    public const int Maximum = 1000000;
}
```

Good:

```csharp
public class Limits
{
    public const int Maximum = 1_000_000;
}
```

## How to fix violations

Add `_` between digit groups without changing the digits. Groups of three are conventional for base-10 numbers. Digit separators require C# 7.0 or later.

There is no automatic code fix.

## Configuration

The rule is disabled by default. Enable it at warning severity with:

```ini
[*.cs]
dotnet_diagnostic.SST1191.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no rule-specific options for the threshold or group size. See [Configuration](../CONFIGURATION.md).

If [SST1119](SST1119.md) is enabled, it checks the grouping after separators are added and expects groups of three for base-10 integers.

## When to suppress

Leave the rule disabled if digit grouping does not suit the project. Suppress a specific value when its digits must match a published identifier or specification, or when the source must compile with a C# version earlier than 7.0.
