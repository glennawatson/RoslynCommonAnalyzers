# SST1192 — Control characters in string literals should be escaped

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | No |
| Default | Disabled (opt-in) |

## Cause

A regular string literal contains an unescaped control character, such as a tab. The rule checks
characters below `U+0020`. These characters are hard to see and easy to change by accident.

Verbatim strings (`@"..."`), raw strings, and interpolated strings are not reported.

## Example

Reported when the rule is enabled. There is an actual tab between `a` and `b`:

```csharp
public class C
{
    public const string Row = "a	b";
}
```

Corrected, with the same string value:

```csharp
public class C
{
    public const string Row = "a\tb";
}
```

## How to fix violations

Replace the control character with an escape such as `\t` for a tab or `\u0001` for a character
without a short escape. There is no code fix.

## Configuration

The rule is disabled by default. Enable it as an error with:

```ini
[*.cs]
dotnet_diagnostic.SST1192.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`; `none` disables the rule.
There are no other options.

## When to suppress

Suppress a case when the source must contain the literal control character, such as a test fixture
that checks source text. An escape is clearer when only the resulting string value matters.
