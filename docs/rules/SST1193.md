# SST1193 - Keep initial member values with construction

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |
| Analyzer | `LanguageStyleAnalyzer` |

## Cause

A local object is created and then immediately has one of its members assigned.

```csharp
var person = new Person();
person.Name = "Ada";
```

## Rule description

Object initialization reads better when construction and initial member values are kept together.
This rule reports only the simple local pattern where an empty object creation is followed
immediately by a field or property assignment on that same local.

## What is not reported

An assignment whose value reads the local being declared, directly or from inside a lambda:

```csharp
var handle = new SerialHandle();
handle.Current = new Watcher(handle);   // the watcher is handed the handle it later replaces
```

An initializer runs before its own local exists, so naming the local inside one is
`CS0841: Cannot use local variable 'handle' before it is declared`. Keeping the two statements
apart is the only shape that compiles, so it is not reported.

## How to fix violations

Move the first assignment into the initializer. The provided code fix performs that rewrite for the
first immediate member assignment.
