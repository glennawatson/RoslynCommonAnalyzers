# SST1193 — Keep initial member values with construction

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A local variable is created with `new Type()`, and the next statement assigns one of its fields or
properties. Put the initial value beside the construction so the setup is easier to read.

The declaration must be inside a block and declare one variable. Construction with arguments,
an existing initializer, or `new()` without a type name is not reported. An assigned value that
mentions the new variable, including inside a lambda, is also excluded: an initializer cannot use
the variable it is still creating.

## Example

Reported:

```csharp
public class Person
{
    public string Name { get; set; } = "";

    public static Person Create()
    {
        var person = new Person();
        person.Name = "Ada";
        return person;
    }
}
```

Corrected:

```csharp
public class Person
{
    public string Name { get; set; } = "";

    public static Person Create()
    {
        var person = new Person() { Name = "Ada" };
        return person;
    }
}
```

## How to fix violations

The code fix moves only the first assignment into an object initializer and removes that assignment
statement. Later assignments stay where they are. Comments attached to the removed statement can
be lost; move them by hand before accepting the fix.

## Configuration

The default is an enabled warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1193.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`; `none` disables the rule.
There are no other options.

## When to suppress

Suppress when separate setup statements make a long initialization sequence easier to read or
provide useful places for breakpoints.
