# SST1194 — Keep initial collection values with construction

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes, for one-argument Add calls |
| Default | Enabled |

## Cause

A local collection is created with `new Type()`, and the next statement calls its `Add` method
with one or more arguments. The collection must implement `System.Collections.IEnumerable`.
Keep its initial contents beside its construction.

The declaration must be inside a block and declare one variable. Construction with arguments,
an existing initializer, or `new()` without a type name is not reported. An `Add` argument that
mentions the new variable is also excluded: an initializer cannot use the variable it is creating.

## Example

Reported:

```csharp
using System.Collections.Generic;

public class C
{
    public List<int> Create()
    {
        var values = new List<int>();
        values.Add(1);
        return values;
    }
}
```

Corrected:

```csharp
using System.Collections.Generic;

public class C
{
    public List<int> Create()
    {
        var values = new List<int>() { 1 };
        return values;
    }
}
```

## How to fix violations

The code fix moves the first `Add` argument into a collection initializer and removes that call.
Later calls stay where they are. It is offered only for an `Add` call with one argument; calls with
several arguments need a manual edit. Comments attached to the removed call can be lost; move
them by hand before accepting the fix.

## Configuration

The default is an enabled warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1194.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`; `none` disables the rule.
There are no other options.

## When to suppress

Suppress when separate `Add` calls make a long setup sequence easier to read or debug.
