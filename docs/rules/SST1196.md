# SST1196 — Write null-guarded access with ?.

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `?:` expression compares a local variable or parameter with `null`, returns null when it is null,
and reads a member from that same variable otherwise. Both `== null` and `!= null` forms are
reported, including comparisons with `null` on the left.

The value being checked must be a local variable or parameter. A field, property, or method call
in that position is excluded. The non-null branch must be a direct member read, such as
`person.Name`; method calls, indexers, and longer access chains are not reported. Checks using
`is null` are also excluded.

## Example

Reported:

```csharp
public class Person
{
    public string Name { get; set; } = "";

    public static string ReadName(Person person)
        => person == null ? null : person.Name;
}
```

Corrected:

```csharp
public class Person
{
    public string Name { get; set; } = "";

    public static string ReadName(Person person)
        => person?.Name;
}
```

`?.` reads the member only when the value on its left is not null. Otherwise, it returns null.

## Code fix

The code fix replaces the whole `?:` expression with `person?.Name`. The checked variable and the
variable before the member name must be written the same way; different parentheses can prevent
the fix from being offered. Comments in the removed null check can be lost.

## Configuration

The default is an enabled warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1196.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`; `none` disables the rule.
There are no other options.

## When to suppress

Suppress inside an expression tree, such as a lambda assigned to `Expression<Func<Person, string>>`,
because C# does not allow `?.` there. Also suppress if the type's custom `==` or `!=` behavior must
be preserved.
