# SST1197 — Collapse return-only branch into one return

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes, for a following return statement |
| Default | Enabled |

## Cause

An `if` without an `else` returns one value, and the next statement returns another. The `if` must
be inside a block. Each return can stand alone or be the only statement in its own block.

The rule skips cases where the condition or either returned value contains another `?:` expression.
It also skips cases where exactly one returned value is the literal `true` or `false`.

## Example

Reported:

```csharp
public class C
{
    public int Choose(bool flag)
    {
        if (flag)
        {
            return 1;
        }

        return 2;
    }
}
```

Corrected:

```csharp
public class C
{
    public int Choose(bool flag)
    {
        return flag ? 1 : 2;
    }
}
```

## Code fix

The code fix replaces the `if` and following return with one return using `?:`. It is offered only
when the following return stands alone, rather than inside another block, and no directive lies
between the two statements.

If the result exceeds the configured line length, the fix puts `?` and `:` on separate lines,
indented four spaces further. Comments inside the removed branches or attached to the second
return can be lost; preserve them by hand.

## Configuration

The default is an enabled warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1197.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`; `none` disables the rule.

The code fix also reads these line-length settings:

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.max_line_length` | Positive integer, in characters | `120` |
| `stylesharp.SST1521.max_line_length` | Positive integer, in characters | Falls back to the general key |

A valid rule-specific value takes priority. Invalid values fall back to the general key, then `120`.
These settings control wrapping, not whether a diagnostic is reported. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when separate returns make complex values, branch comments, or breakpoints easier to follow.
