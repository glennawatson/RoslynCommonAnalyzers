# SST1198 — Collapse assignment-only branch into one assignment

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

Both branches of an `if`/`else` contain only a simple `=` assignment to the same local variable or
parameter. Braces are optional. Assignments to fields, properties, or indexers are not reported,
nor are compound assignments such as `+=`.

## Example

Reported:

```csharp
public class C
{
    public int Choose(bool flag)
    {
        var value = 0;
        if (flag)
        {
            value = 1;
        }
        else
        {
            value = 2;
        }

        return value;
    }
}
```

Corrected:

```csharp
public class C
{
    public int Choose(bool flag)
    {
        var value = 0;
        value = flag ? 1 : 2;
        return value;
    }
}
```

## Code fix

The code fix replaces the whole `if`/`else` with one assignment using `?:`. It keeps the existing
variable declaration. If the result exceeds the configured line length, it puts `?` and `:` on
separate lines, indented four spaces further. Comments inside the removed branches can be lost;
preserve them by hand.

## Configuration

The default is an enabled warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1198.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`; `none` disables the rule.

The code fix also reads these line-length settings:

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.max_line_length` | Positive integer, in characters | `120` |
| `stylesharp.SST1521.max_line_length` | Positive integer, in characters | Falls back to the general key |

A valid rule-specific value takes priority. Invalid values fall back to the general key, then `120`.
These settings control wrapping, not whether a diagnostic is reported. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the values are easier to read in separate branches, especially when they already
contain `?:` expressions or need their own comments or breakpoints.
