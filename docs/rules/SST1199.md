# SST1199 — Prefer compile-time type names

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

Code reads `typeof(Person).Name` where the type is written as a name, such as `Person`,
`App.Person`, or `global::App.Person`. Use `nameof` to obtain the name at compile time.

The rule excludes type parameters, built-in keywords such as `string`, generic type names such as
`List<int>`, nullable types such as `int?`, arrays, pointers, and tuples.

## Example

Reported:

```csharp
public class Person
{
    public static string TypeName() => typeof(Person).Name;
}
```

Corrected:

```csharp
public class Person
{
    public static string TypeName() => nameof(Person);
}
```

Both expressions produce `"Person"` and follow a rename of the type. `nameof` needs no runtime
type lookup.

## Code fix

The code fix replaces the complete `typeof(Person).Name` expression with `nameof(Person)`.
It keeps any qualification on the type name. Comments attached to the removed `typeof` or `.Name`
parts can be lost.

## Configuration

The default is an enabled warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1199.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`; `none` disables the rule.
There are no other options.

## When to suppress

Suppress when code deliberately works with runtime type names and keeping that form makes the
surrounding code clearer. Type parameters need no suppression: `typeof(T).Name` gives the actual
type's name, while `nameof(T)` gives `"T"`, so that case is excluded. See [SST2498](SST2498.md).
