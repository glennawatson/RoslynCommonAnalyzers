# SST1199 - Prefer compile-time type names

| Item | Value |
| --- | --- |
| Category | Readability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |
| Analyzer | `LanguageStyleAnalyzer` |

## Cause

Code reads a non-generic type's runtime `Name`.

```csharp
return typeof(Person).Name;
```

## Rule description

`nameof(Person)` is compile-time only and tracks renames.

## What is not reported

`nameof` takes a **name**, so only an identifier — optionally qualified or alias-qualified — can be
its operand. Everything else in type position is written with syntax `nameof` does not accept, and
suggesting it would produce code that does not compile:

```csharp
typeof(string).Name              // a predefined keyword is not an identifier
typeof(int?).Name                // nullable
typeof(int[]).Name               // array
typeof((int, int)).Name          // tuple
typeof(List<int>).Name           // generic — and nameof would drop the type arguments anyway
```

A type parameter is excluded for a different reason: `typeof(T).Name` is the substituted type's name,
where `nameof(T)` is the literal `"T"`. The two say different things, so neither replaces the other —
see [SST2498](SST2498.md).

### Why the keyword case is not rewritten to the framework name

`nameof(String)` would compile and yield the same text as `typeof(string).Name`, but only with
`using System;` in scope — and [SST1121](SST1121.md) then asks for the built-in alias back, leaving
two rules pulling in opposite directions. There is nothing to gain either way: the rule prefers
`nameof` because it tracks renames, and `System.String` is not going to be renamed.

## How to fix violations

Replace the runtime type name read with `nameof`.
