# SST1200 — Using directives should be placed outside the namespace

| Item | Value |
| --- | --- |
| Category | Ordering |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `using` directive appears inside a namespace. This includes ordinary imports, aliases, and
`using static`. For a file-scoped namespace, imports after `namespace Example;` are inside it.

## Example

Reported:

```csharp
namespace Example
{
    using System;

    public class C
    {
        public DateTime Today => DateTime.Today;
    }
}
```

Corrected:

```csharp
using System;

namespace Example
{
    public class C
    {
        public DateTime Today => DateTime.Today;
    }
}
```

## How to fix violations

Move the directive above the namespace declaration. For a file-scoped namespace, put it above
`namespace Example;`. There is no code fix.

Moving an import changes where its names are looked up and which code can use it. If the imported
name was relative to the namespace, write its full name after moving it. Check for name conflicts
when the file contains several namespaces.

## Configuration

The default is an enabled warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1200.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`; `none` disables the rule.
There is no option to prefer imports inside namespaces.

## When to suppress

Suppress when an alias or import must apply to only one namespace in a file, or when the project's
convention requires imports inside namespaces.
