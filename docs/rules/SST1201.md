# SST1201 — Elements should be ordered by kind

| Item | Value |
| --- | --- |
| Category | Ordering |
| Severity | Warning |
| Code fix | Yes (move) |
| Default | Enabled |

## Cause

A member appears after a member of a kind that belongs later in the type. This applies inside
classes, structs, records, interfaces, and C# 14 extension blocks. It does not order types at
namespace level. Members written as explicit interface implementations, such as `void IFoo.Run()`,
are skipped.

## Rule description

Use this order:

1. Fields
2. Constructors
3. Finalizers (destructors)
4. Delegates
5. Events
6. Enums
7. Interfaces
8. Properties
9. Indexers
10. Methods, operators, and conversions
11. Structs, including record structs
12. Classes
13. Records
14. Unions

The union group contains nested classes or records that implement `System.Runtime.CompilerServices.IUnion`.
An extension block's members follow the order above; the block itself has no required position.

## Example

Reported:

```csharp
public class Widget
{
    public void Run() { _count++; }
    private int _count;
}
```

Corrected:

```csharp
public class Widget
{
    private int _count;
    public void Run() { _count++; }
}
```

## How to fix violations

The code fix moves the reported member before the first earlier member that belongs after it.
It carries the member's comments and whitespace with it. The destination also follows accessibility,
constant, static, and readonly ordering, so it can change the member's position within its kind group.

The fix is unavailable if the file contains `#if`, `#elif`, `#else`, or `#endif`, or if any directive
appears inside the containing type's braces, including `#region` or `#pragma`. Move members by hand
without changing which directives apply to them.

## Configuration

The default is an enabled warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1201.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`; `none` disables the rule.
The kind order is fixed and has no configuration option.

## When to suppress

Suppress when grouping related members by feature makes the type easier to read than grouping
them by kind.
