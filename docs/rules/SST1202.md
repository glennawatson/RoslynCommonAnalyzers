# SST1202 — Elements should be ordered by access

| Item | Value |
| --- | --- |
| Category | Ordering |
| Severity | Warning |
| Code fix | Yes (move) |
| Default | Enabled |

## Cause

Members of the same kind appear in the wrong accessibility order. Group them in this order:

1. `public`
2. `internal`
3. `protected internal`
4. `protected`
5. `private protected`
6. `private`

Kind takes priority: a private field still belongs before a public method. A static constructor
belongs before instance constructors and is allowed before a public constructor.

Members without an access modifier count as public inside an interface and private otherwise.
Explicit interface implementations, such as `void IFoo.Run()`, are skipped.

## Example

Reported:

```csharp
public class Widget
{
    private void Helper() { }
    public void Run() { Helper(); }
}
```

Corrected:

```csharp
public class Widget
{
    public void Run() { Helper(); }
    private void Helper() { }
}
```

## How to fix violations

The code fix moves the reported member before the first earlier member that belongs after it,
carrying its comments and whitespace. The destination follows kind first, then accessibility,
then constant, static, and readonly ordering.

The fix is unavailable if the file contains `#if`, `#elif`, `#else`, or `#endif`, or if any directive
appears inside the containing type's braces, including `#region` or `#pragma`. Move members by hand
without changing which directives apply to them.

## Configuration

The default is an enabled warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1202.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`; `none` disables the rule.
The accessibility order is fixed and has no configuration option.

## When to suppress

Suppress when keeping a helper beside the member that uses it makes the type easier to read.
Also suppress if moving fields would change the required order of their initializers.
