# SST1203 — Constants should appear before fields

| Item | Value |
| --- | --- |
| Category | Ordering |
| Severity | Warning |
| Code fix | Yes (move) |
| Default | Enabled |

## Cause

A `const` field follows a non-constant field of the same accessibility. Put constants before
other fields in each accessibility group, including `static` and `readonly` fields.

Accessibility takes priority. A private constant may follow a public field without violating this
rule. Local constants inside methods are not checked.

## Example

Reported:

```csharp
public class Widget
{
    public int Count;
    public const int Max = 10;
}
```

Corrected:

```csharp
public class Widget
{
    public const int Max = 10;
    public int Count;
}
```

## How to fix violations

The code fix moves the reported constant before the first earlier member that belongs after it,
carrying its comments and whitespace. It follows kind and accessibility before placing constants
ahead of other fields.

The fix is unavailable if the file contains `#if`, `#elif`, `#else`, or `#endif`, or if any directive
appears inside the containing type's braces, including `#region` or `#pragma`. Move the constant by
hand without changing which directives apply to it.

## Configuration

The default is an enabled warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1203.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`; `none` disables the rule.
There are no other options.

## When to suppress

Suppress when keeping a constant beside the field it describes is clearer than grouping all
constants together.
