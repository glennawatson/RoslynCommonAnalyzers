# SST1204 — Static members should appear before instance members

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

A static member follows an instance member of the same kind and access level. For
example, a public static method follows a public instance method in the same type.
Member kind and access level take priority over static ordering. Members written
with an interface name, such as `void IDisposable.Dispose()`, are ignored.

## Example

Bad:

```csharp
public class Widget
{
    public void Instance() { }
    public static void Shared() { }
}
```

Good:

```csharp
public class Widget
{
    public static void Shared() { }
    public void Instance() { }
}
```

## How to fix violations

Move the static member before the instance members in its group. **Move to ordered
position** moves the reported member to the first earlier position required by
member ordering. Its comments and spacing move with it.

The fix is unavailable if the file contains `#if`, `#elif`, `#else`, or `#endif`, or
if any directive, such as `#region` or `#pragma`, appears inside the containing type.
In those cases, move the member manually while keeping it under the same directives.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.SST1204.severity = warning
```

The default is `warning`. Supported values are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options. See
[configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when grouping related static and instance members together makes
the type easier to read, or when an existing layout must be kept for compatibility.
