# SST1205 — Partial elements should declare an access modifier

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

A partial class, struct, interface, record, or method has no access modifier. Each
declaration is checked separately, even when another part declares its access level.
A declaration with an access modifier, including `file`, is not reported.

## Example

Bad:

```csharp
partial class Widget
{
}
```

Good:

```csharp
internal partial class Widget
{
}
```

## How to fix violations

Add an access modifier that agrees with the other parts. The code fix adds
`internal` to a top-level type and `private` to a nested type or partial method.
It edits only the reported declaration; it does not check the access level on other
parts. Choose the modifier yourself if that default does not match the type.

An explicit access modifier on a partial method requires C# 9 or later and a method
implementation, even when the modifier is `private`. The fix does not add that
implementation. Keep the access modifier implicit if the implementation is optional.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.SST1205.severity = warning
```

The default is `warning`. Supported values are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options. See
[configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule for partial methods whose implementation is optional, or when
the project's C# version does not support explicit access on partial methods.
