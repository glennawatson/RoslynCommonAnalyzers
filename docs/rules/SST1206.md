# SST1206 — Declaration keywords should follow the standard order

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

Keywords such as `public`, `static`, and `readonly` are out of order on a type,
member, accessor, or local function. Access modifiers, including `file`, come first.
The remaining recognized keywords follow this order:

```text
required, const, static, extern, new, virtual, abstract, sealed, override,
readonly, unsafe, volatile, async, partial
```

Use only the keywords that apply to the declaration. The relative order of combined
access modifiers is checked by [SST1207](SST1207.md).

## Example

Bad:

```csharp
internal class Widget
{
    static public int Count() => 0;
}
```

Good:

```csharp
internal class Widget
{
    public static int Count() => 0;
}
```

## How to fix violations

**Reorder modifiers** sorts all modifiers on the reported declaration. It also puts
combined access modifiers in `protected internal` or `private protected` order.
Spacing and comments stay in their original positions, so check any comment that
describes a particular keyword.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.SST1206.severity = warning
```

The default is `warning`. Supported values are `error`, `warning`, `suggestion`,
`silent`, and `none`. The keyword order is fixed; `csharp_preferred_modifier_order`
does not change this rule. See [configuration](../CONFIGURATION.md).

## When to suppress

Disable this rule if your team requires a different modifier order. There is no
option to supply a custom order.
