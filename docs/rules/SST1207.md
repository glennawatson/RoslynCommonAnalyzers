# SST1207 — Protected should come before internal

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

Combined access modifiers are reversed: `internal protected` should be `protected
internal`, and `protected private` should be `private protected`. This applies to
types, members, accessors, and local functions that have access modifiers.

## Example

Bad:

```csharp
internal class Widget
{
    internal protected int Count() => 0;
}
```

Good:

```csharp
internal class Widget
{
    protected internal int Count() => 0;
}
```

## How to fix violations

**Reorder modifiers** sorts all modifiers on the declaration, including keywords
such as `static` and `readonly`, using the order described in [SST1206](SST1206.md).
It preserves the access level. Spacing and comments stay in their original
positions, so check any comment that describes a particular keyword.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.SST1207.severity = warning
```

The default is `warning`. Supported values are `error`, `warning`, `suggestion`,
`silent`, and `none`. The access keyword order is fixed;
`csharp_preferred_modifier_order` does not change this rule. See
[configuration](../CONFIGURATION.md).

## When to suppress

Disable this rule if your team requires the opposite order for combined access
modifiers. Reordering them does not change which code can access the declaration.
