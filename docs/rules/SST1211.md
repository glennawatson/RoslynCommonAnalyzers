# SST1211 — Using alias directives should be ordered alphabetically by alias name

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

Using aliases are out of alphabetical order by alias name. The name before `=`
determines the order, regardless of the namespace or type after it. Comparison is
case-sensitive; uppercase letters sort before lowercase letters.

The rule checks each file or namespace's using list separately. Ordering restarts
at `#if`, `#elif`, `#else`, and `#endif`; a blank line does not restart it.

## Example

Bad:

```csharp
using Y = System.Text.StringBuilder;
using X = System.Console;

internal class Widget { }
```

Good:

```csharp
using X = System.Console;
using Y = System.Text.StringBuilder;

internal class Widget { }
```

## How to fix violations

**Sort using directives** sorts the whole using list in the file or namespace:
regular usings first, with System namespaces first, then `using static`, then aliases.
It sorts each group alphabetically and sorts aliases by alias name.

Blank lines and comments before or after a using stay in their original positions.
Review comments that describe a particular import. The fix is unavailable when
directives such as `#if`, `#region`, or `#pragma` occur in or around the using list.
Sort those imports manually within their directive boundaries.

If the list mixes `global using` and ordinary usings, check that global usings remain
first. The fix does not sort them into a separate group.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.SST1211.severity = warning
```

The default is `warning`. Supported values are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options. See
[configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when aliases are deliberately grouped by purpose, or when a
global alias must precede an ordinary alias despite their alphabetical order.
