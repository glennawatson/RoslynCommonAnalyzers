# SST1212 — Property accessors should be ordered with get first

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

A property or indexer puts `get` after `set` or `init`. The rule applies to both
automatic properties and accessors with bodies. A property with only one accessor
is not reported.

## Example

Bad:

```csharp
internal class Widget
{
    private int _count;

    public int Count
    {
        set => _count = value;
        get => _count;
    }
}
```

Good:

```csharp
internal class Widget
{
    private int _count;

    public int Count
    {
        get => _count;
        set => _count = value;
    }
}
```

## How to fix violations

**Reorder accessors** moves `get` before `set` or `init`. Each accessor keeps its body,
attributes, and access modifiers. Spacing and comments before or after each accessor
stay in their original positions. Check those comments after accepting the fix;
comments inside the accessor bodies move with their code.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.SST1212.severity = warning
```

The default is `warning`. Supported values are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options. See
[configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when a project deliberately presents write behavior before read
behavior. Accessor order does not change how a property or indexer works.
