# SST1213 — Event accessors should be ordered with add first

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

An event with explicit `add` and `remove` blocks puts `add` after `remove`. An event
declared without those blocks is not reported.

## Example

Bad:

```csharp
internal class Widget
{
    public event System.EventHandler Changed
    {
        remove { }
        add { }
    }
}
```

Good:

```csharp
internal class Widget
{
    public event System.EventHandler Changed
    {
        add { }
        remove { }
    }
}
```

## How to fix violations

**Reorder accessors** moves `add` before `remove`. Each accessor keeps its body and
attributes. Spacing and comments before or after each accessor stay in their original
positions. Check those comments after accepting the fix; comments inside the
accessor bodies move with their code.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.SST1213.severity = warning
```

The default is `warning`. Supported values are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options. See
[configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when an established event layout deliberately puts removal
first. Accessor order does not change how event handlers are added or removed.
