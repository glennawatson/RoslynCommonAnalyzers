# SST1214 — Static readonly fields should appear before static non-readonly fields

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

A `static readonly` field follows a static non-readonly field with the same access
level in the same type. Instance fields are covered by [SST1215](SST1215.md).
Constants belong before other fields of the same access level; see
[SST1203](SST1203.md). The `readonly` keyword on methods or types is outside this rule.

## Example

Bad:

```csharp
public class Widget
{
    public static int Count;
    public static readonly int Limit = 10;
}
```

Good:

```csharp
public class Widget
{
    public static readonly int Limit = 10;
    public static int Count;
}
```

## How to fix violations

Move the readonly field before the non-readonly static fields in its access group.
**Move to ordered position** moves the reported field declaration to the first
earlier position required by member ordering. Its comments and spacing move with it.
If the declaration contains several fields, they move together.

The fix is unavailable if the file contains `#if`, `#elif`, `#else`, or `#endif`, or
if any directive, such as `#region` or `#pragma`, appears inside the containing type.
In those cases, reorder the fields manually while keeping them under the same directives.

Check field initializers before moving a field. Static initializers run in declaration
order, so moving one can change the values read or the order of method calls.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.SST1214.severity = warning
```

The default is `warning`. Supported values are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options. See
[configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when field initializers depend on their existing order, or when
related fields need to stay together for readability.
