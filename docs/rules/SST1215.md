# SST1215 — Instance readonly fields should appear before instance non-readonly fields

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning (enabled) |
| Code fix | Yes |

## Cause

An instance `readonly` field follows an instance non-readonly field with the same
access level in the same type. Static fields are covered by [SST1214](SST1214.md).
Constants may appear before readonly fields. The `readonly` keyword on methods or
types is outside this rule.

## Example

Bad:

```csharp
public class Widget
{
    public int Count;
    public readonly int Id = 1;
}
```

Good:

```csharp
public class Widget
{
    public readonly int Id = 1;
    public int Count;
}
```

## How to fix violations

Move the readonly field before the non-readonly instance fields in its access group.
**Move to ordered position** moves the reported field declaration to the first
earlier position required by member ordering. Its comments and spacing move with it.
If the declaration contains several fields, they move together.

The fix is unavailable if the file contains `#if`, `#elif`, `#else`, or `#endif`, or
if any directive, such as `#region` or `#pragma`, appears inside the containing type.
In those cases, reorder the fields manually while keeping them under the same directives.

Check field initializers before moving a field. Instance initializers run in
declaration order, so moving one can change the order of method calls.

## Configuration

```editorconfig
[*.cs]
dotnet_diagnostic.SST1215.severity = warning
```

The default is `warning`. Supported values are `error`, `warning`, `suggestion`,
`silent`, and `none`. There are no rule-specific options. See
[configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when field initializers depend on their existing order, when field
order defines a required memory layout, or when related fields need to stay together.
