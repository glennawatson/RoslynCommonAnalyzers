# SST1216 — Using static directives should appear after regular usings and before aliases

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A `using static` directive is followed by a regular `using` directive in the same file or namespace. Place regular usings first, static usings next, and aliases last. An alias placed too early is reported by [SST1209](SST1209.md).

Usings on opposite sides of `#if`, `#elif`, `#else`, or `#endif` are not compared.

## Example

Before:

```csharp
using static System.Math;
using System.Text;

internal class C { }
```

After:

```csharp
using System.Text;
using static System.Math;

internal class C { }
```

## How to fix violations

The **Sort using directives** fix sorts all usings in the containing file or namespace. It puts regular usings first, with `System` namespaces before other namespaces, then static usings, then aliases. Each group is sorted alphabetically; aliases are sorted by alias name.

Blank lines and comments before or after a using stay at their original positions. Check that each comment still describes the using beside it. The fix is unavailable when the using list contains a preprocessor directive such as `#if` or `#region`; reorder those usings by hand.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat reports as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1216.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a shared source file must keep a different import layout, or when deliberate comment groups make the existing order clearer.
