# SST1217 — Using static directives should be ordered alphabetically

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning |
| Code fix | Yes |

## Cause

Consecutive `using static` directives are out of alphabetical order. Compare the full names as written, including the namespace, with uppercase and lowercase letters treated separately.

Usings on opposite sides of `#if`, `#elif`, `#else`, or `#endif` are not compared.

## Example

Before:

```csharp
using static System.Math;
using static System.Console;

internal class C { }
```

After:

```csharp
using static System.Console;
using static System.Math;

internal class C { }
```

## How to fix violations

The **Sort using directives** fix sorts all usings in the containing file or namespace. It puts regular usings first, with `System` namespaces before other namespaces, then static usings, then aliases. It sorts each group alphabetically and sorts aliases by alias name.

Blank lines and comments before or after a using stay at their original positions. Check that each comment still describes the using beside it. The fix is unavailable when the using list contains a preprocessor directive such as `#if` or `#region`; reorder those usings by hand.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat reports as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1217.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when deliberate groups of imports are easier to read than alphabetical order, or a shared source file must keep another ordering convention.
