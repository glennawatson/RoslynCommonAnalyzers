# SST1218 — Method overloads should be grouped together

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning |
| Code fix | Yes |

## Cause

Another member separates methods with the same name, the same written access modifiers, and the same `static` status. The diagnostic marks the later method. Keeping overloads together helps readers find all ways to call a method.

Each class, struct, record, or interface declaration is checked separately. Overloads in different parts of a `partial` type are not compared. Comments and blank lines do not separate overloads. Constructors, operators, indexers, conversions, and explicit interface implementations are excluded.

## Example

Before:

```csharp
public class Writer
{
    public void Write(int value) { }
    public void Flush() { }
    public void Write(string value) { }
}
```

After:

```csharp
public class Writer
{
    public void Write(int value) { }
    public void Write(string value) { }
    public void Flush() { }
}
```

## How to fix violations

The fix moves the reported method immediately after the nearest earlier overload in its group. The method's attached comments, documentation, and blank lines move with it. **Fix All** gathers each overload group at its first method and keeps the overloads in their original relative order.

The fix is unavailable if the type contains any preprocessor directive, including `#if` or `#region`. Move the method by hand while keeping those sections intact.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat reports as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1218.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when grouping methods by feature or interface makes the type easier to use than grouping by method name.
