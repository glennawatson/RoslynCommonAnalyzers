# SST1219 — A default section should appear last

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A `switch` statement has a section containing `default` before another case section. Put the fallback at the end so readers see the named cases first.

A switch with no `default`, or with `default` in its last section, is not reported. This rule does not check switch expressions.

## Example

Before:

```csharp
public class C
{
    public int M(int x)
    {
        switch (x)
        {
            default:
                return 0;
            case 1:
                return 1;
        }
    }
}
```

After:

```csharp
public class C
{
    public int M(int x)
    {
        switch (x)
        {
            case 1:
                return 1;
            default:
                return 0;
        }
    }
}
```

## How to fix violations

The fix moves the entire section containing `default` to the end. Any case labels sharing its body move with it, along with attached comments and formatting. Other sections keep their relative order. `goto case` and `goto default` still target the same labels.

The fix is unavailable when the switch contains a preprocessor directive such as `#if` or `#region`. Reorder the sections by hand in that case.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat reports as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1219.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the section order must match an external specification, or placing the fallback first makes a particular switch easier to read.
