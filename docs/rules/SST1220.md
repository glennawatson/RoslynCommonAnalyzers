# SST1220 — Named arguments should match the parameter declaration order

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Info (suggestion) |
| Code fix | Yes |

## Cause

A call has at least two arguments, every argument is named, and their order differs from the parameter order. This applies to method calls and constructor calls, including `new(...)` with an inferred type.

Calls with any unnamed argument are excluded. The rule also skips calls whose target method or argument names cannot be resolved.

## Example

Before:

```csharp
public class C
{
    private static void M(int a, int b) { }

    private static void Caller() => M(b: 1, a: 2);
}
```

After:

```csharp
public class C
{
    private static void M(int a, int b) { }

    private static void Caller() => M(a: 2, b: 1);
}
```

## How to fix violations

The fix reorders the named arguments to match the parameter list. Each name keeps its expression. Commas, surrounding spacing, and comments before or after arguments stay at their original positions; check that comments still describe the right argument.

C# evaluates arguments in the order written. The fix does not check for side effects, so moving calls, property reads, or increments can change what runs first. If that order matters, first store the results in local variables in the required order, then pass those variables as arguments.

## Configuration

The default severity is `suggestion`. There are no rule-specific options. To treat reports as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1220.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the written argument order is required for evaluation, or when it follows a domain convention that is clearer than the parameter order.
