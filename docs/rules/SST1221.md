# SST1221 — Constraint clauses should match the type-parameter declaration order

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Info (suggestion) |
| Code fix | Yes |

## Cause

A generic declaration has at least two `where` clauses, and their order differs from the type parameters in `<...>`. The rule marks the first clause that belongs before the preceding clause.

This applies to classes, structs, interfaces, records, methods, delegates, and local functions. A type parameter without a constraint does not need a `where` clause.

## Example

Before:

```csharp
public class Cache<TKey, TValue>
    where TValue : class
    where TKey : new()
{
}
```

After:

```csharp
public class Cache<TKey, TValue>
    where TKey : new()
    where TValue : class
{
}
```

## How to fix violations

The fix sorts the `where` clauses to match the type-parameter list. It leaves the constraints inside each clause unchanged. Spacing and comments before or after a clause stay at their original positions, so check that comments still describe the right clause. Review preprocessor directives around clauses before accepting the edit.

[SST1127](SST1127.md) separately checks that each `where` clause starts on its own line.

## Configuration

The default severity is `suggestion`. There are no rule-specific options. To treat reports as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1221.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the clause order must match a shared declaration or external specification and keeping that match is more useful than following the type-parameter order.
