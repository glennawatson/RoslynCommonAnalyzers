# SST1222 — Enum members should be declared in ascending value order

| Item | Value |
| --- | --- |
| Category | Ordering |
| Default severity | Info (suggestion) |
| Code fix | Yes |

## Cause

Every member of an enum has an explicit value, but a member's value is lower than the value before it. The first such member is reported. Equal values are allowed.

The rule skips `[Flags]` enums, enums with fewer than two members, and enums with any implicitly numbered member. It also skips enums with values that cannot be determined or with a `ulong` value greater than `long.MaxValue`.

## Example

Before:

```csharp
internal enum Level
{
    Charlie = 3,
    Alpha = 1,
    Bravo = 2,
}
```

After:

```csharp
internal enum Level
{
    Alpha = 1,
    Bravo = 2,
    Charlie = 3,
}
```

## How to fix violations

The fix sorts all members by numeric value without changing their names or assigned values. It keeps indentation, commas, and the presence or absence of a trailing comma. Members with equal values are not guaranteed to keep their relative order.

The fix is unavailable when a comment or documentation appears immediately before a member, or a preprocessor directive appears inside the enum body. Comments after commas do not block the fix and stay at their original positions; check that they still describe the right members.

## Configuration

The default severity is `suggestion`. There are no rule-specific options. To treat reports as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1222.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when members are grouped by meaning, or when their order must match an external specification. Do not change assigned values to satisfy this rule.
