# SST1222 — Enum members should be declared in ascending value order

| Item | Value |
| --- | --- |
| Category | Ordering |
| Severity | Info |
| Code fix | Yes |
| Default | Enabled |

## Cause

An enum whose members all carry explicit values declares them out of ascending order.

```csharp
// 👎 reported
enum Level
{
    Charlie = 3,
    Alpha = 1,
    Bravo = 2,
}

// 👍
enum Level
{
    Alpha = 1,
    Bravo = 2,
    Charlie = 3,
}
```

## Rule description

When every member names its own number, the declaration order is free — and the only order a reader can check
against is ascending, because that is the one that makes a gap or a repeat visible at a glance.

### What is reported

- The first member that breaks ascending order, in an enum with at least two members where every member has
  an explicit constant value.

### What is not reported

- An enum with any implicitly numbered member. Reordering there would change what the numbering assigns, so
  the rule never asks for it.
- A `[Flags]` enum, where the grouping of single bits and the combinations built from them carries more than
  the numeric order does.

## How to fix violations

Sort the members by value. The fix permutes the members between the positions they already occupy, so the
enum keeps its indentation and trailing-comma shape.

The fix is not offered when any member carries a comment or documentation: moving the member would separate
that text from what it describes, so the reordering is left to a human.

## Performance

The rule registers on the enum declaration and stops at the first member whose value breaks the order. An
enum with any implicitly numbered member is rejected on the first one, before the rest are asked for their
values.
