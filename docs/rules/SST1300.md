# SST1300 — Element names should be PascalCase

| Item | Value |
| --- | --- |
| Category | Naming |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A class, struct, record, enum, delegate, method, property, event, or enum member has a name that does not start with an uppercase letter. Private members are checked too.

PascalCase starts each word with a capital, as in `DoThing`. This rule checks only the first letter; it does not reject `Do_Thing` or `DOTHING`. Names made entirely of underscores are excluded. An `@` used to escape a name is ignored.

Overrides and explicit interface implementations of methods, properties, and events with `add`/`remove` bodies are excluded. Events declared without those bodies are checked even when they use `override`. Interfaces follow [SST1302](SST1302.md); fields, parameters, and local variables have separate naming rules.

## Example

Before:

```csharp
public class widget
{
    public void doThing() { }
}
```

After:

```csharp
public class Widget
{
    public void DoThing() { }
}
```

## How to fix violations

The rename fix removes leading underscores or an `m_`, `s_`, or `t_` prefix, then capitalizes the first remaining letter. It leaves the rest of the name unchanged and updates code references throughout the solution. Each reported name has its own fix.

Renaming a public type or member can break callers outside the solution. Check string-based lookups and external consumers before accepting it.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat reports as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1300.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the name is required by an existing public API, an interface contract, or a framework that finds members by name. This includes implicit interface implementations whose names must match the interface.
