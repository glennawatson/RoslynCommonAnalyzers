# SST1302 — Interface names should begin with I

| Item | Value |
| --- | --- |
| Category | Naming |
| Default severity | Warning |
| Code fix | Yes |

## Cause

An interface name does not start with the capital letter `I`. Other type declarations are excluded.

Use a name such as `IWidget` so readers can recognize an interface. The rule checks only the first letter: `I`, `Item`, and `Iwidget` all pass. An `@` used to escape a name is ignored.

## Example

Before:

```csharp
public interface Widget { }
public class C : Widget { }
```

After:

```csharp
public interface IWidget { }
public class C : IWidget { }
```

## How to fix violations

The rename fix adds `I` to the capitalized name and updates code references throughout the solution. It removes leading underscores or an `m_`, `s_`, or `t_` prefix before capitalizing. It does not treat a lowercase `i` as an existing prefix: `iWidget` becomes `IIWidget`, so choose a better name by hand in that case.

Renaming a public interface can break callers outside the solution. Check external consumers and string-based lookups before accepting the fix.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat reports as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1302.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an existing public interface must keep its name for compatibility, or a shared API requires a different naming convention.
