# SST1303 — Constant names should be PascalCase

| Item | Value |
| --- | --- |
| Category | Naming |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A `const` field has a name that does not start with an uppercase letter. All access levels are checked, including private constants. Local constants inside methods are excluded.

PascalCase starts each word with a capital, as in `MaxRetries`. This rule checks only the first letter, so `MAX_RETRIES` passes. Names made entirely of underscores are excluded. An `@` used to escape a name is ignored.

## Example

Before:

```csharp
public class C
{
    public const int max = 1;
}
```

After:

```csharp
public class C
{
    public const int Max = 1;
}
```

## How to fix violations

The rename fix removes leading underscores or an `m_`, `s_`, or `t_` prefix, then capitalizes the first remaining letter. The rest of the name stays unchanged. It updates code references throughout the solution and leaves the constant's value unchanged.

Check callers outside the solution before renaming a public constant.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat reports as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1303.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a public constant must keep its name for compatibility, or names must match an external specification or native API.
