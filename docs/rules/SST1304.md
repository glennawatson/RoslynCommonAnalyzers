# SST1304 — Non-private readonly fields should be PascalCase

| Item | Value |
| --- | --- |
| Category | Naming |
| Default severity | Warning |
| Code fix | Yes |

## Cause

An instance `readonly` field with `public`, `internal`, `protected`, or `protected internal` access has a name that does not start with an uppercase letter.

PascalCase starts each word with a capital, as in `MaxValue`. This rule checks only the first letter. Names made entirely of underscores are excluded. An `@` used to escape a name is ignored.

Static readonly fields follow [SST1311](SST1311.md). Instance fields declared `private`, `private protected`, or without an access modifier follow [SST1309](SST1309.md). Constants and fields without `readonly` have separate naming rules.

## Example

Before:

```csharp
public class C
{
    public readonly int value;
}
```

After:

```csharp
public class C
{
    public readonly int Value;
}
```

## How to fix violations

The rename fix removes leading underscores or an `m_`, `s_`, or `t_` prefix, then capitalizes the first remaining letter. It leaves the rest of the name unchanged and updates code references throughout the solution. The field's value, access, and `readonly` modifier stay unchanged.

Check external callers and code that finds fields by name before accepting the fix.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat reports as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1304.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a field name is part of a public API, a serialization format, or another name-based contract that must remain compatible.
