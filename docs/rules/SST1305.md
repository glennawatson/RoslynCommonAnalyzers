# SST1305 — Field names should not use Hungarian notation

| Item | Value |
| --- | --- |
| Category | Naming |
| Default severity | Warning (disabled by default) |
| Code fix | No |

## Cause

A field, parameter, or variable in a local declaration has a name that starts with one or two lowercase letters followed by an uppercase letter, unless that prefix is allowed. Leading underscores are ignored, so both `iCount` and `_iCount` are reported.

Hungarian notation puts a type abbreviation at the start of a name, such as `i` for an integer. Prefer a name that describes the value's purpose. The rule checks the name's shape, not the variable's type, so it can also report useful abbreviations such as `vmCount`.

Three-letter prefixes such as `str` are not checked. `strName`, `count`, and `isEnabled` are not reported. Variables declared in `for`, `foreach`, patterns, and deconstruction are outside the local-declaration check.

## Example

With the rule enabled, this parameter is reported:

```csharp
internal class C
{
    private void M(int iCount) { }
}
```

After:

```csharp
internal class C
{
    private void M(int count) { }
}
```

## How to fix violations

Rename the field, parameter, or local variable to describe its purpose without a type prefix. There is no code fix.

## Configuration

The rule is disabled by default. Enable it by setting its severity; this example treats reports as errors and allows the extra prefix `rx`:

```ini
[*.cs]
dotnet_diagnostic.SST1305.severity = error
stylesharp.SST1305.allowed_hungarian_prefixes = rx
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`. Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

Both prefix settings accept lists separated by commas, semicolons, spaces, or tabs:

| Key | Default |
| --- | --- |
| `stylesharp.SST1305.allowed_hungarian_prefixes` | No extra prefixes |
| `stylesharp.allowed_hungarian_prefixes` | No extra prefixes |

The two lists are combined with the built-in list. Neither setting replaces the other. Configured prefixes match without regard to case. For example, `vm, rx` permits both prefixes; a blank list adds nothing.

These prefixes are always allowed:

```text
as at by db do ef gc go id if in io is it
js ms my no of on or so to ui up us ok
```

## When to suppress

Leave the rule disabled when short prefixes are part of your naming convention. For a useful abbreviation, add it to an allowed-prefix list. Suppress an individual report when a name must match an external API or another fixed contract.
