# SST1308 — Field names should not be prefixed

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning (disabled by default) |
| Code fix | No |

## Cause

A field name starts with `m_`, `s_`, or `t_`. The check is case-sensitive and
applies to all fields, including constants and readonly fields.

A leading underscore on its own, as in `_value`, is allowed. Prefixes on local
variables, parameters, and properties are not checked by this rule.

## How to fix violations

Remove the prefix and use your project's field naming style. Update the field's
uses too. There is no automatic code fix.

Reported when enabled:

```csharp
internal class C
{
    private int m_value;
}
```

Corrected for a project that uses `_camelCase`:

```csharp
internal class C
{
    private int _value;
}
```

## Configuration

The rule is disabled by default. To enable it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1308.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
The prefix list cannot be configured. See [configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled if your project uses these prefixes, such as `s_` for
static fields or `t_` for thread-static fields. Suppress an individual field if
other code depends on its exact name.
