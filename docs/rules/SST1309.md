# SST1309 — Private fields should be _camelCase

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning |
| Code fix | Yes (rename) |

## Cause

A private field does not start with a single underscore followed by a lower-case
letter, as in `_value`. This includes fields with no access modifier,
`private protected` fields, private instance readonly fields, and private static
mutable fields.

Constants and `static readonly` fields are handled by [SST1303](SST1303.md) and
[SST1311](SST1311.md). Names made entirely of underscores are ignored. The rule
checks the start of the name, not the casing of later words.

## How to fix violations

Rename the field to `_camelCase`.

Reported:

```csharp
public class C
{
    private int Value;
}
```

Corrected:

```csharp
public class C
{
    private int _value;
}
```

## Code fix

The rename fix removes a leading `m_`, `s_`, or `t_` prefix and leading
underscores, lowercases the first remaining letter, and adds one underscore.
For example, `Value`, `__Value`, and `m_value` become `_value`. It updates the
declaration and references across the solution, keeping the rest of the name's
spelling.

## Configuration

The default severity is `warning`. Set it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1309.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
The prefix and casing cannot be configured. See [configuration](../CONFIGURATION.md).

## When to suppress

Disable the rule if your project uses plain `camelCase` or separate prefixes for
static fields. Suppress a field if a serializer or other code depends on its
exact name. Keep [SST1310](SST1310.md) disabled when using `_camelCase`, because
it forbids underscores.
