# SST1310 — Field names should not contain underscores

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning (disabled by default) |
| Code fix | No |

## Cause

A field name contains an underscore anywhere, including at the start. All fields
are checked, including constants and readonly fields. Even a name made entirely
of underscores is reported.

## How to fix violations

Remove the underscores and capitalize later words to keep the name readable.
Update the field's uses too. There is no automatic code fix.

Reported when enabled:

```csharp
internal class C
{
    private int my_field;
}
```

Corrected:

```csharp
internal class C
{
    private int myField;
}
```

## Configuration

The rule is disabled by default. To enable it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1310.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no naming options. See [configuration](../CONFIGURATION.md).

## When to suppress

Leave this rule disabled if your project uses underscores in field names.
It conflicts with [SST1309](SST1309.md), which requires `_camelCase` for private
fields. Disable that rule if you choose the underscore-free style shown above.

Suppress an individual field if other code depends on its exact name.
