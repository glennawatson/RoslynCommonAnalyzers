# SST1311 — Static readonly fields should be PascalCase

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning |
| Code fix | Yes (rename) |

## Cause

A `static readonly` field does not start with an upper-case letter. This applies
at every accessibility, including private fields.

Only the first character is checked. Names made entirely of underscores are
ignored. Constants, instance readonly fields, and mutable fields have separate
naming rules.

## How to fix violations

Rename the field to PascalCase: start with a capital letter, as in `Max`.

Reported:

```csharp
public class C
{
    private static readonly int max = 1;
}
```

Corrected:

```csharp
public class C
{
    private static readonly int Max = 1;
}
```

## Code fix

The rename fix removes a leading `m_`, `s_`, or `t_` prefix and leading
underscores, then capitalizes the first remaining letter. It updates the field
declaration and references across the solution, keeping the rest of the name's
spelling.

## Configuration

The default severity is `warning`. Set it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1311.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no naming options. See [configuration](../CONFIGURATION.md).

## When to suppress

Disable the rule if your project uses `_camelCase` or `s_` for static readonly
fields. Suppress a field whose name must stay compatible with existing callers
or code that looks it up by name.
