# SST1312 — Local variables should be camelCase

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning |
| Code fix | Yes (rename) |

## Cause

A local variable declared in a statement, or a `foreach` loop variable, does not
start with a lower-case letter. Only the first character is checked.

`const` locals and names made entirely of underscores are ignored. Variables
introduced in a `for` initializer, `out var`, a pattern, or a tuple deconstruction
such as `var (x, y) = point` are not checked by this rule.

## How to fix violations

Rename the variable to camelCase: start with a lower-case letter, as in `count`.

Reported:

```csharp
public class C
{
    public int M()
    {
        int Count = 1;
        return Count;
    }
}
```

Corrected:

```csharp
public class C
{
    public int M()
    {
        int count = 1;
        return count;
    }
}
```

## Code fix

The rename fix removes leading underscores and lowercases the first remaining
letter. It updates the declaration and all references to that variable, including
uses inside lambdas and local functions. The rest of the name keeps its spelling.

## Configuration

The default severity is `warning`. Set it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1312.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no naming options. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress a local name that must match a formula or a code sample maintained
elsewhere. Disable the rule if your project follows a different local naming style.
