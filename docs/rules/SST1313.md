# SST1313 — Parameters should be camelCase

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning |
| Code fix | Yes (rename) |

## Cause

A parameter does not start with a lower-case letter. This includes method,
constructor, and lambda parameters. Only the first character is checked.

Positional record parameters, such as `X` in `record Point(int X)`, are ignored
because they also name properties. Names made entirely of underscores, such as
`_` and `__`, are ignored too.

## How to fix violations

Rename the parameter to camelCase: start with a lower-case letter, as in `value`.

Reported:

```csharp
public class C
{
    public int M(int Value) => Value;
}
```

Corrected:

```csharp
public class C
{
    public int M(int value) => value;
}
```

## Code fix

The rename fix removes leading underscores and lowercases the first remaining
letter. It updates the parameter declaration and references across the solution,
including named arguments at call sites. The rest of the name keeps its spelling.

## Configuration

The default severity is `warning`. Set it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1313.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no naming options. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress a parameter whose name must stay compatible with callers that use named
arguments outside the solution. Also suppress when keeping a base or interface
parameter name is required by [SST1318](SST1318.md).
