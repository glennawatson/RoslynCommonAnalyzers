# SST1314 — Type parameters should begin with T

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning |
| Code fix | Yes (rename) |

## Cause

A generic type parameter on a type or method does not start with capital `T`.
Names made entirely of underscores are ignored. The rule checks only the first
character, so both `T` and `TKey` are accepted.

## How to fix violations

Use `T` for a single general type, or add a descriptive name such as `TKey`.

Reported:

```csharp
public class C<Key> { }
```

Corrected:

```csharp
public class C<TKey> { }
```

## Code fix

The rename fix adds `T` to the suggested PascalCase name: both `Key` and `key`
become `TKey`. It removes leading underscores and a leading `m_`, `s_`, or `t_`
prefix before changing the first remaining letter. It updates the declaration
and references across the solution.

## Configuration

The default severity is `warning`. Set it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1314.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
The required prefix cannot be configured. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a type parameter must keep a name from an external specification
or a mathematical convention. Disable the rule if your project uses another
generic naming style.
