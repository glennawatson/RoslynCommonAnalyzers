# SST1316 — Tuple element names should match the configured casing

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning |
| Code fix | No |
| Default | PascalCase |

## Cause

An explicitly named tuple element has the wrong first-letter casing. PascalCase,
which starts with a capital letter, is the default. You can choose camelCase instead.

The rule checks names in tuple types, such as `(int Count, string Name)`, and
tuple values, such as `(Count: 1, Name: "sample")`. It ignores unnamed elements,
names taken from variables as in `(count, name)`, and names made entirely of
underscores. Later letters are not checked.

## How to fix violations

Rename the tuple element and update code that accesses it by name.
There is no automatic code fix.

Reported with the default setting:

```csharp
public class C
{
    public (int count, string Name) M() => (1, "sample");
}
```

Corrected:

```csharp
public class C
{
    public (int Count, string Name) M() => (1, "sample");
}
```

## Configuration

The default severity is `warning`. Set the severity and casing in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1316.severity = warning
stylesharp.tuple_element_naming = pascal_case
# Optional rule-specific override:
stylesharp.SST1316.tuple_element_naming = pascal_case
```

Both casing keys accept `pascal_case` (the default) or `camel_case`, ignoring
case. A recognized rule-specific value takes priority. A missing or invalid
value falls back to the general key, then to `pascal_case`.

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress an element whose name must match an interface or base member, or a
published API used by callers outside the solution. Choose the casing setting
that matches your project before suppressing individual names.
