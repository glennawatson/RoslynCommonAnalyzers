# SST1317 — Asynchronous method names should end with 'Async'

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A method returns `Task`, `Task<T>`, `ValueTask`, or `ValueTask<T>` but its name
does not end with `Async`. The suffix is case-sensitive and tells callers the
result can be awaited. The method does not need the `async` keyword.

Overrides, interface implementations, and methods named `Main` are skipped.
So are `async void` methods, local functions, and methods returning custom
awaitable types or async streams. A method without `async` is also skipped if
its task return type is written using a different alias, such as `Work` for `Task`.

## How to fix violations

Add `Async` to the method name.

Reported:

```csharp
using System.Threading.Tasks;

public class C
{
    public async Task Load()
    {
        await Task.Delay(1);
    }
}
```

Corrected:

```csharp
using System.Threading.Tasks;

public class C
{
    public async Task LoadAsync()
    {
        await Task.Delay(1);
    }
}
```

## Code fix

The rename fix appends `Async` to the existing name and updates the declaration
and references across the solution. It leaves the return type, `async` keyword,
and method body unchanged.

## Configuration

The default severity is `warning`. Set it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1317.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
The suffix cannot be configured. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress a method whose name is required by a framework or must stay compatible
with existing callers outside the solution. Disable the rule if your project
deliberately uses another naming style for task-returning methods.
