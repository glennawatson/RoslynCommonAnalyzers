# SST1318 — Overriding parameter names should match the base declaration

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning |
| Code fix | Yes (rename) |
| Default | Enabled |

## Cause

A method overrides a base method or implements an interface method, but a parameter
has a different name from the parameter in the same position in that declaration.
The comparison is case-sensitive. Both explicit and implicit interface implementations
are checked.

Matching names keep named arguments and parameter documentation consistent.

## Example

Bad:

```csharp
public abstract class Base
{
    public abstract void Process(int count);
}

public class Derived : Base
{
    public override void Process(int value)
    {
        System.Console.WriteLine(value);
    }
}
```

Corrected:

```csharp
public abstract class Base
{
    public abstract void Process(int count);
}

public class Derived : Base
{
    public override void Process(int count)
    {
        System.Console.WriteLine(count);
    }
}
```

## Code fix

The fix renames the parameter to match the base declaration and updates its uses
across the solution, including named arguments. Check callers outside the solution
before renaming a public parameter: their named arguments may need updating too.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default.

```editorconfig
[*.cs]
dotnet_diagnostic.SST1318.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when an existing public parameter name must remain compatible with callers,
or when one method implements interfaces that require different parameter names.
