# SST1320 — Parameter names should not match the method name

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A method parameter has exactly the same name as the method. The comparison is
case-sensitive, so `Value(int value)` is allowed. Constructors, operators, and local
functions are not checked.

A parameter name should describe the value being passed. Repeating the method name
makes named arguments harder to read, as in `Foo(Foo: 3)`.

## Example

Bad:

```csharp
public class Processor
{
    public void Foo(int Foo)
    {
        System.Console.WriteLine(Foo);
    }
}
```

Corrected:

```csharp
public class Processor
{
    public void Foo(int value)
    {
        System.Console.WriteLine(value);
    }
}
```

## How to fix violations

Rename the parameter to describe its role and update its uses and named arguments.
There is no automatic code fix.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default.

```editorconfig
[*.cs]
dotnet_diagnostic.SST1320.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when the parameter name is required by an inherited contract or when renaming
a public parameter would break callers that use named arguments.
