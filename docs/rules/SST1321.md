# SST1321 — Synchronous method names should not end with 'Async'

| Item | Value |
| --- | --- |
| Category | Naming |
| Severity | Warning |
| Code fix | Yes (rename) |
| Default | Enabled |

## Cause

A method name ends with `Async`, but the method is not declared `async` and does not
return a supported asynchronous type. The suffix tells callers to expect an
asynchronous result, so it is misleading on a method that returns an ordinary value
or `void`.

## What is not reported

- Overrides and explicit or implicit interface implementations.
- Methods declared `async`, including `async void` methods.
- Methods returning `Task`, `Task<T>`, `ValueTask`, `ValueTask<T>`, or `IAsyncEnumerable<T>`.
- Methods returning a custom type that declares a parameterless `GetAwaiter` method.
- A method named exactly `Async`.

`IAsyncEnumerable<T>` represents an asynchronous sequence, which callers read with
`await foreach`. [SST1317](SST1317.md) checks for a missing suffix on task-returning methods.

## Example

Bad:

```csharp
public class Store
{
    public int FetchAsync() => 0;
}
```

Corrected:

```csharp
public class Store
{
    public int Fetch() => 0;
}
```

## Code fix

The fix removes the `Async` suffix and updates references across the solution. It
does not change the method's return type or body. If the method should perform
asynchronous work, implement that behavior instead of accepting the rename.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default.

```editorconfig
[*.cs]
dotnet_diagnostic.SST1321.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when a published method name must remain compatible with existing callers,
or when the method follows an asynchronous convention the rule does not recognize,
such as reporting completion through a callback.
