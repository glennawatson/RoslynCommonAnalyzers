# SST1400 — Access modifier should be declared

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes (add modifier) |
| Default | Enabled |

## Cause

A type or member omits an access modifier such as `public`, `internal`, or `private`.
Writing the modifier makes it clear which code can use the declaration.

The rule skips interface members, explicit interface implementations, static
constructors, and partial methods. Records and record structs are checked.
The `file` modifier, available from C# 11, counts as explicit access.

## Example

Bad:

```csharp
class Widget
{
    void Refresh() { }
}
```

Corrected:

```csharp
internal class Widget
{
    private void Refresh() { }
}
```

## Code fix

The fix adds `internal` to a top-level type and `private` to a nested type or member.
These are the access levels C# supplies when the modifier is omitted. Choose a
different modifier yourself if the declaration needs wider access.

Partial methods are checked separately by [SST1205](SST1205.md).

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default.

```editorconfig
[*.cs]
dotnet_diagnostic.SST1400.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when a project's established style deliberately leaves default access implicit. Otherwise, adding the modifier makes the access level clear without changing it.
