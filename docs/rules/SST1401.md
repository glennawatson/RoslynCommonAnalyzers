# SST1401 — Fields should be private

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A field is declared `public`, `internal`, `protected`, or a combination of those
modifiers. Constants and `static readonly` fields are allowed. An instance
`readonly` field is still reported if it is exposed.

Properties let you add validation or change how a value is stored without exposing
the field. A `static readonly` field cannot be reassigned after initialization, but
the object it holds can still be mutable.

## Example

Bad:

```csharp
public class Counter
{
    public int Count;
}
```

Corrected:

```csharp
public class Counter
{
    public int Count { get; set; }
}
```

## How to fix violations

Make the field private and expose the required access through a property, or replace
it with an auto-property as shown. Use `const` or `static readonly` only when the
value is meant to be shared and cannot be reassigned.

There is no automatic code fix.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default.

```editorconfig
[*.cs]
dotnet_diagnostic.SST1401.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when a field is required by an interop or serialization contract, when replacing a published field would break consumers, or when measurements show that direct field access is needed for a data structure.
