# SST1404 — Code analysis suppression should have justification

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `[SuppressMessage]` attribute has no `Justification`, or its value is `null`,
empty, whitespace, or exactly `<Pending>`. A justification explains why the
suppressed rule should not apply to this code.

Constant strings and strings joined with `+` are accepted when their resulting
text is nonempty and is not the placeholder. This rule does not check `#pragma`
or `.editorconfig` suppressions.

## Example

Bad:

```csharp
using System.Diagnostics.CodeAnalysis;

public class Processor
{
    [SuppressMessage("Naming", "SST1320")]
    public void Foo(int Foo) { }
}
```

Corrected:

```csharp
using System.Diagnostics.CodeAnalysis;

public class Processor
{
    [SuppressMessage("Naming", "SST1320",
        Justification = "Existing callers use Foo as a named argument.")]
    public void Foo(int Foo) { }
}
```

## How to fix violations

Write a reason that explains why changing the code would be wrong or too costly.
Remove an unnecessary suppression.

There is no automatic code fix.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default.

```editorconfig
[*.cs]
dotnet_diagnostic.SST1404.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress only when you cannot edit the attribute, such as in externally maintained source whose suppression reasons are recorded elsewhere. For code you maintain, supply the reason.
