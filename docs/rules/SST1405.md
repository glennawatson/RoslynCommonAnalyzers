# SST1405 — Debug.Assert should provide message text

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `System.Diagnostics.Debug.Assert` call has no second argument, or its second
argument is an empty or whitespace string literal. A message helps the person
investigating a failed assertion understand which assumption failed.

The rule checks calls written with a type name, such as `Debug.Assert(...)`.
It does not inspect unqualified `Assert(...)` calls imported with `using static`,
or determine whether a variable or expression produces empty text.

## Example

Bad:

```csharp
using System.Diagnostics;

public class Processor
{
    public void CheckIndex(int index) => Debug.Assert(index >= 0);
}
```

Corrected:

```csharp
using System.Diagnostics;

public class Processor
{
    public void CheckIndex(int index) =>
        Debug.Assert(index >= 0, "Index must not be negative.");
}
```

## How to fix violations

Pass a message as the second argument. Describe the failed assumption or the state
needed to investigate it.

There is no automatic code fix.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default.

```editorconfig
[*.cs]
dotnet_diagnostic.SST1405.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when the assertion is a temporary debugging check or when the condition and surrounding context already provide all the information needed to investigate a failure.
