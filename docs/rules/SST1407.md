# SST1407 — Arithmetic expressions should declare precedence

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes (add parentheses) |
| Default | Enabled |

## Cause

An expression mixes operators from different groups below without parentheses
around the part evaluated first:

- Multiplication, division, and remainder: `*`, `/`, `%`.
- Addition and subtraction: `+`, `-`.
- Shifts: `<<`, `>>`.

For example, `a + b * c` and `a + b << c` are reported. Operators in the same group,
such as `a + b - c`, do not need parentheses for this rule. The unsigned right shift
operator `>>>` is not checked.

Parentheses show the grouping without requiring readers to remember which operator
takes priority.

## Example

Bad:

```csharp
public class Calculator
{
    public int Calculate(int a, int b, int c) => a + b * c;
}
```

Corrected:

```csharp
public class Calculator
{
    public int Calculate(int a, int b, int c) => a + (b * c);
}
```

## Code fix

The fix adds parentheses around the reported part of the expression. It keeps the
existing evaluation order and surrounding comments. For example, `a + b << c`
becomes `(a + b) << c`. “Fix all” adds parentheses to all reported expressions in
the selected scope.

If a different calculation was intended, change the grouping yourself. Accepting
the fix makes the existing calculation explicit.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default.

```editorconfig
[*.cs]
dotnet_diagnostic.SST1407.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when a familiar mathematical formula is easier for your team to read without the extra parentheses and its grouping is unambiguous to the intended readers.
