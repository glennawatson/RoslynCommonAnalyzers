# SST1408 — Conditional expressions should declare precedence

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Default severity | Warning |
| Code fix | Yes |

## Cause

An expression mixes `&&` and `||` without parentheses around the inner operation.
Parentheses show which conditions belong together. Chains using only `&&` or only
`||` are not reported.

## Example

Reported:

```csharp
public class C
{
    public bool M(bool a, bool b, bool c) => a || b && c;
}
```

Corrected:

```csharp
public class C
{
    public bool M(bool a, bool b, bool c) => a || (b && c);
}
```

## How to fix violations

The **Add parentheses** code fix wraps the reported expression in parentheses.
It preserves the existing grouping and surrounding comments. It does not change
which conditions are evaluated.

## Configuration

The default severity is `warning`. There are no rule-specific options. To report
violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1408.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when your team's style deliberately relies on the standard grouping of
`&&` before `||`. Otherwise, adding parentheses makes the condition easier to read.
