# SST1411 — Attribute constructor should not use unnecessary parenthesis

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Default severity | Warning |
| Code fix | Yes |

## Cause

An attribute has an empty argument list, such as `[System.Obsolete()]`. The
parentheses add no information. Attributes with constructor arguments or named
arguments are not reported.

## Example

Reported:

```csharp
public class C
{
    [System.Obsolete()]
    public void M() { }
}
```

Corrected:

```csharp
public class C
{
    [System.Obsolete]
    public void M() { }
}
```

## How to fix violations

The **Remove empty parentheses** code fix removes the attribute's empty argument
list. The attribute still calls the same constructor. Comments inside or attached
to the removed parentheses can be lost; move them before applying the fix.

## Configuration

The default severity is `warning`. There are no rule-specific options. To report
violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1411.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when your team's style keeps parentheses on every attribute for
consistency. Removing them does not change the attribute's behavior.
