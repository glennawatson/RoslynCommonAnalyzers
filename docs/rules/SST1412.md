# SST1412 — Store files as UTF-8 with a byte order mark

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity when enabled | Warning |
| Default | Disabled |
| Code fix | No |

## Cause

A source file's encoding has no byte order mark (BOM). A BOM is an invisible mark
at the start of a file that identifies its encoding. The diagnostic appears at
the start of the file, including when its encoding is unknown.

The check only requires a BOM. It does not verify UTF-8: a file saved as UTF-16
with a BOM is also accepted.

## Example

Reported when this file is saved as UTF-8 without a BOM:

```csharp
internal class C { }
```

Corrected by saving the same text as UTF-8 with a BOM:

```csharp
internal class C { }
```

The visible C# text is identical; the file encoding changes.

## How to fix violations

Use your editor's encoding or save options to save the file as UTF-8 with a BOM.
There is no automatic code fix.

## Configuration

The rule is disabled by default (`none`). Enable it with `warning`. This rule and
[SST1450](SST1450.md), which requires no BOM, are mutually exclusive; both are
disabled by default.

```ini
[*.cs]
dotnet_diagnostic.SST1412.severity = warning
dotnet_diagnostic.SST1450.severity = none
charset = utf-8-bom
```

`charset` tells editors which encoding to use; it is not a rule-specific option.
Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Leave this rule disabled when your project or its tools require files without a
BOM. For a file-specific exception, set its severity to `none` in `.editorconfig`.
A `#pragma` inside the file cannot suppress a diagnostic at the file's start.
