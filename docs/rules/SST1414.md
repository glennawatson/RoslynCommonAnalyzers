# SST1414 — Tuple types in signatures should have element names

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Default severity | Warning |
| Code fix | No |

## Cause

A tuple type has an unnamed element in a return type, parameter, property, field
or delegate declaration. Tuples inside generic types are checked too. Names tell
callers what each value means and let them avoid positional access such as
`Item1` and `Item2` (see [SST1142](SST1142.md)).

Tuple types in field initializers and expression-bodied members can also be
reported. Tuple types inside method statement blocks or local functions are not
checked.

## Example

Reported:

```csharp
public class C
{
    public (int, string) Lookup() => (1, "Ada");
}
```

Corrected:

```csharp
public class C
{
    public (int Id, string Name) Lookup() => (1, "Ada");
}
```

## How to fix violations

Add a meaningful name to every unnamed element of the tuple type. Naming values
only in the returned tuple does not name the elements of the declared return
type. There is no automatic code fix; you must choose the names.

## Configuration

The default severity is `warning`. There are no rule-specific options. To report
violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1414.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an interface or overridden member requires unnamed tuple elements
and you cannot change that declaration. Tuple element names on implementations
and overrides must match the declaration they implement or override.
