# SST1415 — Use nameof for parameter references

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A string literal passed to an explicitly named `Argument...Exception`
constructor exactly matches a parameter name. This includes parameters of methods,
constructors, local functions, indexers and lambdas. The rule requires C# 6 or
later, where `nameof` is available.

The exception's written type name must start with `Argument` and end with
`Exception`; custom types with such names are checked too. Any constructor
argument can be reported, including a message that exactly equals the parameter
name. Longer messages, existing `nameof` expressions and target-typed `new(...)`
calls are not reported. Inside a local function, parameters of the enclosing
method are not checked.

## Example

Reported:

```csharp
public class C
{
    public void M(string value)
    {
        if (value == null)
            throw new System.ArgumentNullException("value");
    }
}
```

Corrected:

```csharp
public class C
{
    public void M(string value)
    {
        if (value == null)
            throw new System.ArgumentNullException(nameof(value));
    }
}
```

## How to fix violations

The code fix replaces the literal with `nameof(parameter)` and preserves
surrounding comments. The string value stays the same, and a parameter rename
can update the reference.

For an escaped parameter name such as `@class`, write `nameof(@class)` by hand.
The code fix does not add the required `@`.

## Configuration

The default severity is `warning`. There are no rule-specific options. To report
violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1415.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a literal happens to match a parameter name but is fixed text that
must not change with a rename, such as an external key or an exception message.
