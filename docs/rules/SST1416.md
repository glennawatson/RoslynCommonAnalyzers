# SST1416 — Do not declare public members in a non-public type

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity when enabled | Warning |
| Default | Disabled |
| Code fix | Yes |

## Cause

A class, struct or record has a `public` member, but that type or an enclosing
type is not declared `public`. This includes internal, private, protected nested
and file-local types. For an internal type, declaring ordinary members `internal`
makes their reach clearer.

The rule skips `override`, `virtual` and `abstract` members, operators and
conversion operators. It also skips methods, properties, indexers and events
with `add`/`remove` bodies that implement interface members.

## Example

Reported when enabled:

```csharp
internal class C
{
    public void M() { }
}
```

Corrected:

```csharp
internal class C
{
    internal void M() { }
}
```

## How to fix violations

The **Change 'public' to 'internal'** code fix replaces the reported member's
accessibility with `internal`. It keeps the member and its body. Review callers
that discover public members at runtime before applying it.

## Configuration

The rule is disabled by default (`none`). There are no rule-specific options.
Enable it with:

```ini
[*.cs]
dotnet_diagnostic.SST1416.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Keep a member public when reflection, data binding or serialization needs it, or
when a public constructor is required by a `new()` generic constraint. Suppress
also when callers outside the assembly can reach a protected nested type's public
members.

An interface event declared without `add`/`remove` bodies can still be reported.
Keep its implementation public to satisfy the interface. Leave the rule disabled
if your team prefers public members throughout internal types.
