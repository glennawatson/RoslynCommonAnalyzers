# SST1416 — Do not declare public members in a non-public type

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled (opt-in) |

## Cause

A `public` member is declared in a type that is not externally visible (an
internal, private, or file-local type, or one nested in such a type).

```csharp
// 👎 reported (when enabled)
internal class C
{
    public void M() { }
}

// 👍
internal class C
{
    internal void M() { }
}
```

## Rule description

The effective accessibility of a member is capped by its containing type, so a
`public` member of an `internal` type is really only internal — the `public`
modifier overstates its reach. Declaring it `internal` makes the real
accessibility obvious.

The following are **not** reported, because their accessibility is not the containing
type's alone to choose:

- an `override`, which takes its accessibility from the member it overrides;
- a `virtual` or `abstract` member, which gives its accessibility to every override;
- members that implement an interface member; and
- operators and conversion operators (which the language requires to be public).

The inheritance cases are a correctness matter rather than a preference. Narrowing
either end of an override pair does not compile:

```csharp
internal readonly struct Key
{
    public override bool Equals(object? obj) => …   // 👍 not reported
    public override int GetHashCode() => 0;         // 👍 not reported
}
```

`internal override bool Equals(object?)` is CS0507 — the override inherits `public`
from `ValueType`. Demoting a `virtual` member instead strands every override with the
same error from the other direction, and the containing type cannot see who overrides
it, so neither end is reported.

**This rule is off by default** — declaring members `public` inside an internal
type is a widespread, harmless habit, so adopting the stricter style is opt-in.
Enable it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1416.severity = warning
```

## How to fix violations

Change the member's `public` modifier to `internal`. The provided code fix does
this automatically.
