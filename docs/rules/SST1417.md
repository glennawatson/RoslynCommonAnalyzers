# SST1417 — Namespace should match the folder structure

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity when enabled | Warning |
| Default | Disabled |
| Code fix | No |

## Cause

A top-level namespace does not match the root namespace followed by the file's
folders under the project directory. Names are compared with case sensitivity.
Both block namespaces and file-scoped namespaces are checked; nested namespace
declarations are not.

Files outside the project directory are skipped. Each folder name must start
with a letter or `_` and contain only letters, digits or `_`; other folder names
cause the file to be skipped.

## Example

For `Models/Widget.cs` in a project whose root namespace is `MyApp`, this is
reported when the rule is enabled:

```csharp
namespace MyApp.Wrong
{
    public class Widget { }
}
```

Corrected:

```csharp
namespace MyApp.Models
{
    public class Widget { }
}
```

## How to fix violations

Rename the namespace and update references to its types, or move the file to the
matching folder. There is no automatic code fix. Use your editor's namespace
refactoring to update references when renaming.

## Configuration

The rule is disabled by default (`none`). Enable it with:

```ini
[*.cs]
dotnet_diagnostic.SST1417.severity = warning
stylesharp.SST1417.namespace_root = MyApp
```

| Key | Value | Default |
| --- | --- | --- |
| `stylesharp.SST1417.namespace_root` | Root namespace, such as `MyApp` | No override |
| `stylesharp.namespace_root` | Root namespace shared by rules that use it | No override |

The rule-specific key takes priority over the general key. Empty values are
ignored. With neither override, the root comes from `build_property.RootNamespace`;
if that is missing or empty, only the folders form the namespace. With no root
and no folders, there is nothing to check.

The build must supply the project directory as `build_property.ProjectDir`.
Without it, or without a file path, the rule reports nothing.

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a published namespace must stay stable, or when folders organize
files differently from namespaces. Leave the rule disabled if folder alignment
is not a project convention.
