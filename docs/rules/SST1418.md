# SST1418 — Declare precedence when mixing the null-coalescing operator

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Default severity | Warning |
| Code fix | Yes |

## Cause

Either side of `??` contains an operation with two operands, such as addition,
comparison or a logical operation, without parentheses around it. Parentheses
make the grouping clear without requiring readers to remember operator priority.

Chained `??` expressions, already parenthesized operands, and the type-testing
operators `as` and `is` are not reported. For example, `value as string ?? fallback`
does not need extra parentheses for this rule.

## Example

Reported:

```csharp
public class C
{
    public int M(int? a, int b, int c) => a ?? b + c;
}
```

Corrected:

```csharp
public class C
{
    public int M(int? a, int b, int c) => a ?? (b + c);
}
```

## How to fix violations

The **Add parentheses** code fix wraps the reported operand in parentheses and
preserves surrounding comments. It keeps the existing grouping and evaluation
order. Fix All handles every reported operand, including both sides of `??`.

## Configuration

The default severity is `warning`. There are no rule-specific options. To report
violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1418.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when your team's style relies on standard operator grouping. Otherwise,
the added parentheses make a mixed expression easier to read.
