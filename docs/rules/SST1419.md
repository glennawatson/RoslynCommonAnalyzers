# SST1419 — Remove redundant modifiers

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Default severity | Warning |
| Code fix | Partial: `partial` and `sealed` only |

## Cause

The rule reports these cases:

- A `partial` type has only one part and does not contain a partial member.
- A member has `sealed` without `override`, except for an instance member of an
  interface. A `sealed override` is also reported inside a sealed type.
- A `checked` or `unchecked` block or expression contains no arithmetic operator,
  arithmetic compound assignment, increment, decrement, unary minus or cast.

The rule keeps `partial` on types with several parts and on partial members.
Methods marked with `LibraryImport` and their containing types keep `partial`.
It also keeps sealed overrides in an unsealed type and sealed instance members
in an interface.

Any of the listed arithmetic operations makes an overflow check useful, even
inside a nested block. A method call alone does not. `checked` has no effect
on arithmetic inside the called method.

An instance member with a default implementation can use `sealed` in an interface
to prevent an implementing type from replacing that implementation. A static
interface member does not have that behavior, so its redundant `sealed` modifier
is reported.

## Example

Reported:

```csharp
public sealed partial class C
{
    public sealed override string ToString() => "C";

    public int Identity(int value) => checked(value);
}
```

Corrected:

```csharp
public sealed class C
{
    public override string ToString() => "C";

    public int Identity(int value) => value;
}
```

## How to fix violations

The **Remove redundant modifier** code fix deletes the reported `partial` or
`sealed` keyword and supports Fix All. It keeps the declaration. Comments attached
to the removed keyword can be lost; move them first.

There is no code fix for `checked` or `unchecked`. For a block, remove the keyword
and keep the braces if they are needed to preserve local-variable scope. For an
expression, remove the wrapper, keeping parentheses where grouping requires them.

## Configuration

The default severity is `warning`. There are no rule-specific options. To report
violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1419.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when another build configuration needs an extra part of the type.
You can also suppress an empty overflow-check block if your team keeps it
for planned arithmetic changes.
