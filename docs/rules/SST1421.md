# SST1421 — Write-only properties should not be used

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A property has a `set` or `init` accessor but no `get` accessor. Callers expect a
property to expose a value they can read. Use a method for a write-only operation.

Interface declarations, abstract properties, overrides, and explicit interface
implementations are excluded.

## How to fix violations

Add a getter if callers should be able to read the value. Otherwise, replace the
property with a method that names the operation, such as `SetValue`.

There is no automatic code fix.

## Example

Bad:

```csharp
public class Settings
{
    private int _value;

    public int Value { set => _value = value; }
}
```

Corrected, when the value should be readable:

```csharp
public class Settings
{
    private int _value;

    public int Value
    {
        get => _value;
        set => _value = value;
    }
}
```

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.
To report it as an error, set:

```ini
[*.cs]
dotnet_diagnostic.SST1421.severity = error
```

## When to suppress

Suppress when a framework requires a write-only property, or replacing a published
property with a method would break callers. Do not add a getter that exposes a
secret merely to satisfy the rule.
