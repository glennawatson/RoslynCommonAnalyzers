# SST1422 — Private fields used only as locals should be local variables

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Disabled (opt-in) |

## Cause

A private instance field is used by only one method, and that method's first
statement assigns it a value without reading its old value. The field holds
temporary data for that call and can be a local variable.

The rule excludes fields with an initializer or attributes, declarations containing
several fields, and fields in partial types. It also excludes fields referenced by
a lambda, an anonymous method, a local function, or code outside the one method.

An initial `+=`, `??=`, conditional assignment, or assignment such as
`_count = _count + 1` does not qualify: it can depend on a value from an earlier call.

## How to fix violations

Replace the first assignment with a local variable declaration, update the method's
references, and remove the field. There is no automatic code fix.

## Example

Bad, when the rule is enabled:

```csharp
public class Calculator
{
    private int _total;

    public int Sum(int value)
    {
        _total = 0;
        _total += value;
        return _total;
    }
}
```

Corrected:

```csharp
public class Calculator
{
    public int Sum(int value)
    {
        int total = 0;
        total += value;
        return total;
    }
}
```

## Configuration

The rule is disabled by default and has no rule-specific options. Enable it as an
error with:

```ini
[*.cs]
dotnet_diagnostic.SST1422.severity = error
```

Use `warning` instead for a warning, or `none` to disable it.

## When to suppress

Suppress when code outside the method needs the field, such as a framework that
reads it by name through reflection. Check that removing the field will not change
that behavior.
