# SST1423 — Switch statements should not have too many sections

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled; maximum 30 sections |

## Cause

A `switch` statement has more sections than the configured maximum, which defaults
to 30. Each group of labels that shares a body is one section. A `default` section
counts too. Switch expressions are not checked.

## How to fix violations

Group labels that perform the same work. For a larger change, split the work into
smaller methods or use a lookup table when the switch maps inputs to values.

There is no automatic code fix.

## Example

With `stylesharp.SST1423.max_switch_sections = 2`, this three-section switch is
reported:

```csharp
public class Classifier
{
    public int Classify(int value)
    {
        switch (value)
        {
            case 0:
                return 1;
            case 1:
                return 1;
            default:
                return 0;
        }
    }
}
```

Corrected: the same behavior uses two sections.

```csharp
public class Classifier
{
    public int Classify(int value)
    {
        switch (value)
        {
            case 0:
            case 1:
                return 1;
            default:
                return 0;
        }
    }
}
```

## Configuration

The rule is enabled as a warning by default. This example reports it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST1423.severity = error
stylesharp.max_switch_sections = 30
stylesharp.SST1423.max_switch_sections = 20
```

Both maximum settings accept positive whole numbers. A valid rule-specific value
takes precedence over the general value. If neither value is valid, the maximum
is 30.

## When to suppress

Suppress when a complete switch is easier to review than separate methods, such
as a protocol or instruction dispatcher. Keep it when measurement shows that a
replacement would add meaningful runtime cost. Raise the limit if this applies
throughout the project.
