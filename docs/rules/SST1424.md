# SST1424 — Fields that are never reassigned should be readonly

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled (opt-in) |

## Cause

A field declared `private` is never assigned outside its initializer or its type's
instance constructors. Adding `readonly` prevents later reassignment. For a field
that holds an object, this prevents replacing the object; it does not freeze the
object's contents.

The rule excludes partial types and fields marked `static`, `const`, `readonly`,
or `volatile`. Assignments inside lambdas or local functions count as outside the
constructor, even when those functions are declared inside it.

Mutable struct fields are excluded when code outside the constructor changes them
or calls a member that is not `readonly`. Making such a field `readonly` can make
those calls work on a copy and lose the changes. Passing a field by `ref` or `out`
outside a constructor also prevents a report.

## Example

Bad, when the rule is enabled:

```csharp
public class Settings
{
    private int _value;

    public Settings(int value) => _value = value;
}
```

Corrected:

```csharp
public class Settings
{
    private readonly int _value;

    public Settings(int value) => _value = value;
}
```

## Code fix

The fix adds `readonly` to the field declaration. If the declaration contains
several fields, all become `readonly`; the rule reports it only when every field
qualifies. Initializers and constructor assignments stay in place.

## Configuration

The rule is disabled by default and has no rule-specific options. Enable it as an
error with:

```ini
[*.cs]
dotnet_diagnostic.SST1424.severity = error
```

Use `warning` instead for a warning, or `none` to disable it.

## When to suppress

Suppress when a framework must write the field after construction through
reflection or deserialization. Confirm that it requires a writable field before
keeping the suppression.
