# SST1425 — Do not reassign captured primary-constructor parameters

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

Code assigns to, increments, decrements, or passes by `ref` or `out` a parameter
declared in a class or struct's primary constructor. These are the parameters
written after the type name, a C# 12 feature.

When a member uses one of these parameters, the object stores its value.
Reassigning it changes the object's state, even though the name looks like an
ordinary parameter. An explicit field makes that state clear.

Record primary constructors and ordinary method parameters are excluded.

## How to fix violations

Initialize a field from the parameter and change the field instead. Use a local
variable if the changed value is needed only during one call.

There is no automatic code fix.

## Example

Bad:

```csharp
public class Counter(int count)
{
    public int Value => count;

    public void Reset() => count = 0;
}
```

Corrected:

```csharp
public class Counter(int count)
{
    private int _count = count;

    public int Value => _count;

    public void Reset() => _count = 0;
}
```

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.
To report it as an error, set:

```ini
[*.cs]
dotnet_diagnostic.SST1425.severity = error
```

## When to suppress

Suppress when the parameter is deliberately used as mutable object state and
that convention is clear to the people maintaining the type. Prefer an explicit
field when the state changes in several members.
