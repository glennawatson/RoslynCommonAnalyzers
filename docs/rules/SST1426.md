# SST1426 — Use [SuppressMessage] instead of #pragma warning disable

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes, for a matched pair covering one declaration |
| Default | Enabled |

## Cause

A `#pragma warning disable` directive names an analyzer warning. The directive
turns that warning off until a matching restore or the end of the file.
A `[SuppressMessage]` attribute attaches the suppression and its reason to a
specific declaration.

Directives naming only compiler warnings, such as `CS0168` or `0168`, are excluded:
the compiler requires a pragma for those warnings. A directive mixing compiler
and analyzer warnings is reported. A disable directive with no codes is not
reported.

## Example

Bad:

```csharp
internal class Settings
{
    #pragma warning disable SST1309
    private int field;
    #pragma warning restore SST1309
}
```

Corrected, when the field name must be kept:

```csharp
internal class Settings
{
    [System.Diagnostics.CodeAnalysis.SuppressMessage(
        "Naming", "SST1309", Justification = "The file format requires this field name.")]
    private int field;
}
```

## Code fix

The fix adds one fully qualified `[SuppressMessage]` attribute per warning code
to the enclosing declaration. A pragma inside a method becomes an attribute on
the whole method. The fix inserts `Justification = "<Pending>"`; replace that
placeholder with the reason for the suppression.

The fix is offered only when all codes are analyzer warnings, a following
`restore` explicitly names every moved code, and the pair covers only one member
or type. There is no fix for a missing restore, a restore with no codes, a region
covering several members, or a directive mixing compiler and analyzer codes.
Handle those cases by adding attributes to the affected declarations and keeping
any compiler-warning pragmas that are still needed.

The fix removes both directive lines, including comments on them. It also removes
any extra warning codes listed on the matching restore. Review the preview and
keep any comments or restores that are still needed.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.
To report it as an error, set:

```ini
[*.cs]
dotnet_diagnostic.SST1426.severity = error
```

## When to suppress

Keep a narrowly scoped pragma when the diagnostic cannot be suppressed with a
declaration attribute, such as a warning about file-level text, or when an
attribute would suppress too much of a method. Record why the pragma is needed.
Compiler-only pragmas already need no suppression of this rule.
