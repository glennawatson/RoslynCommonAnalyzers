# SST1427 — Protected members of sealed types should not be used

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A member of a sealed type has a `protected` modifier. A sealed type cannot have
derived types, so that modifier grants no useful access to derived code.

The rule checks methods, constructors, properties, indexers, events, and fields.
It also reports `protected internal` and `private protected` declarations.
Overrides are excluded because they must keep the inherited member's access.

## Example

Bad:

```csharp
public sealed class Worker
{
    protected void Run() { }
}
```

Corrected:

```csharp
public sealed class Worker
{
    void Run() { }
}
```

## Code fix

The fix removes `protected`. A member with no remaining access modifier is
private. `protected internal` becomes `internal`, and `private protected` becomes
`private`. It does not add an explicit `private` keyword where none was present.

Comments attached to the removed modifier can be lost. Check the preview if a
comment sits between the modifier and the rest of the declaration.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.
To report it as an error, set:

```ini
[*.cs]
dotnet_diagnostic.SST1427.severity = error
```

## When to suppress

Suppress when a framework inspects and depends on the declared access through
reflection. Otherwise, remove the modifier. If the type is intended to support
inheritance, review whether it should be sealed.
