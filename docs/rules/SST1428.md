# SST1428 — Abstract types should not declare public constructors

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An abstract type declares a `public` instance constructor. Callers cannot create
the abstract type directly. A `protected` constructor makes clear that derived
types use it during construction.

The rule also applies when `abstract` appears on another part of a partial type.
It does not report non-public constructors, static constructors, or primary
constructors written in the type declaration.

## Example

Bad:

```csharp
public abstract class Shape
{
    public Shape() { }
}
```

Corrected:

```csharp
public abstract class Shape
{
    protected Shape() { }
}
```

## Code fix

The fix changes `public` to `protected`. It preserves the constructor's body,
parameters, comments, and surrounding whitespace.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.
To report it as an error, set:

```ini
[*.cs]
dotnet_diagnostic.SST1428.severity = error
```

## When to suppress

Suppress when a framework or tool requires the constructor to be public, such as
one that discovers constructors through reflection. Check compatibility before
changing a constructor in a published library.
