# SST1429 — A catch of the base exception should not swallow it

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |
| Analyzer | `ExceptionHandlingAnalyzer` |

## Cause

A `catch (Exception)` — or a bare `catch` — has an empty body, so it silently discards every
error, including ones the code is not prepared for.

```csharp
// 👎 reported
try
{
    Process();
}
catch (Exception)
{
}

// 👍
try
{
    Process();
}
catch (Exception ex)
{
    logger.LogError(ex);
    throw;
}
```

## Rule description

The clause is reported when its body has no statements and either it is a bare `catch { }` or
its declared type is the base `System.Exception`. A `when` filter, a narrower exception type,
or any statement in the body all mark the catch as deliberate and are left alone. The empty
body is checked syntactically; the caught type is confirmed against `System.Exception`
semantically.

No automatic code fix is offered, because the right handling depends on intent — log, rethrow,
or narrow the caught type.

## Configuration

A catch whose body only hands back a constant swallows the error just as completely — the caller
cannot tell a failure from a legitimate result — but that shape is also how a Try-style member reports
"no value", so only the codebase knows which it is. It is reported where you ask for it:

```ini
[*.cs]
# Rule-specific
stylesharp.SST1429.check_constant_returning_catch = true

# Project-wide
stylesharp.check_constant_returning_catch = true
```

| Option | Values | Default | Effect |
| --- | --- | --- | --- |
| `check_constant_returning_catch` | `true` / `false` | `false` | Also report a catch whose body is a single `return` of a constant, a `default`, or nothing at all. |

```csharp
// reported only when the option is enabled
try
{
    return int.Parse(text);
}
catch (Exception)
{
    return 0;
}
```

A body that does anything else — logs, rethrows, or returns a value derived from the exception — is
handling the error and is never reported.

## How to fix violations

Handle the exception, rethrow it, or catch a narrower type. If the exception genuinely must be
ignored, add a comment and a `when` filter or a narrower type that documents the intent.
