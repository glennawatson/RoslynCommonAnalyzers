# SST1429 — A catch of the base exception should not swallow it

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `catch (System.Exception)` or bare `catch` has an empty body and no `when`
filter. It discards every exception it catches, including failures the code is
not prepared to handle. A comment alone does not make the body non-empty.

Catches of more specific exception types and catches with a `when` filter are
excluded. By default, any statement in the body also prevents a report. You can
enable an additional check for bodies that only return a constant.

## How to fix violations

Handle the failure, rethrow it, or catch only the exceptions you can handle. Remove
the catch if its only purpose would be to rethrow. There is no automatic code fix.

## Example

Bad:

```csharp
using System;

public class Runner
{
    public void Run(Action action)
    {
        try
        {
            action();
        }
        catch (Exception)
        {
        }
    }
}
```

Corrected, when the failure should be logged and passed to the caller:

```csharp
using System;

public class Runner
{
    public void Run(Action action)
    {
        try
        {
            action();
        }
        catch (Exception ex)
        {
            Console.WriteLine(ex);
            throw;
        }
    }
}
```

## Configuration

The rule is enabled as a warning by default. This example reports it as an error
and keeps the optional check disabled:

```ini
[*.cs]
dotnet_diagnostic.SST1429.severity = error
stylesharp.check_constant_returning_catch = false
stylesharp.SST1429.check_constant_returning_catch = false
```

Both option keys accept `true` or `false`; the default is `false`. A valid
rule-specific value takes precedence over the general value. With `true`, a
catch is also reported when its only statement is `return;` or a return of a
constant, `null`, `default`, or `default(T)`. The same exclusions for specific
exception types and `when` filters apply.

## When to suppress

Suppress only when discarding any exception is an intentional part of the
operation's contract, such as cleanup that must not replace an earlier failure.
Explain that decision. For a documented fallback result, keep the constant-return
option disabled or suppress the affected catch.
