# SST1430 — Rethrow with 'throw;' to preserve the stack trace

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `catch` block throws its caught variable with `throw ex;`. This resets the stack
trace, the record of calls that led to the error, at the rethrow. Use `throw;` to
keep the original failure location.

The rule reports a thrown variable only when it belongs to the nearest enclosing
catch. It excludes throws from a lambda or local function declared inside that
catch, where a bare rethrow of the outer exception is not allowed. Throwing a new
exception or a different variable is also excluded.

## Example

Bad:

```csharp
using System;

public class Runner
{
    public void Run(Action action)
    {
        try
        {
            action();
        }
        catch (Exception ex)
        {
            Console.WriteLine(ex);
            throw ex;
        }
    }
}
```

Corrected:

```csharp
using System;

public class Runner
{
    public void Run(Action action)
    {
        try
        {
            action();
        }
        catch (Exception ex)
        {
            Console.WriteLine(ex);
            throw;
        }
    }
}
```

## Code fix

The fix replaces `throw ex;` with `throw;`. It keeps the catch declaration and
other statements. If the exception variable becomes unused, remove it yourself.
Comments between `throw` and the semicolon can be lost when the expression is
removed. Comments after the semicolon are kept.

## Configuration

The rule is enabled as a warning by default. It has no rule-specific options.
To report it as an error, set:

```ini
[*.cs]
dotnet_diagnostic.SST1430.severity = error
```

## When to suppress

Suppress only when resetting the stack trace is intentional. If the catch variable
has been assigned a different exception, review which exception should be thrown:
`throw;` rethrows the exception caught on entry, not its replacement.
