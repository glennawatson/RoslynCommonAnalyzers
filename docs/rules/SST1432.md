# SST1432 — Classes with only static members should be static

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled (opt-in) |

## Cause

A non-empty class contains only static members, constants, nested types, or static
constructors. Marking it `static` prevents callers from creating instances or
deriving from it.

The rule excludes classes with instance members, instance constructors, primary
constructors, a declared base class, or implemented interfaces. Classes already
marked `static` or `abstract` are also excluded. For a partial class, every part
must qualify; the rule reports the first part once.

## Example

Bad, when the rule is enabled:

```csharp
public class Helpers
{
    public static int Add(int x, int y) => x + y;
}
```

Corrected:

```csharp
public static class Helpers
{
    public static int Add(int x, int y) => x + y;
}
```

## Code fix

The fix adds `static` to the reported class declaration, before `partial` when
present. Adding it to one part makes the whole partial type static. It keeps the
members and does not update callers.

For a sealed class, remove `sealed` as well. The fix leaves that modifier in place,
but C# does not allow a class to be both `sealed` and `static`.

## Configuration

The rule is disabled by default and has no rule-specific options. Making a class
static can break existing callers, so enable it where that change is acceptable:

```ini
[*.cs]
dotnet_diagnostic.SST1432.severity = error
```

Use `warning` instead for a warning, or `none` to disable it.

## When to suppress

Suppress when callers must create or derive from the type, use it as a type
argument, or pass it to a framework that requires an instantiable class. Keep the
existing shape when changing a published type would break those callers.
