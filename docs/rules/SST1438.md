# SST1438 — Methods should not be empty

## Cause

A method has a block body with no statements and no comment explaining why it does nothing.

The rule skips methods with attributes, `virtual`, `override`, or `partial` methods, and methods that implement an interface member. Methods without a body, such as abstract or extern declarations, are also excluded.

## Example

Before, with the rule enabled:

```csharp
public class Settings
{
    public void Configure()
    {
    }
}
```

After, when doing nothing is intentional:

```csharp
public class Settings
{
    public void Configure()
    {
        // No configuration is needed for the default pipeline.
    }
}
```

## How to fix violations

Implement the missing work, or put an explanatory `//` or `/* ... */` comment inside the body. There is no automatic code fix. Throw an exception only if callers should be told the operation is unsupported; throwing changes the method's behavior.

## Configuration

Disabled by default. Enable it as a warning with:

```ini
[*.cs]
dotnet_diagnostic.SST1438.severity = warning
```

There are no rule-specific options. Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [configuration](../CONFIGURATION.md).

## When to suppress

A comment inside an intentionally empty method is usually enough. Suppress only when the method must stay empty and adding that comment is impractical, such as in a file maintained by another tool.
