# SST1439 — Nested code blocks should not be left empty

## Cause

An empty `{ }` block is the body of a `for`, `foreach`, `while`, `do`, `if`, `lock`, `fixed`, or `using` statement. A comment inside the block prevents a report.

This rule does not report method, constructor, or accessor bodies, or a bare semicolon used as a statement body. Empty `else` blocks are covered by [SST1180](SST1180.md).

## Example

Before:

```csharp
public class Worker
{
    public void Run(bool flag)
    {
        while (flag)
        {
        }
    }
}
```

After, if the loop should clear the flag:

```csharp
public class Worker
{
    public void Run(bool flag)
    {
        while (flag)
        {
            flag = false;
        }
    }
}
```

## How to fix violations

Add the missing work, remove the statement, or explain the intentional empty body with a comment inside it. Check whether evaluating the condition or acquiring and disposing a resource performs needed work before removing the statement. There is no automatic code fix.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1439.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [configuration](../CONFIGURATION.md).

## When to suppress

An explanatory comment is enough for a loop that does its work in the condition. Suppress only when an empty body is required and adding a comment is impractical.
