# SST1441 — Remove private fields that are never read

## Cause

A field or property declared with `private` is assigned a value elsewhere in its type, but that value is never read. Assigning through an `out` argument counts as a write. Operations such as `+=`, `++`, or passing by `ref` count as reads as well as writes and are not reported.

Members with attributes and constant fields are excluded. Reads across partial declarations, including generated declarations, count. An initializer alone does not count as a write for this rule; a member with no other references is covered by [SST1440](SST1440.md).

## Example

Before:

```csharp
public class Worker
{
    private int _value;

    public int Run()
    {
        _value = 1;
        return 1;
    }
}
```

After:

```csharp
public class Worker
{
    public int Run() => 1;
}
```

## How to fix violations

Remove the member and its unused assignments, or add the missing use if the value is needed. Preserve any work done by the assigned expression or a property setter. There is no automatic code fix.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1441.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a framework reads the value by name at runtime, or when a write-only property deliberately performs work in its setter. Record that reason beside the member.
