# SST1444 — Loops should be able to iterate again

## Cause

A `for`, `foreach`, `while`, or `do` loop contains an unconditional `break`, `return`, or `throw`, with no conditional `continue` path. The rule also reports an unconditional `continue`. A `continue` can still allow another iteration; this report asks you to review the loop's structure.

Jumps inside `if`/`else`, switch cases, or `try`/`catch`/`finally` blocks are excluded. Jumps inside nested loops or nested functions do not count against the outer loop. A `break` that exits a nested switch is also excluded.

## Example

Before:

```csharp
public class Reader
{
    public int FirstOrZero(int[] values)
    {
        foreach (var value in values)
        {
            return value;
        }

        return 0;
    }
}
```

After:

```csharp
public class Reader
{
    public int FirstOrZero(int[] values)
    {
        if (values.Length == 0)
        {
            return 0;
        }

        return values[0];
    }
}
```

## How to fix violations

Replace the loop with direct code when it only needs one item. If it should process multiple items, move the exit behind the condition that should end processing. There is no automatic code fix.

## Configuration

Enabled by default as a warning. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1444.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a loop deliberately consumes one item from a sequence and preserves needed enumeration or disposal behavior. Also suppress when an unconditional `continue` is deliberate and the loop still performs useful work on each iteration.
