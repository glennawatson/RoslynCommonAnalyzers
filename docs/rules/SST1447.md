# SST1447 — Equality overrides should not delegate to object

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

An `Equals` or `GetHashCode` method returns `base.Equals(...)` or
`base.GetHashCode()` directly, and that call reaches the implementation on
`object`. This includes a direct `return` inside a branch.

`object.Equals` checks whether two references point to the same object.
`object.GetHashCode` supplies a hash based on that object's identity. Neither
uses the field values that define value equality.

Calls to a base class's own override are not reported. A reference check used
as a shortcut, such as `if (base.Equals(obj)) return true;`, is also excluded
when the method goes on to compare values. Calls inside local functions or
lambdas are not checked.

## Example

These overrides ignore `Value`:

```csharp
public sealed class Item
{
    public int Value { get; set; }

    public override bool Equals(object obj) => base.Equals(obj);
    public override int GetHashCode() => base.GetHashCode();
}
```

Compare the values that define equality and use those same values for the hash:

```csharp
public sealed class Item
{
    public int Value { get; set; }

    public override bool Equals(object obj) =>
        obj is Item other && other.Value == Value;

    public override int GetHashCode() => Value;
}
```

If objects should compare by identity, remove both overrides instead.

## Configuration

There are no rule-specific options. The default severity is `warning`:

```ini
[*.cs]
dotnet_diagnostic.SST1447.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an override must remain for compatibility and deliberately
preserves object identity. Keep `Equals` and `GetHashCode` consistent.
