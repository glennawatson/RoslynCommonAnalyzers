# SST1449 — Avoid writing directly to the console

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

Code calls `System.Console.Write` or `System.Console.WriteLine`, using
`Console` or its fully qualified name. Diagnostic messages written this way
bypass the application's logging levels and output settings.

Console reads, writes through a `TextWriter`, and methods on a user-defined
type named `Console` are not reported. Calls through a differently named
alias or an unqualified `using static` call are not checked.

## Example

This method chooses the output destination itself:

```csharp
public class Processor
{
    public void Process() => System.Console.WriteLine("processed");
}
```

Let the caller choose a writer:

```csharp
using System.IO;

public class Processor
{
    public void Process(TextWriter writer) => writer.WriteLine("processed");
}
```

For diagnostic messages, use the application's logger so it can control
message levels and destinations.

## Configuration

There are no rule-specific options. The default severity is `warning`:

```ini
[*.cs]
dotnet_diagnostic.SST1449.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress for deliberate command-line output or tests of console output.
Set the severity to `none` for a console application where direct writes are
the intended way to communicate with the user.
