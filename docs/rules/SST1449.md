# SST1449 — Avoid writing directly to the console

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

Code calls `Console.Write` or `Console.WriteLine`. The rule also reports these
calls through `Console.Out` and `Console.Error`. Using the full name
`System.Console` has the same effect.

These calls write straight to the console. They do not use the application's
logging levels or output settings.

Console reads, writes through another `TextWriter`, and methods on a
type named `Console` that you define are not reported. The rule does not check
calls through another name set with `using`, or bare calls such as `WriteLine()`
enabled by `using static`.

## Example

This method chooses the output destination itself:

```csharp
public class Processor
{
    public void Process() => System.Console.WriteLine("processed");
}
```

This also chooses the destination directly:

```csharp
public class Processor
{
    public void Process() => System.Console.Out.WriteLine("processed");
}
```

Let the caller choose a writer:

```csharp
using System.IO;

public class Processor
{
    public void Process(TextWriter writer) => writer.WriteLine("processed");
}
```

For diagnostic messages, use the application's logger so it can control
message levels and destinations.

## How to fix violations

Replace the direct console call with the application's logger or pass a
`TextWriter` into the method. There is no automatic code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`:

```ini
[*.cs]
dotnet_diagnostic.SST1449.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress for deliberate command-line output or tests of console output.
Set the severity to `none` for a console application where direct writes are
the intended way to communicate with the user.
