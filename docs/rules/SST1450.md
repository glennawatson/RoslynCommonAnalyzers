# SST1450 — Store files as UTF-8 without a byte order mark

**Category:** Maintainability
**Severity:** Warning (disabled by default)
**Code fix:** None

## Cause

A source file's encoding includes a byte order mark (BOM), a short marker at
the start of the file. The diagnostic appears at the start of the file.
This check detects the marker; it does not verify that every file without
one uses UTF-8. Other encodings with a BOM are also reported.

## Example

Before: this file is saved as **UTF-8 with BOM** and is reported:

```csharp
internal class C { }
```

After: save the same code as **UTF-8 without BOM**:

```csharp
internal class C { }
```

The code stays the same. Choose the encoding in your editor's save options;
the marker is not visible in these code samples.

## Configuration

The rule is disabled by default and has no rule-specific options. Enable it
and set the editor's encoding preference with:

```ini
[*.cs]
charset = utf-8
dotnet_diagnostic.SST1450.severity = warning
dotnet_diagnostic.SST1412.severity = none
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.
`charset = utf-8` requests UTF-8 without a BOM from editors that support
EditorConfig; `utf-8-bom` requests a BOM. Changing this setting may require
saving existing files again.

[SST1412](SST1412.md) requires the opposite encoding preference. Enable at
most one of these rules. See [configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled when project tools require a BOM. For an exception,
set the severity to `none` in an EditorConfig section matching that file.
A `#pragma` inside the file cannot suppress a diagnostic at its first position.
