# SST1451 — Specify a DateTimeKind when creating a DateTime

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

A `System.DateTime` constructor takes arguments but no `DateTimeKind`.
This includes `DateTime value = new(...)`. The result has
`DateTimeKind.Unspecified`, so later conversions have to assume whether
the value is local time or UTC.

The parameterless constructor, `default(DateTime)`, and constructors that
accept a kind are not reported. This rule does not check clock properties
such as `DateTime.Now` or `DateTime.UtcNow`.

## Example

The date has no stated time zone convention:

```csharp
using System;

public class C
{
    public DateTime Start() => new DateTime(2024, 1, 1);
}
```

If it represents midnight UTC, state that:

```csharp
using System;

public class C
{
    public DateTime Start() =>
        new DateTime(2024, 1, 1, 0, 0, 0, DateTimeKind.Utc);
}
```

Choose `Utc`, `Local`, or `Unspecified` to match the value's meaning.
Adding a kind labels the value; it does not convert the clock time.
Use `DateTimeOffset` when the value needs to carry an explicit UTC offset.

## Configuration

There are no rule-specific options. The default severity is `warning`:

```ini
[*.cs]
dotnet_diagnostic.SST1451.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an API deliberately uses an unspecified date and time, and
changing the constructor would obscure that contract. For a date without
a time, consider `DateOnly` when the target framework supports it.
