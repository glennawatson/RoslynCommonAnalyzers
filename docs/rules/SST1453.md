# SST1453 — Remove unreachable statements

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

A statement follows `return`, `throw`, `break`, `continue`, or `goto` in
the same block. That exit prevents the later statement from running.
The rule does not follow exits through nested `if` statements or other
branches to decide whether later code can run.

## Example

The write cannot run after the return:

```csharp
using System.IO;

public sealed class C
{
    public int M(TextWriter writer)
    {
        return 1;
        writer.WriteLine(1);
    }
}
```

Move it before the return if it should run:

```csharp
using System.IO;

public sealed class C
{
    public int M(TextWriter writer)
    {
        writer.WriteLine(1);
        return 1;
    }
}
```

Otherwise, delete the unreachable statement. The bad example also produces
a compiler warning about unreachable code.

## What is not reported

A local function declaration after an exit is allowed: it runs when called,
not when execution reaches its declaration. Statements after that local
function are still reported if they follow an exit.

A labeled statement and the statements following it are not reported until
another direct exit, because a `goto` can reach the label.

## Configuration

There are no rule-specific options. The default severity is `warning`:

```ini
[*.cs]
dotnet_diagnostic.SST1453.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress for a test that deliberately contains unreachable statements.
In application code, remove the dead statement or correct its position.
