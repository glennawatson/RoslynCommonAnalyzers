# SST1454 — Validate composite format placeholders

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

A `string.Format` call has a constant format string with a numbered
placeholder beyond the supplied arguments. Placeholders start at zero:
`{0}` uses the first value, `{1}` uses the second, and so on. Referring to
a missing value throws `FormatException` when the call runs.

The rule checks constant strings, including `const` values. It accepts
escaped braces (`{{` and `}}`). It does not report unused arguments,
non-constant strings, or malformed braces. Calls with a positional format
provider before the format string are not checked.

## Example

This call supplies one value but asks for the second:

```csharp
public sealed class C
{
    public string Message(string name) => string.Format("Hello {1}", name);
}
```

Use the first value:

```csharp
public sealed class C
{
    public string Message(string name) => string.Format("Hello {0}", name);
}
```

If the second value was intended, supply the missing argument instead.

## Configuration

There are no rule-specific options. The default severity is `warning`:

```ini
[*.cs]
dotnet_diagnostic.SST1454.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress for a test that deliberately expects `FormatException`. Also
suppress after checking an `object[]` argument has enough values: the rule
counts an array passed as one argument as one value, not its elements.
