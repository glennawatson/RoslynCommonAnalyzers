# SST1455 — Remove unused unsafe modifiers

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

A type, delegate, or member declares `unsafe` without any pointer type,
function pointer, pointer operation, `fixed` statement, `sizeof`
expression, or nested `unsafe` block. Removing the modifier makes it clear
that the declaration does not need unsafe code.

Uses inside nested declarations also count. Any `sizeof` expression keeps
the modifier from being reported, including `sizeof(int)`. Fields, event
fields, local functions, and `unsafe` blocks themselves are not checked
for an unnecessary modifier.

## Example

This method performs no unsafe operation:

```csharp
public sealed class C
{
    public unsafe int Count(int[] values) => values.Length;
}
```

Remove `unsafe`:

```csharp
public sealed class C
{
    public int Count(int[] values) => values.Length;
}
```

The bad example requires the project's **Allow unsafe code** setting to
compile. Removing this modifier does not require disabling unsafe code
elsewhere in the project.

## Configuration

There are no rule-specific options. The default severity is `warning`:

```ini
[*.cs]
dotnet_diagnostic.SST1455.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when shared code needs the modifier under another set of
conditional compilation symbols. Otherwise, remove the unused modifier.
