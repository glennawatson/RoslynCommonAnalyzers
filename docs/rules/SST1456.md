# SST1456 — Avoid readonly fields of mutable structs

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

A `readonly` field stores a struct declared in the project's source, and
that struct is not marked `readonly`. The rule reports the field even if
the struct exposes no writable members or the field is never read.
Structs from referenced libraries, built-in types, and `readonly struct`
types are excluded.

Calling a member that can change such a field's value can create a copy.
The member then changes the copy, leaving the stored value unchanged.

## Example

This readonly field stores a struct with a writable value:

```csharp
public struct Counter
{
    public int Value;
}

public sealed class Holder
{
    private readonly Counter _counter;

    public Holder(int value) => _counter = new Counter { Value = value };
    public int Value => _counter.Value;
}
```

If the value should be immutable, make the struct readonly and initialize
its value in a constructor:

```csharp
public readonly struct Counter
{
    public Counter(int value) => Value = value;
    public int Value { get; }
}

public sealed class Holder
{
    private readonly Counter _counter;

    public Holder(int value) => _counter = new Counter(value);
    public int Value => _counter.Value;
}
```

If the stored struct must change, remove `readonly` from the field instead.
Review callers before removing writable members from a public struct.

## Configuration

There are no rule-specific options. The default severity is `warning`:

```ini
[*.cs]
dotnet_diagnostic.SST1456.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the struct cannot be changed and the field's member uses have
been checked for unwanted copies or lost changes. This also applies to
structs that are immutable by design but cannot be marked `readonly`.
