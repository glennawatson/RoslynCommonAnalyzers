# SST1457 — Keep global suppression targets resolvable

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

An assembly-level `SuppressMessage` attribute names a `Target` that cannot
be found in the project being compiled. The suppression may refer to a
declaration that was renamed or removed.

Targets beginning with `E:`, `F:`, `M:`, `N:`, `P:`, or `T:` are checked.
These identify events, fields, methods, namespaces, properties, and types.
Missing or empty targets and targets in other formats are not checked.
Attributes on individual declarations are also excluded. A target starting
with `~` is handled by [SST1458](SST1458.md) instead.

## Example

`C.Missing` does not exist:

```csharp
using System.Diagnostics.CodeAnalysis;

[assembly: SuppressMessage("Style", "SST1000",
    Justification = "Reviewed.", Scope = "member", Target = "M:C.Missing")]

public sealed class C
{
    public void M() { }
}
```

If the suppression belongs to `M`, correct its target:

```csharp
using System.Diagnostics.CodeAnalysis;

[assembly: SuppressMessage("Style", "SST1000",
    Justification = "Reviewed.", Scope = "member", Target = "M:C.M")]

public sealed class C
{
    public void M() { }
}
```

Include the namespace, containing type, and method parameter types when
needed to identify the declaration. If the suppression is unnecessary,
remove the attribute instead. A target that exists does not by itself
prove that the chosen diagnostic should be suppressed there.

## Configuration

There are no rule-specific options. The default severity is `warning`:

```ini
[*.cs]
dotnet_diagnostic.SST1457.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a shared suppression file deliberately includes declarations
available only in other target frameworks or build configurations. Prefer
conditional compilation around those attributes when practical.
