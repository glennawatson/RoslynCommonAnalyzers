# SST1458 - Use declaration ids directly in global suppressions

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

An assembly-level `SuppressMessage` attribute has a `Target` string that starts
with `~`. Remove that prefix and keep the declaration id: the string that names
the type or member, such as `M:C.M` for method `M` in class `C`.

Attributes on individual types or members are not reported. An assembly
attribute without a target is not reported either.

## Example

Before:

```csharp
using System.Diagnostics.CodeAnalysis;

[assembly: SuppressMessage("Style", "SST1000", Scope = "member", Target = "~M:C.M")]

public sealed class C
{
    public void M() { }
}
```

After:

```csharp
using System.Diagnostics.CodeAnalysis;

[assembly: SuppressMessage("Style", "SST1000", Scope = "member", Target = "M:C.M")]

public sealed class C
{
    public void M() { }
}
```

There is no automatic code fix. Edit `Target` by hand and check that the named
declaration exists. [SST1457](SST1457.md) reports declaration ids that do not
match a declaration.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1458.severity = error
```

Severity accepts `error`, `warning` (the default), `suggestion`, `silent`,
`none`, or `default` to restore the default severity.

There are no rule-specific options.

See [docs/CONFIGURATION.md](../CONFIGURATION.md) for configuration and
suppression syntax.

## When to suppress

Suppress when the same suppression file must be consumed by a tool that requires
the `~` prefix. Keep the required spelling for that tool.
