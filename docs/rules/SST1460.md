# SST1460 - Mark non-mutating struct members readonly

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

An instance member on a mutable struct can be marked `readonly` when its body
does not mutate state. That lets callers use it through readonly receivers
without a defensive copy and documents the member's non-mutating contract.

The analyzer deliberately under-reports. Calls, assignments, increment/decrement
operations, and `ref`/`out` arguments are treated as possible mutation.

## Example

```csharp
public struct Counter
{
    private int _value;
    public int Value() => _value; // SST1460
}
```

Use:

```csharp
public readonly int Value() => _value;
```

## A writable `ref` return is left alone

`readonly` makes the receiver a readonly reference, so a member handing out a
writable reference to one of the struct's own fields stops compiling with
"cannot return 'this' by reference". A `ref` return that is not `ref readonly`
is therefore never reported:

```csharp
public struct Counter
{
    private int _value;

    [UnscopedRef]
    public ref int Value => ref _value; // not reported
}
```

Whether the reference actually reaches the struct's storage takes semantic
analysis - `ref _value` does, `ref _items[0]` through a reference-type field
does not - so all of them stay silent. A `ref readonly` return is unaffected and
is still reported.
