# SST1460 - Mark non-mutating struct members readonly

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

An instance method or get-only property on a mutable `struct` can be marked
`readonly`. This states that the member does not change the struct. It also
avoids copying the struct when the member is called through a readonly field
or an `in` parameter.

The rule applies in C# 8 and later. It skips members containing calls,
assignments, increments, decrements, or arguments passed with `ref`, `out`, or
`in`. Static members, members already marked `readonly`, and members of a
`readonly struct` are excluded. Properties with `set` or `init` are excluded.

Writable `ref` returns are not reported because adding `readonly` can make
them invalid. A `ref readonly` return can still be reported.

## Example

Before:

```csharp
public struct Counter
{
    private int _value;

    public Counter(int value) => _value = value;

    public int Value() => _value;
}
```

After:

```csharp
public struct Counter
{
    private int _value;

    public Counter(int value) => _value = value;

    public readonly int Value() => _value;
}
```

There is no automatic code fix. Add `readonly` to the reported member.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1460.severity = error
```

Severity accepts `error`, `warning` (the default), `suggestion`, `silent`,
`none`, or `default` to restore the default severity.

There are no rule-specific options.

See [docs/CONFIGURATION.md](../CONFIGURATION.md) for configuration and
suppression syntax.

## When to suppress

Suppress when shared source must compile with a language version below C# 8,
or when the member relies on a property getter that changes the struct's state.
Check such a getter before promising that the member is readonly.
