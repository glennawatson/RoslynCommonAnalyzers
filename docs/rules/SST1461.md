# SST1461 - Remove a parameter the body never reads

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

A method, constructor, or local function declares a parameter whose name does
not appear in its body. Callers must pass a value that the code ignores. Remove
the parameter, or use it if the missing use is a bug.

A use in a constructor's `base(...)` or `this(...)` call counts. Uses in lambdas,
local functions, `nameof`, and string interpolation also count. A parameter
that is only assigned a value is not reported by this rule.

## What is not reported

- Members visible outside the assembly, unless enabled in configuration. A
  public member of an internal type is still checked.
- Overrides, virtual, abstract, partial, and extern members, and interface
  implementations.
- Members with attributes, and methods or constructors on attribute classes.
- Methods used as callbacks by name within their containing type.
- Methods with two parameters written as `(object, EventArgs)`, including
  `object?` and types derived from `EventArgs`.
- Declarations with a parameter type whose written name ends in
  `StreamingContext`, `DependencyObject`, `DependencyPropertyChangedEventArgs`,
  or `AvaloniaPropertyChangedEventArgs`.
- Bodies that only throw, parameters named `_`, and parameters with modifiers
  such as `ref`, `out`, `in`, `this`, or `params`.

An unread extension method receiver is covered by [SST1708](SST1708.md).

## Example

Before:

```csharp
internal class C
{
    public int Run() => Compute(1, 2);

    private int Compute(int used, int unused) => used;
}
```

After removing the unused parameter and its argument:

```csharp
internal class C
{
    public int Run() => Compute(1);

    private int Compute(int used) => used;
}
```

There is no automatic code fix. Update every call when removing a parameter.
If an argument calls a method whose work is still needed, keep that call as a
separate statement.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1461.severity = error
```

Severity accepts `error`, `warning` (the default), `suggestion`, `silent`,
`none`, or `default` to restore the default severity.

The public API option accepts `true` or `false` and defaults to `false`:

```ini
[*.cs]
stylesharp.SST1461.unread_parameter_include_public_api = false
stylesharp.unread_parameter_include_public_api = false
```

The rule-specific key takes precedence over the project-wide key. Set it to
`true` to include members visible outside the assembly. Removing their
parameters breaks callers, so enable this only when you can update them.

See [docs/CONFIGURATION.md](../CONFIGURATION.md) for configuration and
suppression syntax.

## When to suppress

Suppress when a caller or framework requires the parameter list to stay intact
and the rule does not recognize that requirement. A parameter named `_` is
also excluded, but renaming a parameter can break callers that pass it by name.
