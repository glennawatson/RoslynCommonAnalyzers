# SST1462 - Remove suppressions for disabled diagnostics

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

A `SuppressMessage` attribute names a diagnostic configured as `none` or
`silent` for the file. The attribute is unnecessary because the diagnostic
does not produce a visible report. A diagnostic disabled through `NoWarn` or
a ruleset is also covered.

Both assembly-level attributes and attributes on declarations are checked.
The rule reads the id before any colon in the check string, so
`"SST1000:Rule title"` refers to `SST1000`. Suppressions for enabled diagnostics
and `#pragma warning` directives are not reported.

## Example

With this configuration:

```ini
[*.cs]
dotnet_diagnostic.SST1000.severity = none
```

Before:

```csharp
using System.Diagnostics.CodeAnalysis;

[SuppressMessage("Style", "SST1000", Justification = "Reviewed.")]
public sealed class C
{
}
```

After:

```csharp
public sealed class C
{
}
```

There is no automatic code fix. Remove the attribute and remove its `using`
directive if nothing else needs it.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1462.severity = error
```

Severity accepts `error`, `warning` (the default), `suggestion`, `silent`,
`none`, or `default` to restore the default severity.

There are no rule-specific options.

See [docs/CONFIGURATION.md](../CONFIGURATION.md) for configuration and
suppression syntax.

## When to suppress

Suppress when the same source is built in another configuration where the
diagnostic is enabled and the attribute is still needed there.
