# SST1463 - Use nameof for symbol-name strings

**Category:** Maintainability
**Severity:** Warning
**Code fix:** Use nameof (supports Fix All)

## Cause

A string literal is passed directly to a parameter whose name contains `name`,
ignoring case, and the string matches a name available at that point in the
code. Use `nameof` when the string is meant to name that member, variable, or
type. Then renaming it also updates the string.

The rule applies in C# 6 and later. Empty strings, namespace names, names that
match only a generic type, and local variables declared at or after the string
are excluded. Strings passed to parameters such as `message` are not reported.

## Example

Before:

```csharp
public sealed class C
{
    public int Count { get; set; }

    public void M() => Notify("Count");

    private static void Notify(string propertyName) { }
}
```

After:

```csharp
public sealed class C
{
    public int Count { get; set; }

    public void M() => Notify(nameof(Count));

    private static void Notify(string propertyName) { }
}
```

## Code fix

The fix replaces only the string literal with `nameof(Count)`. It keeps a named
argument such as `propertyName:` and comments around the literal. It supports
Fix All. No fix is offered when the string cannot be written as a valid C# name
without an escape, such as a name that needs an `@` prefix.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1463.severity = error
```

Severity accepts `error`, `warning` (the default), `suggestion`, `silent`,
`none`, or `default` to restore the default severity.

There are no rule-specific options.

See [docs/CONFIGURATION.md](../CONFIGURATION.md) for configuration and
suppression syntax.

## When to suppress

Suppress when the string is a fixed external name, such as a file name, protocol
field, or stored key, that happens to match a C# name. Such strings must not
change when the C# member is renamed.
