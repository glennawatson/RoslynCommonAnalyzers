# SST1464 - Unwrap else after a branch that does not fall through

**Category:** Maintainability
**Severity:** Warning
**Code fix:** Unwrap the else clause (supports Fix All)

## Cause

An `else` follows an `if` branch that is a `return`, `throw`, `break`, or
`continue`, or a block ending directly in one of those statements. The branch
exits, so the code in the `else` can follow the `if` without the extra nesting.

An `else if` can also be reported. In a chain, every earlier branch must end
with one of those exits. A branch ending in another nested `if` is not enough,
even if every path through it returns.

## Example

Before:

```csharp
public sealed class C
{
    public int M(int value)
    {
        if (value > 0)
        {
            return 1;
        }
        else
        {
            return 2;
        }
    }
}
```

After:

```csharp
public sealed class C
{
    public int M(int value)
    {
        if (value > 0)
        {
            return 1;
        }

        return 2;
    }
}
```

## Code fix

The fix removes `else` and its braces, moves the statements after the `if`, and
adjusts their indentation. An `else if` becomes a separate `if` statement. It
supports Fix All.

The diagnostic can appear without a fix. The `if` must sit directly inside a
block. If the `else` declares a local variable or local function, the `if` must
be the block's last statement. Directives such as `#if` or `#region` within the
`else` also prevent the fix.

Comments attached to the removed `else` keyword or braces can be lost. Move
those comments onto the statements before applying the fix.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1464.severity = error
```

Severity accepts `error`, `warning` (the default), `suggestion`, `silent`,
`none`, or `default` to restore the default severity.

There are no rule-specific options.

See [docs/CONFIGURATION.md](../CONFIGURATION.md) for configuration and
suppression syntax.

## When to suppress

Suppress when keeping the branches together makes a set of related choices
easier to read, or when the braces are needed to keep local names separate.
