# SST1466 - Remove case labels that share a section with default

**Category:** Maintainability
**Severity:** Warning
**Code fix:** Remove redundant case label (supports Fix All)

## Cause

A `case` label shares the same statements as `default:` in a `switch`. The
default already handles that value, so the extra label can suggest special
handling that is not there. Pattern labels such as `case > 5:` are also checked.

Each non-default label in that section is reported. Labels in other sections
are not reported. A switch containing any `goto case` or `goto default` is
excluded because removing a label could break a jump.

## Example

Before:

```csharp
public sealed class C
{
    public int M(int value)
    {
        switch (value)
        {
            case 0:
                return 1;
            case 1:
            default:
                return 0;
        }
    }
}
```

After:

```csharp
public sealed class C
{
    public int M(int value)
    {
        switch (value)
        {
            case 0:
                return 1;
            default:
                return 0;
        }
    }
}
```

## Code fix

The fix deletes the reported label and keeps `default:` and the shared
statements. Fix All removes every reported label. Comments before a removed
label are kept; comments within it or after its colon can be lost. Move those
comments onto the shared statements before applying the fix.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1466.severity = error
```

Severity accepts `error`, `warning` (the default), `suggestion`, `silent`,
`none`, or `default` to restore the default severity.

There are no rule-specific options.

See [docs/CONFIGURATION.md](../CONFIGURATION.md) for configuration and
suppression syntax.

## When to suppress

Suppress when listing a value explicitly documents an intentional choice, such
as an enum value deliberately handled by the default branch. Also suppress
when evaluating a pattern or its `when` condition does work the program needs,
or when removing it would let a later case handle the value instead.
