# SST1467 - Enumerate with foreach instead of driving the enumerator by hand

**Category:** Maintainability
**Severity:** Warning
**Code fix:** Enumerate with foreach (supports Fix All)

## Cause

A local variable gets an enumerator from `GetEnumerator()`, and the next
statement is `while (e.MoveNext())`. The loop body uses that variable only to
read `Current`, and the variable is not used after the loop. Use `foreach` to
express the same walk through the collection with less code.

The rule skips `using` declarations, declarations with multiple variables,
loops separated from the declaration by another statement, and loops that
write to `Current` or use the enumerator for other work.

## Example

Before:

```csharp
using System.Collections.Generic;

public sealed class C
{
    public int Sum(List<int> values)
    {
        var total = 0;
        var e = values.GetEnumerator();
        while (e.MoveNext())
        {
            var value = e.Current;
            total += value;
        }

        return total;
    }
}
```

After:

```csharp
using System.Collections.Generic;

public sealed class C
{
    public int Sum(List<int> values)
    {
        var total = 0;
        foreach (var value in values)
        {
            total += value;
        }

        return total;
    }
}
```

## Code fix

The fix removes the enumerator declaration and replaces `while` with `foreach`
over the collection. When the body starts with a local initialized from its
only `Current` read, the fix moves that local's name and type into the `foreach`
header. Otherwise it introduces `var item` and replaces the `Current` reads
with `item`. It adjusts formatting and supports Fix All.

When the fix needs to introduce `item`, it is unavailable if that name appears
in the declaration or loop. Choose a different iteration name and rewrite the
loop by hand. A directive between the declaration and loop also prevents the fix.

Comments before the enumerator declaration are kept. Comments on the removed
declaration, the `while` header, or the local moved into the header can be lost.
Move them into the loop body before applying the fix.

The rewrite also changes cleanup: `foreach` disposes a disposable enumerator
when the loop ends, including on an exception. It reads `Current` once per
iteration, and its iteration variable cannot be assigned a new value. Check
these differences when using a custom enumerator or changing the local value
inside the loop.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1467.severity = error
```

Severity accepts `error`, `warning` (the default), `suggestion`, `silent`,
`none`, or `default` to restore the default severity.

There are no rule-specific options.

See [docs/CONFIGURATION.md](../CONFIGURATION.md) for configuration and
suppression syntax.

## When to suppress

Suppress when a custom enumerator requires different cleanup timing or repeated
`Current` reads have a deliberate effect. For an ordinary collection loop,
prefer `foreach` and its automatic cleanup.
