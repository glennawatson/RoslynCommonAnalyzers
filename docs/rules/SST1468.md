# SST1468 - Boolean logic should short-circuit

**Category:** Maintainability
**Severity:** Warning
**Code fix:** Use && or || (supports Fix All)

## Cause

The `&` or `|` operator joins two `bool` values and the right side uses reads
or calculations. Both operators always evaluate both sides. Use `&&` to skip
the right side when the left is false, or `||` to skip it when the left is true.
This is called short-circuiting.

Reported right sides include names, literals, field and property accesses,
casts, negation, and calculations or comparisons made from those expressions.
If the right side includes a method call, indexer access, assignment, increment,
or object creation, [SST2415](SST2415.md) covers that case instead.

Integer and enum operations, nullable booleans, `&=` and `|=`, and lambdas
stored as `Expression<TDelegate>` are excluded. An `Expression<TDelegate>`
stores code for another component to interpret, so changing the operator can
affect it.

## Example

Before:

```csharp
public sealed class C
{
    public bool CanRun(bool enabled, bool ready) => enabled & ready;
}
```

After:

```csharp
public sealed class C
{
    public bool CanRun(bool enabled, bool ready) => enabled && ready;
}
```

## Code fix

The fix replaces `&` with `&&` or `|` with `||`. It preserves comments and adds
parentheses when needed to keep the grouping inside another `&`, `|`, or `^`
expression. It supports Fix All.

Property getters and custom operators in the right side are treated as reads,
but they can still run code. Review them before accepting the fix: skipping
the right side can skip their effects or exceptions.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1468.severity = error
```

Severity accepts `error`, `warning` (the default), `suggestion`, `silent`,
`none`, or `default` to restore the default severity.

There are no rule-specific options.

See [docs/CONFIGURATION.md](../CONFIGURATION.md) for configuration and
suppression syntax.

## When to suppress

Suppress when evaluating both sides is intentional, such as when a property
getter or custom comparison must run even after the result is decided. Prefer
separate statements when they make that requirement clearer.
