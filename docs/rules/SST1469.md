# SST1469 - Do not compare a value type to null

**Category:** Maintainability
**Severity:** Warning
**Code fix:** None

## Cause

A `==` or `!=` comparison has the literal `null` on one side and a non-nullable
value type on the other. An `int`, enum, or struct value cannot be null. For
ordinary value comparisons, `== null` is always false and `!= null` is always
true. This often means the declaration is missing `?`, or the check is not
needed.

Nullable value types such as `int?`, reference types, pointers, and generic
type parameters are excluded. Checks written with `is null` are not covered
by this rule.

## Example

Before:

```csharp
using System;

public sealed class C
{
    public bool HasStarted(DateTime start) => start != null;
}
```

When an absent value is valid, make the parameter nullable:

```csharp
using System;

public sealed class C
{
    public bool HasStarted(DateTime? start) => start != null;
}
```

If the value must always exist, remove the check instead. Keep any method call
or other work in the checked expression if the program still needs it.

There is no automatic code fix because the rule cannot choose between changing
the type and removing the check.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1469.severity = error
```

Severity accepts `error`, `warning` (the default), `suggestion`, `silent`,
`none`, or `default` to restore the default severity.

There are no rule-specific options.

See [docs/CONFIGURATION.md](../CONFIGURATION.md) for configuration and
suppression syntax.

## When to suppress

Suppress for a test that deliberately exercises this comparison, or for a
custom struct operator that accepts null and gives it a defined meaning. For
ordinary value comparisons, correct the type or remove the check.
