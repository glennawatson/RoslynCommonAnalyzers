# SST1470 - Remove a catch clause that only rethrows

**Category:** Maintainability  
**Default severity:** Warning  
**Enabled by default:** Yes  
**Code fix:** Yes (supports Fix All)

## Cause

The last `catch` in a `try` statement contains only `throw;` and has no `when` filter.
Removing it lets the exception continue to the caller in the same way.

An earlier catch is not reported: removing it could let a later catch handle the exception.
A catch with a filter, another statement, or `throw ex;` is also not reported.

## Example

Before:

```csharp
public class Worker
{
    public void Run()
    {
        try
        {
            System.Console.WriteLine("work");
        }
        catch
        {
            throw;
        }
    }
}
```

After:

```csharp
public class Worker
{
    public void Run()
    {
        System.Console.WriteLine("work");
    }
}
```

## Code fix

The fix removes the reported catch. It keeps other catches and any `finally` block.
If no handler remains, it replaces the whole `try` statement with the statements inside
the try block and adjusts their indentation. It keeps a block where one is needed.

Comments in the deleted catch are lost. Unwrapping the try can also lose comments on its
braces or before its first statement, so move any useful comments before accepting the fix.
The fix is not offered when the try statement contains directives such as `#if` or `#region`.

## Configuration

There are no rule-specific options. Severity defaults to `warning` and accepts `none`,
`silent`, `suggestion`, `warning`, or `error`. For example:

```ini
[*.cs]
dotnet_diagnostic.SST1470.severity = error
```

See [configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress locally if you need to keep the catch as a deliberate debugger breakpoint.
Otherwise, remove the redundant catch.
