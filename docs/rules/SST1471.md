# SST1471 — Magic numbers should be named constants

**Category:** Maintainability  
**Default severity:** Warning  
**Enabled by default:** Yes  
**Code fix:** No

## Cause

A number is written directly in an expression without a name that explains its meaning.
For example, a timeout or threshold should have a name so readers know why that value was chosen.

## Example

Before:

```csharp
public class CachePolicy
{
    public bool IsExpired(int age) => age > 90;
}
```

After:

```csharp
public class CachePolicy
{
    private const int MaximumAge = 90;

    public bool IsExpired(int age) => age > MaximumAge;
}
```

There is no code fix. Choose a meaningful name and use a `const` local or field, or a
`readonly` field when the value needs a constructor or method call.

## What is not reported

- Allowed values: `-1`, `0`, and `1` by default. Values are compared as numbers, so `0.0` and `0L` both count as zero.
- Initializers of `const` locals and `const` or `readonly` fields; enum values; attribute arguments; default parameter values.
- A number that is the whole initializer of a field, local, or property, such as `int timeout = 500;`.
- Direct numeric elements of an array or collection expression that is the whole initializer of a named field, local, or property, such as `int[] offsets = [0, 4, 8];`.
- Hexadecimal and binary numbers, shift distances, direct indexes such as `items[3]`, array lengths, and named arguments.
- Comparisons against members named `Count`, `Length`, `LongLength`, or `Rank`, and numbers in a `GetHashCode` method body.
- Direct arguments to the framework constructors `DateTime`, `DateTimeOffset`, `TimeSpan`, `Version`, and `Guid`.

A number inside a lambda or local function does not gain an exemption from an enclosing
field or method. Numbers inside ordinary method calls and case patterns can still be
reported. For example, `TimeSpan.FromMinutes(30)` needs a named value unless it is inside
an exempt declaration, such as a `static readonly` field initializer.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST1471.severity = error
stylesharp.SST1471.magic_number_allowed_values = -1, 0, 1
stylesharp.SST1471.allow_capacity_arguments = false
```

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.SST1471.magic_number_allowed_values` | Comma-separated decimal numbers | `-1, 0, 1` |
| `stylesharp.SST1471.allow_capacity_arguments` | `true`, `false` | `false` |

The project-wide keys are `stylesharp.magic_number_allowed_values` and
`stylesharp.allow_capacity_arguments`. A rule-specific key takes precedence when present.
The allowed list replaces the defaults; invalid entries are ignored. An empty list or a
list with no valid numbers uses the defaults. An invalid capacity setting uses `false`.

Set `allow_capacity_arguments` to `true` to allow a positional constructor argument whose
parameter is named `capacity`. A named argument such as `capacity: 4` is already allowed.

Severity defaults to `warning` and accepts `none`, `silent`, `suggestion`, `warning`, or
`error`. See [configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress locally when a number comes from a published formula and keeping that formula
intact makes the code easier to check. For values your project regularly accepts without
a name, configure the allowed list instead.
