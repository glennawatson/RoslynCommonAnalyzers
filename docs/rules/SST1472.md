# SST1472 — Signatures should not declare too many parameters

**Category:** Maintainability  
**Default severity:** Warning  
**Enabled by default:** Yes  
**Code fix:** No

## Cause

A method, constructor, delegate, local function, or indexer declares more parameters than
the configured maximum. The default limit is seven. Primary constructors on classes and
structs are included.

Long parameter lists are hard to read and easy to call with arguments in the wrong order.
Group values that belong together into a type, split the work into smaller methods, or move
shared state onto the class.

## Example

Before:

```csharp
public abstract class OrderService
{
    public abstract void Create(
        string customer, string street, string city, string postcode, string country,
        decimal total, decimal tax, string currency);
}
```

After:

```csharp
public record Address(string Street, string City, string Postcode, string Country);
public record Money(decimal Total, decimal Tax, string Currency);

public abstract class OrderService
{
    public abstract void Create(string customer, Address address, Money money);
}
```

There is no code fix. Choose the groups and names, then update callers to use the new signature.
The record example requires C# 9 or later; a class can hold the same values.

## What is not reported

- Overrides and interface implementations. Change the original declaration when you control it.
- `extern` members and members marked with `DllImport` or `LibraryImport`.
- Methods named `Deconstruct`, lambdas, anonymous methods, and operators.
- The implementation of a partial member; only its defining declaration is checked.
- Positional records, unless `check_positional_records` is enabled.

Extension receivers do not count, including receivers in C# 14 extension blocks.
Optional parameters marked with `CallerMemberName`, `CallerFilePath`, `CallerLineNumber`,
or `CallerArgumentExpression` do not count. Other optional parameters count by default.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST1472.severity = error
stylesharp.SST1472.max_parameters = 7
stylesharp.SST1472.check_positional_records = false
stylesharp.SST1472.count_optional_parameters = true
```

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.SST1472.max_parameters` | Positive integer | `7` |
| `stylesharp.SST1472.check_positional_records` | `true`, `false` | `false` |
| `stylesharp.SST1472.count_optional_parameters` | `true`, `false` | `true` |

The project-wide keys are `stylesharp.max_parameters`,
`stylesharp.check_positional_records`, and `stylesharp.count_optional_parameters`.
A valid rule-specific value wins; otherwise the rule uses a valid project-wide value,
then the default.

Severity defaults to `warning` and accepts `none`, `silent`, `suggestion`, `warning`, or
`error`. See [configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress locally when changing a published signature would break callers, or when each
parameter is an independent input and grouping them would hide their meaning. Raise the
limit if long signatures are an accepted project-wide convention.
