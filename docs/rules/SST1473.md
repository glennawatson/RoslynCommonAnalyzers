# SST1473 — Floating-point values should not be compared for exact equality

**Category:** Maintainability  
**Default severity:** Warning  
**Enabled by default:** Yes  
**Code fix:** For certain NaN tests (supports Fix All)

## Cause

Two values are compared with `==` or `!=` as `float` or `double`, including nullable forms.
A typed `float.Equals(float)` or `double.Equals(double)` call is also checked.
These types round arithmetic results, so values that should be equal can differ slightly.

Comparisons against `float.NaN` or `double.NaN` are reported for all six comparison
operators. NaN means “not a number”. Equality against NaN is always false; inequality is
always true. `<`, `<=`, `>`, and `>=` against NaN are always false.

## Example

Before:

```csharp
public class Measurements
{
    public bool Same(double left, double right) => left == right;

    public bool Missing(double value) => value == double.NaN;
}
```

After:

```csharp
public class Measurements
{
    private const double Tolerance = 1e-9;

    public bool Same(double left, double right) =>
        System.Math.Abs(left - right) < Tolerance;

    public bool Missing(double value) => double.IsNaN(value);
}
```

Choose the tolerance for your data; `1e-9` is only an example. This difference test is for
finite values. Handle infinities separately if your inputs can contain them.

## What is not reported

- Comparisons of `decimal` or other types that do not convert to `float` or `double`.
- Comparisons against a literal zero or `default`, by default. A typed `Equals` call with a zero argument is also allowed.
- `<`, `<=`, `>`, and `>=` comparisons that do not directly compare against NaN.
- Comparisons against the framework's `PositiveInfinity` or `NegativeInfinity` fields.
- Typed `Equals` calls directly involving NaN or infinity. Unlike `==`, `double.NaN.Equals(double.NaN)` is true.
- The `Equals(object)` overload and comparisons against `null`.

## Code fix

The fix uses `double.IsNaN` or `float.IsNaN`:

| Before | After |
| --- | --- |
| `x == double.NaN` | `double.IsNaN(x)` |
| `x != double.NaN` | `!double.IsNaN(x)` |
| `x == x` | `!double.IsNaN(x)` |
| `x != x` | `double.IsNaN(x)` |

A NaN field can be on either side. Replacing a comparison against that field changes the
result into a working NaN test. Replacing a self-comparison keeps its result when both
reads return the same value, but evaluates the value once. Property reads qualify, so
check that reading the property twice has no intended effect.

No fix is offered for nullable values, comparisons with NaN on both sides, relational
operators, or general equality comparisons. Self-comparisons containing calls, indexing,
assignments, or increments also have no fix. There is no automatic tolerance choice.
Comments attached to the removed operator or operand can be lost.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST1473.severity = error
stylesharp.SST1473.allow_zero_comparison = true
stylesharp.SST1473.allow_equality_member_comparison = false
```

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.SST1473.allow_zero_comparison` | `true`, `false` | `true` |
| `stylesharp.SST1473.allow_equality_member_comparison` | `true`, `false` | `false` |

Set `allow_zero_comparison` to `false` when computed values must also use a tolerance near
zero. Set `allow_equality_member_comparison` to `true` to allow ordinary exact comparisons
inside `Equals`, `GetHashCode`, `CompareTo`, and `==` or `!=` operator implementations.
Direct comparisons against NaN are still reported.

The project-wide keys are `stylesharp.allow_zero_comparison` and
`stylesharp.allow_equality_member_comparison`. A valid rule-specific value wins; otherwise
the rule uses a valid project-wide value, then the default.

Severity defaults to `warning` and accepts `none`, `silent`, `suggestion`, `warning`, or
`error`. See [configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress locally when exact equality is required, such as checking a stored marker value
or implementing value equality that must agree with `GetHashCode`. Do not add a tolerance
to an equality method without checking that contract: two pairs can be within the tolerance
while a third pair is outside it.

For a NaN test, use `IsNaN`. [SST1474](SST1474.md) handles identical operands for other
operators; floating-point self-equality is covered here.
