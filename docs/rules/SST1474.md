# SST1474 — Identical expressions should not appear on both sides of an operator

**Category:** Maintainability  
**Default severity:** Warning  
**Enabled by default:** Yes  
**Code fix:** No

## Cause

Both sides of an operator contain the same expression. The checked operators are
`==`, `!=`, `<`, `<=`, `>`, `>=`, `&&`, `||`, `&`, `|`, `^`, `-`, `/`, and `%`.
Whitespace and comments do not make the expressions different.

This can mean an operand was copied and left unchanged. For example, subtracting an
integer from itself returns zero instead of the difference between two values.

## Example

Before:

```csharp
public class Measurements
{
    public int Difference(int left, int right) => left - left;
}
```

After:

```csharp
public class Measurements
{
    public int Difference(int left, int right) => left - right;
}
```

## What is not reported

- Addition, multiplication, and shifts, such as `value + value` and `value * value`.
- Operands containing calls, indexing, `await`, assignments, increments, decrements, or object creation. Two calls to `Next()` can return different values.
- `==` and `!=` on `float`, `double`, or their nullable forms. [SST1473](SST1473.md) covers those comparisons and NaN tests.

Names, literals, field and property reads, casts, and combinations of these can be reported.
The rule does not check what a property getter or an overloaded operator does.
Other floating-point operators, such as `value - value`, are still checked.

## How to fix violations

There is no code fix. Correct the operand that should differ, or remove the redundant
operation after checking its behavior. Do not assume every repeated expression has a
constant result: division can throw, floating-point arithmetic can produce NaN, and a
property getter can return a different value on each read.

## Configuration

There are no rule-specific options. Severity defaults to `warning` and accepts `none`,
`silent`, `suggestion`, `warning`, or `error`. For example:

```ini
[*.cs]
dotnet_diagnostic.SST1474.severity = error
```

See [configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress locally when a test deliberately exercises an operator with the same value on
both sides, or when repeated property reads or a custom operator have required behavior.
Explain that behavior beside the code.
