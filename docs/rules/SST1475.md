# SST1475 — A condition should not be repeated

**Category:** Maintainability  
**Default severity:** Warning  
**Enabled by default:** Yes  
**Code fix:** No

## Cause

A condition repeats an earlier one in an `if`/`else if` chain, a `switch` statement, or
a `switch` expression. The rule also checks two immediately adjacent `if` statements in
the same block. The diagnostic marks the later condition and gives the earlier line number.

In a chain, an unchanged condition cannot match after it has already failed. For adjacent
`if` statements, both bodies can run when the condition is true; the repeated test can
mean the blocks should be combined or one condition is wrong.

## Example

Before:

```csharp
public class Classifier
{
    public int Classify(int value)
    {
        if (value < 0)
        {
            return -1;
        }
        else if (value < 0)
        {
            return 0;
        }

        return 1;
    }
}
```

After:

```csharp
public class Classifier
{
    public int Classify(int value)
    {
        if (value < 0)
        {
            return -1;
        }
        else if (value == 0)
        {
            return 0;
        }

        return 1;
    }
}
```

## What is reported

Conditions must use the same code, ignoring whitespace and comments. A switch case must
also have the same `when` guard. The returned value or branch body does not affect this check.
The rule does not compare a nested `if` with its enclosing condition, and it skips switch
`default` labels and discard (`_`) arms.

A condition or guard containing a call, `await`, assignment, increment, decrement, or
object creation is excluded. Property and indexer reads can still be reported.

For adjacent `if` statements, the first statement's body and any `else` must contain no
calls, object or array creation, or `await`. Any writes must be to ordinary locals or
parameters that the condition does not mention. Writes to fields, properties, or through
`ref` variables prevent the report. Any statement between the two `if` statements also
prevents it.

## How to fix violations

There is no code fix. Check which case the later branch should handle and correct its
condition. If the repetition is deliberate, remove the unreachable branch or combine
adjacent blocks after checking variable scopes and early returns.

## Configuration

There are no rule-specific options. Severity defaults to `warning` and accepts `none`,
`silent`, `suggestion`, `warning`, or `error`. For example:

```ini
[*.cs]
dotnet_diagnostic.SST1475.severity = error
```

See [configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress locally when separate adjacent checks make distinct steps clearer and combining
them adds no value. Suppression can also be appropriate when a property or indexer is
deliberately read again because its value can change. Document why the second check matters.
