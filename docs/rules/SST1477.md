# SST1477 — Integer division should not be assigned to a floating-point target

**Category:** Maintainability  
**Default severity:** Warning  
**Enabled by default:** Yes  
**Code fix:** Yes (supports Fix All)

## Cause

Two integers are divided and the result is converted to `float`, `double`, or `decimal`.
Integer division discards the fractional part before the conversion happens. A method
returning `double` does not change how integer operands are divided.

The rule includes assignments, returns, arguments, compound assignments, conditional
expression branches, and explicit casts of the result. Parentheses or a leading `+` or
`-` do not prevent the report. Native integers (`nint` and `nuint`) are included.

## Example

Before, `Average(3, 4)` returns zero:

```csharp
public class Statistics
{
    public double Average(int total, int count) => total / count;
}
```

After, `Average(3, 4)` returns `0.75`:

```csharp
public class Statistics
{
    public double Average(int total, int count) => (double)total / count;
}
```

## What is not reported

- Division with an operand already typed as `float`, `double`, or `decimal`, such as `value / 2.0`.
- Division whose result remains an integer, such as `int pages = total / size;`.
- Nullable division and division on custom numeric types.
- Division followed by other integer arithmetic before conversion. For example, returning `(a / b) + 1` from a `double` method is not reported, although it can still lose the fraction.

## Code fix

The fix casts the left operand to the target type. It uses `float`, `double`, or `decimal`
to match that target and adds parentheses around a compound left operand. For example,
`a * b / c` becomes `(double)(a * b) / c`; the multiplication still uses integers.

When a matching keyword cast surrounds the quotient, such as `(double)(total / count)`,
the fix replaces it with `(double)total / count`. It keeps parentheses needed by the
surrounding expression. Comments on removed casts or parentheses can be lost.

The fix changes arithmetic behavior. For `float` and `double`, dividing by zero produces
infinity or NaN instead of the integer divide-by-zero exception. Keep any required zero check.

## Configuration

There are no rule-specific options. Severity defaults to `warning` and accepts `none`,
`silent`, `suggestion`, `warning`, or `error`. For example:

```ini
[*.cs]
dotnet_diagnostic.SST1477.severity = error
```

See [configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress locally when discarding the fraction is required before conversion. A clearer
alternative is to store the quotient in an integer local, then convert that local.
The rule also reports divisions known to have no remainder; suppress those when keeping
the integer operation is intentional.
