# SST1478 — Shift counts should be within the operand's width

**Category:** Maintainability  
**Default severity:** Warning  
**Enabled by default:** Yes  
**Code fix:** No

## Cause

A `<<`, `>>`, or `>>>` expression has a constant shift count that is zero, negative, or
at least the width of its left operand. Named constants and constant expressions count too.

C# uses only the lowest five bits of the count for a 32-bit shift, or six bits for a
64-bit shift. For an `int`, shifting by `32` therefore shifts by zero; shifting by `33`
shifts by one; shifting by `-1` shifts by 31. An excessive count does not clear the value.

## Example

Before, the 32-bit shift returns the input unchanged:

```csharp
public class BitOperations
{
    public long MoveToUpperHalf(uint value) => value << 32;
}
```

After, convert the value to 64 bits before shifting:

```csharp
public class BitOperations
{
    public long MoveToUpperHalf(uint value) => (long)value << 32;
}
```

## Rule description

| Left operand type | Width used |
| --- | --- |
| `sbyte`, `byte`, `short`, `ushort`, `char`, `int`, `uint` | 32 bits |
| `long`, `ulong` | 64 bits |
| `nint`, `nuint` | Not checked |

Smaller integer types convert to `int` for the shift, so `byteValue << 8` is within range.
Nullable forms of the checked types use the same width. A count calculated at run time,
a custom operand type, and compound assignments such as `value <<= 32` are not checked.
The `>>>` operator requires C# 11 or later.

A zero shift in an enum member value, such as `Read = 1 << 0`, is allowed. Negative counts
and counts at or beyond the width are still reported there. [SST1481](SST1481.md) covers
redundant `&`, `|`, and `^` operations.

## How to fix violations

There is no code fix. Correct the count or convert the left operand to the intended
integer type before shifting. If the intended result is zero, write that result explicitly
after checking whether evaluating the operand performs required work.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST1478.severity = error
stylesharp.SST1478.allow_zero_shift = false
```

`stylesharp.SST1478.allow_zero_shift` accepts `true` or `false` and defaults to `false`.
Set it to `true` to allow deliberate zero shifts, such as the first term in a table of
bit positions. It does not allow negative or excessive counts.

The project-wide key is `stylesharp.allow_zero_shift`. A valid rule-specific value wins;
otherwise the rule uses a valid project-wide value, then the default.

Severity defaults to `warning` and accepts `none`, `silent`, `suggestion`, `warning`, or
`error`. See [configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress locally when the algorithm deliberately relies on C# reducing the count to its
low bits, and explain the expected effective count. Use `allow_zero_shift` for a project
that deliberately keeps zero shifts for consistent layout.
