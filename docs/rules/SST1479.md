# SST1479 — Count and length comparisons should be satisfiable

**Category:** Maintainability  
**Default severity:** Warning  
**Enabled by default:** Yes  
**Code fix:** Yes (supports Fix All)

## Cause

A count or length is compared with zero or a negative number in a way that always gives
the same answer when the count is read successfully. Counts cannot be negative.

| Comparison | Result |
| --- | --- |
| `count >= 0` | `true` |
| `count < 0` | `false` |
| `count > -1`, `count >= -1`, `count != -1` | `true` |
| `count < -1`, `count <= -1`, `count == -1` | `false` |

Other negative literals behave the same way. Either operand order is checked.

## Example

Before, the check accepts an empty collection:

```csharp
using System.Collections.Generic;

public class CollectionChecks
{
    public bool Any(List<int> items) => items.Count >= 0;
}
```

After, check for at least one item:

```csharp
using System.Collections.Generic;

public class CollectionChecks
{
    public bool Any(List<int> items) => items.Count > 0;
}
```

## What is reported

The checked members are array `Length` and `LongLength`, string `Length`, span `Length`,
and `Count` properties that implement `ICollection<T>` or `IReadOnlyCollection<T>`.
The rule also checks `Enumerable.Count()` and `Enumerable.LongCount()`, including their
static call forms.

The bound must be written directly as a decimal numeric literal, optionally with a minus
sign. Named constants, hexadecimal or binary literals, and exponent notation are not checked.
Comparisons that can have either result, such as `Count > 0`, `Count == 0`, or comparisons
against positive numbers, are not reported. Neither are `items?.Count` or unrelated
properties that happen to be named `Count` or `Length`.

## Code fix

The fix replaces the whole comparison with `true` or `false`. For the example above it
produces `public bool Any(List<int> items) => true;`. It does not choose `> 0` for you or
remove a surrounding `if`. Correct the condition manually when it should still test something.

Replacing the comparison also removes its evaluation. A `Count()` call stops enumerating,
a property getter stops running, and a null receiver stops throwing at that expression.
Comments inside the comparison are removed; comments before or after it are kept.

## Configuration

There are no rule-specific options. Severity defaults to `warning` and accepts `none`,
`silent`, `suggestion`, `warning`, or `error`. For example:

```ini
[*.cs]
dotnet_diagnostic.SST1479.severity = error
```

See [configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress locally for a deliberate contract check, such as testing whether a custom
collection violates its non-negative `Count` requirement. If reading the count performs
required work, keep that work explicit when removing the comparison.
