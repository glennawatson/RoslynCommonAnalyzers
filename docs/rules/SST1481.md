# SST1481 — Bitwise operations should not use identity operands

**Category:** Maintainability  
**Default severity:** Warning  
**Enabled by default:** Yes  
**Code fix:** Yes, except for `x & 0` (supports Fix All)

## Cause

A constant operand makes a bitwise operation return the other value unchanged, or always
produce zero. Check whether the constant was meant to be a different flag or mask.

| Operation | Result |
| --- | --- |
| `x \| 0` or `0 \| x` | `x` |
| `x ^ 0` or `0 ^ x` | `x` |
| `x & allBits` or `allBits & x`, where every bit in `allBits` is set | `x` |
| `x & 0` or `0 & x` | Zero |

The operation must have an `int`, `uint`, `long`, or `ulong` result. Named constants and
constant expressions are included. An all-bits mask is `-1` or `~0` for signed operations,
`uint.MaxValue` for `uint`, and `ulong.MaxValue` for `ulong`.

## Example

Before:

```csharp
public class Flags
{
    public int Combine(int value) => value | 0;
}
```

After, if the original value is the intended result:

```csharp
public class Flags
{
    public int Combine(int value) => value;
}
```

## What is not reported

- Boolean, enum, nullable, and native-integer results.
- Operations without a qualifying constant, such as `value & mask` or `value | 1`.
- Partial masks such as `byteValue & 0xFF`. The byte converts to `int`, so `0xFF` does not set all 32 bits of the operation's result type.
- Compound assignments such as `value |= 0`.
- Shifts. [SST1478](SST1478.md) covers suspicious shift counts, including zero shifts.

## Code fix

The fix removes the operator and constant and keeps the other expression. It can also
remove surrounding parentheses when the remaining value is a name, literal, member read,
call, or index access. It keeps parentheses around compound expressions: `a & (b ^ c | 0)`
becomes `a & (b ^ c)`. Comments attached to removed parts can be lost.

The fix does not add a cast to preserve the operation's result type. Removing `| 0` from
a `byte` expression can therefore change type inference or overload selection from `int`
to `byte`. Add an explicit cast if the wider type is required.

There is no code fix for `x & 0`. Choose the intended mask or result yourself, and keep any
required work performed while evaluating `x`.

## Configuration

There are no rule-specific options. Severity defaults to `warning` and accepts `none`,
`silent`, `suggestion`, `warning`, or `error`. For example:

```ini
[*.cs]
dotnet_diagnostic.SST1481.severity = error
```

See [configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress locally when a deliberate zero or all-bits mask keeps an algorithm or table
consistent with its specification. If the operation exists only to convert an integer
to a wider type, an explicit cast states that intent more clearly.
