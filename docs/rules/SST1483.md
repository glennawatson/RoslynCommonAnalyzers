# SST1483 — Constructors should not call overridable members

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An instance constructor calls a method, reads or writes a property, or subscribes
to an event on `this` that a derived class can override. This includes `virtual`,
`abstract`, and unsealed `override` members.

The derived override can run before the derived constructor body has initialized
the fields it needs. This can produce wrong results or throw an exception.

## Example

Bad:

```csharp
public class Control
{
    public Control() => Render();

    public virtual void Render()
    {
    }
}
```

Corrected: call the overridable member after construction.

```csharp
var control = new Control();
control.Render();

public class Control
{
    public virtual void Render()
    {
    }
}
```

## What is not reported

- Constructors in sealed classes or structs, and static constructors.
- Non-virtual members and `sealed override` members.
- Calls written with `base.`, which use the base implementation, and calls on other objects.
- Method references assigned to delegates, `nameof`, and code inside lambdas or local functions.
- Subscriptions to a field-like event inside the class that declares it.

An inherited virtual event subscription is reported. So is a call to an inherited
virtual method such as `ToString()`. Code inside a lambda or local function is
excluded even if you invoke it during construction; review those calls yourself.

## How to fix violations

Move the call after construction. If inheritance is unnecessary, seal the class
or make the member non-virtual. A `sealed override` prevents further overrides of
one member. Check callers before changing a public inheritance contract.

There is no code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`.

```ini
[*.cs]
dotnet_diagnostic.SST1483.severity = warning
```

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress only when the inheritance contract requires this call during construction
and every allowed override can run safely before the derived constructor body.
Document that requirement for authors of derived classes.
