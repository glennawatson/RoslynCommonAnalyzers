# SST1484 — Declarations should not shadow an outer field or property

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A local variable or parameter uses the name of a visible field or property.
Inside that scope, the name refers to the local or parameter, which can hide an
accidental read or write of the wrong value.

Loop variables, pattern variables, `out` variables, deconstruction variables, and
catch variables also count. A nested class's field or property is reported when
it hides a containing type's visible static field or property.

## Example

Bad:

```csharp
public class Counter
{
    public int Total { get; set; }

    public int Measure(int[] values)
    {
        var Total = values.Length;
        return Total;
    }
}
```

Corrected:

```csharp
public class Counter
{
    public int Total { get; set; }

    public int Measure(int[] values)
    {
        var length = values.Length;
        return length;
    }
}
```

## What is not reported

- Primary constructor parameters, including positional record parameters.
- Parameters in declarations that assign to the matching name, such as
  `this.name = name`, or forward the parameter through `this(...)` or `base(...)`.
- Locals in static members, static lambdas, or static local functions that match
  only an instance member.
- Names that match only a private base member or an unrelated type's member.
- Nested members matching only an outer instance member, explicit interface
  properties, and nested members marked `new` or `override`.
- The name `_`.

Visible inherited fields and properties are checked for local and parameter
conflicts regardless of the option below.

## How to fix violations

Rename the inner declaration to describe its role. Use `this.Total` or a containing
type's name when you need to refer to the hidden member. Qualification alone does
not generally clear the diagnostic on the declaration.

There is no code fix.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST1484.severity = warning
stylesharp.SST1484.check_base_types = false
```

| Key | Values | Default | Effect |
| --- | --- | --- | --- |
| `stylesharp.SST1484.check_base_types` | `true`, `false` | `false` | Also report a field declaration that hides an inherited field, unless marked `new`. |

`stylesharp.check_base_types` supplies the project-wide fallback. A valid
rule-specific value takes precedence; invalid values fall back to the general
key, then to the default. The default severity is `warning`.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when a required parameter name or an established naming convention makes
renaming more confusing, and all intended member accesses are clearly qualified.
For deliberate hiding of an inherited field, use `new` to state that intent.
