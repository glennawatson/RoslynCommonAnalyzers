# SST1485 — Members that must not throw should not throw

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A member that callers expect to succeed contains an explicit `throw`. Calls to
these members often happen during logging, collection lookups, or cleanup. In
particular, an exception from `Dispose` can replace an exception already being handled.

The rule checks:

- `Equals` with one parameter.
- Parameterless `GetHashCode`, `ToString`, `Dispose`, and `DisposeAsync` methods.
- Static constructors and finalizers.
- Comparison operators: `==`, `!=`, `<`, `>`, `<=`, and `>=`.
- Implicit conversion operators.

Methods are matched by name and parameter count, even without an override or
interface declaration. Configured additional method names are checked with any
parameter count.

## Example

Bad:

```csharp
public class Resource
{
    public override string ToString()
        => throw new System.InvalidOperationException();
}
```

Corrected:

```csharp
public class Resource
{
    public override string ToString() => nameof(Resource);
}
```

## What is not reported

`NotImplementedException`, `NotSupportedException`, and types derived from them
are allowed. A bare `throw;` in a catch block is excluded, but throwing a new
exception there is reported.

Throws inside lambdas or local functions are excluded. Ordinary methods, instance
constructors, explicit conversions, and overloads such as `Dispose(bool)` are
excluded unless an additional method name matches. The rule does not detect
exceptions raised by other methods you call.

## How to fix violations

Choose behavior that fits the member's contract: return `false` for an unequal
value, return a usable description from `ToString`, or release available resources
during disposal. Move validation that must throw into an explicit operation the
caller can handle. Use an explicit conversion when conversion failure is expected.

There is no code fix.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST1485.severity = warning
stylesharp.SST1485.additional_members = OnError, OnCompleted
```

| Key | Values | Default | Effect |
| --- | --- | --- | --- |
| `stylesharp.SST1485.additional_members` | Comma-separated method names | Empty | Check these names in addition to the built-in members. |

Names are case-sensitive and apply to every method with that name. The
rule-specific key takes precedence over `stylesharp.additional_members`, including
when its value is empty. The default severity is `warning`.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when an existing API contract requires the exception, or when a method
matches a built-in name but is an ordinary operation whose callers expect failure.
Keep the exception behavior documented for callers.
