# SST1487 — Collection elements should not be overwritten before they are read

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

Two adjacent statements assign to the same array element or indexer with `=`.
The collection expression and all indexes must match. The diagnostic marks the
first assignment because its stored value is overwritten.

## Example

Bad:

```csharp
public class BufferWriter
{
    public void Fill(int[] values, int i)
    {
        values[i] = 1;
        values[i] = 2;
    }
}
```

Corrected, when two neighboring elements were intended:

```csharp
public class BufferWriter
{
    public void Fill(int[] values, int i)
    {
        values[i] = 1;
        values[i + 1] = 2;
    }
}
```

The caller must supply space for both elements. If only the second value was
intended, remove the first assignment instead.

## What is not reported

- Assignments separated by another statement or placed in different blocks.
- Compound assignments such as `+=` and `??=`.
- Calls or increments in the collection expression or index, such as `map[Next()]`.
- A second assigned value that mentions the collection, such as `values[i] + 1`,
  `values.Length`, or `Sum(values)`.
- Nested element access such as `grid[i][j]`, repeated field or property
  assignments, and assignments containing preprocessor directives.

Adjacent statements in a `switch` section are checked too. Three matching writes
report the first two.

## How to fix violations

Check whether the key or index is wrong. Correct it, or remove the unwanted write.
Before deleting an assignment, check whether its value calculation or the indexer
setter performs work that must be preserved. The rule does not inspect those methods.

There is no code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`.

```ini
[*.cs]
dotnet_diagnostic.SST1487.severity = warning
```

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when both writes are required by a custom indexer, or when a called
method observes the first value or changes which element the second write reaches.
Document why both assignments are needed.
