# SST1488 — Exception types should declare the standard constructors

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A class derived from `System.Exception` does not explicitly declare the standard
constructors: no arguments, a message, and a message plus an inner exception.
The inner exception preserves the original failure when you wrap it in a more
specific exception.

Constructors are matched by parameter types, not parameter names. An automatically
supplied parameterless constructor does not count, and derived classes do not
inherit constructors.

## Example

Bad:

```csharp
public class WidgetException : System.Exception
{
}
```

Corrected:

```csharp
public class WidgetException : System.Exception
{
    public WidgetException()
    {
    }

    public WidgetException(string message) : base(message)
    {
    }

    public WidgetException(string message, System.Exception innerException)
        : base(message, innerException)
    {
    }
}
```

Use public constructors for a concrete public exception. Abstract exceptions can
use `protected` or `protected internal` constructors. Concrete exceptions that
are not visible outside the assembly can use `internal` constructors.

## What is not reported

The rule does not require a serialization constructor. See [SST1489](SST1489.md)
before retaining formatter-based serialization members.

A derived exception is excluded when its immediate base class offers none of the
standard constructor forms other than private ones. Non-public exception types
can also be excluded through configuration.

## Code fix

The fix inserts the missing constructors after existing constructors, or at the
start of the class if there are none. It adds XML documentation and formats the
class. Message and inner-exception arguments are passed to `base`; the
parameterless constructor has an empty body.

Added constructors are `protected` when the edited class declaration is marked
`abstract`, and `public` otherwise, including on internal classes.

The fix adds declarations; it does not change existing constructors' accessibility.
If an inaccessible constructor already has the required signature, adjust it by
hand to avoid a duplicate. With a custom base exception, check that it supports
each generated call to `base`.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST1488.severity = warning
stylesharp.SST1488.require_parameterless = true
stylesharp.SST1488.include_non_public_types = true
```

| Key | Values | Default | Effect |
| --- | --- | --- | --- |
| `stylesharp.SST1488.require_parameterless` | `true`, `false` | `true` | Require an explicit parameterless constructor. |
| `stylesharp.SST1488.include_non_public_types` | `true`, `false` | `true` | Check exceptions that are not visible outside the assembly. |

Project-wide fallbacks are `stylesharp.require_parameterless` and
`stylesharp.include_non_public_types`. Each valid rule-specific value takes
precedence; invalid values fall back to the general key, then to the default.
The default severity is `warning`.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when an exception deliberately requires extra data or can only be
created through a factory. If only the parameterless constructor is unwanted,
set `require_parameterless = false` instead.
