# SST1489 — Exception types should not carry formatter-based serialization members

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An exception class declares a constructor taking `SerializationInfo` and
`StreamingContext`, or a `GetObjectData` override with those parameters, on a
target where `System.Exception.GetObjectData` is obsolete.

These members support formatter-based serialization, such as `BinaryFormatter`.
Remove them when your application does not use that serialization contract.

## Example

Bad on .NET 8 or later:

```csharp
using System.Runtime.Serialization;

public class WidgetException : System.Exception
{
    public WidgetException()
    {
    }

    public WidgetException(string message) : base(message)
    {
    }

    public WidgetException(string message, System.Exception innerException)
        : base(message, innerException)
    {
    }

    protected WidgetException(SerializationInfo info, StreamingContext context)
    {
    }
}
```

Corrected:

```csharp
public class WidgetException : System.Exception
{
    public WidgetException()
    {
    }

    public WidgetException(string message) : base(message)
    {
    }

    public WidgetException(string message, System.Exception innerException)
        : base(message, innerException)
    {
    }
}
```

## What is not reported

The rule reports nothing on targets where `Exception.GetObjectData` is not
obsolete, including .NET Framework and .NET Standard 2.0. It does not report
`[Serializable]` itself, ordinary exception constructors, or a non-override
method named `GetObjectData`.

For a project targeting both older and newer frameworks, keep required legacy
members under conditional compilation so they are included only for the targets
that need them.

## Code fix

The fix deletes the selected constructor or `GetObjectData` method, including its
body, XML documentation, and attached comments. It leaves `[Serializable]` and
other members in place. Review derived classes and callers before removing a
constructor or a public serialization method they use.

## Configuration

There are no rule-specific options. The default severity is `warning`.

```ini
[*.cs]
dotnet_diagnostic.SST1489.severity = warning
```

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when a legacy serializer or an existing public API contract still
requires the member on the affected target. Marking a framework member obsolete
does not prove that your own callers have stopped using it.
