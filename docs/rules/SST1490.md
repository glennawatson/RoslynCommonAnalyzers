# SST1490 — Base lists should not state what is already implied

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

The list after a type's colon names an interface that another entry already
includes. That other entry can be an interface that inherits it or a base class
that implements it. Removing the extra name makes the type declaration easier to read.

## Example

Bad:

```csharp
public interface IBase { }
public interface IDerived : IBase { }

public sealed class Item : IDerived, IBase
{
}
```

Corrected:

```csharp
public interface IBase { }
public interface IDerived : IBase { }

public sealed class Item : IDerived
{
}
```

`Item` still implements `IBase` through `IDerived`. Classes, structs, interfaces,
records, and record structs are checked.

## What is not reported

- A list with only one entry, or entries that do not imply each other.
- An interface implied only by another declaration of a partial type.
- An explicit `object` base, which is covered by [SST1177](SST1177.md).
- An interface repeated after a base class when removing it would change which
  member handles calls through that interface.

The last case matters when a class supplies a `new` member or an explicit
interface implementation. Repeating the interface can make interface calls use
that member instead of the base implementation. This also applies to hidden
members inherited from an intermediate base class. An ordinary virtual override
still runs without the repeated interface, so that repetition is reported.

## Code fix

The fix removes the reported interface and its separating comma. It keeps the
entry that implies the interface and never removes the last entry.

Review comments attached to the removed entry or comma: the fix does not relocate
all of them. It keeps the trailing text at the end of the base list.

## Configuration

There are no rule-specific options. The default severity is `warning`.

```ini
[*.cs]
dotnet_diagnostic.SST1490.severity = warning
```

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when a tool requires the interface to be written directly on the type,
or when your API documentation convention deliberately lists inherited interfaces.
Normal interface reimplementation that changes the called member is already excluded.
