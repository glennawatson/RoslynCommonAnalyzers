# SST1491 — Modifiers should not restate the default

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A method, property, indexer, or event has a modifier that its context already
supplies. Removing it reduces the keywords a reader has to check.

| Modifier | Reported when |
| --- | --- |
| `public` | The member is declared in an interface, including a static member. |
| `abstract` | An instance interface member has no body. |
| `virtual` | An instance interface member has a body. |
| `readonly` | An instance member is inside a declaration marked `readonly struct` or `readonly record struct`. |
| `unsafe` | An enclosing type or member is already `unsafe`, and this member contains unsafe code. |

The interface checks apply to C# 8 or later. Fields, constructors, nested type
declarations, and individual accessor modifiers are not checked by this rule.

## Example

Bad:

```csharp
public interface IService
{
    public abstract void Run();
    virtual int Fallback() => 0;
}
```

Corrected:

```csharp
public interface IService
{
    void Run();
    int Fallback() => 0;
}
```

## What is not reported

- `private` interface members, because removing `private` changes accessibility.
- `abstract` and `virtual` on static interface members, where they are required.
- Explicit interface implementations declared inside an interface.
- `static` on members of static classes, where the language requires it.
- `readonly` on members of mutable structs.
- Class and struct access modifiers, and `sealed` modifiers.
- `unsafe` with no enclosing unsafe declaration, or on a member with no unsafe code.

## Code fix

The fix removes the selected keyword. Each redundant keyword has its own
diagnostic; Fix All can remove both `public` and `abstract` from the same member.
Review comments between modifiers, which can be removed with the keyword.

## Configuration

There are no rule-specific options. The default severity is `warning`.

```ini
[*.cs]
dotnet_diagnostic.SST1491.severity = warning
```

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when a team convention requires explicit interface modifiers for
readability, or when a member must retain its own `readonly` or `unsafe` modifier
because it is routinely copied into a different containing type.
