# SST1492 — Do not test a value against what it is about to be assigned

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An `if` compares two values for inequality, and its only statement assigns one
of those values to the other. For a plain stored value, the comparison adds no
useful work: assigning the same value again leaves the value unchanged.

The operands can appear in either order. The rule also reports an equality test
with an empty `if` block and the assignment as the only statement in `else`.

## Example

Bad:

```csharp
public sealed class Counter
{
    public int Value { get; set; }

    public void SetValue(int value)
    {
        if (Value != value)
        {
            Value = value;
        }
    }
}
```

Corrected:

```csharp
public sealed class Counter
{
    public int Value { get; set; }

    public void SetValue(int value)
    {
        Value = value;
    }
}
```

## What is not reported

- A branch that does more than assign, such as raising a change notification.
- Assignment to a property with a hand-written setter or a setter from another assembly.
- Calls, increments, or element access in the compared assignment target or value.
- Compound assignments, assignments of a different value, and inequality tests with an `else` branch.

Auto-implemented property setters can be reported. The rule does not check the
behavior of every property getter or overloaded comparison operator involved.

## Code fix

The fix replaces the entire `if` statement with the assignment and formats it.
It removes the condition, braces, and any empty branch. Comments before or after
the whole `if` are retained, but comments inside the removed condition or block,
including comments directly before or after the assignment, can be lost.

Before accepting, check whether a name was mistyped or the branch is missing work
that should happen only when the value changes. Also check that removing the
comparison and assigning an equal value preserve the intended behavior.

## Configuration

There are no rule-specific options. The default severity is `warning`.

```ini
[*.cs]
dotnet_diagnostic.SST1492.severity = warning
```

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when the comparison has a required side effect, or when it deliberately
keeps the existing object even though another object compares equal. Explain why
an unconditional assignment would change the behavior.
