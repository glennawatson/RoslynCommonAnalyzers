# SST1495 — Do not compare with `==` when the type overrides `Equals`

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes — uses `object.Equals` |
| Default | Enabled |

## Cause

A comparison uses `==` or `!=` on class instances when the left-hand type overrides
`Equals(object)` but has no `==` overload. Inherited overrides and operators count.
Without an operator overload, two separate objects can compare unequal even when
`Equals` says their values match.

## Example

Before:

```csharp
public class Money
{
    public decimal Amount { get; set; }

    public override bool Equals(object? obj) => obj is Money other && other.Amount == Amount;

    public override int GetHashCode() => Amount.GetHashCode();

    public static bool Same(Money left, Money right) => left == right;
}
```

After:

```csharp
public class Money
{
    public decimal Amount { get; set; }

    public override bool Equals(object? obj) => obj is Money other && other.Amount == Amount;

    public override int GetHashCode() => Amount.GetHashCode();

    public static bool Same(Money left, Money right) => object.Equals(left, right);
}
```

## What is not reported

The rule skips literal `null` and `default` comparisons, types with a `==` overload,
records, and value types. It also skips comparisons where either operand is typed as
`object`, an interface, `dynamic`, or a generic type parameter.

## How to fix violations

The code fix replaces `left == right` with `object.Equals(left, right)` and replaces
`left != right` with `!object.Equals(left, right)`. This handles null operands without
calling a method on null: two nulls compare equal, and one null compares unequal.
Comments between the operands and the operator can be lost; check the preview.

If you own the type and want `==` to compare values everywhere, add matching `==` and
`!=` overloads yourself. The code fix changes the comparison only.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository
sets it to `error`:

```ini
[*.cs]
dotnet_diagnostic.SST1495.severity = error
```

Use `warning`, `suggestion`, or `silent` for a lower severity, or `none` to disable the rule.

## When to suppress

Suppress when you need to test whether two references point to the same object.
Prefer `object.ReferenceEquals(left, right)` to make that intent clear without a suppression.
