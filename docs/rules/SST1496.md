# SST1496 — Abstract types should declare something abstract

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes, except for partial classes |
| Default | Enabled |

## Cause

An `abstract class` has no abstract members of its own and no inherited abstract members
left to implement. A protected constructor alone does not exempt the class.

Abstract methods, properties, indexers, and events count, including members declared in
another part of a partial class. Static classes and records are not reported.

## Example

Before:

```csharp
public abstract class Helper
{
    public int Add(int left, int right) => left + right;
}
```

After, when no class in the solution derives from it:

```csharp
public sealed class Helper
{
    public int Add(int left, int right) => left + right;
}
```

## How to fix violations

If derived classes must supply some behavior, declare that member abstract. Otherwise,
remove `abstract`.

The code fix removes `abstract`. It replaces it with `sealed` when the class has no
derived classes in the solution and declares no `protected` or `virtual` members.
A sealed class cannot be inherited. Check for users outside the solution before accepting
that change on a public class.

No code fix is offered for partial classes. Review all parts and change their modifiers
together. Removing `abstract` does not change constructor access. Comments attached to
the removed keyword can be lost when the fix does not replace it with `sealed`.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository
sets it to `error`:

```ini
[*.cs]
dotnet_diagnostic.SST1496.severity = error
```

Use `warning`, `suggestion`, or `silent` for a lower severity, or `none` to disable the rule.

## When to suppress

Suppress when the class deliberately provides shared behavior while preventing direct
construction, even though derived classes have no required members to implement.
