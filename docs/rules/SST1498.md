# SST1498 — Move a private member used only by a nested type into it

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes, for methods, some properties, and constants |
| Default | Enabled |

## Cause

A private static field, property, or method is used by exactly one nested type and
not by the containing type. Constants count too. Put the member near the code that uses it.
A method calling itself does not count as a separate user.

Instance members, attributed members, partial or extern methods, and members of a
partial containing type are skipped. A member with no users, or users in more than
one nested type, is also skipped.

## Example

Before:

```csharp
public sealed class Parser
{
    private static int Double(int value) => value * 2;

    public sealed class Cursor
    {
        public int Advance(int value) => Double(value);
    }
}
```

After:

```csharp
public sealed class Parser
{
    public sealed class Cursor
    {
        public int Advance(int value) => Double(value);

        private static int Double(int value) => value * 2;
    }
}
```

## How to fix violations

The code fix moves a static method, a static property without an initializer, or a
constant declared on its own to the end of the nested type. It carries the member's
documentation and attached comments, adjusts indentation, and removes the leading gap
if the moved member was first in the outer type.

The fix requires all of these conditions:

- Nested uses omit the outer type name: `Double(value)`, rather than `Parser.Double(value)`.
- No other member has that name in either type.
- The destination is a non-partial class, struct, or record with no explicit base class.
- The containing type has no preprocessor directives.

Other reported fields and properties with initializers need a manual move. Moving
stored static data can change when it is initialized, so check that behavior first.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository
sets it to `error`:

```ini
[*.cs]
dotnet_diagnostic.SST1498.severity = error
```

Use `warning`, `suggestion`, or `silent` for a lower severity, or `none` to disable the rule.

## When to suppress

Suppress when reflection requires the member to remain on its containing type, or
when moving static data would change required initialization behavior.
