# SST1499 — Do not expose a mutable static field

| Item | Value |
| --- | --- |
| Category | Maintainability |
| Severity | Warning |
| Code fix | Yes, when the field can take `readonly` |
| Default | Enabled |

## Cause

A static field visible outside its type can be reassigned, or it is a `readonly` array
or supported mutable collection. Shared changes affect every caller. `readonly` stops
replacement of an array or list, but does not stop changes to its contents.

Visibility includes the containing types. Private fields and fields inside private
nested types are skipped. Internal fields are included by default. Constants and
fields marked `[ThreadStatic]` are skipped.

For `readonly` fields, the collection check covers arrays and these declared types:

- Generic `List`, `Dictionary`, `HashSet`, `SortedDictionary`, `SortedList`, `SortedSet`,
  `Queue`, `Stack`, and `LinkedList`.
- `Collection<T>`, `KeyedCollection<TKey, TItem>`, and `ObservableCollection<T>`.
- Generic `ICollection`, `IList`, `IDictionary`, and `ISet` interfaces.
- Non-generic `ArrayList`, `Hashtable`, `ICollection`, `IList`, and `IDictionary`.

Other `readonly` types are not reported, including concurrent collections, immutable
collections, read-only wrappers, and custom types. This does not prove their contents
cannot change. A concurrent collection field without `readonly` is still reported.

## Example

Before:

```csharp
public class Settings
{
    public static int Timeout = 30;
}
```

After:

```csharp
public class Settings
{
    public static readonly int Timeout = 30;
}
```

## How to fix violations

The code fix adds `readonly` when no code in the solution writes to the field outside
its own type's static constructor. Writes inside a lambda or local function still
block the fix. It is not offered for `volatile` fields or custom mutable structs.
If several fields share one declaration, they must all qualify and all gain `readonly`.

Adding `readonly` does not resolve the diagnostic for an array or supported mutable
collection. Use an immutable collection, expose a read-only wrapper, or return a copy
through a method. The code fix does not choose or make that API change. Check callers
outside the solution before restricting writes to a public field.

## Configuration

The default severity is `warning`; this repository sets it to `error`:

```ini
[*.cs]
dotnet_diagnostic.SST1499.severity = error
stylesharp.SST1499.include_internal = true
```

| Key | Values | Default | Effect |
| --- | --- | --- | --- |
| `stylesharp.SST1499.include_internal` | `true`, `false` | `true` | Include fields visible only inside the assembly. |
| `stylesharp.include_internal` | `true`, `false` | `true` | Fallback when the rule-specific value is absent or invalid. |

A valid rule-specific value takes precedence. If neither value is valid, `true` applies.
Set it to `false` to report only fields accessible outside the assembly.
Severity also accepts `warning`, `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when an existing public API must keep its writable field for compatibility,
or when deliberate shared state has controlled access that this rule cannot express.
Document how callers coordinate updates.
