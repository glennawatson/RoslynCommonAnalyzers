# SST1500 — Braces for multi-line statements should not share a line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes — moves braces onto separate lines |
| Default | Enabled |

## Cause

An opening brace shares a line with code before or after it, or a closing brace shares
a line with code before it. The opening and closing braces must be on different lines
for this rule to apply.

This includes blocks, types, namespaces, accessor lists, switches, and object or collection
initializers. A closing brace followed by code on the same line is not reported on that
basis alone. Braces on the same line are left to [SST1501](SST1501.md) and
[SST1502](SST1502.md).

## Example

Before:

```csharp
class Worker
{
    void Run() {
        return;
    }
}
```

After:

```csharp
class Worker
{
    void Run()
    {
        return;
    }
}
```

## How to fix violations

The code fix inserts line breaks before the reported brace and, for an opening brace,
after it where needed. It aligns braces with the surrounding declaration and adds four
spaces when moving following code onto a new line. It keeps the file's line-ending style.

A comment between the brace and adjacent code prevents that part of the edit. The fix
can leave the diagnostic in place; move the brace and comment manually in that case.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository
sets it to `error`:

```ini
[*.cs]
dotnet_diagnostic.SST1500.severity = error
```

Use `warning`, `suggestion`, or `silent` for a lower severity, or `none` to disable the rule.

## When to suppress

Disable the rule if your project keeps opening braces on declaration lines. Suppress
a local occurrence when matching an external code sample's layout is required.
