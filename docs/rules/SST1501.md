# SST1501 — Statement should not be on a single line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes — expands the block |
| Default | Enabled |

## Cause

A non-empty statement block has both braces on one line. This includes bodies of
`if`, loops, `using`, `lock`, `try`, `catch`, and `finally`, as well as bare nested blocks.

Empty blocks are skipped. Method and local-function bodies belong to
[SST1502](SST1502.md); accessors belong to [SST1504](SST1504.md). Lambda and anonymous-method
bodies are also skipped.

## Example

Before:

```csharp
class Worker
{
    void Run(bool enabled)
    {
        if (enabled) { enabled = false; }
    }
}
```

After:

```csharp
class Worker
{
    void Run(bool enabled)
    {
        if (enabled)
        {
            enabled = false;
        }
    }
}
```

## How to fix violations

The code fix puts each statement and brace on its own line. It indents statements by
four additional spaces and keeps the file's line-ending style. Comments between the
braces and statements, or between statements, prevent expansion. Move those comments
and expand the block manually if the fix makes no change.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository
sets it to `error`:

```ini
[*.cs]
dotnet_diagnostic.SST1501.severity = error
```

Use `warning`, `suggestion`, or `silent` for a lower severity, or `none` to disable the rule.

## When to suppress

Suppress a compact block when it makes a repeated pattern easier to compare. Disable
the rule if single-line blocks are part of your project's style.
