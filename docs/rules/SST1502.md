# SST1502 — Element should not be on a single line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes for method-like bodies; no for type or enum bodies |
| Default | Enabled |

## Cause

A non-empty method, constructor, destructor, operator, conversion operator, or local
function has its body braces on the same line. A class, struct, interface, record, or
enum containing members is also reported when its braces share a line.

Empty bodies and expression-bodied members are skipped. Statement blocks belong to
[SST1501](SST1501.md). Accessor and lambda bodies are not checked by this rule.

## Example

Before:

```csharp
class Worker
{
    void Run() { System.Console.WriteLine(); }
}
```

After:

```csharp
class Worker
{
    void Run()
    {
        System.Console.WriteLine();
    }
}
```

## How to fix violations

The code fix expands method, constructor, destructor, operator, and local-function
bodies. It puts braces and statements on separate lines, adds four spaces of indentation
for statements, and keeps the file's line-ending style.

Comments between braces and statements, or between statements, prevent expansion.
If the fix makes no change, expand the body manually and keep its comments.
Type and enum bodies have no automatic fix; put their members and braces on separate lines.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository
sets it to `error`:

```ini
[*.cs]
dotnet_diagnostic.SST1502.severity = error
```

Use `warning`, `suggestion`, or `silent` for a lower severity, or `none` to disable the rule.

## When to suppress

Suppress a compact declaration when its layout helps readers compare a group of short
members or enum values. Disable the rule if that layout is your project's general style.
