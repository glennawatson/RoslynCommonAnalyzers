# SST1503 — Braces should not be omitted

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes — wraps the child statement in braces |
| Default | Enabled |

## Cause

An `if`, `else`, `for`, `foreach`, `while`, `do`, `using`, `lock`, or `fixed` statement
has a child statement without braces. This applies even when that child fits on one line.

A child that is itself an `if` is skipped, including `else if` chains. A `using` directly
containing another `using` is also skipped, but the innermost body still needs braces.
A `using` directly inside an unbraced `if` is reported.

## Example

Before:

```csharp
class Worker
{
    int Run(bool enabled)
    {
        if (enabled) return 1;
        return 0;
    }
}
```

After:

```csharp
class Worker
{
    int Run(bool enabled)
    {
        if (enabled)
        {
            return 1;
        }
        return 0;
    }
}
```

## How to fix violations

The code fix wraps the child statement in braces on separate lines and indents its
first line by four spaces. It keeps the file's line-ending style. A comment between
the control statement's header and its child prevents the edit, so add the braces
manually in that case. Check trailing comments: a comment after the child can end up
after the inserted closing brace.

## Configuration

There are no rule-specific options. The rule is enabled by default with severity
`warning`; this repository sets it to `error`:

```ini
[*.cs]
dotnet_diagnostic.SST1503.severity = error
```

Use `warning`, `suggestion`, or `silent` for a lower severity, or `none` to disable the rule.

## When to suppress

Disable this rule if your style allows short unbraced statements. You can enable
[SST1519](SST1519.md) for multi-line children and [SST1520](SST1520.md) for consistency
across an `if`/`else` chain instead.
