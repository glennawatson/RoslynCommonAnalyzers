# SST1503 — Braces should not be omitted

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes (add braces) |

## Cause

A control-flow statement (`if`, `else`, `for`, `foreach`, `while`, `do`, `using`,
`lock`, `fixed`) has a child statement that is not wrapped in braces.

## Rule description

The child statement of a control-flow statement is always wrapped in braces, even when
it is a single statement. An `else if` chain is not treated as an unbraced child, and
neither is a `using` stacked directly over another `using`.

This is the strict always-braces rule. The repository disables it by default in favour
of [SST1519](SST1519.md)/[SST1520](SST1520.md), but it is provided for
projects that prefer the single combined rule.

```csharp
// 👎 reported
if (enabled)
    Work();

// 👍 braces
if (enabled)
{
    Work();
}
```

## What is not reported

A `using` whose body is another `using` is left alone. Stacking is how the language opens
several resources over a single body, and the braces belong on the innermost statement —
which this rule still reports if it goes without them.

```csharp
// 👍 not reported — the outer using carries the inner one
using (var stream = File.OpenRead(path))
using (var reader = new StreamReader(stream))
{
    return reader.ReadToEnd();
}

// 👎 reported — the innermost body still needs its braces
using (var stream = File.OpenRead(path))
using (var reader = new StreamReader(stream))
    return reader.ReadToEnd();
```

There is no flatter rewrite to suggest here. A using declaration (`using var reader = ...`)
only replaces the form that declares a variable, and it runs the disposal at the end of the
enclosing scope rather than the end of the block — so it is not an equivalent edit where the
block is what bounds the resource's life.

The exemption is for the stacked shape alone. A `using` that is the unbraced child of some
other statement is still reported:

```csharp
// 👎 reported — the 'if' has an unbraced child
if (enabled)
    using (var stream = File.OpenRead(path))
    {
        Work(stream);
    }
```

## How to fix violations

The code fix wraps the child statement in braces.
