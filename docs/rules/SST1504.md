# SST1504 — All accessors should be single-line or multi-line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes — expands single-line accessors |
| Default | Enabled |

## Cause

A property, indexer, or event mixes accessors whose body braces share a line with
accessors whose braces are on different lines. Empty brace bodies count too.
Auto accessors (`get;`) and expression-bodied accessors (`get => value;`) are ignored.

## Example

Before:

```csharp
class Counter
{
    private int _value;

    public int Value
    {
        get { return _value; }
        set
        {
            _value = value;
        }
    }
}
```

After:

```csharp
class Counter
{
    private int _value;

    public int Value
    {
        get
        {
            return _value;
        }
        set
        {
            _value = value;
        }
    }
}
```

## How to fix violations

The code fix expands every single-line accessor body in that property, indexer, or
event. It puts braces and statements on separate lines, adds four spaces of indentation
for statements, and keeps the file's line-ending style. If a comment between braces
and statements prevents any expansion, the whole edit is left unapplied.

You can also make all brace bodies single-line by hand. Both consistent forms satisfy
this rule; [SST1501](SST1501.md) and [SST1502](SST1502.md) exclude accessor bodies.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository
sets it to `error`:

```ini
[*.cs]
dotnet_diagnostic.SST1504.severity = error
```

Use `warning`, `suggestion`, or `silent` for a lower severity, or `none` to disable the rule.

## When to suppress

Suppress when a short getter and a longer setter are clearer in different layouts,
or disable the rule if your project intentionally uses that style.
