# SST1505 — Opening brace should not be followed by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes — removes the following blank lines |
| Default | Enabled |

## Cause

The line immediately after an opening brace is empty or contains only whitespace,
and the closing brace is on a later line. This applies to blocks, types, namespaces,
accessor lists, switches, and object or collection initializers, including empty bodies.
A comment directly after the opening-brace line is not a blank line.

## Example

Before:

```csharp
class Worker
{
    void Run()
    {

        return;
    }
}
```

After:

```csharp
class Worker
{
    void Run()
    {
        return;
    }
}
```

## How to fix violations

The code fix removes every consecutive blank line immediately after the opening
brace. It stops at the next nonblank line, preserving comments, code, and indentation.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository
sets it to `error`:

```ini
[*.cs]
dotnet_diagnostic.SST1505.severity = error
```

Use `warning`, `suggestion`, or `silent` for a lower severity, or `none` to disable the rule.

## When to suppress

Suppress when you must preserve an external sample's spacing. Disable the rule if
your project's style intentionally leaves space at the start of a body.
