# SST1506 — Element documentation header should not be followed by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A blank line separates an XML documentation comment (`///` or `/** ... */`)
from the declaration it describes. This applies to types, fields, events,
methods, properties, indexers and constructors.

A line containing a comment or a directive such as `#if` is not a blank line.
A gap containing both a directive and a blank line is still reported.

## Example

Reported:

```csharp
class C
{
    /// <summary>Does the work.</summary>

    public void M()
    {
    }
}
```

Corrected:

```csharp
class C
{
    /// <summary>Does the work.</summary>
    public void M()
    {
    }
}
```

## How to fix violations

The code fix removes all lines between the documentation comment and the
declaration. It also deletes any comments or directives in that gap. If the
gap contains either, remove only the blank lines by hand to preserve them.

## Configuration

This rule is enabled by default with severity `warning`. It has no rule-specific
options. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1506.severity = warning
```

Accepted values are `error`, `warning`, `suggestion`, `silent` and `none`.
Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when an external documentation format requires a blank
line after the documentation. Otherwise, keep the documentation next to the
declaration it describes.
