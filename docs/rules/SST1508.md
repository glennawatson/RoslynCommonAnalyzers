# SST1508 — Closing brace should not be preceded by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A blank line appears directly before `}` when the matching braces are on
different lines. This includes method and statement blocks, types,
namespaces, property accessors, switches and initializers.

A comment directly above the closing brace is not a blank line. A pair of
braces on the same line is not reported by this rule.

## Example

Reported:

```csharp
class C
{
    private void M()
    {
        return;

    }
}
```

Corrected:

```csharp
class C
{
    private void M()
    {
        return;
    }
}
```

## How to fix violations

The code fix removes every consecutive blank line directly above the closing
brace. It keeps comments, code and the brace's indentation.

## Configuration

This rule is enabled by default with severity `warning`. It has no rule-specific
options. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1508.severity = warning
```

Accepted values are `error`, `warning`, `suggestion`, `silent` and `none`.
Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when a required file layout reserves blank space before
closing braces. Otherwise, remove the gap so the end of the block is clear.
