# SST1509 — Opening brace should not be preceded by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A blank line appears directly before `{`, and no code precedes that brace
on the same line. This includes method and statement blocks, types,
namespaces, property accessors, switches and initializers.

A brace that follows code on the same line, such as the brace in
`public int Value { get; set; }`, is not reported by this rule.

## Example

Reported:

```csharp
class C
{
    private void M()

    {
        return;
    }
}
```

Corrected:

```csharp
class C
{
    private void M()
    {
        return;
    }
}
```

## How to fix violations

The code fix removes every consecutive blank line directly above the opening
brace. It keeps comments, code and the brace's indentation.

## Configuration

This rule is enabled by default with severity `warning`. It has no rule-specific
options. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1509.severity = warning
```

Accepted values are `error`, `warning`, `suggestion`, `silent` and `none`.
Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when a required layout separates a declaration from its
opening brace with a blank line. Otherwise, remove the gap.
