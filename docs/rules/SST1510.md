# SST1510 — Chained statement block should not be preceded by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Default severity | Warning |
| Code fix | Yes |

## Cause

An `else`, `catch` or `finally` starts more than one line after the preceding
part of the statement ends. The rule also reports gaps occupied by comments
or directives, even when there is no empty line.

The keyword can follow on the same line or the next line without triggering
this rule.

## Example

Reported:

```csharp
class C
{
    private void M(bool enabled)
    {
        if (enabled)
        {
        }

        else
        {
        }
    }
}
```

Corrected:

```csharp
class C
{
    private void M(bool enabled)
    {
        if (enabled)
        {
        }
        else
        {
        }
    }
}
```

## How to fix violations

The code fix removes consecutive blank lines directly above the keyword.
It keeps comments and directives. If either still separates the keyword
from the preceding code, the diagnostic remains. Move a comment inside
the block it describes when that preserves its meaning. If the line above
the keyword is not blank, accepting the fix makes no change.

## Configuration

This rule is enabled by default with severity `warning`. It has no rule-specific
options. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1510.severity = warning
```

Accepted values are `error`, `warning`, `suggestion`, `silent` and `none`.
Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when a comment or directive must remain between the
blocks, or when your project deliberately separates the clauses with blank
lines.
