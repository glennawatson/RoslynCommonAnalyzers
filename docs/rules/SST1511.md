# SST1511 — Do/while footer should not be preceded by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Default severity | Warning |
| Code fix | Yes |

## Cause

The `while` at the end of a `do` loop starts more than one line after the
loop body ends. Gaps occupied by comments or directives also count, even
when there is no empty line.

This rule does not check ordinary `while` loops. A `do` loop's `while` can
follow the body on the same line or the next line without a diagnostic.

## Example

Reported:

```csharp
class C
{
    private void M(bool condition)
    {
        do
        {
        }

        while (condition);
    }
}
```

Corrected:

```csharp
class C
{
    private void M(bool condition)
    {
        do
        {
        }
        while (condition);
    }
}
```

## How to fix violations

The code fix removes consecutive blank lines directly above `while`.
It keeps comments and directives, so the diagnostic remains if either
still separates `while` from the body. If the line above `while` is not
blank, accepting the fix makes no change. Move an intervening comment
inside the loop body when that preserves its meaning.

## Configuration

This rule is enabled by default with severity `warning`. It has no rule-specific
options. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1511.severity = warning
```

Accepted values are `error`, `warning`, `suggestion`, `silent` and `none`.
Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when a comment or directive must stay between the loop
body and `while`, or when a required layout uses a blank line there.
