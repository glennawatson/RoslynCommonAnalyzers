# SST1512 — Single-line comment should not be followed by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A blank line follows a `//` comment that is on a line of its own. Consecutive
`//` lines form one comment block; the rule checks the last line.

File-header comments before the first code in the file are exempt, so a
copyright header can have a blank line below it. Comments after code on the
same line, XML documentation comments and `/* ... */` comments are not checked.

## Example

Reported:

```csharp
class C
{
    private int M()
    {
        // Return the starting value.

        return 1;
    }
}
```

Corrected:

```csharp
class C
{
    private int M()
    {
        // Return the starting value.
        return 1;
    }
}
```

## How to fix violations

The code fix removes all consecutive blank lines after the comment block.
It preserves the comment text and indentation.

## Configuration

This rule is enabled by default with severity `warning`. It has no rule-specific
options. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1512.severity = warning
```

Accepted values are `error`, `warning`, `suggestion`, `silent` and `none`.
Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule for a section banner that needs blank space below it,
or a comment that describes the code above it. File-header comments do
not need suppression.
