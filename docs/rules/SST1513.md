# SST1513 — Closing brace should be followed by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A statement block ends with `}`, and the next code starts on the very next
line without a blank line. For example, this applies to an `if` block
followed by a method call.

No diagnostic is reported when the next code starts with `}`, `;`, `else`,
`catch`, `finally` or `while`. The `while` exception applies to ordinary
loops as well as `do` loops. Code on the same line as `}` is not checked.
A comment or directive on a separate intervening line also prevents a report.

Method, constructor, accessor, local-function and lambda bodies are excluded.
Spacing between members is covered by [SST1516](SST1516.md).

## Example

Reported:

```csharp
class C
{
    private void M(bool enabled)
    {
        if (enabled)
        {
        }
        System.Console.WriteLine();
    }
}
```

Corrected:

```csharp
class C
{
    private void M(bool enabled)
    {
        if (enabled)
        {
        }

        System.Console.WriteLine();
    }
}
```

## How to fix violations

The code fix inserts one blank line before the code on the next line.
It preserves the surrounding code, comments and indentation.

## Configuration

This rule is enabled by default with severity `warning`. It has no rule-specific
options. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1513.severity = warning
```

Accepted values are `error`, `warning`, `suggestion`, `silent` and `none`.
Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when a compact sequence of short blocks is clearer
without blank lines, and that layout matches your project's style.
