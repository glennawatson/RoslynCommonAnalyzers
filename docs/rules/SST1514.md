# SST1514 — Element documentation header should be preceded by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Default severity | Warning |
| Code fix | Yes |

## Cause

An XML documentation comment (`///` or `/** ... */`) starts immediately
after preceding code, without a separating line. This applies to types,
fields, events, methods, properties, indexers and constructors.

No blank line is required when no code precedes the header or the preceding
code is an opening brace. An intervening comment or directive also provides enough
separation to avoid a diagnostic.

## Example

Reported:

```csharp
class C
{
    private int _x = 0;
    /// <summary>Gets the value.</summary>
    public int X => _x;
}
```

Corrected:

```csharp
class C
{
    private int _x = 0;

    /// <summary>Gets the value.</summary>
    public int X => _x;
}
```

## How to fix violations

The code fix inserts one blank line before the documentation comment.
It leaves the comment text, declaration and indentation in place.

## Configuration

This rule is enabled by default with severity `warning`. It has no rule-specific
options. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1514.severity = warning
```

Accepted values are `error`, `warning`, `suggestion`, `silent` and `none`.
Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when a required documentation layout keeps adjacent
documented declarations together without blank lines.
