# SST1515 — Single-line comment should be preceded by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A `//` comment on a line of its own lacks a blank line above it. Consecutive
`//` lines form one comment block; the rule checks the first line.

No blank line is required at the start of a file, after a directive such as
`#if` or `#else`, or after a line ending in `{` or `=>`. Comments after code
on the same line, XML documentation comments and `/* ... */` comments are
not checked.

Keep a comment directly below an expression-body arrow (`=>`). Adding a
blank line there would trigger [SST1537](SST1537.md).

## Example

Reported:

```csharp
class C
{
    private int M()
    {
        var value = 1;
        // Return the result.
        return value;
    }
}
```

Corrected:

```csharp
class C
{
    private int M()
    {
        var value = 1;

        // Return the result.
        return value;
    }
}
```

## How to fix violations

The code fix inserts one blank line before the first line of the comment
block. It preserves the comment text and indentation.

## Configuration

This rule is enabled by default with severity `warning`. It has no rule-specific
options. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1515.severity = warning
```

Accepted values are `error`, `warning`, `suggestion`, `silent` and `none`.
Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule when a standalone comment describes the code immediately
above it and a blank line would make that relationship unclear.
