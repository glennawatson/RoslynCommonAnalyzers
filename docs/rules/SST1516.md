# SST1516 — Elements should be separated by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A declaration in a type, namespace or file starts on the same line as the
preceding declaration ends, or on the next line. A leading comment or
XML documentation comment counts as the start of the second declaration.

Fields need separation too. The rule also checks consecutive top-level
statements. It does not check enum values, `using` directives, individual
accessors, or statements inside a method. Spacing after statement blocks
is covered by [SST1513](SST1513.md).

## Example

Reported:

```csharp
class C
{
    private void A()
    {
    }
    private void B()
    {
    }
}
```

Corrected:

```csharp
class C
{
    private void A()
    {
    }

    private void B()
    {
    }
}
```

## How to fix violations

The code fix inserts one blank line above the second declaration, before
its leading comment or documentation when present. It preserves comment
text and indentation.

The fix does not split declarations that share a line. Put each declaration
on its own line by hand before applying the fix.

## Configuration

This rule is enabled by default with severity `warning`. It has no rule-specific
options. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1516.severity = warning
```

Accepted values are `error`, `warning`, `suggestion`, `silent` and `none`.
Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress this rule for a compact group of related fields or short members
when blank lines would make the group harder to read, or for top-level
statements that your project keeps together.
