# SST1519 — Braces should not be omitted from a multi-line child statement

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

The body of an `if`, `else`, `for`, `foreach`, `while`, `do`, `using`, `lock`, or
`fixed` statement spans several lines without braces. The body itself must span
several lines; putting a one-line body below the condition does not trigger this rule.

A body that is another `if`, `using`, `lock`, or `fixed` statement is excluded.
This allows `else if` chains and stacked resource statements.

## Example

Reported:

```csharp
internal class C
{
    private void M(bool enabled)
    {
        if (enabled)
            System.Console
                .WriteLine();
    }
}
```

Corrected:

```csharp
internal class C
{
    private void M(bool enabled)
    {
        if (enabled)
        {
            System.Console
                .WriteLine();
        }
    }
}
```

## How to fix violations

The code fix adds braces on separate lines, aligned with the control statement.
It indents the body's first line by four spaces beyond that statement and keeps
the remaining body text. A comment or directive between the control statement
and its body prevents the edit; add braces by hand in that case. A comment after
the body's last statement ends up after the new closing brace, so review its position.

## Configuration

There are no rule-specific options. The default severity is `warning`.

```ini
[*.cs]
dotnet_diagnostic.SST1519.severity = warning
```

Use `error` to fail the build or `none` to disable the rule.
To require braces around one-line bodies too, enable [SST1503](SST1503.md).

## When to suppress

Suppress when a deliberate layout makes a wrapped body clear and your team's
style allows it. Otherwise, braces make the body's extent easier to see.
