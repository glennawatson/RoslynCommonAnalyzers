# SST1520 — Braces should be used consistently

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An `if`/`else if`/`else` chain mixes bodies with braces and bodies without them.
The diagnostic appears on the first `if`. A chain with braces on every body, or
with no braces on any body, is accepted.

## Example

Reported:

```csharp
internal class C
{
    private void M(bool enabled)
    {
        if (enabled)
        {
            System.Console.WriteLine();
        }
        else
            System.Console.WriteLine();
    }
}
```

Corrected:

```csharp
internal class C
{
    private void M(bool enabled)
    {
        if (enabled)
        {
            System.Console.WriteLine();
        }
        else
        {
            System.Console.WriteLine();
        }
    }
}
```

## How to fix violations

The code fix adds braces to each unbraced body in the chain and keeps `else if`
chains intact. It puts the braces on separate lines and indents each body's
first line by four spaces. Existing braces and the remaining body text stay intact.

A comment or directive between a clause and its body prevents that body from
being changed; add its braces by hand. A comment after the body's last statement
ends up after the new closing brace, so review its position.

## Configuration

There are no rule-specific options. The default severity is `warning`.

```ini
[*.cs]
dotnet_diagnostic.SST1520.severity = warning
```

Use `error` to fail the build or `none` to disable the rule.

## When to suppress

Suppress if your team deliberately allows short branches without braces alongside
longer braced branches. Otherwise, apply the fix to make the chain consistent.
