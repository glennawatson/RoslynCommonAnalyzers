# SST1521 — Lines should not be too long

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A line exceeds the configured length, which defaults to 120 characters.
Indentation counts, each tab counts as one character, and the line break does not count.
Long comments made of separate words are checked too.

A long run without spaces inside a comment, string, or character literal is exempt
if it crosses the limit and still would not fit on its own line at the same indentation.
This covers long URLs and encoded strings. Long code, such as a chain of member
accesses without spaces, is still reported.

## Example

With `stylesharp.max_line_length = 40`, the property line has 42 characters and is reported:

```csharp
public class C
{
    public int Value => 1 + 1 + 1 + 1 + 1;
}
```

Corrected:

```csharp
public class C
{
    public int Value =>
        1 + 1 + 1 + 1 + 1;
}
```

## How to fix violations

There is no code fix. Wrap arguments, conditions, or call chains at a readable
point, or move part of an expression into a named local variable.

## Configuration

These are the defaults:

```ini
[*.cs]
dotnet_diagnostic.SST1521.severity = warning
stylesharp.max_line_length = 120
```

You can also set `stylesharp.SST1521.max_line_length`. Both keys accept a positive
integer. A valid rule-specific value takes priority, followed by a valid project-wide
value, then `120`. Zero, negative values, and invalid text are ignored.
Use severity `error` to fail the build or `none` to disable the rule.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress for text whose exact layout must be retained, such as a copied query or
aligned data table, when wrapping would make it harder to check. Raise the limit
for a project that consistently uses wider lines.
