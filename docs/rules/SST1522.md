# SST1522 — Files should not be too long

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A file contains more code lines than the configured maximum, which defaults to 500.
The diagnostic appears once, at the start of the file's code.

Declarations, statements, and braces count. Blank lines, comment-only lines,
documentation, and directive-only lines do not. Every line inside a multi-line
string counts, including empty lines in the string. Generated code is excluded.

## Example

With `stylesharp.max_file_lines = 5`, this file has eight code lines and is reported:

```csharp
public class Orders
{
    public int Count { get; set; }
}
public class Settings
{
    public int Limit { get; set; }
}
```

Corrected: put each type in its own file. Each file has four code lines.

`Orders.cs`:

```csharp
public class Orders
{
    public int Count { get; set; }
}
```

`Settings.cs`:

```csharp
public class Settings
{
    public int Limit { get; set; }
}
```

## How to fix violations

There is no code fix. Move separate types into separate files. If one type does
several jobs, move one of those jobs into another type.

## Configuration

These are the defaults:

```ini
[*.cs]
dotnet_diagnostic.SST1522.severity = warning
stylesharp.max_file_lines = 500
```

You can also set `stylesharp.SST1522.max_file_lines`. Both keys accept a positive
integer. A valid rule-specific value takes priority, followed by a valid project-wide
value, then `500`. Zero, negative values, and invalid text are ignored.
Use severity `error` to fail the build or `none` to disable the rule.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress or raise the limit for a large table of constants or another file whose
contents are easier to check together. Do not remove useful comments to reduce
the count; comments do not count.
