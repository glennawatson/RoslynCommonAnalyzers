# SST1523 — Members should not be too long

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A method, constructor, operator, conversion operator, property or event accessor,
or local function exceeds the configured maximum, which defaults to 60 code lines.
Its declaration and braces count as well as its body.

Blank lines, comments, documentation, and directive-only lines do not count.
Lines inside a multi-line string do count. Declarations without a body, such as
abstract methods and auto-property accessors, are excluded.

A local function's lines also count toward its containing method. Both can be
reported if both exceed the limit.

## Example

With `stylesharp.max_member_lines = 4`, this six-line method is reported:

```csharp
public class C
{
    public int Total()
    {
        var total = 1;
        total += 2;
        return total;
    }
}
```

Corrected: the method has four code lines.

```csharp
public class C
{
    public int Total()
    {
        return 1 + 2;
    }
}
```

## How to fix violations

There is no code fix. Simplify repeated work or move a separate step into a
named method. For a long branch in a `switch`, extract the branch's work into
a method; see [SST1524](SST1524.md).

## Configuration

These are the defaults:

```ini
[*.cs]
dotnet_diagnostic.SST1523.severity = warning
stylesharp.max_member_lines = 60
```

You can also set `stylesharp.SST1523.max_member_lines`. Both keys accept a positive
integer. A valid rule-specific value takes priority, followed by a valid project-wide
value, then `60`. Zero, negative values, and invalid text are ignored.
Use severity `error` to fail the build or `none` to disable the rule.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress or raise the limit for a long table-building method or a sequence that
is clearer kept together. Avoid splitting a method at an arbitrary line if the
parts would have no clear purpose.
