# SST1525 — Switch sections with multiple statements should use braces

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `switch` section has two or more statements outside a shared pair of braces.
A `break` or `return` counts as a statement, so a call followed by `break` needs
braces. A section containing only one statement or one braced block is accepted.

## Example

Reported:

```csharp
internal class C
{
    private void M(int x)
    {
        switch (x)
        {
            case 1:
                x++;
                x--;
                break;
        }
    }
}
```

Corrected:

```csharp
internal class C
{
    private void M(int x)
    {
        switch (x)
        {
            case 1:
            {
                x++;
                x--;
                break;
            }
        }
    }
}
```

## How to fix violations

The code fix wraps all statements in the section in braces on separate lines,
aligned with the label. It indents the first statement four spaces beyond the
label and keeps the remaining statement text.

A comment or directive between the last label and the first statement prevents
the edit; add braces by hand in that case. A comment after the last statement
ends up after the new closing brace, so review its position. Braces also limit
where variables declared in the section can be used; check any use from another case.

## Configuration

There are no rule-specific options. The default severity is `warning`.

```ini
[*.cs]
dotnet_diagnostic.SST1525.severity = warning
```

Use `error` to fail the build or `none` to disable the rule.
See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress if your team permits unbraced sections or a section deliberately shares
a variable with another case. If you require braces here, disable [SST1534](SST1534.md),
which asks to remove braced blocks that declare nothing.
