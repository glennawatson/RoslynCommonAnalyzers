# SST1526 — Wrapped binary operators should sit on the configured side of the line break

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled |

## Cause

A binary operator, such as `+`, `==`, `&&`, or `??`, has a line break on the
wrong side for your configured style. The default style puts the operator at
the start of the next line. Each operator is checked separately; operators
with no line break beside them are not reported.

## Example

With the rule enabled and the default `before` style, this is reported:

```csharp
internal class C
{
    private static int M(int a, int b)
    {
        return a +
            b;
    }
}
```

Corrected:

```csharp
internal class C
{
    private static int M(int a, int b)
    {
        return a
            + b;
    }
}
```

## How to fix violations

The code fix moves the line break to the configured side of the operator.
It keeps the continuation indentation and puts one space on the unbroken side.
It is available only when one side has a line break and both surrounding gaps
contain whitespace alone. If comments or directives are in the way, or the
operator has a break on both sides, adjust the layout by hand.

## Configuration

The rule is disabled by default. Enable it and choose a style in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1526.severity = warning
stylesharp.binary_operator_new_line = before
```

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.binary_operator_new_line` | `before`, `after` | `before` |
| `stylesharp.SST1526.binary_operator_new_line` | `before`, `after` | Inherits the project-wide value |

`before` puts the line break before the operator; `after` puts it after.
The first non-empty value wins, with the rule-specific key taking priority.
Values ignore case. An unrecognised value uses `before`.
Use severity `error` to fail the build or `none` to disable the rule.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Leave the rule disabled if your team accepts either placement. Suppress a local
exception when aligning a formula makes it easier to read.
