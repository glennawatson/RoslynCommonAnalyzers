# SST1527 — A wrapped expression-body arrow should sit on the configured side of the line break

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled |

## Cause

An expression-bodied member or local function has a line break on the wrong side
of `=>` for your configured style. The default style keeps the arrow at the end
of the declaration line.

Arrows with no adjacent line break are not reported. Lambda and switch-expression
arrows are excluded. An arrow separated from its declaration by a directive,
such as `#if`, is also excluded.

## Example

With the rule enabled and the default `after` style, this is reported:

```csharp
internal class C
{
    private static int M(int x)
        => x;
}
```

Corrected:

```csharp
internal class C
{
    private static int M(int x) =>
        x;
}
```

## How to fix violations

The code fix moves the line break to the configured side of `=>`. It keeps the
continuation indentation and puts one space on the unbroken side. It is available
only when one side has a line break and both surrounding gaps contain whitespace
alone. With comments, directives, or breaks on both sides, adjust the layout by hand.

Moving the arrow can push the declaration past your line-length limit. If that
happens, wrap the parameter list as well.

## Configuration

The rule is disabled by default. Enable it and choose a style in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1527.severity = warning
stylesharp.arrow_token_new_line = after
```

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.arrow_token_new_line` | `before`, `after` | `after` |
| `stylesharp.SST1527.arrow_token_new_line` | `before`, `after` | Inherits the project-wide value |

`before` puts the line break before the arrow; `after` puts it after.
The first non-empty value wins, with the rule-specific key taking priority.
Values ignore case. An unrecognised value uses `after`.
Use severity `error` to fail the build or `none` to disable the rule.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Leave the rule disabled if your team accepts either placement. Suppress a local
exception when moving the arrow would make a deliberately aligned set of members
harder to read.
