# SST1528 — A wrapped initializer '=' should sit on the configured side of the line break

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled |

## Cause

A field or local variable initializer has a line break on the wrong side of `=`
for your configured style. The default style keeps `=` at the end of the line
containing the variable's name.

Property initializers, parameter defaults, and assignments to existing variables
are excluded. An initializer with no line break beside `=` is not reported.

## Example

With the rule enabled and the default `after` style, this is reported:

```csharp
internal class C
{
    public static readonly int Value
        = 3;
}
```

Corrected:

```csharp
internal class C
{
    public static readonly int Value =
        3;
}
```

## How to fix violations

The code fix moves the line break to the configured side of `=`. It keeps the
continuation indentation and puts one space on the unbroken side. It is available
only when one side has a line break and both surrounding gaps contain whitespace
alone. With comments, directives, or breaks on both sides, adjust the layout by hand.

## Configuration

The rule is disabled by default. Enable it and choose a style in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1528.severity = warning
stylesharp.equals_token_new_line = after
```

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.equals_token_new_line` | `before`, `after` | `after` |
| `stylesharp.SST1528.equals_token_new_line` | `before`, `after` | Inherits the project-wide value |

`before` puts the line break before `=`; `after` puts it after.
The first non-empty value wins, with the rule-specific key taking priority.
Values ignore case. An unrecognised value uses `after`.
Use severity `error` to fail the build or `none` to disable the rule.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Leave the rule disabled if your team accepts either placement. Suppress a local
exception for declarations whose alignment is easier to check with `=` on the
other side of the break.
