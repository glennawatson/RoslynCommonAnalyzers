# SST1529 — Wrapped call-chain operators should sit on the configured side of the line break

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled |

## Cause

A member access using `.` or `?.` has a line break on the wrong side for your
configured style. The default style puts the operator at the start of the next
line. This applies to member access as well as method-call chains. Links with
no adjacent line break are not reported.

## Example

With the rule enabled and the default `before` style, this is reported:

```csharp
internal class C
{
    private static void M(string s)
    {
        _ = s?.
            Trim();
    }
}
```

Corrected:

```csharp
internal class C
{
    private static void M(string s)
    {
        _ = s
            ?.Trim();
    }
}
```

## How to fix violations

The code fix moves the line break to the configured side of `.` or `?.` and
keeps the continuation indentation. It keeps `?.` together and removes spaces
on the unbroken side.

The fix is available only when one side has a line break and both surrounding
gaps contain whitespace alone. With comments, directives, or breaks on both sides,
adjust the layout by hand.

## Configuration

The rule is disabled by default. Enable it and choose a style in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1529.severity = warning
stylesharp.null_conditional_new_line = before
```

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.null_conditional_new_line` | `before`, `after` | `before` |
| `stylesharp.SST1529.null_conditional_new_line` | `before`, `after` | Inherits the project-wide value |

`before` puts the line break before the operator; `after` puts it after.
The first non-empty value wins, with the rule-specific key taking priority.
Values ignore case. An unrecognised value uses `before`.
Use severity `error` to fail the build or `none` to disable the rule.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Leave the rule disabled if your team accepts either placement. Suppress a local
exception when matching a surrounding chain layout is clearer than moving one link.
