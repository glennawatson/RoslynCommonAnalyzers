# SST1530 — A base list should not start on its own line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled |

## Cause

The colon before a type's base class or interfaces starts on a separate line. The rule reports this
only when the base list occupies one line and fits on the declaration line within the line-length limit.
Indentation counts towards the limit.

## Example

Before:

```csharp
internal interface IMarker { }

internal class Foo
    : IMarker
{
}
```

After:

```csharp
internal interface IMarker { }

internal class Foo : IMarker
{
}
```

## How to fix violations

The code fix replaces the whitespace before the colon with one space. If a comment or directive sits
in that gap, the fix leaves the code unchanged. Move the comment or adjust the declaration by hand.

## Configuration

Enable the rule in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1530.severity = warning
stylesharp.max_line_length = 120
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.

`stylesharp.max_line_length` accepts a positive integer and defaults to `120`. A valid
`stylesharp.SST1521.max_line_length` takes precedence; both keys are shared with
[SST1521](SST1521.md). Invalid values fall back to the other key, then to `120`.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Disable the rule with `dotnet_diagnostic.SST1530.severity = none` if your project puts base lists on
separate lines for consistency. Base lists that span multiple lines or exceed the limit need no suppression.
