# SST1531 — A short initializer should be written on a single line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled |

## Cause

A non-empty object or collection initializer has its opening and closing braces on different lines,
but fits within the line-length limit when joined. The length includes indentation and the code before
the opening brace, through the closing brace.

Initializers with a comment or directive in a gap that would be joined are left alone. So are
initializers containing a string literal that spans lines. Array initializers, collection expressions
such as `[1, 2]`, and method bodies are not checked.

## Example

Before:

```csharp
internal class Point
{
    public int X { get; set; }
    public int Y { get; set; }
}

internal class C
{
    private static Point Make() => new Point
    {
        X = 1,
        Y = 2,
    };
}
```

After:

```csharp
internal class Point
{
    public int X { get; set; }
    public int Y { get; set; }
}

internal class C
{
    private static Point Make() => new Point { X = 1, Y = 2, };
}
```

## How to fix violations

The code fix joins the initializer to the preceding code. It replaces each line break and its
surrounding whitespace with one space, or no space before a comma. It keeps existing spacing within
each line and keeps any trailing comma.

## Configuration

Enable the rule in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1531.severity = warning
stylesharp.max_line_length = 120
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.

`stylesharp.max_line_length` accepts a positive integer and defaults to `120`. A valid
`stylesharp.SST1521.max_line_length` takes precedence; both keys are shared with
[SST1521](SST1521.md). Invalid values fall back to the other key, then to `120`.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Disable the rule with `dotnet_diagnostic.SST1531.severity = none` if keeping one assignment or item per
line makes your initializers easier to read or review. Initializers that exceed the limit need no suppression.
