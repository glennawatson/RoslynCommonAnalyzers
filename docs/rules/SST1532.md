# SST1532 — Files should use consistent line endings

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled |

## Cause

A source file contains a line ending that differs from the configured style. This includes a file
that uses one style throughout when the project requires the other. One diagnostic marks the first
line with a wrong ending.

## Example

With the default `lf` setting, change CRLF endings to LF endings. In these displays, `\r\n` means
a CRLF line ending and `\n` means an LF line ending; the escapes stand for invisible characters in the file.

Before:

```text
internal class C\r\n
{\r\n
}\r\n
```

After:

```text
internal class C\n
{\n
}\n
```

## How to fix violations

The code fix converts every mismatched line ending in the file to the configured style. It does not
add a missing final newline; [SST1518](SST1518.md) covers that.

The edit includes line endings inside multiline string literals. Check those strings if their exact
contents matter.

## Configuration

Enable the rule in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1532.severity = warning
stylesharp.line_ending = lf
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.

`stylesharp.line_ending` accepts `lf` or `crlf` and defaults to `lf`. A non-empty
`stylesharp.SST1532.line_ending` overrides it. Values are case-insensitive; an unrecognised value
uses `lf`. See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Disable the rule with `dotnet_diagnostic.SST1532.severity = none` for files whose exact line endings
must be preserved, such as test inputs stored in multiline strings. For a file that needs a different
uniform style, set its line-ending option instead.
