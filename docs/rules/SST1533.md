# SST1533 — A source file should declare at least one type

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | No |
| Default | Disabled |

## Cause

A source file contains `using` directives, `extern alias` directives, or comments, but no namespace,
type, or top-level statement. This can leave an unused file after its code moves elsewhere.

Empty or whitespace-only files, files with assembly or module attributes, and generated files are
not reported. A namespace declaration also satisfies the rule, even if it contains no types.

Source inside an inactive `#if` region prevents a report. This allows a file to provide an API only on
frameworks that need it. An empty `#if` region does not exempt a file that contains only usings or comments.

## Example

Before, the entire file contains only a leftover comment:

```csharp
// The widget implementation belongs here.
```

After, restore the intended declaration:

```csharp
internal class Widget
{
}
```

## How to fix violations

Restore the missing code, or delete the unneeded file.

There is no code fix.

## Configuration

The rule is disabled by default and has no options beyond severity. Enable it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1533.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.

See [configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress the rule for a deliberate placeholder or a file used only to share global usings. Set
`dotnet_diagnostic.SST1533.severity = none` for those files. Files with inactive source need no suppression.
