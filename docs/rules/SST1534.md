# SST1534 — Switch section braces that scope nothing should be removed

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A switch section's only statement is a block that declares nothing.

```csharp
// 👎 reported
case 1:
    {
        return 2;
    }

// 👍
case 1:
    return 2;
```

## Rule description

A switch section is already its own statement list, so wrapping it in braces adds an indentation level for
nothing.

The one time the braces earn their place is when the section declares something. Every section of a switch
shares a single declaration space, so a local declared in one collides with the same name in another unless a
block scopes it:

```csharp
case 1:
    {
        var result = Compute();   // the braces are load-bearing
        return result;
    }

case 2:
    {
        var result = Other();     // same name, different section
        return result;
    }
```

### What is reported

- A section whose single statement is a non-empty block that declares no local, no local function, and no
  pattern or `out` variable.

### What is not reported

- A block that declares any of those, where removing the braces could collide with a sibling section.
- A section with no braces, or one whose block is empty.

## How to fix violations

Remove the braces and let the statements sit in the section. The rewritten section is formatter-annotated, so
the lifted statements are re-indented.

## Performance

The rule registers on the switch section and rejects on shape before scanning: only a section holding exactly
one non-empty block is walked, and that walk stops at the first declaration it finds.
