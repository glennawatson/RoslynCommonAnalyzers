# SST1534 — Switch section braces that scope nothing should be removed

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `case` or `default` section contains one non-empty braced block that declares no local variables,
local functions, pattern variables such as `value is string text`, or variables such as `out var result`.
The braces add indentation without keeping any of those names separate from other cases.

Blocks containing those declarations, empty blocks, and sections with statements outside the block
are not reported.

## Example

Before:

```csharp
internal class C
{
    public int M(int value)
    {
        switch (value)
        {
            case 1:
                {
                    return 2;
                }
            default:
                return 0;
        }
    }
}
```

After:

```csharp
internal class C
{
    public int M(int value)
    {
        switch (value)
        {
            case 1:
                return 2;
            default:
                return 0;
        }
    }
}
```

## How to fix violations

The code fix removes the braces and reindents the statements. Comments attached to the removed
braces can be lost, including a comment on the opening-brace line. Move those comments to a statement
before applying the fix. The fix is not offered when the block contains a directive such as `#region`.

## Configuration

The rule is enabled as a warning by default and has no options beyond severity:

```ini
[*.cs]
dotnet_diagnostic.SST1534.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.

## When to suppress

Disable the rule with `dotnet_diagnostic.SST1534.severity = none` if your project keeps braces around
switch sections for consistency. This also avoids a conflict with [SST1525](SST1525.md), which asks
for braces around sections with multiple statements.
