# SST1535 — A constructor initializer colon should not be followed by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes (remove the blank line) |

## Cause

A blank line follows the `:` of a constructor initializer.

## Rule description

The `:` binds the `base` or `this` call to the declaration above it. A blank line after the colon splits
one declaration in two on the page, so the initializer reads as an unrelated fragment.

Wrapping the initializer onto its own line is fine; leaving the colon dangling above empty space is not.

```csharp
// 👎 reported
public C()
    :

    base(1)
{
}

// 👍 not reported
public C()
    : base(1)
{
}
```

## How to fix violations

Remove the blank line, or move the initializer up onto the colon's line.
