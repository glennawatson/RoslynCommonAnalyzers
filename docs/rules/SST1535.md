# SST1535 — A constructor initializer colon should not be followed by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

The line immediately after a constructor initializer's `:` is blank, separating it from the `base`
or `this` call. A call on the next line is allowed. A comment on that next line also prevents a report.

## Example

Before:

```csharp
public class Base
{
    public Base(int value) { }
}

public sealed class C : Base
{
    public C()
        :

        base(1)
    {
    }
}
```

After applying the code fix:

```csharp
public class Base
{
    public Base(int value) { }
}

public sealed class C : Base
{
    public C()
        :
        base(1)
    {
    }
}
```

## Code fix

The fix removes all consecutive blank lines immediately after the colon. It keeps indentation and
comments and leaves the call on a separate line. You can also move the call onto the colon's line by hand.

## Configuration

The rule is enabled as a warning by default and has no options beyond severity:

```ini
[*.cs]
dotnet_diagnostic.SST1535.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.

## When to suppress

Suppress the rule if a required project format deliberately leaves this gap. Set
`dotnet_diagnostic.SST1535.severity = none` for the affected files.
