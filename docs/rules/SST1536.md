# SST1536 — A conditional operator token should not be followed by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

The line immediately after the `?` or `:` in a conditional expression is blank, separating the
operator from its value. A value on the next line is allowed. A comment on that next line also
prevents a report. The rule does not check `?.` or `??` operators.

## Example

Before:

```csharp
public sealed class C
{
    public int M(bool flag) => flag
        ?

        1
        : 0;
}
```

After applying the code fix:

```csharp
public sealed class C
{
    public int M(bool flag) => flag
        ?
        1
        : 0;
}
```

The same rule applies to a blank line after the colon.

## Code fix

The fix removes all consecutive blank lines immediately after the reported operator. It keeps
indentation and comments and leaves the value on a separate line. You can also move the value onto
the operator's line by hand.

## Configuration

The rule is enabled as a warning by default and has no options beyond severity:

```ini
[*.cs]
dotnet_diagnostic.SST1536.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.

## When to suppress

Suppress the rule if a required project format deliberately separates the operator from its value
with a blank line. Set `dotnet_diagnostic.SST1536.severity = none` for the affected files.
