# SST1537 — An expression-body arrow should not be followed by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

The line immediately after an expression-bodied member's `=>` is blank, separating the arrow from
the expression. An expression on the next line is allowed. This rule does not check lambda arrows
or switch-expression arms.

A comment directly below the arrow prevents a report. A blank line before that comment is still reported.

## Example

Before:

```csharp
public sealed class C
{
    public int M()
        =>

        42;
}
```

After applying the code fix:

```csharp
public sealed class C
{
    public int M()
        =>
        42;
}
```

## Code fix

The fix removes all consecutive blank lines immediately after the arrow. It keeps indentation and
comments and leaves the expression on a separate line. You can also move the expression onto the
arrow's line by hand.

## Configuration

The rule is enabled as a warning by default and has no options beyond severity:

```ini
[*.cs]
dotnet_diagnostic.SST1537.severity = warning
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.

## When to suppress

Suppress the rule if a required project format deliberately leaves this gap. Set
`dotnet_diagnostic.SST1537.severity = none` for the affected files. A comment directly below the
arrow needs no suppression or extra blank line.
