# SST1537 — An expression-body arrow should not be followed by a blank line

| Item | Value |
| --- | --- |
| Category | Layout |
| Severity | Warning |
| Code fix | Yes (remove the blank line) |

## Cause

A blank line follows the `=>` of an expression-bodied member.

## Rule description

An expression-bodied member is a declaration and its single expression. A blank line after the `=>`
pushes the expression away from the member it belongs to and makes the member look unfinished.

Wrap after the arrow when the expression is long, but keep the two on consecutive lines. A comment
between them is content rather than a gap, and is not reported.

```csharp
// 👎 reported
public int Value()
    =>

    42;

// 👍 not reported
public int Value()
    => 42;
```

## How to fix violations

Remove the blank line so the expression follows its arrow.
