# SST1600 — Elements should be documented

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A type, delegate, method, constructor, destructor, property, field, or field-like event has no XML
documentation comment and falls within the configured coverage. By default, public, protected, and
internal declarations are covered. Ordinary `//` comments do not count as XML documentation.

A containing type limits visibility: a public member inside an internal class follows the internal
setting. Interfaces have their own setting. Private fields, including constants and
`private protected` fields, have a separate option from other private members.

Overridden methods and properties and explicit interface implementations are skipped, as is generated
code. Partial declarations are excluded here; [SST1601](SST1601.md) covers partial types and methods.
[SST1602](SST1602.md) covers enum items.

## Example

Before:

```csharp
public class Widget { }
```

After:

```csharp
/// <summary>A widget.</summary>
public class Widget { }
```

## How to fix violations

Add an XML documentation comment describing the declaration. Where documentation should come from
another declaration, use `<inheritdoc/>`. If several fields share one declaration, one comment
above it covers all their names.

There is no code fix.

## Configuration

The rule is enabled as a warning by default. These `.editorconfig` entries show the coverage defaults:

```ini
[*.cs]
dotnet_diagnostic.SST1600.severity = warning
stylesharp.document_exposed_elements = true
stylesharp.document_internal_elements = true
stylesharp.document_private_elements = false
stylesharp.document_private_fields = false
stylesharp.document_interfaces = all
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.

The first four coverage options accept `true` or `false`; missing or invalid values use the defaults
shown. `document_exposed_elements` covers public and protected declarations; `document_internal_elements`
covers internal declarations. Turning on `document_private_elements` requires all non-field declarations
outside interfaces, even if the exposed or internal option is off. Field-like events follow the field options.

`stylesharp.document_interfaces` accepts `all` (default), `exposed`, or `none`. `all` requires every
interface declaration; `exposed` skips internal declarations; `none` skips interface declarations.
Public interface members remain required in both `all` and `exposed` modes, including those in internal
interfaces. Explicitly non-public interface members follow `document_private_elements`. `true` means
`all`, `false` means `none`, and unrecognised values use `all`.

These options also affect related coverage rules. See
[documentation coverage scope](../CONFIGURATION.md#documentation-coverage-scope).

## When to suppress

Reduce the coverage when documentation is not useful for internal implementation details. For example,
set `stylesharp.document_internal_elements = false` to skip internal classes and their members.
For a deliberate exception, set `dotnet_diagnostic.SST1600.severity = none` for the affected files.
