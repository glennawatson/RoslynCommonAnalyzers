# SST1602 — Enumeration items should be documented

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An enum item has no XML documentation comment and its enum falls within the configured coverage.
Public, protected, and internal enums are covered by default. A summary on the enum itself does not
document its individual items. Generated code is excluded.

## Example

Before:

```csharp
/// <summary>Traffic light colors.</summary>
public enum Color
{
    Red,
}
```

After:

```csharp
/// <summary>Traffic light colors.</summary>
public enum Color
{
    /// <summary>Stop.</summary>
    Red,
}
```

## How to fix violations

Add an XML documentation comment above each reported enum item to explain what the value means.

There is no code fix.

## Configuration

The rule is enabled as a warning by default. These `.editorconfig` entries show the coverage defaults:

```ini
[*.cs]
dotnet_diagnostic.SST1602.severity = warning
stylesharp.document_exposed_elements = true
stylesharp.document_internal_elements = true
stylesharp.document_private_elements = false
```

Severity accepts `none`, `silent`, `suggestion`, `warning`, or `error`.

The coverage options accept `true` or `false`; missing or invalid values use the defaults shown.
Containing types limit visibility: a public enum nested in an internal class follows the internal
setting. Turning on `document_private_elements` requires items in all enums, even if the exposed or
internal option is off. `document_private_fields` does not control enum items.

These settings are shared with the other
[documentation coverage rules](../CONFIGURATION.md#documentation-coverage-scope).

## When to suppress

Reduce coverage for internal or private enums whose values need no separate documentation. For
a deliberate exception, set `dotnet_diagnostic.SST1602.severity = none` for the affected files.
