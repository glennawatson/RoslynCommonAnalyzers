# SST1604 — Element documentation should have a summary

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning |
| Code fix | No |

## Cause

A member has a documentation comment that does not contain a `<summary>`.

## Rule description

When a member is documented, the documentation should include a `<summary>`
(unless it uses `<inheritdoc>`).

## What is not reported

A further part of a partial declaration that describes itself with `<content>`. One part carries the
`<summary>` that says what the type is; the rest say what they add. Repeating the summary in every
part states the same thing several times and leaves the reader to work out which copy is
authoritative. An empty `<content>` does not stand in for the summary, and neither does `<content>`
on a type that is not partial — there is no other part to carry it.
