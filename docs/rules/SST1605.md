# SST1605 — Partial element documentation should have a summary

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning (disabled by default) |
| Code fix | No |

## Cause

A partial type or partial method has an XML documentation comment with no `<summary>`.
This includes private declarations that already have documentation.

A comment with a populated `<content>` element is accepted: it describes what this part
adds to the type or method. An empty `<content>` does not replace a summary. Declarations
with no documentation, or with `<inheritdoc/>` outside other elements, are not reported.

## How to fix violations

Add a summary describing the type or method. For an additional part, use `<content>` to
describe what that part adds. There is no code fix.

Before:

```csharp
/// <remarks>Contains parsing members.</remarks>
public partial class Parser { }
```

After:

```csharp
/// <content>Contains parsing members.</content>
public partial class Parser { }
```

## Configuration

Disabled by default. Enable it in `.editorconfig`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1605.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled if one part provides all the documentation your readers need.
If the other parts need their own descriptions, use `<content>` instead of repeating
the summary.
