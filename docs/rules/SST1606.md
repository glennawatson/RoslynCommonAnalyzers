# SST1606 — Summary documentation should have text

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning |
| Code fix | No |

## Cause

A documented type or member has an empty `<summary>`. Both `<summary/>` and a summary
containing only spaces or line breaks are reported.

The rule checks types, delegates, methods, constructors, destructors, properties and
enum members, including private declarations. It does not check fields, events,
indexers or local functions. A missing summary is handled by [SST1604](SST1604.md).
A comment with `<inheritdoc/>` outside other elements is skipped; a summary containing
`<inheritdoc/>` is also accepted.

## How to fix violations

Describe what the type or member does. There is no code fix.

Before:

```csharp
/// <summary></summary>
public class Widget { }
```

After:

```csharp
/// <summary>A reusable screen component.</summary>
public class Widget { }
```

## Configuration

Enabled by default with severity `warning`. To treat it as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1606.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress it for a required empty tag in a documentation template that another tool
fills before publication. For inherited documentation, use `<inheritdoc/>`.
