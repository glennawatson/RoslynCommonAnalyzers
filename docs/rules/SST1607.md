# SST1607 — Partial element summary should have text

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning (disabled by default) |
| Code fix | No |

## Cause

A partial type or partial method has an empty `<summary>`. A self-closing `<summary/>`
or a summary containing only spaces or line breaks is also reported. This applies to
existing documentation at every access level.

Declarations without a summary are handled by [SST1605](SST1605.md). A comment with
`<inheritdoc/>` outside other elements is skipped. A populated `<content>` does not
excuse an empty summary beside it.

## How to fix violations

Add a description to the summary. There is no code fix.

Before:

```csharp
/// <summary></summary>
public partial class Parser { }
```

After:

```csharp
/// <summary>Reads commands from text.</summary>
public partial class Parser { }
```

For a part that only adds members, remove the empty summary and use `<content>` to
describe those members. The general empty-summary rule, [SST1606](SST1606.md), also
checks partial declarations.

## Configuration

Disabled by default. Enable it in `.editorconfig`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1607.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Leave it disabled if the general empty-summary rule provides enough coverage.
Suppress it locally only when a documentation tool requires an empty summary and
supplies its text before publication.
