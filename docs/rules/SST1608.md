# SST1608 — Documentation should not use placeholder text

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning |
| Code fix | No |

## Cause

A summary starts with the exact text `Summary description here`, after any leading
spaces or line breaks. The match is case-sensitive and does not require a final period.
It also reports summaries that add more text after that phrase.

The rule checks documented types, delegates, methods, constructors, destructors,
properties and enum members, including private declarations. A comment with
`<inheritdoc/>` outside other elements, or a summary containing `<inheritdoc/>`, is
skipped. Other placeholder phrases are not checked by this rule.

## How to fix violations

Replace the placeholder with a description of the type or member. There is no code fix.

Before:

```csharp
/// <summary>Summary description here.</summary>
public class Widget { }
```

After:

```csharp
/// <summary>A reusable screen component.</summary>
public class Widget { }
```

## Configuration

Enabled by default with severity `warning`. To treat it as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1608.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
The placeholder phrase cannot be configured. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress it in a template or sample whose purpose is to demonstrate placeholder text.
Replace the phrase in documentation intended for callers.
