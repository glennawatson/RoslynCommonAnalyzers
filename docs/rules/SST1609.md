# SST1609 — Property documentation should have a value

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning (disabled by default) |
| Code fix | No |

## Cause

A property has an XML documentation comment with no `<value>` element. This applies
to documented properties at every access level. Indexers, properties without
documentation, and comments with `<inheritdoc/>` outside other elements are skipped.

## How to fix violations

Add a `<value>` that explains what the property holds, such as its units, range or
meaning when empty. There is no code fix.

Before:

```csharp
/// <summary>A collection of pending items.</summary>
public class QueueStatus
{
    /// <summary>Gets the pending item count.</summary>
    public int Count => 0;
}
```

After:

```csharp
/// <summary>A collection of pending items.</summary>
public class QueueStatus
{
    /// <summary>Gets the pending item count.</summary>
    /// <value>The number of pending items; zero when the queue is empty.</value>
    public int Count => 0;
}
```

An empty `<value>` satisfies this rule but is reported by [SST1610](SST1610.md) when
that rule is enabled.

## Configuration

Disabled by default. To enable it as a warning:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1609.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled, or suppress it for a property, when the summary already
explains the value and a separate section would repeat it.
