# SST1610 — Property value documentation should have text

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning (disabled by default) |
| Code fix | No |

## Cause

A documented property has an empty `<value>`. A self-closing `<value/>` or a value
element containing only spaces or line breaks is also reported, at every access level.

Indexers, properties without documentation, and comments with `<inheritdoc/>` outside
other elements are skipped. A missing `<value>` belongs to [SST1609](SST1609.md).

## How to fix violations

Describe what the property holds. There is no code fix.

Before:

```csharp
/// <summary>A collection of pending items.</summary>
public class QueueStatus
{
    /// <summary>Gets the pending item count.</summary>
    /// <value></value>
    public int Count => 0;
}
```

After:

```csharp
/// <summary>A collection of pending items.</summary>
public class QueueStatus
{
    /// <summary>Gets the pending item count.</summary>
    /// <value>The number of pending items; zero when the queue is empty.</value>
    public int Count => 0;
}
```

If the summary already covers the value, remove the empty tag. This is suitable when
the rule requiring a `<value>` is disabled.

## Configuration

Disabled by default. Enable it in `.editorconfig`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1610.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress it when a documentation tool requires an empty `<value>` and supplies the
content before publication. Otherwise, fill in or remove the empty tag.
