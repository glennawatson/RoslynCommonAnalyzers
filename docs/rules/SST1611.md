# SST1611 — Parameters should be documented

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning |
| Code fix | Yes |

## Cause

A documented member has a parameter with no matching `<param name="...">` element.
Parameter names must match exactly, including case.

This covers methods, constructors, delegates, and parameters declared on a class,
struct or record. It applies to existing documentation at every access level.
Indexers, operators and local functions are not checked. Members without
documentation, or with `<inheritdoc/>` outside other elements, are skipped.

## How to fix violations

Add a `<param>` describing each missing parameter. Explain useful details such as
units, accepted values or what the argument controls.

Before:

```csharp
/// <summary>Receives numeric values.</summary>
public class Sink
{
    /// <summary>Writes a value.</summary>
    public void Write(int value) { }
}
```

After:

```csharp
/// <summary>Receives numeric values.</summary>
public class Sink
{
    /// <summary>Writes a value.</summary>
    /// <param name="value">The number to write.</param>
    public void Write(int value) { }
}
```

## Code fix

**Add documentation element** inserts an empty `<param name="value"></param>` on a
new `///` line immediately before the declaration, using the reported parameter's
name. It keeps the existing text and uses the file's line endings and the declaration's
indentation. It appends the tag rather than placing it among existing parameter tags.

Write the description yourself: the empty tag is reported by [SST1614](SST1614.md).
Move the new line if needed to keep parameter descriptions in declaration order.

## Configuration

Enabled by default with severity `warning`. To treat it as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1611.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress it when a parameter's meaning is fully covered by the summary and a separate
description would only repeat it. Use `<inheritdoc/>` when documentation comes from
a base member or interface.
