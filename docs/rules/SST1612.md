# SST1612 — Parameter documentation should match the parameters

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning |
| Code fix | No |

## Cause

A `<param>` names a parameter that the documented declaration does not have. Names
must match exactly, including case. A tag left behind after removing or renaming a
parameter is reported.

Parameters on methods, constructors, delegates, classes, structs and records are
checked. A `<param>` on a checked declaration with no parameters is also reported.
Indexers, operators and local functions are not checked. A comment with `<inheritdoc/>`
outside other elements is skipped. Private declarations with documentation are checked.

## How to fix violations

Correct the `name` attribute, or remove the tag if its parameter has been removed.
There is no code fix.

Before:

```csharp
/// <summary>Receives numeric values.</summary>
public class Sink
{
    /// <summary>Writes a value.</summary>
    /// <param name="value">The number to write.</param>
    /// <param name="extra">An additional number.</param>
    public void Write(int value) { }
}
```

After:

```csharp
/// <summary>Receives numeric values.</summary>
public class Sink
{
    /// <summary>Writes a value.</summary>
    /// <param name="value">The number to write.</param>
    public void Write(int value) { }
}
```

## Configuration

Enabled by default with severity `warning`. To treat it as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1612.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress it only when a documentation tool deliberately uses a different parameter
list and resolves the tags before publication. Otherwise, correct the mismatch so
callers see descriptions for the actual parameters.
