# SST1613 — Parameter documentation should declare the parameter name

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning |
| Code fix | No |

## Cause

A `<param>` element has no `name` attribute identifying the parameter it describes.
This includes self-closing tags such as `<param/>`.

The rule checks documentation on types, delegates, methods, constructors, destructors,
properties and enum members, including private declarations. Fields, events, indexers
and local functions are not checked. A comment with `<inheritdoc/>` outside other
elements is skipped.

## How to fix violations

Add `name="parameterName"` using the exact parameter name. If the declaration has no
such parameter, remove the tag or move useful text into the summary. There is no code fix.

Before:

```csharp
/// <summary>A reusable screen component.</summary>
/// <param>No name.</param>
public class Widget { }
```

After:

```csharp
/// <summary>A reusable screen component.</summary>
public class Widget { }
```

Adding a name that does not match a parameter causes [SST1612](SST1612.md).

## Configuration

Enabled by default with severity `warning`. To treat it as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1613.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress it for a documentation template whose parameter names are filled by another
tool. Documentation published directly from source needs the names to connect each
description to its parameter.
