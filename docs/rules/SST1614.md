# SST1614 — Parameter documentation should have text

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning |
| Code fix | No |

## Cause

A parameter has a matching `<param>` element with no text. A self-closing tag or one
containing only spaces or line breaks is also reported. The empty tag inserted by the
missing-parameter code fix needs a description too.

The rule checks documented methods, constructors, delegates, and parameters declared
on classes, structs and records, at every access level. Indexers, operators and local
functions are not checked. Comments with `<inheritdoc/>` outside other elements are
skipped. Missing or unmatched tags are handled by other parameter documentation rules.

## How to fix violations

Describe what the argument means, including useful limits or units. There is no code fix.

Before:

```csharp
/// <summary>Receives numeric values.</summary>
public class Sink
{
    /// <summary>Writes a value.</summary>
    /// <param name="value"></param>
    public void Write(int value) { }
}
```

After:

```csharp
/// <summary>Receives numeric values.</summary>
public class Sink
{
    /// <summary>Writes a value.</summary>
    /// <param name="value">The number to write.</param>
    public void Write(int value) { }
}
```

## Configuration

Enabled by default with severity `warning`. To treat it as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1614.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress it if a documentation tool requires the empty tag and supplies its text
before publication. If the description would only repeat the summary, remove the
tag and decide whether to suppress [SST1611](SST1611.md) for that parameter.
