# SST1615 — Return value should be documented

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning |
| Code fix | Yes |

## Cause

A documented method or delegate returns something other than `void` but has no
`<returns>` element. This includes `Task` and `ValueTask`, even without a result type:
describe what completion of the returned task means.

Existing documentation is checked at every access level. Members without documentation,
or with `<inheritdoc/>` outside other elements, are skipped. Properties, constructors,
operators, indexers and local functions are not checked by this rule.

## How to fix violations

Add `<returns>` describing the result and any useful edge cases.

Before:

```csharp
/// <summary>Tracks pending items.</summary>
public class QueueStatus
{
    /// <summary>Counts pending items.</summary>
    public int GetCount() => 0;
}
```

After:

```csharp
/// <summary>Tracks pending items.</summary>
public class QueueStatus
{
    /// <summary>Counts pending items.</summary>
    /// <returns>The number of pending items; zero when the queue is empty.</returns>
    public int GetCount() => 0;
}
```

## Code fix

**Add documentation element** inserts `/// <returns></returns>` on a new line
immediately before the declaration. It keeps the existing text and uses the file's
line endings and the declaration's indentation. It appends the tag after the existing
documentation rather than reordering the sections.

Write the description yourself: the empty tag is reported by [SST1616](SST1616.md).
Move the new line if your documentation puts return information before other sections.

## Configuration

Enabled by default with severity `warning`. To treat it as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1615.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress it when the summary already explains the complete return contract and a
separate section would only repeat it. Use `<inheritdoc/>` when the contract is
documented on a base member or interface.
