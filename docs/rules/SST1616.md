# SST1616 — Return value documentation should have text

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Warning |
| Code fix | No |

## Cause

A documented method or delegate returning something other than `void` has an empty
`<returns>`. A self-closing `<returns/>` or one containing only spaces or line breaks
is also reported. This includes the empty tag inserted by the missing-return code fix.

`Task` and `ValueTask` return types are included. Existing documentation is checked
at every access level. Comments with `<inheritdoc/>` outside other elements are
skipped. A missing tag belongs to [SST1615](SST1615.md); a tag on a `void` member
belongs to [SST1617](SST1617.md). Properties, constructors, operators, indexers and
local functions are not checked by this rule.

## How to fix violations

Describe what the result means. For a task, describe what its completion means.
There is no code fix.

Before:

```csharp
/// <summary>Tracks pending items.</summary>
public class QueueStatus
{
    /// <summary>Counts pending items.</summary>
    /// <returns></returns>
    public int GetCount() => 0;
}
```

After:

```csharp
/// <summary>Tracks pending items.</summary>
public class QueueStatus
{
    /// <summary>Counts pending items.</summary>
    /// <returns>The number of pending items; zero when the queue is empty.</returns>
    public int GetCount() => 0;
}
```

## Configuration

Enabled by default with severity `warning`. To treat it as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST1616.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, or `none` (disabled).
There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress it if a documentation tool requires the empty tag and supplies its text
before publication. If the summary already covers the result, remove the empty tag
and decide whether to suppress the missing-return rule for that member.
