# SST1617 — Void return value should not be documented

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A method or delegate declared with a `void` return type has a `<returns>` element
in its documentation. An empty or self-closing `<returns>` is also reported.

`Task` and `ValueTask` are return values, even without a result type. Keep their
`<returns>` documentation. Comments with a top-level `<inheritdoc>` are skipped.

## How to fix violations

Remove the `<returns>` element. Put any useful description of the method's work
in its summary or remarks.

Bad:

```csharp
public class Worker
{
    /// <summary>Does the work.</summary>
    /// <returns>Nothing.</returns>
    public void Run() { }
}
```

Corrected:

```csharp
public class Worker
{
    /// <summary>Does the work.</summary>
    public void Run() { }
}
```

## Code fix

**Remove `<returns>`** deletes every line occupied by the first `<returns>`
element, including its text. It also deletes any other documentation on those
same lines. If a line contains both `<summary>` and `<returns>`, remove the
unwanted element by hand to preserve the summary.

## Configuration

Enabled by default as a warning. The example changes it to an error.
There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1617.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
Use `none` to disable the rule. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress only when a documentation format you must follow requires a return
section even for `void` methods. A `Task` or `ValueTask` return needs no suppression.
