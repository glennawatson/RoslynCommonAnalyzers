# SST1618 — Generic type parameters should be documented

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A documented generic type, method, or delegate has a type parameter without a
matching `<typeparam name="...">` element. Names must match exactly, including
capital letters.

A declaration with no documentation, or with a top-level `<inheritdoc>`, is not
reported by this rule. For a partial type, a matching element on another part
is enough; do not duplicate it on every part.

## How to fix violations

Add a `<typeparam>` element that explains what each missing type parameter is for.

Bad:

```csharp
public class Worker
{
    /// <summary>Does work for the selected type.</summary>
    public void Run<T>() { }
}
```

Corrected:

```csharp
public class Worker
{
    /// <summary>Does work for the selected type.</summary>
    /// <typeparam name="T">The type to process.</typeparam>
    public void Run<T>() { }
}
```

## Code fix

**Add documentation element** inserts an empty `<typeparam name="T"></typeparam>`
line immediately above the declaration, using the reported parameter's name.
It keeps the file's line endings and the declaration's indentation. Fill in the
description afterward; an empty element is reported by [SST1622](SST1622.md).

## Configuration

Enabled by default as a warning. The example changes it to an error.
There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1618.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
Use `none` to disable the rule. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the type parameter's role is already clear from the summary and a
separate description would only repeat it. Documentation on another part of a
partial type does not need suppression.
