# SST1619 — Partial generic type parameters should be documented

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning (disabled by default) |
| Code fix | No |

## Cause

A documented partial class, struct, interface, or record has a type parameter
with no matching `<typeparam>` element on any part of that type.

Each type parameter needs documentation on only one part. Names must match
exactly, including capital letters. This rule does not check partial methods,
declarations with no documentation, or comments with a top-level `<inheritdoc>`.

## How to fix violations

Add the missing `<typeparam>` elements to one part, usually the part that holds
the main summary. Repeating them across parts can cause duplicate documentation
warnings from the compiler.

Bad:

```csharp
/// <summary>A container for stored items.</summary>
public partial class Container<T> { }
```

Corrected:

```csharp
/// <summary>A container for stored items.</summary>
/// <typeparam name="T">The type of item stored.</typeparam>
public partial class Container<T> { }
```

There is no code fix.

[SST1618](SST1618.md) also checks missing type-parameter documentation on partial
types. Enabling both rules can report the same missing element twice.

## Configuration

Disabled by default. Set a severity to enable it; the example enables it as an error.
There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1619.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
Use `none` to disable the rule. See [configuration](../CONFIGURATION.md).

## When to suppress

Leave this rule disabled if the general type-parameter rule already provides
the coverage you need. Suppress a particular case when the summary fully
explains the type parameter and separate text would add nothing.
