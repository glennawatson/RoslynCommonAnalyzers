# SST1621 — Type parameter documentation should declare the type parameter name

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | No |

## Cause

A `<typeparam>` element has no `name` attribute to identify the type parameter
it describes. This includes self-closing elements. Comments with a top-level
`<inheritdoc>` are skipped.

## How to fix violations

Add `name="T"`, replacing `T` with the exact type-parameter name. If the type or
member has no type parameters, remove the element or move its text to the summary.

Bad:

```csharp
/// <summary>A widget.</summary>
/// <typeparam>No name.</typeparam>
public class Widget { }
```

Corrected:

```csharp
/// <summary>A widget.</summary>
public class Widget { }
```

There is no code fix. A name that is present but does not match a type parameter
is handled by [SST1620](SST1620.md).

## Configuration

Enabled by default as a warning. The example changes it to an error.
There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1621.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
Use `none` to disable the rule. See [configuration](../CONFIGURATION.md).

## When to suppress

Keep this rule enabled for documentation consumed directly by C# tools. Suppress
only when a separate documentation tool supplies the missing names before publication.
