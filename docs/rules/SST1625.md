# SST1625 — Element documentation should not be copy-pasted

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | No |

## Cause

Two sections in the same documentation comment contain the same text. The later
section is reported, for example when a `<param>` repeats the `<summary>`.
Differences in spaces or line breaks do not make the descriptions distinct.

References inside the descriptions count too. Matching prose with different
`<see cref="...">` or `<paramref name="...">` targets is accepted. Different names
on the outer `<param>` elements do not make identical descriptions distinct.
Empty and self-closing sections are skipped, and separate comments are not compared.

## How to fix violations

Describe what each section is for. Do not change words only to evade the check.

Bad:

```csharp
public class Worker
{
    /// <summary>The input value.</summary>
    /// <param name="value">The input value.</param>
    public void Run(int value) { }
}
```

Corrected:

```csharp
public class Worker
{
    /// <summary>Does the work.</summary>
    /// <param name="value">The input value.</param>
    public void Run(int value) { }
}
```

There is no code fix.

## Configuration

Enabled by default as a warning. The example changes it to an error.
There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1625.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
Use `none` to disable the rule. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when two sections need the same wording to state the same contract
accurately, and rephrasing one would add no useful distinction.
