# SST1626 — Single-line comments should not use documentation style slashes

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | No |

## Cause

A documentation comment appears where it does not document a declaration, such
as before a statement inside a method. Both `///` and `/** ... */` documentation
comments are checked. Comments directly before members or local functions are accepted.

## How to fix violations

Use `//` for an ordinary line comment or `/* ... */` for an ordinary block comment.
If the text is meant to document a member, move it directly above the declaration.

Bad:

```csharp
public class Worker
{
    public void Run()
    {
        /// Separate the output groups.
        System.Console.WriteLine();
    }
}
```

Corrected:

```csharp
public class Worker
{
    public void Run()
    {
        // Separate the output groups.
        System.Console.WriteLine();
    }
}
```

There is no code fix.

## Configuration

Enabled by default as a warning. The example changes it to an error.
There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1626.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
Use `none` to disable the rule. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress only when another documentation tool deliberately uses documentation
comments in these positions. For ordinary notes inside methods, change the comment style.
