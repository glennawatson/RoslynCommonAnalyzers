# SST1627 — Documentation text must not be empty

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning (disabled by default) |
| Code fix | No |

## Cause

A `<remarks>`, `<para>`, `<note>`, `<example>`, `<value>`, or `<returns>` section
directly inside a documentation comment contains no text, or only whitespace.

Sections containing child XML elements are skipped. Nested sections and
self-closing forms such as `<remarks/>` are not checked. Empty summaries are
handled by [SST1606](SST1606.md).

## How to fix violations

Add useful text, or remove an optional section that has nothing to say. Keep
required sections such as `<returns>` and fill them in.

Bad:

```csharp
public class Worker
{
    /// <summary>Does useful work.</summary>
    /// <remarks></remarks>
    public void Run() { }
}
```

Corrected:

```csharp
public class Worker
{
    /// <summary>Does useful work.</summary>
    public void Run() { }
}
```

There is no code fix.

## Configuration

Disabled by default. Set a severity to enable it; the example enables it as an error.
There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1627.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
Use `none` to disable the rule. See [configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled or suppress it when a documentation template requires
empty sections or a separate tool fills them before publication.
