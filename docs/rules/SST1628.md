# SST1628 — Documentation text should begin with a capital letter

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning (disabled by default) |
| Code fix | Yes |

## Cause

A documentation `<summary>` starts with a lowercase letter after leading
whitespace. Other sections, such as `<remarks>` and `<param>`, are not checked.

Empty summaries and summaries starting with a number or punctuation are skipped.
A summary opening with an XML element, such as `<c>`, `<see>`, or `<paramref>`,
is also skipped: the code or name inside it can keep its required casing.

## How to fix violations

Capitalise the first letter of the summary's prose.

Bad:

```csharp
public class Worker
{
    /// <summary>does the work here.</summary>
    public void Run() { }
}
```

Corrected:

```csharp
public class Worker
{
    /// <summary>Does the work here.</summary>
    public void Run() { }
}
```

## Code fix

**Begin the summary with a capital letter** capitalises the first lowercase
character in the opening text. It keeps the surrounding whitespace and works
for summaries written on one line or across several lines.

## Configuration

Disabled by default. Set a severity to enable it; the example enables it as an error.
There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST1628.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
Use `none` to disable the rule. See [configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled or suppress it when your documentation style requires
a lowercase opening, such as a product name. If the opening is a code identifier,
mark it with `<c>` or the appropriate reference element to preserve its casing.
