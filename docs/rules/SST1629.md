# SST1629 — Documentation text should end with a period

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A `<summary>`, `<returns>`, `<remarks>`, or `<value>` section ends with text that
lacks final punctuation. The accepted endings are `.`, `!`, `?`, `:`, and `;`.
Punctuation immediately before a closing quote or bracket also counts, as in
`"true."` or `(text.)`.

Empty sections and sections ending with an XML element, such as `<see/>`, are
not reported. A comment with an `<inheritdoc>` outside its sections is also exempt.

## Example

Before:

```csharp
/// <summary>A widget</summary>
public class Widget { }
```

After:

```csharp
/// <summary>A widget.</summary>
public class Widget { }
```

## How to fix violations

The code fix inserts a period after the last text character, before any trailing
spaces or line breaks. It keeps the rest of the comment and its layout. Fix all
adds periods to every reported section in the selected scope.

## Configuration

There are no rule-specific options. Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1629.severity = warning
```

The default is `warning`. Use `error` to fail the build or `none` to disable the rule.

## When to suppress

Suppress it for an exact quotation or a documentation format that deliberately
omits final punctuation.
