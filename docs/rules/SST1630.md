# SST1630 — Documentation text should contain whitespace

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default | Disabled; warning when enabled |
| Code fix | No |

## Cause

A nonempty `<summary>` has no whitespace between its words. Spaces, tabs, and
line breaks count as separators; whitespace at the start or end does not.

A summary made only of XML elements and punctuation is exempt. For example,
`<summary><c>string.IsNullOrEmpty(text.Trim())</c>.</summary>` is accepted.
Adding prose outside the elements makes the summary subject to the rule.

## Example

Before:

```csharp
internal class C
{
    /// <summary>Singleword</summary>
    public void M() { }
}
```

After:

```csharp
internal class C
{
    /// <summary>Does the work.</summary>
    public void M() { }
}
```

## How to fix violations

Expand the summary into a phrase that describes the type or member.
There is no code fix.

## Configuration

The rule is disabled by default and has no rule-specific options. Enable it in
`.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1630.severity = warning
```

Use `error` to fail the build or `none` to disable it.

## When to suppress

Leave it disabled for documentation written in a language that does not separate
words with spaces. Suppress a particular comment when a single word gives the
reader all the information they need.
