# SST1633 — File should have a header

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A file's opening comments do not match `file_header_template`. The rule reports
nothing when the template is missing, empty, or `unset`.

The header must use `//` comments. A matching header among or after leading
preprocessor directives, such as `#if` or `#nullable`, is accepted in the active
code. Trailing whitespace on header lines is ignored.

## Example

With `file_header_template = Copyright text.`, this file is reported:

```csharp
namespace N { }
```

After the fix:

```csharp
// Copyright text.
namespace N { }
```

## How to fix violations

The code fix inserts the configured header at the top of the file. If the file
starts with a block of `//` or `/* */` comments, it replaces that block, including
any unrelated comments in the same block. A blank line or a preprocessor directive
ends the block; comments beyond that point are preserved. The fix uses the file's
line endings. Fix all is available.

## Configuration

Set the header text and severity in `.editorconfig`:

```ini
[*.cs]
file_header_template = Copyright (c) Contoso.\nLicensed under the MIT license.
dotnet_diagnostic.SST1633.severity = warning
```

Each literal `\n` starts a new `//` line. `{fileName}` inserts the file name,
including its extension. There is no default header text. The default severity is
`warning`; use `error` to fail the build or `none` to disable the rule.

## When to suppress

Exclude imported files that must retain their own copyright or licence header.
Use `file_header_template = unset` or severity `none` in a matching `.editorconfig`
section. An in-file warning directive cannot suppress the diagnostic at the very
start of the file.
