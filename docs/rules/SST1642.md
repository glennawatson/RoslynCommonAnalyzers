# SST1642 — Constructor summary should begin with the standard text

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | Yes |

## Cause

An instance constructor's summary does not start with
`Initializes a new instance of the `. A constructor declared with `private` may
instead start with `Prevents a default instance of the `.

Static constructors and inherited summaries are exempt. This rule checks the
opening words of an existing summary; it does not require the whole sentence to
match the example.

## Example

Before:

```csharp
public class C
{
    /// <summary>Creates the thing.</summary>
    public C() { }
}
```

After:

```csharp
public class C
{
    /// <summary>Initializes a new instance of the <see cref="C"/> class.</summary>
    public C() { }
}
```

## How to fix violations

The code fix replaces the entire `<summary>` with the standard sentence on one
line. It adds a reference to the containing type and uses `struct.` for a struct
or record struct, otherwise `class.`. It uses the `Initializes` wording even for a
private constructor.

Custom text, XML elements, and XML comments inside the summary are removed.
Edit the opening words by hand if you need to retain that content. Other sections,
such as `<param>` and `<remarks>`, stay in place. Fix all is available.

## Configuration

There are no options to change the required wording. Set the severity in
`.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1642.severity = warning
```

The default is `warning`. Use `error` to fail the build or `none` to disable the rule.

## When to suppress

Suppress it when your documentation uses another language or an agreed constructor
wording that better explains the API.
