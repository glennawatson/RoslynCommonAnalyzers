# SST1643 — Destructor summary should begin with the standard text

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A destructor's summary does not start with `Finalizes an instance of the `.
This rule checks the opening words of an existing summary, not the whole sentence.
Inherited summaries are exempt.

## Example

Before:

```csharp
public class C
{
    /// <summary>Cleans up.</summary>
    ~C() { }
}
```

After:

```csharp
public class C
{
    /// <summary>Finalizes an instance of the <see cref="C"/> class.</summary>
    ~C() { }
}
```

## How to fix violations

The code fix replaces the entire `<summary>` with the standard sentence on one
line, including a reference to the containing type. Custom text, XML elements,
and XML comments inside the summary are removed. Edit the opening words by hand
if you need to retain that content. Other documentation sections stay in place.
Fix all is available.

## Configuration

There are no options to change the required wording. Set the severity in
`.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1643.severity = warning
```

The default is `warning`. Use `error` to fail the build or `none` to disable the rule.

## When to suppress

Suppress it when your documentation uses another language or an agreed destructor
wording that better explains the API.
