# SST1644 — Documentation headers must not contain blank lines

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default | Disabled; warning when enabled |
| Code fix | No |

## Cause

An interior line of a `///` documentation comment contains only `///` and optional
whitespace. The first and last lines of the comment are not checked.

Blank lines inside `<code>` or `<example>` are accepted, including nested samples
and samples inside `<![CDATA[...]]>`. Blank lines elsewhere in the same comment are
still reported. The rule does not check `/** ... */` comments.

## Example

Before:

```csharp
internal class C
{
    /// <summary>
    /// First line.
    ///
    /// Second line.
    /// </summary>
    public void M() { }
}
```

After:

```csharp
internal class C
{
    /// <summary>
    /// First line.
    /// Second line.
    /// </summary>
    public void M() { }
}
```

## How to fix violations

Remove the blank documentation line. Use `<para>` elements if the text needs
separate paragraphs in the generated documentation. There is no code fix.

## Configuration

The rule is disabled by default and has no rule-specific options. Enable it in
`.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1644.severity = warning
```

Use `error` to fail the build or `none` to disable it.

## When to suppress

Leave it disabled if your team uses blank documentation lines to separate sections
for people reading the source. Code and example samples already allow blank lines.
