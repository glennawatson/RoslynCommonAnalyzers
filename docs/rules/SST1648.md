# SST1648 — inheritdoc should be used with inheriting elements

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | No |

## Cause

A documentation comment uses `<inheritdoc/>` outside its other sections, but the
type or member has no base from which to inherit documentation.

For methods, properties, indexers, and events with accessors, the member must
override a base member or implement an interface member. For a type, it must name
an interface or be a class derived from a class other than `object`. The rule does
not check whether that base or interface actually has documentation.

An `<inheritdoc>` with a `cref` attribute is accepted because it names its source
directly. The source can be an unrelated member. The compiler reports an invalid
reference.

## Example

Before, the method has no inherited documentation source:

```csharp
internal class C
{
    /// <inheritdoc/>
    public void M() { }
}
```

After, describe the method directly:

```csharp
internal class C
{
    /// <summary>Does the work.</summary>
    public void M() { }
}
```

## How to fix violations

Write the documentation directly, or add a `cref` that points to the documentation
you intend to reuse. Keep the bare form for overrides and interface implementations.
There is no code fix.

## Configuration

There are no rule-specific options. Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1648.severity = warning
```

The default is `warning`. Use `error` to fail the build or `none` to disable the rule.

## When to suppress

Suppress it only if your documentation tool supplies an inheritance source through
a convention this rule cannot recognise. Otherwise, name the source with `cref`
or write the missing documentation.
