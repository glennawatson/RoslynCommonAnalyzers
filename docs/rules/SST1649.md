# SST1649 — File name should match the first type name

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | Yes |

## Cause

A file name does not match the first type declared in the file, including its
capitalisation. Classes, structs, interfaces, records, enums, and delegates count.
If the first type is `partial`, the file is exempt. Files without a type are also
exempt.

The comparison ignores a suffix beginning with `.`, `{`, or a backtick. For example,
`Widget.cs`, `Widget.Logic.cs`, `Widget{T}.cs`, and ``Widget`1.cs`` all match a type
named `Widget`.

## Example

Before, in `Other.cs`:

```csharp
public class Widget { }
```

After, in `Widget.cs`:

```csharp
public class Widget { }
```

## How to fix violations

The code fix renames the file to the type name followed by `.cs`. It leaves the
contents unchanged and renames linked copies in other projects together. Any
suffix on the old file name is dropped. Fix all renames every reported file in
the selected scope.

For a generic type, the fix uses the naming convention configured below. The
analyzer accepts either convention regardless of the code-fix setting.

## Configuration

Set the severity and generic file-name convention in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1649.severity = warning
stylesharp.file_naming_convention = braces
```

| Option | Values | Default |
| --- | --- | --- |
| `stylesharp.file_naming_convention` | `braces`: `Widget{T}.cs`; `metadata`: ``Widget`1.cs`` | `braces` |
| `stylesharp.SST1649.file_naming_convention` | Same values; a nonempty value overrides the general option | General option |

The default severity is `warning`. Use `error` to fail the build or `none` to disable
the rule. See [CONFIGURATION](../CONFIGURATION.md) for shared configuration guidance.

## When to suppress

Suppress it when a file groups several related types under a useful shared name,
or when an external tool requires a fixed file name. Partial types already have
an exemption.
