# SST1651 — Documentation should not contain placeholder text

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | No |

## Cause

A documentation comment contains a `<placeholder>` element. Both
`<placeholder>text</placeholder>` and `<placeholder/>` are reported, including
elements nested inside a summary or another section.

The rule checks the element name. Plain text such as `TODO` without a
`<placeholder>` element is outside its scope.

## Example

Before:

```csharp
internal class C
{
    /// <summary><placeholder>TODO</placeholder></summary>
    public void M() { }
}
```

After:

```csharp
internal class C
{
    /// <summary>Does the work.</summary>
    public void M() { }
}
```

## How to fix violations

Replace the placeholder element with documentation that describes the member.
There is no code fix.

## Configuration

There are no rule-specific options. Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1651.severity = warning
```

The default is `warning`. Use `error` to fail the build or `none` to disable the rule.

## When to suppress

Suppress it for a documentation template whose placeholders are filled before
publication. For finished API documentation, replace the placeholder.
