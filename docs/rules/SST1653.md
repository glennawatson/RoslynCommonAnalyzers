# SST1653 — Short documentation summaries should be on a single line

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Code fix | Yes |
| Default summary limit | 100 characters |

## Cause

A `<summary>` in a `///` comment spans several lines even though its text is
shorter than the configured limit. The default limit is 100 characters.

The text length ignores whitespace at the ends and counts each run of spaces,
tabs, or line breaks as one space. Empty summaries and summaries at or above the
limit are not reported. The rule does not check `/** ... */` comments.

The summary also stays wrapped if the full collapsed line would exceed the limit
enforced by [SST1521](SST1521.md). That line includes indentation, `///`, XML tags,
and text. If the line-length rule is disabled, only the summary limit applies.

## Example

Before:

```csharp
/// <summary>
/// Short text.
/// </summary>
public class C { }
```

After:

```csharp
/// <summary>Short text.</summary>
public class C { }
```

## How to fix violations

The code fix puts the opening tag, content, and closing tag on one line. It removes
line breaks and extra spaces from the content, leaving a single space between
words. XML elements inside the summary remain, but their whitespace is collapsed
too. Fix all is available.

## Configuration

Set the severity and summary limit in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1653.severity = warning
stylesharp.summary_single_line_max_length = 100
```

| Option | Values | Default |
| --- | --- | --- |
| `stylesharp.summary_single_line_max_length` | Positive integer | `100` |
| `stylesharp.SST1653.summary_single_line_max_length` | Positive integer; overrides the general option | General option |
| `stylesharp.max_line_length` | Positive integer; full-line limit when the line-length rule is enabled | `120` |
| `stylesharp.SST1521.max_line_length` | Positive integer; overrides the general full-line limit | General option |

An invalid or nonpositive summary limit falls back to the general option, then
`100`. The default severity is `warning`; use `error` to fail the build or `none`
to disable the rule.

## When to suppress

Suppress it when line breaks or spacing inside the summary carry meaning, such as
in a code sample. Disable it if your team keeps all summaries in a multiline layout.
