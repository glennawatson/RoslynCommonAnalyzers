# SST1654 — Extension blocks should be documented

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Default | Enabled |
| Code fix | No |

## Cause

A C# 14 extension block has no documentation comment, or its comment has no
`<summary>` element. The block's containing class must be included in the
configured documentation scope. Public and internal classes are included by
default. A block with `<inheritdoc>` is not reported.

## Example

This block has no summary:

```csharp
public static class StringExtensions
{
    extension(string text)
    {
        public bool IsEmpty => text.Length == 0;
    }
}
```

## How to fix violations

Add a summary that describes the helpers in the block. There is no code fix.

```csharp
public static class StringExtensions
{
    /// <summary>Adds checks for empty text.</summary>
    /// <param name="text">The text to check.</param>
    extension(string text)
    {
        public bool IsEmpty => text.Length == 0;
    }
}
```

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST1654.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

These shared coverage keys accept `true` or `false`:

| Key | Default | Controls |
| --- | --- | --- |
| `stylesharp.document_exposed_elements` | `true` | Blocks in public classes |
| `stylesharp.document_internal_elements` | `true` | Blocks in internal classes |
| `stylesharp.document_private_elements` | `false` | Includes all blocks when enabled |

See [documentation coverage](../CONFIGURATION.md#documentation-coverage-scope).

## When to suppress

Suppress the rule when the block only groups members whose own documentation
already gives readers all the information they need. For internal helpers,
adjust the coverage settings if the whole class should be outside the scope.
