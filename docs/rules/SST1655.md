# SST1655 — Extension block parameters should be documented

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Default | Enabled |
| Code fix | Yes |

## Cause

A documented C# 14 extension block has a named receiver parameter with no
matching `<param>` element. The receiver is the value the extension members
operate on. The name must match exactly, including letter case.

The block's containing class must be in the configured documentation scope.
Public and internal classes are included by default. Blocks with `<inheritdoc>`
are skipped. A block with no documentation at all is reported by
[SST1654](SST1654.md) instead.

## Example

The receiver `text` has no description:

```csharp
public static class StringExtensions
{
    /// <summary>Adds checks for empty text.</summary>
    extension(string text)
    {
        public bool IsEmpty => text.Length == 0;
    }
}
```

## How to fix violations

The code fix appends `/// <param name="text"></param>` to the documentation,
immediately above the block. It leaves the description empty; fill it in:

```csharp
public static class StringExtensions
{
    /// <summary>Adds checks for empty text.</summary>
    /// <param name="text">The text to check.</param>
    extension(string text)
    {
        public bool IsEmpty => text.Length == 0;
    }
}
```

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST1655.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

These shared coverage keys accept `true` or `false`:

| Key | Default | Controls |
| --- | --- | --- |
| `stylesharp.document_exposed_elements` | `true` | Blocks in public classes |
| `stylesharp.document_internal_elements` | `true` | Blocks in internal classes |
| `stylesharp.document_private_elements` | `false` | Includes all blocks when enabled |

See [documentation coverage](../CONFIGURATION.md#documentation-coverage-scope).

## When to suppress

Suppress the rule if the receiver is already explained in the block's summary
and a separate parameter description would repeat it. Adjust coverage instead
when a whole group of internal helpers does not need documentation.
