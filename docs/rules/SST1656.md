# SST1656 — Extension block type parameters should be documented

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Default | Enabled |
| Code fix | Yes |

## Cause

A documented C# 14 extension block has a generic type parameter with no matching
`<typeparam>` element. The name must match exactly, including letter case.

The block's containing class must be in the configured documentation scope.
Public and internal classes are included by default. Blocks with `<inheritdoc>`
are skipped. A block with no documentation at all is reported by
[SST1654](SST1654.md) instead.

## Example

The type parameter `T` has no description:

```csharp
public static class ValueExtensions
{
    /// <summary>Adds a null check to a value.</summary>
    /// <param name="value">The value to check.</param>
    extension<T>(T value)
    {
        public bool IsNull => value is null;
    }
}
```

## How to fix violations

The code fix appends `/// <typeparam name="T"></typeparam>` to the documentation,
immediately above the block. It leaves the description empty and does not reorder
the existing tags. Fill in the description:

```csharp
public static class ValueExtensions
{
    /// <summary>Adds a null check to a value.</summary>
    /// <param name="value">The value to check.</param>
    /// <typeparam name="T">The type of value to check.</typeparam>
    extension<T>(T value)
    {
        public bool IsNull => value is null;
    }
}
```

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST1656.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

These shared coverage keys accept `true` or `false`:

| Key | Default | Controls |
| --- | --- | --- |
| `stylesharp.document_exposed_elements` | `true` | Blocks in public classes |
| `stylesharp.document_internal_elements` | `true` | Blocks in internal classes |
| `stylesharp.document_private_elements` | `false` | Includes all blocks when enabled |

See [documentation coverage](../CONFIGURATION.md#documentation-coverage-scope).

## When to suppress

Suppress the rule if the summary already explains the type parameter and a
separate tag adds no useful information. Adjust coverage instead when internal
helpers do not need documentation.
