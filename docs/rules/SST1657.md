# SST1657 — Extension block documentation should reference a real parameter or type parameter

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Default | Enabled |
| Code fix | No |

## Cause

A `<param>` or `<typeparam>` tag in a C# 14 extension block's documentation names
something the block does not declare. Names must match exactly, including letter
case. A `<param>` must name a receiver parameter; a `<typeparam>` must name a
generic type parameter. Using the wrong tag is also reported.

Only tags directly in the block's documentation are checked. Tags without a
`name` attribute are skipped. The block must be in the configured documentation
scope and must not use `<inheritdoc>`. Public and internal classes are included
by default.

## Example

The block declares `value`, but its documentation also names `other`:

```csharp
public static class ValueExtensions
{
    /// <summary>Adds a null check to a value.</summary>
    /// <typeparam name="T">The type of value to check.</typeparam>
    /// <param name="value">The value to check.</param>
    /// <param name="other">Another value.</param>
    extension<T>(T value)
    {
        public bool IsNull => value is null;
    }
}
```

## How to fix violations

Correct the name or tag, or remove an entry for a parameter that does not exist.
There is no code fix.

```csharp
public static class ValueExtensions
{
    /// <summary>Adds a null check to a value.</summary>
    /// <typeparam name="T">The type of value to check.</typeparam>
    /// <param name="value">The value to check.</param>
    extension<T>(T value)
    {
        public bool IsNull => value is null;
    }
}
```

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST1657.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

These shared coverage keys accept `true` or `false`:

| Key | Default | Controls |
| --- | --- | --- |
| `stylesharp.document_exposed_elements` | `true` | Blocks in public classes |
| `stylesharp.document_internal_elements` | `true` | Blocks in internal classes |
| `stylesharp.document_private_elements` | `false` | Includes all blocks when enabled |

See [documentation coverage](../CONFIGURATION.md#documentation-coverage-scope).

## When to suppress

Keep the rule enabled for documentation you maintain: a name that does not exist
misleads readers. Suppress it only when the comment must be kept verbatim for an
external documentation process that supplies the missing information.
