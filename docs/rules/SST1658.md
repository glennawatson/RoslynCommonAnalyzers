# SST1658 — Documentation should not repeat a word

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Default | Enabled |
| Code fix | Yes |

## Cause

A word appears twice in a row in documentation text, such as `the the` or
`The the`. Letter case does not matter. A pair separated by whitespace or a
documentation line break is reported on its second word.

The rule checks text inside documentation elements such as `<summary>` and
`<param>`. It skips `<c>`, `<code>`, `<see>`, and `<seealso>` content. Punctuation
or an intervening XML tag breaks the pair, so `The end. End of story.` is allowed.

## Example

```csharp
public class Store
{
    /// <summary>Gets the the value.</summary>
    public int Value { get; }
}
```

## How to fix violations

The code fix removes the second word and the spaces or tabs before it:

```csharp
public class Store
{
    /// <summary>Gets the value.</summary>
    public int Value { get; }
}
```

If the second word starts a new documentation line, the fix keeps the line break
and removes that word plus one following space. If neither removal is possible,
edit the text by hand.

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST1658.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

There are no rule-specific options.

See [configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress an intentional repetition, such as `had had`, or a quotation that must
be kept exactly as written.
