# SST1659 — Documentation comments should not be empty

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Default | Enabled |
| Code fix | Yes |

## Cause

A documentation comment before a declaration contains only its comment markers
and whitespace. This includes a lone `///`, several consecutive blank `///`
lines, and an empty `/** */` comment.

Ordinary `//` and `/* */` comments are not reported by this rule. A blank `///`
line inside a comment with text or XML tags is allowed. An empty `<summary>` tag
is also outside this rule: the comment contains a tag, even though the summary
has no text.

## Example

```csharp
public class Counter
{
    ///
    public int Value;
}
```

## How to fix violations

The code fix deletes the whole empty documentation comment. It removes lines
occupied only by that comment, so it leaves no blank line behind:

```csharp
public class Counter
{
    public int Value;
}
```

If an empty block documentation comment shares a line with code, the fix removes
the comment and the spaces or tabs before it. If the declaration needs
documentation, write a useful summary instead of deleting the comment.

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST1659.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

There are no rule-specific options.

## When to suppress

Suppress only when an external tool requires an empty documentation marker.
Otherwise remove it or write the missing documentation. Blank lines within a
useful documentation comment do not need suppression.
