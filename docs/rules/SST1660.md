# SST1660 — Parameter documentation should be ordered to match the parameters

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Info |
| Default | Enabled |
| Code fix | Yes |

## Cause

The `<param>` tags describe every parameter exactly once, but list them in a
different order from the declaration. Matching orders let readers follow the
parameters and their descriptions together.

This applies to methods, constructors, delegates, indexers, and primary
constructors on classes, structs, and records. It requires at least two
parameters. Missing, duplicate, or unknown parameter names are not reported by
this rule. Documentation with `<inheritdoc>` is skipped.

## Example

```csharp
public class Copier
{
    /// <summary>Copies a range.</summary>
    /// <param name="count">The number of items.</param>
    /// <param name="source">The source array.</param>
    public void Copy(int[] source, int count) { }
}
```

## How to fix violations

The code fix reorders the complete `<param>` elements to match the declaration:

```csharp
public class Copier
{
    /// <summary>Copies a range.</summary>
    /// <param name="source">The source array.</param>
    /// <param name="count">The number of items.</param>
    public void Copy(int[] source, int count) { }
}
```

Each description moves with its tag. The surrounding documentation layout stays
in place; the method's parameter order does not change.

## Configuration

Enabled by default at Info severity (`suggestion` in `.editorconfig`). To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST1660.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

There are no rule-specific options.

## When to suppress

Suppress the rule when your documentation deliberately groups related parameters
in a different order and that grouping helps readers more than declaration order.
