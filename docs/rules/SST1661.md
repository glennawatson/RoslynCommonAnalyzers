# SST1661 — Code documentation tag should match its content

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Info |
| Default | Enabled |
| Code fix | Yes |

## Cause

A one-line code snippet uses `<code>`, or a snippet with content on several lines
uses `<c>`. Use `<c>` for code within a sentence and `<code>` for a code block.

Leading and trailing whitespace does not count. Placing the opening and closing
tags on separate lines does not make a one-line snippet a block. Empty tags are
not reported.

## Example

```csharp
public class Counter
{
    /// <summary>Returns <code>value + 1</code>.</summary>
    public int Increment(int value) => value + 1;
}
```

## How to fix violations

The code fix changes both tag names from `<code>` to `<c>`, or from `<c>` to
`<code>`, according to the content:

```csharp
public class Counter
{
    /// <summary>Returns <c>value + 1</c>.</summary>
    public int Increment(int value) => value + 1;
}
```

It keeps the snippet, attributes, spaces, and line breaks as written.

## Configuration

Enabled by default at Info severity (`suggestion` in `.editorconfig`). To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST1661.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

There are no rule-specific options.

## When to suppress

Suppress the rule when a one-line snippet must render as a separate code block,
or when your documentation generator requires a particular tag for its layout.
