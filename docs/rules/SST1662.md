# SST1662 — Thrown exceptions should be documented

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Default | Disabled (opt-in) |
| Code fix | Yes, for supported conditions |

## Cause

A documented method, constructor, operator, or conversion operator uses
`throw new SomeException(...)` without a matching `<exception cref="...">` tag.
The rule reports the member once, even if several exception types are missing.

It checks direct throws, including throw expressions. It does not check property
accessors, exceptions from called methods, rethrows, or throws inside lambdas,
anonymous methods, or local functions. Members without documentation and those
using `<inheritdoc>` are skipped.

Exception names match without their namespace, so `InvalidOperationException`
and `System.InvalidOperationException` match. A tag that names the type counts
even if its description is empty; [SST1665](SST1665.md) checks that description.

## Example

```csharp
using System;

public class Processor
{
    /// <summary>Processes a value.</summary>
    /// <param name="value">The value to process.</param>
    public void Process(string value)
    {
        if (value.Length == 0)
        {
            throw new InvalidOperationException();
        }
    }
}
```

## How to fix violations

Add an `<exception>` tag that says when the exception is thrown. For `///`
documentation, the code fix appends a tag when the throw is inside the true
branch of an `if` or is the right side of `??`. For the example, it copies the
`if` condition:

```csharp
using System;

public class Processor
{
    /// <summary>Processes a value.</summary>
    /// <param name="value">The value to process.</param>
    /// <exception cref="InvalidOperationException">Thrown when <c>value.Length == 0</c>.</exception>
    public void Process(string value)
    {
        if (value.Length == 0)
        {
            throw new InvalidOperationException();
        }
    }
}
```

For `value ?? throw new ...`, the inserted description says that `value` is null.
The fix escapes XML characters and joins whitespace in the copied expression.
It uses the nearest enclosing `if` condition and the first throw of each missing
type. Review the description if nested conditions or several throw sites need
to be explained.

Unconditional throws and `/** */` documentation have no code fix. If only some
missing types have a supported condition, the fix adds those tags and leaves
the rest for you to document.

## Configuration

Disabled by default. Enable it as an error with:

```ini
[*.cs]
dotnet_diagnostic.SST1662.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

There are no rule-specific options.

## When to suppress

Leave the rule disabled if your team documents only exceptions that callers
are expected to handle. Suppress an individual report for an implementation
failure that is not part of the member's documented contract.
