# SST1663 — A summary comment should be a documentation comment

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Default | Disabled (opt-in) |
| Code fix | Yes |

## Cause

A lone `//` comment sits directly above a declaration marked `public`, and its
first non-whitespace character after `//` is a letter. The declaration has no
documentation comment. A `/// <summary>` makes the description available in
generated documentation and editor tooltips.

The comment must occupy its own line with no blank line before the declaration.
Consecutive `//` comment lines, comments starting with punctuation, and comments
starting with `///` or more slashes are skipped. The containing class may be
internal; the declaration itself must explicitly say `public`.

## Example

```csharp
public class Counter
{
    // Gets the widget count
    public int Count { get; }
}
```

## How to fix violations

The code fix replaces the comment with one `/// <summary>` line:

```csharp
public class Counter
{
    /// <summary>Gets the widget count</summary>
    public int Count { get; }
}
```

It trims spaces at the ends of the comment text and escapes `&`, `<`, and `>`
for XML. It keeps the wording and does not add a full stop.

## Configuration

Disabled by default. Enable it as an error with:

```ini
[*.cs]
dotnet_diagnostic.SST1663.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

There are no rule-specific options.

## When to suppress

Suppress the rule when the comment is a maintenance note, a section label, or
commented-out code that starts with a letter. The rule cannot tell those apart
from a summary. Leave it disabled if your team often places such notes above
public declarations.
