# SST1664 — Summary paragraphs should use `<para>` elements

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Default | Disabled (opt-in) |
| Code fix | Yes |

## Cause

A `<summary>` uses blank documentation lines to separate paragraphs of plain
text. Documentation viewers can collapse those blank lines. A `<para>` element
marks a paragraph explicitly.

The rule applies when the opening and closing summary tags are on lines
separate from the text, with at least one blank line between two text paragraphs.
It skips summaries containing nested elements such as `<see>`, `<c>`, or `<para>`.
Blank lines only before or after the text do not trigger it.

## Example

```csharp
public class Counter
{
    /// <summary>
    /// Stores the running total.
    ///
    /// The total is reset when the batch closes.
    /// </summary>
    public int Total { get; }
}
```

## How to fix violations

The code fix wraps each paragraph in `<para>` and `</para>` lines. It removes
blank lines inside the summary and preserves the text lines:

```csharp
public class Counter
{
    /// <summary>
    /// <para>
    /// Stores the running total.
    /// </para>
    /// <para>
    /// The total is reset when the batch closes.
    /// </para>
    /// </summary>
    public int Total { get; }
}
```

## Configuration

Disabled by default. Enable it as an error with:

```ini
[*.cs]
dotnet_diagnostic.SST1664.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

There are no rule-specific options.

## When to suppress

Leave the rule disabled or suppress it if your documentation viewer already
preserves blank lines, or if your team keeps summaries as plain text.
