# SST1665 — Documented exceptions should describe what triggers them

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Warning |
| Default | Enabled |
| Code fix | No |

## Cause

An `<exception>` tag has a `cref` naming a type, but no text or nested element
explaining when it is thrown. Empty tags, whitespace-only descriptions, and
self-closing tags such as `<exception cref="ArgumentNullException" />` are
reported.

Only exception tags directly in a documentation comment are checked. Tags
inside `<remarks>` or `<example>`, tags without `cref`, and descriptions containing
an element such as `<paramref>` or `<inheritdoc>` are skipped. The rule does not
check whether the member actually throws the named exception.

## Example

```csharp
using System;

public class Reader
{
    /// <summary>Reads the requested number of items.</summary>
    /// <param name="count">The number of items.</param>
    /// <exception cref="ArgumentOutOfRangeException"></exception>
    public void Read(int count)
    {
        if (count < 0)
        {
            throw new ArgumentOutOfRangeException(nameof(count));
        }
    }
}
```

## How to fix violations

Describe the argument or state that causes the exception. There is no code fix.

```csharp
using System;

public class Reader
{
    /// <summary>Reads the requested number of items.</summary>
    /// <param name="count">The number of items.</param>
    /// <exception cref="ArgumentOutOfRangeException"><paramref name="count"/> is negative.</exception>
    public void Read(int count)
    {
        if (count < 0)
        {
            throw new ArgumentOutOfRangeException(nameof(count));
        }
    }
}
```

Remove the tag if the member cannot throw that exception.
[SST1662](SST1662.md) checks for missing exception tags; an empty tag satisfies
that rule but does not tell callers what to avoid.

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST1665.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule and `default` to restore its default.

There are no rule-specific options.

## When to suppress

Suppress the rule if an external documentation process supplies the description
and requires the empty tag to remain. For documentation you maintain directly,
state the condition even when it seems obvious.
