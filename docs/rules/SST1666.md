# SST1666 — Documentation elements should follow the standard order

| Item | Value |
| --- | --- |
| Category | Documentation |
| Default severity | Info |
| Enabled by default | Yes |
| Code fix | Yes (supports Fix All) |

## Cause

A documentation comment puts its top-level XML elements in the wrong order. The expected order is:

`summary`, `typeparam`, `param`, `returns`, `value`, `exception`, `remarks`, `example`, `seealso`.

The rule reports the first element that should come before an earlier element. It applies to both
`///` and `/** ... */` documentation comments. Other tags, such as `inheritdoc`, `include`, and custom
tags, are ignored. Elements of the same kind can appear in any order; [SST1660](SST1660.md) checks
the order of parameter descriptions.

## Example

Before:

```csharp
internal class Calculator
{
    /// <summary>Returns the supplied value.</summary>
    /// <returns>The supplied value.</returns>
    /// <param name="value">The value to return.</param>
    public int Echo(int value) => value;
}
```

After:

```csharp
internal class Calculator
{
    /// <summary>Returns the supplied value.</summary>
    /// <param name="value">The value to return.</param>
    /// <returns>The supplied value.</returns>
    public int Echo(int value) => value;
}
```

## Code fix

The fix reorders the listed elements in the comment. It leaves other tags and the text between
elements in place. Elements of the same kind keep their relative order.

## Configuration

There are no rule-specific options. The default is `suggestion` (Info). To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1666.severity = error
```

Allowed severities are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress this rule when your documentation convention requires a different element order.
The rule does not change how the documented code runs.
