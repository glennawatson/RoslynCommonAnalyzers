# SST1666 — Documentation elements should follow the standard order

| Item | Value |
| --- | --- |
| Category | Documentation |
| Severity | Info |
| Code fix | Yes |
| Default | Enabled |

## Cause

A documentation comment writes its elements out of the conventional order.

```csharp
// 👎 reported
/// <summary>Copies a range.</summary>
/// <returns>The number copied.</returns>
/// <param name="source">The source array.</param>
public int Copy(int[] source) => source.Length;

// 👍
/// <summary>Copies a range.</summary>
/// <param name="source">The source array.</param>
/// <returns>The number copied.</returns>
public int Copy(int[] source) => source.Length;
```

## Rule description

A documentation comment is read top to bottom, and every generator lays its sections out in the same order
regardless of how they were written: what the member is, then its type parameters, its parameters, what it
returns, what it throws, then the longer prose. A comment written in a different order reads out of sequence
in the source while rendering in sequence everywhere else, so the file and the docs disagree about what comes
first.

The order is:

`summary`, `typeparam`, `param`, `returns`, `value`, `exception`, `remarks`, `example`, `seealso`.

### What is reported

- The first element written after one it should come before, considering only the elements the order above
  names.

### What is not reported

- Any other element — `inheritdoc`, `include`, a custom tag — which has no place in the order and stays
  exactly where it was written.
- The order of two elements of the same kind. Two `<param>` elements belong to
  [SST1660](SST1660.md), which matches them against the signature.

## How to fix violations

Reorder the elements. The fix permutes the ranked elements among the slots they already sit in, which leaves
the interleaved `///` text and every unranked element untouched, and keeps elements of equal rank in their
existing relative order.

## Performance

One pass over the comment's content settles the question, and a comment whose elements are already in order
allocates nothing. The rank lookup is a linear scan of nine strings, which beats hashing each name for the
handful of elements a comment holds.
