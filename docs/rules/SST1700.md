# SST1700 — Extension blocks should not be empty

| Item | Value |
| --- | --- |
| Category | Extensions |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | No |
| Applies to | C# 14 extension blocks |

## Cause

An `extension` block has no members. Comments inside the block do not count as members.
An empty block adds no methods or properties to its receiver type, the type named after `extension`.

## Example

Before:

```csharp
public static class StringExtensions
{
    extension(string text)
    {
    }
}
```

After adding a member:

```csharp
public static class StringExtensions
{
    extension(string text)
    {
        public bool IsEmpty => text.Length == 0;
    }
}
```

## How to fix violations

Add the intended members or remove the empty block. There is no automatic code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1700.severity = error
```

Allowed severities are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress temporarily when an empty block is a deliberate placeholder in a template or unfinished code.
Remove it when there are no members to add.
