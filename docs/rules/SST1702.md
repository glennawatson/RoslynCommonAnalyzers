# SST1702 — Extension blocks should be grouped together

| Item | Value |
| --- | --- |
| Category | Extensions |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | No |
| Applies to | C# 14 extension blocks |

## Cause

A class declaration has another member between its `extension` blocks. The rule reports blocks
after that interruption. Keeping the blocks together makes the class's extensions easier to find.
Comments and blank lines do not separate the blocks for this rule.

## Example

Before:

```csharp
public static class SampleExtensions
{
    extension(int value)
    {
        public bool IsZero => value == 0;
    }

    public static int Helper() => 0;

    extension(string text)
    {
        public bool IsEmpty => text.Length == 0;
    }
}
```

After:

```csharp
public static class SampleExtensions
{
    extension(int value)
    {
        public bool IsZero => value == 0;
    }

    extension(string text)
    {
        public bool IsEmpty => text.Length == 0;
    }

    public static int Helper() => 0;
}
```

## How to fix violations

Move other members before or after the extension blocks. There is no automatic code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1702.severity = error
```

Allowed severities are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when keeping a helper beside the block that uses it makes the class easier to read,
or when moving blocks would disrupt conditional compilation.
