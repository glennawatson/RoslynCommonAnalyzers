# SST1703 — Prefer extension blocks over extension methods

| Item | Value |
| --- | --- |
| Category | Extensions |
| Default severity | Warning |
| Enabled by default | No |
| Code fix | Yes (supports Fix All) |
| Applies to | C# 14 or later |

## Cause

A classic extension method declares its receiver as a `this` parameter. When enabled, the rule asks
you to move that method into an `extension` block. It reports nothing below C# 14.

## Example

Before:

```csharp
public static class StringExtensions
{
    public static bool IsBlank(this string text) => text.Length == 0;
}
```

After applying the fix:

```csharp
public static class StringExtensions
{
    /// <summary>Extension members for <c>string</c>.</summary>
    extension(string text)
    {
        public bool IsBlank() => text.Length == 0;
    }
}
```

## Code fix

The fix removes `static` and the receiver parameter from the method and moves the method into a
block. The receiver keeps its name and modifiers, including `in` or `ref`. The method keeps its
body and remains a method, so callers can still write `text.IsBlank()`.

The method joins an existing block only when its receiver type spelling, name, modifiers, block
type parameters, and constraints match. Otherwise, the fix creates a block with a short XML summary.
Different receiver names can therefore produce duplicate blocks reported by [SST1701](SST1701.md).

Type parameters used in the receiver type move to the block with their constraints. Other type
parameters stay on the method. No fix is offered if a constraint moved to the block refers to a
type parameter left on the method.

The fix formats the moved code. It removes the receiver's `<param>...</param>` description and
`<typeparam>...</typeparam>` descriptions for type parameters moved to the block. Copy any needed
text into the block's documentation. Comments attached to the removed receiver name or modifiers
can be lost.

No fix is offered for a method without a body or a receiver parameter with attributes or a default
value. Joining an existing block is also withheld when the method contains preprocessor directives
or the move would split a directive pair, such as `#if` and `#endif`.

## Configuration

The rule is disabled by default. There are no rule-specific options. Set a severity to enable it:

```ini
[*.cs]
dotnet_diagnostic.SST1703.severity = error
```

Use `warning` for warnings, `suggestion` for suggestions, or `silent` for a hidden diagnostic.
Use `none` to disable the rule.

## When to suppress

Leave the rule disabled if your project prefers classic extension methods or shares source with
projects below C# 14. Suppress individual methods when receiver attributes or generic constraints
prevent a suitable conversion.
