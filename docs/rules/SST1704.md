# SST1704 — Extension container class names should end in 'Extensions' or 'Mixins'

| Item | Value |
| --- | --- |
| Category | Extensions |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | Yes (supports Fix All) |
| Applies to | C# 14 extension blocks |

## Cause

A class declaring an `extension` block has a name that does not end in `Extensions` or `Mixins`.
The suffix check is case-sensitive. Classes containing only classic extension methods are not
checked by this rule.

## Example

Before:

```csharp
public static class StringStuff
{
    extension(string text)
    {
        public bool IsEmpty => text.Length == 0;
    }
}
```

After applying the default fix:

```csharp
public static class StringStuffExtensions
{
    extension(string text)
    {
        public bool IsEmpty => text.Length == 0;
    }
}
```

## Code fix

The fix appends the preferred suffix to the class name and renames references to the class across
the solution. The default suffix is `Extensions`; choosing `Mixins` produces `StringStuffMixins`
in this example.

## Configuration

The default severity is `warning`. To report violations as errors and use the default fix suffix:

```ini
[*.cs]
dotnet_diagnostic.SST1704.severity = error
stylesharp.extension_container_preferred_suffix = Extensions
```

Allowed severities are `none`, `silent`, `suggestion`, `warning`, and `error`.

The fix also accepts `stylesharp.SST1704.preferred_suffix`. Both suffix keys accept `Extensions`
or `Mixins`, without regard to case. A valid rule-specific value takes priority over the general
key. If neither provides a valid value, the fix uses `Extensions`.

These options choose the fix's suffix. The rule accepts both suffixes regardless of the preference.

## When to suppress

Suppress when an existing public class name must remain compatible with callers outside the
solution, or when your project has a different naming convention.
