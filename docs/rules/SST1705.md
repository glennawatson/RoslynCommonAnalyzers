# SST1705 — Do not mix classic extension methods with extension blocks

| Item | Value |
| --- | --- |
| Category | Extensions |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | Yes (supports Fix All) |
| Applies to | C# 14 extension blocks |

## Cause

A class declaration contains both an `extension` block and a classic extension method with a
`this` parameter. Each classic extension method is reported, even if it extends a different type
from the block.

A class containing only classic extension methods is not reported. To request conversion of those
methods too, enable [SST1703](SST1703.md).

## Example

Before:

```csharp
public static class StringExtensions
{
    public static bool IsBlank(this string text) => text.Length == 0;

    extension(string text)
    {
        public int Words => text.Split(' ').Length;
    }
}
```

After applying the fix:

```csharp
public static class StringExtensions
{
    extension(string text)
    {
        public bool IsBlank() => text.Length == 0;
        public int Words => text.Split(' ').Length;
    }
}
```

## Code fix

The fix moves the method into a block and removes its `static` modifier and `this` parameter.
The receiver keeps its name and modifiers, including `in` or `ref`. The body stays the same and
the member remains a method.

The method joins a block only when the receiver type spelling, name, modifiers, block type
parameters, and constraints match. Otherwise, it gets a separate block with a short XML summary.
If only the receiver names differ, this can produce a duplicate-block report from
[SST1701](SST1701.md).

Type parameters used in the receiver type move to the block with their constraints; the rest stay
on the method. A fix is not offered if a constraint moved to the block refers to a type parameter
left on the method.

The fix formats the moved code. It removes the receiver's `<param>...</param>` description and
`<typeparam>...</typeparam>` descriptions for type parameters moved to the block. Copy any needed
text into the block's documentation. Comments attached to the removed receiver name or modifiers
can be lost.

No fix is offered for methods without bodies or receiver parameters with attributes or default
values. Joining an existing block is withheld when the method contains preprocessor directives
or the move would split a directive pair, such as `#if` and `#endif`.

## Configuration

There are no rule-specific options. The default severity is `warning`. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1705.severity = error
```

Allowed severities are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress during a gradual migration or when a method needs receiver attributes or generic
constraints that cannot be preserved in a block.
