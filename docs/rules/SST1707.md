# SST1707 — Extension blocks should be ordered by receiver type

| Item | Value |
| --- | --- |
| Category | Extensions |
| Default severity | Warning |
| Enabled by default | No |
| Code fix | No |
| Applies to | C# 14 extension blocks |

## Cause

An `extension` block's receiver type sorts before the receiver type of the preceding block in the
same class declaration. Receiver types are compared as written, in case-sensitive text order.
For example, `int` comes before `string`. The receiver variable name does not affect the order.

## Example

Before, reported when the rule is enabled:

```csharp
public static class SampleExtensions
{
    extension(string text)
    {
        public bool IsEmpty => text.Length == 0;
    }

    extension(int value)
    {
        public bool IsZero => value == 0;
    }
}
```

After:

```csharp
public static class SampleExtensions
{
    extension(int value)
    {
        public bool IsZero => value == 0;
    }

    extension(string text)
    {
        public bool IsEmpty => text.Length == 0;
    }
}
```

## How to fix violations

Reorder the blocks by receiver type. There is no automatic code fix.

[SST1701](SST1701.md) checks duplicate blocks for one receiver type. [SST1702](SST1702.md) asks you
to keep blocks together, without other members between them.

## Configuration

The rule is disabled by default. There is no option to change the sort order. Set a severity to enable it:

```ini
[*.cs]
dotnet_diagnostic.SST1707.severity = error
```

Use `warning` for warnings, `suggestion` for suggestions, or `silent` for a hidden diagnostic.
Use `none` to disable the rule.

## When to suppress

Leave the rule disabled or suppress it when grouping blocks by purpose is more useful than sorting
by type name. Also suppress when moving a block would change its conditional compilation.
