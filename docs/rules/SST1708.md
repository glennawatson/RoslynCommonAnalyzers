# SST1708 — Extension methods should use their receiver parameter

| Item | Value |
| --- | --- |
| Category | Extensions |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | No |

## Cause

A classic extension method has a body that never mentions its `this` parameter's name. That
parameter is the receiver: in `text.Zero()`, it receives `text`. A method that ignores it may
work better as a static helper.

Both block bodies and expression bodies are checked. A receiver named `_` and methods without
bodies are ignored. A use inside `nameof` counts. Members inside extension blocks are covered
separately by [SST1711](SST1711.md).

## Example

Before:

```csharp
public static class StringExtensions
{
    public static int Zero(this string text) => 0;
}
```

After removing the unused receiver:

```csharp
public static class NumberHelpers
{
    public static int Zero() => 0;
}
```

## How to fix violations

If the operation should depend on the receiver, use it in the body. Otherwise, make the method a
static helper and remove unused parameters. Update callers, for example from `text.Zero()` to
`NumberHelpers.Zero()`.

There is no automatic code fix because changing the method requires a decision about its callers.

## Configuration

There are no rule-specific options. The default severity is `warning`. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST1708.severity = error
```

Allowed severities are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when an existing extension signature must remain compatible with callers, or when a
constant result is intentional for this receiver type. A receiver named `_` already expresses
intentional non-use and is not reported.
