# SST1709 — Static helpers in an extension container should be extensions

| Item | Value |
| --- | --- |
| Category | Extensions |
| Default severity | Warning |
| Enabled by default | No |
| Code fix | Yes (supports Fix All) |
| Applies to | C# 14 or later |

## Cause

A class whose name ends in `Extensions` declares a static helper that could become an extension.
All of these conditions must hold:

- The method is `public` or `internal`, has a body, and declares no type parameters.
- It has at least one parameter, and the first parameter has no modifiers such as `this`, `ref`,
  `out`, `in`, or `params`.
- The first parameter is not a delegate, such as `Action<string>`.

The suffix check is case-sensitive; a class ending in `Mixins` is not checked. Nullable first
parameters are included. The rule reports nothing below C# 14.

## Example

Before, reported when the rule is enabled:

```csharp
public static class StringExtensions
{
    public static bool IsBlank(string text) => text.Length == 0;
}
```

After applying the fix:

```csharp
public static class StringExtensions
{
    /// <summary>Extension members for <c>string</c>.</summary>
    extension(string text)
    {
        public bool IsBlank() => text.Length == 0;
    }
}
```

## Code fix

The fix turns the first parameter into a block receiver, removes that parameter and `static`
from the method, and moves the method into the block. Its body stays the same. Callers can use
extension syntax, such as `text.IsBlank()`.

The method joins an existing block only when the receiver type spelling, name, modifiers, type
parameters, and constraints match. Otherwise, the fix creates a block with a short XML summary.
Different receiver names can lead to a duplicate-block report from [SST1701](SST1701.md).

The fix formats the moved code and removes the receiver's `<param>...</param>` description from
the method's XML comment. Copy any needed text into the block's documentation. Comments attached
to the removed receiver name can be lost.

No fix is offered when the first parameter has attributes or a default value. Joining an existing
block is withheld when the method contains preprocessor directives or the move would split a
directive pair, such as `#if` and `#endif`.

## Configuration

The rule is disabled by default. There are no rule-specific options. Set a severity to enable it:

```ini
[*.cs]
dotnet_diagnostic.SST1709.severity = error
```

Use `warning` for warnings, `suggestion` for suggestions, or `silent` for a hidden diagnostic.
Use `none` to disable the rule.

## When to suppress

Leave the rule disabled or suppress a method when an `Extensions` class intentionally contains
plain static helpers. A first parameter does not always represent an object you want to extend.
