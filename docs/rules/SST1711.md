# SST1711 — Extension block members should use the block's receiver

| Item | Value |
| --- | --- |
| Category | Extensions |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | No |
| Applies to | C# 14 or later |
| Analyzer | `Sst1711UnusedBlockReceiverAnalyzer` |

## Cause

A member of an `extension(Receiver) { … }` block never reads the block's receiver.

```csharp
public static class StringExtensions
{
    extension(string text)
    {
        // 👎 reported — answers 42 for every string
        public int Always => 42;

        // 👍
        public int Doubled => text.Length * 2;
    }
}
```

## Rule description

A block member is reached through the receiver — `"abc".Always` reads as something the string knows
about itself. One whose body never touches the receiver answers the same for every instance, so the
receiver in its signature is decoration: the member is a plain helper that has been given
instance-style call syntax it does not earn.

Moved out of the block it says what it is, and it stops appearing in completion for every value of
the receiver type.

**Static members are never reported.** The receiver is not in scope for a static extension member, so
it could not read it either way — reporting one would make every static extension member a violation:

```csharp
extension(string text)
{
    public static string Blank => "   "; // not reported
}
```

Where a block holds only static members the receiver name is unusable and the nameless form
`extension(string)` says so.

Both accessors of a property or indexer count as one member: a receiver read in either the getter or
the setter satisfies the rule.

## Why there is no code fix

Moving the member out of the block changes how every call site spells it — `value.Always` becomes
`StringExtensions.Always(value)` or something else the author chooses — and whether it should keep
the receiver as a parameter at all is a design decision. SST1708 declines to fix the classic-method
form for the same reason.

## How to fix violations

Either use the receiver, or declare the member outside the block:

```csharp
public static class StringExtensions
{
    public static int Always => 42;

    extension(string text)
    {
        public int Doubled => text.Length * 2;
    }
}
```

## Performance

The rule runs on class declarations and only walks the members of a block that declares a named
receiver. A member's body is scanned only after the static and shape gates pass, and the token scan
stops at the first read of the receiver.
