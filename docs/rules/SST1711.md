# SST1711 — Extension block members should use the block's receiver

| Item | Value |
| --- | --- |
| Category | Extensions |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | No |
| Applies to | C# 14 or later |

## Cause

An instance method, property, or indexer in an extension block has a body that does not use the receiver. The receiver is the value named in the block header, such as `text` in `extension(string text)`.

Static members are not reported. Neither are blocks with an unnamed receiver or a receiver named `_`. For a property or indexer, using the receiver in either accessor is enough.

## How to fix violations

Use the receiver if the result should depend on it. Otherwise, move the member outside the block and make it static.

Reported:

```csharp
public static class StringExtensions
{
    extension(string text)
    {
        public int Always => 42;
    }
}
```

Corrected:

```csharp
public static class StringExtensions
{
    public static int Always => 42;
}
```

Update callers from `value.Always` to `StringExtensions.Always`.

There is no automatic code fix.

## Configuration

There are no rule-specific options. Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1711.severity = warning
```

Values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when existing callers depend on the public extension member and moving it would break that API.
