# SST1712 — Extension blocks with only static members should omit the receiver name

| Item | Value |
| --- | --- |
| Category | Extensions |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | Yes |
| Applies to | C# 14 or later |

## Cause

An extension block names its receiver, but every member in the block is `static`. Static members cannot use the receiver name, so keep only its type.

Blocks with any instance member are not reported. Empty blocks are also excluded; [SST1700](SST1700.md) reports those.

## How to fix violations

Remove the receiver name.

Reported:

```csharp
public static class StringExtensions
{
    extension(string text)
    {
        public static string Blank => "   ";
    }
}
```

Corrected:

```csharp
public static class StringExtensions
{
    extension(string)
    {
        public static string Blank => "   ";
    }
}
```

## Code fix

**Drop the receiver name** removes the name and the space after the receiver type. It keeps the type, attributes, and modifiers such as `in` or `ref`.

Comments between the type and name, or attached to the removed name, are also removed. Move any comment you need before accepting the fix.

## Configuration

There are no rule-specific options. Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1712.severity = warning
```

Values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

## When to suppress

Suppress if your project deliberately keeps named receivers in every extension block for consistency. Removing this unused name is a style choice.
