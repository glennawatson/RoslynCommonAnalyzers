# SST1800 — Record classes should be sealed

| Item | Value |
| --- | --- |
| Category | Records |
| Default severity | Warning |
| Enabled by default | No |
| Code fix | No |

## Cause

A record class declaration has neither `sealed` nor `abstract`. Record structs are not reported.

The rule reports the declaration even when another record inherits from it. Enable it when your project expects concrete record classes to be closed to inheritance.

## How to fix violations

Add `sealed` if other records should not inherit from this type.

Reported when enabled:

```csharp
public record Animal(string Name);
```

Corrected:

```csharp
public sealed record Animal(string Name);
```

Use `abstract` instead if the record exists only as a base type. That prevents callers from creating it directly. Check existing subclasses and callers before choosing either modifier.

There is no automatic code fix.

## Configuration

The rule is disabled by default and has no rule-specific options. Enable it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1800.severity = warning
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable it.

## When to suppress

Suppress when a concrete record is intentionally both a base type and a type callers can create directly. Neither `sealed` nor `abstract` preserves that contract.
