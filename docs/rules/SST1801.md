# SST1801 — Positional record parameters should match the configured casing

| Item | Value |
| --- | --- |
| Category | Records |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | No |

## Cause

A parameter in the header of a `record` or `record struct` does not start with the configured letter case. The default is PascalCase: an uppercase first letter. Names made entirely of underscores are excluded.

These parameters usually become public properties, so their names should follow your project's property naming convention.

## How to fix violations

Rename the parameter and update references to it and its generated property, including named constructor arguments.

Reported with the default configuration:

```csharp
public sealed record Point(int x, int y);
```

Corrected:

```csharp
public sealed record Point(int X, int Y);
```

There is no automatic code fix.

## Configuration

Set the severity and naming convention in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1801.severity = warning
stylesharp.record_parameter_naming = pascal_case
```

| Option | Values | Default |
| --- | --- | --- |
| `stylesharp.record_parameter_naming` | `pascal_case`, `camel_case` | `pascal_case` |
| `stylesharp.SST1801.record_parameter_naming` | `pascal_case`, `camel_case` | Uses the general option |

A recognized rule-specific value overrides the general option. Values are case-insensitive. Unrecognized values are ignored; if neither option has a recognized value, PascalCase applies. `camel_case` requires a lowercase first letter. The rule checks the first letter, not the rest of the name.

Severity values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when renaming a published parameter or property would break callers or a serialized data contract. If the whole project uses camelCase, configure that convention instead.
