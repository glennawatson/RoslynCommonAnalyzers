# SST1802 — Record properties should be init-only

| Item | Value |
| --- | --- |
| Category | Records |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | Yes |

## Cause

An instance property declared in a record class or a `readonly record struct` has a `set` accessor. This includes private setters and setters with bodies.

Static properties, properties without `set`, and record structs without `readonly` are excluded.

Changing a record's stored values can change its equality and hash code. This can make it hard to find after it has been added to a hash set or used as a dictionary key.

## How to fix violations

Use `init` to allow callers to assign the property during initialization instead of changing it later.

Reported:

```csharp
public sealed record Scan
{
    public bool Found { get; set; }
}
```

Corrected:

```csharp
public sealed record Scan
{
    public bool Found { get; init; }
}
```

## Code fix

**Use 'init' accessor** replaces `set` with `init`. It preserves the accessor's body, attributes, access modifiers, comments, and spacing.

The fix does not update assignments elsewhere. Move those assignments into initialization, or create an updated record with a `with` expression. Code that requires a setter after initialization will need to change.

## Configuration

There are no rule-specific options. Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1802.severity = warning
```

Values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when the record intentionally supports changes after initialization, such as a model used by a framework that requires writable properties. Avoid changing values used for equality while the record is a dictionary key or belongs to a hash set.
