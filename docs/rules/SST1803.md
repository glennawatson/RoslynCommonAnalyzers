# SST1803 — Record structs should be readonly

| Item | Value |
| --- | --- |
| Category | Records |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | Yes |
| Applies to | C# 10 or later |

## Cause

A `record struct` is declared without `readonly`. The rule excludes records that declare an instance property with `set` or an instance field that is neither `readonly` nor `const`.

A nested positional record struct is also excluded when code in its containing type assigns to, increments, or decrements a member through an instance of that record. This does not cover writes elsewhere in the project or in callers' projects.

## How to fix violations

Add `readonly` when the record represents a value that should not change after initialization.

Reported:

```csharp
public record struct Point(int X, int Y);
```

Corrected:

```csharp
public readonly record struct Point(int X, int Y);
```

## Code fix

**Add 'readonly' modifier** adds the modifier and arranges the declaration's modifiers in standard order.

For a positional record struct, this also changes the generated properties from `set` to `init`. The fix does not update callers. Check for assignments after construction, especially when the record is public; those assignments will fail to compile.

## Configuration

There are no rule-specific options. Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1803.severity = warning
```

Values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when callers must be able to change the record's properties after initialization, or when adding `readonly` would break an existing public API.
