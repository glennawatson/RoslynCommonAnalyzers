# SST1901 — Do not lock on a publicly accessible object

| Item | Value |
| --- | --- |
| Category | Concurrency |
| Default severity | Warning |
| Enabled by default | Yes |
| Code fix | No |

## Cause

A `lock` targets a `public`, `protected`, or `protected internal` field or property. Unrelated code can take the same lock and block your code, or cause a deadlock where each thread waits for the other.

Private, internal, and private protected members are not reported. Parentheses or an `object` cast around the target do not hide it from the rule.

## How to fix violations

Use a private, dedicated lock object. Every operation protecting the same state must use the same object.

Reported:

```csharp
public class Counter
{
    public readonly object Gate = new();
    private int _count;

    public void Increment()
    {
        lock (Gate) { _count++; }
    }
}
```

Corrected:

```csharp
public class Counter
{
    private readonly object _gate = new();
    private int _count;

    public void Increment()
    {
        lock (_gate) { _count++; }
    }
}
```

Do not expose the private lock object through another member. Use a static lock field when the protected state is static.

There is no automatic code fix.

## Configuration

There are no rule-specific options. Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1901.severity = warning
```

Values are `error`, `warning` (default), `suggestion`, `silent`, and `none`.

## When to suppress

Suppress when exposing the lock is part of a documented contract that callers must share. Changing only the lock inside this type would stop it coordinating with those callers; migrate both sides together.
