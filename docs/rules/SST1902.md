# SST1902 — Do not lock on 'this', a Type, or a string

| Item | Value |
| --- | --- |
| Category | Concurrency |
| Default severity | Warning |
| Enabled by default | No |
| Code fix | No |

## Cause

A `lock` targets `this`, a string, or a `System.Type` value such as `typeof(Counter)`. This includes fields and properties typed as string or `Type`, even if they are private.

Other code can lock on the same instance. Type objects are shared, and equal string literals can refer to the same string object. This can cause unexpected blocking or deadlocks.

## How to fix violations

Use a private, dedicated lock object for every operation protecting the same state.

Reported when enabled:

```csharp
public class Counter
{
    private int _count;

    public void Increment()
    {
        lock (this) { _count++; }
    }
}
```

Corrected:

```csharp
public class Counter
{
    private readonly object _gate = new();
    private int _count;

    public void Increment()
    {
        lock (_gate) { _count++; }
    }
}
```

Use a static lock field when the protected state is static. Keep the lock object private.

There is no automatic code fix.

## Configuration

The rule is disabled by default and has no rule-specific options. Enable it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST1902.severity = warning
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable it.

## When to suppress

Suppress when an existing contract requires callers to lock on this same object. Changing the target in only one place breaks that coordination; migrate all participants together.
