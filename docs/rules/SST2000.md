# SST2000 — Use ArgumentNullException.ThrowIfNull

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An `if` checks `value is null`, `value == null`, or `null == value` and only
throws a new `ArgumentNullException`. It must have no `else` branch. The exception
must have no arguments, or one `nameof(...)` or string argument naming the checked
value. Guards with a custom message are not reported.

The rule reports nothing when `ArgumentNullException.ThrowIfNull` is unavailable.
The helper is included in .NET 6 and later.

## Example

Before:

```csharp
using System;

public class Example
{
    public void Check(object value)
    {
        if (value is null)
        {
            throw new ArgumentNullException(nameof(value));
        }
    }
}
```

After:

```csharp
using System;

public class Example
{
    public void Check(object value)
    {
        ArgumentNullException.ThrowIfNull(value);
    }
}
```

## How to fix violations

The code fix replaces the whole `if` statement with `ThrowIfNull(value)`. The helper
takes the parameter name from the argument expression. This adds a parameter name
when the original exception had none; a member expression can also produce a
different name from `nameof(...)`.

Comments before and after the `if` are kept. Comments inside the removed guard
can be lost. Fix All is supported.

## Configuration

There are no rule-specific options. The rule is enabled by default at `warning`
severity. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2000.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule or `default` to restore its default.

## When to suppress

Suppress when callers rely on the exact exception message or parameter name.
Also keep an explicit comparison if the type's custom `==` operator gives it a
meaning that a null check would not preserve.
