# SST2001 — Use ArgumentException.ThrowIfNullOrEmpty

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled (opt-in) |

## Cause

An `if (string.IsNullOrEmpty(value))` only throws a new `ArgumentException` or
`ArgumentNullException`. The `if` must have no `else` branch. Custom exception
messages do not prevent a report.

The rule reports nothing when `ArgumentException.ThrowIfNullOrEmpty` is unavailable.
The helper is included in .NET 7 and later.

## Example

Before, when the rule is enabled:

```csharp
using System;

public class Example
{
    public void Check(string value)
    {
        if (string.IsNullOrEmpty(value))
        {
            throw new ArgumentException("Value required.", nameof(value));
        }
    }
}
```

After:

```csharp
using System;

public class Example
{
    public void Check(string value)
    {
        ArgumentException.ThrowIfNullOrEmpty(value);
    }
}
```

## How to fix violations

The code fix replaces the whole guard with `ThrowIfNullOrEmpty(value)`. It removes
the exception constructor and all its arguments, including any custom message or
inner exception. The helper uses the argument expression as the parameter name.
It throws `ArgumentNullException` for null and `ArgumentException` for an empty
string, so the exception type can change.

Comments before and after the `if` are kept. Comments inside the removed guard
can be lost. Fix All is supported.

## Configuration

There are no rule-specific options. The rule is disabled by default because the
rewrite can change exception behavior. Its default severity is `warning`. Enable
it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2001.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule or `default` to restore its default.

## When to suppress

Leave the rule disabled, or suppress a guard, when callers depend on the existing
exception type, message, parameter name, or inner exception. Keep the guard if
evaluating its exception arguments performs work that must still happen.
