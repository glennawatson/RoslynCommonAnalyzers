# SST2004 — Use ArgumentOutOfRangeException range helpers

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An `if` compares a value with a limit and only throws a new
`ArgumentOutOfRangeException(nameof(value))`. The `if` must have no `else` branch,
and exactly one side of the comparison must be the identifier named by `nameof`.
Custom messages and other constructor arguments are not reported.

The rule reports nothing when the matching helper is unavailable. These helpers
are included in .NET 8 and later.

## Example

Before:

```csharp
using System;

public class Example
{
    public void Check(int value)
    {
        if (value < 0) throw new ArgumentOutOfRangeException(nameof(value));
    }
}
```

After:

```csharp
using System;

public class Example
{
    public void Check(int value)
    {
        ArgumentOutOfRangeException.ThrowIfNegative(value);
    }
}
```

## How to fix violations

The code fix replaces the whole guard with a helper call on
`ArgumentOutOfRangeException`:

| Condition | Helper call |
| --- | --- |
| `value < 0` | `ThrowIfNegative(value)` |
| `value <= 0` | `ThrowIfNegativeOrZero(value)` |
| `value == 0` | `ThrowIfZero(value)` |
| `value < limit` | `ThrowIfLessThan(value, limit)` |
| `value <= limit` | `ThrowIfLessThanOrEqual(value, limit)` |
| `value > limit` | `ThrowIfGreaterThan(value, limit)` |
| `value >= limit` | `ThrowIfGreaterThanOrEqual(value, limit)` |
| `value == limit` | `ThrowIfEqual(value, limit)` |
| `value != limit` | `ThrowIfNotEqual(value, limit)` |

Reversed comparisons, such as `0 > value`, are supported. When the limit is the
literal `0`, only the first three conditions in the table are reported.

The helper supplies its own message and includes the rejected value in the
exception. Comments before and after the `if` are kept; comments inside the
removed guard can be lost. Fix All is supported.

## Configuration

There are no rule-specific options. The rule is enabled by default at `warning`
severity. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2004.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule or `default` to restore its default.

## When to suppress

Suppress when callers require the existing exception message or contents. Keep
the comparison if the value's type cannot be passed to the helper, or its custom
comparison behavior differs from the helper's comparison.
