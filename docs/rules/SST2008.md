# SST2008 — Use is-not patterns

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A pattern test is negated with `!`, as in `!(value is null)` or
`!(value is string text)`. The rule requires C# 9 or later. Plain type tests such
as `!(value is string)` are handled by [SST2006](SST2006.md).

A whole `var` pattern is not reported: it matches every value, and the compiler
rejects `not var text`. A `var` inside a property pattern can still be reported
because the enclosing pattern can fail.

## Example

Before:

```csharp
public class Example
{
    public int Length(object value)
    {
        if (!(value is string text))
        {
            return 0;
        }

        return text.Length;
    }
}
```

After:

```csharp
public class Example
{
    public int Length(object value)
    {
        if (value is not string text)
        {
            return 0;
        }

        return text.Length;
    }
}
```

## How to fix violations

The code fix removes `!` and its wrapping parentheses, then negates the pattern.
It keeps declared variable names, so `text` remains available after the early
return in the example. Fix All is supported.

An existing `not` is removed: `!(value is not null)` becomes `value is null`.
Combined patterns are grouped: `!(value is 1 or 2)` becomes
`value is not (1 or 2)`. Comments attached to removed punctuation can be lost.

## Configuration

There are no rule-specific options. The rule is enabled by default at `warning`
severity. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2008.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule or `default` to restore its default.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when shared source must compile before C# 9, or when keeping `!` makes
a complex condition easier to read alongside nearby conditions.
