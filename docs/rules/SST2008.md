# SST2008 - Use is-not patterns

**Category:** Modernization
**Severity:** Warning
**Code fix:** Yes (supports Fix All)

A negated pattern test reads more directly as an `is not` pattern. The rewrite
also removes the extra grouping needed around the positive pattern expression.

A pattern that binds a name is rewritten along with the rest: the name is
assigned on exactly the branch it was assigned on before, which is what makes
the early-return form below work.

## What is not reported

A whole pattern that is `var`. It accepts every value, so `not var v` can never
match and the compiler rejects it outright. A `var` inside a subpattern is
reached only once the enclosing pattern has matched, so that pattern can still
fail and it is reported as normal.

## Example

```csharp
if (!(value is null)) // SST2008
{
}
```

Use:

```csharp
if (value is not null)
{
}
```

A pattern that binds a name:

```csharp
if (!(value is string text)) // SST2008
{
    return 0;
}

return text.Length;
```

Use:

```csharp
if (value is not string text)
{
    return 0;
}

return text.Length;
```
