# SST2009 — Filter exceptions with a when clause

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A catch block starts with a condition that decides whether to rethrow the caught
exception. Two forms are reported:

- The catch contains only an `if`/`else`, and exactly one branch is a bare `throw;`.
- The catch starts with `if (condition) throw;` and has handling statements after it.

The rule requires C# 6 or later. Catches with an existing `when` filter are not
reported. Conditions can use variables, member reads, literals, comparisons,
`!`, `&&`, `||`, type tests, and simple constant or property patterns. Conditions
with method calls, indexing, assignments, or patterns that declare variables are
not reported.

A `when` filter decides whether to enter the handler before intervening `finally`
blocks run. A false filter lets the exception continue to another handler.

## Example

Before:

```csharp
using System;

public class Example
{
    public void Process(Action work, bool canHandle)
    {
        try
        {
            work();
        }
        catch (Exception ex)
        {
            if (canHandle)
            {
                Console.WriteLine(ex.Message);
            }
            else
            {
                throw;
            }
        }
    }
}
```

After:

```csharp
using System;

public class Example
{
    public void Process(Action work, bool canHandle)
    {
        try
        {
            work();
        }
        catch (Exception ex) when (canHandle)
        {
            Console.WriteLine(ex.Message);
        }
    }
}
```

## How to fix violations

The code fix moves the condition into `when`, removes the rethrow branch, and
keeps the handling statements as the catch body. If the true branch rethrows,
the fix negates the condition. It removes an existing `!`, reverses a comparison
operator such as `==` to `!=`, or wraps the condition in `!(...)`.

The fix formats the catch and removes leading blank lines from its body.
Comments on retained statements are kept; comments attached to the removed
`if`, braces, or rethrow can be lost. No fix is offered when the catch contains
directives such as `#region` or `#if`. Fix All is supported.

## Configuration

There are no rule-specific options. The rule is enabled by default at `warning`
severity. Set its severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2009.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule or `default` to restore its default.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the condition must run after `finally` blocks, or when evaluating
it can throw an exception that must reach the caller. Exceptions thrown inside
a filter are treated as a false result. Accepted property reads and custom
operators can still throw or change state, so review those before accepting.

Also review reversed comparisons involving floating-point `NaN` or custom
operators: reversing `<` to `>=`, for example, need not preserve the negation.
