# SST2010 — Read the clock through a TimeProvider

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | No |
| Default | Disabled (opt-in) |

## Cause

Code inside a type reads `DateTime.Now`, `DateTime.UtcNow`, `DateTimeOffset.Now`,
or `DateTimeOffset.UtcNow` directly. Reads used within a larger expression, such
as `DateTime.UtcNow.Hour`, are included.

Passing a `TimeProvider` into the type lets tests control time without waiting
for the machine clock. This is useful for expiry, scheduling, and deadlines.

The rule reports nothing when `System.TimeProvider` is unavailable. It is
included in .NET 8 and later. Top-level statements, `DateTime.Today`, and reads
through a provider are not reported.

## Example

Before, when the rule is enabled:

```csharp
using System;

public class Clock
{
    public DateTimeOffset Read() => DateTimeOffset.UtcNow;
}
```

After:

```csharp
using System;

public class Clock
{
    private readonly TimeProvider _time;

    public Clock(TimeProvider time) => _time = time;

    public DateTimeOffset Read() => _time.GetUtcNow();
}
```

## How to fix violations

There is no code fix.

Accept a `TimeProvider` in the constructor and store it in a field. Replace UTC
clock reads with `GetUtcNow()`, or use `GetLocalNow()` where local time is needed.
Both methods return `DateTimeOffset`; use `.UtcDateTime` if a caller needs a UTC
`DateTime`. Update construction sites to pass `TimeProvider.System` in normal
use and a controlled provider in tests.

## Configuration

There are no rule-specific options. The rule is disabled by default because
adding a provider changes how callers construct the type. Its default severity
is `warning`. Enable it in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2010.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and
`default`. Use `none` to disable the rule or `default` to restore its default.
See [configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled, or suppress a read, when controlling time would add no
useful test coverage. Examples include a diagnostic timestamp or a short script.
Suppression can also be appropriate when an external API fixes how the type is
constructed.

## Related rules

[SST2011](SST2011.md) asks for UTC when a clock value is stored or returned.
Changing `Now` to `UtcNow` can satisfy that rule while still leaving a direct
clock read here.
