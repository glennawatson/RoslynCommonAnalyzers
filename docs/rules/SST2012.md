# SST2012 — Use Guid.Empty for the empty GUID

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A parameterless `new Guid()` creates the all-zero GUID. Use `Guid.Empty` to make that intent clear.
The rule also reports `new System.Guid()` and `new()` where the required type is `System.Guid`.
Constructors with arguments, `Guid.NewGuid()`, `default`, and other types named `Guid` are not reported.

## Example

Before:

```csharp
using System;

public class Identifiers
{
    public Guid Blank() => new Guid();
}
```

After:

```csharp
using System;

public class Identifiers
{
    public Guid Blank() => Guid.Empty;
}
```

If you need a fresh identifier, use `Guid.NewGuid()` instead. The code fix keeps the all-zero value.

## How to fix violations

The code fix replaces the constructor call with `Guid.Empty`. It keeps an explicit qualification:
`new System.Guid()` becomes `System.Guid.Empty`. For `new()`, it uses `Guid.Empty` or
`global::System.Guid.Empty` as needed to refer to the framework value. Move comments inside the
constructor call before applying the fix; they can be lost.

## Configuration

The default is `warning`. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2012.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the constructor spelling is part of a test or example that must demonstrate
parameterless construction. Ordinary code should use the named empty value.
