# SST2014 — Avoid goto

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `goto` jumps to a label. Prefer `return`, `break`, `continue`, or a separate method so the reader
can follow where execution goes without searching for a label.

`goto case` and `goto default` are not reported. In C# 15 or later, a jump to a label outside the
innermost enclosing loop is also excluded. Jumps with no enclosing loop, or to a label inside that
loop, are still reported.

## Example

Before:

```csharp
public class Validation
{
    public int Check(int value)
    {
        if (value < 0)
        {
            goto Failed;
        }

        return 0;

    Failed:
        return -1;
    }
}
```

After:

```csharp
public class Validation
{
    public int Check(int value)
    {
        if (value < 0)
        {
            return -1;
        }

        return 0;
    }
}
```

## How to fix violations

There is no code fix. Choose a replacement that preserves the paths through the method, including
any cleanup that must run before it returns.

## Configuration

The default is `warning`. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2014.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress for a parser or state machine where explicit jumps make the transitions easier to follow,
or where removing a jump would duplicate substantial cleanup code. Keep the reason close to the jump.
