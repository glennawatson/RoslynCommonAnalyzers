# SST2015 — Do not bury an increment inside a larger expression

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `++` or `--` appears inside a larger expression, such as an array index, a method argument,
arithmetic, or a compound assignment. The expression both uses a value and changes it, which makes
the order of operations harder to follow.

The rule allows an increment or decrement on its own, as a `for` initializer or increment, as the
whole value of a variable initializer or plain assignment statement, or as the whole return value
or expression body of a method or lambda. Parentheses do not change these exclusions.

## Example

Before:

```csharp
public class Updates
{
    public void Set(int[] values, int i)
    {
        values[i++] = Compute(i);
    }

    private static int Compute(int value) => value;
}
```

After, preserving the order in which `i` changes:

```csharp
public class Updates
{
    public void Set(int[] values, int i)
    {
        int index = i;
        i++;
        values[index] = Compute(i);
    }

    private static int Compute(int value) => value;
}
```

## How to fix violations

There is no code fix. Separate the increment from the larger expression and check when each value
is read. In the example, `Compute` receives the incremented value. Moving `i++` after the assignment
would change that behavior. Preserve conditional execution too: an increment inside the right side
of `&&` must still run only when the left side is true.

## Configuration

The default is `warning`. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2015.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress for a compact indexing operation where the evaluation order is deliberate and splitting
it would make the algorithm harder to follow. Document which value is read before it changes.
