# SST2016 — Expose DateTimeOffset rather than DateTime

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A field, property, method return type, or parameter visible outside the assembly uses `DateTime`
or `DateTime?`. This includes constructor parameters, positional record parameters, and delegate
signatures. Members and their containing types must be externally visible, such as `public`,
`protected`, or `protected internal`.

Use `DateTimeOffset` for a point in time passed between callers. It carries the difference from
UTC with the clock time. `DateTime.Kind` can identify UTC or local time, but it does not carry a
specific UTC offset.

Locals, private and internal members, overrides, and interface implementations are excluded.
The rule checks directly declared types, not `DateTime` inside an array or generic type.
It reports nothing if `System.DateTimeOffset` is unavailable.

## Example

Before:

```csharp
using System;

public class Booking
{
    public DateTime Start { get; set; }
    public DateTime? Cancelled { get; set; }
}
```

After:

```csharp
using System;

public class Booking
{
    public DateTimeOffset Start { get; set; }
    public DateTimeOffset? Cancelled { get; set; }
}
```

## How to fix violations

There is no code fix. Change the declared type and update callers, storage, and serialization
together. When converting existing values, establish which offset they represent; a type change
cannot recover missing time-zone information.

An offset does not identify a time zone. For future appointments tied to a local clock, keep the
time-zone identifier as well so you can apply the rules for that date.

## Configuration

The default is `warning`. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2016.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an external API, database mapping, or published contract requires `DateTime`, or when
the value deliberately represents a local clock time rather than a point in time. An explicit,
enforced UTC-only contract can also justify keeping `DateTime`.
