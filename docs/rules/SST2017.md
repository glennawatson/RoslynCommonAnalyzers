# SST2017 — Use DateOnly or TimeOnly when only a date or a time of day is meant

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

Code reads `.Date` or `.TimeOfDay` from a `System.DateTime`. Use `DateOnly` for a calendar date and
`TimeOnly` for a time on a clock. `.Date` returns a `DateTime` set to midnight; `.TimeOfDay` returns
a `TimeSpan`, which represents a duration.

The rule excludes direct clock reads such as `DateTime.Now.Date` and `DateTime.UtcNow.TimeOfDay`,
properties on `DateTimeOffset` or other types, and components such as `.Day` and `.Hour`.

Each suggestion requires its corresponding type to be available. `DateOnly` and `TimeOnly` are
included in .NET 6 and later; if neither is available, nothing is reported.

## Example

Before:

```csharp
using System;

public class Schedule
{
    public DateTime Birthday(DateTime when) => when.Date;
    public TimeSpan Opening(DateTime when) => when.TimeOfDay;
}
```

After:

```csharp
using System;

public class Schedule
{
    public DateOnly Birthday(DateTime when) => DateOnly.FromDateTime(when);
    public TimeOnly Opening(DateTime when) => TimeOnly.FromDateTime(when);
}
```

## How to fix violations

There is no code fix. Replace the property read with the corresponding conversion and change the
type that stores or returns its result. Update callers and check that your database and serializer
support the new type. Where an API requires `DateTime`, convert a date with
`date.ToDateTime(TimeOnly.MinValue)`. Use `time.ToTimeSpan()` where an API requires `TimeSpan`.

## Configuration

The default is `warning`. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2017.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when `.Date` deliberately supplies a midnight boundary for comparisons with `DateTime`
values, or `.TimeOfDay` is needed as a duration since midnight. Suppress at an external API or
storage boundary that requires the existing type if converting away and back adds no value.
