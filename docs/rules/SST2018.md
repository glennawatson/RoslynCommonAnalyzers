# SST2018 — A null check beside a type pattern is redundant

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A null check sits beside a type test on the same value. A type test such as `value is string` is
false for null, so a separate non-null check is unnecessary.

| Reported expression | Replacement |
| --- | --- |
| `value != null && value is string` | `value is string` |
| `value is not null && value is string` | `value is string` |
| `value == null || value is not string` | `value is not string` |
| `value is null || value is not string` | `value is not string` |
| `value is not null and string` | `value is string` |
| `value is string and not null` | `value is string` |

For `&&` and `||`, the null test must come first and both checks must use the same expression.
Method calls and index accesses used as that repeated expression are excluded. A type test that
also declares a variable is supported.

Checks such as `value != null && value is not string` and `value == null || value is string` are
not reported: their null checks affect the result.

## Example

Before:

```csharp
public class Checks
{
    public bool IsText(object value) => value != null && value is string;
}
```

After:

```csharp
public class Checks
{
    public bool IsText(object value) => value is string;
}
```

## How to fix violations

The code fix removes the null check and keeps the type test, including any variable it declares.
It keeps `is not` for the `||` form. Comments within the removed check or around the joining
operator can be lost; move them outside the expression before applying the fix.

## Configuration

The default is `warning`. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2018.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a custom `==` or `!=` operator gives the null comparison a different meaning, or
when a repeated property read changes state or returns different values. Removing the check in
those cases can change behavior. Consider storing the property value in a local before testing it.
