# SST2019 — Test for null rather than for object

| Item | Value |
| --- | --- |
| Category | Modernization |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled; requires C# 9 or later |

## Cause

Code tests `value is object` or `value is not object` when the value can be null. These expressions
test whether a value is non-null or null. Write the null test directly.

Reference types, nullable value types, and unconstrained generic types are included. Non-nullable
value types and declarations such as `value is object bound` are excluded. Only the `object`
keyword is matched; `System.Object` and aliases are not reported. The rule requires C# 9 or later.

## Example

Before:

```csharp
public class Checks
{
    public bool HasValue(string value) => value is object;
    public bool IsMissing(string value) => value is not object;
}
```

After:

```csharp
public class Checks
{
    public bool HasValue(string value) => value is not null;
    public bool IsMissing(string value) => value is null;
}
```

## How to fix violations

The code fix replaces `is object` with `is not null`, and `is not object` with `is null`.
The tested expression stays the same. Comments between that expression and the type test can be
lost; move them outside the expression before applying the fix.

## Configuration

The default is `warning`. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2019.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress in tests or teaching examples that need to demonstrate an `object` type test. Ordinary
null checks are clearer with `is null` or `is not null`.
