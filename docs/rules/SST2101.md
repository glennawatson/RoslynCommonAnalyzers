# SST2101 — Use an explicit collection expression

| Item | Value |
| --- | --- |
| Category | CollectionExpressions |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled; requires C# 12 or later |

## Cause

A non-empty array or collection initializer can use `[element1, element2]`. The destination must
supply a type: a one-dimensional array, `List<T>`, `IList<T>`, `ICollection<T>`, `IEnumerable<T>`,
`IReadOnlyList<T>`, or `IReadOnlyCollection<T>`. The rule requires C# 12 or later.

The rule is opt-in because removing the explicit creation type can affect which method overload
is called. Arguments are excluded when the replacement would select a different overload or fail
to compile.

## Example

Before:

```csharp
public class Data
{
    public int[] Values = new[] { 1, 2, 3 };
}
```

After:

```csharp
public class Data
{
    public int[] Values = [ 1, 2, 3 ];
}
```

## What is not reported

The rule excludes empty initializers, declarations using `var`, `new()` initializers, and
dictionary-style entries such as `{ key, value }`. Arguments whose parameter type uses a method's
generic type parameter are excluded. A type fixed by the containing collection is allowed, such as
the `byte[]` argument to `List<byte[]>.Add`.

## How to fix violations

The code fix replaces the creation and initializer braces with brackets. It preserves the text
inside the braces, including spaces, line breaks, and comments. It leaves `using` directives in
place. Comments in the removed creation before the opening brace can be lost.

Only the initializer elements are retained. Constructor arguments, such as an initial capacity,
are removed. Check that the constructor does not supply behavior your code needs.

## Configuration

The rule is disabled by default. Its declared severity is `warning`; enable it at your chosen
severity. There are no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST2101.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).
See [configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled if your project prefers explicit collection types. Suppress individual
cases that rely on constructor arguments, a particular concrete collection type, a comparer, or
measured allocation behavior. An interface destination can produce a different collection type.
