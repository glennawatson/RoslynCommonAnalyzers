# SST2103 — Use a collection expression for this factory call

| Item | Value |
| --- | --- |
| Category | CollectionExpressions |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled; requires C# 12 or later |

## Cause

A static `Create` or `CreateRange` call builds a collection whose destination type supports
collection expressions. That type must use `CollectionBuilderAttribute` to name the same factory
type and method. The call's parameters must supply elements or supported sequences of elements,
not settings such as a comparer.

The rule requires C# 12 or later and an explicit destination type. Declarations using `var`,
factories without a matching collection builder, and arguments whose parameter type uses a method's
generic type parameter are excluded.

## Example

With .NET 8 or later, before:

```csharp
using System.Collections.Immutable;

public class Data
{
    public ImmutableArray<int> Values = ImmutableArray.Create(1, 2, 3);
}
```

After:

```csharp
using System.Collections.Immutable;

public class Data
{
    public ImmutableArray<int> Values = [1, 2, 3];
}
```

## How to fix violations

The code fix replaces the factory call with brackets. It writes individual arguments as elements,
an empty call as `[]`, and a single inline array initializer as its element list. For a supported
`CreateRange(source)` call, it writes `[.. source]`; `..` copies the elements from that sequence.
`CreateRange` is reported only if that exact method name is registered as the destination's builder.

For individual arguments, the fix joins them with a comma and a space and can drop comments around
the arguments. For an inline initializer, it keeps the text inside the braces. Comments on
the removed factory call can be lost. The destination type and `using` directives stay in place.

## Configuration

The default is `warning`. There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2103.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none` (disabled).
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the selected factory overload performs validation, copying, or other work that the
collection builder does not preserve. A collection expression can call a different overload.
Keep the factory call when measured allocation or copying behavior matters.
