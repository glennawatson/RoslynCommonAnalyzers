# SST2105 - Use the target collection expression directly

## Cause

A non-empty array initializer is followed immediately by LINQ's `ToList()` or `ToArray()`,
and the surrounding code supplies a target type. Write the elements directly as `[...]`.

This rule requires C# 12 or later. It does not report a `var` initializer, a conversion of an
existing array variable, or a call to a custom method with the same name. It also skips method
arguments whose collection type depends on the method's generic type parameters.

## Example

Before:

```csharp
using System.Collections.Generic;
using System.Linq;

public class Example
{
    private List<int> _values = new[] { 1, 2, 3 }.ToList();
}
```

After:

```csharp
using System.Collections.Generic;
using System.Linq;

public class Example
{
    private List<int> _values = [ 1, 2, 3 ];
}
```

## Code fix

The fix replaces the array creation and LINQ call with one collection expression.
It keeps the spacing and comments inside the initializer, including spaces inside the brackets.
Comments between the array and the LINQ call can be lost. It leaves `using System.Linq;` in place.

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2105.severity = error
```

There are no rule-specific options. Severity values are `error`, `warning`, `suggestion`,
`silent`, and `none`. See [configuration](../CONFIGURATION.md).

## When to suppress

Keep the explicit conversion when code depends on the concrete collection type. For example,
an interface target does not guarantee that `[...]` creates the same runtime type as `ToList()`.
Disable the rule if your project prefers explicit array and list creation.
