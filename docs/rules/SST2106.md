# SST2106 - Pass the capacity or comparer through a collection expression

## Cause

A `List<T>`, `HashSet<T>`, or `Dictionary<TKey, TValue>` is created with constructor arguments
that only set capacity or comparison rules. C# 15's `with(...)` element can pass those arguments
through a collection expression.

Only C# 15 or later is reported. An explicit creation such as `new List<int>(4)` must initialize
a local, field, or property with a written type. A creation such as `new(4)` already has a target
type and is also checked.

The rule skips `var` initializers, parameterless constructors, named arguments, arguments passed
by reference, and constructors that take initial contents. Other collection types are not reported.

## Example

Before:

```csharp
using System;
using System.Collections.Generic;

public class Example
{
    private static readonly HashSet<string> Names =
        new HashSet<string>(StringComparer.Ordinal) { "a" };
}
```

After, with C# 15:

```csharp
using System;
using System.Collections.Generic;

public class Example
{
    private static readonly HashSet<string> Names =
        [with(StringComparer.Ordinal), "a"];
}
```

## How to fix violations

Move the capacity or comparer arguments into a leading `with(...)` element. Keep every
initializer element after it. Do not drop the comparer: doing so can change which values
the collection treats as equal.

There is no code fix.

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2106.severity = error
```

There are no rule-specific options. Severity values are `error`, `warning`, `suggestion`,
`silent`, and `none`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the same source must compile with a compiler that does not support
`with(...)`, or when your project prefers constructor syntax for capacity and comparers.
