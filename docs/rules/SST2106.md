# SST2106 — Pass the capacity or comparer through a collection expression

| Item | Value |
| --- | --- |
| Category | CollectionExpressions |
| Severity | Warning |
| Code fix | No |
| Applies to | C# 15 or later |

## Cause

A `List<T>`, `HashSet<T>`, or `Dictionary<TKey, TValue>` is created with a capacity or a comparer
argument, where a collection expression carrying a `with(...)` element says the same thing.

```csharp
private static readonly HashSet<string> Names = new HashSet<string>(StringComparer.Ordinal) { "a", "b" };
```

## Rule description

A collection expression could not carry constructor arguments, so any collection that needed a
capacity or a comparer had to be written as an object creation and gave up the concise element
syntax. C# 15 adds a `with(...)` element that forwards its arguments to the underlying constructor,
so the configuration and the elements live in one expression:

```csharp
// 👍
private static readonly HashSet<string> Names = [with(StringComparer.Ordinal), "a", "b"];

List<int> values = [with(capacity: 4)];
```

The rule is gated on the compilation's language version being **C# 15 or later**, so it never fires
where `with(...)` would not compile.

## What is not reported

An argument that supplies the collection's *contents* rather than its configuration:

```csharp
List<int> values = new List<int>(source);
```

That rewrite is a spread element (`[.. source]`), not a `with(...)` element — a different shape, left
to the rules that cover seeding a collection from a source. Only `int` capacity parameters and
`IEqualityComparer<T>` / `IComparer<T>` parameters count as configuration.

Also not reported:

- A `var` target. A collection expression takes its type from its target, so there has to be a
  written target type for the rewrite to bind.
- A creation with no arguments — `[]` already covers that, under SST2100.
- A named or `ref`/`out`/`in` argument, which does not map cleanly onto a positional `with(...)`.
- Collections outside the three listed above.

## How to fix violations

Move the constructor arguments into a leading `with(...)` element and write the initializer elements
directly:

```csharp
new HashSet<string>(StringComparer.Ordinal) { "a" }   →   [with(StringComparer.Ordinal), "a"]
new List<int>(4)                                      →   [with(capacity: 4)]
new Dictionary<string, int>(StringComparer.Ordinal)   →   [with(StringComparer.Ordinal)]
```
