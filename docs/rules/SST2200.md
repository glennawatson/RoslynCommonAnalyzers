# SST2200 - Prefer the field keyword

## Cause

A private instance field is used only by one property, and at least one accessor does more than
read or assign that field. C# 14's `field` keyword lets the property keep that logic without a
separate field declaration.

This rule requires C# 14 or later. It skips partial types, static properties, explicit interface
implementations, shared fields, and fields with attributes or `volatile`. A field declared
alongside another field is also skipped. Plain read/write properties are covered by
[SST1420](SST1420.md).

## Example

Before:

```csharp
public class Example
{
    private int _value;

    public int Value
    {
        get => _value;
        set => _value = value < 0 ? 0 : value;
    }
}
```

After:

```csharp
public class Example
{
    public int Value
    {
        get => field;
        set => field = value < 0 ? 0 : value;
    }
}
```

## How to fix violations

The code fix replaces references to the backing field with `field`, including references
written as `this._value`. It removes the field declaration and moves any field initializer
to the property.

Comments attached to the removed field are not retained, and the fix removes the extra blank
line before the property. Move any useful field comments before applying it.
No fix is offered when directives such as `#region` separate members of the containing type.

## Configuration

Disabled by default. To enable it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2200.severity = error
```

There are no rule-specific options. Severity values are `error`, `warning`, `suggestion`,
`silent`, and `none`. See [configuration](../CONFIGURATION.md).

## When to suppress

Keep a named field when reflection or serialization depends on its name, or when your team
prefers explicit backing fields. Review initializer order before moving an initializer to a
property: its position among other initializers can affect behavior.
