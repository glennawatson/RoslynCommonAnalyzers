# SST2202 - Let the target type carry object creation

## Cause

An object creation repeats the exact type supplied by a declaration, assignment, return type,
or method parameter. C# 9's `new(...)` can use that target type.

The rule covers local and field declarations, property initializers, simple assignments, and
returns from methods, properties, accessors, and local functions. Method arguments are reported
only when the shorter form still calls the same method and creates the same type.

It skips `var` initializers, discard assignments, returns inside lambdas, constructor arguments,
arguments to calls made through `?.`, and arguments filling a `params` parameter.
A different target type, such as `object value = new Person();`, is not reported.
This rule requires C# 9 or later.

## Example

Before:

```csharp
using System.Collections.Generic;

public class Example
{
    private List<int> _values = new List<int>();
}
```

After:

```csharp
using System.Collections.Generic;

public class Example
{
    private List<int> _values = new();
}
```

## Code fix

The fix removes the type after `new`. It keeps the constructor arguments and any object or
collection initializer. Comments on the removed type or between `new` and the type can be lost.

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2202.severity = error
dotnet_diagnostic.SST2254.severity = none
```

[SST2254](SST2254.md) asks for the opposite style and is disabled by default. Enable only one
of these rules.

There are no rule-specific options. Severity values are `error`, `warning`, `suggestion`,
`silent`, and `none`. See [configuration](../CONFIGURATION.md).

## When to suppress

Keep the explicit type when the target type is far from the creation and naming it makes the
code easier to read. Disable this rule if your project prefers explicit construction types.
