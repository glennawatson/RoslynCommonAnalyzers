# SST2204 - Slice strings with range syntax

## Cause

A string local or parameter calls `Substring(start)` or `Substring(start, length)`.
Each argument must be a literal, local variable, or parameter.

This rule requires C# 8 or later. It skips strings read from fields or properties, and bounds
that contain calls or calculations such as `start + 1`.

## Example

Before:

```csharp
public class Example
{
    public string Tail(string text, int start) => text.Substring(start);

    public string Slice(string text, int start, int length) =>
        text.Substring(start, length);
}
```

After:

```csharp
public class Example
{
    public string Tail(string text, int start) => text[start..];

    public string Slice(string text, int start, int length) =>
        text[start..(start + length)];
}
```

A range's end is the position after the last character to include. It is not a character count.

## Code fix

The fix converts the one-argument call to `text[start..]`. For two arguments it creates
`text[start..(start + length)]`, repeating the start value to calculate the end position.
Comments inside the removed call can be lost.

Rewrite reordered named arguments by hand. The fix reads arguments in their written order,
so a call written with `length:` before `startIndex:` would produce the wrong bounds.

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2204.severity = error
```

There are no rule-specific options. Severity values are `error`, `warning`, `suggestion`,
`silent`, and `none`. See [configuration](../CONFIGURATION.md).

## When to suppress

Keep `Substring` when thinking in a start position and character count is clearer for the
algorithm, or when shared source must compile without range syntax.
