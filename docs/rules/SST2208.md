# SST2208 - Declare out variables at the call site

## Cause

A local variable is declared without an initializer and passed to exactly one `out` argument
in the next statement. Declare it in that argument to keep its type and first write together.

This rule requires C# 7 or later. It skips declarations with multiple variables, initializers,
or comments before or after the declaration. Calls inside lambdas are skipped. The rule also
leaves the declaration alone when moving it into a nested block or condition would prevent
later code from using the variable.

## Example

Before:

```csharp
public class Example
{
    public int Parse(string text)
    {
        int value;
        if (int.TryParse(text, out value))
        {
            return value;
        }

        return 0;
    }
}
```

After:

```csharp
public class Example
{
    public int Parse(string text)
    {
        if (int.TryParse(text, out var value))
        {
            return value;
        }

        return 0;
    }
}
```

## Code fix

The fix removes the separate declaration and changes the argument to `out var value`.
It replaces the written type with `var`. If an overloaded call needs the explicit type,
write an inline declaration such as `out int value` by hand.

Comments inside the removed declaration can be lost. No fix is offered when a directive
separates the declaration and the next statement.

## Configuration

Enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2208.severity = error
```

There are no rule-specific options. Severity values are `error`, `warning`, `suggestion`,
`silent`, and `none`. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a separate declaration makes the variable's lifetime or surrounding control
flow clearer. If only the explicit type matters, use an inline typed declaration instead.
