# SST2209 - Remove a no-op null-forgiving operator

The null-forgiving operator (`!`) tells the compiler to ignore nullable warnings for an
expression. Remove it when the value cannot be null and the operator has no effect.

## What is reported

The rule reports `!` on non-nullable value types such as `int`, new objects, non-null
literals, interpolated strings, `typeof(...)`, and `this`.

Arrays, pointers, tuples, and types with generic arguments are excluded, even when
created with `new`. Their elements or type arguments can have different nullable
annotations, and removing `!` can expose a warning about that difference.

Reference-type calls, properties, fields, locals, and parameters are left alone.
So are `null!`, `default!`, and `default(T)!`.

## Example

```csharp
class Example
{
    public int GetValue()
    {
        var value = 1;
        return value!;
    }
}
```

Use:

```csharp
class Example
{
    public int GetValue()
    {
        var value = 1;
        return value;
    }
}
```

## Code fix

The fix removes `!` and keeps the expression and its surrounding comments.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2209.severity = error
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`. There are no other
options. See [configuration](../CONFIGURATION.md).

## When to suppress

Keep the operator if removing it exposes a nullable warning that your code must
deliberately suppress. Otherwise, it adds no useful information.
