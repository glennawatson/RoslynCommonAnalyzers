# SST2210 - Remove repeated nullable state

The rule reports a `#nullable enable` or `#nullable disable` directive when the
preceding nullable directive has the same setting and target. The target can be
`warnings`, `annotations`, or omitted for both.

Other code can appear between the two directives. A different nullable directive,
including `#nullable restore`, breaks the repetition. The first directive in a file
is not reported merely because it matches the project setting.

## Example

```csharp
#nullable enable
#nullable enable

class Example { }
```

Use:

```csharp
#nullable enable

class Example { }
```

## Code fix

The fix deletes the repeated directive's whole line, including its line break and
any comment on that line. Move a comment you need to keep before accepting the fix.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2210.severity = error
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`. There are no other
options. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a repeated directive intentionally marks the start of a section
that is copied into other files and must carry its own nullable setting.
