# SST2213 - Remove no-op discard designation

A typed pattern does not need an explicit discard name. The type alone carries the same match and avoids
making the reader scan a binding that is never used.

## Example

```csharp
if (value is int _)
{
    return true;
}
```

Use:

```csharp
if (value is int)
{
    return true;
}
```

## Notes

The analyzer skips broad `var _` patterns, because removing the designation there would not leave a
useful type test behind.

It also skips a pattern whose type is a bare identifier that something other than a type answers to at
that point. A declaration pattern's name is always a type; a constant pattern's name is looked up as a
value first, so dropping the designation is not a no-op wherever a member shares the type's name.

```csharp
class A { }
class B { }

static class C
{
    public const A A = null;
    public static B B { get; set; }

    public static bool M(object o) => o is not A _;   // not reported
    public static bool N(object o) => o is not B _;   // not reported
}
```

Without the discard, `o is not A` compares against the constant `A` rather than testing the type, and
`o is not B` does not compile at all — a constant is expected. A keyword, a qualified name, or a generic
name cannot be captured this way and is still reported.
