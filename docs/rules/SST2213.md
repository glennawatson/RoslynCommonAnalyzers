# SST2213 - Remove no-op discard designation

A typed pattern such as `value is int _` tests the type and discards the matched
value. The rule reports the `_` because `value is int` performs the same test.

The rule leaves `var _` alone. It also leaves a type name alone when a variable or
member with that name is in scope: removing `_` could turn the type test into a
comparison with that value, or make the code fail to compile.

## Example

```csharp
class Example
{
    public bool IsInteger(object value) => value is int _;
}
```

Use:

```csharp
class Example
{
    public bool IsInteger(object value) => value is int;
}
```

## Code fix

The fix removes `_` from a direct test such as `value is int _`. It does not offer
a fix for patterns inside `not`, other combined patterns, or switch arms. Remove
the discard manually in those cases; type-only patterns there require C# 9 or later.
Comments attached to the discarded part can be lost.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2213.severity = error
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`. There are no other
options. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a switch pattern must retain `_` to compile with a C# version older
than 9, or when explicit discards make a set of related patterns easier to read.
