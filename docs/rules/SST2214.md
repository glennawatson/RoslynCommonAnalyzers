# SST2214 - Declare tuple parts directly

The rule reports a local holding a two-element tuple when the next two statements
copy its elements into separate locals, in tuple order. The tuple local must not
be used later in the block. Tuples with more elements are left alone.

Use deconstruction to declare both locals together. This requires C# 7 or later.

## Example

```csharp
class Example
{
    public string Describe()
    {
        var pair = GetPair();
        var name = pair.Name;
        var age = pair.Age;
        return name + age;
    }

    private static (string Name, int Age) GetPair() => ("Ada", 36);
}
```

Use:

```csharp
class Example
{
    public string Describe()
    {
        var (name, age) = GetPair();
        return name + age;
    }

    private static (string Name, int Age) GetPair() => ("Ada", 36);
}
```

## Code fix

The fix replaces the tuple declaration with `var (name, age) = ...;` and deletes
the two copied-local declarations. It keeps the local names and the original
tuple-producing expression. Comments on the deleted declarations can be lost.

The fix always uses `var`. If the copied locals have explicit types different
from the tuple element types, use a typed deconstruction to keep those conversions.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2214.severity = error
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`. There are no other
options. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when separate declarations carry useful explanations or make the code
easier to step through in a debugger.
