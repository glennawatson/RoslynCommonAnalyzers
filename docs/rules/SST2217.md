# SST2217 - Combine hash inputs with System.HashCode

The rule reports a returned hash expression inside a parameterless `int GetHashCode()`
method when it combines two to eight value-type inputs. The expression must call
`GetHashCode()` on each input and combine the results using multiplication by `31`
or `397`, followed by `+` or `^`.

Reference-type inputs and methods with other names are left alone. The rule reports
nothing when the project does not provide `System.HashCode.Combine`.

## Example

```csharp
class Person
{
    public int Id { get; set; }
    public int Age { get; set; }

    public override int GetHashCode() => (Id.GetHashCode() * 397) ^ Age.GetHashCode();
}
```

Use:

```csharp
class Person
{
    public int Id { get; set; }
    public int Age { get; set; }

    public override int GetHashCode() => System.HashCode.Combine(Id, Age);
}
```

## Code fix

The fix replaces the arithmetic and individual `GetHashCode()` calls with
`System.HashCode.Combine(...)`, passing the input values in their original order.
Comments within the removed arithmetic can be lost.

This changes the returned hash numbers. `System.HashCode` also uses a random seed,
so results can differ between program runs. Do not use these results as stored
identifiers or values exchanged with another process.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2217.severity = error
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`. There are no other
options. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when callers depend on the exact hash algorithm, or when measurements
justify keeping a custom implementation. Shared source targeting a framework
without `System.HashCode.Combine` may also need to keep the arithmetic.
