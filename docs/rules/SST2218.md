# SST2218 - Let lambda parameter types come from the target

The rule reports a lambda whose parameters all have explicit types that can come
from the receiving delegate or expression-tree type. For example, a
`Func<int, int, int>` already supplies the types for two integer parameters.

Parameters with modifiers such as `ref`, attributes, or default values are left
alone. Types needed to select a method overload or infer a generic type argument
are also kept.

## Example

```csharp
using System;

class Example
{
    public Func<int, int, int> Add = (int left, int right) => left + right;
}
```

Use:

```csharp
using System;

class Example
{
    public Func<int, int, int> Add = (left, right) => left + right;
}
```

## Code fix

The fix removes every parameter type and keeps the parameter names, parentheses,
and lambda body. It keeps parentheses even for a single parameter. Comments attached
to removed type names can be lost.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2218.severity = error
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`. There are no other
options. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when explicit types help readers understand a long lambda or a target
type declared far from the lambda.
