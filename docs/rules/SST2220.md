# SST2220 - Let interpolation format the value

The rule reports a `ToString()` call that is the whole expression inside an
interpolated string's braces. A call with one non-empty string literal argument,
such as `value.ToString("X")`, is also reported.

Calls with a format provider, computed formats, empty format strings, or more
than one argument are left alone. Calls on `ref struct` values are excluded.

## Example

```csharp
class Example
{
    public string Format(int value) => $"Value: {value.ToString("X")}";
}
```

Use:

```csharp
class Example
{
    public string Format(int value) => $"Value: {value:X}";
}
```

## Code fix

The fix removes `ToString()`, leaving the value inside the braces. For a literal
format argument, it moves the text after `:`. Alignment, such as `,10`, is kept.
Any existing interpolation format is replaced by the call's format, or removed
when the call has no argument. Comments inside the removed call can be lost.

Check formats containing quotes, backslashes, braces, or line breaks before
accepting the fix. The fix copies the format text without escaping it for the
surrounding string.

## Configuration

Enabled by default as a warning. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2220.severity = error
```

Values: `error`, `warning`, `suggestion`, `silent`, or `none`. There are no other
options. See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when calling `ToString` directly has required behavior. For example, a
direct call on a null reference throws, while ordinary string interpolation writes
empty text. A custom type's formatting methods or a custom string formatter can
also produce different text when they receive the value instead of its string.
