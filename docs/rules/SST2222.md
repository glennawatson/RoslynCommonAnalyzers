# SST2222 - Remove value overwritten before use

## Cause

A value is replaced by the next assignment in the same block, before that assignment
reads it. The first value must be a literal, `default`, or a local or parameter read.
Calls and object creations on the right side are skipped.

The rule checks local declarations with one explicitly typed variable, and
assignments to a bare name such as `value`. It skips `var` initializers and discard
assignments.

It also reports `return value++;`, `return value--;`, `value = value++;`, and
`value = value--;` for ordinary local variables with built-in operators. The return
forms return the old value; the assignment forms put the old value back.

## Example

Before:

```csharp
class C
{
    public int GetValue()
    {
        int value = 0;
        value = 1;
        return value;
    }
}
```

After:

```csharp
class C
{
    public int GetValue()
    {
        int value;
        value = 1;
        return value;
    }
}
```

## What is not reported

The increment and decrement cases skip `ref` locals, custom operators, `decimal`
values, and arithmetic in a checked context. An explicit `unchecked` block allows
the rule even when overflow checking is enabled for the project.

The return cases also skip fields, parameters, array elements, top-level returns,
and returns inside `try` statements. A local is left alone if another lambda or
local function can read it, if its reference or address is taken, or if it belongs
to an enclosing function.

## Code fix

**Remove overwritten value** removes the initializer but keeps the declaration,
as above. For an overwritten assignment or `value = value++;`, it removes the
whole statement. For `return value++;` or `return value--;`, it removes only the
increment or decrement.

Comments attached to a removed initializer or statement are lost. Move any comment
you need before accepting the fix.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report it
as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2222.severity = error
```

Use `none` to disable the rule, or choose `silent`, `suggestion`, `warning`, or
`error`.

## When to suppress

Review the first write before removing it. Suppress if it calls a property setter
or a type conversion with required effects. If the write is a mistake, fix the
intended value instead of suppressing the diagnostic.
