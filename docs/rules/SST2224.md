# SST2224 - Use tuple syntax for local value bundles

## Cause

An anonymous object initializes a local variable and has at least two named values.
Every use of that local accesses a member by name. A tuple can hold those values
with less syntax.

This rule requires C# 7 or later and is disabled by default. It skips anonymous
objects returned directly, locals returned as a whole, and locals passed to another
method, including a serializer. Single-member anonymous objects are also skipped.

## Example

Before:

```csharp
class C
{
    public int Measure(int id, string name)
    {
        var bundle = new { id, Label = name };
        return bundle.id + bundle.Label.Length;
    }
}
```

After:

```csharp
class C
{
    public int Measure(int id, string name)
    {
        var bundle = (id, Label: name);
        return bundle.id + bundle.Label.Length;
    }
}
```

## Code fix

**Use tuple literal** replaces `new { ... }` with `( ... )`. An explicit member
name such as `Label = name` becomes `Label: name`; an inferred name such as `id`
stays inferred. The fix keeps the value expressions and their order. Comments
around the removed braces, names, and separators can be lost.

The resulting value has a different type. Tuple members are fields, and tools that
inspect them at run time see names such as `Item1` and `Item2`. Equality and
`ToString()` results can also differ from those of an anonymous object.

## Configuration

Disabled by default. Its default severity is warning when enabled. There are no
rule-specific options. To enable it as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2224.severity = error
```

Use `none` to disable the rule, or choose `silent`, `suggestion`, `warning`, or
`error`.

## When to suppress

Leave the rule disabled if your team prefers anonymous objects. Suppress a reported
case when code depends on the anonymous object's type, equality, or text output.
