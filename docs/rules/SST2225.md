# SST2225 - Show foreach element casts at the source

## Cause

A `foreach` loop uses a variable type that requires an explicit conversion from
the collection's element type. For example, reading `object[]` as `string` checks
each element's type at run time. Put that cast in the source expression to make it
visible.

The rule checks arrays and collections with a known element type. It skips
conversions that need no cast and old non-generic collections that expose only
`object` elements.

## Example

Before:

```csharp
class C
{
    public void Read(object[] values)
    {
        foreach (string value in values)
        {
            System.Console.WriteLine(value);
        }
    }
}
```

After:

```csharp
class C
{
    public void Read(object[] values)
    {
        foreach (string value in System.Linq.Enumerable.Cast<string>(values))
        {
            System.Console.WriteLine(value);
        }
    }
}
```

## Code fix

**Cast foreach source explicitly** wraps the source in
`System.Linq.Enumerable.Cast<T>(source)`, where `T` is the loop variable's type.
It keeps the variable declaration and loop body. It adds no `using` directive.

The fix needs LINQ and a source that implements `System.Collections.IEnumerable`.
`Cast<T>` checks element types; it does not perform numeric or custom conversions.
For those conversions, keep the original loop or write the conversion inside its
body. An element of the wrong type can still throw an `InvalidCastException`.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report it
as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2225.severity = error
```

Use `none` to disable the rule, or choose `silent`, `suggestion`, `warning`, or
`error`.

## When to suppress

Suppress when the loop needs a numeric or custom conversion, or its collection
cannot be passed to `Enumerable.Cast<T>`. Suppress when measurements show that the
extra LINQ call costs too much in frequently run code.
