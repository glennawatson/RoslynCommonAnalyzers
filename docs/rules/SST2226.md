# SST2226 - Show the inner explicit conversion

## Cause

A cast performs an extra conversion that is not written in the code. This can
happen when a custom conversion produces a base class before the result is cast
to a derived class. Write both casts so readers can see the steps.

Ordinary casts that perform only the written conversion are not reported.

## Example

Before:

```csharp
class Base { }
class Derived : Base { }

class Castable
{
    public static explicit operator Base(Castable value) => new Derived();
}

class C
{
    public Derived Convert(Castable value) => (Derived)value;
}
```

After:

```csharp
class Base { }
class Derived : Base { }

class Castable
{
    public static explicit operator Base(Castable value) => new Derived();
}

class C
{
    public Derived Convert(Castable value) => (Derived)(Base)value;
}
```

## Code fix

**Add inner cast** inserts the missing type cast inside the existing cast. It
keeps the outer cast and value expression. Comments directly before or after the
value inside the outer cast can be lost.

The added cast does not prevent a failed conversion. In this example, the final
cast still fails if the custom conversion returns a `Base` that is not a `Derived`.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report it
as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2226.severity = error
```

Use `none` to disable the rule, or choose `silent`, `suggestion`, `warning`, or
`error`.

## When to suppress

Suppress when the conversion path is familiar to the team and spelling out the
intermediate type makes the code harder to read.
