# SST2231 - State null checks directly

## Cause

Code uses `value is object` to check that a reference is not null. Use
`value is not null` to say what is being tested. A negated object pattern can use
`value is null`.

This rule requires C# 9 or later. It checks reference types and generic type
parameters, and skips other value types. It checks the `object` keyword, not the
qualified spelling `System.Object`.

Object patterns that declare a variable or test members can also be reported.
These need manual review because they do more than check for null.

## Example

Before:

```csharp
class C
{
    public bool HasValue(object value) => value is object;
}
```

After:

```csharp
class C
{
    public bool HasValue(object value) => value is not null;
}
```

## Code fix

**Use a direct null pattern** replaces the object test with `is not null`, or a
negated object pattern with `is null`.

The fix replaces the whole pattern. It removes any variable declaration, member
tests, and comments inside that pattern. If those parts are needed, keep them or
rewrite the test manually.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report it
as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2231.severity = error
```

Use `none` to disable the rule, or choose `silent`, `suggestion`, `warning`, or
`error`.

## When to suppress

Suppress when an object pattern introduces a variable you use or includes member
tests you need. Suppress a plain null check only when the team deliberately prefers
the `is object` spelling.
