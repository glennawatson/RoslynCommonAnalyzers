# SST2235 - Make capture-free local functions static

## Cause

A local function is not `static` and does not use variables, parameters, or instance
state from the enclosing code. Add `static` to prevent later edits from making it
depend on that state.

This rule requires C# 8 or later. It covers both expression and block bodies,
including functions that call themselves. It skips functions already marked
`static` and functions that use outer state through a nested lambda or local
function.

## Example

Before:

```csharp
class C
{
    public int Run(int value)
    {
        int Twice(int input) => input * 2;
        return Twice(value);
    }
}
```

After:

```csharp
class C
{
    public int Run(int value)
    {
        static int Twice(int input) => input * 2;
        return Twice(value);
    }
}
```

## How to fix violations

Add `static` before the local function's return type. There is no code fix.

## Configuration

Enabled by default as a warning. There are no rule-specific options. To report it
as an error:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2235.severity = error
```

Use `none` to disable the rule, or choose `silent`, `suggestion`, `warning`, or
`error`.

See [docs/CONFIGURATION.md](../CONFIGURATION.md).

## When to suppress

Suppress when the same source must compile with C# 7, or when the team deliberately
keeps local functions in a consistent non-static style. Also suppress if adding
`static` would prevent a required call to another non-static local function.
