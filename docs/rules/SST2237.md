# SST2237 - Use the configured namespace declaration form

**Category:** ModernSyntax
**Severity:** Warning
**Code fix:** None

A file with one namespace and no sibling declarations can be written either way. A codebase reads
better when every file picks the same one, so this rule reports the files that disagree with the
form the project has chosen.

The default is `file_scoped`, which keeps the namespace at the top of the file and removes one
indentation level from every contained member.

## Example

With the default `file_scoped`:

```csharp
namespace App.Services // SST2237
{
    internal sealed class Worker;
}
```

Use:

```csharp
namespace App.Services;

internal sealed class Worker;
```

With `namespace_declaration_style = block_scoped`, the two are reversed and the file-scoped
declaration is the one reported.

## Configuration

```ini
[*.cs]
# Rule-specific
stylesharp.SST2237.namespace_declaration_style = file_scoped

# Project-wide
stylesharp.namespace_declaration_style = file_scoped
```

| Option | Values | Default | Effect |
| --- | --- | --- | --- |
| `namespace_declaration_style` | `file_scoped`, `block_scoped` | `file_scoped` | Which namespace form a file with a single namespace should use. |

An unset or unrecognized value falls back to `file_scoped`.

## One rule, both directions

The two forms are held by one setting rather than by a rule per form, and that is deliberate. Two
rules — one demanding each form — can both be switched on, and then no file satisfies either:
converting to one form immediately trips the other, and no code fix can resolve it. A single setting
cannot contradict itself.

## What is not reported

A file declaring more than one namespace, or a namespace with sibling declarations beside it, since
neither can be file-scoped. A file-scoped namespace is only reported when the block-scoped form has
been configured.

## Performance

The block-scoped path applies its syntactic gate first — the declaration has to be the compilation
unit's only member — so the configured form is only read for a declaration that could actually be
rewritten. The file-scoped path has no such gate, because any file-scoped namespace is convertible;
it costs one option read per file, which allocates nothing while the setting is unset.

Measured on the `FileScopedNamespaceBenchmarks` corpus, adding the second direction left both the
clean and violating paths unchanged: 20191 KB allocated for the 3000-node clean case against a
20200 KB baseline, within the harness's own run-to-run spread.
