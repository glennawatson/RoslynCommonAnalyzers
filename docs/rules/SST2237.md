# SST2237 - Use the configured namespace declaration form

**Category:** ModernSyntax  
**Default severity:** Warning (enabled)  
**Code fix:** None

## Cause

A namespace uses a different form from the configured style. The default is
`file_scoped`: a namespace ending in `;` instead of enclosing the file's types in braces.

A block namespace is reported only in C# 10 or later and only when it is the file's
sole top-level declaration. Using directives may appear beside it. Files with sibling
namespaces or types are left alone. With `block_scoped` configured, a file-scoped
namespace is reported instead.

## Example

Before, with the default style:

```csharp
namespace App.Services
{
    public sealed class Worker
    {
    }
}
```

After:

```csharp
namespace App.Services;

public sealed class Worker
{
}
```

With `block_scoped` configured, reverse this change.

## How to fix violations

There is no code fix. Change the namespace declaration to the configured form and
adjust the indentation of its contents.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST2237.severity = error
stylesharp.namespace_declaration_style = file_scoped
stylesharp.SST2237.namespace_declaration_style = file_scoped
```

Both style keys accept `file_scoped` and `block_scoped`. The rule-specific key overrides
the project-wide key. If neither is set, or the selected value is unrecognized, the
style is `file_scoped`. Values ignore case and surrounding spaces.

The default severity is `warning`. Values are `error`, `warning`, `suggestion`,
`silent`, and `none` (disabled). See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress for a file shared with a project that requires the other form, or when the
file must keep the layout of an external template. For a project-wide preference,
set the style instead.
