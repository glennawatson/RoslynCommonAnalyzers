# SST2238 - Flatten nested property patterns

**Category:** ModernSyntax  
**Default severity:** Warning (enabled)  
**Code fix:** Yes (supports Fix All)

## Cause

In C# 10 or later, a property pattern contains another pattern with one named property
test, such as `Address: { City: "Melbourne" }`. A dotted path expresses the same check
with fewer braces. Both forms fail to match when `Address` is null.

A nested pattern is left alone if it tests a type, declares a variable, uses positional
matching, or contains more than one property test.

## Example

Before:

```csharp
public class Person
{
    public Address Address { get; set; } = new();
    public bool IsLocal() => this is { Address: { City: "Melbourne" } };
}

public class Address
{
    public string City { get; set; } = "";
}
```

After:

```csharp
public class Person
{
    public Address Address { get; set; } = new();
    public bool IsLocal() => this is { Address.City: "Melbourne" };
}

public class Address
{
    public string City { get; set; } = "";
}
```

## Code fix

**Flatten the property pattern** joins the two property names with a dot and removes
the inner braces. It keeps the final test. Comments around the removed braces, names,
or colons can be lost; move useful comments outside the pattern before applying it.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST2238.severity = error
```

The default severity is `warning`. Values are `error`, `warning`, `suggestion`,
`silent`, and `none` (disabled). There are no rule-specific options.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when nested braces make a long pattern easier to read or keep related tests
visually grouped.
