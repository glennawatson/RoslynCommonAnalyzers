# SST2239 - Use method groups for forwarding lambdas

**Category:** ModernSyntax  
**Default severity:** Warning (enabled)  
**Code fix:** Yes (supports Fix All)

## Cause

A lambda only passes its parameters, unchanged and in order, to one method call.
It can use a method group: a method name supplied as a delegate, such as `Square`.

The rule requires at least one parameter and a call written directly after `=>`.
It skips block bodies, named or `ref` arguments, omitted optional arguments, and calls
that pack separate arguments into a `params` array or collection. It also skips
expression trees, incompatible parameter or return types, and lambdas that discard a
method's return value.

When the lambda is an argument to another method call, the replacement must select
the same overload. Calls reached through `?.` are left alone.

## Example

Before:

```csharp
using System;

public class Example
{
    public Func<int, int> Create() => value => Square(value);

    private static int Square(int value) => value * value;
}
```

After:

```csharp
using System;

public class Example
{
    public Func<int, int> Create() => Square;

    private static int Square(int value) => value * value;
}
```

## Code fix

**Use the method group** replaces the lambda with the called method's name, including
its object when present: `(a, b) => formatter.Combine(a, b)` becomes `formatter.Combine`.
The lambda's parameter list, `=>`, and call arguments are removed. Comments within
those removed parts are lost; comments surrounding the lambda are kept.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST2239.severity = error
```

The default severity is `warning`. Values are `error`, `warning`, `suggestion`,
`silent`, and `none` (disabled). There are no rule-specific options.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the parameter names explain the operation better than the method name.
Also keep a lambda when its target object must be read afresh on every call: a method
group captures the object when the delegate is created, which matters if that object
reference can change or its getter does work.
