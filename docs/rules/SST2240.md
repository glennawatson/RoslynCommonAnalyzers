# SST2240 - Use conditional delegate invocation

**Category:** ModernSyntax  
**Default severity:** Warning (enabled)  
**Code fix:** None

## Cause

An `if` checks a delegate for null and its only statement calls that delegate, either
directly or through `.Invoke(...)`. The `if` must have no `else`. Supported checks are
`callback != null`, `null != callback`, and `callback is not null`.

In C# 6 or later, `?.Invoke(...)` performs the null check and call together. It reads
the delegate once. Checks with extra conditions or extra body statements are not reported.

## Example

Before:

```csharp
using System;

public class Example
{
    public void Notify(Action callback)
    {
        if (callback != null)
        {
            callback();
        }
    }
}
```

After:

```csharp
using System;

public class Example
{
    public void Notify(Action callback)
    {
        callback?.Invoke();
    }
}
```

## How to fix violations

There is no code fix. Replace the guard and call with `?.Invoke(...)`, keeping the
original arguments. Move any useful comments out of the removed guard.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST2240.severity = error
```

The default severity is `warning`. Values are `error`, `warning`, `suggestion`,
`silent`, and `none` (disabled). There are no rule-specific options.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an explicit guard improves readability, or when the delegate comes from
a property whose repeated reads have required effects. Conditional invocation reads
that property only once.
