# SST2241 - Move simple constructor storage to the type declaration

**Category:** ModernSyntax  
**Default severity:** Warning (enabled)  
**Code fix:** Yes, for supported storage members (supports Fix All)

## Cause

In C# 12 or later, a class or struct constructor only copies each parameter once into
an instance field or a property with a setter. A primary constructor puts the parameters
after the type name and lets member initializers store them.

The type must have only one explicitly declared instance constructor. That constructor
must be `public`, or `protected` on an abstract class. Records, types that already have
a primary constructor, parameterless constructors, and constructors that validate or
transform inputs are left alone. A `base(...)` call is allowed; a `this(...)` call with
arguments is not.

## Example

Before:

```csharp
public sealed class Example
{
    private readonly int _value;

    public Example(int value)
    {
        _value = value;
    }
}
```

After:

```csharp
public sealed class Example(int value)
{
    private readonly int _value = value;
}
```

## Code fix

**Move storage to primary constructor** moves the parameter list to the type, adds
field or auto-property initializers, and removes the constructor. It carries arguments
from `base(...)` to the base type declaration.

The fix requires the assigned fields and auto-properties to be in the same type
declaration and to have no existing initializers. It is not offered for custom setters,
conflicting parameter names in the type body, or preprocessor directives between members.

Single-line `<param>` documentation moves to the type. The constructor's summary,
other documentation, attributes, and body comments are removed. Multi-line parameter
documentation needs manual review.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST2241.severity = error
```

The default severity is `warning`. Values are `error`, `warning`, `suggestion`,
`silent`, and `none` (disabled). There are no rule-specific options.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when constructor attributes or documentation must stay on an explicit
constructor, or when a property's setter performs required work. Keep the constructor
if moving its assignments into member initializers would change required initialization
order, including work performed by the base constructor.
