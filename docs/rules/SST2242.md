# SST2242 - Complete enum switch statement mappings

**Category:** ModernSyntax
**Severity:** Warning
**Code fix:** Yes - *Add missing enum cases* / *Add a catch-all section*

A switch statement that maps enum values should either name every enum member or
include an intentional catch-all section. Missing values make enum growth and
forgotten cases hard to audit.

This is narrower than broad switch-statement coverage: a `default` section is
treated as intentional, and empty fall-through-shaped sections are skipped.

## Example

```csharp
switch (color) // SST2242 when Color.Blue is missing
{
    case Color.Red:
        return 1;
}
```

Add the missing enum cases or an intentional `default` section.

## Code fix

The omitted values are stacked onto one section, written the way the file itself names them:

```csharp
switch (color)
{
    case Color.Red:
        return 1;
    case Color.Blue:
    case Color.Green:
        break;
}
```

A `default: break;` section is offered instead when naming the values would not complete the
mapping:

- The enum is declared outside the assembly, where naming every value is hundreds of dead sections.
- A value is named only under a `when` guard, so a second unguarded label for it reads as a
  duplicate of the one already there.
