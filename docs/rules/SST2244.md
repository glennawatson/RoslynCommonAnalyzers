# SST2244 - Numeric literal suffixes should be upper case

**Category:** ModernSyntax  
**Default severity:** Warning (enabled)  
**Code fix:** Yes (supports Fix All)

## Cause

A numeric literal has a lower-case letter in its type suffix: `l`, `u`, `f`, `d`, or
`m`. Combined and mixed-case suffixes, such as `ul` or `Lu`, are included. Upper-case
`L` is easier to tell apart from the digit `1`; using upper case for all suffixes
keeps the style consistent.

## Example

Before:

```csharp
long ticks = 1l;
ulong mask = 1ul;
float ratio = 1.5f;
decimal price = 1m;
```

After:

```csharp
long ticks = 1L;
ulong mask = 1UL;
float ratio = 1.5F;
decimal price = 1M;
```

## How to fix violations

**Upper-case the literal suffix** changes every suffix letter to upper case. It keeps
the digits, separators, exponent, base prefix, and surrounding comments. For example,
`0xffl` becomes `0xffL`, and `1Lu` becomes `1LU`.

Hexadecimal digits are not suffixes: `0xff` and `0xffd` are left alone. The change is
valid in every C# version that supports the original literal.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST2244.severity = error
```

The default severity is `warning`. Values are `error`, `warning`, `suggestion`,
`silent`, and `none` (disabled). There is no option to enforce only the `L` suffix.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a file must match an external sample exactly or your project deliberately
uses lower-case suffixes. Suffix casing does not change the number's value or type.
