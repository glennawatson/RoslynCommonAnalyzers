# SST2246 - Express a same-value conditional chain as a switch

**Category:** ModernSyntax  
**Default severity:** Warning (enabled)  
**Code fix:** Yes (supports Fix All)

## Cause

In C# 8 or later, at least two nested `?:` tests compare the same value with distinct
constants using `value == constant`. A switch expression lists each constant beside
its result and writes the tested value once.

The value must be a local, parameter, or non-constant field written as a plain name.
Its type must be an enum, an integer type from `sbyte` through `ulong`, `char`, or
`string`. Properties, method calls, floating-point values, and types with custom
equality are left alone.

Single tests, repeated constants, and chains testing different values are not reported.
The replacement must produce a value usable in the same place as the original chain.

## Example

Before:

```csharp
public class Example
{
    public string Describe(int value)
    {
        return value == 1 ? "one" : value == 2 ? "two" : "other";
    }
}
```

After:

```csharp
public class Example
{
    public string Describe(int value)
    {
        return value switch
        {
            1 => "one",
            2 => "two",
            _ => "other"
        };
    }
}
```

## How to fix violations

**Rewrite the conditional chain as a switch expression** keeps each constant and
result, adds `_` for the final fallback, and formats the switch across multiple lines.
Comments before and after the whole expression are kept. Comments between tests and
results can be lost because the comparison and conditional operators are removed.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST2246.severity = error
```

The default severity is `warning`. Values are `error`, `warning`, `suggestion`,
`silent`, and `none` (disabled). There are no rule-specific options.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a short conditional chain reads more clearly in its context. Also keep
the chain if repeated reads of a field are intentional: the switch reads it once,
which matters when another thread can change it.
