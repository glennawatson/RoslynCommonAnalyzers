# SST2247 - Deconstruct a value instead of copying its members

**Category:** ModernSyntax  
**Default severity:** Warning (enabled)  
**Code fix:** Yes (supports Fix All)

## Cause

In C# 7 or later, two or more consecutive `var` declarations copy members from the
same local or parameter. Deconstruction assigns those parts to several locals in one
statement, such as `var (a, b) = pair;`.

For tuples, the declarations must read every element in order. Named elements and
`Item1`, `Item2`, and later positions are supported. For other types, there must be
one matching public instance `void Deconstruct` method with an `out` parameter for
each copy. Each member name must match the corresponding parameter name, ignoring case.
Extension methods are not considered.

Partial or reordered tuple copies, explicitly typed locals, and sources that are
fields or properties are left alone. A source declared in the statement immediately
before the copies is also left alone.

## Example

Before:

```csharp
public class Example
{
    public int Sum((int, int) pair)
    {
        var a = pair.Item1;
        var b = pair.Item2;
        return a + b;
    }
}
```

After:

```csharp
public class Example
{
    public int Sum((int, int) pair)
    {
        var (a, b) = pair;
        return a + b;
    }
}
```

## How to fix violations

**Fold the member copies into a deconstruction** replaces the declarations with one
`var (...) = source;` statement, retaining the local names. The source variable stays
available for later code.

The fix keeps comments before the first declaration and after the last declaration.
Comments inside or between the removed declarations are lost. Move useful comments
outside the group before applying the fix.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.SST2247.severity = error
```

The default severity is `warning`. Values are `error`, `warning`, `suggestion`,
`silent`, and `none` (disabled). There are no rule-specific options.
See [configuration](../CONFIGURATION.md).

## When to suppress

Suppress when separate member names make the code easier to read. For a custom
`Deconstruct` method, check that it returns the same values and types as the copied
members and performs no extra work you need to avoid. Matching names alone do not
guarantee matching behavior.
