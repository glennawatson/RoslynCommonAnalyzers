# SST2248 — Combine comparisons into a pattern

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Default severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

Two comparisons test the same variable against constants and can be combined into one
`is` pattern. The rule requires C# 9 or later and reports these forms:

- A lower and an upper bound joined by `&&`.
- Two `==` comparisons joined by `||`, or two `!=` comparisons joined by `&&`.
- Two bounds joined by `||` that test for values outside a range.

The variable must be a local, parameter or field named without a qualifier such as `this.`.
Its type must be `sbyte`, `byte`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`, `char`
or an enum. Properties, calls, nullable types and comparisons against other variables are
left alone. Each constant must fit the variable's type without a cast.

The rule skips empty ranges such as `x >= 9 && x <= 0`, always-true combinations such
as `x >= 0 || x <= 9`, and other forms such as `x == 1 && x == 2`.

## Example

Before:

```csharp
public class Checks
{
    public bool InRange(int x) => x >= 0 && x <= 9;
    public bool OutsideRange(int n) => n < 0 || n > 100;
    public bool Allowed(int x) => x != 3 && x != 5;
}
```

After:

```csharp
public class Checks
{
    public bool InRange(int x) => x is >= 0 and <= 9;
    public bool OutsideRange(int n) => n is < 0 or > 100;
    public bool Allowed(int x) => x is not 3 and not 5;
}
```

## How to fix violations

The code fix replaces the two comparisons with one `is` pattern. It changes `&&` to
`and`, `||` to `or`, and `!=` to `not`. It also reverses comparisons written with the
constant first: `0 <= x` becomes `x is >= 0`.

The fix puts spaces around the pattern keywords and keeps comments outside the whole
expression. Comments between the comparisons or beside their operators can be lost;
move them before applying the fix.

## Configuration

To report violations as errors, set:

```ini
[*.cs]
dotnet_diagnostic.SST2248.severity = error
```

There are no rule-specific options.

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. The default is `warning`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when separate comparisons make a mathematical condition easier to review, or when
reading a field once would change code that depends on separate reads.
