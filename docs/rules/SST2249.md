# SST2249 — Use an interpolated string

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Default severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

Text can be written as an interpolated string, with each value inside `{}` where it
appears in the text. The rule requires C# 6 or later and reports:

- `string.Format` with a regular string literal and each value used exactly once.
- A `+` chain that mixes string literals and values, where each `+` joins strings.
- `string.Concat` with at least one string literal, using an overload whose parameters
  are all individual strings.

## Example

Before:

```csharp
public class Messages
{
    public string Pair(string a, string b) => string.Format("{0} {1}", a, b);
    public string Greet(string name) => "Hello " + name + "!";
    public string Prefix(string value) => string.Concat("prefix", value);
}
```

After:

```csharp
public class Messages
{
    public string Pair(string a, string b) => $"{a} {b}";
    public string Greet(string name) => $"Hello {name}!";
    public string Prefix(string value) => $"prefix{value}";
}
```

## What is not reported

The rule leaves these cases alone:

- `string.Format` with a format provider, named arguments, a format stored in a variable,
  repeated or missing placeholder indexes, or a single array supplied as the values.
- Verbatim or raw string literals, and format strings with unsupported or invalid formatting.
- A `+` chain with no string literal, or with numeric addition such as `1 + 2 + " items"`.
- `string.Concat` calls that take objects, arrays or sequences, or have no string literal.
- Message templates passed to `Microsoft.Extensions.Logging.LoggerExtensions` methods.
  Values passed as separate logging arguments can still be reported.
- A replacement line that would exceed the limit enforced by [SST1521](SST1521.md).

## How to fix violations

The code fix replaces the call or `+` chain with a regular `$"..."` string. It keeps
alignment widths, format specifiers and escaped braces. For example, `"{0, 5:X}"`
becomes `$"{value,5:X}"`. It adds parentheses around conditional values when needed.

A wrapped chain becomes one string, so its line layout changes. Comments beside removed
arguments or `+` operators can be lost; move them before accepting the fix.

Placeholders determine the order of values in the replacement. For example,
`string.Format("{1}-{0}", a, b)` becomes `$"{b}-{a}"`. If the arguments are calls or
properties whose evaluation order matters, store their results in locals first.

## Configuration

To report violations as errors, set:

```ini
[*.cs]
dotnet_diagnostic.SST2249.severity = error
```

There are no options specific to this rule. The following line-length settings also affect
whether a replacement is offered:

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.max_line_length` | Positive integer | `120` |
| `stylesharp.SST1521.max_line_length` | Positive integer; overrides the general key | Falls back to the general key |

Invalid or non-positive values fall back to the next setting, then to `120`. The limit
includes text before and after the replacement on its line. Setting
`dotnet_diagnostic.SST1521.severity = none` removes this limit from the suggestion.

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. The default is `warning`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when a format string needs to match an external template, or when interpolation
would change evaluation order or custom formatting that the code relies on.
