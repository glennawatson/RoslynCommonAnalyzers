# SST2251 — Let inference supply the type arguments

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Default severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

A generic method call writes type arguments, such as `<int>`, that the compiler can work
out from the supplied values. Removing them must select the same method with the same
types, including nullable reference annotations such as `object?`.

The rule leaves required type arguments alone. It also skips calls where removal would
choose a different overload or type, calls through `?.` or `?[]`, and type arguments
that belong to a class rather than the called method.

## Example

Before:

```csharp
public class C
{
    public T Echo<T>(T value) => value;
    public int Use() => Echo<int>(42);
}
```

After:

```csharp
public class C
{
    public T Echo<T>(T value) => value;
    public int Use() => Echo(42);
}
```

## How to fix violations

The code fix removes only the called method's `<...>` list. It keeps the method name,
the object or type before it, and the value arguments. Comments inside the removed
list are lost; move them before applying the fix.

## Configuration

To report violations as errors, set:

```ini
[*.cs]
dotnet_diagnostic.SST2251.severity = error
```

There are no rule-specific options.

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. The default is `warning`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when the explicit types explain the call to readers better than the arguments
alone, or when they deliberately fix the types against future changes to those arguments.
