# SST2252 — Avoid nesting switch statements

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `switch` statement is inside another `switch` statement. The diagnostic marks the
inner `switch`, including one inside an intervening `if`, loop or block. With three
nested switches, both the middle and innermost switches are reported.

Switch expressions and switches placed one after another are not reported. A switch
inside a lambda, anonymous method or local function is considered part of that function,
even when the function is declared inside an outer switch.

## Example

Before:

```csharp
public class C
{
    public int Pick(int outer, int inner)
    {
        switch (outer)
        {
            case 1:
                switch (inner)
                {
                    case 10: return 100;
                    default: return 0;
                }
            default: return -1;
        }
    }
}
```

After extracting the inner decision:

```csharp
public class C
{
    public int Pick(int outer, int inner)
    {
        switch (outer)
        {
            case 1: return PickInner(inner);
            default: return -1;
        }
    }

    private int PickInner(int value)
    {
        switch (value)
        {
            case 10: return 100;
            default: return 0;
        }
    }
}
```

## How to fix violations

There is no code fix.

Move the inner switch into a method with a name that explains the decision. If all
branches return values, a switch expression can also make the decision shorter; it
requires C# 8 or later. Preserve the existing order of work and the meaning of each
`break`, `return` and `goto` when rewriting branches.

## Configuration

To report violations as errors, set:

```ini
[*.cs]
dotnet_diagnostic.SST2252.severity = error
```

There are no rule-specific options.

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. The default is `warning`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when nested switches are the clearest way to express a small decision table,
or when extracting a method would hide state or control flow that readers need together.
