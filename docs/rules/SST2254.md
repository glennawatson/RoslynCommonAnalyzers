# SST2254 — Name the created type in an object creation

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Default severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Disabled (opt-in) |

## Cause

An object creation uses `new()` or `new(arguments)` without naming the type after `new`.
The type instead comes from the variable, property, return type or method parameter.
This form requires C# 9 or later.

Enable this rule if your team wants the type written at each creation. It reports
initializers, returns and arguments when the explicit form names the same created type.
Tuple targets and types that cannot be written as a type name are left alone.

## Example

Before:

```csharp
using System.Collections.Generic;

public class C
{
    public List<int> Make() => new() { 1, 2 };
}
```

After:

```csharp
using System.Collections.Generic;

public class C
{
    public List<int> Make() => new List<int>() { 1, 2 };
}
```

## How to fix violations

The code fix inserts the created type after `new`, using the shortest name that identifies
it at that location. It keeps constructor arguments and any object or collection initializer.
It replaces the spacing after `new` with one space, so a comment between `new` and `(` is lost.

For a nullable value target such as `int?`, `new()` creates the underlying value: the fix
writes `new int()`, which produces zero, rather than an empty nullable value.

## Configuration

The rule is disabled by default.

There are no rule-specific options. [SST2202](SST2202.md) prefers the opposite style and
is enabled by default. To adopt explicit creation types, enable this rule and disable
that one together:

```ini
[*.cs]
dotnet_diagnostic.SST2254.severity = warning
dotnet_diagnostic.SST2202.severity = none
```

Enable only one direction to avoid alternating suggestions.

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Leave the rule disabled if your team prefers `new()` with the type supplied by its context.
Suppress individual cases where repeating a long type name makes the code harder to read.
