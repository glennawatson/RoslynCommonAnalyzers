# SST2257 — Keep single-return lambdas expression-shaped

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Default severity | Info |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

A lambda has a brace block containing only `return expression;`. The braces and `return`
can be removed to leave the expression after `=>`.

The rule covers lambdas with or without parentheses around their parameters. It leaves
multi-statement blocks, blocks with only a call or `return;`, and `delegate` expressions
alone.

## Example

Before:

```csharp
using System;

public class C
{
    public Func<int, int> Make() => x => { return x + 1; };
}
```

After:

```csharp
using System;

public class C
{
    public Func<int, int> Make() => x => x + 1;
}
```

## How to fix violations

The code fix replaces the block with its returned expression. It keeps the parameters,
lambda modifiers and any explicit return type, and puts one space after `=>`.
Comments attached to the braces, `return`, or the edges of the expression can be lost.
Move useful comments outside the block before applying the fix.

## Configuration

To report violations as errors, set:

```ini
[*.cs]
dotnet_diagnostic.SST2257.severity = error
```

There are no rule-specific options.

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. The default is `suggestion`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when the block gives a useful place for a breakpoint or an explanatory comment,
or when matching nearby multi-statement lambdas makes the code easier to follow.
