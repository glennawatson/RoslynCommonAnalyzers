# SST2259 — Remove a stray semicolon after a declaration

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Default severity | Info |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

A `class`, `struct`, `interface`, `record`, `record struct` or `enum` declaration has a
semicolon after its closing brace. That semicolon is allowed but is not needed.

A record without a brace body, such as `record R(int X);`, needs its semicolon and is
not reported. A semicolon after a method body is a compiler error and is not reported
by this rule. Empty statements inside methods are outside its scope.

## Example

Before:

```csharp
internal class Marker
{
};
```

After:

```csharp
internal class Marker
{
}
```

## How to fix violations

The code fix removes the semicolon and keeps the declaration. Comments and line breaks
after the semicolon are moved after the closing brace. A comment on its own line
immediately before the semicolon can be lost; move it before applying the fix.

## Configuration

To report violations as errors, set:

```ini
[*.cs]
dotnet_diagnostic.SST2259.severity = error
```

There are no rule-specific options.

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. The default is `suggestion`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when the declaration must match a shared source template that includes the
semicolon. Otherwise, removing it is a small readability fix.
