# SST2260 — Remove an 'as' cast to a type the value already has

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Default severity | Info |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

An `as` expression names the type its input already has. For example, `s as string` is
redundant when `s` is declared as `string`. It returns the same value, including null
when the input is null.

The rule uses the input's declared type, not the type of an object it might hold at
runtime. It leaves `object` to `string` and `string` to `object` conversions alone.
It does not cover casts written as `(Type)value`.

## Example

Before:

```csharp
public class C
{
    public string Copy(string s)
    {
        var text = s as string;
        return text;
    }
}
```

After:

```csharp
public class C
{
    public string Copy(string s)
    {
        var text = s;
        return text;
    }
}
```

## How to fix violations

The code fix removes `as Type` and keeps the input expression. Existing surrounding
parentheses remain: `(s as string).Length` becomes `(s).Length`. Comments outside the
whole cast are kept, but comments beside the removed `as` or type can be lost.

## Configuration

To report violations as errors, set:

```ini
[*.cs]
dotnet_diagnostic.SST2260.severity = error
```

There are no rule-specific options.

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. The default is `suggestion`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md) for details.

## When to suppress

Suppress when keeping the cast makes a group of related conversions easier to compare,
or when the same source is shared with a build where the input has a different type.
