# SST2261 — Use the exclusive-or operator

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Info |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

Two Boolean values are compared with `(x && !y) || (!x && y)`, or with
`(x & !y) | (!x & y)`. Both forms mean that exactly one value is `true`.
The `^` operator expresses that check in one operation.

The rule accepts either order within each pair. Both values must be `bool`.
Method calls, indexing, assignments, and increments in the values are excluded.
Names, member accesses, and expressions built from supported operators can be reported.

## Example

Before:

```csharp
class Comparison
{
    public bool Differ(bool x, bool y) => (x && !y) || (!x && y);
}
```

After:

```csharp
class Comparison
{
    public bool Differ(bool x, bool y) => x ^ y;
}
```

## How to fix violations

The code fix replaces the whole comparison with `x ^ y`. It keeps comments
before and after the expression, but comments on the removed operators or
repeated operands can be lost.

`^` reads both values once. The longer `&&`/`||` form can skip a read or read a
value twice, depending on the values. Property reads are accepted without
checking what their getters do.

## Configuration

The rule is enabled by default at Info severity (`suggestion` in `.editorconfig`).
There are no rule-specific options. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2261.severity = error
```

Set the severity to `none` to disable it. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the expanded condition makes a business rule easier to read, or
when a property getter changes state or must be read in a particular order.
Changing those property reads can change the program's behavior.
