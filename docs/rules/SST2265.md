# SST2265 — Fold consecutive fluent calls into one chain

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Disabled (opt-in) |

## Cause

Two or more consecutive statements in a block call methods on the same object,
and each call returns that object's type. A fluent API lets these calls form a
chain, such as `builder.Append("a").Append("b")`.

The object must be named by a variable, `this`, or a member access such as
`this.builder`. Calls on different objects, calls returning `void` or another
type, and calls such as `GetBuilder().Append("a")` are left alone.

## Example

With the rule enabled, before:

```csharp
using System.Text;

class TextWriter
{
    public void Write(StringBuilder builder)
    {
        builder.Append("a");
        builder.Append("b");
    }
}
```

After:

```csharp
using System.Text;

class TextWriter
{
    public void Write(StringBuilder builder)
    {
        builder.Append("a").Append("b");
    }
}
```

## How to fix violations

The code fix folds the consecutive calls into one statement and removes the
extra statements. It keeps comments before the first statement and after the
last. Comments between the statements can be lost. No fix is offered when the
change would cross a preprocessor directive such as `#if` or `#region`.

Check that each method returns the same object it was called on. Matching the
return type does not prove this: a method can return a new object of the same
type. Also check that property reads or arguments do not change which object
the later statements use.

## Configuration

The rule is disabled by default. There are no rule-specific options. Enable it
in `.editorconfig`, for example as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2265.severity = error
```

Use `warning` for a warning or `none` to disable it. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when separate calls are easier to read, comment, or debug. Suppress
when a method returns a different object or a repeated property read is needed
to preserve behavior.
