# SST2266 — Inline a local that is read once

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Disabled (opt-in) |

## Cause

A local variable has one initializer and one read, and that read is in the next
statement. Replacing the read with the initializer can remove an unnecessary name.

The rule reports only declarations with one variable, excluding `const` and
`ref` locals. The initializer must be at most 40 characters by default. It can
be a literal, name, property read, cast, or supported expression made from these.
Method calls, object creation, indexing, and `await` are excluded.

## What is not reported

- The declaration changes the value's type, such as assigning an `int` to an `object`, or supplies the type for `null`, `default`, or a method name used as a delegate.
- The local is read more than once, written again, passed by `ref`, `out`, or `in`, or used inside a lambda or local function.
- Another statement separates the declaration from its use, or a call or assignment runs before the read in that statement.
- The containing block has code excluded by an inactive `#if` branch.
- The read is inside a loop and the initializer is a member access, cast, or operator expression. Moving these into the loop would repeat their work.

Simple initializers such as literals, names, `default(T)`, and `typeof(T)` can
still be moved into a loop.

## Example

With the rule enabled, before:

```csharp
class Calculator
{
    public int DoubleSum(int a, int b)
    {
        var sum = a + b;
        return sum * 2;
    }
}
```

After:

```csharp
class Calculator
{
    public int DoubleSum(int a, int b)
    {
        return (a + b) * 2;
    }
}
```

## How to fix violations

The code fix replaces the read with the initializer and deletes the declaration.
It adds parentheses where needed to keep operators grouped correctly. Comments
on the deleted declaration are lost; move them to the remaining statement if
they are useful. No fix is offered across a preprocessor directive boundary.

Inlining can make another local eligible, so another diagnostic can appear
after applying a fix.

## Configuration

The rule is disabled by default. Enable it and set the maximum initializer
length in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2266.severity = error
stylesharp.SST2266.max_initializer_length = 40
```

`stylesharp.max_initializer_length` is the project-wide alternative. Both keys
accept a positive integer; the default is `40` characters, including spaces
inside the expression. A valid rule-specific value takes precedence. If it is
missing or invalid, the project-wide value is tried, then the default.

Lower the limit to keep more named locals, or raise it to allow longer
expressions. Use severity `warning` for warnings or `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the local name explains the value or helps with debugging.
Also suppress when moving a property read or overloaded operator changes
behavior: these expressions are accepted without checking their implementation.
Keep a local that must capture a value before a loop changes it.
