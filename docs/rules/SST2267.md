# SST2267 — Write infinite loops in one consistent style

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Disabled (opt-in) |

## Cause

An infinite loop uses `for (;;)` when the selected style is `while (true)`, or
the reverse. This rule enforces a spelling preference and is disabled by default.

Only a `for` header with all its parts empty and a `while` condition written as
the literal `true` are checked. A condition such as `(true)` or a constant name
is left alone, as is a `for` header with an initializer or increment.

## Example

With the rule enabled and the default `while` style, before:

```csharp
class Worker
{
    public void Run()
    {
        for (;;)
        {
            System.Console.WriteLine();
        }
    }
}
```

After:

```csharp
class Worker
{
    public void Run()
    {
        while (true)
        {
            System.Console.WriteLine();
        }
    }
}
```

## How to fix violations

The code fix changes the header to the selected form and keeps the loop body.
With `for` selected, `while (true)` becomes `for (;;)`. Header spacing follows
the editor's formatting. Comments attached to the removed `true` or semicolons
can be lost.

## Configuration

Enable the rule and choose its style in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2267.severity = error
stylesharp.SST2267.infinite_loop_style = while
```

| Value | Preferred form |
| --- | --- |
| `while` (default) | `while (true)` |
| `for` | `for (;;)` |

`stylesharp.infinite_loop_style` is the project-wide alternative. A nonempty
rule-specific value takes precedence. Values ignore case and surrounding
spaces; a missing or unrecognized choice uses `while`.

Use severity `warning` for warnings or `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled if both spellings are acceptable. Suppress a particular
loop when its spelling helps it match a published algorithm or nearby code.
