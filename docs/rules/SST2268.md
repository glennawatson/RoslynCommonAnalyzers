# SST2268 — Keep object-creation parentheses consistent

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Disabled (opt-in) |

## Cause

An object creation with an object or collection initializer includes or omits
empty `()` against the selected style. Both forms call the same constructor.
The default preference is to omit the empty parentheses.

The rule skips constructor calls with arguments, creations without an
initializer, and creations written as `new()` without a type name.

## Example

With the rule enabled and the default `omit` style, before:

```csharp
class Point
{
    public int X { get; set; }

    public Point Make() => new Point() { X = 1 };
}
```

After:

```csharp
class Point
{
    public int X { get; set; }

    public Point Make() => new Point { X = 1 };
}
```

## How to fix violations

The code fix removes empty `()` for `omit`, or adds them for `include`. It keeps
the type and initializer. When removing parentheses, comments inside them or
between the type and the opening parenthesis can be lost. Comments after the
closing parenthesis are kept.

## Configuration

The rule is disabled by default. Enable it and choose a style in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2268.severity = error
stylesharp.SST2268.object_creation_parentheses = omit
```

| Value | Preferred form |
| --- | --- |
| `omit` (default) | `new T { ... }` |
| `include` | `new T() { ... }` |

`stylesharp.object_creation_parentheses` is the project-wide alternative. A
nonempty rule-specific value takes precedence. Values ignore case and surrounding
spaces; a missing or unrecognized choice uses `omit`.

Use severity `warning` for warnings or `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Leave the rule disabled if both forms are acceptable. Suppress when keeping
parentheses helps a group of constructor calls read consistently, including
calls that pass arguments.
