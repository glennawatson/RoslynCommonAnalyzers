# SST2270 — Keep array-creation element types consistent

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Disabled (opt-in) |

## Cause

An array creation uses `new T[] { ... }` or `new[] { ... }` against the selected
style. The shorter form asks the compiler to infer the element type from the
values. The rule reports only changes that keep the same array type.

To remove a type, the array must have one dimension, an initializer, and no
written size. For example, `new int[2] { 1, 2 }` is left alone. So is
`new object[] { 1, "text" }`, because removing `object` would not compile.
Adding a type requires one that can be named in C#, so arrays of anonymous
objects are left alone.

The rule does not suggest collection expressions such as `[1, 2]`.

## Example

With the rule enabled and the default `implicit_when_obvious` style, before:

```csharp
class Values
{
    public int[] Make() => new int[] { 1, 2 };
}
```

After:

```csharp
class Values
{
    public int[] Make() => new[] { 1, 2 };
}
```

## How to fix violations

The code fix removes the written element type, or adds the inferred type for
the `explicit` style. It keeps the initializer. Comments around the type or
array brackets can be lost when that part of the creation is replaced.

## Configuration

The rule is disabled by default. Enable it and choose a style in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2270.severity = error
stylesharp.SST2270.array_creation_type_style = implicit_when_obvious
```

| Value | Effect |
| --- | --- |
| `explicit` | Add the element type to `new[]` when the same array type can be written. |
| `implicit` | Remove the element type when the compiler can infer the same array type. |
| `implicit_when_obvious` (default) | Remove the type only when every element is a literal, cast, or object or array creation that names its type. Leave existing `new[]` expressions alone. |

Under the default, elements that are variables or method calls do not qualify
as obvious.

`stylesharp.array_creation_type_style` is the project-wide alternative. A
nonempty rule-specific value takes precedence. Values ignore case and surrounding
spaces; a missing or unrecognized choice uses `implicit_when_obvious`.

Use severity `warning` for warnings or `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the written element type helps explain the values, or leave the
rule disabled if the choice is best made for each array.
