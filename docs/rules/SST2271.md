# SST2271 — Keep the var-versus-explicit choice consistent

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Disabled (opt-in) |

## Cause

A local variable or `foreach` variable uses `var` or a written type against the
selected style. `var` asks the compiler to infer the type; it does not make the
variable change type at runtime.

For local declarations, the rule requires one variable with an initializer and
skips `const` and `ref` locals. It changes a written type to `var` only when the
inferred type is identical. For example, `IList<int> items = new List<int>()`
keeps its interface type. A `foreach` variable is also kept if `var` would give
it a different type.

Initializers written as `new()`, a collection expression, or bare `default`
are not converted to `var`. Neither is `stackalloc`, including inside
parentheses or conditional branches. In particular, changing a `Span<T>`
declaration with `stackalloc` to `var` would make it a pointer declaration.
When replacing `var`, the type must have a usable C# name; anonymous types are
left alone.

## Example

With the rule enabled and the default `when_obvious` style, before:

```csharp
using System.Collections.Generic;

class Values
{
    public void Make()
    {
        List<int> numbers = new List<int>();
        numbers.Add(1);
    }
}
```

After:

```csharp
using System.Collections.Generic;

class Values
{
    public void Make()
    {
        var numbers = new List<int>();
        numbers.Add(1);
    }
}
```

## How to fix violations

The code fix replaces the written type with `var`, or replaces `var` with the
inferred type's name. It keeps the initializer and comments before and after
the type. Comments inside a replaced type, such as between generic type
arguments, can be lost.

## Configuration

The rule is disabled by default. Enable it and choose a style in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2271.severity = error
stylesharp.SST2271.use_var = when_obvious
```

| Value | Effect |
| --- | --- |
| `always` | Use `var` when it preserves the type, including for `foreach` variables. |
| `never` | Write the type wherever it can be named, including for `foreach` variables. |
| `when_obvious` (default) | Use `var` for a typed object or array creation, cast, `default(T)`, or literal other than `null` and bare `default`. Write the type for other initializers. Leave `foreach` variables alone. |

For example, under `when_obvious`, a local initialized by a method call uses a
written type even if the method's name suggests what it returns.

`stylesharp.use_var` is the project-wide alternative. A nonempty rule-specific
value takes precedence. Values ignore case and surrounding spaces; a missing
or unrecognized choice uses `when_obvious`.

Use severity `warning` for warnings or `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a written type makes an unfamiliar API easier to understand, or
when `var` avoids repeating a long type name. Leave the rule disabled if this
choice is best made for each declaration.
