# SST2273 — Prefer a guard clause over a trailing wrapping if

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Disabled (opt-in) |

## Cause

The last statement in a body is an `if` with no `else`, and it wraps at least two statements by default.
An early-exit guard can move that work out one level of indentation.

This applies to `void` methods and local functions, `async Task` and `async ValueTask` methods and local
functions, constructors, and `set`, `init`, `add`, and `remove` accessors. In `for`, `foreach`, and `while`
loop bodies, the guard skips the current iteration.

An `if` inside another `if`, `try`, `using`, or `lock` block is not reported directly. Neither are
value-returning members, iterator bodies, or cases where moving declarations out would clash with another name.

## Example

Before:

```csharp
public class Reporter
{
    public void Report(bool ready)
    {
        if (ready)
        {
            System.Console.WriteLine("a");
            System.Console.WriteLine("b");
        }
    }
}
```

After:

```csharp
public class Reporter
{
    public void Report(bool ready)
    {
        if (!ready)
        {
            return;
        }

        System.Console.WriteLine("a");
        System.Console.WriteLine("b");
    }
}
```

## How to fix violations

The code fix reverses the condition, inserts a braced `return;` guard, and moves the wrapped statements
out of the `if`. In a loop it uses `continue;`. It adds a blank line after the guard and adjusts indentation.
Statements before the original `if` keep their position.

For example, `count > 0` becomes `count <= 0` for an integer. Comparisons with nullable or floating-point
values keep a surrounding `!(...)` so null and `NaN` retain their meaning. `NaN` is a floating-point value
that means "not a number".

The diagnostic can appear without a fix when the wrapped body contains directives such as `#if` or
`#region`. Comments attached to removed braces or rewritten parts of the condition can be lost; review
the preview and move those comments by hand. Nested trailing conditions can need another application of the fix.

## Configuration

The rule is disabled by default. Enable it with `warning` or choose `error`, `suggestion`, or `silent`.
Use `none` to disable it.

```ini
[*.cs]
dotnet_diagnostic.SST2273.severity = warning
stylesharp.SST2273.min_wrapped_statements = 2
```

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.SST2273.min_wrapped_statements` | Positive integer | `2` |
| `stylesharp.min_wrapped_statements` | Positive integer; fallback for the rule-specific key | `2` |

A valid rule-specific value takes priority. If it is missing or invalid, the general value is tried,
then the default. Set the minimum to `1` to include single statements, or raise it to report larger bodies only.

## When to suppress

Suppress when the positive condition makes the work easier to understand than an early exit. Leave the rule
disabled if your team prefers wrapping conditions. Keep the original condition if custom comparison operators
do not behave as opposites when the fix swaps them.
