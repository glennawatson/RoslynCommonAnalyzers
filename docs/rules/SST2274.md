# SST2274 — Convert an as assignment and null check to an is pattern

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

A local variable receives an `as` conversion, and the next statement is an `if` with no `else` that checks
that variable for null. An `is` pattern can test the type and name the converted value in one condition.

The rule handles two cases:

- A non-null check (`!= null`, `is not null`, or `is object`) followed by uses inside the `if` body only.
- A null check (`== null` or `is null`) whose body ends with `return`, `throw`, `continue`, or `break`.
  The variable must not be used inside that exit branch.

Equality checks also accept `null` on the left. The variable must have the same type as the `as` target,
apart from a nullable reference annotation. The target must be a reference type.

The rule skips `using` declarations, declarations of several variables, reassigned variables, uses through
`ref`, `out`, or `in`, compound conditions, and conversions whose input is a method call. A declaration
directly in a `switch` section is also skipped unless it is inside a block.

## Example

Before:

```csharp
public class TextReader
{
    public int Measure(object value)
    {
        var text = value as string;
        if (text != null)
        {
            return text.Length;
        }

        return 0;
    }
}
```

After:

```csharp
public class TextReader
{
    public int Measure(object value)
    {
        if (value is string text)
        {
            return text.Length;
        }

        return 0;
    }
}
```

## How to fix violations

The code fix removes the local declaration and replaces the condition with `value is string text`.
For an early exit on null, it uses `value is not string text`. It keeps the variable name, the `if` body,
and later uses of the variable.

The fix is unavailable when a directive such as `#region` separates the declaration and the `if`.
Comments attached to the removed declaration or replaced condition can be lost. Move them by hand before
accepting the fix.

## Language versions

The positive pattern requires C# 7. The early-exit pattern requires C# 9. The rule reports only when the
required version is available.

## Configuration

The rule is enabled by default at Warning (`warning`).

```ini
[*.cs]
dotnet_diagnostic.SST2274.severity = warning
```

Use `none` to disable it, or choose `silent`, `suggestion`, `warning`, or `error` for severity.
There are no rule-specific options.

## When to suppress

Suppress when separate conversion and validation steps make the code clearer. Also suppress when a custom
`==` or `!=` operator treats null differently from an `is` pattern; the rewrite bypasses those operators.
