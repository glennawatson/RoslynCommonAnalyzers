# SST2280 — Use an expression body for a get-only indexer

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Info |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

An indexer has one `get` accessor, and its body contains only `return expression;`.
The indexer can use `=> expression;` without a separate `get` block.

Indexers with `set` or `init`, getters with several statements, and getters that already use `=>` are not
reported. The rule also skips getters with attributes or modifiers, since removing `get` would remove those settings.

The rule skips a body when the rewrite would lose a comment, or when it contains inactive code in an
`#if` branch. A comment within the kept expression, such as `a + /* offset */ b`, does not prevent a report.

## Example

Before:

```csharp
public sealed class Values
{
    private readonly int[] _items = new int[4];

    public int this[int index]
    {
        get { return _items[index]; }
    }
}
```

After:

```csharp
public sealed class Values
{
    private readonly int[] _items = new int[4];

    public int this[int index] => _items[index];
}
```

## How to fix violations

The code fix removes the `get` keyword and both sets of braces, then writes `=>` and the returned
expression after the indexer's parameter list. It keeps comments inside that expression and after the
indexer's closing brace. The expression is still evaluated on each read of the indexer.

The fix puts the arrow beside the signature when the result fits the configured line length. Otherwise,
it wraps at the arrow and indents the continuation by four spaces. The options below control that layout.

## Language versions

This rule requires C# 6 or later. For indexers that also have a setter, [SST2219](SST2219.md) covers
expression bodies on individual accessors.

## Configuration

The rule is enabled by default at Info (`suggestion`).

```ini
[*.cs]
dotnet_diagnostic.SST2280.severity = suggestion
```

Use `none` to disable it, or choose `silent`, `suggestion`, `warning`, or `error` for severity.

The diagnostic has no rule-specific options. These shared options control the code fix's layout:

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.max_line_length` | Positive integer; character limit before wrapping | `120` |
| `stylesharp.SST1521.max_line_length` | Positive integer; takes priority over the general line limit | `120` |
| `stylesharp.arrow_token_new_line` | `after` or `before`; where to break a wrapped line relative to `=>` | `after` |
| `stylesharp.SST1527.arrow_token_new_line` | `after` or `before`; takes priority over the general arrow option | `after` |

An invalid line limit falls back to the general value, then `120`. An invalid arrow option uses `after`.
These options affect formatting, not which bodies are reported.

## When to suppress

Suppress when keeping the `get` block makes the lookup easier to read, or when your team prefers indexers
with explicit accessors.
