# SST2282 — Use an is-null pattern instead of ReferenceEquals against null

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

A call to `object.ReferenceEquals` has exactly one `null` argument, in either position. The value being
checked is a reference type or a generic type parameter that is not constrained to a value type.
The call can be written as a direct null check with `is null`.

Calls with two null arguments, two non-null arguments, or a value-type argument (including `int?`) are not
reported. A different method named `ReferenceEquals` is also left alone.

## Example

Before:

```csharp
public class TextChecks
{
    public bool IsMissing(string value) => ReferenceEquals(value, null);

    public bool IsPresent(string value) => !ReferenceEquals(value, null);
}
```

After:

```csharp
public class TextChecks
{
    public bool IsMissing(string value) => value is null;

    public bool IsPresent(string value) => value is not null;
}
```

## How to fix violations

The code fix replaces the call with `value is null`. If `!` negates the call, it replaces both with
`value is not null`. It adds parentheses around a compound value expression when needed.
Comments inside the removed call, outside the kept value expression, can be lost; move those comments by hand.

Like `ReferenceEquals`, a null pattern does not call a custom `==` operator.

## Language versions

The plain check requires C# 7. The negated check requires C# 9. The rule reports only when the required
version is available.

## Configuration

The rule is enabled by default at Warning (`warning`).

```ini
[*.cs]
dotnet_diagnostic.SST2282.severity = warning
```

Use `none` to disable it, or choose `silent`, `suggestion`, `warning`, or `error` for severity.
There are no rule-specific options.

## When to suppress

Suppress when the code must remain a method call, such as inside an expression tree used by a query provider.
C# expression trees cannot contain these patterns. A consistent project style that uses `ReferenceEquals`
for null checks is another reason to disable the rule.
