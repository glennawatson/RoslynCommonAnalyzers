# SST2283 — Fold a preceding null guard into the assigned value

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

An `if` checks a local variable or parameter for null, throws an exception, and is immediately followed
by an assignment of that same value. The assignment can use `?? throw` to reject null and store the value
in one statement.

The value must be a reference type. The check must be `value is null`, `value == null`, or `null == value`,
without a custom equality operator. The `if` must have no `else` and contain only the throw. The assignment
target must be a simple name or a `this` member, such as `_value` or `this.Value`.

The rule skips guards followed by a return or a variable declaration, guards with extra statements, and
targets such as `other.Value` or `items[index]`. A comment immediately before or after the guard also
prevents a report.

When the target framework provides `ArgumentNullException.ThrowIfNull`, a guard throwing
`ArgumentNullException` with no arguments or only the matching parameter name is left alone. A custom
exception message does not get this exclusion.

## Example

Before:

```csharp
using System;

public sealed class Setting
{
    private readonly string _value;

    public Setting(string value)
    {
        if (value is null)
        {
            throw new InvalidOperationException();
        }

        _value = value;
    }
}
```

After:

```csharp
using System;

public sealed class Setting
{
    private readonly string _value;

    public Setting(string value)
    {
        _value = value ?? throw new InvalidOperationException();
    }
}
```

## How to fix violations

The code fix removes the `if` and replaces the assignment's value with `value ?? throw` followed by the
same exception expression. It places the assignment where the guard stood and removes the blank line
between them.

The fix is unavailable when a directive separates the guard and assignment. Comments inside the removed
guard or attached to the assignment can be lost, even though comments around the guard prevent a report.
Move those comments by hand before accepting the fix.

## Language versions

This rule requires C# 7 or later.

## Configuration

The rule is enabled by default at Warning (`warning`).

```ini
[*.cs]
dotnet_diagnostic.SST2283.severity = warning
```

Use `none` to disable it, or choose `silent`, `suggestion`, `warning`, or `error` for severity.
There are no rule-specific options.

## When to suppress

Suppress when keeping validation separate makes the code clearer, or when a long exception expression
would make the assignment hard to read.
