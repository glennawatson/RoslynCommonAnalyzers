# SST2284 — Step a value with the increment or decrement operator

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

A standalone statement adds or subtracts the integer literal `1` with `+=` or `-=`. It can use `++` or `--`.
The target must be a name or a member reached through names or `this`, and its type must support the matching operator.

This includes built-in numeric types, `char`, enums, pointers, and nullable versions of supported value
types. Custom types qualify when they declare the matching `++` or `--` operator. `IntPtr` and `UIntPtr`
qualify only when that operator is available in the referenced framework.

## What is not reported

- An assignment whose result is used, such as `return count += 1;`.
- An assignment in a `for` header.
- A step other than the integer literal `1`, including a named constant or `1.0`.
- An indexed or computed target, such as `items[index]` or `GetCounter().Value`.
- A `dynamic` target or a type without the matching operator.

## Example

Before:

```csharp
public class Counter
{
    public int Next(int count)
    {
        count += 1;
        return count;
    }
}
```

After:

```csharp
public class Counter
{
    public int Next(int count)
    {
        count++;
        return count;
    }
}
```

## How to fix violations

The code fix replaces `count += 1` with `count++`, or `count -= 1` with `count--`. It puts the operator
after the target because the statement does not use the result. Fix All is supported.

Comments between the target, assignment operator, and literal can be lost. Comments after the statement
are kept. Move any affected comment by hand before accepting the fix.

## Configuration

The rule is enabled by default at Warning (`warning`).

```ini
[*.cs]
dotnet_diagnostic.SST2284.severity = warning
```

Use `none` to disable it, or choose `silent`, `suggestion`, `warning`, or `error` for severity.
There are no rule-specific options.

## When to suppress

Suppress for a custom type when `++` does different work from `+ 1`, or `--` does different work from `- 1`.
Having both operators does not mean they behave alike. Suppress for style when keeping the amount explicit
helps compare nearby updates with different step sizes.
