# SST2284 — Step a value with the increment or decrement operator

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A standalone statement moves a value on by one through a compound assignment.

```csharp
// 👎 reported
i += 1;
count -= 1;

// 👍
i++;
count--;
```

## Rule description

A statement whose whole job is to step a value by one says in three tokens what one operator says on its
own, and the stepping operators are what a reader scans for when following a counter. Because the statement
discards the assignment's value, the prefix and postfix forms are interchangeable here, so the fix uses the
conventional postfix one.

### What is reported

- `x += 1;` and `x -= 1;` written as an expression statement, where `x` is a plain name, a `this` member, or
  a member-access chain of those, and the type has the matching stepping operator.

### What is not reported

- An assignment whose value is consumed — `return i += 1;`, `y = (i += 1)` — because there the prefix and
  postfix results differ and the rewrite would not be neutral.
- A step of anything other than one.
- An indexed or otherwise computed target, which the rule leaves to a human.
- A type that overloads `+` without overloading `++`: the shorter form would not compile, so the compound
  assignment stays. `IntPtr` and `UIntPtr` are checked against the referenced framework rather than assumed,
  because they gained `++` only when they became the `nint`/`nuint` types.
- A `dynamic` target, whose operator is not known until run time.

## How to fix violations

Replace the compound assignment with `++` or `--`.

## Performance

The rule registers on the two compound-assignment kinds. Everything cheap is checked first — the statement
context, the literal `1`, the shape of the target — and the semantic model is asked for the target's type
only for a candidate that already looks rewritable.
