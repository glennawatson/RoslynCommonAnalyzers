# SST2285 — Fold a null check into a conditional access

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A check such as `text != null` is followed by `&&` and a member read or call on the same value.
The rule applies in C# 6 or later. It accepts `null != text` too.

The guarded expression must return `bool`, or compare a member with another value using `<`, `>`,
`<=`, `>=`, or `==`. A guarded `.Value` read on a `bool?` is also reported.

## Example

Bad:

```csharp
public class Checks
{
    public bool HasText(string text) => text != null && text.Length > 0;

    public bool IsReady(bool? ready) => ready != null && ready.Value;
}
```

Corrected:

```csharp
public class Checks
{
    public bool HasText(string text) => text?.Length > 0;

    public bool IsReady(bool? ready) => ready == true;
}
```

`?.` skips the member access when the value is null. Both tests above return `false` for null.

## What is not reported

- A guarded `!=` comparison, or `== null` after the guard.
- A comparison whose right side also reads the guarded value.
- A guard on a method call, such as `GetText() != null`.
- A check written as `is not null`, or a use of a different value after `&&`.

## Code fix

The fix removes the null check and adds `?.` at the guarded value. It changes a boolean member
read or call to a comparison with `true`: `text?.StartsWith("a") == true`. For a `bool?` read through
`.Value`, it compares the nullable value directly with `true`. Longer member chains keep their other accesses.
Fix All is supported. Comments attached to the removed guard or operators can be lost.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets it
to `error`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2285.severity = error
```

Accepted values are `none`, `silent`, `suggestion`, `warning`, and `error`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the explicit guard makes a complex condition easier to read. Keep the guard if reading
a property twice is intentional, or if a comparison must skip its right side when the guarded value
is null; folding the guard can change those evaluations.
