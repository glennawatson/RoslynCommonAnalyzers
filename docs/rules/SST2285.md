# SST2285 — Fold a null check into a conditional access

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A null guard is conjoined with a member read on the same value.

```csharp
// 👎 reported
if (text != null && text.Length > 0) { }
if (ready != null && ready.Value) { }      // bool?

// 👍
if (text?.Length > 0) { }
if (ready == true) { }
```

## Rule description

`x != null && x.Count > 0` names the value twice and leaves a reader to check that both halves talk about the
same thing. `x?.Count > 0` says it once. The two are the same test because a conditional access yields null
when its receiver is null, and every relational comparison against null is false — exactly the answer the
guard produced.

A `bool?` tested through `.Value` needs no conditional access at all: `b == true` already means "not null and
true".

### What is reported

- `x != null && <use>` (either operand order for the guard) where `x` is a side-effect-free name repeated
  verbatim as the receiver of `<use>`, and `<use>` is one of:
  - a bool-valued member read on `x` — folded to `x?.Member == true`;
  - a comparison of a member read on `x` against something that does not mention `x`, using `<`, `>`, `<=`,
    `>=`, or `==` against a non-null operand — folded to `x?.Member op operand`;
  - `.Value` on a `bool?` — folded to `x == true`.

### What is not reported

- A `!=` comparison. `x?.Count != 0` is true when `x` is null and the guarded form is false, so the two are
  not the same test.
- A comparison against `null` on the right, for the same reason.
- A right operand that also reads the guarded value: once the guard folds away that operand is evaluated
  whatever the receiver is, so it would start dereferencing a null it used to be protected from.
- A receiver that is not side-effect-free, such as a method call, which the fold would evaluate a different
  number of times.

## How to fix violations

Fold the guard into a conditional access on the receiver, or compare a `bool?` to `true` directly.

## Performance

The conjunction's shape, the receiver's repetition, and the operator are all settled syntactically before the
semantic model is asked anything, so a conjunction that is not a guarded member read costs one pattern match.
