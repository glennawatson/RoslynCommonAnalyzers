# SST2286 — Remove a ToString call on a value that is already a string

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A value typed as `string` calls `ToString()` with no arguments. For a non-null string, the call
returns the same string and performs no conversion.

## Example

Bad:

```csharp
public class Labels
{
    public string Label(string text) => "id: " + text.ToString();
}
```

Corrected:

```csharp
public class Labels
{
    public string Label(string text) => "id: " + text;
}
```

## What is not reported

Calls with arguments, calls on other types, and `text?.ToString()` are excluded. A call used
directly inside an interpolation, such as `$"{text.ToString()}"`, is also excluded.

## Code fix

The fix replaces the call with the expression before `.ToString()`. It keeps parentheses around
that expression and supports Fix All. Comments within the removed call can be lost.

If the string is null, removing the call also removes the `NullReferenceException` it would throw.
Add an explicit null check if callers rely on rejection of null.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets it
to `error`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2286.severity = error
```

Accepted values are `none`, `silent`, `suggestion`, `warning`, and `error`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an external expression consumer requires the method call, or when you must preserve
its null exception until you can add an explicit check. A normal string conversion needs no suppression.
