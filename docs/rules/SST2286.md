# SST2286 — Remove a ToString call on a value that is already a string

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An argument-less `ToString` is called on a receiver the compiler already types as `string`.

```csharp
// 👎 reported
return text.ToString();
log.Write("id: " + text.ToString());

// 👍
return text;
log.Write("id: " + text);
```

## Rule description

`string.ToString()` returns the same reference it was called on. The call converts nothing, and it hides from
a reader that the value was a string all along — the sort of leftover that survives a refactor which changed
a member's type. Removing it leaves the expression with the identical value and type.

### What is reported

- `receiver.ToString()` with no arguments, where the receiver's type is `string`.

### What is not reported

- A `ToString` that takes a format or a provider: that does real work.
- A receiver of any other type, where `ToString` is the conversion it looks like.
- A call reached through `?.`, which is a member binding rather than a member access.
- A call inside an interpolation hole, which belongs to the rule that simplifies interpolations, so the two
  never report the same `ToString`.

## How to fix violations

Delete the call and use the receiver.

## Performance

Only an invocation whose invoked name is `ToString` and whose argument list is empty reaches the semantic
model, and the model is asked one question — the receiver's type. That type settles the call on its own:
`string` declares one argument-less `ToString`, and an extension method cannot displace an applicable
instance method.
