# SST2287 — Use a for loop when a while loop owns its counter

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A variable declared immediately above a `while` loop is tested by its condition, stepped by its last
statement, and never read afterwards.

```csharp
// 👎 reported
int i = 0;
while (i < n)
{
    Handle(i);
    i++;
}

// 👍
for (int i = 0; i < n; i++)
{
    Handle(i);
}
```

## Rule description

That variable is a loop counter with its three parts spread over three places: the declaration above the
loop, the test in the header, the step buried at the bottom of the body. A `for` header gathers them, puts
the step where a reader looks for it, and scopes the counter to the loop so nothing after it can reach a
value that no longer means anything.

### What is reported

- A `while` whose immediately preceding statement declares one initialized local, whose condition mentions
  that local, whose body is a block ending in a step of that local (`i++`, `++i`, `i--`, `--i`, or a `+=`/`-=`
  whose amount does not read the counter), and whose counter is neither read nor written after the loop.

### What is not reported

- A body containing a `continue` that targets this loop. A `continue` skips a trailing step in a `while` but
  runs the incrementor in a `for`, so the two are not the same loop. A `continue` belonging to a nested loop
  or to a lambda does not block the rewrite.
- A counter still used after the loop, which the `for` header would scope away.
- A declaration of more than one variable, or one with no initializer.
- A body of a single statement, where nothing would be left once the step moves into the header.

## How to fix violations

Move the declaration and the trailing step into a `for` header.

## Performance

The body shape, the preceding declaration, and the trailing step are all checked syntactically first. The
data-flow question — whether the counter outlives the loop — is asked last, and only for a loop that already
looks like a `for`.
