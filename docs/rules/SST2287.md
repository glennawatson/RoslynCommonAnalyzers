# SST2287 — Use a for loop when a while loop owns its counter

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `while` loop has a counter declared immediately before it, tests that counter in its condition,
and changes it in the last statement of its body. The counter is neither read nor assigned after
the loop. A `for` header puts these three parts together.

The declaration must initialize one variable. The loop must have a braced body with at least two
statements. Its final statement must use `++`, `--`, `+=`, or `-=` on the counter; the amount in
`+=` or `-=` must not read the counter.

## Example

Bad:

```csharp
public class Printer
{
    public void Print(int count)
    {
        int i = 0;
        while (i < count)
        {
            System.Console.WriteLine(i);
            i++;
        }
    }
}
```

Corrected:

```csharp
public class Printer
{
    public void Print(int count)
    {
        for (int i = 0; i < count; i++)
        {
            System.Console.WriteLine(i);
        }
    }
}
```

A `continue` targeting this loop prevents the diagnostic: it skips the trailing step in a `while`
but runs the step in a `for`. A `continue` in a nested loop does not prevent it.

## Code fix

The fix moves the declaration and final step into a `for` header, removes their old statements,
and leaves the other body statements in place. The counter becomes local to the loop. Fix All is supported.

The header gets spaces after its semicolons. Comments before the counter declaration are kept,
but comments attached to the `while` header, the removed declaration semicolon, or the final step
can be lost. Move those comments to a statement that remains before applying the fix.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets it
to `error`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2287.severity = error
```

Accepted values are `none`, `silent`, `suggestion`, `warning`, and `error`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the condition and step describe a process more clearly as a `while`, or when a long
step expression makes the `for` header hard to read.
