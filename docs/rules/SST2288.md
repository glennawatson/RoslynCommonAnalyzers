# SST2288 — Express a conditional with a literal branch as a logical operator

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `condition ? value : value` expression has `true` or `false` in exactly one branch, and the
other branch has type `bool`. The expression can use `&&` or `||` instead.

Expressions with two literal branches, no literal branch, or a `bool?` branch are not reported.

## Example

Bad:

```csharp
public class Checks
{
    public bool CanRun(bool ready, bool hasItems) => ready ? hasItems : false;
}
```

Corrected:

```csharp
public class Checks
{
    public bool CanRun(bool ready, bool hasItems) => ready && hasItems;
}
```

## Code fix

The fix makes these replacements and supports Fix All:

| Conditional | Replacement |
| --- | --- |
| `a ? b : false` | `a && b` |
| `a ? true : b` | `a \|\| b` |
| `a ? false : b` | `!a && b` |
| `a ? b : true` | `!a \|\| b` |

The right side is evaluated only when needed, as in the conditional. When the condition needs
negating, the fix removes an existing `!` where possible. In C# 9 or later it also uses `is not`
for a pattern test. It adds parentheses around a comparison being negated or a `||` branch placed
inside `&&`.

A line break after the condition is kept, and the logical operator takes the indentation of `?`.
Comments attached to removed branches or punctuation can be lost.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets it
to `error`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2288.severity = error
```

Accepted values are `none`, `silent`, `suggestion`, `warning`, and `error`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when spelling out both outcomes makes a business condition easier to follow, especially
when the shorter form would introduce a confusing negation.
