# SST2288 — Express a conditional with a literal branch as a logical operator

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A conditional expression has a boolean literal in exactly one branch.

```csharp
// 👎 reported
var ok = ready ? HasItems : false;

// 👍
var ok = ready && HasItems;
```

## Rule description

`a ? b : false` is `a && b` — same value, same short-circuit, one operator instead of a three-part
conditional. The long form invites a reader to work out what each branch yields before noticing it is
ordinary boolean logic, and it hides the shape from anything that reasons about conditions.

All four forms fold:

| Written | Means |
| --- | --- |
| `a ? b : false` | `a && b` |
| `a ? true : b` | `a \|\| b` |
| `a ? false : b` | `!a && b` |
| `a ? b : true` | `!a \|\| b` |

### What is reported

- A conditional where exactly one branch is `true` or `false`.

### What is not reported

- A conditional whose branches are *both* literals — that collapses to the condition itself, which is a
  different rule's business.
- A conditional with no literal branch, or one whose branches are not boolean.

## How to fix violations

Use the operator. Where the fold negates the condition, a leading `!` is dropped rather than doubled, and a
non-primary condition is parenthesized so the `!` binds to the whole of it. A branch that is itself a `||` is
parenthesized when it lands inside a `&&`.

## Performance

The whole match is syntactic, and the suggestion text is built only once a branch is known to be a literal.
