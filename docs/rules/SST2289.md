# SST2289 — Remove an unnecessary unsafe block

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Info |
| Code fix | No |
| Default | Enabled |
| Applies to | C# 15 or later |

## Cause

An `unsafe` block contains operations C# 15 permits in safe code, without a pointer access that
needs the block. These operations include declaring pointer types, taking addresses with `&`,
using `fixed`, applying `sizeof` to an unmanaged type, and using `stackalloc`.

## Example

Bad, in a C# 15 project:

```csharp
public class Sizes
{
    public int Size()
    {
        unsafe
        {
            return sizeof(int);
        }
    }
}
```

Corrected:

```csharp
public class Sizes
{
    public int Size()
    {
        return sizeof(int);
    }
}
```

## What is not reported

- Blocks containing `*pointer`, `pointer->Member`, or `pointer[index]`.
- Blocks containing a function-pointer type such as `delegate*<void>`.
- Blocks containing none of the operations listed in the cause.
- Code targeting a language version below C# 15.

## How to fix violations

Remove the `unsafe` keyword. Keep the braces if they limit the scope of local variables.
There is no code fix.

## Configuration

There are no rule-specific options. The default severity is `suggestion`; this repository sets it
to `error`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2289.severity = error
```

Accepted values are `none`, `silent`, `suggestion`, `warning`, and `error`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress in shared source that must also compile with a language version requiring `unsafe`
for the same operations. Keeping the block can also be useful when your team requires an explicit
marker around all pointer-related code.
