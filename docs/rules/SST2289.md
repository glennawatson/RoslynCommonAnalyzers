# SST2289 — This unsafe block no longer needs an unsafe context

| Item | Value |
| --- | --- |
| Category | ModernSyntax |
| Severity | Info |
| Code fix | No |
| Applies to | C# 15 or later |

## Cause

An `unsafe` block contains pointer operations, but only ones C# 15 permits in safe code.

```csharp
unsafe
{
    int number = 42;
    int* pointer = &number;
}
```

## Rule description

C# 15 ties the unsafe context to the operations that actually read or write unmanaged memory, rather
than to the presence of a pointer type. These no longer need one:

- declaring a pointer type
- taking an address with `&`
- pinning with a `fixed` statement
- `sizeof` applied to any unmanaged type
- converting a `stackalloc` to a pointer

A block containing only those marks a region unsafe that the compiler no longer treats as unsafe.
That matters because the keyword is an audit signal: reviewers and security tooling read every unsafe
region, so a region that cannot corrupt memory dilutes the ones that can.

```csharp
// 👍
int number = 42;
int* pointer = &number;
```

## What is not reported

Operations that still require the context, and therefore stop the rule:

| Operation | Example |
| --- | --- |
| Pointer indirection | `*pointer` |
| Pointer member access | `pointer->Field` |
| Pointer element access | `pointer[0]` |
| Function-pointer invocation | `delegate*<void>` calls |

A block with **no** pointer operations at all is also not reported here — an `unsafe` modifier
guarding nothing is a different shape, covered by SST1455.

## How to fix violations

Remove the `unsafe` keyword from the block, keeping the body as it is. Where the block was the whole
body of a member, the member's `unsafe` modifier can usually go too.
