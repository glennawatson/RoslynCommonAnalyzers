# SST2301 — Types implementing IEquatable&lt;T&gt; should be sealed

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A non-abstract class implements `IEquatable<T>` for its own type but is not sealed. This includes
generic classes such as `Box<T> : IEquatable<Box<T>>`.

A derived class can add data that the base equality method ignores. The two classes can then
disagree about whether their instances are equal. Sealing the class prevents that mismatch.

Abstract classes, sealed classes, structs, and records are excluded. A class implementing
`IEquatable<OtherType>` is excluded too. A derived class that inherits only `IEquatable<BaseType>`
is not reported for that inherited interface.

## Example

Bad:

```csharp
using System;

public class Money : IEquatable<Money>
{
    public decimal Amount { get; }

    public Money(decimal amount) => Amount = amount;

    public bool Equals(Money other) => other != null && other.Amount == Amount;
}
```

Corrected:

```csharp
using System;

public sealed class Money : IEquatable<Money>
{
    public decimal Amount { get; }

    public Money(decimal amount) => Amount = amount;

    public bool Equals(Money other) => other != null && other.Amount == Amount;
}
```

## Code fix

The fix adds `sealed` to the class declaration. For a partial class, it places `sealed` before
`partial`. It keeps the members and supports Fix All.

The fix does not change derived classes or virtual members. Existing derived classes and virtual
members declared in the class can stop compiling when the class becomes sealed. Resolve those uses
before accepting the change.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets it
to `error`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2301.severity = error
```

Accepted values are `none`, `silent`, `suggestion`, `warning`, and `error`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a public class must remain open to inheritance and its equality contract is designed
and tested for derived types. Check that comparing base and derived instances gives the same result
in both directions. Otherwise, move shared data to a base class and implement equality in sealed classes.
