# SST2302 — Overload operators in their complete set

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A type declares operators without the related equality or ordering members callers need.

| Declared members | What is missing |
| --- | --- |
| `==` | An `Equals(object)` or `GetHashCode()` override declared on the same type |
| `<` and `>` | `<=` and `>=` |
| `<=` and `>=` | `<` and `>` |
| Ordering operators | `IComparable<T>` or non-generic `IComparable` |
| A binary `+`, `-`, `*`, `/`, or `%` on a public class | All of `==`, an `Equals(object)` override, and a `GetHashCode()` override are absent |

Inherited equality overrides do not satisfy these checks. The arithmetic check excludes structs,
non-public classes, and unary operators. Declaring any one of its three equality members satisfies
that check; a declared `==` still gets the equality check above.

The missing comparison-interface check applies only when the project has `IComparable<T>` available.
Missing operator pairs already required by C#, such as `==` without `!=`, are compiler errors.

## Example

Bad:

```csharp
public sealed class Money
{
    public decimal Amount { get; }

    public Money(decimal amount) => Amount = amount;

    public static bool operator ==(Money left, Money right) => left?.Amount == right?.Amount;

    public static bool operator !=(Money left, Money right) => !(left == right);
}
```

Corrected:

```csharp
public sealed class Money
{
    public decimal Amount { get; }

    public Money(decimal amount) => Amount = amount;

    public override bool Equals(object obj) => obj is Money other && Amount == other.Amount;

    public override int GetHashCode() => Amount.GetHashCode();

    public static bool operator ==(Money left, Money right) => object.Equals(left, right);

    public static bool operator !=(Money left, Money right) => !object.Equals(left, right);
}
```

## How to fix violations

Add the missing members named in the diagnostic. Equality and hash codes must use the same data,
and `CompareTo` must agree with the ordering operators. Do not derive `<=` by negating `>` when
values such as floating-point `NaN` make both comparisons false.

There is no code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets it
to `error`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2302.severity = error
```

Accepted values are `none`, `silent`, `suggestion`, `warning`, and `error`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the operators intentionally do not describe ordinary equality or a sortable order,
such as operators that build query expressions. Document that contract. Suppression can also be
appropriate when inherited equality is intentional and covers all the derived type's relevant data.
