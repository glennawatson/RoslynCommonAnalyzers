# SST2304 — Events should use the standard handler signature

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An event uses a delegate other than `System.EventHandler` or `System.EventHandler<TEventArgs>`.
This includes a custom delegate that already has the standard `void (object sender, TEventArgs e)`
signature. Different delegate types cannot share a stored handler value merely because their
signatures match.

When the custom delegate returns `void` and takes `object` plus an `EventArgs`-derived value,
both passed by value, the message names the matching `EventHandler<T>`. It suggests plain
`EventHandler` for an `EventArgs` payload. Other signatures need a suitable event-arguments type.

## Example

Bad:

```csharp
using System;

public delegate void Poked(object sender, EventArgs e);

public class Button
{
    public event Poked Pressed;

    public void Press() => Pressed?.Invoke(this, EventArgs.Empty);
}
```

Corrected:

```csharp
using System;

public class Button
{
    public event EventHandler Pressed;

    public void Press() => Pressed?.Invoke(this, EventArgs.Empty);
}
```

## What is not reported

Overrides and interface implementations are excluded; change the event declared on the base class
or interface instead. Generated code is excluded. The rule reports nothing when the project has
no `EventHandler<T>` available.

## How to fix violations

Replace the delegate with the handler type named in the diagnostic. If the signature differs,
put the event's data in an `EventArgs`-derived class and update the code that raises and handles it.
Check variables and subscriptions that name the old delegate type, then remove that delegate if
it has no remaining uses. Changing a public event type breaks callers compiled against the old type.

There is no code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets it
to `error`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2304.severity = error
```

Accepted values are `none`, `silent`, `suggestion`, `warning`, and `error`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an external API requires the delegate type or a published event cannot change
compatibly. If the subscriber's return value is essential, consider a callback instead of an event.
