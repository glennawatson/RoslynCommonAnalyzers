# SST2305 — Collection properties should not be settable

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A non-private property exposes a mutable collection through a `set` accessor that is not private.
A getter already lets callers change the collection's contents. A setter also lets them replace
the whole collection, leaving other code or event subscriptions attached to the old instance.

The rule covers arrays and types implementing `ICollection`, `IList`, or `IDictionary`, including
their generic forms and `ISet<T>`. Examples include `List<T>`, `Dictionary<TKey, TValue>`, and `HashSet<T>`.
Static properties and explicitly declared properties in records are included.

## Example

Bad:

```csharp
using System.Collections.Generic;

public sealed class Basket
{
    public List<int> Items { get; set; } = new List<int>();
}
```

Corrected:

```csharp
using System.Collections.Generic;

public sealed class Basket
{
    public List<int> Items { get; } = new List<int>();
}
```

Callers can still use `basket.Items.Add(1)` and `basket.Items.Clear()`.

## What is not reported

- Get-only properties, `init` accessors, private properties, `private set`, and `required` properties.
- A property, setter, or declaring type with attributes.
- Overrides and interface implementations. The base or interface declaration can be reported instead.
- Properties generated from positional record parameters.
- Collections exposed only as `IEnumerable<T>` or read-only interfaces, immutable and frozen
  collections, and `ReadOnly*` wrappers in `System.Collections.ObjectModel`.
- A property inside a private nested type when it is assigned through a member access within the
  enclosing type.

## Code fix

The fix removes the entire setter, including its body and attached comments. It leaves the getter,
initializer, and backing fields in place, and supports Fix All.

It does not update assignments to the property. Those assignments can stop compiling; replace them
with collection operations, or provide a method that controls replacement. Use `private set` or
`init` manually when replacement belongs inside the type or only during construction.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets it
to `error`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2305.severity = error
```

Accepted values are `none`, `silent`, `suggestion`, `warning`, and `error`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a serializer, binding framework, or public API requires collection replacement through
a setter. Also suppress when replacement is intentional and the type handles references and
subscriptions to the old collection.

## Related rules

[PSH1017](PSH1017.md) reports collection getters that allocate a fresh copy on each read. Removing
a setter does not address that getter behavior.
