# SST2306 — Return an empty collection instead of null

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | Yes, for supported return types |
| Default | Enabled |

## Cause

A method, local function, property getter, or indexer returns a literal `null` where its declared
return type is a collection. The rule covers `return null`, expression bodies, and a null branch
directly inside a returned conditional expression. Parentheses around these expressions are allowed.

Returning an empty collection lets callers iterate or count the result without a null check.

## Example

Bad:

```csharp
using System.Collections.Generic;

public sealed class Store
{
    public IReadOnlyList<int> Values() => null;
}
```

Corrected:

```csharp
using System;
using System.Collections.Generic;

public sealed class Store
{
    public IReadOnlyList<int> Values() => Array.Empty<int>();
}
```

## What is not reported

- Return types explicitly marked nullable, such as `IEnumerable<int>?` or `int[]?`.
- Strings, `ref struct` types such as `Span<T>`, and generic type parameters.
- Async members, `Task<T>` and `ValueTask<T>` returns, lambdas, and anonymous methods.
- Members without bodies, or a returned variable that might contain null rather than the literal `null`.

Collections include arrays and types implementing `IEnumerable`.

## Code fix

The fix replaces the null literal and keeps its surrounding comments. It formats the replacement,
adds namespace qualification where needed, and supports Fix All.

| Return type | Replacement |
| --- | --- |
| One-dimensional `T[]`, C# 12 or later | `[]` |
| One-dimensional `T[]`, earlier C# | `Array.Empty<T>()`, or `new T[0]` if that API is unavailable |
| `IEnumerable<T>`, `ICollection<T>`, `IList<T>`, `IReadOnlyCollection<T>`, `IReadOnlyList<T>` | `Array.Empty<T>()`, with the same fallback |
| Non-generic `IEnumerable` | `Array.Empty<object>()`, or `new object[0]` |
| `ISet<T>`, `IReadOnlySet<T>` | `new HashSet<T>()` |
| `IDictionary<TKey, TValue>`, `IReadOnlyDictionary<TKey, TValue>` | `new Dictionary<TKey, TValue>()` |
| A non-abstract concrete collection with a public parameterless constructor | A call to that constructor, such as `new List<T>()` |

Other types can be reported without a fix, including multidimensional arrays and collections
without a supported constructor. Conditional branches have no fix below C# 9. A replacement that
cannot resolve to a type in the project is not offered.

`Array.Empty<T>()` reuses an empty array. Constructing a list, set, or dictionary creates a new object.
An empty array returned as `ICollection<T>` or `IList<T>` cannot accept added items; use a mutable
collection manually if callers need to add to the result. For a custom collection, check that its
parameterless constructor creates an empty result.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets it
to `error`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2306.severity = error
```

Accepted values are `none`, `silent`, `suggestion`, `warning`, and `error`.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when null has a documented meaning distinct from an empty result, or changing that meaning
would break callers. Prefer a nullable return type to make that contract visible in C# 8 or later.
