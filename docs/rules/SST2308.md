# SST2308 — Obsolete attributes should explain what to use instead

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `System.ObsoleteAttribute` has no message, or its message is null, empty or only whitespace.
This includes blank messages supplied through constants. Setting `DiagnosticId`, `UrlFormat` or
the error flag does not supply a message.

## How to fix violations

Tell callers what to use instead. If there is no replacement, explain why they should stop using
the member.

Bad:

```csharp
using System;

public sealed class Worker
{
    [Obsolete]
    public void Run() { }

    public void Run(int retries) { }
}
```

Corrected:

```csharp
using System;

public sealed class Worker
{
    [Obsolete("Use Run(int retries) instead.")]
    public void Run() { }

    public void Run(int retries) { }
}
```

There is no code fix.

The rule checks that a message contains text; it cannot judge whether the advice is useful.
It ignores generated code and unrelated attributes also named `Obsolete`.

## Configuration

The default severity is `warning`. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2308.severity = error
```

Use `none` to disable the rule. There are no rule-specific options.

## When to suppress

Suppress it when you must preserve an attribute supplied by an external contract and cannot add
a message. Keeping a member for compatibility is not a reason to omit migration advice.
