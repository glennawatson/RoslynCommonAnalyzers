# SST2309 — Use an overload instead of an optional parameter

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A method or constructor visible outside its assembly declares a parameter with a default value.
This includes extension methods and protected methods that callers in another assembly can use.

The compiler copies an omitted argument's default into the caller. If a library changes that
default, callers keep using their compiled value until they are rebuilt.

## How to fix violations

Add an overload that supplies the default, then remove the default from the full parameter list.
This keeps the choice of default inside the library.

Bad:

```csharp
public class Client
{
    public void Send(string request, int timeout = 30) { }
}
```

Corrected:

```csharp
public class Client
{
    public void Send(string request) => Send(request, 30);

    public void Send(string request, int timeout) { }
}
```

There is no code fix.

## What is not reported

- Caller-info parameters marked with `CallerMemberName`, `CallerFilePath`, `CallerLineNumber` or
  `CallerArgumentExpression`. These parameters need defaults for the compiler to supply caller details.
- Overrides and interface implementations. The interface or base declaration can still be reported.
- Primary constructors, including positional record constructors.
- Parameters without an explicit default, including `params` arrays.
- Members that are not visible outside the assembly, and generated code.

## Configuration

The default severity is `warning`. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2309.severity = error
```

Use `none` to disable the rule. There are no rule-specific options.

## When to suppress

Disable it for an application or library that always rebuilds and ships with all its callers.
Suppress an individual member when its optional parameters are part of a contract you must preserve.
