# SST2310 — Deprecated code should be removed

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A declaration has `System.ObsoleteAttribute`. A message, error flag, `DiagnosticId` or `UrlFormat`
does not exempt it. The rule also reports private members and overrides with their own attribute.

This is a reminder to finish removing deprecated code. It does not check whether callers still
need the declaration, so a diagnostic alone is not evidence that deletion is safe.

## How to fix violations

Migrate callers to the replacement, then remove the obsolete declaration when compatibility allows it.

Bad, when all callers have migrated:

```csharp
using System;

public sealed class Worker
{
    [Obsolete("Use Run(int retries) instead.")]
    public void Run() => Run(3);

    public void Run(int retries) { }
}
```

Corrected:

```csharp
public sealed class Worker
{
    public void Run(int retries) { }
}
```

Removing only the attribute hides the deprecation without completing the migration.
There is no code fix.

The rule reports declarations in your source, not calls to obsolete members in other libraries.
It ignores generated code and unrelated attributes also named `Obsolete`.

## Configuration

The default severity is `warning`. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2310.severity = error
```

Use `none` to disable the rule. There are no rule-specific options.

## When to suppress

Suppress a declaration while callers still need it. Disable the rule for a library whose support
policy requires keeping deprecated APIs.

For those libraries, [SST2308](SST2308.md) checks migration messages and [SST2314](SST2314.md) checks
diagnostic IDs on supported frameworks. Neither requires removing the API.
