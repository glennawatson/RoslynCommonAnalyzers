# SST2311 — Visible constants should be static readonly

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `const` field is visible outside its assembly. This includes public constants in visible types
and interfaces, and protected or protected internal constants in visible types that can be inherited.
Each constant in a declaration is reported separately.

The compiler copies a constant's value into code that uses it. Changing a library's constant does
not change the value used by callers that have already been compiled.

## How to fix violations

Use `static readonly` when callers can read the value at run time.

Bad:

```csharp
public class Limits
{
    public const int Maximum = 100;
}
```

Corrected:

```csharp
public class Limits
{
    public static readonly int Maximum = 100;
}
```

A `static readonly` field is read from the library at run time. Replacing a constant this way still
requires rebuilding existing callers to remove their copied values.

There is no code fix.

## What is not reported

- Private, internal and private protected constants.
- Constants inside types that are not visible outside the assembly.
- Protected and protected internal constants in sealed types.
- Local constants, enum members, `static readonly` fields and generated code.

## Configuration

The default severity is `warning`. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2311.severity = error
```

Use `none` to disable the rule. There are no rule-specific options.

## When to suppress

Keep the constant and suppress the rule if callers need a compile-time value. Attribute arguments,
`case` labels, optional parameter defaults, other constants and fixed-size buffer declarations can
require one. Replacing it with `static readonly` can break those uses.

Suppression also makes sense for a value that is part of a fixed public contract and will never change.
