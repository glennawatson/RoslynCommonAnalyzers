# SST2312 — Types should be declared in a named namespace

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A class, struct, interface, enum, record or record struct is declared outside any namespace or
containing type. This is the global namespace. The rule applies at every accessibility level and
reports each part of a partial type separately.

A named namespace helps keep your type names from colliding with names in other code.

## How to fix violations

Choose a namespace and move all parts of the type into it. Update references to the type as needed.

Bad:

```csharp
public class Widget
{
}
```

Corrected, using C# 10 or later:

```csharp
namespace Vendor.Widgets;

public class Widget
{
}
```

For older C# versions, place the type inside a `namespace Vendor.Widgets { }` block.
There is no code fix.

## What is not reported

- Delegates and nested types.
- Types in either block-scoped or file-scoped namespaces.
- The `Program` class created for top-level statements, including an explicit partial declaration
  that joins it. Keep that partial declaration in the global namespace; moving it creates a different type.
- Generated code.

## Configuration

The default severity is `warning`. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2312.severity = error
```

Use `none` to disable the rule. There are no rule-specific options.

## When to suppress

Suppress it when a public type must keep its full name for compatibility, or when a tool requires
a type in the global namespace. Moving an existing public type into a namespace changes its name
for every caller.
