# SST2314 — Obsolete attributes should carry a DiagnosticId

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |
| Requires | A settable `ObsoleteAttribute.DiagnosticId`, available in .NET 5 and later |

## Cause

A `System.ObsoleteAttribute` has a nonblank message but does not set `DiagnosticId`.
Setting the error flag or `UrlFormat` does not satisfy the rule.

A custom diagnostic ID lets callers change the severity of one deprecation or suppress it without
hiding unrelated deprecations.

## How to fix violations

Choose an ID for the deprecation and keep it stable for callers.

Bad:

```csharp
using System;

public sealed class Worker
{
    [Obsolete("Use Run(int retries) instead.")]
    public void Run() { }

    public void Run(int retries) { }
}
```

Corrected on .NET 5 or later:

```csharp
using System;

public sealed class Worker
{
    [Obsolete("Use Run(int retries) instead.", DiagnosticId = "ACME001")]
    public void Run() { }

    public void Run(int retries) { }
}
```

You can also set `UrlFormat` to a migration guide URL containing `{0}`, which is replaced with the
ID. That property is optional. The rule checks whether `DiagnosticId` is assigned; it does not
validate the assigned value or check that IDs are unique.

There is no code fix.

## What is not reported

- Attributes with no message or a null, empty or whitespace-only message. [SST2308](SST2308.md)
  reports those instead.
- Targets where `ObsoleteAttribute` has no settable `DiagnosticId`, including .NET Framework and
  .NET Standard 2.0.
- Generated code and unrelated attributes also named `Obsolete`.

## Configuration

The rule is enabled as a warning by default on supported targets. There are no rule-specific options.
To disable it for source shared with older targets:

```ini
[*.cs]
dotnet_diagnostic.SST2314.severity = none
```

Use `warning` to enable it, or `error` to make violations fail the build.

## When to suppress

Suppress it when the same source must compile for targets both with and without the property.
For example, adding `DiagnosticId` to source shared by `net462` and `net8.0` breaks the older target.
If you want to keep the rule enabled, use conditional compilation to include the property only on
supported targets. Keep the migration message on every target.
