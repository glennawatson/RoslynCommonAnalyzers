# SST2315 — A type that owns a disposable should be disposable

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | Yes, for supported fields and properties |
| Default | Enabled |

## Cause

A class, struct or record keeps a disposable object it creates, but implements neither
`IDisposable` nor `IAsyncDisposable`. Without a disposal interface, callers using those interfaces
cannot ask the owner to release its resources.

The rule reports these forms of ownership:

- An instance field or auto-property initialized by a static factory call, such as `File.OpenRead`.
- An instance auto-property initialized with `new`.
- An instance collection field initialized with `new`, whose type implements `ICollection<T>` for a
  disposable reference type, with a call such as `_items.Add(new Resource())` in the same type declaration.

## How to fix violations

Implement the appropriate disposal interface and release the objects you own.

Bad:

```csharp
using System.IO;

public sealed class Reader
{
    private readonly Stream _stream = File.OpenRead("data.bin");
}
```

Corrected:

```csharp
using System;
using System.IO;

public sealed class Reader : IDisposable
{
    private readonly Stream _stream = File.OpenRead("data.bin");

    public void Dispose()
    {
        _stream.Dispose();
    }
}
```

For an owned collection, dispose each element. For objects that support only asynchronous disposal,
implement `IAsyncDisposable` and await their disposal.

## Code fix

The fix adds `IDisposable` and appends a public `void Dispose()` method. The method calls `.Dispose()`
on each detected owned field or property. It formats the edited type and keeps existing members.

The fix is available only when all detected owned members support synchronous disposal. It is not
offered for owned collections, objects that support only asynchronous disposal, or declarations
with directives such as `#if` or `#region` inside their braces.

Review the generated method: it adds no null checks or protection against repeated disposal. If a
`Dispose()` method already exists, merge the cleanup manually. Members that expose disposal only
through an explicit interface implementation also need manual calls through that interface.

## What is not reported

- Types already implementing either disposal interface, and `ref struct` types.
- Disposable fields initialized directly with `new`, except the collection case above.
- Members assigned in a constructor or supplied through constructor parameters.
- Instance factory calls, static members, disposable value types and `Task` objects.
- Generated code.

An unreported member can still need disposal; these exclusions are not an ownership check.

## Configuration

The default severity is `warning`. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2315.severity = error
```

Use `none` to disable the rule. There are no rule-specific options.

## When to suppress

Suppress it when a factory returns a shared object whose lifetime is managed elsewhere, or another
owner is explicitly responsible for cleanup. Document that ownership so callers do not dispose a
shared resource by mistake.
