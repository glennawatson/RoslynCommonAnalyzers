# SST2317 — Wrap an owned native handle in a SafeHandle

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A class or struct implements `IDisposable`, declares no finalizer of its own, and passes a raw
pointer field directly to a call inside a method named `Dispose` or `DisposeAsync`.
The field can be `IntPtr`, `UIntPtr`, their `nint` or `nuint` forms, or a C# pointer type.

The check considers only the first instance field with one of those types. It does not prove that
the call releases the pointer or that the type owns it. A type implementing only `IAsyncDisposable`
is not reported. The rule reports nothing when `SafeHandle` is unavailable in the project.

## How to fix violations

Wrap an owned native resource in a `SafeHandle` that knows how to release it. This provides fallback
cleanup if a caller forgets `Dispose()`; callers should still dispose promptly.

Bad:

```csharp
using System;
using System.Runtime.InteropServices;

public sealed class Buffer : IDisposable
{
    private IntPtr _handle = Marshal.AllocHGlobal(8);

    public void Dispose() => Marshal.FreeHGlobal(_handle);
}
```

Corrected:

```csharp
using System;
using System.Runtime.InteropServices;
using Microsoft.Win32.SafeHandles;

public sealed class Buffer : IDisposable
{
    private readonly HGlobalHandle _handle = new HGlobalHandle();

    public void Dispose() => _handle.Dispose();
}

internal sealed class HGlobalHandle : SafeHandleZeroOrMinusOneIsInvalid
{
    public HGlobalHandle() : base(ownsHandle: true)
    {
        SetHandle(Marshal.AllocHGlobal(8));
    }

    protected override bool ReleaseHandle()
    {
        Marshal.FreeHGlobal(handle);
        return true;
    }
}
```

Use an existing wrapper, such as `SafeFileHandle`, when it matches the resource. A custom wrapper
must release the handle with the API that matches its allocation. Changing to another raw allocation
API alone does not provide fallback cleanup.

There is no code fix.

## Configuration

The default severity is `warning`. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2317.severity = error
```

Use `none` to disable the rule. There are no rule-specific options.

## When to suppress

Suppress it when the field holds a borrowed handle or an opaque identifier and another owner controls
its lifetime. A call that only logs or inspects the field can trigger the check; do not add ownership
and release someone else's resource to satisfy it.
