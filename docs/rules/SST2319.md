# SST2319 -- An optional parameter whose default can never be used

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A method has an optional parameter, and another overload in the same type takes exactly the parameters
before the first optional one. Those parameters must have the same types and `ref`, `in`, or `out`
modifiers. The diagnostic marks the first optional parameter.

In this example, `Log("hello")` calls the shorter overload, so it never uses the default for `echo`.

```csharp
public sealed class Logger
{
    public void Log(string message) { }

    public void Log(string message, bool echo = false) { }
}
```

An optional parameter without a matching shorter overload is not reported. Constructors and `params`
arrays without an explicit default are also outside this rule.

## How to fix violations

Remove the unused default so callers must supply the argument when choosing the longer overload:

```csharp
public sealed class Logger
{
    public void Log(string message) { }

    public void Log(string message, bool echo) { }
}
```

You can instead rename or redesign the overloads. Check callers before changing an existing public API.
There is no code fix.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST2319.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an existing public API must retain its optional parameter for compatibility, or when a
caller can still select the longer overload while omitting that argument, such as by supplying a later
named argument. The rule compares declarations; it does not check every possible call.
