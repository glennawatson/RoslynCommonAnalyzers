# SST2320 -- An interface inherits the same member from two interfaces

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An interface directly inherits at least two interfaces, and its base interfaces contain separate
declarations of the same method, property, or event with a matching signature. The interface itself
compiles, but accessing the duplicated member through it can cause an ambiguity error.

```csharp
public interface ILeft { string Name { get; } }
public interface IRight { string Name { get; } }

public interface IBoth : ILeft, IRight { }
```

Here, a caller cannot read `Name` through an `IBoth` value without choosing a base interface.
There is no report when both inheritance paths lead to one shared declaration, when the signatures
differ, or when the derived interface declares a member with the same name itself.

## How to fix violations

Declare the member on the derived interface with `new`:

```csharp
public interface ILeft { string Name { get; } }
public interface IRight { string Name { get; } }

public interface IBoth : ILeft, IRight
{
    new string Name { get; }
}
```

This gives callers one `IBoth.Name` to use. It adds a declaration rather than selecting one of the base
members, so check classes that implement the interfaces explicitly. Another option is to move the
shared member to a common base interface.

There is no code fix.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST2320.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the two inherited members have different meanings and callers are expected to choose a
base interface explicitly, or when changing a published interface would break its implementations.
