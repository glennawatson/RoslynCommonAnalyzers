# SST2321 - Do not terminate the process from library code

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A class library calls `System.Environment.Exit` or `System.Environment.FailFast`. Both end the entire
host process, including unrelated requests or work using the same library.

```csharp
using System;

public sealed class Worker
{
    public void Panic()
    {
        Environment.FailFast("Unrecoverable failure");
    }
}
```

The rule applies to library output, not executable output. It reports calls written with a type name
or alias, including `System.Environment.Exit(1)`. An unqualified call imported with `using static` is
not reported. Methods named `Exit` or `FailFast` on other types are not reported.

## How to fix violations

Throw an exception that describes the failure and let the caller decide how to respond:

```csharp
using System;

public sealed class Worker
{
    public void Panic()
    {
        throw new InvalidOperationException("Unrecoverable failure");
    }
}
```

If the library is responsible for stopping a hosted application, request an orderly shutdown through
`IHostApplicationLifetime.StopApplication()`. The diagnostic suggests that API when the project
references it.

There is no code fix.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST2321.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress for a dedicated process-control library whose documented purpose is to stop its host, or for
a fatal corruption path where continuing or running cleanup would be unsafe. Ordinary invalid input
should be reported to the caller instead.
