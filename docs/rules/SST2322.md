# SST2322 — Readonly fields should not expose a mutable collection

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An instance `readonly` field exposes a mutable collection through `public`, `internal`, `protected`,
or `protected internal` access. `readonly` stops callers from replacing the field's value. It does not
stop them from changing the collection's contents.

```csharp
using System.Collections.Generic;

public class Order
{
    public readonly List<string> Lines = new();
}
```

A caller can still use `order.Lines.Add(...)` or `order.Lines.Clear()`.

The rule covers arrays and these declared collection types:

- Generic `List`, `Dictionary`, `HashSet`, `SortedDictionary`, `SortedList`, `SortedSet`, `Queue`,
  `Stack`, and `LinkedList`.
- Generic `ICollection`, `IList`, `IDictionary`, and `ISet`.
- `Collection<T>`, `KeyedCollection<TKey, TItem>`, and `ObservableCollection<T>`.
- Non-generic `ArrayList`, `Hashtable`, `ICollection`, `IDictionary`, and `IList`.

Private and `private protected` fields, static fields, and fields without `readonly` are not reported.
Read-only, immutable, frozen, concurrent, and user-defined collection types are not reported either.
This does not prove that an unreported type is immutable.

## How to fix violations

Keep the mutable collection private and expose a read-only wrapper:

```csharp
using System.Collections.Generic;
using System.Collections.ObjectModel;

public class Order
{
    private readonly List<string> _lines = new();

    public Order() => Lines = _lines.AsReadOnly();

    public ReadOnlyCollection<string> Lines { get; }
}
```

The wrapper reflects changes made by `Order` but prevents callers from changing the list through it.
Returning the list itself as `IReadOnlyList<string>` hides its write methods, but callers can cast it
back to `List<string>`. Return a copy or an immutable collection when callers need a fixed snapshot.

There is no code fix.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST2322.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when callers are deliberately allowed to edit the shared collection and the API documents
who controls its contents, or when replacing a published field would break compatibility.
