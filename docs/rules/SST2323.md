# SST2323 - Express an all-abstract class as an interface

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An abstract class inherits only from `object`, declares at least one member, and every declared member
is public and abstract. It supplies no state or implementation for derived classes to share.

```csharp
public abstract class Shape
{
    public abstract double Area();

    public abstract void Draw();
}
```

A class can inherit from only one class but implement several interfaces. Using an interface for this
contract lets each implementation choose its own base class.

The rule does not report records, empty classes, or classes with a field, an explicit constructor,
a nested type, an implemented member, a non-public abstract member, or a base class other than `object`.
For a partial class, members in every part count. The rule applies only to C# 8 and later.

## How to fix violations

Replace the abstract class with an interface:

```csharp
public interface IShape
{
    double Area();

    void Draw();
}
```

Update callers to use the interface. In implementing classes, remove `override` from members that
implemented the old abstract members, unless they also override another base member. This changes
the API and can break existing consumers.

There is no code fix.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST2323.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a framework requires a class base, or when the abstract class is a published API whose
inheritance contract must remain compatible.
