# SST2325 — Validate an async method's arguments before its first await

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An `async` method checks a parameter after an `await`. Invalid input can start work or wait for an
operation before the method rejects it.

```csharp
using System;
using System.Threading.Tasks;

public sealed class Store
{
    public async Task SaveAsync(string name)
    {
        await Task.Yield();
        if (name is null)
        {
            throw new ArgumentNullException(nameof(name));
        }
    }
}
```

The rule checks statements directly in the method body. It recognizes `await WorkAsync();`, an
assignment from `await`, or a local variable initialized from `await`. A later check is reported when
it names a parameter and either:

- Uses an `if` without `else` whose body ends by throwing a newly created `Argument...Exception`.
- Calls an `Argument...Exception.ThrowIf...` helper, such as `ArgumentNullException.ThrowIfNull(name)`.

Custom exception types with those names also match. Checks before the first recognized `await`,
checks of local copies instead of parameters, and `async void` methods are not reported. Awaits inside
conditions or loops do not establish the boundary. Checks inside nested blocks, lambdas, or local
functions are outside the scan.

## How to fix violations

Move validation before the first `await`:

```csharp
using System;
using System.Threading.Tasks;

public sealed class Store
{
    public async Task SaveAsync(string name)
    {
        if (name is null)
        {
            throw new ArgumentNullException(nameof(name));
        }

        await Task.Yield();
    }
}
```

This rejects bad input before starting the awaited work. Exceptions from an `async Task` method are
still stored in the returned task, even when thrown before its first `await`. To throw directly from
the method call, put validation in a method without `async` that returns the task from a separate
async implementation.

An async method resumes when its awaited operation completes; the caller does not need to await the
returned task to make that happen.

There is no code fix.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST2325.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when validation needs information obtained asynchronously, or must run after acquiring an
asynchronous lock to read shared state safely. Keep checks that need neither ahead of the await.
