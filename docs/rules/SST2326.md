# SST2326 — Do not narrow an interface reference to a concrete implementation type

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Info |
| Code fix | No |
| Default | Enabled |

## Cause

Code casts or tests an interface value against a non-abstract class from another assembly that
implements that interface. The rule covers explicit casts, `as`, and plain `is` type tests with or
without a variable.

```csharp
using System.Collections.Generic;

public class Consumer
{
    public int Count(IEnumerable<int> items)
    {
        var list = (List<int>)items;
        return list.Count;
    }
}
```

The cast fails if the caller supplies another implementation, such as an array. An `as` cast would
return `null`, and an `is` test would take a different branch.

## What is not reported

- Classes declared in the same assembly, or types listed in `allowed_types`.
- Casts to interfaces, abstract classes, structs, or classes that do not implement the source interface.
- Values declared as `object`, `dynamic`, a class, or a type parameter, even one constrained to an interface.
- Negated or property patterns, such as `items is not List<int>` or `items is List<int> { Count: 0 }`.

## How to fix violations

Use the interface's members. If the operation needs more capabilities, accept an interface that
provides them:

```csharp
using System.Collections.Generic;

public class Consumer
{
    public int Count(ICollection<int> items) => items.Count;
}
```

Update callers when changing the parameter type. If you need to keep `IEnumerable<int>`, use an
operation that supports any enumerable, such as `Enumerable.Count`, while accounting for the cost of
counting its items.

There is no code fix.

## Configuration

The rule is enabled by default as a suggestion (`Info`).

```ini
[*.cs]
dotnet_diagnostic.SST2326.severity = suggestion
stylesharp.SST2326.allowed_types = System.Collections.Generic.List`1
```

`stylesharp.SST2326.allowed_types` is a comma-separated list of fully qualified type metadata names.
Its default is empty: no external types are exempt. The example exempts every `List<T>`. For generic
types, use a backtick followed by the number of type parameters, such as ``List`1`` or ``Dictionary`2``.
Use `+` between containing and nested type names. Spaces around entries are ignored; unknown names
have no effect.

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress a deliberate optimization for a known implementation when other implementations still have
a correct fallback. Use `allowed_types` when that decision applies throughout the configured files.
Suppression is also reasonable when an external API guarantees the concrete type but returns an interface.
