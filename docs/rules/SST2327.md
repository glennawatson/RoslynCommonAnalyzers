# SST2327 — Do not branch on a type's own runtime type

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An instance checks whether `this` is a particular named class. A base class that chooses behavior this
way needs another branch whenever a new derived class needs different behavior.

```csharp
public class Animal
{
    public string Speak() => this is Dog ? "woof" : "";
}

public class Dog : Animal { }
```

The rule reports `this is Dog`, `this is Dog dog`, `this as Dog`, and comparisons between
`this.GetType()` and `typeof(Dog)` using `==` or `!=` in either order. The named class can be abstract.

It does not report checks against interfaces or type parameters, checks on another object, negated
or property patterns, or a `GetType()` call without an explicit `this.`.

## How to fix violations

Put the behavior in a virtual member and override it in each derived class that needs different behavior:

```csharp
public class Animal
{
    public virtual string Speak() => "";
}

public class Dog : Animal
{
    public override string Speak() => "woof";
}
```

Use an abstract member instead if every derived class must supply an implementation. Check exact-type
comparisons carefully: an override is also inherited by further derived classes, while
`GetType() == typeof(Dog)` accepts only `Dog` itself.

There is no code fix.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST2327.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when exact runtime type is part of the contract, such as an equality check, or when an
existing type hierarchy cannot be changed and a local type check is required for compatibility.
