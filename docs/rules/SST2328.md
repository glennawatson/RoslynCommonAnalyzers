# SST2328 — Do not expose a raw native pointer handle

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An instance field or property of type `IntPtr`, `UIntPtr`, `nint`, or `nuint` is declared `public`,
`protected`, or `protected internal`. A raw handle lets callers keep using a resource after it has
been released or release it through the wrong API.

```csharp
using System;

public sealed class NativeFile
{
    public IntPtr Handle { get; }

    public NativeFile(IntPtr handle) => Handle = handle;
}
```

Get-only properties and properties with private setters are reported too. The rule applies to classes,
including abstract classes, structs, and records. It also covers the public property created by a
positional record parameter. It checks the member's declared access even inside a non-public type.

Private, internal, and `private protected` members are not reported. Neither are static members,
overrides, indexers, interface declarations, or explicit interface implementations. Public implicit
interface implementations can still be reported.

## How to fix violations

Use a suitable `SafeHandle` type to represent the resource:

```csharp
using Microsoft.Win32.SafeHandles;

public sealed class NativeFile
{
    public SafeFileHandle Handle { get; }

    public NativeFile(SafeFileHandle handle) => Handle = handle;
}
```

[`SafeHandle`](https://learn.microsoft.com/dotnet/api/system.runtime.interopservices.safehandle)
manages release of a native resource. Use the wrapper for native calls that support it. Define who
disposes it: exposing a `SafeHandle` still lets callers dispose the wrapper, so expose operations on
the resource instead if callers must not close it. Use `SafeFileHandle` only for file handles, and
choose or implement a wrapper with the correct release operation for other resources.

There is no code fix.

## Configuration

The rule is enabled by default as a warning. It has no rule-specific options.

```ini
[*.cs]
dotnet_diagnostic.SST2328.severity = warning
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule.
See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress for an interop contract that requires a raw handle and documents its lifetime and ownership.
Also suppress when the value is a pointer-sized number rather than a resource handle; the rule cannot
distinguish those uses from the declared type.
