# SST2331 — Give enum members explicit values

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled (opt-in) |

## Cause

An enum has at least one member without an explicit value. The diagnostic appears once on the enum name. Empty enums and enums with a value on every member are not reported.

An implicit member gets zero if it is first, or one more than the member before it. Inserting or reordering members can therefore change values saved in files, databases, or messages.

## Example

Before:

```csharp
public enum Color
{
    Red,
    Green,
    Blue,
}
```

After:

```csharp
public enum Color
{
    Red = 0,
    Green = 1,
    Blue = 2,
}
```

## How to fix violations

The code fix adds each missing value using the number the compiler assigns to that member. It keeps existing explicit values, so the numeric mapping stays the same. Comments after a member name move after its added value, and line breaks are kept.

## Configuration

There are no rule-specific options. To enable the rule as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2331.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. Use `none` to disable it or `default` to restore the package default shown above.

## When to suppress

Leave the rule disabled, or suppress it for an enum, when its numbers never leave the running program and changing them has no effect on callers.
