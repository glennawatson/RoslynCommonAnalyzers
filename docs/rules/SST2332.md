# SST2332 — Make a construction-only property get-only

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An auto-property has `get; private set;` and no writes outside constructors of its declaring type. A property initializer is allowed, and a property with no writes is also reported.

A get-only property can still be assigned in its constructor or initializer. Removing the setter prevents other members from changing the value after construction.

## Example

Before:

```csharp
public class Counter
{
    public int Value { get; private set; }

    public Counter(int value) => Value = value;
}
```

After:

```csharp
public class Counter
{
    public int Value { get; }

    public Counter(int value) => Value = value;
}
```

## What is not reported

- A property written from a method, object initializer, lambda, or local function. This includes lambdas and local functions declared inside a constructor.
- A property with an accessor body, an `init` accessor, or a setter that is not private.
- A property declared in a `partial` type.

## How to fix violations

The code fix removes the private setter and keeps the getter, property initializer, and constructor assignments. Attributes and comments attached to the removed setter are also removed; move any comment you need to keep before applying the fix.

## Configuration

There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2332.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. Use `none` to disable it or `default` to restore the package default shown above.

## When to suppress

Suppress the rule when a serializer or framework needs the private setter and calls it through reflection. Those writes are not visible as assignments in your code.
