# SST2333 — Provide the non-generic form of a generic comparison contract

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | Yes, except where directives occur inside the type |
| Default | Disabled (opt-in) |

## Cause

A class or struct visible outside its assembly implements a generic comparison or equality interface but lacks the matching non-generic interface or method. Inherited implementations count. Each missing counterpart produces a diagnostic.

| Generic interface | Required counterpart |
| --- | --- |
| `System.IComparable<T>` | `System.IComparable` |
| `System.Collections.Generic.IComparer<T>` | `System.Collections.IComparer` |
| `System.Collections.Generic.IEqualityComparer<T>` | `System.Collections.IEqualityComparer` |
| `System.IEquatable<T>` | An override of `object.Equals(object)` |

Code using a non-generic interface cannot call an implementation available only through its generic form. Likewise, calls to `object.Equals` do not automatically use `IEquatable<T>.Equals`.

Types hidden inside the assembly are not reported. A record's generated `Equals(object)` satisfies the equality requirement; other comparison interfaces still need their counterparts.

## Example

Before:

```csharp
using System.Collections.Generic;

public class IntComparer : IComparer<int>
{
    public int Compare(int x, int y) => x.CompareTo(y);
}
```

After:

```csharp
using System.Collections.Generic;

public class IntComparer : IComparer<int>, System.Collections.IComparer
{
    public int Compare(int x, int y) => x.CompareTo(y);

    int System.Collections.IComparer.Compare(object x, object y) =>
        ((IComparer<int>)this).Compare((int)x, (int)y);
}
```

## How to fix violations

The code fix adds the missing interface and explicit implementations that call your generic implementation. For `IEquatable<T>`, it adds only an `Equals(object)` override.

Review the generated handling of null and wrong types:

- `IComparable.CompareTo` throws `InvalidCastException` for null or a value that is not `T`. Adjust this to meet your comparison contract.
- The comparer methods cast their arguments to `T` before calling your implementation.
- The `Equals(object)` override returns false for null or a value that is not `T`. It does not add `GetHashCode()`; ensure equal values have equal hash codes.

The fix formats the edited type. It is not offered when directives such as `#if` or `#region` occur inside the type's braces. Add the members by hand in that case.

## Configuration

There are no rule-specific options. To enable the rule as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2333.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. Use `none` to disable it or `default` to restore the package default shown above.

## When to suppress

Leave the rule disabled or suppress it when callers deliberately use only generic comparison interfaces. Keep the equality warning when callers also rely on `object.Equals`.
