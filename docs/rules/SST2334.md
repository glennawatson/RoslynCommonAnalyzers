# SST2334 — Give a public type a debugger-display attribute

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled (opt-in) |

## Cause

A class, struct, or record visible outside its assembly has something to display but does not declare `[System.Diagnostics.DebuggerDisplay]`.

A type qualifies if it declares an instance field, a readable property that is neither an indexer nor an override, or its own `ToString()` override. Private members count, as do properties declared through record parameters.

Static types, empty types, and types with only constants, static members, indexers, write-only properties, or overriding properties are not reported. The rule also reports nothing if the project has no reference to `DebuggerDisplayAttribute`.

## Example

Before:

```csharp
public class Money
{
    public int Amount { get; set; }
}
```

After:

```csharp
[System.Diagnostics.DebuggerDisplay("Money: {Amount}")]
public class Money
{
    public int Amount { get; set; }
}
```

The debugger shows the type name and amount together, without requiring you to expand the object.

## How to fix violations

The code fix adds `[System.Diagnostics.DebuggerDisplay]` above the type, so no `using` is needed. It keeps existing attributes and leading comments.

The display string starts with the type's name. From the declaration being edited, the fix chooses the first public readable instance property, then another readable instance property, then an instance field. It skips explicit interface properties. If none is available, it uses `{ToString(),nq}`; `nq` tells the debugger to omit quotation marks.

Review the string and choose the members that best identify an instance. Properties declared only through record parameters are not selected by the fix.

## Configuration

There are no rule-specific options. To enable the rule as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2334.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. Use `none` to disable it or `default` to restore the package default shown above.

## When to suppress

Suppress the rule when the debugger's existing display is enough, or when the useful properties are costly to read or change state when read.
