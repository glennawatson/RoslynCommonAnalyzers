# SST2335 — Declare the same 'static' modifier on every part of a partial type

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | Yes |
| Default | Disabled (opt-in) |

## Cause

One declaration of a partial class includes `static`, while another omits it. Each declaration missing `static` is reported.

The combined class is static either way. Repeating the modifier makes that clear in every file.

## Example

Before:

```csharp
static partial class Widget
{
}

partial class Widget
{
}
```

After:

```csharp
static partial class Widget
{
}

static partial class Widget
{
}
```

## What is not reported

A class whose declarations all include `static`, or all omit it, is not reported. Classes with only one declaration and types other than classes are also excluded.

## How to fix violations

The code fix inserts `static` immediately before `partial` in the reported declaration. It preserves the class body, comments, and indentation. Fix All updates the reported declarations in the selected scope.

## Configuration

There are no rule-specific options. To enable the rule as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2335.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. Use `none` to disable it or `default` to restore the package default shown above.

## When to suppress

Leave the rule disabled when your team is comfortable declaring `static` on one part only. Suppress a report when a declaration is maintained by an external generator or template that you cannot change.
