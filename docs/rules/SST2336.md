# SST2336 — An attribute type should declare where it can be applied

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A non-abstract class derives from `System.Attribute` and has no `[AttributeUsage]` on itself or an intermediate base class. Abstract attribute classes are not reported.

Without a specific usage declaration, an attribute allows all targets, cannot be repeated on the same target, and is inherited by derived classes and overriding members. Declaring the intended targets lets the compiler reject misplaced attributes.

## Example

Before:

```csharp
using System;

internal sealed class MarkerAttribute : Attribute
{
}
```

After:

```csharp
using System;

[AttributeUsage(AttributeTargets.Method)]
internal sealed class MarkerAttribute : Attribute
{
}
```

## How to fix violations

Add `[AttributeUsage]` with the targets the attribute supports. Combine targets with `|`. Set `AllowMultiple = true` if repeated use is supported, or `Inherited = false` if derived classes and overriding members should not inherit it. The defaults are `AllowMultiple = false` and `Inherited = true`.

There is no code fix; you must choose the intended targets and behavior.

## Configuration

There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2336.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. Use `none` to disable it or `default` to restore the package default shown above.

## When to suppress

Suppress the rule when the default usage is intentional and you cannot edit the attribute declaration. Otherwise, state that choice with `[AttributeUsage(AttributeTargets.All)]`.
