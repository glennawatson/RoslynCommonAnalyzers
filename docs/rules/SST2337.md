# SST2337 — Remove a parameter the body never reads

| Item | Value |
| --- | --- |
| Package | StyleSharp.Analyzers |
| Category | Design |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A member declares a parameter whose name appears nowhere in its body.

```csharp
// 👎 reported
private int Compute(int used, int unused) => used;
```

## Rule description

A parameter the body never mentions is a promise the member does not keep. Every caller has to compute and
pass a value that is then discarded, and the next person to read the method has to prove for themselves that
it really does not matter. It is usually the residue of a change that removed the last use, and occasionally a
bug — the value that *should* have been read is sitting right there in the signature.

The test is by **name, not by binding**: a parameter is reported only when its identifier occurs nowhere in
the body, the expression body, or the constructor initializer. That makes a use inside a lambda, a local
function, a `nameof`, or a string interpolation count automatically, and it makes a shadowed name a silence
rather than a false report.

### What is not reported

Everything whose signature the author is not free to change:

- an `override`, `virtual`, or `abstract` member, and an interface implementation — implicit or explicit;
- a `partial` member, whose other part may read the parameter, and an `extern` one matching a native API;
- an **attribute constructor**, where every usage site depends on the parameter list;
- an **event-handler or framework callback shape** — a parameter typed `EventArgs`, `StreamingContext`,
  `DependencyObject`, `DependencyPropertyChangedEventArgs` or `AvaloniaPropertyChangedEventArgs` means a
  delegate chose the signature, and the unread parameter is the price of matching it;
- a method **handed on as a method group**, which must keep the delegate's shape rather than its own;
- a body that only `throw`s, which is a deliberate stub;
- a parameter named `_`, which already says it is unused.

Externally visible members are excluded by default — see below.

## Configuration

```ini
# Rule-specific
stylesharp.SST2337.unread_parameter_include_public_api = false

# Project-wide
stylesharp.unread_parameter_include_public_api = false
```

| Option | Values | Default | Effect |
| --- | --- | --- | --- |
| `unread_parameter_include_public_api` | `true`, `false` | `false` | Whether externally visible members are reported. |

Removing a parameter from a public member is a breaking change for every caller outside the assembly, so the
rule stays quiet there by default and asks only about code you can freely change. Turn it on in an
application, or while preparing a major version, to see the rest.

## How to fix violations

Remove the parameter and update the call sites — or use it, if the value it carries is the one the body
should have been reading.

There is **no code fix**. Deleting the parameter from the declaration alone would leave every call site
passing an argument that no longer exists, so the edit has to reach code the fix cannot see. Renaming the
parameter to `_` also silences the rule, and is the right answer when a signature must be kept but the value
genuinely is not wanted.

## Performance

The clean path is syntactic and never touches the semantic model: one pass over the body collects the
identifiers it mentions, and a parameter whose name is in that set is done. Only a parameter that is
mentioned nowhere — rare — is bound, and only then are the contract, accessibility and method-group checks
paid for.
