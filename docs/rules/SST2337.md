# SST2337 — Declare a fully known hierarchy as closed

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Enabled by default | **No** (opt-in) |
| Code fix | No |
| Applies to | C# 15 or later |

## Cause

An abstract class or record that cannot be reached from outside its assembly already has two or more
direct descendants in the compilation, and is not marked `closed`.

```csharp
internal abstract class GateState;

internal sealed class Shut : GateState;

internal sealed class Open : GateState;
```

## Rule description

A `closed` class can only be derived from inside the assembly that declares it, which fixes the set of
direct descendants at compile time. That is what lets a switch over the hierarchy be exhaustive
without a default arm:

```csharp
// 👍
internal closed class GateState;

internal sealed class Shut : GateState;

internal sealed class Open : GateState;

string Describe(GateState state) => state switch
{
    Shut => "shut",
    Open => "open",
    // No warning: every direct descendant is handled.
};
```

The benefit is not the modifier itself but what it does to the switches. Adding a third descendant
later turns every switch that has not been updated into a warning, instead of letting it fall through
to a default arm that silently returns the wrong answer.

## What is not reported

- **An externally visible type.** There, `closed` forbids derivation that callers may already depend
  on — a breaking change rather than a tidy-up. Only types that are internal, private, or nested
  inside such a type are reported.
- **A base with fewer than two direct descendants.** A single implementation gains nothing from
  exhaustiveness checking.
- **A concrete base**, or one already marked `closed`.

## Why it is opt-in

The rule is **disabled by default**. Whether a hierarchy is meant to stay open is a design decision,
and "every subtype happens to be in this assembly today" is not the same as "no more should be added
from elsewhere later". Enable it in `.editorconfig` when closing hierarchies is the house style:

```ini
dotnet_diagnostic.SST2337.severity = warning
```

## How to fix violations

Replace `abstract` with `closed` on the base declaration. The modifier is implicitly abstract, so the
two cannot be combined, and it cannot be used with `sealed` or `static`.

Derivation is not transitive: a non-closed descendant of a closed class can still be derived from
elsewhere. To extend exhaustiveness down the hierarchy, mark intermediate descendants `closed` too.
