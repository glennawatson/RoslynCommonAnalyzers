# SST2338 — Declare a hand-rolled discriminated type as a union

| Item | Value |
| --- | --- |
| Category | Design |
| Severity | Warning |
| Enabled by default | **No** (opt-in) |
| Code fix | No |
| Applies to | C# 15 or later, on a runtime with union support |

## Cause

A type holds an enum discriminator beside two or more differently typed nullable payloads.

```csharp
public sealed class Payload
{
    public PayloadKind Kind { get; set; }

    public string? Text { get; set; }

    public byte[]? Bytes { get; set; }
}
```

## Rule description

This is a discriminated union written by hand. The invariant it depends on — exactly one payload is
set, and it is the one the tag names — lives only in whatever code remembers to check it. Nothing
stops a caller reading `Text` when `Kind` is `Bytes`, or setting both, and the failure surfaces far
from the mistake as a null reference.

A union states the same shape in the type system:

```csharp
// 👍
public union Payload(string, byte[]);

string Describe(Payload payload) => payload switch
{
    string text => text,
    byte[] bytes => $"{bytes.Length} bytes",
};
```

The value is one of the case types, conversions from each case come for free, and the compiler checks
a `switch` over the cases for exhaustiveness.

## What is not reported

The shape being matched is deliberately narrow, because "a type with a tag and some nullable fields"
describes a great deal of ordinary code:

- Exactly **one** enum-typed member whose name ends in `Kind`, `Tag`, `Case`, `Discriminator`, or
  `Type`. Zero or several means the type is not modelling a single choice.
- **Two or more** payload members of *distinct* reference or nullable value types. One payload beside
  a tag is an optional value, not a choice between alternatives.
- The type is concrete, and does not already implement the union marker interface.
- **No payload is a value type**, unless `report_value_type_payloads` is turned on — see below.

The rule is also gated on the union marker interface resolving in the compilation, so it stays silent
where the target framework's runtime has no union support and the suggestion could not be taken.

## Value-typed payloads box

A union is a value type, but it stores its payload in a single `object` field. A value-typed case
therefore boxes on every construction:

```csharp
// 👎 not reported by default — Count and Ratio would box on every Reading
public sealed class Reading
{
    public ReadingKind Kind { get; set; }

    public int? Count { get; set; }

    public double? Ratio { get; set; }
}
```

The hand-rolled form here allocates nothing, so taking the suggestion would trade a non-allocating
type for one that allocates per instance — which bites hardest in exactly the hot, per-item types this
shape gets used for. One value-typed payload is enough to leave the whole type alone.

Set the option where the clarity is worth the boxing:

```ini
stylesharp.SST2338.report_value_type_payloads = true
```

| Option | Values | Default | Effect |
| --- | --- | --- | --- |
| `report_value_type_payloads` | `true`, `false` | `false` | Report a hand-rolled union whose payloads are value types, even though the union form boxes them. |

## Why it is opt-in

The rule is **disabled by default**. Reshaping a type into a union changes its public surface — every
construction site, every property read, and any serialization contract — so it is a migration rather
than a cleanup. Enable it in `.editorconfig` when that migration is one you want flagged:

```ini
dotnet_diagnostic.SST2338.severity = warning
```

## How to fix violations

Declare the alternatives as a union and replace the tag-plus-payload reads with a `switch` over the
case types. Where the payloads carry more than one value each, give each case its own record type
first and make those the union's cases.
