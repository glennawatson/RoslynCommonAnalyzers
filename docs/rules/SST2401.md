# SST2401 — Do not catch NullReferenceException

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A catch clause names `System.NullReferenceException`, or its exception filter mentions that type. This includes a filter such as `when (error is NullReferenceException)`.

A null reference exception means code tried to use a null value. Catching it can hide an unchecked value anywhere in the try block, including inside methods it calls.

Other exception types and a custom exception with the same name in another namespace are not reported.

## Example

Before:

```csharp
#nullable enable
using System;

public sealed class Printer
{
    public void PrintLength(string? value)
    {
        try
        {
            Console.WriteLine(value!.Length);
        }
        catch (NullReferenceException)
        {
            Console.WriteLine("Missing value");
        }
    }
}
```

After:

```csharp
#nullable enable
using System;

public sealed class Printer
{
    public void PrintLength(string? value)
    {
        if (value is null)
        {
            Console.WriteLine("Missing value");
            return;
        }

        Console.WriteLine(value.Length);
    }
}
```

## How to fix violations

Check the value before using it. If null violates the method's contract, reject the input or fix the code that supplies it.

There is no code fix; you must identify which value can be null and choose how to handle it.

## Configuration

There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2401.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. Use `none` to disable it or `default` to restore the package default shown above.

## When to suppress

Suppress a narrow handler when testing a documented exception, or when containing a failure from external code you cannot change. Keep enough information to diagnose that failure.
