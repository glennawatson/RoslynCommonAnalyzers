# SST2403 — Do not let 'this' escape from a constructor

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A constructor passes `this` as an argument, stores it in a static member or another object's member, or hands over a lambda that explicitly uses `this`. This can let other code use the object before its constructor finishes.

For example, an event subscription using `() => this.Refresh()` carries the object inside the callback. The event owner could run it immediately.

## Example

Before:

```csharp
public static class Registry
{
    public static void Add(object item) { }
}

public sealed class Widget
{
    public Widget()
    {
        Registry.Add(this);
        Name = "widget";
    }

    public string Name { get; }
}
```

After:

```csharp
public static class Registry
{
    public static void Add(object item) { }
}

public sealed class Widget
{
    private Widget() => Name = "widget";

    public string Name { get; }

    public static Widget Create()
    {
        var widget = new Widget();
        Registry.Add(widget);
        return widget;
    }
}
```

## What is not reported

- Accessing the object's own members, saving `this` in a local or its own instance state, or subscribing to its own event.
- Passing `this` to a method and assigning the returned value directly to an instance field or property.
- Passing `this` to a struct constructor and storing that struct directly in the object's own instance field. Creating a class in the same place is still reported.
- Calls to methods allowed by configuration.

The rule checks written uses of `this`. A callback that uses only an unqualified member name, such as `() => Refresh()`, is not reported. These exclusions do not prove that a called method or callback is safe during construction.

## How to fix violations

Pass the completed object to other code after construction, through a static creation method as above or an initialization method. Move external event subscriptions there too.

There is no code fix; moving this work changes how callers create or initialize the object.

## Configuration

To report violations as errors and allow selected methods:

```ini
[*.cs]
dotnet_diagnostic.SST2403.severity = error
stylesharp.SST2403.allowed_escape_methods = WhenActivated, ToProperty
```

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.SST2403.allowed_escape_methods` | Comma-separated method names | Empty |
| `stylesharp.allowed_escape_methods` | Comma-separated method names | Empty |

The rule-specific list replaces the project-wide list when present, even if it is empty. Spaces around names and empty entries are ignored. Names are case-sensitive and have no type or namespace prefix, so every method with that simple name is allowed, including extension methods.

Only allow a method after confirming that it cannot expose or use the unfinished object.

Severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. Use `none` to disable it or `default` to restore the package default shown above.

## When to suppress

Suppress a specific call when a framework requires registration during construction and guarantees that the object cannot be used until construction finishes. Use the method list for a trusted method used throughout the project.
