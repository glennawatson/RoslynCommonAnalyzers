# SST2405 — DebuggerDisplay should reference members that exist

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A literal string in a type's `[DebuggerDisplay]` attribute names a member that the type does not declare or inherit. The compiler accepts the string, but the debugger cannot show the requested value.

The rule checks names such as `{Amount}`, `{Amount,nq}` and `{Describe(),nq}`. Private and inherited members count. It skips longer expressions such as `{Items.Count}`, `{Items[0]}` and arithmetic, strings supplied through constants or other expressions, and attributes on fields or properties. It checks that a name exists, not whether a method call has the right arguments.

## Example

`Total` does not exist:

```csharp
using System.Diagnostics;

[DebuggerDisplay("Order {Total}")]
public sealed class Order
{
    public decimal Amount { get; }
}
```

Use the member's actual name:

```csharp
using System.Diagnostics;

[DebuggerDisplay("Order {Amount}")]
public sealed class Order
{
    public decimal Amount { get; }
}
```

There is no code fix; choose the member the debugger should display.

## Configuration

The rule is enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2405.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress only if you have checked that a debugger extension supplies the named value and the display works. For an ordinary missing or misspelled member, correct the string.
