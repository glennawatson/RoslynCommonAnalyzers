# SST2406 — A loop's stop condition should be able to change

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `while` or `for` condition reads local variables or parameters that the loop never updates. With no other way out, the loop can run forever or never run at all.

The rule checks simple conditions made from variables, literals and operators. Assignments, increments, decrements and arguments passed with `ref`, `out` or `in` count as updates. A `for` loop's update clause counts too.

## What is not reported

- Conditions containing calls, fields, properties or element access, such as `queue.Count > 0`.
- Loops containing `break`, `return`, `throw`, `goto`, `yield return` or `yield break`, even inside a nested loop or switch.
- Loops with a lambda, local function or `ref` alias in the body.
- Conditions with no variable reads, such as `while (true)`.

A `for` loop that declares and tests an unstepped counter is covered by [SST2411](SST2411.md), which can report even when the body contains a `break`.

## Example

The loop prints the same number without advancing:

```csharp
using System;

var limit = 3;
var index = 0;
while (index < limit)
{
    Console.WriteLine(index);
}
```

Update the value used by the condition:

```csharp
using System;

var limit = 3;
var index = 0;
while (index < limit)
{
    Console.WriteLine(index);
    index++;
}
```

There is no code fix; choose the correct update, exit or condition for the loop.

## Configuration

The rule is enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2406.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the loop deliberately runs until the process ends or a called method never returns. Use `while (true)` if it expresses that intent clearly.
