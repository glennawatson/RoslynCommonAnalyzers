# SST2407 — Declared events should be raised

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An event declared without `add` and `remove` accessors is never used as a value anywhere in the project. Adding or removing subscribers with `+=` or `-=` does not count as raising it. Subscribers can attach handlers, but those handlers receive no notification.

## What is not reported

- Events declared in interfaces, abstract or extern events, overrides, and events that implement interface members.
- Events with custom `add` and `remove` accessors or attributes targeted at their backing field with `[field: ...]`.
- Events used as values, including events copied to a local variable before invocation.

A value read with the same name elsewhere in the project also prevents a report, even if it refers to a different member. The absence of a diagnostic does not prove that an event is raised.

## Example

Nothing raises `Started`:

```csharp
#nullable enable
using System;

public sealed class Service
{
    public event EventHandler? Started;
}
```

Raise the event at the point it promises to notify subscribers about:

```csharp
#nullable enable
using System;

public sealed class Service
{
    public event EventHandler? Started;

    public void Start() => Started?.Invoke(this, EventArgs.Empty);
}
```

Remove the event if it has no purpose. There is no code fix; the rule cannot choose when to notify subscribers or whether to remove a public event.

## Configuration

The rule is enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2407.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress for an event retained to preserve a public API when its notification deliberately cannot occur. Document that behavior for subscribers.
