# SST2409 — Do not throw a general exception type

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `throw` directly constructs one of these types in the `System` namespace:

- `Exception`, `SystemException` or `ApplicationException`: these give callers too little information to catch a specific failure.
- `NullReferenceException`, `IndexOutOfRangeException` or `OutOfMemoryException`: throwing these yourself makes a deliberate check look like a runtime failure.

Both throw statements and throw expressions are checked. Rethrows, thrown variables, derived exception types and types in other namespaces are not reported.

## Example

A general exception hides the reason for failure:

```csharp
#nullable enable
using System;

public sealed class Validator
{
    public string Check(string? value) => value ?? throw new Exception("missing");
}
```

Choose the type that describes the failure:

```csharp
#nullable enable
using System;

public sealed class Validator
{
    public string Check(string? value) => value ?? throw new ArgumentNullException(nameof(value));
}
```

Use an existing type such as `InvalidOperationException` or `FileNotFoundException` when it fits. Define an exception derived from `Exception` for a failure that needs its own contract.

There is no code fix; the appropriate exception depends on what failed and what callers should catch.

## Configuration

The rule is enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2409.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress in a test that must simulate one of these exact exception types, or when an existing public contract requires that type. Keep the suppression limited to that throw.
