# SST2410 — A created disposable should be disposed

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes (`using` or `await using` declaration) |
| Default | Enabled |

## Cause

A local variable holds a reference type created with `new` that implements `IDisposable` or `IAsyncDisposable`. The method neither disposes it nor passes it elsewhere. Undisposed resources can leave files locked, connections open or timers running.

## What is not reported

- Values in `using` or `await using`, or values with a `Dispose` or `DisposeAsync` member reference.
- Values returned, assigned to another variable or member, passed to a method or constructor, added to a collection, or used inside a lambda or local function.
- Values on which a method returns a disposable reference type other than `Task` or its derived types. Such a method could return the same object and transfer responsibility for disposing it.
- Fields, disposable structs, `Task` and its derived types, and values obtained from factory calls such as `File.OpenRead(path)`.

These exclusions do not prove that disposal is correct. When you pass a resource elsewhere, check who is responsible for disposing it. A call returning an `int`, such as `stream.ReadByte()`, does not transfer the stream.

## Example

The stream is created and used without being disposed:

```csharp
using System.IO;

public sealed class Writer
{
    public void Write()
    {
        var stream = new MemoryStream();
        stream.WriteByte(1);
    }
}
```

Use a `using` declaration to dispose it when the scope ends, including when an exception leaves the scope:

```csharp
using System.IO;

public sealed class Writer
{
    public void Write()
    {
        using var stream = new MemoryStream();
        stream.WriteByte(1);
    }
}
```

## Code fix

The fix adds `using` to a declaration with one variable and no modifiers. It uses `await using` when the created type implements `IAsyncDisposable` and the containing method, local function or lambda is `async`. In other cases it uses `using` if the type implements `IDisposable`. An async-only disposable in a synchronous body is reported without a fix.

Declarations containing several variables are reported without a fix. The fix keeps the initializer and surrounding comments and formats the declaration. `using` declarations and `await using` require C# 8 or later; use a `using` statement for synchronous disposal on earlier language versions.

## Configuration

The rule is enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2410.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress in a focused test of undisposed behavior or a benchmark that deliberately measures creation without disposal. Arrange cleanup outside the measured operation where needed. A value held only by this method should otherwise be disposed here.
