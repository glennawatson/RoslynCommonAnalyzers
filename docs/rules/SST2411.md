# SST2411 — A for loop's counter should be advanced

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `for` loop declares a counter, reads it in the condition and never updates it in the body or update clause. A missing update, or an update to the wrong variable, can make the loop repeat the same work forever.

The condition must be a simple expression over locals and parameters. Calls, fields, properties and element access in the condition are skipped. A lambda, local function or `ref` alias in the body also prevents a report.

Assignments, increments, decrements and passing the counter with `ref`, `out` or `in` count as updates. When the header declares several variables, updating any declared variable read by the condition prevents a report. A `break` does not prevent this diagnostic: the tested counter still never advances. This differs from [SST2406](SST2406.md), which checks unchanged conditions.

## Example

The update clause is empty:

```csharp
using System;

var limit = 3;
for (var i = 0; i < limit;)
{
    Console.WriteLine(i);
}
```

Advance the counter:

```csharp
using System;

var limit = 3;
for (var i = 0; i < limit; i++)
{
    Console.WriteLine(i);
}
```

A `foreach` can remove the manual counter when you only need to visit each item. There is no code fix; choose the update or loop form that matches the intended work.

## Configuration

The rule is enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2411.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the declared value must stay fixed and a separate exit deliberately controls the loop. Prefer a `while` loop if it makes that intent clearer.
