# SST2413 — A for loop's body should be able to run

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `for` loop compares an integer counter's constant starting value with a constant bound, and the condition is false on the first check. The body never runs.

The rule checks `<`, `<=`, `>` and `>=` with one update: `++`, `--`, or `+=`/`-=` with a positive integer literal. The body must not also write to the counter. The update must move toward the bound; a conflicting direction is covered by [SST2412](SST2412.md).

Values supplied at runtime, including `items.Count`, are not reported. A collection being empty is a valid reason for a loop to do no work.

## Example

The counter starts beyond the bound:

```csharp
using System;

for (var i = 10; i < 5; i++)
{
    Console.WriteLine(i);
}
```

Choose a starting value and bound that describe the intended range:

```csharp
using System;

for (var i = 0; i < 5; i++)
{
    Console.WriteLine(i);
}
```

There is no code fix; the starting value, bound or comparison could be the mistake. Remove the loop if no work is intended.

## Configuration

The rule is enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2413.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress for a test that deliberately exercises an empty range, or shared source whose build-specific constants intentionally disable the loop. Otherwise correct or remove the unreachable work.
