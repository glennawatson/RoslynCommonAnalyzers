# SST2414 — Two branches should not share an implementation

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes, for switch statements and switch expressions |
| Default | Enabled |

## Cause

Two branches in an `if`/`else if` chain or a `switch` contain the same code, ignoring comments and whitespace. This can be a copy-and-paste mistake. Check whether one branch should do something different before merging them.

For `if` chains, the repeated bodies must contain at least two statements; the final `else` is not compared. Switch statements and switch expressions can report a single repeated statement or value. If [SST1476](SST1476.md) reports that every outcome shares one body, this rule does not add a second report.

## What is not reported

- Pairs involving a `default` section or an unguarded `_` arm.
- Switch statements containing `goto case` or `goto default`.
- Switch branches with a `when` condition or a pattern that declares a variable.
- Non-adjacent switch statement sections when merging them would move pattern cases past other cases.

## Example

Two switch expression arms return the same value:

```csharp
public sealed class Labels
{
    public string Get(int value) => value switch
    {
        1 => "a",
        2 => "b",
        3 => "a",
        _ => "z",
    };
}
```

If that result is intended, combine the patterns:

```csharp
public sealed class Labels
{
    public string Get(int value) => value switch
    {
        1 or 3 => "a",
        2 => "b",
        _ => "z",
    };
}
```

## Code fix

For a switch statement, the fix moves the duplicate section's labels onto an earlier matching section, removes the duplicate body and formats the merged section. Comments in the removed body are lost; comments attached to the moved labels travel with them.

For a switch expression, the fix joins the patterns with `or` and removes the duplicate arm. It wraps long pattern lists onto separate lines using the configured line limit. Comments on the removed arm or around joined patterns can be lost. Review useful comments before accepting either edit. An `or` pattern requires C# 9 or later.

The fix does not merge across directives. There is no code fix for `if` chains. Merge those conditions by hand only after checking their order and whether evaluating them changes program state.

## Configuration

The rule is enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2414.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`.

The switch expression fix uses these shared settings:

| Key | Values | Default |
| --- | --- | --- |
| `stylesharp.max_line_length` | Positive integer | `120` |
| `stylesharp.SST1521.max_line_length` | Positive integer; overrides the shared value | Falls back to `stylesharp.max_line_length` |

Invalid or non-positive values fall back to the next setting, then to `120`.

The two-statement minimum for duplicate `if` branches is fixed; the minimum-statement options for [SST1476](SST1476.md) control the separate all-branches check. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when keeping the branches separate makes distinct business cases clearer, or merging conditions would change their evaluation order. Keep a comment explaining why the duplicate behavior is intentional.
