# SST2415 — A boolean guard should short-circuit

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A single `&` or `|` joins two `bool` expressions, and the right side contains work such as a call, assignment, increment, element access or object creation. Both sides run even when the left side has already decided the result.

With `&&`, the right side runs only if the left side is true. With `||`, it runs only if the left side is false. This lets a null check or readiness check guard the work on the right.

Integer and enum bitwise operations, nullable `bool` operands, and `&=` or `|=` assignments are not reported. Lambdas converted to `Expression<TDelegate>` are also skipped because changing the operator changes the expression data passed to the consumer. Plain reads, including property access without a call, are covered by [SST1468](SST1468.md).

## Example

`Compute()` runs even when `ready` is false:

```csharp
public sealed class Worker
{
    public bool Run(bool ready) => ready & Compute();

    private static bool Compute() => true;
}
```

Let `ready` guard the call:

```csharp
public sealed class Worker
{
    public bool Run(bool ready) => ready && Compute();

    private static bool Compute() => true;
}
```

## Code fix

The fix replaces `&` with `&&` or `|` with `||`, preserving comments and spacing. It adds parentheses when needed inside another `&`, `^` or `|` expression to preserve grouping. Accepting the fix changes behavior: the right side can be skipped, including its state changes and exceptions.

## Configuration

The rule is enabled by default as a warning. To report it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2415.severity = error
```

Severity values are `none`, `silent`, `suggestion`, `warning` and `error`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when both expressions must run, such as independent checks that each record a validation error. Add a comment explaining that requirement, or evaluate each check in a separate statement before combining the results.
