# SST2417 — An assignment should not read as a transposed operator

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An assignment joins `=` to a following `+`, `-` or `!`, then puts whitespace or a comment after that operator. For example, `x =+ 1` assigns positive one; it does not add one to `x`.

```csharp
public sealed class Counter
{
    public void Update(int x)
    {
        x =+ 1;
    }
}
```

The rule does not report `x = +1`, `x += 1` or `x =+1`. The spacing rules leave the reported operator alone, so choose the intended operation first.

## How to fix violations

If the code should add to the existing value, use `+=`:

```csharp
public sealed class Counter
{
    public void Update(int x)
    {
        x += 1;
    }
}
```

If it should assign a positive value, write `x = +1` instead.

## Code fix

For `=+` and `=-`, the lightbulb offers two choices: use `+=` or `-=`, or move the space to make `= +` or `= -`. Choose carefully: the compound assignment uses the old value, while the ordinary assignment replaces it.

For `=!`, the fix only adds spacing for an ordinary assignment, such as `flag = !other`. There is no compound assignment for `!`.

The ordinary-assignment fix removes whitespace and comments immediately after the unary operator. Move any comment you need to keep before accepting that fix.

## Configuration

The rule is enabled by default at `warning`. It has no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2417.severity = error
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent` and `none`. See [Configuration](../CONFIGURATION.md) for scope and other configuration guidance.

## When to suppress

Prefer correcting the spacing. Suppress only when the exact text must stay unchanged, such as a code sample that deliberately demonstrates this typo.
