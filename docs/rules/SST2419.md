# SST2419 — A collection operation should not be applied to itself

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A supported set or list operation receives the same collection it is called on:

```csharp
using System.Collections.Generic;

public sealed class Sets
{
    public void Merge(HashSet<int> set) => set.UnionWith(set);
}
```

## What is reported

For a type that implements `ISet<T>`, the rule reports these operations against itself:

- `UnionWith` and `IntersectWith`: the set stays unchanged.
- `ExceptWith` and `SymmetricExceptWith`: the set becomes empty.
- `SetEquals`, `IsSubsetOf` and `IsSupersetOf`: the result is always true.

For a type that implements `IList<T>`, it reports `AddRange` and `InsertRange` with the same list as the range. These operations double the contents of a `List<T>`.

The collection expressions must match, such as `set.UnionWith(set)`. Calls such as `GetSet().UnionWith(GetSet())` and indexed expressions are excluded because evaluating them twice can produce different collections. Different variable names are not reported, even if they refer to the same collection.

## How to fix violations

Pass the intended second collection:

```csharp
using System.Collections.Generic;

public sealed class Sets
{
    public void Merge(HashSet<int> target, HashSet<int> source)
        => target.UnionWith(source);
}
```

If clearing the collection is intentional, use `Clear()` to make that intent clear. Remove an operation that has no useful effect.

There is no code fix.

## Configuration

The rule is enabled by default at `warning`. It has no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2419.severity = error
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent` and `none`. See [Configuration](../CONFIGURATION.md) for scope and other configuration guidance.

## When to suppress

Suppress for intentional list duplication or a test of an operation against its own collection. For custom collection methods with these names, check their actual behavior before changing the call.
