# SST2420 — An index-of test should not skip the first position

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

The result of an `IndexOf` or `LastIndexOf` call is compared with the literal `0` using `> 0` or the reversed form `0 < ...`. A match at the first position returns zero, so this test misses it:

```csharp
public sealed class Search
{
    public bool HasA(string text) => text.IndexOf('a') > 0;
}
```

The rule covers searches returning `int` on strings, arrays, spans, immutable arrays, and types implementing `IList<T>`. It does not report `>= 0`, `!= -1` or `>= 1`.

## How to fix violations

Include position zero when testing whether a match exists:

```csharp
public sealed class Search
{
    public bool HasA(string text) => text.IndexOf('a') >= 0;
}
```

## Code fix

For `IndexOf`, the fix replaces the comparison with a `Contains` call if that call accepts the existing arguments and returns `bool`. For example, `text.IndexOf('a') > 0` becomes `text.Contains('a')`.

If no matching `Contains` call is available, the fix changes `> 0` to `>= 0`, or `0 <` to `0 <=`. It always uses this comparison change for `LastIndexOf`. This also handles frameworks without `string.Contains(char)`, such as .NET Framework and .NET Standard 2.0.

A `Contains` replacement can remove comments around the old comparison. For string searches, `IndexOf(string)` uses the current culture's text rules, while `Contains(string)` compares character values. To keep the original search behavior, change the comparison manually or use an explicit `StringComparison` overload.

## Configuration

The rule is enabled by default at `warning`. It has no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2420.severity = error
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent` and `none`. See [Configuration](../CONFIGURATION.md) for scope and other configuration guidance.

## When to suppress

If the search should exclude position zero, write `>= 1` to make that intent clear. Suppress when the existing `> 0` spelling must be kept and the exclusion is deliberate.
