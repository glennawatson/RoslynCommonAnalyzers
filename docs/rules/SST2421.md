# SST2421 — A readonly field of an unconstrained type parameter should not be mutated

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

Code assigns a member or indexer, or calls a potentially mutating method, through a `readonly` field of type `T` without a reference-type constraint. The field must be accessed as a name such as `_point` or as `this._point`.

```csharp
public interface IPoint
{
    int X { get; set; }
}

public sealed class Holder<T> where T : IPoint
{
    private readonly T _point;

    public Holder(T point) => _point = point;

    public void Move() => _point.X = 5;
}
```

If `T` is a struct, C# makes a copy to protect the readonly field. The setter changes that copy, so the stored value stays unchanged. If `T` is a class, the setter changes the referenced object.

The rule also checks struct-constrained type parameters. It excludes fields with a reference-type constraint, fields declared as an interface type, readonly methods, static methods, and methods declared on `object`, `ValueType` or `Enum`.

## How to fix violations

If the holder requires an object that can be changed through a reference, add a `class` constraint:

```csharp
public interface IPoint
{
    int X { get; set; }
}

public sealed class Holder<T> where T : class, IPoint
{
    private readonly T _point;

    public Holder(T point) => _point = point;

    public void Move() => _point.X = 5;
}
```

If structs must be supported and the stored value must change, remove `readonly` instead. Another option is an API that returns an updated value, which the caller stores in a writable field.

There is no code fix.

## Configuration

The rule is enabled by default at `warning`. It has no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2421.severity = error
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent` and `none`. See [Configuration](../CONFIGURATION.md) for scope and other configuration guidance.

## When to suppress

Suppress a method call when you have checked that it only reads the value. The rule treats an instance method without a `readonly` modifier as potentially mutating; it does not check the method body. Do not suppress a write that must update a stored struct.
