# SST2422 — A property's getter and setter should use the same field

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A property's getter returns one instance field, but its `set` or `init` accessor assigns `value` to a different field:

```csharp
public sealed class Size
{
    private int _width;
    private int _height;

    public int Height
    {
        get => _height;
        set => _height = value;
    }

    public int Width
    {
        get => _height;
        set => _width = value;
    }
}
```

Setting `Width` does not change what its getter returns.

The getter must directly return a field, either after `=>` or in a block containing only one `return`. The setter must directly assign `value` to exactly one field. A setter block can also contain validation or notification code, but the assignment must be outside any nested block.

Fields can be written as `_width` or `this._width`. Auto-properties, static fields, computed getters such as `_width * _height`, and setters that only update fields through helper calls are not reported.

## How to fix violations

Make both accessors use the intended field:

```csharp
public sealed class Size
{
    private int _width;
    private int _height;

    public int Height
    {
        get => _height;
        set => _height = value;
    }

    public int Width
    {
        get => _width;
        set => _width = value;
    }
}
```

## Code fix

The fix changes the getter to read the field written by the setter. It keeps an existing `this.` prefix and leaves the setter and field declarations in place. If the setter is the mistaken accessor, edit it manually instead.

For a getter using `this.field`, comments attached to the replaced field name can be lost. Check the preview if that reference contains a comment.

## Configuration

The rule is enabled by default at `warning`. It has no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2422.severity = error
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent` and `none`. See [Configuration](../CONFIGURATION.md) for scope and other configuration guidance.

## When to suppress

Suppress when the property deliberately reads and writes different fields, such as a setter that queues a requested value while the getter returns a confirmed value. Document that contract for callers.
