# SST2423 - Do not return a disposable owned by a using

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes, for single-variable using declarations |
| Default | Enabled |

## Cause

A local declared by `using` or `await using` is returned directly, returned as a tuple element, or passed out with `yield return`. Its type implements `IDisposable` or `IAsyncDisposable`.

```csharp
using System.IO;

public sealed class Files
{
    public Stream Open()
    {
        using var stream = File.OpenRead("data.bin");
        return stream;
    }
}
```

An ordinary `return` leaves the scope and disposes the resource before the caller receives it. Reading this stream then throws `ObjectDisposedException`.

With `yield return`, the resource stays alive while the iterator is suspended inside the scope. It is disposed when iteration leaves that scope or the iterator is disposed. A caller that keeps the resource beyond that point receives an unusable value.

Both `using var resource = ...;` declarations and `using (...) { ... }` blocks are checked. Returning a member such as `resource.Name`, or returning a different object, is not reported.

## How to fix violations

If the caller owns the resource, remove `using` and make the caller responsible for disposal:

```csharp
using System.IO;

public sealed class Files
{
    public Stream Open()
    {
        var stream = File.OpenRead("data.bin");
        return stream;
    }
}
```

The caller should use `using`, or `await using` for asynchronous disposal. Check exception paths between creation and return: until the resource reaches the caller, this method still needs to dispose it if an operation fails.

## Code fix

The fix removes `using`, and `await` if present, from a declaration containing one variable. It keeps the variable and return statement and formats the changed declaration. It does not add disposal code to the caller.

There is no fix for a `using (...)` block or a declaration containing several variables. Comments between `await`, `using` and the variable type can be lost when those keywords are removed; move them before accepting the fix.

## Configuration

The rule is enabled by default at `warning`. It has no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2423.severity = error
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent` and `none`. See [Configuration](../CONFIGURATION.md) for scope and other configuration guidance.

## When to suppress

Suppress for an iterator with an explicit borrowing contract: callers may use each resource only while iteration keeps its scope alive and must not retain it. Do not suppress an ordinary return when the caller needs a usable resource after the method exits.
