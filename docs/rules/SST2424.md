# SST2424 — An override should not change a parameter's default value

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An override changes a parameter's default value, adds a default that the base method lacks, or removes a default supplied by the base method.

```csharp
public class Base
{
    public virtual int Go(int a, int b = 1) => b;
}

public class Derived : Base
{
    public override int Go(int a, int b = 2) => b;
}
```

C# chooses an omitted argument from the type used at the call site. For the same object, a call through a `Derived` variable supplies `2`, while a call through a `Base` variable supplies `1`. Both calls execute the override.

The rule checks overridden methods only. Matching default values are not reported.

## How to fix violations

Match the base method's default:

```csharp
public class Base
{
    public virtual int Go(int a, int b = 1) => b;
}

public class Derived : Base
{
    public override int Go(int a, int b = 1) => b;
}
```

If the base parameter has no default, remove the default from the override. If a different default is part of a different operation, give that operation its own method.

There is no code fix.

## Configuration

The rule is enabled by default at `warning`. It has no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2424.severity = error
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent` and `none`. See [Configuration](../CONFIGURATION.md) for scope and other configuration guidance.

## When to suppress

Suppress when a published API must keep different defaults for compatibility. Document which default callers receive through each type, and prefer explicit arguments at affected call sites.
