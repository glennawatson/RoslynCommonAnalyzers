# SST2425 — Forward the optional argument to the base call

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An override calls the method it overrides through `base`, but omits an optional argument. The override also declares an optional parameter with the same name as the omitted base parameter.

```csharp
public class Base
{
    public virtual void Go(int a, string mode = "fast") { }
}

public class Derived : Base
{
    public override void Go(int a, string mode = "fast")
    {
        base.Go(a);
    }
}
```

Calling `new Derived().Go(1, "slow")` passes `"fast"` to the base method. The base call uses its own default instead of the value received by the override.

Calls to a different base method are not reported. Passing an argument by position or by name avoids this diagnostic. The rule checks omitted arguments; it does not check whether an explicit argument has the intended value.

## How to fix violations

Pass the received parameter to the base method:

```csharp
public class Base
{
    public virtual void Go(int a, string mode = "fast") { }
}

public class Derived : Base
{
    public override void Go(int a, string mode = "fast")
    {
        base.Go(a, mode);
    }
}
```

The named form `base.Go(a, mode: mode)` also works.

There is no code fix.

## Configuration

The rule is enabled by default at `warning`. It has no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2425.severity = error
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent` and `none`. See [Configuration](../CONFIGURATION.md) for scope and other configuration guidance.

## When to suppress

Suppress when the override deliberately uses the base default regardless of its own argument, for example when it handles that argument itself. Add a comment explaining why forwarding it would be wrong.
