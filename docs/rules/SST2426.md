# SST2426 — An override should keep the base's params modifier

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An override adds `params` where the base method has none, or omits it where the base method has it:

```csharp
public class Base
{
    public virtual void Log(string first, params int[] rest) { }
}

public class Derived : Base
{
    public override void Log(string first, int[] rest) { }
}
```

`params` lets callers supply separate trailing arguments instead of an array. For an override, the base declaration controls that behavior. Removing `params` from the override does not prevent those calls, and adding it does not enable them when the base lacks it.

Only overrides with a mismatch are reported.

## How to fix violations

Use the same `params` modifier as the base method:

```csharp
public class Base
{
    public virtual void Log(string first, params int[] rest) { }
}

public class Derived : Base
{
    public override void Log(string first, params int[] rest) { }
}
```

## Code fix

The fix adds or removes `params` on the reported parameter to match the base declaration. It leaves the parameter's type, name and default value in place. This does not change which ordinary C# calls can pass separate trailing arguments.

When removing `params`, the fix can drop comments between that keyword and the parameter type. Move those comments before accepting the fix.

## Configuration

The rule is enabled by default at `warning`. It has no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2426.severity = error
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent` and `none`. See [Configuration](../CONFIGURATION.md) for scope and other configuration guidance.

## When to suppress

Prefer matching the base declaration. Suppress only when an external contract requires the exact declaration to remain unchanged, after checking how callers use it.
