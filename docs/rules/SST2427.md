# SST2427 - A derived overload should not hide a base overload with a more specific parameter

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A derived class declares a method that accepts a more general parameter type than a same-named method in a base class:

```csharp
public class Base
{
    public virtual void Handle(string message) { }
}

public class Derived : Base
{
    public void Handle(object message) { }
}
```

A call such as `new Derived().Handle("hello")` selects `Handle(object)`. C# finds a matching method in the derived class and does not choose the more specific base method.

## What is reported

The methods must have the same number of parameters. At least one derived parameter must accept a base class or interface of the corresponding base parameter's type. The other parameters must have the same type or also be more general. Parameters passed with `ref`, `in` or `out` must match exactly.

For example, `object` can hide a base overload taking `string` or `int`, and `IEnumerable<int>` can hide one taking `List<int>`.

Overrides, methods declared `new`, generic methods, methods with `params` parameters, and private base methods are excluded. Unrelated parameter types, more specific derived parameters, and different parameter counts are also excluded.

## How to fix violations

If the derived method should replace the base behavior, use the same signature and override it:

```csharp
public class Base
{
    public virtual void Handle(string message) { }
}

public class Derived : Base
{
    public override void Handle(string message) { }
}
```

If it performs a separate operation, give it a different name so it does not hide the base overload.

There is no code fix.

## Configuration

The rule is enabled by default at `warning`. It has no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2427.severity = error
```

Allowed severity values are `error`, `warning`, `suggestion`, `silent` and `none`. See [Configuration](../CONFIGURATION.md) for scope and other configuration guidance.

## When to suppress

If the general method should deliberately take precedence, declare it with `new` to record that intent; the rule then leaves it alone. Suppress when the hiding is intentional but the declaration must remain unchanged for an external contract.
