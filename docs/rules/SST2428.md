# SST2428 — A static field initializer should not read a static field declared later

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A static field initializer reads a non-constant static field of the same type that is declared later in the file, or in another file of a `partial` type.

Static field initializers run in declaration order. A field that has not been initialized still holds its default value: `null` for a reference type or zero for a number. In this example, `Full` becomes `"root"`:

```csharp
public static class Endpoints
{
    public static readonly string Full = "root" + Suffix;
    public static readonly string Suffix = "/v1";
}
```

Reading a constant, an earlier field in the same file, or a field of another type is not reported. Instance field initializers are not checked.

## How to fix violations

Declare the field being read first:

```csharp
public static class Endpoints
{
    public static readonly string Suffix = "/v1";
    public static readonly string Full = "root" + Suffix;
}
```

For a `partial` type split across files, the order between files is unspecified. Put dependent assignments in a static constructor, which runs after the field initializers, or keep the fields together in the required order.

There is no code fix.

## Configuration

The rule is enabled by default with severity `warning`. To treat it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2428.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress a specific occurrence if reading the default value is intentional, or if the reference is inside a function that only runs after initialization. Document that timing so a later edit does not introduce an ordering bug.
