# SST2429 — This accessor never uses its value

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `set`, `init`, `add`, or `remove` accessor has a non-empty body that never mentions `value` and contains no `throw`.

For a property, `value` is the value being assigned. For an event, it is the handler being added or removed. Ignoring it often means the accessor uses the wrong field:

```csharp
public class Size
{
    private int _height;
    private int _width = 10;

    public int Height
    {
        get => _height;
        set => _height = _width;
    }
}
```

An assignment such as `size.Height = 20` stores the width instead of 20. Empty bodies, accessors without a body such as `set;`, and bodies containing `throw` are not reported.

## How to fix violations

Use `value` for the incoming assignment or event handler:

```csharp
public class Size
{
    private int _height;

    public int Height
    {
        get => _height;
        set => _height = value;
    }
}
```

There is no code fix.

## Configuration

The rule is enabled by default with severity `warning`. To treat it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2429.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress an accessor that must exist to meet an interface or base-class contract and intentionally ignores the input while doing other work. Explain that behavior to callers. An empty accessor needs no suppression.
