# SST2430 — A serialization callback has the wrong signature

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A method marked with `[OnSerializing]`, `[OnSerialized]`, `[OnDeserializing]`, or `[OnDeserialized]` has an invalid declaration for a serialization callback.

The method must be an instance method, have no type parameters, return `void`, and take exactly one `System.Runtime.Serialization.StreamingContext` parameter. The rule reports a method that fails any of these checks.

```csharp
using System.Runtime.Serialization;

public class Order
{
    [OnDeserialized]
    private void AfterLoad(int version)
    {
    }
}
```

The serializer cannot use this method as the expected callback. Methods without these attributes are not checked. The rule reports nothing when the project lacks `StreamingContext` or all four callback attributes.

## How to fix violations

Give the method the required declaration and adjust its body to match:

```csharp
using System.Runtime.Serialization;

public class Order
{
    [OnDeserialized]
    private void AfterLoad(StreamingContext context)
    {
    }
}
```

There is no code fix.

## Configuration

The rule is enabled by default with severity `warning`. To treat it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2430.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress only if a custom serialization system deliberately uses these attributes with a different callback contract. Verify that it calls the method. For a standard serialization callback, correct the declaration.
