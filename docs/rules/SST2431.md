# SST2431 — ToString() should not return null

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A parameterless `ToString` override returns an explicit `null`, either from its expression body or from a `return` statement. The rule also reports `null!`, null wrapped in parentheses or a cast, and null in either branch of a `?:` expression.

```csharp
public sealed class Money
{
    public override string ToString() => null!;
}
```

Callers expect a string. Code that reads the result's `Length` or calls a string method on it will throw if the result is null.

The rule does not check whether a returned variable or method call might produce null. It also ignores returns inside nested lambdas or local functions, and methods that are not parameterless overrides.

## How to fix violations

Return a useful description, or an empty string when there is no text to return:

```csharp
public sealed class Money
{
    public override string ToString() => string.Empty;
}
```

## Code fix

The fix replaces the reported null expression with `string.Empty`. For `null!`, a cast, or parentheses around null, it replaces the whole reported expression. For a conditional return, it replaces only the null branch.

Comments before and after that expression are kept. Comments inside removed parentheses or casts are not preserved.

## Configuration

The rule is enabled by default with severity `warning`. To treat it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2431.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress only when preserving an existing API contract that deliberately returns null, or when testing how callers handle such an implementation. Prefer a separate nullable property or method for new APIs that need to represent missing text.
