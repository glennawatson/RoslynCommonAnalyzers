# SST2432 — Do not call GetType() on a value that is already a Type

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A parameterless `.GetType()` call is made on an expression whose declared type is `System.Type` or a class derived from it. This includes `typeof(string).GetType()`.

```csharp
using System;

public sealed class TypeDisplay
{
    public string Name(Type type) => type.GetType().Name;
}
```

A `Type` object already describes a type. Calling `GetType()` on it asks for the class of that describing object, often `RuntimeType`. It does not return the type being described.

Calls on ordinary objects, such as a parameter declared as `object` or `string`, are not reported. The conditional form `type?.GetType()` is not checked.

## How to fix violations

Use the `Type` value directly:

```csharp
using System;

public sealed class TypeDisplay
{
    public string Name(Type type) => type.Name;
}
```

## Code fix

The fix removes `.GetType()`, leaving the expression before it. For example, `typeof(string).GetType()` becomes `typeof(string)`. Comments around the whole call are kept; comments in the removed part of the call can be lost.

## Configuration

The rule is enabled by default with severity `warning`. To treat it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2432.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress when you need the implementation class of the `Type` object itself, such as when inspecting a custom `Type` subclass. Explain that intent beside the call.
