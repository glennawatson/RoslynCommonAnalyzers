# SST2434 — Avoid array covariance

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An array of reference types is converted to an array with a different element type. A common case is array covariance: using a `string[]` as an `object[]`.

```csharp
public sealed class Catalog
{
    public object[] Items = new string[3];
}
```

The array still stores strings. Assigning `catalog.Items[0] = 42` compiles but throws `ArrayTypeMismatchException` when it runs, because the array cannot store an integer.

The rule checks array conversions in assignments, arguments, returns, and expressions, including the left side of `??`. Adding an explicit array cast does not avoid the diagnostic. Conversions passed directly to a `params` parameter are excluded.

Keeping the same element type, using a value-type array such as `int[]`, or converting to a read-only interface rather than another array type is not reported.

## How to fix violations

If callers only read the elements, expose a read-only view:

```csharp
using System.Collections.Generic;

public sealed class Catalog
{
    public IReadOnlyList<object> Items = new string[3];
}
```

If callers need to write strings, keep the field typed as `string[]`. If they need to write arbitrary objects, create an actual `object[]`. `ReadOnlySpan<T>` is another option for read-only access where the target framework provides it.

There is no code fix.

## Configuration

The rule is enabled by default with severity `warning`. To treat it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2434.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress a conversion required by an API you cannot change when you have verified that it only reads the array or writes values compatible with the actual element type. For an explicit cast to a more specific array type, also verify the array's runtime type.
