# SST2435 — Do not use a base value equality as an equality fast path

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

Inside a method named `Equals`, a one-argument `base.Equals(...)` call is used as either `if (base.Equals(obj)) return true;` or the left side of `||`. The called method is declared on a base class other than `object`.

A base class can compare its fields without comparing the fields added by a derived class. Returning true as soon as the base fields match skips the derived comparison:

```csharp
public class Base
{
    public int Y { get; set; }
    public override bool Equals(object? obj) => obj is Base b && b.Y == Y;
    public override int GetHashCode() => Y;
}

public class Derived : Base
{
    public int Z { get; set; }
    public override bool Equals(object? obj)
        => base.Equals(obj) || (obj is Derived d && d.Z == Z);
    public override int GetHashCode() => Z;
}
```

Two `Derived` objects with the same `Y` compare equal even if their `Z` values differ. The rule also applies to `Equals` overloads without `override`. Calls inside nested lambdas or local functions are not checked.

## How to fix violations

Require both comparisons to succeed. Keep `GetHashCode` consistent with the equality fields:

```csharp
public class Base
{
    public int Y { get; set; }
    public override bool Equals(object? obj)
        => obj is Base b && b.GetType() == GetType() && b.Y == Y;
    public override int GetHashCode() => Y;
}

public class Derived : Base
{
    public int Z { get; set; }
    public override bool Equals(object? obj)
        => base.Equals(obj) && obj is Derived d && d.Z == Z;
    public override int GetHashCode() => System.HashCode.Combine(Y, Z);
}
```

For an early return that means both arguments refer to the same object, use `ReferenceEquals(this, obj)`. A call that uses `object.Equals` through `base` is not reported by this rule.

There is no code fix.

## Configuration

The rule is enabled by default with severity `warning`. To treat it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2435.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress only if the base implementation deliberately checks object identity, or if a successful base comparison fully establishes equality for the derived type. Check the base implementation before relying on that contract.
