# SST2437 — Avoid recursive generic inheritance

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A generic class, struct, or record lists a base type or interface that nests the declaring type inside its own type arguments. In this example, `Recursive<T>` appears inside another `Recursive<...>`:

```csharp
public class Base<T>
{
}

public class Recursive<T> : Base<Recursive<Recursive<T>>>
{
}
```

Following the same pattern for each nested `Recursive` produces increasingly nested types. This example compiles, but loading `Recursive<int>` throws `TypeLoadException` because the generic definition is recursive.

One use of the declaring type, such as `Base<Recursive<T>>`, is not reported. Neither is `Base<Wrapper<Recursive<T>>>`, where `Wrapper<T>` is a different generic type. Interfaces and non-generic declarations are not checked as declaring types.

## How to fix violations

Remove the repeated nesting. If the base needs the derived type, pass it once:

```csharp
public class Base<T>
{
}

public class Recursive<T> : Base<Recursive<T>>
{
}
```

Use `Base<T>` instead if the base needs the type parameter `T` rather than the derived type.

There is no code fix; the correct base or interface depends on its contract.

## Configuration

The rule is enabled by default with severity `warning`. To treat it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2437.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no rule-specific options.

## When to suppress

Suppress deliberate nesting only after checking it on the target runtimes and with tools that inspect the type hierarchy. Also suppress if the matching names refer to different types in different namespaces; qualifying those names does not prevent this diagnostic.
