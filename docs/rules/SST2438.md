# SST2438 — A caught exception should be passed to the logger

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A catch block names an exception and logs at or above the configured minimum level without passing that exception through the logger's exception parameter. The minimum is `error`, so `LogError` and `LogCritical` are checked by default.

The rule reports when the exception is unused in the catch block, or when a message value uses part of it, such as `ex.Message`. The latter is reported even if the catch also uses the exception elsewhere.

The following example uses `Microsoft.Extensions.Logging`:

```csharp
using System;
using Microsoft.Extensions.Logging;

public sealed class Processor
{
    public void Run(ILogger logger, Action process)
    {
        try
        {
            process();
        }
        catch (Exception ex)
        {
            logger.LogError("failed to process");
        }
    }
}
```

Passing only a message loses the exception object, including its stack trace and inner exceptions. Pass the exception through the dedicated parameter so the logging provider can record those details.

## What is not reported

- Calls outside a named catch. A lambda or local function needs its own catch to be checked.
- Catch blocks containing `throw`, including rethrows.
- Calls below the minimum level, or a general `Log` call whose level cannot be determined as a constant.
- Calls that already use the caught exception in the exception argument.
- Calls that pass the exception variable directly as a message value; [SST2439](SST2439.md) covers that mistake.
- An exception used elsewhere in the catch when no message value uses part of it.

Only `Microsoft.Extensions.Logging.LoggerExtensions` calls with a string literal message and an available exception overload are checked. Messages held in variables or constants, interpolated messages, and custom logging methods are not checked.

## How to fix violations

Pass the caught exception before the message:

```csharp
using System;
using Microsoft.Extensions.Logging;

public sealed class Processor
{
    public void Run(ILogger logger, Action process)
    {
        try
        {
            process();
        }
        catch (Exception ex)
        {
            logger.LogError(ex, "failed to process");
        }
    }
}
```

## Code fix

The fix inserts the caught exception immediately before the message. If a message value uses part of the exception and has a matching placeholder, the fix removes that value and placeholder, plus one adjacent space. For example, `logger.LogError("failed: {Message}", ex.Message)` becomes `logger.LogError(ex, "failed:")`. It does not rewrite the remaining wording.

The fix rebuilds the argument list with a comma and one space between arguments. Comments and line breaks between arguments can be lost. When it removes a placeholder, it rewrites the message as an ordinary quoted string, including messages written as verbatim or raw strings.

If the call already has an exception argument, correct it manually: the fix inserts another argument rather than replacing the existing one.

## Configuration

The rule is enabled by default with severity `warning`. To treat it as an error and keep the default minimum log level:

```ini
[*.cs]
dotnet_diagnostic.SST2438.severity = error
stylesharp.SST2438.minimum_level = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.

`stylesharp.SST2438.minimum_level` accepts `trace`, `debug`, `information`, `warning`, `error`, or `critical`, in that order. It includes the chosen level and all higher levels. Values ignore case and surrounding spaces; a missing or invalid value uses `error`. There is no general `stylesharp.minimum_level` fallback.

## When to suppress

Suppress when the exception is deliberately excluded from this log, for example because a separate error-reporting system captures it or the log must omit sensitive exception details. If lower-level logs are too noisy, raise the minimum level instead of suppressing each call.
