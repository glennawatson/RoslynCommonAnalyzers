# SST2439 — An exception should be passed as the exception argument

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A logging call passes a value typed as `System.Exception` or a derived exception type among its message values, after the message string. Pass it through the dedicated exception parameter so the logging provider can record its stack trace, type, and inner exceptions as exception details.

The following example uses `Microsoft.Extensions.Logging`:

```csharp
using System;
using Microsoft.Extensions.Logging;

public sealed class Processor
{
    public void Report(ILogger logger, Exception ex)
        => logger.LogError("failed {Ex}", ex);
}
```

The rule checks `Microsoft.Extensions.Logging.LoggerExtensions` calls with a string literal message and an available exception overload. It applies at every log level, inside or outside a catch block. It also reports an exception among the message values when the call already has a separate exception argument.

`ex.Message` is a string, so it is not reported here. Neither are exception objects hidden behind an `object` variable or inside an argument array. Messages held in variables or constants, interpolated messages, and custom logging methods are not checked.

## How to fix violations

Move the exception before the message and remove its placeholder:

```csharp
using System;
using Microsoft.Extensions.Logging;

public sealed class Processor
{
    public void Report(ILogger logger, Exception ex)
        => logger.LogError(ex, "failed");
}
```

## Code fix

The fix moves the reported expression immediately before the message and removes its old argument. It removes the matching placeholder, if present, and one adjacent space. Other words remain, so review whether the message still reads well.

The fix rebuilds the argument list with a comma and one space between arguments. Comments and line breaks between arguments can be lost. When it removes a placeholder, it rewrites the message as an ordinary quoted string, including messages written as verbatim or raw strings.

If the call already has an exception argument, correct it manually: the fix inserts another argument rather than replacing the existing one. Moving a method call that returns an exception also changes when it runs relative to the other message values.

## Configuration

The rule is enabled by default with severity `warning`. To treat it as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2439.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no rule-specific options or minimum log level setting.

## When to suppress

Suppress when an exception is deliberately recorded as a message property and the logging provider handles it as intended, such as a second exception beside the primary one. If only a caught exception's message is logged, [SST2438](SST2438.md) may also apply.
