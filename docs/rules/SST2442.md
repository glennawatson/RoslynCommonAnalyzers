# SST2442 - A message template should not repeat a placeholder name

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A log template uses the same property name more than once. A log store that keeps one value per property name can lose one of these values, even when the displayed message looks correct.

This rule checks string literals passed to `Microsoft.Extensions.Logging` logging methods and `BeginScope`. Names are compared without regard to case, and the second and each later use is reported. Changing a format suffix does not make a name distinct: `{Id}` and `{Id:N0}` repeat the same name.

Names must match in full, so `{User}` and `{UserName}` are different. Repeated numeric placeholders such as `{0}` are not reported. Templates passed through variables or interpolation are not checked.

## Example

Incorrect:

```csharp
using Microsoft.Extensions.Logging;

public class Example
{
    public void Log(ILogger logger, int first, int second) =>
        logger.LogInformation("{Id} then {Id}", first, second);
}
```

Correct:

```csharp
using Microsoft.Extensions.Logging;

public class Example
{
    public void Log(ILogger logger, int first, int second) =>
        logger.LogInformation("{FirstId} then {SecondId}", first, second);
}
```

## How to fix violations

Give each value a distinct placeholder name. Check any saved log queries that use names you change.

There is no code fix because the replacement names depend on what the values mean.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default; this repository sets its severity to `error`.

```editorconfig
[*.cs]
dotnet_diagnostic.SST2442.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when repeated names are intentional and every log provider and consumer handles them as required. Verify both the displayed message and the stored properties.
