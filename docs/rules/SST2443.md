# SST2443 - A typed logger's category should be the type that logs through it

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An `ILogger<T>` field, property, or parameter uses a category type unrelated to the containing type. The rule also checks `CreateLogger<T>()` and `CreateLogger(typeof(T))` calls that return a Microsoft logger.

The category identifies the source of log entries. Using the wrong type can send entries to the wrong destination or bypass the log-level settings intended for the containing type.

The rule accepts the containing type, its base types and implemented interfaces, and types that contain it. It also accepts types with no declared members and types whose names end in `Category` or `Logs`. Generic types may use their own type with type arguments. Local variable declarations are not checked, though a logger creation call in their initializer can be reported.

## Example

Incorrect:

```csharp
using Microsoft.Extensions.Logging;

public class PaymentService
{
    public void Pay() { }
}

public class OrderService
{
    public OrderService(ILogger<PaymentService> logger) { }
}
```

Correct:

```csharp
using Microsoft.Extensions.Logging;

public class PaymentService
{
    public void Pay() { }
}

public class OrderService
{
    public OrderService(ILogger<OrderService> logger) { }
}
```

## Code fix

**Use the enclosing type as the logger category** replaces the reported category with the containing type. For a generic type, it includes the type parameters, such as `Repository<T>`. It changes the selected declaration or creation call; update related fields, parameters, and callers if their types also need to change. Comments inside a replaced qualified or generic type name are not preserved.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default; this repository sets its severity to `error`.

```editorconfig
[*.cs]
dotnet_diagnostic.SST2443.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when the type deliberately logs on behalf of another component or shares a category that does not meet the accepted patterns. Confirm that the shared category matches the intended logging settings.
