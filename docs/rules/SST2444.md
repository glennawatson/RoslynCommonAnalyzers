# SST2444 - A regular expression pattern should be valid

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Refactoring | Convert a valid construction to a source-generated regular expression |
| Default | Enabled |

## Cause

A constant regular expression pattern is invalid for the supplied options. Examples include an unclosed bracket, an unclosed group, and a reference to a group the pattern does not define. Such patterns throw when the application constructs or uses the regular expression.

The rule checks `new Regex(...)` and static `Regex` calls to `IsMatch`, `Match`, `Matches`, `Replace`, `Split`, `Count`, `EnumerateMatches`, and `EnumerateSplits`. The call must contain at least one string literal. The pattern and any supplied options must be constant values. For example, `new Regex(patternConstant)` alone is not checked, but `Regex.IsMatch("input", patternConstant)` is.

Runtime patterns, runtime options, and instance matching calls without a pattern argument are not checked. Validation of constructs rejected by `RegexOptions.NonBacktracking` requires an editor or build runtime that supports that option.

## Example

Incorrect:

```csharp
using System.Text.RegularExpressions;

public class Example
{
    public Regex Build() => new Regex("[a-z");
}
```

Correct:

```csharp
using System.Text.RegularExpressions;

public class Example
{
    public Regex Build() => new Regex("[a-z]+");
}
```

## How to fix violations

Correct the pattern using the error in the diagnostic, then check that it matches the intended inputs. There is no code fix for an invalid pattern.

## Code fix and refactoring

The separate **Convert to a source-generated regular expression** refactoring works only after the pattern is valid. It requires C# 11 or later and `GeneratedRegexAttribute`, available in .NET 7 and later. Select a `new Regex("pattern")` construction with one literal argument, no initializer, options, or timeout, inside a non-generic class, struct, or record that is not nested in another type.

The refactoring replaces the construction with `PatternRegex()`, adds a formatted `private static partial Regex` method with `[GeneratedRegex]`, and adds `partial` to the containing type. It chooses a numbered method name if needed. The generated method returns a cached regex instead of constructing one per call. Keep `using System.Text.RegularExpressions;` in scope; the refactoring does not add it. Comments inside the removed construction are not preserved.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default; this repository sets its severity to `error`.

```editorconfig
[*.cs]
dotnet_diagnostic.SST2444.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress in a test that deliberately supplies an invalid pattern to check error handling. If the target runtime supports a pattern that the editor or build runtime rejects, verify it on the target runtime before suppressing.
