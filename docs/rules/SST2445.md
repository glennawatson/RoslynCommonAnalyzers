# SST2445 - A custom date/time format should not depend on the culture's separators

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Quote separators or use invariant culture |
| Default | Enabled |

## Cause

A date or time format contains an unquoted, unescaped `/` or `:` and uses the current culture. In custom date/time formats, these characters request the culture's separators. They do not guarantee a literal slash or colon, so a file name or stored value can change between machines.

The rule checks `ToString`, `ParseExact`, and `TryParseExact` with a constant format and an explicit `CultureInfo.CurrentCulture` or `CultureInfo.CurrentUICulture` provider. A method call must contain a string literal with `/` or `:`. It also checks date/time formats in interpolated strings converted directly to `string`.

It covers `DateTime`, `DateTimeOffset`, `DateOnly`, `TimeOnly`, and `TimeSpan`, including nullable values in interpolation. Custom `TimeSpan` formats require literal separators to be quoted or escaped; invariant culture alone does not make those separators valid.

Calls with no provider, an invariant provider, or another provider are outside this rule. Quoted or escaped separators, standard formats such as `"O"`, and invariant interpolation through `string.Create` are not reported. A call with no provider can still produce culture-dependent output.

## Example

Incorrect for a format that requires slashes:

```csharp
using System;
using System.Globalization;

public class Example
{
    public string Show(DateTime date) =>
        date.ToString("dd/MM/yyyy", CultureInfo.CurrentCulture);
}
```

Correct:

```csharp
using System;
using System.Globalization;

public class Example
{
    public string Show(DateTime date) =>
        date.ToString("dd'/'MM'/'yyyy", CultureInfo.CurrentCulture);
}
```

## Code fix

- **Quote the format separators** wraps each unquoted, unescaped `/` and `:` in single quotes. It works on literal format arguments and interpolation formats. It preserves existing quotes and escapes, but rewrites a verbatim or raw format literal as an ordinary C# string literal.
- **Use the invariant culture** replaces `CurrentCulture` or `CurrentUICulture` with `InvariantCulture` in a method call. It leaves the format unchanged and also affects other culture-dependent details, such as month names and calendars. It is not offered for interpolation.

For dates shown to users, consider a standard format such as `"d"` or `"g"` so both the date order and separators follow their culture.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default; this repository sets its severity to `error`.

```editorconfig
[*.cs]
dotnet_diagnostic.SST2445.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when the custom date order is intentional and the separators must follow the user's culture. Do not suppress when the result must follow a fixed storage or exchange format.
