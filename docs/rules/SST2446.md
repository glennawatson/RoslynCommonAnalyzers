# SST2446 - The number of bytes read from a stream should not be discarded

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | `ReadExactlyAsync`, for supported calls and frameworks |
| Default | Enabled |

## Cause

A `ReadAsync` call on `Stream` or a derived stream is awaited as a statement, and its returned byte count is discarded. The rule reports these forms:

- A read awaited through `ConfigureAwait`, with either `true` or `false`.
- A local initialized from `ReadAsync`, then awaited as a statement, with or without `ConfigureAwait`.

A read can return fewer bytes than the buffer holds. Only the returned count tells you how many bytes are valid. Processing the whole buffer after a short read can include stale or unfilled bytes.

Assigning or returning the count is not reported. A plain `await stream.ReadAsync(buffer);` is outside this rule, but still discards the count and has the same risk. Writes and reads on unrelated types are not checked.

## Example

Incorrect when the whole buffer is required:

```csharp
using System;
using System.IO;
using System.Threading.Tasks;

public class Example
{
    public async Task Fill(Stream stream, Memory<byte> buffer)
    {
        await stream.ReadAsync(buffer).ConfigureAwait(false);
    }
}
```

Correct on .NET 7 or later:

```csharp
using System;
using System.IO;
using System.Threading.Tasks;

public class Example
{
    public async Task Fill(Stream stream, Memory<byte> buffer)
    {
        await stream.ReadExactlyAsync(buffer).ConfigureAwait(false);
    }
}
```

## Code fix

**Read the buffer fully with ReadExactlyAsync** changes the method name and preserves the arguments, comments, and `ConfigureAwait` call. It is offered for a read awaited directly through `ConfigureAwait`, when the target framework provides `Stream.ReadExactlyAsync`.

This changes behavior: the call keeps reading until the buffer is full and throws `EndOfStreamException` if the stream ends first. Use it only when a full buffer is required.

Reads stored in locals have no automatic fix. Change them by hand. When partial reads are valid, use the returned count. On older frameworks, loop until the required bytes are read and handle a zero count as the end of the stream.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default; this repository sets its severity to `error`.

```editorconfig
[*.cs]
dotnet_diagnostic.SST2446.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress only when both the data and the byte count are deliberately ignored, such as a test that exercises cancellation. A read intended to fill or skip a known number of bytes must check completion.
