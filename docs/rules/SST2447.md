# SST2447 — Compare the operands instead of their difference

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An integer subtraction is compared against the literal zero.

```csharp
// 👎 reported
if (a - b > 0) { }
if (0 < a - b) { }

// 👍
if (a > b) { }
```

## Rule description

`a - b > 0` reads as `a > b`, but integer subtraction wraps. When the difference does not fit the operand
type the wrapped value lands on the wrong side of zero and the test returns the opposite answer:

```csharp
int a = int.MinValue, b = 1;
_ = a - b > 0;   // true  — the difference wrapped to a large positive
_ = a > b;       // false — what the test was meant to ask
```

On an unsigned type it is worse, because *every* case where `b` exceeds `a` wraps to a large positive number
and the test says "greater" for every pair it should reject. Comparing the operands has no intermediate value
to overflow and is right for every input.

This is a comparison that does not mean what it says, so the fix deliberately changes behaviour: it produces
the test the code reads as. Where the difference itself is wanted — a signed delta fed to something else —
compute it into a wider type and compare that.

### What is reported

- A subtraction of two integer operands compared against the literal `0` with `>`, `>=`, `<`, `<=`, `==`, or
  `!=`, in either operand position. When the subtraction is on the right the operands change sides, so the
  rewritten relational operator mirrors.

### What is not reported

- Floating-point and `decimal` arithmetic, which have no wrapping difference to misread.
- A comparison against anything other than zero.

## How to fix violations

Compare the two operands directly.

## Performance

A comparison whose operands are not a subtraction and a zero literal is dropped before the semantic model is
consulted; only then is the subtraction's type checked.
