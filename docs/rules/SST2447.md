# SST2447 - Compare the operands instead of their difference

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

An integer subtraction is compared with the literal `0` using `>`, `>=`, `<`, `<=`, `==`, or `!=`. The subtraction can be on either side of the comparison and can be wrapped in parentheses.

Subtraction can overflow before the comparison runs. For example, subtracting `1` from `int.MinValue` wraps to a positive value in unchecked code, so testing whether that difference is greater than zero gives the wrong order. In checked code, overflow throws instead. Comparing the values directly avoids that intermediate result.

Floating-point, `decimal`, nullable, and native-sized integer subtraction are outside this rule. Comparisons with a nonzero value or a named constant are also outside it.

## Example

Incorrect:

```csharp
public class Example
{
    public bool IsGreater(int first, int second) => first - second > 0;
}
```

Correct:

```csharp
public class Example
{
    public bool IsGreater(int first, int second) => first > second;
}
```

## Code fix

**Compare the operands directly** removes the subtraction and zero. For example, both `a - b > 0` and `0 < a - b` become `a > b`. It reverses the comparison sign when zero is on the left; equality and inequality keep their signs.

The fix adds one space around the comparison operator. It preserves comments outside the whole comparison, but can remove comments around the operands and the removed operators or zero. Review those comments before accepting it. The fix intentionally changes overflow behavior.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default; this repository sets its severity to `error`.

```editorconfig
[*.cs]
dotnet_diagnostic.SST2447.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress only when the wrapped difference or an overflow exception is part of the intended behavior, such as a test of arithmetic overflow. Document that intent. Use a direct comparison when the question is which value is larger or whether they are equal.
