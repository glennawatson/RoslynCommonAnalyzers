# SST2449 - Unsubscribing with a new lambda removes nothing

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An event or a delegate field, local, parameter, or property uses `-=` with a lambda or anonymous method written on the right. Parentheses around the lambda do not change the report.

Writing the same lambda text at subscription and removal does not reliably identify the subscribed handler. Removal compares the method and target held by the delegate. A separate lambda expression can identify a different handler, leaving the original attached. It can keep running and keep objects alive after the intended removal.

Stored delegates and named methods are not reported. Delegate array elements, casts around lambdas, and subtraction operators on non-delegate types are outside this rule.

## Example

Incorrect:

```csharp
using System;
using System.IO;

public class Watcher
{
    public void Start(FileSystemWatcher watcher) =>
        watcher.Changed += (sender, args) => Console.WriteLine(args.Name);

    public void Stop(FileSystemWatcher watcher) =>
        watcher.Changed -= (sender, args) => Console.WriteLine(args.Name);
}
```

Correct:

```csharp
using System;
using System.IO;

public class Watcher
{
    private readonly FileSystemEventHandler _handler =
        (sender, args) => Console.WriteLine(args.Name);

    public void Start(FileSystemWatcher watcher) => watcher.Changed += _handler;

    public void Stop(FileSystemWatcher watcher) => watcher.Changed -= _handler;
}
```

## How to fix violations

Store the handler when you create it and use that same delegate for removal. Keep it in a local or field that remains available until you unsubscribe. Alternatively, use a named method for both operations, on the same object for an instance method. Pair each subscription with one removal.

There is no code fix because the repair also changes the subscription site and where the handler is stored.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default; this repository sets its severity to `error`.

```editorconfig
[*.cs]
dotnet_diagnostic.SST2449.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress in a test that deliberately checks an unsuccessful removal, or for a custom event whose remove accessor intentionally handles these delegates without ordinary handler matching. Use a stored handler for normal event unsubscription.
