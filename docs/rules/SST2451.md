# SST2451 - A class with private constructors needs a way to create instances

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A class declares only private instance constructors, and nothing inside the class creates an instance of it. A constructor without an access modifier is private too. A sealed class with `private protected` constructors is also checked.

Callers cannot use private constructors directly. Provide a static method or property that creates an instance, or make a constructor accessible to the intended callers.

Creation inside a field or property initializer, method, lambda, local function, or nested type is accepted. Both `new ClassName(...)` and `new(...)` count. A nested type that derives from the class is also accepted.

## What is not reported

- Static, abstract, or partial classes, structs, and records.
- Classes with no declared instance constructor, or with a public, internal, or protected constructor.
- Unsealed classes with a `private protected` constructor.
- Classes with a constructor attribute whose written name ends in `Constructor` or `ConstructorAttribute`.
- Classes with a constructor taking `SerializationInfo` followed by `StreamingContext`.

The last two cases allow common framework construction patterns. The rule does not confirm that a framework actually creates the class.

## Example

Incorrect:

```csharp
public sealed class Session
{
    private Session(string user) => User = user;

    public string User { get; }
}
```

Correct:

```csharp
public sealed class Session
{
    private Session(string user) => User = user;

    public string User { get; }

    public static Session Open(string user) => new Session(user);
}
```

## How to fix violations

Add a factory method or singleton property, as appropriate for the class. Alternatively, give a constructor the access level callers need. If the class is only a container for static members, consider making it static and removing its instance constructor.

There is no code fix because the choice changes how callers create and use the type.

## Configuration

There are no rule-specific options. The rule is enabled as a warning by default; this repository sets its severity to `error`.

```editorconfig
[*.cs]
dotnet_diagnostic.SST2451.severity = warning
```

Severity values are `none`, `silent`, `suggestion`, `warning`, and `error`.

## When to suppress

Suppress when a framework or test creates instances through reflection, or when the type is deliberately never instantiated, such as a type used only as a generic marker. Document that use. Do not add a constructor attribute solely to hide the diagnostic.
