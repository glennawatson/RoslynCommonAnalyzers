# SST2453 — Coalescing to null leaves the value unchanged

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

The right operand of a `??` is a compile-time constant null, so the fallback substitutes null for null.

```csharp
// 👎 reported
var name = candidate ?? null;

// 👍
var name = candidate;
```

## Rule description

`??` reads as a fallback: keep the left unless it is null, otherwise use the right. When the right operand is
a constant null, the whole expression is its left operand. The operator advertises a default that does not
exist, so a reader looking for what happens on null finds an answer that was never written — usually the
right operand is the mistake, a default that was meant to hold a real value or a leftover from a rewrite.

This is the mirror of [SST2494](SST2494.md), which folds a `??` whose *left* operand is a constant null.

### What is reported

- `a ?? b` where `b` is a compile-time constant null — the null literal, `default`/`default(T)` of a
  reference or nullable type, or a constant whose value is null, including through a cast or parentheses —
  and the coalescing's own type equals the left operand's.

### What is not reported

- `nullableInt ?? default`, where the right operand unwraps the nullable and the expression's type is *not*
  the left operand's. Folding there would change the type, so the type check keeps the rule out of it. The
  same guard covers a fallback that widens, such as `intValue ?? (long?)null`.
- A coalescing whose left operand is also a constant null, which [SST2494](SST2494.md) owns, so the
  expression is reported once rather than twice.
- `a ??= b`, a different operator.

## How to fix violations

Replace the expression with its left operand.

## Performance

A right operand whose shape cannot be a constant — a call, a `new`, an index — is dropped without binding.
Only a constant-shaped operand is asked for its constant value.
