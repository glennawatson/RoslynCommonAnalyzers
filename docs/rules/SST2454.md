# SST2454 — Do not dereference the result of an 'as' conversion

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

The result of an `as` conversion is dereferenced with no null check.

```csharp
// 👎 reported
var length = (value as string).Length;

// 👍
if (value is string text)
{
    var length = text.Length;
}
```

## Rule description

The whole point of `as` over a cast is that a failed conversion yields null instead of throwing.
Dereferencing that result immediately gives back the throw — but as a `NullReferenceException` at the member
access, not an `InvalidCastException` naming the type that did not match. The failure then reads as a missing
value rather than a wrong type, and whoever debugs it starts by looking for where the null came from.

Either the conversion cannot fail, in which case a cast says so and fails with the right exception, or it
can, in which case the result needs handling.

### What is reported

- A member access, an index, or a call written directly on an `as` expression, through however many
  parentheses.

### What is not reported

- A conditional access (`?.`, `?[]`), which is exactly the null check this rule asks for.
- An `as` result stored in a local and checked before use: whether that check is adequate is a flow question
  this rule does not ask.
- A cast, which already throws with the exception that names the problem.

## How to fix violations

Pick the shape that matches the intent:

- the conversion is expected to succeed — use a cast, `((string)value).Length`;
- it may fail and there is a sensible fallback — use a conditional access, `(value as string)?.Length ?? 0`;
- it may fail and the success path is the interesting one — use a type pattern, `value is string text`, which
  binds the converted value only when the conversion worked.

There is no code fix, because which of those three is right is a decision about what the code means.

## Performance

The whole match is syntactic — the shape of the expression around the `as` — so nothing binds, and the clean
path costs one walk up through the enclosing parentheses.
