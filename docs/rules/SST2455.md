# SST2455 — Enum members should not silently share a value

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

Two members of an enum hold the same number without saying they are the same thing.

```csharp
// 👎 reported
enum Level
{
    First = 1,
    Second = 1,
}

// 👍 — the alias says so
enum Level
{
    Read = 1,
    Default = Read,
}
```

## Rule description

Two members holding the same number *are* the same value: they compare equal, a switch cannot have a section
for each, and `ToString` gives whichever the runtime picks. When that is intended it is written as an alias,
which says so and stays correct if the underlying number changes. A bare literal that happens to repeat an
earlier member's number is almost always a copy-paste, or a renumbering that missed one.

### What is reported

- The second and later members of an enum whose constant value equals an earlier member's, where the
  duplicate's value is not expressed by naming another member of the same enum. A member with no initializer
  is reported too, because an implicit number that lands on an explicit one is exactly the surprise this rule
  is about.

### What is not reported

- A deliberate alias, `Default = Read`.
- A combination written from the enum's own members, `All = Read | Write`, even when it equals another
  combination.

## How to fix violations

Decide which of the two is wrong. If they really are the same value, say so by writing the later one as an
alias of the earlier; otherwise give it its own number. There is no code fix, because which member is the
mistake is not something the source says.

## Performance

One pass over the members collects their declared constant values, so an enum is walked once however many
members it has.
