# SST2455 — Enum members should not silently share a value

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An enum member has the same number as an earlier member without naming another member in its initializer. The second and later duplicates are reported. This includes a member with no explicit value when its automatic number repeats an earlier value.

Members with the same number compare equal. A `switch` cannot distinguish them, and `ToString()` is not guaranteed to choose the name you expect.

An alias such as `Default = Read` is not reported. An initializer that names another member, such as `All = Read | Write`, is also excluded even if its value repeats another member.

## How to fix violations

If the shared value is intentional, name the earlier member:

```csharp
public enum Level
{
    First = 1,
    Second = 1,
}
```

Corrected:

```csharp
public enum Level
{
    First = 1,
    Second = First,
}
```

If the members mean different things, assign distinct numbers. Check stored data and public callers before changing an enum's numbers.

There is no code fix; the rule cannot choose between an alias and a different number.

## Configuration

The rule is enabled by default as a warning. This repository sets it to an error:

```editorconfig
dotnet_diagnostic.SST2455.severity = error
```

Supported severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an external specification requires repeated numeric literals in the source. Otherwise, an explicit alias preserves the number and makes the shared value clear.
