# SST2456 — A redeclared event can split its subscriber list

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An event without `add` and `remove` accessors is declared `override`, or is declared `new` with a same-named event in a base class. This kind of event stores its own list of handlers. If the base class also stores handlers, the two lists are separate, so raising one event can miss handlers added to the other.

Every non-abstract `override` of this form is reported, including an implementation of an abstract event. The rule also reports a `new` declaration when a same-named base event is private.

Abstract events, interface events, events with explicit accessors, and declarations without `override` or `new` are excluded. A `new` event with no same-named base event is also excluded.

## How to fix violations

This derived event has its own handler list, which `Raise()` does not use:

```csharp
using System;

public class Publisher
{
    public virtual event EventHandler Changed = delegate { };

    public void Raise() => Changed(this, EventArgs.Empty);
}

public class LoudPublisher : Publisher
{
    public override event EventHandler Changed = delegate { };

    public void RaiseLoud() => Changed(this, EventArgs.Empty);
}
```

Remove the derived event declaration to share the inherited event:

```csharp
using System;

public class Publisher
{
    public event EventHandler Changed = delegate { };

    public void Raise() => Changed(this, EventArgs.Empty);
}

public class LoudPublisher : Publisher
{
    public void RaiseLoud() => Raise();
}
```

Removing only the `override` or `new` keyword still leaves a separate event. If you must keep the redeclaration, write `add` and `remove` accessors that forward subscriptions to the base event. Both raising methods must use the same handler list.

There is no code fix; sharing event storage requires a decision about the class design.

## Configuration

The rule is enabled by default as a warning. This repository sets it to an error:

```editorconfig
dotnet_diagnostic.SST2456.severity = error
```

Supported severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when implementing an abstract event creates the only handler list, or when separate base and derived events are intentional and their subscription and raising paths are clear.
