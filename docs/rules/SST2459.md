# SST2459 — [Optional] cannot make a ref or out parameter optional

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

`System.Runtime.InteropServices.OptionalAttribute` is applied to a `ref` or `out` parameter, including a delegate parameter. Ordinary C# calls must supply those arguments. The attribute does not make them optional, although code that inspects parameter attributes sees them as optional.

Parameters passed by value, `in` parameters, and `ref readonly` parameters are excluded. Members of `[ComImport]` types are also excluded because COM calls have different argument rules. An unrelated attribute named `Optional` does not trigger the rule.

## How to fix violations

Remove the misleading attribute:

```csharp
using System.Runtime.InteropServices;

public sealed class Session
{
    public void Load([Optional] ref int value) => value = 1;
}
```

Corrected:

```csharp
public sealed class Session
{
    public void Load(ref int value) => value = 1;
}
```

If callers should be able to omit the argument, add an overload without it or redesign how the method accepts and returns the value.

## Code fix

The fix removes `[Optional]` and keeps other attributes in the same list. If it is the only attribute in the list, the brackets are removed too. Comments attached to the removed attribute can be lost. The parameter remains `ref` or `out`, and callers must still supply it.

## Configuration

The rule is enabled by default as a warning. This repository sets it to an error:

```editorconfig
dotnet_diagnostic.SST2459.severity = error
```

Supported severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when an external interop or reflection-based caller requires the parameter's optional metadata and you have verified that caller's behavior. Removing the attribute changes that metadata even though ordinary C# calls still require an argument.
