# SST2460 — [DefaultValue] does not supply a parameter default

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

`System.ComponentModel.DefaultValueAttribute` is applied to a parameter, including a record's positional parameter. The C# compiler does not use this attribute as an argument default or make the parameter optional.

When combined with `[Optional]`, an omitted integer argument receives zero instead of the number in `[DefaultValue]`. Attributes aimed at a record's generated property or field with `[property:]` or `[field:]` are excluded. An unrelated attribute named `DefaultValue` is also excluded.

## How to fix violations

Write the default into the parameter declaration:

```csharp
using System.ComponentModel;

public static class Api
{
    public static void Connect([DefaultValue(5)] int retries)
    {
    }
}
```

Corrected:

```csharp
public static class Api
{
    public static void Connect(int retries = 5)
    {
    }
}
```

For an interop API, `[Optional, DefaultParameterValue(5)]` from `System.Runtime.InteropServices` supplies an optional argument with that default. If a record attribute is meant for a property reader, use `[property: DefaultValue(5)]` instead; that does not supply a constructor argument default.

## Code fix

The fix replaces `DefaultValue` with `DefaultParameterValue`, keeping the argument, other attributes, and any `Attribute` suffix. It uses the full `global::System.Runtime.InteropServices` name when needed. Comments inside a qualified attribute name can be lost when that name is replaced.

The fix only changes the attribute name. It does not add `[Optional]` or an `= value` default, so a parameter without `[Optional]` still requires an argument in ordinary C# calls.

The fix is offered for one unnamed argument that can be assigned to the parameter type without an explicit cast, and only when `DefaultParameterValueAttribute` is available. The two-argument form, such as `[DefaultValue(typeof(int), "5")]`, named arguments, and incompatible values require a manual edit.

## Configuration

The rule is enabled by default as a warning. This repository sets it to an error:

```editorconfig
dotnet_diagnostic.SST2460.severity = error
```

Supported severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a framework explicitly reads `[DefaultValue]` from parameters and needs it for its own behavior. Confirm that contract; the C# compiler does not use it as a default argument.
