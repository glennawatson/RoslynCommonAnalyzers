# SST2461 — A combined flags value should only set bits the enum defines

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A member of a `[Flags]` enum sets a bit that no member of that enum declares.

```csharp
[Flags]
public enum Access
{
    None = 0,
    Read = 1,
    Write = 2,
    All = 7,   // SST2461 — bit 2 (value 4) belongs to nothing
}
```

## Rule description

A composite member of a flags enum is supposed to be the union of members that exist. When its number sets a
bit no member defines, that bit belongs to nothing:

- `HasFlag` answers true for a value no name describes;
- `ToString` prints the number instead of a name;
- a member added later on that bit silently becomes part of the composite.

It is nearly always a hand-written literal that drifted from the members it was meant to combine — `All = 7`
left behind when a third flag was deleted, or written before it was added.

### What is reported

- A member of a `[Flags]` enum whose value sets a bit that no single-bit member of the same enum declares.
  The message names the lowest such bit.

### What is not reported

- A single-bit member, however sparse the enum — a lone `Reserved = 64` defines its own bit.
- Zero.
- A composite written from the enum's own members, `All = Read | Write`, which cannot drift.
- An enum with no `[Flags]` attribute.

## How to fix violations

Either add the member that owns the bit, or write the composite in terms of the members it combines so it
cannot drift again. There is no code fix, because which of those two you meant is not something the source
says.

## Performance

The declared bits are collected in one pass and reused for every member, so an enum is walked twice however
many members it has, and an enum without the attribute is rejected before either pass.
