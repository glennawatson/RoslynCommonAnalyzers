# SST2462 — A member hidden with 'new' should not reduce its accessibility

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A member declared with `new` has narrower access than a matching member in a base class. Hiding a public member with a private member does not make the base member private. Callers can still use the base member through a variable of the base type.

The rule checks methods, properties, events, fields, and nested types against base members of the same kind and name. Methods must have matching parameter types and `ref`, `in`, or `out` modifiers, and the same number of generic type parameters. Nested types must have the same number of generic type parameters.

Overrides, members without `new`, private base members, and equal or wider access are excluded. Changing `protected` to `internal` is also excluded: each permits callers that the other does not, so neither is strictly narrower.

## How to fix violations

This private method does not prevent a caller from using `Base.M()`:

```csharp
public class Base
{
    public void M() { }
}

public class Derived : Base
{
    private new void M() { }
}
```

If hiding is intentional, keep the same or wider access:

```csharp
public class Base
{
    public void M() { }
}

public class Derived : Base
{
    public new void M() { }
}
```

Rename an unrelated member, or remove a redundant declaration and use the inherited member. If the base method is virtual and you want to replace its behavior, consider an override. None of these choices makes an inherited public member private; restricting the exposed API requires a different class design.

There is no code fix; the rule cannot choose the intended API or rename callers safely for you.

## Configuration

The rule is enabled by default as a warning. This repository sets it to an error:

```editorconfig
dotnet_diagnostic.SST2462.severity = error
```

Supported severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a compatibility contract requires both declarations and the narrower member is intentional. Base-type callers retain access to the inherited member. A report involving an `internal` base member from another assembly may also need suppression if that member is not accessible to the derived class.
