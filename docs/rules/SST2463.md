# SST2463 — A field should not differ from an inherited field only by case

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A class declares an instance field whose name differs from a non-private instance field in a base class only by letter case. The base field can come from any level of inheritance.

The two fields store separate values. When both are accessible, typing the wrong case can read or write the wrong field without a compiler error.

Exactly matching names, private base fields, static fields on either side, and compiler-generated fields are excluded. Fields declared together in one class are outside this rule.

## How to fix violations

Give distinct values distinct names:

```csharp
public class Base
{
    public int Value;
}

public class Derived : Base
{
    public int VALUE;
}
```

Corrected, when the derived field holds a cached value:

```csharp
public class Base
{
    public int Value;
}

public class Derived : Base
{
    public int CachedValue;
}
```

Update uses of the renamed field. If both names were meant to refer to one value, remove the derived field and use the inherited field instead. Check callers and serialization before renaming a public field.

There is no code fix; choose a meaningful name or decide which storage to remove.

## Configuration

The rule is enabled by default as a warning. This repository sets it to an error:

```editorconfig
dotnet_diagnostic.SST2463.severity = error
```

Supported severity values are `error`, `warning`, `suggestion`, `silent`, `none`, and `default`. There are no rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when public field names must remain for compatibility and renaming would break callers or stored data. A report involving an `internal` base field from another assembly may also need suppression if that field is not accessible to the derived class.
