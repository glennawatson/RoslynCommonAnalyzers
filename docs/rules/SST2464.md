# SST2464 — A value-equality operator should not be declared on a mutable reference type

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A class declares `operator ==` and an instance field that is not `readonly`, or a property with a
`set` accessor. Private members and members in other parts of a partial class count too.

Equality based on changing data can give different answers for the same two objects. If
`GetHashCode` also uses that data, changing an object stored in a `Dictionary` or `HashSet` can
make lookups fail. These collections use `Equals` and `GetHashCode`, not `operator ==`.

The rule does not report structs, records, static state, or classes with only `readonly` fields
and get-only or `init`-only properties. It also allows an operator whose only expression is
`ReferenceEquals(left, right)` or `(object)left == (object)right`.

## Example

This class compares a property that callers can change:

```csharp
#nullable enable
public sealed class Point
{
    public int X { get; set; }

    public static bool operator ==(Point? a, Point? b) =>
        ReferenceEquals(a, b) || (a is not null && b is not null && a.X == b.X);
    public static bool operator !=(Point? a, Point? b) => !(a == b);
    public override bool Equals(object? obj) => obj is Point other && X == other.X;
    public override int GetHashCode() => X;
}
```

Make the property read-only after construction:

```csharp
#nullable enable
public sealed class Point
{
    public Point(int x) => X = x;
    public int X { get; }

    public static bool operator ==(Point? a, Point? b) =>
        ReferenceEquals(a, b) || (a is not null && b is not null && a.X == b.X);
    public static bool operator !=(Point? a, Point? b) => !(a == b);
    public override bool Equals(object? obj) => obj is Point other && X == other.X;
    public override int GetHashCode() => X;
}
```

If the class needs reference equality, remove the operator pair and any value-based `Equals`
and `GetHashCode` overrides instead. Check callers before changing this public behavior.

There is no automatic code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets
it to `error`. Set the severity in `.editorconfig`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2464.severity = warning
```

Allowed values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable
the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when equality and the hash code depend only on data that cannot change, and the
settable members do not affect either result. The rule does not check which members equality uses.
