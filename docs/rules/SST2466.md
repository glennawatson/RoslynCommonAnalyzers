# SST2466 — An empty finally clause should be removed

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A `finally` clause contains no statements.

```csharp
// 👎 reported
try
{
    Work();
}
finally
{
}
```

## Rule description

A `finally` exists to run cleanup whatever happens. An empty one runs nothing, so the `try` it is attached to
buys only the cost of the exception region — and, worse, it reads as though unwinding is handled when it is
not. The usual history is cleanup that moved elsewhere, or a block someone opened and never filled.

### What is reported

- A `finally` whose block has no statements.

### What is not reported

- A clause holding only comments. The comment is often the note explaining why nothing runs, and deleting it
  would delete the explanation.

## How to fix violations

Remove the clause. When the `try` has a `catch`, that is the whole edit. When it has neither handler nor
cleanup, the `try` guards nothing at all, so the fix lifts its body into the enclosing block and drops the
statement.

## Performance

The rule registers on the `finally` clause and looks only at its statement count. The comment check reads the
two brace tokens' trivia rather than walking the block, because an empty block holds its trivia there.
