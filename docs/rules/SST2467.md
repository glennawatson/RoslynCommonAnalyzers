# SST2467 — A params overload should not be silently bypassable by a more specific overload

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A type declares a method ending in a `params` array and another overload whose final parameter
is more specific than the array's element type. A single trailing argument of that type selects the
other overload, which may do different work.

Both methods must be non-generic, have the same name and parameter count, and both be static
or both be instance methods. Their earlier parameters must have matching types and `ref`,
`in`, or `out` modifiers. The other overload's last parameter must be passed by value and
must not be `params`.

A more specific type can inherit the element type. If the element type is an interface,
a type that implements it also qualifies. For
`params object[]`, any type other than `object` qualifies. An overload taking the element
type itself is not reported. Neither are overloads declared only in a base type or `params`
collections that are not arrays. No call is needed for the declaration to be reported.

## Example

With these declarations, `Write("Failed: {0}", exception)` selects the `Exception` overload:

```csharp
using System;

public class Log
{
    public void Write(string format, params object[] args) { }
    public void Write(string format, Exception error) { }
}
```

Give the operation with different behavior a distinct name:

```csharp
using System;

public class Log
{
    public void Write(string format, params object[] args) { }
    public void WriteError(string format, Exception error) { }
}
```

Update callers that need `WriteError`. If both overloads must stay, callers can pass an
explicit `object[]` to select the array overload. That does not remove the diagnostic on
the declarations. There is no automatic code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets
it to `error`. Set the severity in `.editorconfig`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2467.severity = warning
```

Allowed values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable
the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when selecting the more specific overload is intentional and its behavior is
compatible with the array overload, or when an existing public API must keep both signatures.
Document which overload callers should use.
