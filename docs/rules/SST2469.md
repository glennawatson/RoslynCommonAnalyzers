# SST2469 — A write through a by-value struct receiver is discarded

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | No |
| Applies to | C# 14 or later |
| Analyzer | `Sst2469DiscardedReceiverWriteAnalyzer` |

## Cause

A member of an `extension(Receiver receiver) { … }` block writes into the receiver, and the receiver is
a struct passed by value.

```csharp
public struct Point
{
    public int X { get; set; }
}

public static class PointExtensions
{
    extension(Point point)
    {
        public int Doubled
        {
            get => point.X * 2;
            set => point.X = value / 2; // 👎 reported — writes to a copy
        }
    }
}
```

```csharp
var p = new Point { X = 1 };
p.Doubled = 10;
// p.X is still 1
```

## Rule description

An extension block's receiver is an ordinary parameter. When its type is a struct and it is passed by
value, the member receives a **copy**: assigning to a field or property of it changes the copy, and the
caller's value is untouched.

Nothing else reports this. The code compiles, the setter runs, and the write simply goes nowhere — so
it reads as a working mutable property right up until someone depends on it.

Both the assignment forms and the compound ones are reported, since each writes into the receiver:

```csharp
point.X = 5;
point.X += 1;
point.X++;
point[0] = 5;
```

### What is not reported

- A receiver declared **`ref`** — the write reaches the caller's value:

  ```csharp
  extension(ref Point point)
  {
      public int Doubled { set => point.X = value / 2; } // fine
  }
  ```

- A **reference type** receiver — the copy is of the reference, so the write reaches the same object.
- A receiver declared `in` or `ref readonly` — the compiler already rejects assigning through those.
- A write to a local, even one copied from the receiver. `var copy = point; copy.X = 5;` says what it
  does.

## How to fix violations

Decide which the member meant:

- To mutate the caller's value, declare the receiver `ref`.
- Not to mutate, remove the accessor that writes — a struct extension that looks settable and is not is
  worse than one that is plainly read-only.

There is no code fix: adding `ref` changes the call sites that may use the member, and removing an
accessor removes API, so the choice is the author's.

## Performance

The receiver's type is resolved only once a write into it has been found syntactically, so a block that
never writes to its receiver pays nothing beyond the member walk.
