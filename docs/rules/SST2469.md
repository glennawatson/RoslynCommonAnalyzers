# SST2469 — A write through a by-value struct receiver is discarded

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A C# 14 extension block writes to a struct receiver passed by value. The receiver is the
parameter named in `extension(...)`. Passing it by value gives the member a copy, so changes
to the struct's fields or properties do not reach the caller's variable.

The rule reports assignments, compound assignments, `++`, and `--` whose target starts from
that receiver, including member and indexer access. Reads, writes to a separate local copy,
class receivers, and `ref` receivers are not reported. Calling a method that changes the
struct is outside this rule's checks.

## Example

This setter changes a copy of the point:

```csharp
public struct Point
{
    public int X { get; set; }
}

public static class PointExtensions
{
    extension(Point point)
    {
        public int Doubled
        {
            get => point.X * 2;
            set => point.X = value / 2;
        }
    }
}
```

Use `ref` when the setter must change the caller's point:

```csharp
public struct Point
{
    public int X { get; set; }
}

public static class PointExtensions
{
    extension(ref Point point)
    {
        public int Doubled
        {
            get => point.X * 2;
            set => point.X = value / 2;
        }
    }
}
```

A `ref` receiver requires a writable variable at the call site. If the member is meant only
to read data, remove the setter instead. There is no automatic code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets
it to `error`. Set the severity in `.editorconfig`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2469.severity = warning
```

Allowed values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable
the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when the write deliberately changes only a temporary copy, or when a nested write
changes an object referenced by the struct and therefore does reach shared data. Prefer an
explicit local copy when that makes the intent clearer.
