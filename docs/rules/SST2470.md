# SST2470 — String literals concatenated without a space should not fuse a SQL keyword

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes (regular right-hand string literals) |
| Default | Enabled |

## Cause

Two string literals joined with `+` run a SQL keyword into the next word or number.
The resulting SQL can fail or mean something different from what you intended.

The rule reports a join where one side ends or starts with a keyword and the other side
touches it with a letter from A–Z or a–z, a digit, or an underscore. Keywords are matched without regard
to case: `WHERE`, `AND`, `OR`, `FROM`, `JOIN`, `INNER`, `LEFT`, `RIGHT`, `ON`, `ORDER`, `GROUP`,
`HAVING`, `SELECT`, `SET`, `VALUES`, `INTO`, `UNION`, `LIMIT`, `OFFSET`, and `RETURNING`.

The left literal must also contain one of these whole words: `SELECT`, `FROM`, `WHERE`, `JOIN`,
`INTO`, `VALUES`, `UNION`, `HAVING`, `RETURNING`, `INSERT`, `UPDATE`, or `DELETE`.

Regular, verbatim, and raw string literals are checked. A space, tab, newline, or punctuation
between the words avoids the diagnostic. A keyword inside a longer word, such as `WHEREVER`,
does not count. Variables, interpolated strings, and joins where either operand is another
concatenation are not checked.

## Example

The query contains `tWHERE` instead of `t WHERE`:

```csharp
public class Queries
{
    public string Get() => "SELECT * FROM t" + "WHERE id = 1";
}
```

Add the missing space:

```csharp
public class Queries
{
    public string Get() => "SELECT * FROM t" + " WHERE id = 1";
}
```

## Code fix

**Add a space between the concatenated string literals** adds one space to the start of the
right literal's value. It preserves comments and whitespace around that literal. It rewrites
the literal with regular C# escapes, so an escape's spelling can change while keeping its value.

The fix is available only when the right literal is a regular quoted string. If it is
verbatim or raw, add the space by hand. The left literal can use any of the three forms.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets
it to `error`. Set the severity in `.editorconfig`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2470.severity = warning
```

Allowed values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable
the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when the text is not SQL, or when joining the pieces without a space is intentional,
such as building a quoted SQL identifier or string value. Check the complete resulting text.
