# SST2474 — A part-creation-policy attribute is meaningless without an export

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A type has `[PartCreationPolicy(...)]` from `System.ComponentModel.Composition`, or `[Shared]`
from `System.Composition`, but has no export attribute. These attributes control instances
created by a composition container. They do not register the type as an export.

Any `PartCreationPolicy` value is checked. An `[Export]` on the same type, including another
part of a partial declaration, satisfies the rule. A custom attribute derived from either
MEF `ExportAttribute` also counts. The rule requires the relevant MEF attributes to be
available in the project.

## Example

The sharing policy does not export this service:

```csharp
using System.ComponentModel.Composition;

[PartCreationPolicy(CreationPolicy.Shared)]
public class Service { }
```

Add the export if the container should provide the service:

```csharp
using System.ComponentModel.Composition;

[Export]
[PartCreationPolicy(CreationPolicy.Shared)]
public class Service { }
```

If the type does not belong in the container, remove the policy attribute instead. There is
no automatic code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets
it to `error`. Set the severity in `.editorconfig`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2474.severity = warning
```

Allowed values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable
the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when the application's composition conventions register the export without an
attribute and honor the sharing policy. Verify that registration; the rule checks attributes
on the type, not container setup code.
