# SST2475 — An entity's primary key should not be a temporal type

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A property identified as a primary key has type `DateTime`, `DateTimeOffset`, or a nullable
form of either. Timestamps do not guarantee unique values, and database storage can reduce
their precision. Use a separate identifier when those risks would make rows hard to identify.

The rule identifies key properties in two ways:

- A property has `System.ComponentModel.DataAnnotations.KeyAttribute`.
- A public instance property has a getter and a setter and is named `Id` or `<TypeName>Id`.
  The containing entity type must appear in a `DbSet<T>` field or property on an Entity Framework Core
  `DbContext` subclass declared in the project. `Id` is matched without regard to case;
  the `<TypeName>` portion must match the class name's case.

The naming check accepts private setters and `init` accessors. It does not check fluent
mapping configuration. A convention-named property on a type with no qualifying `DbSet<T>`
is not reported. Neither are fields or keys of other types, such as `int` or `Guid`.

## Example

Two readings can have the same timestamp:

```csharp
using System;
using System.ComponentModel.DataAnnotations;

public class Reading
{
    [Key]
    public DateTime CapturedAt { get; set; }
}
```

Give each reading a separate key and keep the timestamp as data:

```csharp
using System;
using System.ComponentModel.DataAnnotations;

public class Reading
{
    [Key]
    public int Id { get; set; }

    public DateTime CapturedAt { get; set; }
}
```

Configure how the new key is assigned and migrate existing rows and foreign keys before
deploying the schema change. There is no automatic code fix.

## Configuration

There are no rule-specific options. The default severity is `warning`; this repository sets
it to `error`. Set the severity in `.editorconfig`:

```editorconfig
[*.cs]
dotnet_diagnostic.SST2475.severity = warning
```

Allowed values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable
the rule. See [Configuration](../CONFIGURATION.md) for shared settings.

## When to suppress

Suppress when an existing schema requires a timestamp key and guarantees its uniqueness and
stored precision. Also suppress when explicit mapping selects a different key from the
convention-named property that was reported.
