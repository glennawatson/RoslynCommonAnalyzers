# SST2485 — A NotImplementedException should not be left in shipped code

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `throw` statement or expression creates `System.NotImplementedException`, with
or without a message. Reaching that code fails instead of doing the promised work.
The rule applies to unfinished code during development too; it does not check
whether the code is included in a release.

Rethrows, throwing an existing exception variable, `NotSupportedException`, and
same-named exception types in other namespaces are not reported.

## Example

Bad: the method is still a placeholder.

```csharp
using System;

public static class Counter
{
    public static int Count(int[] items) => throw new NotImplementedException();
}
```

Corrected: implement the operation.

```csharp
public static class Counter
{
    public static int Count(int[] items) => items.Length;
}
```

Remove a member that is not ready to be exposed if callers do not need it. Use
`NotSupportedException` only when the operation is deliberately unsupported, such
as modifying a read-only collection.

There is no code fix. The intended implementation must be written by hand.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat
the diagnostic as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2485.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress temporarily for a deliberate development stub that cannot reach users,
or for a test that needs to throw this exception. Do not suppress an unfinished
operation that callers can reach in shipped code.
