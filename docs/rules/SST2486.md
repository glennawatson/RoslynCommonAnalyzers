# SST2486 — Prefer Assembly.Load over the path and partial-name load APIs

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes (LoadWithPartialName only) |
| Default | Enabled |

## Cause

Code calls `Assembly.LoadFrom`, `Assembly.LoadFile`, or `Assembly.LoadWithPartialName`
through a qualified call such as `Assembly.LoadFrom(...)`. A same-named method on
another type is not reported. Unqualified calls brought into scope with
`using static` are not checked.

Loading by path can affect how the runtime finds dependencies and whether loaded
types match types already in the application. The details depend on the runtime
and API. `LoadWithPartialName` is obsolete and does not specify a full assembly
identity.

## Example

Bad: select an assembly by its file path.

```csharp
using System.Reflection;

public static class Loader
{
    public static Assembly LoadPlugin() => Assembly.LoadFrom("Some.Assembly.dll");
}
```

Corrected: request the intended assembly by its full name. It must be available
through the application's assembly resolution setup.

```csharp
using System.Reflection;

public static class Loader
{
    public static Assembly LoadPlugin() =>
        Assembly.Load("Some.Assembly, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null");
}
```

Use the name, version, culture, and public key token of your actual assembly.
A file path cannot be passed to `Assembly.Load(string)` as a replacement name.

## Code fix

The fix changes only `LoadWithPartialName` to `Load`. It keeps the argument and
comments around the method name. For example, `Assembly.LoadWithPartialName("Plugin")`
becomes `Assembly.Load("Plugin")`; the fix does not expand `"Plugin"` to a full name.
Check assembly resolution and failure handling: `Load` throws if it cannot find
the assembly, while `LoadWithPartialName` can return null.

No fix is offered for `LoadFrom` or `LoadFile`. Choose the assembly name and any
changes to dependency resolution by hand.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat
the diagnostic as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2486.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when a plugin loader deliberately loads a selected file or requires
separate copies of an assembly. Check dependency loading and interactions between
types loaded by the plugin and the application before keeping the path-based call.
