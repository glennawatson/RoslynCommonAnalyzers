# SST2487 — A [ConstructorArgument] should name a constructor parameter

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A property has `System.Windows.Markup.ConstructorArgumentAttribute` with a string
literal that matches no parameter of any constructor on that property's type.
Names are case-sensitive. A match in any constructor overload is accepted.

The attribute tells a XAML serializer which constructor argument supplies the
property's value. A wrong name prevents that mapping when the object is written
back to XAML.

The rule checks string literals only. It does not check a constant name,
`nameof(...)`, or `null` passed as the argument. Same-named attributes from other
namespaces are excluded. The markup attribute must be available in the project.

## Example

These examples require a reference that provides `System.Windows.Markup`, such
as a WPF project.

Bad: the constructor parameter is `source`, not `src`.

```csharp
using System.Windows.Markup;

public class MapExtension
{
    public MapExtension(string source) => Source = source;

    [ConstructorArgument("src")]
    public string Source { get; set; }
}
```

Corrected: use the constructor parameter's exact name.

```csharp
using System.Windows.Markup;

public class MapExtension
{
    public MapExtension(string source) => Source = source;

    [ConstructorArgument("source")]
    public string Source { get; set; }
}
```

If no constructor takes the value, add the intended parameter or remove an
attribute that does not describe the type.

There is no code fix. Choose which constructor parameter the property represents.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat
the diagnostic as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2487.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress only when a custom serialization system deliberately interprets the
attribute differently and the mapping has been tested. For normal XAML
serialization, correct the name or remove the invalid mapping.
