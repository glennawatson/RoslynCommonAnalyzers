# SST2488 — Do not log and rethrow the same exception

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `catch` contains only one or more recognized logging calls followed by `throw;`.
The exception can then be logged again by an outer handler, making one failure
look like several failures.

Calls such as `LogError`, `Error`, and `Warn` count as logging when the object's
type, a base type, or an interface is named `ILog` or ends in `Logger`. Calls such
as `Log`, `LogError`, and `LogException` also count when an argument uses the caught
exception, including a member such as `ex.Message`.

A catch with other statements, logging without a rethrow, a lone `throw;`, or
`throw ex;` is not reported. `throw ex;` still loses the original throw location;
it is not a repair for duplicate logging.

## Example

Bad: this layer logs the failure and passes it to another handler.

```csharp
using System;

public interface ILogger
{
    void LogError(Exception error, string message);
}

public static class Worker
{
    public static void Run(Action work, ILogger logger)
    {
        try
        {
            work();
        }
        catch (Exception ex)
        {
            logger.LogError(ex, "Work failed");
            throw;
        }
    }
}
```

Corrected: let the outer handler log and decide how to recover.

```csharp
using System;

public static class Worker
{
    public static void Run(Action work) => work();
}
```

If this layer is responsible for recovery, keep the log and replace the rethrow
with the intended fallback or recovery action. Do not discard an exception merely
to remove the diagnostic.

There is no code fix. Choose which layer handles the failure.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat
the diagnostic as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2488.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when this catch is the only place that records the failure and the caller
still needs the exception, or when a required audit record serves a separate
purpose. Confirm that outer handlers will not create unwanted duplicate records.
