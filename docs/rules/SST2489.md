# SST2489 — Relational comparison is decided by the operand's type

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An integer is compared to its type's minimum or maximum value with `<`, `<=`, `>`,
or `>=`. The reported comparisons are always true, always false, or equivalent
to checking that the value is not the minimum.

| Comparison | Meaning |
| --- | --- |
| `value >= minimum` | Always true |
| `value < minimum` | Always false |
| `value > minimum` | Equivalent to `value != minimum` |
| `value <= maximum` | Always true |
| `value > maximum` | Always false |

The bound can appear on either side. It must be written as a number, a negative
number, or a constant `MinValue`/`MaxValue` member. Other named constants are not
checked as bounds.

The rule covers `byte`, `sbyte`, `short`, `ushort`, `int`, `uint`, `long`, and
`ulong`. For `nuint`, it checks only the minimum, zero. It excludes `nint`, `char`,
nullable integers, and floating-point types.

## Example

Bad: for an unsigned value, this is a check for a nonzero value.

```csharp
public static class Counter
{
    public static bool HasItems(uint count) => count > 0;
}
```

Corrected: state that check directly.

```csharp
public static class Counter
{
    public static bool HasItems(uint count) => count != 0;
}
```

For an always-true or always-false comparison, remove the redundant check or use
the actual application limit that it was meant to enforce.

Comparisons inside or outside the type's range, constant operands, and signed
integers compared to zero are not reported. Neither are `value <= minimum`,
`value >= maximum`, or `value < maximum`.

There is no code fix. The intended check cannot be inferred from the type limit.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat
the diagnostic as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2489.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when a bounds check must retain the same form across code using several
integer types, or when `count > 0` communicates the domain meaning better than
`count != 0`. Confirm that an always-true check is not being relied on to reject input.
