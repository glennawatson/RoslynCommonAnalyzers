# SST2490 — Adjacent try statements with identical handling should be merged

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

Two `try` statements are next to each other in the same block and repeat the same
catch clauses and `finally` block. Catch types, variable names, filters, and bodies
must match; whitespace and comments do not affect the comparison. In a longer run,
each matching statement after the first is reported.

A typed catch or a catch filter counts even with an empty body. A pair with only
empty `finally` blocks, or only empty catches without a type or filter, is excluded.

## Example

Bad when both operations should share one failure handler:

```csharp
using System;
using System.IO;

public static class Loader
{
    public static void Load(Action primary, Action secondary)
    {
        try
        {
            primary();
        }
        catch (IOException ex)
        {
            Console.Error.WriteLine(ex.Message);
        }

        try
        {
            secondary();
        }
        catch (IOException ex)
        {
            Console.Error.WriteLine(ex.Message);
        }
    }
}
```

Corrected when `secondary` should run only if `primary` succeeds:

```csharp
using System;
using System.IO;

public static class Loader
{
    public static void Load(Action primary, Action secondary)
    {
        try
        {
            primary();
            secondary();
        }
        catch (IOException ex)
        {
            Console.Error.WriteLine(ex.Message);
        }
    }
}
```

There is no code fix. Review the change in execution before merging: separate
statements can run `secondary` after a handled failure in `primary`; a merged
statement skips it. Separate `finally` blocks run after each operation; a merged
block runs once after the combined work. Also check local variable name conflicts.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat
the diagnostic as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2490.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when each operation must be attempted independently, when cleanup must
run between operations, or when filters and handlers must run separately. Identical
handler text does not prove that merging preserves the required behavior.
