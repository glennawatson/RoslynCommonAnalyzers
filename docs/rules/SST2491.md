# SST2491 — Do not return a pending task from inside a using, lock, or try/finally

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes (except functions with returns inside lock) |
| Default | Enabled |

## Cause

A method or local function without `async` returns a `Task`, `Task<T>`, `ValueTask`,
or `ValueTask<T>` from a resource scope. The scope is a `using` statement, a block
after a `using` declaration, a `lock`, or the body of a `try` with a `finally`.

Returning the task lets disposal, lock release, or `finally` run before the work
finishes. The caller awaiting the task does not keep that scope open.

## Example

Bad: the reader is disposed before the read necessarily finishes.

```csharp
using System.IO;
using System.Threading.Tasks;

public static class Reader
{
    public static Task<string> ReadAsync(string path)
    {
        using var reader = new StreamReader(path);
        return reader.ReadToEndAsync();
    }
}
```

Corrected: await the read before disposing the reader.

```csharp
using System.IO;
using System.Threading.Tasks;

public static class Reader
{
    public static async Task<string> ReadAsync(string path)
    {
        using var reader = new StreamReader(path);
        return await reader.ReadToEndAsync();
    }
}
```

## What is not reported

Already-`async` methods, lambdas, accessors, and returns outside these scopes are
excluded. Direct returns of `null`, `default`, `Task.CompletedTask`, or calls to
`Task.FromResult`, `Task.FromException`, and `Task.FromCanceled` are also excluded.

Direct constructors written as `new Type(...)` are skipped, including
`new ValueTask(...)`. This exclusion does not prove that the returned work has
finished; a constructed value task can wrap pending work.

## Code fix

The fix adds `async` to the method or local function and rewrites all of its
returns, including ones outside the reported scope. It leaves nested functions
alone. For `Task<T>` and `ValueTask<T>`, `return X;` becomes `return await X;`.
For `Task` and `ValueTask`, it becomes a new block containing `await X; return;`.
The changed function is formatted. Comments attached to the removed return keyword
or semicolon can be lost in the non-generic case; review the preview.

No fix is offered if any return in that function is inside a `lock`, because C#
does not allow `await` there. If the entire asynchronous operation needs exclusive
access, use a design that supports asynchronous waiting, such as `SemaphoreSlim`.
Awaiting after leaving a `lock` does not keep the work protected by that lock.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat
the diagnostic as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2491.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when the returned operation is known to have completed, or when its
remaining work does not use the resource or protected state. Document that lifetime
guarantee; a task that usually finishes quickly is not enough.
