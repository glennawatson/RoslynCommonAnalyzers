# SST2492 — Do not throw for null on a parameter the signature allows to be null

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A null guard throws for a parameter declared as a nullable reference or nullable
type parameter, such as `string?` or `T?`. It also reports parameters with an
explicit optional default of `null`. The signature allows a value that the body
rejects.

The checked value must be the parameter itself. Guards on fields, locals, or
property expressions are excluded. A nullable value type such as `int?` is not
reported unless the parameter also has an optional null default.

The rule recognizes `ArgumentNullException.ThrowIfNull(parameter)` with one
argument. It also recognizes `if (parameter is null)` and either order of
`parameter == null` when the body only throws `new ArgumentNullException(...)`
and there is no `else`. That constructor must have no arguments or one argument
naming the checked parameter. Guards with custom messages are not checked.

## Example

Bad: the signature invites null, but the method rejects it. `ThrowIfNull` requires
.NET 6 or later; a hand-written null guard also works on older targets.

```csharp
#nullable enable
using System;

public static class Settings
{
    public static void Configure(string? value)
    {
        ArgumentNullException.ThrowIfNull(value);
    }
}
```

Corrected when null is not allowed: remove `?` and keep the runtime guard.

```csharp
#nullable enable
using System;

public static class Settings
{
    public static void Configure(string value)
    {
        ArgumentNullException.ThrowIfNull(value);
    }
}
```

Remove an optional `= null` default too if omitting the argument is invalid.
Non-nullable annotations warn callers; they do not stop null values at runtime.
If null is valid, keep the nullable signature and replace the throw with the
intended handling for null.

There is no code fix. Decide whether the signature or the null handling is wrong.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat
the diagnostic as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2492.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when an interface or override requires the nullable signature but this
implementation has a documented reason to reject null, or when null is valid only
in a state the rule cannot distinguish. Check that the restriction still meets
the contract callers rely on.
