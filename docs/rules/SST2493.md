# SST2493 — Compare an unconstrained type parameter with 'is null', not '== null'

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A value of a generic type parameter is compared with the literal `null` using
`==` or `!=`, in either order. The rule reports parameters without a `class`,
`struct`, `notnull`, `unmanaged`, or class base-type constraint. An interface
constraint alone does not exclude the comparison.

Use a null pattern to express the check directly. It checks for null, not for
`default(T)`. For an `int` value of zero, the generic null check returns false.
For a nullable value with no value, it returns true.

## Example

Bad:

```csharp
public static class Missing
{
    public static bool IsMissing<T>(T value) => value == null;
}
```

Corrected:

```csharp
public static class Missing
{
    public static bool IsMissing<T>(T value) => value is null;
}
```

Both versions return false for `IsMissing(0)`. If the intended check is for the
type's default value, use `EqualityComparer<T>.Default.Equals(value, default(T))`
from `System.Collections.Generic` instead.

Comparisons of concrete types, parameters with the listed constraints, and calls
to `Equals` or comparers are not reported. A `notnull` constraint can allow both
reference and value types; it does not mean `class`.

## Code fix

The fix replaces `value == null` with `value is null` and `value != null` with
`value is not null`. If null is on the left, the value moves to the left. Comments
outside the comparison are kept, but comments between its operands and operator
can be lost.

For these generic null checks, use C# 8 or later for `is null` and C# 9 or later
for `is not null`. The fix does not check the project's language version. On an
older version that supports `is null`, write `!(value is null)` for inequality.

## Configuration

The default severity is `warning`. There are no rule-specific options. To treat
the diagnostic as an error:

```ini
[*.cs]
dotnet_diagnostic.SST2493.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`.
See [Configuration](../CONFIGURATION.md) for severity settings.

## When to suppress

Suppress when a required language version cannot express the replacement, or
when shared code must keep an established null-check style. A suppression does
not turn a null comparison into a default-value comparison.
