# SST2496 — Do not dispose a value an enclosing using already disposes

| Item | Value |
| --- | --- |
| Category | Correctness |
| Default severity | Suggestion (Info) |
| Code fix | Yes |
| Default | Enabled |

## Cause

A local variable declared with `using` receives a parameterless `Dispose()` or
`Close()` call. The `using` already disposes that variable when its scope ends.
Both `using var` and `using (var ...)` declarations are covered.

The call must use the variable directly, such as `stream.Dispose()`. A plain local
declared outside the `using`, or a call through `?.`, is not reported.

## Example

Before:

```csharp
using System.IO;

public class Reader
{
    public int ReadFirstByte(string path)
    {
        using var stream = File.OpenRead(path);
        int value = stream.ReadByte();
        stream.Dispose();
        return value;
    }
}
```

After:

```csharp
using System.IO;

public class Reader
{
    public int ReadFirstByte(string path)
    {
        using var stream = File.OpenRead(path);
        int value = stream.ReadByte();
        return value;
    }
}
```

## Code fix

The fix deletes the whole call statement, including its attached comments. Disposal
then happens at the end of the `using` scope, which can be later than the explicit
call. Move useful comments and check that this timing is suitable.

A call inside a larger expression can be reported, but has no code fix. Review it
manually. A custom `Close()` or `Dispose()` method can do work beyond releasing the
resource.

## Configuration

Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2496.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no
rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the explicit call must release the resource early and a smaller
`using` scope is unsuitable, or when a custom method performs required extra work.
Confirm that the later disposal by `using` is safe.
