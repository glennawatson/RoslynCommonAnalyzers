# SST2497 — Do not forward a member to itself

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |
| Analyzer | `Sst2497SelfRecursiveForwarderAnalyzer` |

## Cause

An expression-bodied method or local function calls its own name and hands every parameter straight
back in its own position.

```csharp
public string Process(string body, string url, DateTimeOffset? expiry) => body;

// 👎 reported — binds to itself, not to the overload above
public string Process(string body, Uri url, DateTimeOffset? expiry)
    => Process(body, url, expiry);
```

## Rule description

Passing each parameter at its declared type produces an exact signature match, and an exact match beats
every overload that would need a conversion. The call therefore reaches the member being declared, with
arguments identical to the ones it was given, and nothing changes between one call and the next: the
first caller gets a `StackOverflowException`, which cannot be caught and takes the process with it.

This is what a forwarder looks like when the target was meant to be something else and the matching
name won. The three shapes that produce it:

```csharp
// an overload — the argument list has to actually select the sibling
public string Render(string body, Uri url) => Render(body, url.ToString());

// a base implementation — reached with base.
public override int Scale(int value) => base.Scale(value);

// a differently named member
public int Forwarded(int value) => Helper(value);
```

## What is not reported

**A call that can terminate.** A body that only recurses under a condition has a base case, so it is
ordinary recursion:

```csharp
public int Countdown(int value) => value <= 0 ? 0 : Countdown(value - 1);
```

**A self-call whose arguments are not the parameters in their own positions.** Reordered and named
arguments recurse just as endlessly, but the positional match is what proves which member the call
reaches, so they sit outside what this rule claims:

```csharp
public int Swapped(int first, int second) => Swapped(second, first);           // not reported
public int Named(int first, int second) => Named(second: second, first: first); // not reported
```

**A block body.** Only the expression-bodied form is reported.

## How to fix violations

Call the member that was meant. There is no code fix, because which one that is — the sibling overload,
the base implementation, or a differently named member — is the question the defect leaves open.

## Performance

The clean path is syntax only: a member is not a candidate unless it is expression-bodied, its body is
an invocation, and that invocation names the member being declared with its own parameters in order.
The semantic model is consulted once, at the end, to confirm the call really binds to the declared
symbol — so the report rests on the compiler's own overload resolution rather than on reasoning about it.
