# SST2498 — Do not use nameof on a type parameter

| Item | Value |
| --- | --- |
| Category | Correctness |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

`nameof` is applied to a generic type parameter. `nameof(T)` returns the text `"T"`
for every type supplied as `T`. It does not return the supplied type's name.
This applies to type parameters declared on classes and methods.

## Example

Before:

```csharp
public class SettingsStore<T>
{
    public string DatabaseName(string overrideName)
        => overrideName ?? nameof(T);
}
```

After:

```csharp
public class SettingsStore<T>
{
    public string DatabaseName(string overrideName)
        => overrideName ?? typeof(T).Name;
}
```

## How to fix violations

Use `typeof(T).Name` when you need the supplied type's name. Use
`typeof(T).FullName` when the namespace matters too.

These values cannot be used in a `const` declaration. Change such a field to
`static readonly` or use a property. If the string is a stored file name or cache
key, plan how existing data will be found after the name changes.

There is no automatic code fix.

`nameof` on an ordinary type, member, or value parameter is not reported.

## Related rules

[SST1199](SST1199.md) recommends `nameof` for ordinary type names, but excludes
generic type parameters.

## Configuration

Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2498.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no
rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when you need the type parameter's declared name, such as `"T"` in a
message about a generic API. A parameter name used intentionally does not need
to be replaced with the supplied type's name.
