# SST2498 — Do not use nameof on a type parameter

| Item | Value |
| --- | --- |
| Category | Correctness |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |
| Analyzer | `Sst2498NameofTypeParameterAnalyzer` |

## Cause

`nameof` is applied to a type parameter.

```csharp
public sealed class SettingsStore<T>
{
    // 👎 reported — every instantiation gets the file "T.db"
    private string DatabaseName(string? overrideName) => overrideName ?? nameof(T);
}
```

## Rule description

`nameof` is resolved by the compiler against the source spelling, so `nameof(T)` is the literal text
`"T"` in every instantiation. It never becomes the name of the type substituted for `T`. The intent is
always `typeof(T).Name`, which is the substituted type's name at run time.

Where the value is shown to a person, the result is a message that reads "of type T". Where it is used
as data, the consequences are worse, because every instantiation contributes the same fragment and
values meant to be distinct per type collide:

```csharp
// one file, shared by every settings type
var databaseName = overrideName ?? nameof(T);

// one cache-key fragment, shared by every T
internal const string Name = nameof(T);
```

```csharp
var databaseName = overrideName ?? typeof(T).Name;
```

Note that `typeof(T).Name` cannot be a `const`, since it is a run-time value — a constant built this way
has to become a static readonly field or a property.

## What is not reported

`nameof` on anything that is not a type parameter, including a non-generic type, a member, or a
parameter — those all name the thing that was written, which is what `nameof` is for.

```csharp
nameof(Widget)        // fine
nameof(Widget.Count)  // fine
nameof(value)         // fine
```

A method someone declared as `nameof` is an ordinary call, not the operator, and is left alone.

## How to fix violations

Use `typeof(T).Name`, or `typeof(T).FullName` where the namespace has to disambiguate it. There is no
code fix: the replacement is not a constant expression, so where the result was a `const` the
declaration has to change too, and where it was a file name or cache key the change alters values that
may already be persisted.

## See also

- [SST1199](SST1199.md) — `typeof(T).Name` is reported in favour of `nameof(T)` for ordinary types, and
  stays silent on type parameters for exactly this reason.
