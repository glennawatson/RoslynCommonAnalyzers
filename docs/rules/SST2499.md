# SST2499 — Read the exit status rather than the exit code when a process can be signalled

| Item | Value |
| --- | --- |
| Category | Correctness |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

Code reads `System.Diagnostics.Process.ExitCode` in a member that also calls
`WaitForExit` or `WaitForExitAsync`.

On Unix, the integer exit code cannot distinguish a code returned by the child
process from termination by a signal. For example, `137` can mean a deliberate
exit code or termination by `SIGKILL`. The full exit status lets you handle these
outcomes separately.

The rule applies only when the target framework provides `WaitForExitStatus`.
It reports nothing on frameworks without that API.

## Example

Before:

```csharp
using System.Diagnostics;

public class Runner
{
    public int Run(Process process)
    {
        process.WaitForExit();
        return process.ExitCode;
    }
}
```

After, on a framework with the exit-status API:

```csharp
using System.Diagnostics;

public class Runner
{
    public ProcessExitStatus Run(Process process)
        => process.WaitForExitStatus();
}
```

## How to fix violations

Use `WaitForExitStatus()` or await `WaitForExitStatusAsync()`. Check the returned
status's `Signal` before treating `ExitCode` as a code chosen by the child. If you
return the status to a caller, update that caller to handle signal termination.

There is no automatic code fix.

## What is not reported

An `ExitCode` read without either wait call in the same member is not reported.
An `ExitCode` property on an unrelated type is not reported either.

The wait call does not have to target the process whose exit code is read. Check
which process each call concerns when reviewing a diagnostic.

## Configuration

Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2499.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no
rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when your contract requires the integer exit code, or the application
only runs on Windows and does not need Unix signal information. Suppression is
also reasonable when the wait call concerns an unrelated process and this read
does not need to distinguish signal termination.
