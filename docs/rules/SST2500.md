# SST2500 — A test method should verify something

| Item | Value |
| --- | --- |
| Category | Testing |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A test method has no assertion or expected-exception check. Its body is empty,
only computes local values, or only calls .NET APIs such as `Console.WriteLine`
and `StringBuilder.Append`. Without a check, a wrong result can go unnoticed.

Supported test attributes are xUnit's `[Fact]` and `[Theory]`; NUnit's `[Test]`,
`[TestCase]`, `[TestCaseSource]`, and `[Theory]`; MSTest's `[TestMethod]` and
`[DataTestMethod]`; and TUnit's `[Test]`.

## Example

Before:

```csharp
using Xunit;

public class ArithmeticTests
{
    [Fact]
    public void Adds()
    {
        var result = 1 + 1;
        _ = result;
    }
}
```

After:

```csharp
using Xunit;

public class ArithmeticTests
{
    [Fact]
    public void Adds()
    {
        var result = 1 + 1;
        Assert.Equal(2, result);
    }
}
```

## How to fix violations

Assert the result the test promises to check. If it tests failure, assert the
expected exception. Remove an empty test that serves no purpose.
There is no automatic code fix.

## What is not reported

A method is left alone if it calls your code or a third-party library, creates an
object from either, or contains a `throw`. Such code could perform a check.
Assertion calls, MSTest expected-exception attributes, and calls to `Debug`,
`Trace`, or `Contract` also prevent a report. Calls that cannot be resolved are
left alone.

The absence of a diagnostic does not prove that a test checks its result. A single
call to your own code is enough to leave the test unreported.

## Configuration

Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2500.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no
rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress for a test whose entire purpose is to verify that an operation completes
without throwing. State that purpose in its name or a comment. Otherwise add an
assertion for the expected result.
