# SST2501 — An equality or identity assertion should not compare an expression with itself

| Item | Value |
| --- | --- |
| Category | Testing |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

An equality assertion, or an assertion that compares object references, uses the
same expression on both sides. Comparing a value with itself usually checks
nothing; asserting that it differs from itself usually fails every time.

The rule covers xUnit, MSTest, NUnit `Assert`, and NUnit `ClassicAssert` methods:
`Equal`, `StrictEqual`, `AreEqual`, `Same`, `AreSame`, `NotEqual`, `NotSame`,
`AreNotEqual`, and `AreNotSame`. It also covers `Assert.That` with `Is.EqualTo`
or `Is.SameAs`. The call need not be inside a test method.

## Example

Before:

```csharp
using Xunit;

public class ArithmeticTests
{
    [Fact]
    public void Adds()
    {
        var result = 1 + 1;
        Assert.Equal(result, result);
    }
}
```

After:

```csharp
using Xunit;

public class ArithmeticTests
{
    [Fact]
    public void Adds()
    {
        var result = 1 + 1;
        Assert.Equal(2, result);
    }
}
```

## How to fix violations

Replace one side with the intended expected value or the other object you meant
to compare. There is no automatic code fix.

## What is not reported

Different expressions and operands containing calls, object creation, `await`,
assignments, or increments are not reported. Ordinary equality calls with a named
first or second argument are also excluded.

Repeated property and indexer reads can be reported. If those reads can change
the result, store each result in a separate local before comparing them.

## Configuration

Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2501.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no
rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when testing that a custom equality implementation considers an object
equal to itself. For changing property or indexer values, separate locals usually
make the test clearer than suppression.
