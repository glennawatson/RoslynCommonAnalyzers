# SST2502 — The expected value should be the first argument to an equality assertion

| Item | Value |
| --- | --- |
| Category | Testing |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A two-argument equality assertion puts a computed value first and a constant
second. These methods expect the expected value first and the actual result
second, so a failure can label the values backwards.

The rule covers xUnit's `Assert.Equal` and MSTest's or NUnit's `Assert.AreEqual`.
Constants include literals, `const` fields, enum members, and `nameof` results.
The call need not be inside a test method.

## Example

Before:

```csharp
using Xunit;

public class Checks
{
    public void CheckAnswer(int result)
    {
        Assert.Equal(result, 42);
    }
}
```

After:

```csharp
using Xunit;

public class Checks
{
    public void CheckAnswer(int result)
    {
        Assert.Equal(42, result);
    }
}
```

## Code fix

The fix swaps the two argument expressions. It preserves the surrounding layout
and leaves comments around each argument in their original positions. Review
comments that describe a value, because the value they sit beside changes.

## What is not reported

The rule leaves calls alone when both arguments are constants, both are computed,
or the constant is first. Named arguments and calls with more than two arguments
are excluded. NUnit's `Assert.That(actual, Is.EqualTo(expected))` form is excluded,
as are calls on `NUnit.Framework.Legacy.ClassicAssert`.

## Configuration

Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2502.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no
rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the expected value is deliberately computed and the actual value
is a constant. Naming the arguments `expected` and `actual` also makes that intent
clear and avoids the diagnostic.
