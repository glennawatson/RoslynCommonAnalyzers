# SST2503 — An equality assertion against a boolean literal should use the boolean assertion

| Item | Value |
| --- | --- |
| Category | Testing |
| Default severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A two-argument equality assertion compares a `bool` value with the literal `true`
or `false`, in either position. A dedicated boolean assertion states the expected
condition directly.

| Framework | Equality call | Replacement |
| --- | --- | --- |
| xUnit | `Assert.Equal(true, value)` | `Assert.True(value)` |
| xUnit | `Assert.Equal(false, value)` | `Assert.False(value)` |
| MSTest or NUnit `Assert` | `Assert.AreEqual(true, value)` | `Assert.IsTrue(value)` |
| MSTest or NUnit `Assert` | `Assert.AreEqual(false, value)` | `Assert.IsFalse(value)` |

## Example

Before:

```csharp
using Xunit;

public class Checks
{
    public void CheckPaid(bool isPaid)
    {
        Assert.Equal(true, isPaid);
    }
}
```

After:

```csharp
using Xunit;

public class Checks
{
    public void CheckPaid(bool isPaid)
    {
        Assert.True(isPaid);
    }
}
```

## Code fix

The fix changes the method name and keeps only the expression being checked. It
removes argument names and explicit generic type arguments. It also removes
comments and whitespace around the arguments, so review comments before accepting
it. Calls imported with `using static` are supported.

## What is not reported

The rule requires a matching boolean assertion that accepts one argument. It
does not report calls with an extra message argument, a `bool?` or `object` value,
or a named constant in place of the `true` or `false` literal. NUnit
`ClassicAssert` is outside its scope. The call need not be inside a test method.

## Configuration

Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2503.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no
rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the test deliberately exercises the equality assertion API itself.
For ordinary boolean checks, use the dedicated assertion.
