# SST2505 — A parameterized test declares no data source

| Item | Value |
| --- | --- |
| Category | Testing |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A test method declares parameters but has no recognized data source to supply
their values. The test runner can reject or skip the test without running its
assertions.

The rule covers xUnit, NUnit, MSTest, and TUnit test methods. It checks for data
attributes on the method, its return value, and its parameters.

## Example

Before:

```csharp
using Xunit;

public class ArithmeticTests
{
    [Theory]
    public void Adds(int a, int b)
    {
        Assert.Equal(3, a + b);
    }
}
```

After:

```csharp
using Xunit;

public class ArithmeticTests
{
    [Theory]
    [InlineData(1, 2)]
    public void Adds(int a, int b)
    {
        Assert.Equal(3, a + b);
    }
}
```

## How to fix violations

Add a data source for your framework, or remove parameters that the test does not
need. In xUnit, use `[Theory]` rather than `[Fact]` for a test that takes data.

| Framework | Data source examples |
| --- | --- |
| xUnit | `[InlineData]`, `[MemberData]`, `[ClassData]` |
| NUnit | `[TestCase]`, `[TestCaseSource]`, or `[Values]`, `[Range]`, `[Random]` on parameters |
| MSTest | `[DataRow]`, `[DynamicData]` |
| TUnit | `[Arguments]`, `[MethodDataSource]`, `[ClassDataSource]` |

Custom attributes count when they derive from xUnit's `Xunit.Sdk.DataAttribute`
or implement the framework's data-source interface: NUnit's `ITestBuilder` or
`IParameterDataSource`, MSTest's `ITestDataSource`, or TUnit's `IDataSourceAttribute`.

There is no automatic code fix.

## What is not reported

Parameterless tests and tests with any recognized data source are excluded. The
rule does not check that the source provides enough values or the right types.

`CancellationToken` parameters are ignored, even when there is no data source.
Check that your runner supplies the token; the rule does not verify that. Other
parameters alongside the token still need data.

## Configuration

Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2505.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no
rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when a custom runner or data provider supplies the arguments through a
mechanism this rule does not recognize. Verify that the test is discovered and
each required argument is supplied before suppressing it.
