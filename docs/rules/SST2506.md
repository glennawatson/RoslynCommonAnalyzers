# SST2506 — A test should not pause on a fixed real-time delay

| Item | Value |
| --- | --- |
| Category | Testing |
| Default severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A test method calls `System.Threading.Thread.Sleep`. The call blocks a thread and
delays every run. If it is waiting for background work, the delay is a guess: a
busy machine can take longer, and the test can fail before the work finishes.

The rule covers xUnit's `[Fact]` and `[Theory]`; NUnit's `[Test]`, `[TestCase]`,
`[TestCaseSource]`, and `[Theory]`; MSTest's `[TestMethod]` and `[DataTestMethod]`;
and TUnit's `[Test]`. Calls inside loops, conditions, lambdas, and local functions
within the test are included.

## Example

Before:

```csharp
using System.Threading;
using Xunit;

public class TextTests
{
    [Fact]
    public void Uppercases()
    {
        string result = "hello".ToUpperInvariant();
        Thread.Sleep(100);
        Assert.Equal("HELLO", result);
    }
}
```

After, when the operation has already completed:

```csharp
using Xunit;

public class TextTests
{
    [Fact]
    public void Uppercases()
    {
        string result = "hello".ToUpperInvariant();
        Assert.Equal("HELLO", result);
    }
}
```

## How to fix violations

Remove a delay that serves no purpose. For background work, await the task or
completion signal. If neither is available, wait for the required condition with
a timeout that fails the test. For time-based behavior, use a controllable clock
and advance it in the test.

Replacing `Thread.Sleep` with a fixed `Task.Delay` still guesses when the work
will finish. There is no automatic code fix because the right wait depends on
the operation.

## What is not reported

Calls in separate helper methods without a test attribute are not reported.
Neither are unrelated methods named `Sleep` or calls to `Task.Delay`. A custom
test attribute with a name outside the supported list is not recognized, even
when it derives from a framework test attribute.

## Configuration

Set the severity in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2506.severity = error
```

Values are `error`, `warning`, `suggestion`, `silent`, and `none`. There are no
rule-specific options. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress for an integration test that must exercise real elapsed time and cannot
use a completion signal or controllable clock. Document why the delay is required
and keep such tests separate from fast unit tests.
