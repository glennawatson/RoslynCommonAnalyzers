# SST2507 — Assert the expected exception on the specific operation

| Item | Value |
| --- | --- |
| Category | Testing |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A test method uses MSTest's `[ExpectedException]` or NUnit's legacy attribute of the same name.
The attribute lets the test pass when any statement throws the expected exception, including a setup
statement. It does not check which operation failed.

The method must also have a test attribute from MSTest, NUnit, xUnit, or TUnit. Non-test methods and
unrelated attributes named `ExpectedException` are not reported.

## Example

This MSTest example declares the expected exception for the whole method:

```csharp
using System;
using Microsoft.VisualStudio.TestTools.UnitTesting;

[TestClass]
public class ExceptionTests
{
    [TestMethod]
    [ExpectedException(typeof(InvalidOperationException))]
    public void OperationThrows() => throw new InvalidOperationException();
}
```

Remove the attribute and put only the operation expected to fail inside the assertion:

```csharp
using System;
using Microsoft.VisualStudio.TestTools.UnitTesting;

[TestClass]
public class ExceptionTests
{
    [TestMethod]
    public void OperationThrows()
    {
        Assert.ThrowsException<InvalidOperationException>(
            () => throw new InvalidOperationException());
    }
}
```

## How to fix violations

Use your framework's exception assertion, such as `Assert.Throws<T>` or
`Assert.ThrowsException<T>`. Keep setup outside the call passed to the assertion.

There is no code fix because you must choose which operation should throw.

## Configuration

There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2507.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
Use `none` to disable the rule or `default` to restore its default setting.

## When to suppress

Suppress when maintaining tests on a framework version that has no suitable exception assertion,
provided you have checked that setup cannot throw the expected exception.
