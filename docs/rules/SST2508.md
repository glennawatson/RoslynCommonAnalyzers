# SST2508 — Complete the fluent assertion

| Item | Value |
| --- | --- |
| Category | Testing |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A statement calls `value.Should()` from FluentAssertions or AwesomeAssertions without adding a
check. `Should()` selects a value to test; it does not verify anything on its own.

The rule applies outside test methods too. It does not report a result that is stored or returned,
a call with another method chained after it, or an unrelated `Should()` that returns a type outside
these assertion libraries. It reports nothing when neither library is referenced.

## Example

This statement checks nothing:

```csharp
using FluentAssertions;

public class Checks
{
    public void CheckValue(int value)
    {
        value.Should();
    }
}
```

Add the intended check:

```csharp
using FluentAssertions;

public class Checks
{
    public void CheckValue(int value)
    {
        value.Should().Be(1);
    }
}
```

## How to fix violations

Chain a check such as `.Be(...)`, `.Contain(...)`, or `.BeTrue()`. Delete the statement if no
assertion was intended.

There is no code fix because you must choose what to assert.

## Configuration

There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2508.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
Use `none` to disable the rule or `default` to restore its default setting.

## When to suppress

Suppress only when you deliberately exercise `Should()` itself, such as in a test of an assertion
library. An ordinary test should complete or remove the statement.
