# SST2600 — Use structured logging for application output

| Item | Value |
| --- | --- |
| Category | Logging |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

Code calls `System.Diagnostics.Trace.Write`, `WriteLine`, `WriteIf`, or `WriteLineIf` in a project
that references `Microsoft.Extensions.Logging.ILogger`. Calls imported with `using static` are
included.

Logging through `ILogger` lets you choose a severity level and keep values as named fields that
can be searched and filtered.

The rule does not report `Debug` calls, other `Trace` methods such as `TraceInformation`, or
methods on an unrelated type named `Trace`. It reports nothing without the logging abstraction.

## Example

This writes a plain trace message:

```csharp
using System.Diagnostics;

public class Worker
{
    public void Process(int orderId)
    {
        Trace.WriteLine("Processing order " + orderId);
    }
}
```

Pass a logger to the method and use a named value in the message:

```csharp
using Microsoft.Extensions.Logging;

public class Worker
{
    public void Process(int orderId, ILogger logger)
    {
        logger.LogInformation("Processing order {OrderId}", orderId);
    }
}
```

## How to fix violations

Use an available `ILogger` or receive one through the constructor or method parameters. Choose
the log level and message fields. Preserve the condition when replacing `WriteIf` or `WriteLineIf`.

`Trace.Write*` calls depend on the `TRACE` compilation symbol. Logger calls do not, so check
which build configurations should emit the replacement message.

There is no code fix because you must choose the logger, level, and message template.

## Configuration

There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2600.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
Use `none` to disable the rule or `default` to restore its default setting.

## When to suppress

Suppress when the output must reach an existing `TraceListener`, or when tracing is deliberately
separate from application logs and migrating it would break that contract.
