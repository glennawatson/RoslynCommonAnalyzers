# SST2601 — Use consistent names for logger fields and properties

| Item | Value |
| --- | --- |
| Category | Logging |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A field or property declared as `Microsoft.Extensions.Logging.ILogger` or `ILogger<T>` does not
have an accepted name. Nullable logger declarations are included.

| Member | Accepted names by default |
| --- | --- |
| Private instance field or property | `_logger`, `_log` |
| Static field or property, at any accessibility | `Logger` |
| Non-private instance field or property | `Logger` |

Names are case-sensitive. Explicit interface property implementations are excluded because the
interface fixes their names. The interface declaration itself is checked. Unrelated types named
`ILogger` are not reported.

## Example

This public logger property has the wrong name:

```csharp
using Microsoft.Extensions.Logging;

public class Service
{
    public Service(ILogger logger) => MyLogger = logger;

    public ILogger MyLogger { get; }
}
```

Rename the property and its uses:

```csharp
using Microsoft.Extensions.Logging;

public class Service
{
    public Service(ILogger logger) => Logger = logger;

    public ILogger Logger { get; }
}
```

## How to fix violations

Use your editor's Rename command so references change with the declaration. For private instance
members, you can configure the accepted names to match your project's convention.

There is no code fix.

## Configuration

`stylesharp.SST2601.fieldname` replaces the list of accepted private instance names, for fields
and properties. Separate names with commas, semicolons, spaces, or tabs. The default is
`_logger, _log`; an empty value restores that default. The first name is used in diagnostic
suggestions. `Logger` for other members is fixed and cannot be configured.

```ini
[*.cs]
dotnet_diagnostic.SST2601.severity = error
stylesharp.SST2601.fieldname = _logger, _log
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
Use `none` to disable the rule or `default` to restore its default setting.

## When to suppress

Suppress when renaming a public member would break callers, or when a type needs several distinct
loggers whose names explain their roles. Configure private instance names when that meets your needs.
