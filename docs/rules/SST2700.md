# SST2700 — Use forward slashes in route templates

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | Yes |
| Default | Enabled |

## Cause

A route template written directly as a string in an ASP.NET Core MVC routing attribute contains
a backslash (`\`). This includes `[Route]`, HTTP method attributes such as `[HttpGet]` and
`[HttpPost]`, and attributes derived from them.

URL path segments use `/`. A backslash will not match the intended path separator.

Ordinary, verbatim, and raw strings are checked, including a named `template:` argument.
Constants and expressions that build the string are not checked. A backslash in the route's
`Name` property is not reported. An escape such as `\t`, which represents a tab, is not reported
as a backslash. The rule requires the ASP.NET Core MVC routing types.

## Example

This template uses a backslash:

```csharp
using Microsoft.AspNetCore.Mvc;

public class Endpoints
{
    [HttpGet(@"api\products")]
    public void Get() { }
}
```

Use a forward slash:

```csharp
using Microsoft.AspNetCore.Mvc;

public class Endpoints
{
    [HttpGet("api/products")]
    public void Get() { }
}
```

## Code fix

The fix replaces every backslash in the template value with `/`. It writes an ordinary quoted
string, even when the original was verbatim or raw, and preserves comments around the string.
It supports Fix All.

## Configuration

There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2700.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
Use `none` to disable the rule or `default` to restore its default setting.

## When to suppress

Suppress only when the backslash is intentional and you have verified that requests reach the
endpoint through your actual server and proxy setup.
