# SST2702 — Use a supported type for query parameters

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A property marked `[Microsoft.AspNetCore.Components.SupplyParameterFromQuery]` has a type outside
the set accepted by this rule. An unsupported type can fail when Blazor tries to fill the
property from query-string text. The property does not have to be public to be checked.

The rule accepts these types:

- `bool` and `string`.
- `byte`, `sbyte`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`, `float`, `double`, and `decimal`.
- `Guid`, `DateTime`, `DateTimeOffset`, `DateOnly`, and `TimeOnly`, when available in the project.
- Nullable forms of these value types, such as `int?`.
- One-dimensional arrays of these types, such as `string[]`, `int[]`, and `int?[]`.

Enums, custom types, `char`, `TimeSpan`, `Uri`, multidimensional arrays, and jagged arrays are
reported. Properties without the attribute and types the compiler cannot resolve are excluded.
The rule reports nothing without the Blazor components library.

## Example

This property tries to bind an enum directly:

```csharp
using Microsoft.AspNetCore.Components;

public enum Tone { Light, Dark }

public class Page : ComponentBase
{
    [SupplyParameterFromQuery]
    public Tone Theme { get; set; }
}
```

Bind text and convert it where you need the enum:

```csharp
using System;
using Microsoft.AspNetCore.Components;

public enum Tone { Light, Dark }

public class Page : ComponentBase
{
    [SupplyParameterFromQuery]
    public string Theme { get; set; } = string.Empty;

    private Tone GetTheme() =>
        Enum.TryParse<Tone>(Theme, true, out var value) ? value : Tone.Light;
}
```

## How to fix violations

Expose a supported type and decide how to handle missing or invalid input when converting it.
Check that your Blazor version supports the type you choose, especially date and time types.

There is no code fix because you must choose the replacement type and conversion behavior.

## Configuration

There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2702.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
Use `none` to disable the rule or `default` to restore its default setting.

## When to suppress

Suppress when your framework version or custom query binding supports the reported type and you
have tested that it binds correctly. Keep the rule enabled for properties using standard binding.
