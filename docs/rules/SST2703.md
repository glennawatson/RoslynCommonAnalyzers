# SST2703 — Match route constraints to component parameter types

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A class with a Blazor `[Route]` attribute has a typed route segment whose type disagrees with
the matching `[Parameter]` property. For example, `{id:int}` supplies an integer but `Id` is a
string. Blazor can fail when it assigns the route value to the property.

Names are matched without regard to case. Properties declared on base classes are included.
These are the checked constraints:

| Constraint | Matching property type |
| --- | --- |
| `int` | `int` |
| `long` | `long` |
| `guid` | `Guid` |
| `bool` | `bool` |
| `datetime` | `DateTime` |
| `decimal` | `decimal` |
| `double` | `double` |
| `float` | `float` |

Nullable versions of these types also match. The rule handles optional and catch-all segments.
With several constraints, only the first determines the checked type: `int` in
`{id:int:min(1)}`.

Untyped segments, other constraint names, and segments without a matching `[Parameter]` property
are not reported. Types the compiler cannot resolve are excluded. The rule requires the Blazor
components library.

## Example

The constraint and property disagree:

```csharp
using Microsoft.AspNetCore.Components;

[Route("/user/{id:int}")]
public class UserPage : ComponentBase
{
    [Parameter]
    public string Id { get; set; } = string.Empty;
}
```

Use the type required by the constraint:

```csharp
using Microsoft.AspNetCore.Components;

[Route("/user/{id:int}")]
public class UserPage : ComponentBase
{
    [Parameter]
    public int Id { get; set; }
}
```

## How to fix violations

Change the property type or the route constraint so they agree. Check every route that supplies
the property, including routes on derived components when the property comes from a base class.

There is no code fix because you must choose the intended route and parameter type.

## Configuration

There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2703.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
Use `none` to disable the rule or `default` to restore its default setting.

## When to suppress

Suppress only when custom routing converts the value before assigning it and you have tested
that path. Standard Blazor routing needs the constraint and property type to agree.
