# SST2704 — Declare an HTTP method for each API action

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A public instance method declared in an ASP.NET Core controller has no HTTP method attribute.
The controller must derive from `ControllerBase` and have `[ApiController]` on itself or a base
class. A route alone does not restrict the action to `GET`, `POST`, or another HTTP method.

An unrestricted action can accept requests you did not intend and conflict with another action
on the same route.

The rule accepts attributes such as `[HttpGet]`, `[HttpPost]`, and `[AcceptVerbs]`. Custom
attributes also count if they derive from `HttpMethodAttribute` or implement
`IActionHttpMethodProvider`.

Methods marked `[NonAction]`, non-public methods, static methods, abstract methods, generic
methods, property accessors, and overrides of `object` methods are excluded. The rule reports
nothing without the ASP.NET Core MVC types.

## Example

This route has no HTTP method restriction:

```csharp
using Microsoft.AspNetCore.Mvc;

[ApiController]
public class WidgetController : ControllerBase
{
    [Route("widgets")]
    public object List() => new object();
}
```

Restrict it to `GET`:

```csharp
using Microsoft.AspNetCore.Mvc;

[ApiController]
public class WidgetController : ControllerBase
{
    [HttpGet("widgets")]
    public object List() => new object();
}
```

## How to fix violations

Add the HTTP method attribute that matches the action. For a public helper that should not
handle requests, add `[NonAction]` or reduce its accessibility.

There is no code fix because you must choose which HTTP methods the action should accept.

## Configuration

There are no rule-specific options. To report violations as errors:

```ini
[*.cs]
dotnet_diagnostic.SST2704.severity = error
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
Use `none` to disable the rule or `default` to restore its default setting.

## When to suppress

Suppress when the action deliberately accepts every HTTP method, or when application conventions
set the allowed methods elsewhere. Verify the resulting routes and restrictions.
