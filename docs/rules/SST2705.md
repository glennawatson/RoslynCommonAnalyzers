# SST2705 — Make missing request values detectable

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | No |
| Default | Disabled (opt-in) |

## Cause

A request model has a public writable field or property with a non-nullable value type and no
`[Required]` or `[BindRequired]` attribute. If the request omits an `int`, for example, its value
stays `0`. The action cannot tell a missing value from an explicit zero.

The rule checks model classes declared in your project and used directly as parameters of public
instance actions on a `ControllerBase` subclass marked `[ApiController]`, including an inherited
controller attribute. It treats these class parameters as body input unless they have
`[FromQuery]`, `[FromRoute]`, `[FromForm]`, `[FromHeader]`, or `[FromServices]`.

Only members declared on that model class are checked. It does not follow nested models or
inherited members. Collection parameters, reference-type members, nullable value types, static
members, read-only fields, and properties without public setters are excluded. Methods marked
`[NonAction]` are also excluded. The rule requires ASP.NET Core MVC.

## Example

This model cannot distinguish an omitted quantity from zero:

```csharp
using Microsoft.AspNetCore.Mvc;

public class OrderRequest
{
    public int Quantity { get; set; }
}

[ApiController]
[Route("orders")]
public class OrdersController : ControllerBase
{
    [HttpPost]
    public IActionResult Create(OrderRequest request) => Ok();
}
```

For a mandatory value, make absence visible as `null` and require a value:

```csharp
using System.ComponentModel.DataAnnotations;
using Microsoft.AspNetCore.Mvc;

public class OrderRequest
{
    [Required]
    public int? Quantity { get; set; }
}

[ApiController]
[Route("orders")]
public class OrdersController : ControllerBase
{
    [HttpPost]
    public IActionResult Create(OrderRequest request) => Ok();
}
```

## How to fix violations

Use a nullable value type when absence matters. Add `[Required]` when an omitted value should
fail validation; otherwise handle `null` in the action.

The rule also accepts `[Required]` or `[BindRequired]` on a non-nullable member, but that does
not prove a missing JSON value will be rejected. `[Required]` cannot distinguish an omitted
`int` from its default zero, and `[BindRequired]` does not enforce required JSON properties.
Test omission through your actual input and validation setup. The C# `required` keyword and
`[JsonRequired]` do not exempt a member from this rule.

There is no code fix because you must decide whether the value is required, optional, or has an
intentional default.

## Configuration

The rule is disabled by default and has no rule-specific options. Enable it as a warning:

```ini
[*.cs]
dotnet_diagnostic.SST2705.severity = warning
```

Severity accepts `error`, `warning`, `suggestion`, `silent`, `none`, or `default`.
Use `none` to disable the rule or `default` to restore its default setting.

## When to suppress

Suppress when a missing value should keep its default, such as an optional flag that defaults to
`false`, or when separate validation already rejects omissions. The rule is disabled by default
because these defaults are often part of the intended API contract.
