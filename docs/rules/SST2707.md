# SST2707 - Do not capture HttpContext in a fire-and-forget Task.Run

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | No |
| Default | Disabled (opt-in) |

## Cause

A class derived from `ControllerBase` starts `Task.Run` with a lambda or anonymous method that uses an `HttpContext` value, then discards the task. Both `Task.Run(...);` and `_ = Task.Run(...);` are reported.

The background work can run after the request ends. At that point, the request context and its services are unsafe to use: they may have been disposed or reused.

The rule does not report tasks that are awaited, returned, or stored in a variable or member. It also leaves named callbacks such as `Task.Run(Work)` alone. Storing the task alone does not make access to the context safe.

## Example

This callback reads the request context after starting the background work:

```csharp
using System;
using System.Threading.Tasks;
using Microsoft.AspNetCore.Mvc;

public class OrdersController : ControllerBase
{
    public IActionResult Submit()
    {
        _ = Task.Run(() => Console.WriteLine(HttpContext.User.Identity?.Name));
        return Ok();
    }
}
```

Copy the needed data while the request is active, then use the copy:

```csharp
using System;
using System.Threading.Tasks;
using Microsoft.AspNetCore.Mvc;

public class OrdersController : ControllerBase
{
    public IActionResult Submit()
    {
        var userName = HttpContext.User.Identity?.Name;
        _ = Task.Run(() => Console.WriteLine(userName));
        return Ok();
    }
}
```

## How to fix violations

Copy only the data the work needs, such as a name or an ID. Copying `HttpContext` or `HttpContext.Request` into a local still keeps a request object. For work that must finish, await it before returning the response or send the copied data to a queue or hosted background service with its own lifetime.

There is no automatic code fix.

## Configuration

The rule is disabled by default and has a default severity of warning. There are no rule-specific options. To enable it as an error, add this to `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2707.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress only when the callback uses a context that your code owns and keeps valid for the whole task, or another mechanism guarantees the request stays active until the task finishes. Copying a string before starting the task needs no suppression because that shape is not reported.
