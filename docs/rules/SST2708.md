# SST2708 - Unsubscribe a lifecycle event subscription

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A class derived from `ComponentBase` subscribes to another object's event in an override of `OnInitialized`, `OnParametersSet`, `OnAfterRender`, or one of their `Async` forms, but has no `-=` for that event in the same class declaration.

An event source that outlives the component can keep the component in memory through its handler. Remove the handler when the component is disposed.

Subscriptions to the component's own events through `this`, `base`, or an unqualified name are not reported. Neither are additions to delegate fields or subscriptions outside lifecycle overrides.

## Example

This component subscribes to a service but never removes its handler:

```csharp
using System;
using Microsoft.AspNetCore.Components;

public class TimeService
{
    public event Action Tick = delegate { };
    public void Notify() => Tick();
}

public class Clock : ComponentBase
{
    [Inject]
    public TimeService Time { get; set; } = null!;

    protected override void OnInitialized() => Time.Tick += OnTick;

    private void OnTick() => StateHasChanged();
}
```

Implement disposal and remove the same handler from the same source:

```csharp
using System;
using Microsoft.AspNetCore.Components;

public class TimeService
{
    public event Action Tick = delegate { };
    public void Notify() => Tick();
}

public class Clock : ComponentBase, IDisposable
{
    [Inject]
    public TimeService Time { get; set; } = null!;

    protected override void OnInitialized() => Time.Tick += OnTick;

    public void Dispose() => Time.Tick -= OnTick;

    private void OnTick() => StateHasChanged();
}
```

## How to fix violations

Unsubscribe in `Dispose` or `DisposeAsync` and implement `IDisposable` or `IAsyncDisposable` so Blazor calls it. If you subscribe with a lambda, store that handler so you can remove the same one later.

The rule accepts a `-=` for the event anywhere in the class declaration. It does not check that the handler or source instance matches, or that the removal runs. Check those details yourself.

There is no automatic code fix.

## Configuration

The rule is enabled by default as a warning. There are no rule-specific options. To report violations as errors, add this to `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2708.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the event source is owned only by the component and both become unused together. Suppression also fits a subscription that is removed in another part of a partial class or by a cleanup helper that the rule cannot check.
