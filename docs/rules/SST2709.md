# SST2709 - Do not request a render while disposing

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A class derived from `ComponentBase` calls the framework's `StateHasChanged()` in a method named `Dispose` or `DisposeAsync`. Calls through `this` or `base` and calls inside `Dispose(bool)` are included.

Blazor does not support requesting a render during disposal. The component is being removed, so its cleanup should release resources without requesting a UI update.

Calls inside a lambda, anonymous method, or local function are not reported, even if they appear inside a disposal method. This exclusion does not make rendering during disposal safe.

## Example

This disposal method requests a render:

```csharp
using System;
using Microsoft.AspNetCore.Components;

public class Panel : ComponentBase, IDisposable
{
    public void Dispose()
    {
        StateHasChanged();
    }
}
```

Remove the render request:

```csharp
using System;
using Microsoft.AspNetCore.Components;

public class Panel : ComponentBase, IDisposable
{
    public void Dispose()
    {
        // Release any owned resources here.
    }
}
```

There is no automatic code fix.

## Configuration

The rule is enabled by default as a warning. There are no rule-specific options. To report violations as errors, add this to `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2709.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Do not suppress a render request on a real disposal path. If a method named `Dispose` or `DisposeAsync` does other work while the component is active, rename it or suppress the diagnostic when the name is required by another contract.
