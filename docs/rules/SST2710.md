# SST2710 - Use InvokeAsync for a timer callback's render request

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `System.Threading.Timer` callback or a `System.Timers.Timer.Elapsed` handler calls the component's `StateHasChanged()` without going through `InvokeAsync`.

Timer callbacks usually run on a background thread. Use `InvokeAsync` to run the render request on Blazor's dispatcher, which controls access to the UI.

The rule covers lambdas, anonymous methods, and named callback methods declared in the same file. It does not follow named callbacks into other files. Both `InvokeAsync(StateHasChanged)` and `InvokeAsync(() => StateHasChanged())` are accepted.

## Example

This timer requests a render directly:

```csharp
#nullable enable
using System;
using System.Threading;
using Microsoft.AspNetCore.Components;

public class Ticker : ComponentBase, IDisposable
{
    private Timer? _timer;

    protected override void OnInitialized()
    {
        _timer = new Timer(_ => StateHasChanged(), null, 0, 1000);
    }

    public void Dispose() => _timer?.Dispose();
}
```

Pass the render request to `InvokeAsync`:

```csharp
#nullable enable
using System;
using System.Threading;
using Microsoft.AspNetCore.Components;

public class Ticker : ComponentBase, IDisposable
{
    private Timer? _timer;

    protected override void OnInitialized()
    {
        _timer = new Timer(_ => InvokeAsync(StateHasChanged), null, 0, 1000);
    }

    public void Dispose() => _timer?.Dispose();
}
```

If the callback also changes component state, put those changes and the render request in the same `InvokeAsync` callback.

There is no automatic code fix.

## Configuration

The rule is enabled by default as a warning. There are no rule-specific options. To report violations as errors, add this to `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2710.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress only when another mechanism already runs the reported call on the component's dispatcher. An ordinary timer callback does not provide that guarantee.
