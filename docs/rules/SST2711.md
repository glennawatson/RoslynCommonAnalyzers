# SST2711 - A synchronous component lifecycle override must not be async void

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | Yes (supports Fix All) |
| Default | Enabled |

## Cause

A component overrides `OnInitialized`, `OnParametersSet`, or `OnAfterRender` as `async void`. This includes overrides through a custom base class when the original method comes from `ComponentBase`.

Blazor gets no task to await from an `async void` method. It can continue before the work finishes, and cannot handle failures through the normal lifecycle task. Use the matching method ending in `Async`, which returns `Task`.

A synchronous `void` override, a `Task`-returning lifecycle override, and an unrelated method with the same name are not reported.

## Example

This override gives Blazor no task to await:

```csharp
using System.Threading.Tasks;
using Microsoft.AspNetCore.Components;

public class Counter : ComponentBase
{
    protected override async void OnInitialized() => await Task.Delay(1);
}
```

Override the matching asynchronous method:

```csharp
using System.Threading.Tasks;
using Microsoft.AspNetCore.Components;

public class Counter : ComponentBase
{
    protected override async Task OnInitializedAsync() => await Task.Delay(1);
}
```

## Code fix

The fix appends `Async` to the method name and changes `void` to `Task`. It keeps the modifiers, parameters, body, and comments, including the `firstRender` parameter of `OnAfterRender`. It supports Fix All.

No fix is offered if the same class declaration already contains a method or property with the target name. Combine the work in the existing asynchronous override by hand. Check other parts of a partial class for duplicates too: the fix does not check them.

The fix leaves calls inside the body unchanged. Review any calls to the base lifecycle method so they still run the intended base-class work.

## Configuration

The rule is enabled by default as a warning. There are no rule-specific options. To report violations as errors, add this to `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2711.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppression is rarely appropriate because all three lifecycle methods have asynchronous alternatives. If the work needs no `await`, remove `async` and keep the synchronous override.
