# SST2712 - An injected or cascading component property must have a setter

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | Yes, for get-only auto-properties (supports Fix All) |
| Default | Enabled |

## Cause

An instance property marked with Blazor's `[Inject]` or `[CascadingParameter]` has no setter. This includes get-only auto-properties, getters with a body, and properties written with `=>`.

Blazor needs a setter to supply a service or cascading value. A getter alone cannot accept that value. The rule checks these attributes even on classes that do not derive from `ComponentBase`.

Properties with `set`, `private set`, or `init` are not reported. Static properties, indexers, and attributes with the same names from other namespaces are also excluded.

## Example

This cascading property cannot receive a value:

```csharp
using Microsoft.AspNetCore.Components;

public class Widget : ComponentBase
{
    [CascadingParameter]
    public string Theme { get; } = "light";
}
```

Add a setter so Blazor can assign it:

```csharp
using Microsoft.AspNetCore.Components;

public class Widget : ComponentBase
{
    [CascadingParameter]
    public string Theme { get; private set; } = "light";
}
```

## Code fix

The fix adds `private set;` to a property whose only accessor is `get;` with no body. It keeps the getter, attributes, initializer, and existing comments, and formats the property. It supports Fix All.

No fix is offered for a getter with a body or a property written with `=>`. Change those properties by hand. For a private property, add `set;` by hand: adding `private set;` would repeat the property's access level and cause a compiler error.

## Configuration

The rule is enabled by default as a warning. There are no rule-specific options. To report violations as errors, add this to `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2712.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Do not suppress a property that Blazor must fill. If the property computes its own value, remove the attribute. Suppression can fit a class outside Blazor where custom code deliberately reads the attribute without assigning the property.
