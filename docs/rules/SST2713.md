# SST2713 - A DotNetObjectReference must be stored so it can be disposed

| Item | Value |
| --- | --- |
| Category | Frameworks |
| Severity | Warning |
| Code fix | No |
| Default | Enabled |

## Cause

A `DotNetObjectReference.Create(...)` result is passed directly as a method argument, used as a bare statement, or assigned to `_`. The argument case includes calls to any method, not only JavaScript interop. The rule applies to any class, not only components.

The reference lets JavaScript call a .NET object. Once passed to JavaScript, it keeps that object available until the reference is disposed. Losing the reference makes cleanup difficult and can keep the object in memory.

References stored in fields, properties, or locals, created in a `using` declaration, or returned to a caller are not reported. Storing a reference does not remove the need to dispose it.

## Example

This call creates a reference without keeping it for cleanup:

```csharp
using System.Threading.Tasks;
using Microsoft.JSInterop;

public class Map
{
    private readonly IJSRuntime _js;

    public Map(IJSRuntime js) => _js = js;

    public async Task InitAsync() =>
        await _js.InvokeVoidAsync("map.init", DotNetObjectReference.Create(this));
}
```

Keep one reference and dispose it when the owner is disposed:

```csharp
using System;
using System.Threading.Tasks;
using Microsoft.JSInterop;

public class Map : IDisposable
{
    private readonly IJSRuntime _js;
    private readonly DotNetObjectReference<Map> _self;

    public Map(IJSRuntime js)
    {
        _js = js;
        _self = DotNetObjectReference.Create(this);
    }

    public async Task InitAsync() =>
        await _js.InvokeVoidAsync("map.init", _self);

    public void Dispose() => _self.Dispose();
}
```

## How to fix violations

Choose an owner for the reference and make sure its cleanup runs. Keep the reference alive for as long as JavaScript can call the object. A short-lived `using` declaration is unsuitable if JavaScript stores it for later callbacks. Stop those callbacks before disposal.

There is no automatic code fix.

## Configuration

The rule is enabled by default as a warning. There are no rule-specific options. To report violations as errors, add this to `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SST2713.severity = error
```

Severity values are `error`, `warning`, `suggestion`, `silent`, and `none`. Use `none` to disable the rule. See [Configuration](../CONFIGURATION.md).

## When to suppress

Suppress when the receiving method takes responsibility for storing and disposing the reference, or when JavaScript reliably calls its `dispose` method after its last use. Passing a reference inline without an agreed cleanup owner is not a reason to suppress.
